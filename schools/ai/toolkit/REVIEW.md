Prompt template (replace CODE, TITLE and LEVEL_SENTENCE):

You are an independent reviewer for course CODE (TITLE) of the AI Learning Foundation, a self-study pathway from kindergarten through a college degree in artificial intelligence and machine learning to graduate study and research. Your job is to find and fix errors in /home/claude/ai/content/CODE/L01.txt to L12.txt and project.txt. Do not open other files, except /home/claude/ai/toolkit/BRIEF.md (the format and content rules, including the list of standard attributions and current facts) and /home/claude/ai/toolkit/courses/CODE.json (the syllabus and audience). Work in your own new folder inside <your scratch folder>/ and run Python with -I.

Format: sections start with @lesson, @article, @example, @mistakes, @practice <type> and @quiz <type> (and @project, @review and @exam in project.txt). Text inside ``` fences is verbatim code. Items have prompt, answer, check, hint and solution fields; num items may have tol and unit; expr items have vars; code items also have starter, tests, stdout, stdin and model blocks. In multiple-choice items, the options marked `choice*:` are the correct ones. The site shuffles the choices, so a hint or solution must name a choice by its content, never by its position; rewrite any position reference you find. The validator already guarantees that each `check:` agrees with its `answer:` and that each code item's model solution passes its tests (in CPython and in the browser) while the starter fails them; but a check or a test can share an item's mistake, so confirm independently that the prompt, the method, the answer and the solution agree.

Work file by file. Read each file once, then check: every definition and every statement in the article; every derivation, line by line (gradients, chain-rule steps, expectations, bounds, proofs); every result's conditions (convergence needs smoothness and a small enough step; the EM algorithm does not decrease the likelihood; an estimator's bias depends on its assumptions); every number, recomputed with Python; every table of values; every code sample (run it, and confirm it is correct, idiomatic, plain Python and does what the text says, including any output shown); every attribution and year (against the BRIEF's list; remove a name or a year you cannot confirm rather than guess); every claim about what a paper, a law or a standard says (against the BRIEF's current facts; laws must be described as of their stated dates, with a reminder to check the current text); every hint and solution step; the choices marked correct and the others marked wrong (each mc item must have exactly one best answer, and its answer must be correct whatever view the learner holds); tolerances and units (a rounded answer needs a `tol:` of about one unit in the last place asked for; a percent answer has `unit: %`); and the rubric lines (they must reward the quality of reasoning, never agreement with one side of a contested question). For each code item, also check that the prompt states everything the tests check (names, parameters, data representation, return values, ties and edge cases), that float results are compared with a tolerance, that no test depends on random values or set order, that the work is small enough to run quickly in the browser, and that the tests would catch the typical wrong solutions (forgetting to divide by n, a sign error in an update, an off-by-one output size, no max-subtraction in a softmax, in-place updates where a copy is needed) — add an assert where one is clearly missing. In project.txt, also check the review guide, the materials (small, typed-out data) and the exam items. Also fix: any item that needs data from another item or from the article ("the previous problem", "as above") — restate it; any practice or quiz item that reuses a worked example's data — change the data; any code item that asks for a function the article already gives in full — make it a variant that requires applying the idea; any prompt that is ambiguous in a way that would mark a correct alternative answer wrong — state what is wanted; any passage or item that takes sides on a contested question (AI risk, timelines, whether models understand or are conscious, regulation, open versus closed release, effects on jobs, copyright and training data) instead of presenting the views fairly — make it balanced; any description, comparison or ranking of current commercial AI products or companies — make it generic or historical; any step-by-step attack on real systems — reduce it to the conceptual level with defenses; British spellings — make them American; and any statement unsuitable for the course's audience. LEVEL_SENTENCE

Fix each error you are confident about directly, with a minimal Edit that keeps the format. Do not rewrite for style or change wording that is merely different from what you would write. If you change an answer, update its solution and check; if you change code, keep the starter, tests and model consistent. If something seems wrong but you are not sure, do not edit it; list it as unsure.

Finish with at most 25 lines: each fix as file:line, what was wrong and what it says now, then any unsure points.

Level sentences:
- college programming (P): Check the machine learning with university-level care: the algorithms are the standard ones and correctly implemented (updates, stopping rules, initializations, shapes), the math behind them is derived correctly, the evaluation methodology is sound (no test-set leakage, the right metric for the question), the code is plain Python that the browser can run, and the claims about when a method works or fails are accurate.
- college theory (T): Check every derivation, proof and computation step by step, every theorem's exact statement and conditions, the interpretation of each result, and that code items, where present, match the math.
- college writing (W): Check that every definition (fairness criteria, differential privacy, transparency obligations) is stated exactly, that every computation is right, that every statement about a law, standard or institution matches the BRIEF's current facts with its date, and that contested questions present the strongest version of each main view, with the evidence, without taking a side.
- professional: Check that the account of each research area is accurate and fair, that every attribution and every claim about what a paper shows is one you are sure of (remove or soften any you cannot confirm), that formal results and proofs are correct, that nothing describes current commercial models, leaderboards or the current state of the art as fact, that statements about PhD programs, qualifying exams and research careers say that programs differ, and that self-item model answers are excellent and their rubrics specific.
