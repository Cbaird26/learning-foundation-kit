@article
A single convolution sees only a small window of its input. How can a stack of layers recognize a whole digit or an object? By letting each layer look at the previous layer's output, so that the window it effectively sees grows with depth.

### LeNet and the shape trace
The convolutional network for digit recognition of LeCun and colleagues (1989, 1998), known as LeNet-5, takes a $32 \times 32$ grayscale image and alternates convolution and pooling. In the variant we trace:

| layer | output shape | parameters |
|---|---|---|
| input | $1 \times 32 \times 32$ | 0 |
| conv $5 \times 5$, 6 channels | $6 \times 28 \times 28$ | $6 (25 + 1) = 156$ |
| pool $2 \times 2$ | $6 \times 14 \times 14$ | 0 |
| conv $5 \times 5$, 16 channels | $16 \times 10 \times 10$ | $16 (150 + 1) = 2416$ |
| pool $2 \times 2$ | $16 \times 5 \times 5$ | 0 |
| flatten | 400 | 0 |
| fully connected 400 to 120 | 120 | $400 \cdot 120 + 120 = 48120$ |
| fully connected 120 to 84 | 84 | 10164 |
| fully connected 84 to 10 | 10 | 850 |

The total is 61,706 parameters. Notice that most of them are in the first fully connected layer: convolutions are cheap, flattened dense layers are not.

### Growing the field of view
The **receptive field** of a unit is the set of input pixels that can affect it. For a stack of layers with kernel sizes $k_\ell$ and strides $s_\ell$, start with receptive field $r = 1$ and jump $j = 1$ (the spacing between neighboring units, measured in input pixels). For each layer in order:

$$r \leftarrow r + (k_\ell - 1)\, j, \qquad j \leftarrow j\, s_\ell.$$

Two $3 \times 3$ convolutions with stride 1 give $r = 3$ and then $r = 3 + 2 = 5$, the same field as one $5 \times 5$ kernel. With $c$ channels in and out and no biases, two $3\times 3$ layers use $2 \cdot 9 c^2 = 18c^2$ weights against $25 c^2$ for one $5 \times 5$ layer, and they add an extra nonlinearity. This is the idea behind VGG-style networks, which build deep stacks of $3 \times 3$ convolutions.

### Deeper and deeper
AlexNet (Krizhevsky, Sutskever and Hinton, 2012) showed that a large convolutional network trained on GPUs could win the ImageNet challenge by a wide margin, using ReLU units and dropout. Adding even more layers then ran into trouble: very deep plain networks trained worse than shallower ones, even on the training set. Batch normalization (Ioffe and Szegedy, 2015) made optimization easier, but depth still hurt.

**Residual networks** (He and colleagues, 2015) change what a block computes. Instead of learning $\mathbf{y} = H(\mathbf{x})$ directly, a residual block learns a correction $F$ and adds the input back:

$$\mathbf{y} = \operatorname{ReLU}\big(\mathbf{x} + F(\mathbf{x})\big), \qquad F(\mathbf{x}) = \mathbf{W}_2 \operatorname{ReLU}(\mathbf{W}_1 \mathbf{x}).$$

The **shortcut** (skip connection) passes $\mathbf{x}$ unchanged, so the block can represent the identity by driving $F$ toward 0, and the gradient has a direct path: $\partial \mathbf{y}/\partial \mathbf{x} = \mathbf{I} + \partial F/\partial \mathbf{x}$ (before the final ReLU). When the shapes of $\mathbf{x}$ and $F(\mathbf{x})$ differ, a $1 \times 1$ convolution on the shortcut matches them. A $1 \times 1$ convolution mixes channels at each position and is also used to shrink the channel count before an expensive $3 \times 3$ layer, the "bottleneck" design.

### In code
```python
def relu(v):
    return [max(0.0, a) for a in v]

def matvec(W, x):
    return [sum(w * a for w, a in zip(row, x)) for row in W]

def residual(x, W1, W2):
    f = matvec(W2, relu(matvec(W1, x)))
    return relu([a + b for a, b in zip(x, f)])

print(residual([1.0, 2.0], [[1, 0], [0, 1]], [[0.5, 0], [0, 0.5]]))
```

In PyTorch the same block is a few lines in an `nn.Module`, with convolutions in place of the matrices.

problem: An image of height 64 passes through a convolution with kernel 7, stride 2 and padding 3, then a max pool with kernel 3, stride 2 and padding 1, then a convolution with kernel 3, stride 1, padding 1. Give the height after each layer and the receptive field of the last layer.

step: Receptive field. Start with $r = 1$, $j = 1$. Layer 1 ($k = 7$, $s = 2$): $r = 1 + 6 = 7$, $j = 2$. Pool ($k = 3$, $s = 2$): $r = 7 + 2 \cdot 2 = 11$, $j = 4$. Last conv ($k = 3$, $s = 1$): $r = 11 + 2 \cdot 4 = 19$.
answer: The heights are 32, 16 and 16, and the receptive field is 19 pixels.

@example
title: One residual block by hand
problem: Let $\mathbf{x} = (2, -1)$, $\mathbf{W}_1$ have rows $(1, 1)$ and $(0, 2)$, and $\mathbf{W}_2$ have rows $(1, 0)$ and $(1, -1)$. Compute $\mathbf{y} = \operatorname{ReLU}(\mathbf{x} + \mathbf{W}_2 \operatorname{ReLU}(\mathbf{W}_1 \mathbf{x}))$.
step: $\mathbf{W}_1 \mathbf{x} = (2 - 1,\ 0 - 2) = (1, -2)$.
step: Apply ReLU: $(1, 0)$.
step: $\mathbf{W}_2 (1, 0) = (1,\ 1 - 0) = (1, 1)$, so $F(\mathbf{x}) = (1, 1)$.
step: Add the shortcut: $(2, -1) + (1, 1) = (3, 0)$. The final ReLU leaves $(3, 0)$ unchanged.
answer: $\mathbf{y} = (3, 0)$.

@mistakes
- Adding the shortcut after the final ReLU when the design puts it before, or the reverse: write down the order of operations before computing.
- Updating the receptive field with the wrong jump: the jump is multiplied by the stride after the layer's contribution is added.
- Believing that a deeper plain network must fit the training set at least as well as a shallower one; in practice optimization can fail, which is what shortcuts fix.
- Forgetting that fully connected layers after flattening usually hold most of the parameters of a small classic network.

model:
```python
def receptive_field(layers):
    """Receptive field of the last layer of a stack of (kernel, stride) layers."""
    r, jump = 1, 1
    for k, s in layers:
        r += (k - 1) * jump
        jump *= s
    return r
```
hint: Keep two running variables, the field `r` and the jump, and update `r` before the jump inside the loop.
solution: Each layer widens the field by $(k - 1)$ steps of the current jump, then strides multiply the jump. The last test (stride first, then a larger kernel) gives 6 and fails if the jump is updated before the field.

model:
```python
def residual_block(x, W1, W2, Ws=None):
    """Residual block with an identity or projection shortcut."""
    def relu(v):
        return [max(0.0, a) for a in v]

    def matvec(W, v):
        return [sum(w * a for w, a in zip(row, v)) for row in W]

    f = matvec(W2, relu(matvec(W1, x)))
    shortcut = list(x) if Ws is None else matvec(Ws, x)
    return relu([a + b for a, b in zip(shortcut, f)])
```
hint: Compute the branch $F(\mathbf{x})$ first, then choose the shortcut: `x` itself, or `Ws @ x` when `Ws` is given.
hint: Add the shortcut and the branch elementwise, and only then apply the last ReLU.
solution: The branch is two matrix-vector products with a ReLU between them; the shortcut is added before the final ReLU. The projection test changes the output length from 3 to 2, so code that always adds `x` fails it, and the test with an all-negative input fails if the final ReLU is forgotten.

@quiz mc
prompt: Which statement best explains why identity shortcuts help optimization of very deep networks?
choice*: The derivative of a block's output with respect to its input contains the identity matrix, so gradients have a direct path through the shortcut.
choice: The shortcut removes the nonlinearity, so the network becomes a linear model.
choice: The shortcut adds parameters, so the network can always fit the data set.
choice: The shortcut makes every layer's receptive field larger than the layer before it.
hint: Differentiate $\mathbf{x} + F(\mathbf{x})$ with respect to $\mathbf{x}$.
solution: Since $\partial(\mathbf{x} + F(\mathbf{x}))/\partial \mathbf{x} = \mathbf{I} + \partial F/\partial \mathbf{x}$, the identity term carries the gradient backward even when the branch's gradient is small. The branch still has nonlinearities, the shortcut adds no parameters when shapes match, and it does not change receptive fields in that way.

model:
```python
def count_params(layers):
    """Total parameters of conv and fully connected layers, with biases."""
    total = 0
    for layer in layers:
        if layer[0] == 'conv':
            _, c_in, c_out, k = layer
            total += c_out * (c_in * k * k + 1)
        else:
            _, n_in, n_out = layer
            total += n_out * (n_in + 1)
    return total
```
hint: A convolution has `c_out * (c_in * k * k + 1)` parameters; a fully connected layer has `n_out * (n_in + 1)`.
solution: Branch on the layer kind and add the weights plus one bias per output unit or channel. The last test mixes two convolutions and two fully connected layers, so a solution that forgets a bias term or treats a $1 \times 1$ kernel specially is caught.
