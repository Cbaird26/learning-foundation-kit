@article
You have 200 labeled photos of leaf diseases. Training a convolutional network from random weights on 200 images will overfit badly. But a network already trained on a million everyday images has learned edges, textures and shapes that are useful for leaves too. **Transfer learning** reuses what a model learned on a large source task to help a small target task.

### Two ways to reuse a backbone
Split a pretrained model into a **backbone** (the layers that compute features) and a **head** (the final layers that map features to the task's outputs). The target task usually needs a new head, because its labels differ.

**Feature extraction** (also called a **linear probe** when the head is linear) freezes the backbone and trains only the new head. It is cheap, has few trainable parameters, and cannot damage the pretrained features. For fixed features $\mathbf{f}(\mathbf{x})$ and a linear head $\mathbf{w}$ with squared error, the gradient for one example is $2(\mathbf{w}^\top\mathbf{f} - y)\,\mathbf{f}$. With features $\mathbf{f} = (1, 2)$, label $y = 1$, $\mathbf{w} = \mathbf{0}$ and step size $0.1$, the gradient is $(-2, -4)$ and the new head is $(0.2, 0.4)$.

**Fine-tuning** continues training some or all backbone layers on the target data, starting from the pretrained weights. It can adapt the features themselves, which helps when the target data differ from the source or when there is more labeled data, but it risks overfitting a small data set and **catastrophic forgetting**, where the model loses source-task behavior. Common safeguards are a small learning rate for the backbone, a larger one for the new head (**discriminative learning rates**), training the head first, freezing early layers, and stopping early on a validation set. Which strategy is best depends on how much target data you have and how close the target task is to the source; there is no universal rule, so compare options on a validation set.

### A two-learning-rate step
Take a tiny model $\hat y = \mathbf{v}^\top \operatorname{ReLU}(\mathbf{W}\mathbf{x})$ with backbone $\mathbf{W}$ and head $\mathbf{v}$, and loss $(\hat y - y)^2$. Let $\mathbf{z} = \mathbf{W}\mathbf{x}$, $\mathbf{h} = \operatorname{ReLU}(\mathbf{z})$ and $\epsilon = \hat y - y$. Then

$$\nabla_{\mathbf{v}} L = 2\epsilon\,\mathbf{h}, \qquad \nabla_{\mathbf{W}} L = \big(2\epsilon\,\mathbf{v} \odot \mathbb{1}[\mathbf{z} > 0]\big)\,\mathbf{x}^\top.$$

Updating $\mathbf{W}$ with learning rate $\eta_{\text{body}}$ and $\mathbf{v}$ with $\eta_{\text{head}}$ gives discriminative learning rates; setting $\eta_{\text{body}} = 0$ freezes the backbone and recovers feature extraction.

### Low-rank adaptation
Large pretrained models have enormous weight matrices. **Low-rank adaptation** (LoRA; Hu and colleagues, 2021) freezes the pretrained matrix $\mathbf{W}_0 \in \mathbb{R}^{d_{out}\times d_{in}}$ and learns a low-rank update:

$$\mathbf{W} = \mathbf{W}_0 + \frac{\alpha}{r}\,\mathbf{B}\mathbf{A}, \qquad \mathbf{B} \in \mathbb{R}^{d_{out}\times r},\ \mathbf{A} \in \mathbb{R}^{r \times d_{in}},\ r \ll \min(d_{in}, d_{out}).$$

Only $\mathbf{A}$ and $\mathbf{B}$ are trained, so the trainable parameters number $r(d_{in} + d_{out})$ instead of $d_{in} d_{out}$. For a $768 \times 3072$ matrix and rank $r = 4$ that is $4(768 + 3072) = 15{,}360$ against $2{,}359{,}296$, about $0.65\%$. In the forward pass, $\mathbf{W}\mathbf{x} = \mathbf{W}_0\mathbf{x} + \frac{\alpha}{r}\mathbf{B}(\mathbf{A}\mathbf{x})$, and after training the update can be merged into $\mathbf{W}_0$ at no extra inference cost. The update has rank at most $r$, which limits how much the layer can change: this is a modeling assumption, not a guarantee. Other **adapter** methods insert small trainable layers between frozen ones.

### Pitfalls
The source data may differ from the target data (distribution shift), and in the worst case pretraining hurts (**negative transfer**). Pretraining data can also overlap with a benchmark's test set, which inflates scores; check for leakage before trusting a result, and tune choices on validation data, not the test set.

### In code
```python
def features(x, W):
    """Frozen backbone: one ReLU layer."""
    return [max(0.0, sum(w * a for w, a in zip(row, x))) for row in W]

def train_head(F, ys, lr, steps):
    """Fit a linear head on fixed features F by gradient descent on MSE."""
    n, k = len(F), len(F[0])
    w = [0.0] * k
    for _ in range(steps):
        g = [0.0] * k
        for f, y in zip(F, ys):
            e = sum(a * b for a, b in zip(w, f)) - y
            for i in range(k):
                g[i] += 2 * e * f[i] / n
        w = [a - lr * b for a, b in zip(w, g)]
    return w

W = [[1, 0], [0, 1], [1, -1]]
X = [[1, 0], [0, 1], [2, 1], [1, 2]]
F = [features(x, W) for x in X]
print([round(a, 3) for a in train_head(F, [1, 0, 1, 0], 0.1, 200)])
```

Libraries make freezing a one-line change (`requires_grad = False` in PyTorch), and LoRA is available in common fine-tuning toolkits.

@example
title: A LoRA update by hand
problem: A frozen matrix is $\mathbf{W}_0$ with rows $(1, 2)$ and $(0, 1)$. A rank-1 adapter has $\mathbf{B} = \begin{pmatrix} 2 \\ 1 \end{pmatrix}$, $\mathbf{A} = (1, -1)$ and scale $\alpha/r = 0.5$. Compute the adapted matrix and the output for $\mathbf{x} = (3, 1)$.
step: The product $\mathbf{B}\mathbf{A}$ is the outer product with rows $(2, -2)$ and $(1, -1)$. Scaled by $0.5$ it is $\Delta\mathbf{W}$ with rows $(1, -1)$ and $(0.5, -0.5)$.
step: The adapted matrix is $\mathbf{W}_0 + \Delta\mathbf{W}$ with rows $(2, 1)$ and $(0.5, 0.5)$.
step: The output is $\mathbf{W}\mathbf{x} = (2\cdot 3 + 1\cdot 1,\ 0.5 \cdot 3 + 0.5 \cdot 1) = (7, 2)$.
step: Check by the factored form: $\mathbf{W}_0\mathbf{x} = (5, 1)$ and $\mathbf{A}\mathbf{x} = 3 - 1 = 2$, so the update adds $0.5 \cdot 2 \cdot (2, 1) = (2, 1)$, giving $(7, 2)$.
answer: $\mathbf{W}$ has rows $(2, 1)$ and $(0.5, 0.5)$, and $\mathbf{W}\mathbf{x} = (7, 2)$.

@example
title: One fine-tuning step with two learning rates
problem: The model is $\hat y = \mathbf{v}^\top \operatorname{ReLU}(\mathbf{W}\mathbf{x})$ with $\mathbf{W}$ having rows $(1, -1)$ and $(0.5, 2)$, $\mathbf{v} = (1, -1)$, input $\mathbf{x} = (2, 1)$ and target $y = 1$. Take one gradient step on $(\hat y - y)^2$ with $\eta_{\text{body}} = 0.01$ and $\eta_{\text{head}} = 0.1$.
step: Forward: $\mathbf{z} = \mathbf{W}\mathbf{x} = (1, 3)$, $\mathbf{h} = (1, 3)$ (both positive), $\hat y = 1 - 3 = -2$ and $\epsilon = \hat y - y = -3$.
step: Head gradient: $2\epsilon\,\mathbf{h} = -6\,(1, 3) = (-6, -18)$. New head: $\mathbf{v} = (1 + 0.6,\ -1 + 1.8) = (1.6, 0.8)$.
step: Backbone gradient: $2\epsilon\,\mathbf{v} = (-6, 6)$, and both ReLU gates are open, so $\nabla_{\mathbf{W}} L = (-6, 6)^\top (2, 1)$ has rows $(-12, -6)$ and $(12, 6)$.
step: New backbone (using the old $\mathbf{v}$ in the gradient): rows $(1 + 0.12,\ -1 + 0.06) = (1.12, -0.94)$ and $(0.5 - 0.12,\ 2 - 0.06) = (0.38, 1.94)$.
answer: $\mathbf{v} = (1.6, 0.8)$ and $\mathbf{W}$ has rows $(1.12, -0.94)$ and $(0.38, 1.94)$.

@mistakes
- Using the same large learning rate for a pretrained backbone and a freshly initialized head; the large updates can destroy the pretrained features.
- Updating the backbone with the new head's weights after the head has already changed. Compute both gradients from the same forward pass before updating.
- Assuming LoRA adds $d_{in} d_{out}$ parameters; it adds only $r(d_{in} + d_{out})$, and the frozen $\mathbf{W}_0$ is not trained.
- Evaluating a fine-tuned model on data that may have appeared in pretraining, or choosing the number of fine-tuning epochs on the test set.

model:
```python
def lora_forward(W0, A, B, x, scale):
    """W0 x plus the scaled low-rank correction B (A x)."""
    base = [sum(w * a for w, a in zip(row, x)) for row in W0]
    low = [sum(w * a for w, a in zip(row, x)) for row in A]
    delta = [sum(w * a for w, a in zip(row, low)) for row in B]
    return [b + scale * d for b, d in zip(base, delta)]
```
hint: First compute `A @ x` (a vector of length `r`), then `B` times that vector, scale it, and add it to `W0 @ x`.
solution: Multiplying `A` into `x` first keeps the intermediate vector of size `r`, so the cost is $O(r(d_{in} + d_{out}))$ instead of forming the full update. With `scale = 0` the adapter has no effect, and the starter, which returns only $\mathbf{W}_0\mathbf{x}$, passes that test but fails the others.

model:
```python
def finetune_step(W, v, x, y, lr_body, lr_head):
    """One SGD step on a ReLU backbone and a linear head with two rates."""
    z = [sum(w * a for w, a in zip(row, x)) for row in W]
    h = [max(0.0, a) for a in z]
    y_hat = sum(a * b for a, b in zip(v, h))
    err = y_hat - y
    new_v = [v[i] - lr_head * 2 * err * h[i] for i in range(len(v))]
    new_W = []
    for i, row in enumerate(W):
        gate = 1.0 if z[i] > 0 else 0.0
        new_W.append([row[j] - lr_body * 2 * err * v[i] * gate * x[j]
                      for j in range(len(row))])
    return new_W, new_v
```
hint: Do the forward pass once, then compute the update for `v` and for each row of `W` from those same values, using the old `v` in the backbone gradient.
solution: The ReLU gate is 0 for units whose pre-activation is not positive, so their row of `W` does not change (see the second test, where the first unit is inactive). Setting `lr_body = 0` freezes the backbone, which the third test checks, and the last assertion checks that the inputs are not modified in place.

model:
```python
def layer_lrs(n_layers, base_lr, decay):
    """Learning rates that shrink geometrically towards the input layers."""
    return [base_lr * decay ** (n_layers - 1 - i) for i in range(n_layers)]
```
hint: Layer `i` is `n_layers - 1 - i` steps below the last layer, so multiply `base_lr` by `decay` that many times.
solution: The exponent counts how far a layer is from the output, so the first layer gets the smallest rate and the last gets `base_lr`. With `decay = 1.0` all layers share one rate, which the last test checks.
