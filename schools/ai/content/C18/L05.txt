@article
Translate "the cat sleeps" into French: the output may be shorter, longer, or ordered differently than the input. A plain RNN that emits one output per input cannot do that. A **sequence-to-sequence** (seq2seq) model solves it with two networks, an **encoder** that reads the whole source and a **decoder** that writes the target one token at a time. Sutskever, Vinyals and Le (2014) and Cho and colleagues (2014) introduced this design for machine translation using recurrent networks.

### Encoder and decoder
The encoder is a recurrent network (typically an LSTM or GRU) that reads the source tokens $x_1, \dots, x_S$ and produces a final state $\mathbf{c} = \mathbf{h}_S$, the **context vector**. The decoder is another recurrent network whose initial state is $\mathbf{c}$. At each step it reads the previous target token and produces a probability distribution over the vocabulary with a softmax, $p(y_t \mid y_{<t}, \mathbf{x})$. Special tokens mark the boundaries: `<s>` starts decoding and `<eos>` ends it. The probability of a whole target is the product

$$p(\mathbf{y} \mid \mathbf{x}) = \prod_{t=1}^{T} p(y_t \mid y_{<t}, \mathbf{x}).$$

The context vector is a **bottleneck**: a source of 5 tokens or 50 tokens is squeezed into the same fixed number of values. Long sentences suffer, and fixing this is the motivation for attention in the next lesson.

### Training: teacher forcing
We train by maximizing the likelihood of the correct target, which means minimizing the **negative log-likelihood** (cross-entropy summed over steps):

$$L = -\sum_{t=1}^{T} \log p(y^\star_t \mid y^\star_{<t}, \mathbf{x}).$$

With **teacher forcing**, the decoder's input at step $t$ is the *correct* previous token $y^\star_{t-1}$, not its own earlier prediction. This makes every step an independent classification problem and trains fast. The cost is a mismatch (sometimes called exposure bias): at test time the decoder must feed on its own outputs, and an early mistake can propagate. For example, if the correct target is "b `<eos>`" and a trained model assigns probabilities 0.4 and 0.7 to those two tokens, then $L = -\ln 0.4 - \ln 0.7 = -\ln 0.28 = 1.273$ nats. The **perplexity** per token is $\exp(L / T) = \exp(0.6366) = 1.89$, a measure of how many choices the model is effectively choosing among at each step.

### Decoding
At test time we want the most probable target, $\arg\max_{\mathbf{y}} p(\mathbf{y} \mid \mathbf{x})$, but the number of candidates grows as $|V|^T$. **Greedy decoding** picks the most likely token at each step. It is fast but can be wrong: a likely first token may lead to a poor continuation. **Beam search** keeps the $k$ best partial sequences (the **beam**) by total log-probability: at each step it extends every hypothesis with every token, keeps the $k$ best extensions overall, and sets aside those ending in `<eos>`. With $k = 1$ it is greedy decoding. Beam search is a heuristic, not an exact algorithm, and it favors short outputs because every extra token multiplies in a probability below 1; a common fix divides the log-probability by the length.

We use a toy decoder whose next-token distribution depends only on the previous token:

| previous | `a` | `b` | `<eos>` |
|---|---|---|---|
| `<s>` | 0.6 | 0.4 | 0 |
| `a` | 0.1 | 0.5 | 0.4 |
| `b` | 0.2 | 0.1 | 0.7 |

Greedy decoding gives `a`, `b`, `<eos>` with probability $0.6 \cdot 0.5 \cdot 0.7 = 0.21$. But the sequence `b`, `<eos>` has probability $0.4 \cdot 0.7 = 0.28$: greedy missed it, and beam search with $k = 2$ finds it.

### In code
```python
def greedy_decode(P, max_len=10):
    """P[prev][token] is the next-token probability; stop at '<eos>'."""
    prev, out = '<s>', []
    for _ in range(max_len):
        prev = max(P[prev], key=P[prev].get)
        if prev == '<eos>':
            break
        out.append(prev)
    return out

P = {'<s>': {'a': 0.6, 'b': 0.4, '<eos>': 0.0},
     'a': {'a': 0.1, 'b': 0.5, '<eos>': 0.4},
     'b': {'a': 0.2, 'b': 0.1, '<eos>': 0.7}}
print(greedy_decode(P))
```

In practice, frameworks implement the batched version of this loop on a GPU; the logic is the same.

@mistakes
- Computing the loss of a whole sequence as an average of probabilities. The sequence probability is a product, so the log-probability is a sum.
- Thinking beam search is exact. It is a heuristic; larger beams usually find higher-probability sequences but need not find the best one.
- Feeding the model its own predictions during training and calling it teacher forcing. Teacher forcing feeds the ground truth.
- Comparing hypotheses of different lengths by raw log-probability without noticing the bias towards short sequences.

```python
from math import log


def sequence_nll(P, tokens):
    """Teacher-forced negative log-likelihood of tokens under the table P."""
    prev, total = '<s>', 0.0
    for tok in tokens:
        total -= log(P[prev][tok])
        prev = tok
    return total
```
hint: Walk through the tokens keeping the previous one, and subtract the log of each conditional probability.
solution: Teacher forcing means each step conditions on the true previous token, so the previous token is the one from the list, and the losses add. The empty list returns 0 because no token is scored.

model:
```python
from math import log


def beam_search(P, k, max_len):
    """Beam search over a next-token table; returns (tokens, log_prob)."""
    beam = [(0.0, [])]
    finished = []
    for _ in range(max_len):
        cands = []
        for lp, seq in beam:
            prev = seq[-1] if seq else '<s>'
            for tok, p in P[prev].items():
                if p > 0:
                    cands.append((lp + log(p), seq + [tok]))
        cands.sort(key=lambda c: -c[0])
        beam = []
        for lp, seq in cands[:k]:
            if seq[-1] == '<eos>':
                finished.append((lp, seq[:-1]))
            else:
                beam.append((lp, seq))
        if not beam:
            break
    if not finished:
        return None
    lp, seq = max(finished, key=lambda f: f[0])
    return seq, lp
```
hint: Keep the live beam as a list of `(log_prob, tokens)` pairs; each step builds all extensions, sorts them, and splits the top `k` into finished and live.
solution: The finished hypotheses leave the beam, so the beam can shrink and the loop stops when it empties. In the first test greedy decoding ($k = 1$) follows the likely token `a` and never finishes within four steps, while $k = 2$ also keeps `b`, whose continuation `<eos>` has probability 0.9.

model:
```python
def best_normalized(cands):
    """Candidate with the highest length-normalized log-probability."""
    best, best_score = None, None
    for tokens, lp in cands:
        score = lp / len(tokens)
        if best_score is None or score > best_score:
            best, best_score = tokens, score
    return best
```
hint: Divide each log-probability by its length and keep the first candidate that beats the best so far.
solution: Normalizing makes the score an average log-probability per token, so longer hypotheses are no longer penalized just for being long. Using a strict comparison keeps the earlier candidate on ties, as the fourth test checks (both score $-1.0$).
