@article
A network works with numbers, but its inputs are words, characters or subword units. The first layer of almost every language model turns each token into a vector. Then, because self-attention treats its inputs as an unordered set, a second ingredient injects the position of each token.

### Embeddings
An **embedding layer** is a table $\mathbf{E}$ with one row per vocabulary item and $d$ columns. Token $t$ becomes the row $\mathbf{E}_t$. This equals multiplying a one-hot vector by the matrix, $\mathbf{e}_t^\top \mathbf{E}$, but a lookup avoids the multiplication. The table has $|V| \cdot d$ parameters: a vocabulary of 5000 and $d = 64$ means 320,000 numbers. The rows are learned along with the rest of the network by gradient descent, because the lookup is differentiable with respect to the table entries.

Embeddings can also be learned on their own. The word2vec models (Mikolov and colleagues, 2013) train vectors so that a word predicts, or is predicted by, its neighbors in text. Words that occur in similar contexts end up with similar vectors. We measure closeness with the **cosine similarity**

$$\cos(\mathbf{u}, \mathbf{v}) = \frac{\mathbf{u}^\top \mathbf{v}}{\lVert \mathbf{u} \rVert_2 \lVert \mathbf{v} \rVert_2},$$

which is 1 for vectors in the same direction, 0 for orthogonal vectors and $-1$ for opposite ones. In word2vec-style embeddings some relations appear as roughly constant offsets, so $\mathbf{v}_{\text{king}} - \mathbf{v}_{\text{man}} + \mathbf{v}_{\text{woman}}$ lies close to $\mathbf{v}_{\text{queen}}$. This works only approximately and on some relations; it is a useful picture, not a law. The same tokens, in a trained transformer, get **contextual** representations from later layers: the embedding is only the starting point.

### Why position must be added
Self-attention computes each output from scores between pairs of tokens. If you permute the input rows, the output rows are permuted in the same way: the layer is **permutation equivariant**, so "dog bites man" and "man bites dog" look alike to it. We fix this by adding a **positional encoding** $\mathbf{p}_i$ to each token embedding, so the input at position $i$ is $\mathbf{x}_i = \mathbf{E}_{t_i} + \mathbf{p}_i$.

### Sinusoidal encodings
Vaswani and colleagues (2017) used fixed vectors with sines and cosines of geometrically spaced wavelengths. For position $\text{pos}$ and pair index $i = 0, \dots, d/2 - 1$:

$$p_{\text{pos},\,2i} = \sin\!\big(\text{pos}\cdot \omega_i\big), \quad p_{\text{pos},\,2i+1} = \cos\!\big(\text{pos}\cdot \omega_i\big), \quad \omega_i = 10000^{-2i/d}.$$

For $d = 4$ the frequencies are $\omega_0 = 1$ and $\omega_1 = 0.01$. Position 0 is $(0, 1, 0, 1)$, and position 3 is $(\sin 3, \cos 3, \sin 0.03, \cos 0.03) = (0.141, -0.990, 0.030, 1.000)$. Low-index pairs oscillate quickly and distinguish neighboring positions; high-index pairs change slowly and distinguish distant ones, like the digits of a number.

Two properties explain the design. First, each pair at position $\text{pos} + k$ is a rotation of the same pair at $\text{pos}$ by the angle $k\omega_i$, so $\mathbf{p}_{\text{pos}+k}$ is a linear function of $\mathbf{p}_{\text{pos}}$. Second, the dot product depends only on the offset:

$$\mathbf{p}_a^\top \mathbf{p}_b = \sum_{i} \big[\sin(a\omega_i)\sin(b\omega_i) + \cos(a\omega_i)\cos(b\omega_i)\big] = \sum_i \cos\big((a - b)\omega_i\big).$$

This uses $\cos(x - y) = \cos x \cos y + \sin x \sin y$. Also $\mathbf{p}_a^\top \mathbf{p}_a = d/2$ for every position.

### Alternatives
Many models instead learn a table of position embeddings, a second embedding layer with one row per position up to a maximum length; this cannot represent positions beyond the table. Other designs inject *relative* position into the attention scores, for example with learned biases or with rotation-based schemes. Which works best for long sequences is an ongoing research question.

### In code
```python
def embed(tokens, table):
    """Look up the vector of each token id."""
    return [list(table[t]) for t in tokens]

def add_vectors(A, B):
    return [[a + b for a, b in zip(r, s)] for r, s in zip(A, B)]

table = [[1.0, 0.0], [0.0, 1.0], [0.5, 0.5]]
pos = [[0.0, 1.0], [0.84, 0.54]]
print(add_vectors(embed([2, 1], table), pos))
```

PyTorch provides `nn.Embedding` for the lookup; for the encodings, practitioners precompute a matrix of sines and cosines or use `nn.Embedding` for learned positions.

Add sinusoidal encodings for $d = 2$ (positions 0 and 1, $\omega_0 = 1$), then compute scaled dot-product self-attention output for the first token, with the inputs as queries, keys and values.

step: The inputs are $\mathbf{x}_1 = (0, 1) + (0, 1) = (0, 2)$ and $\mathbf{x}_2 = (1, 0) + (0.8415, 0.5403) = (1.8415, 0.5403)$.
step: Scores for the first query $(0, 2)$, scaled by $\sqrt 2$: against $\mathbf{x}_1$, $4/1.4142 = 2.828$; against $\mathbf{x}_2$, $1.0806/1.4142 = 0.764$. The weights are $(0.8874, 0.1126)$.
step: The output is $0.8874\,(0, 2) + 0.1126\,(1.8415, 0.5403) = (0.2074, 1.8356)$.
answer: The weights are $(0.8874, 0.1126)$ and the output is $(0.2074, 1.8356)$. Swapping the order of the tokens changes the positional terms and so the result.

@mistakes
- Believing the transformer knows word order automatically. Without added positions, permuting the tokens just permutes the outputs.
- Confusing the embedding table's size ($|V| \cdot d$) with the number of tokens in a sequence; the table does not grow with sequence length.
- Using the Euclidean distance and the cosine similarity interchangeably: cosine ignores vector length, so two vectors can be far apart in distance but have cosine 1.
- Treating the king minus man plus woman result as exact; it is an approximate, relation-dependent pattern.

model:
```python
from math import cos, sin


def sinusoidal_pe(n, d):
    """Sinusoidal positional encodings for positions 0 .. n-1."""
    rows = []
    for pos in range(n):
        row = []
        for i in range(d // 2):
            w = 10000 ** (-2 * i / d)
            row += [sin(pos * w), cos(pos * w)]
        rows.append(row)
    return rows
```
hint: Loop over positions, then over pair indices `i`; each pair contributes a sine and a cosine of the same angle.
solution: The entries come in (sine, cosine) pairs that share an angle, which is why each row has squared norm $d/2$. The starter returns all zeros, so it fails the position-0 test, where every cosine is 1.

model:
```python
from math import sqrt


def analogy(a, b, c, table):
    """Nearest word by cosine similarity to table[b] - table[a] + table[c]."""
    target = [y - x + z for x, y, z in zip(table[a], table[b], table[c])]

    def cosine(u, v):
        nu = sqrt(sum(p * p for p in u))
        nv = sqrt(sum(p * p for p in v))
        return sum(p * q for p, q in zip(u, v)) / (nu * nv)

    best, best_sim = None, None
    for word, vec in table.items():
        if word in (a, b, c) or all(x == 0 for x in vec):
            continue
        sim = cosine(target, vec)
        if best_sim is None or sim > best_sim:
            best, best_sim = word, sim
    return best
```
hint: Compute the target vector, then scan the other words keeping the one with the largest cosine similarity.
solution: Cosine similarity compares directions, so the word `big`, whose vector is long but points in another direction, does not win by length alone (a plain dot product would pick it). The query words are excluded because the target is often closest to one of them.

```python
from math import cos


def pe_dot(a, b, d):
    """Dot product of two sinusoidal encodings; depends only on a - b."""
    return sum(cos((a - b) * 10000 ** (-2 * i / d)) for i in range(d // 2))
```
hint: Use the identity $\cos(x - y) = \cos x \cos y + \sin x \sin y$ on each sine-cosine pair.
solution: Each pair contributes $\cos((a - b)\omega_i)$, so the dot product depends only on $a - b$ and is symmetric. The fourth test shows that positions $(7, 5)$ and $(4, 2)$, both two apart, give the same value.
