@article
A flexible model can fit its training data almost perfectly and still predict new data badly. Fitting a polynomial of degree $n - 1$ through $n$ points gives zero training error, yet the curve wiggles wildly between the points. This is **overfitting**: the model has learned the noise in the sample, not only the pattern. The opposite failure, **underfitting**, is a model too simple to capture the pattern (a straight line through data that curve), which has high error on training and new data alike.

### Training error versus validation error

Training error always falls as flexibility (polynomial degree, tree depth, number of features) grows. Error on **held-out** data falls at first and then rises, giving a U shape. The best flexibility is near the bottom of the U. A large and growing gap between low training error and high validation error is the signature of overfitting.

### Bias and variance

Suppose $y = f(x) + \varepsilon$ with noise of mean 0 and variance $\sigma^2$. Train the same algorithm on many different training sets of the same size, and look at the prediction $\hat{f}(x_0)$ at one fixed input $x_0$. The expected squared error at $x_0$ decomposes exactly as
$$\mathbb{E}\bigl[(y - \hat{f}(x_0))^2\bigr] = \underbrace{\bigl(\mathbb{E}[\hat f(x_0)] - f(x_0)\bigr)^2}_{\text{bias}^2} + \underbrace{\mathbb{E}\bigl[(\hat f(x_0) - \mathbb{E}[\hat f(x_0)])^2\bigr]}_{\text{variance}} + \underbrace{\sigma^2}_{\text{irreducible noise}}.$$
**Bias** is the systematic error from wrong assumptions (a line cannot be a parabola). **Variance** is how much the fitted function changes from one training set to another. Simple models tend to have high bias and low variance; flexible models, low bias and high variance. No model removes $\sigma^2$. More data reduces variance but not bias.

### Ridge regression

**Ridge regression** discourages large coefficients by adding an L2 penalty:
$$\min_{\beta}\ \sum_i (y_i - \beta_0 - x_i^\top\beta)^2 + \lambda\sum_{j=1}^{d}\beta_j^2, \qquad \lambda \ge 0.$$
The intercept $\beta_0$ is not penalized. The solution is $\hat\beta = (X^\top X + \lambda I)^{-1}X^\top y$ for centered features, and $X^\top X + \lambda I$ is invertible even when $X^\top X$ is not. For one feature with the data centered, $\hat\beta_1 = S_{xy}/(S_{xx} + \lambda)$ and $\hat\beta_0 = \bar{y} - \hat\beta_1\bar{x}$. Increasing $\lambda$ shrinks coefficients toward 0: bias goes up, variance goes down. Because the penalty depends on the size of the coefficients, features must be standardized first. $\lambda$ is a **hyperparameter** chosen on validation data (week 6), not learned from the training loss.

### The lasso

The **lasso** uses the L1 penalty $\lambda\sum_j|\beta_j|$. Its geometry produces coefficients that are exactly zero, so it performs feature selection. With orthonormal features ($X^\top X = I$) and the loss $\frac12\lVert y - X\beta\rVert^2 + \lambda\lVert\beta\rVert_1$, each coefficient is the least-squares coefficient passed through the **soft-threshold**
$$S_\lambda(z) = \operatorname{sign}(z)\max(|z| - \lambda,\ 0).$$
Small coefficients become exactly 0 and large ones are shrunk by $\lambda$. Ridge instead shrinks every coefficient proportionally and rarely makes any exactly 0.

### Other ways to control complexity

**Early stopping** halts gradient descent when validation loss stops improving, which acts like regularization. Models with many parameters also use **weight decay** (the L2 penalty in gradient form), **dropout** (week 12) and **data augmentation**. The common principle: constrain the model so that it cannot use the freedom it has to memorize noise.

@example
title: Ridge shrinks the slope
problem: Fit a ridge line to the points $(1, 2), (2, 4), (3, 6)$ with $\lambda = 2$ (intercept unpenalized).
step: The means are $\bar{x} = 2$ and $\bar{y} = 4$. The centered values are $x - \bar x = (-1, 0, 1)$ and $y - \bar y = (-2, 0, 2)$.
step: $S_{xy} = 2 + 0 + 2 = 4$ and $S_{xx} = 1 + 0 + 1 = 2$.
step: With $\lambda = 0$ the slope is $4/2 = 2$, the exact line $\hat y = 2x$.
step: With $\lambda = 2$ the slope is $4/(2 + 2) = 1$, and the intercept is $\bar y - 1\cdot\bar x = 4 - 2 = 2$, so $\hat y = 2 + x$.
step: The penalty halved the slope. The fit to this noise-free data is worse, which is the price of lower variance on noisy data.
answer: Slope $1$ and intercept $2$.

@example
title: Decomposing the error at one point
problem: At $x_0$ the true value is $f(x_0) = 3$ and the noise variance is $\sigma^2 = 0.5$. Over repeated training sets, model A predicts $4$ or $6$ (equally often) and model B predicts $1$ or $5$ (equally often). Compare their expected squared errors.
step: Model A: the mean prediction is 5, so $\text{bias}^2 = (5 - 3)^2 = 4$. The predictions deviate by $\pm 1$, so the variance is $1$.
step: Model B: the mean prediction is 3, so $\text{bias}^2 = 0$. The predictions deviate by $\pm 2$, so the variance is $4$.
step: Add the noise: A has $4 + 1 + 0.5 = 5.5$ and B has $0 + 4 + 0.5 = 4.5$.
step: B has the higher variance but the lower total error, because A's bias is large. Neither bias nor variance alone decides.
answer: A: $5.5$, B: $4.5$.

@mistakes
- Choosing the model with the lowest training error: more flexible models always win on training data.
- Forgetting to standardize features before ridge or the lasso, so the penalty punishes features by their units instead of their usefulness.
- Penalizing the intercept, which makes the fit depend on where the targets are centered.
- Believing that variance and bias can both be driven to zero by choosing the right model: the noise term $\sigma^2$ remains.

model:
```python
def ridge_fit_1d(xs, ys, lam):
    n = len(xs)
    xbar = sum(xs) / n
    ybar = sum(ys) / n
    sxy = sum((x - xbar) * (y - ybar) for x, y in zip(xs, ys))
    sxx = sum((x - xbar) ** 2 for x in xs)
    slope = sxy / (sxx + lam)
    return (ybar - slope * xbar, slope)
```
hint: This is the least-squares fit of week 2 with $\lambda$ added to the denominator of the slope.
solution: Compute the centered sums, divide `sxy` by `sxx + lam`, and set the intercept so the line passes through the point of means. With a huge `lam` the slope is about 0 and the line is the horizontal line at the mean of `ys`.

model:
```python
def bias_variance(true_value, predictions):
    n = len(predictions)
    mean = sum(predictions) / n
    bias_sq = (mean - true_value) ** 2
    variance = sum((p - mean) ** 2 for p in predictions) / n
    return (bias_sq, variance)
```
hint: The bias uses only the mean prediction; the variance uses the spread of predictions around that mean.
solution: Compute the mean prediction once. Squared bias is its squared distance from the truth, and variance is the average squared distance of the predictions from their own mean. Adding the noise variance $\sigma^2$ gives the expected squared error.

model:
```python
def early_stopping_epoch(val_losses, patience):
    best_loss = float("inf")
    best_index = 0
    for i, loss in enumerate(val_losses):
        if loss < best_loss:
            best_loss = loss
            best_index = i
        elif i - best_index >= patience:
            break
    return best_index
```
hint: Remember the best loss and the epoch where it occurred.
hint: A loss that only ties the best does not count as an improvement. The stopping check applies when the current epoch is not an improvement.
solution: Update `best_index` only on a strictly lower loss, and break when the current epoch is at least `patience` epochs after the best one. In the first example the best is epoch 2, and at epoch 4 the distance is 2, so scanning stops before epoch 6 (loss 2) is reached.

```python
def soft_threshold(z, t):
    if z > t:
        return z - t
    if z < -t:
        return z + t
    return 0.0
```
hint: There are three cases: large positive, large negative and small in size.
solution: Shrink the value toward 0 by `t`, and return exactly 0 when `|z| <= t`. This exact-zero behavior is why the lasso selects features.
