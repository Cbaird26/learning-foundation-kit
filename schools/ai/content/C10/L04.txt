@article
Linear regression predicts any real number, which is wrong for a probability. **Logistic regression** fixes this for binary classification ($y \in \{0, 1\}$) by passing a linear score through the **sigmoid** (logistic) function
$$\sigma(z) = \frac{1}{1 + e^{-z}}, \qquad p(y = 1 \mid x) = \sigma(w^\top x + b).$$
The sigmoid maps the real line to $(0, 1)$, with $\sigma(0) = 0.5$, $\sigma(-z) = 1 - \sigma(z)$ and $\sigma'(z) = \sigma(z)\bigl(1 - \sigma(z)\bigr)$.

### Odds and log-odds

The **odds** of an event of probability $p$ are $p/(1-p)$, and the **log-odds** (logit) is $\ln\frac{p}{1-p}$. Inverting the sigmoid shows that logistic regression says the log-odds are linear in the features: $\ln\frac{p}{1-p} = w^\top x + b$. So increasing feature $j$ by one unit adds $w_j$ to the log-odds, which multiplies the odds by $e^{w_j}$. The effect on the probability itself depends on where you start.

### Decision boundary

Predict class 1 when $p \ge 0.5$, which is exactly when $w^\top x + b \ge 0$. The boundary $w^\top x + b = 0$ is a line (a hyperplane in higher dimensions), so logistic regression is a **linear classifier**. A different threshold (for example 0.2) trades false negatives for false positives; week 6 studies that choice.

### The log loss

Squared error works poorly with probabilities (its loss surface is non-convex in $w$ for this model). Instead use maximum likelihood: the probability the model assigns to the observed label is $p_i$ if $y_i = 1$ and $1 - p_i$ if $y_i = 0$. Minimizing the average negative log of that probability gives the **log loss** (binary cross-entropy)
$$L(w, b) = -\frac{1}{n}\sum_{i=1}^{n}\Bigl[y_i \ln p_i + (1 - y_i)\ln(1 - p_i)\Bigr].$$
A confident wrong prediction is punished severely: for $y = 1$ the loss is $-\ln p$, which is $0.105$ at $p = 0.9$ but $2.30$ at $p = 0.1$ and grows without bound as $p \to 0$. The loss is convex in $(w, b)$.

### The gradient

Using $\sigma' = \sigma(1 - \sigma)$, the terms cancel and the gradient takes the same shape as in linear regression:
$$\frac{\partial L}{\partial w_j} = \frac{1}{n}\sum_i (p_i - y_i)\,x_{ij}, \qquad \frac{\partial L}{\partial b} = \frac{1}{n}\sum_i (p_i - y_i).$$
Gradient descent therefore repeats: compute all $p_i$ with the current parameters, then update $w$ and $b$ with the gradient above. There is no closed form, which is why logistic regression is the first model in this course that needs an optimizer.

```python
import math

def sigmoid(z):
    return 1 / (1 + math.exp(-z))
```

This simple version overflows for large negative $z$ (for example $z = -1000$ makes `math.exp(1000)` raise `OverflowError`); a careful implementation computes `exp(z) / (1 + exp(z))` when $z < 0$.

### Separable data and regularization

If a line separates the two classes perfectly, the loss keeps decreasing as $\lVert w\rVert$ grows, so the minimizer does not exist and the weights drift to infinity. Adding an L2 penalty (week 5) keeps them finite. Features should be standardized, as for any gradient-based method.

### More than two classes

For $K$ classes, **softmax regression** uses a score $z_k$ for each class and sets $p_k = e^{z_k}/\sum_j e^{z_j}$; the loss is the average of $-\ln p_{y_i}$. With $K = 2$ it reduces to logistic regression.

@example
title: From features to a class
problem: A model has $w = 1$ and $b = -2$ for one feature $x$. Find $p(y=1 \mid x)$ for $x = 3$, the predicted class, and the decision boundary.
step: The score is $z = wx + b = 3 - 2 = 1$.
step: The probability is $\sigma(1) = 1/(1 + e^{-1}) \approx 0.731$.
step: Since $0.731 \ge 0.5$ (equivalently $z \ge 0$), the predicted class is 1.
step: The boundary is where $z = 0$: $x - 2 = 0$, so $x = 2$. Inputs above 2 are classified 1 and inputs below 2 are classified 0.
answer: $p \approx 0.731$, class 1, boundary at $x = 2$.

@example
title: One gradient step
problem: Data: $x = (1, 3)$, $y = (0, 1)$. Starting from $w = 0$, $b = 0$ with $\eta = 1$, do one step of gradient descent on the log loss.
step: With $w = b = 0$ the score is 0 for both examples, so $p_1 = p_2 = 0.5$.
step: The differences $p_i - y_i$ are $0.5$ and $-0.5$.
step: $\partial L/\partial w = \frac{1}{2}\bigl(0.5 \cdot 1 + (-0.5)\cdot 3\bigr) = -0.5$.
step: $\partial L/\partial b = \frac{1}{2}(0.5 - 0.5) = 0$.
step: The update is $w = 0 - 1(-0.5) = 0.5$ and $b = 0$. The positive weight raises $p$ for large $x$, as the data suggest.
answer: $w = 0.5$, $b = 0$.

@mistakes
- Treating the output of the sigmoid as a class instead of a probability that must be compared with a threshold.
- Evaluating $\sigma(z)$ naively for large negative $z$ and getting an overflow, instead of using the numerically stable form.
- Using the squared error as the training loss for classification, which gives a poorly behaved optimization problem.
- Reading $w_j$ as a change in probability: it is a change in log-odds.

```python
import math

def sigmoid(z):
    if z >= 0:
        return 1 / (1 + math.exp(-z))
    e = math.exp(z)
    return e / (1 + e)
```
hint: For $z \ge 0$ the expression $e^{-z}$ is at most 1, so the usual formula is safe.
hint: For $z < 0$ multiply the numerator and denominator by $e^{z}$ to get $e^{z}/(1 + e^{z})$, which only exponentiates a negative number.
solution: Use `1 / (1 + exp(-z))` when `z >= 0` and the algebraically equal `exp(z) / (1 + exp(z))` when `z < 0`. In both branches the exponential argument is non-positive, so it never overflows.

model:
```python
import math

def log_loss(ys, ps):
    total = 0.0
    for y, p in zip(ys, ps):
        total += y * math.log(p) + (1 - y) * math.log(1 - p)
    return -total / len(ys)
```
hint: For each example only one of the two terms is nonzero, because $y$ is 0 or 1.
solution: Sum `y * log(p) + (1 - y) * log(1 - p)` over the examples, negate, and divide by `n`. A label of 1 contributes $-\ln p$ and a label of 0 contributes $-\ln(1-p)$.

model:
```python
import math

def train_logistic(xs, ys, lr, steps):
    n = len(xs)
    w = 0.0
    b = 0.0
    for _ in range(steps):
        ps = [1 / (1 + math.exp(-(w * x + b))) for x in xs]
        gw = sum((p - y) * x for p, y, x in zip(ps, ys, xs)) / n
        gb = sum(p - y for p, y in zip(ps, ys)) / n
        w, b = w - lr * gw, b - lr * gb
    return (w, b)
```
hint: In each step first compute the list of probabilities from the current `w` and `b`.
hint: The gradient for `w` weights each difference $p_i - y_i$ by $x_i$; the gradient for `b` does not.
solution: Compute all probabilities, then both gradients, then update both parameters together. For the separable data the boundary $-b/w$ settles between the classes (near $x = 3.5$) while $\lVert w\rVert$ keeps growing slowly, which is why the test checks predictions rather than exact weights.
