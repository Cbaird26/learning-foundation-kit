@article
Try printing an object of one of your classes. You get something like `<__main__.Dog object at 0x7f...>`, which is useless. Try `Dog("Rex") == Dog("Rex")` and you get `False`. Python is not being unfair: it only knows how to compare and print things when the class tells it how. The way to tell it is with **special methods**, whose names start and end with two underscores (people call them *dunder methods*). You never call them directly; Python calls them when you use the matching syntax.

### Printing: `__str__` and `__repr__`

```python
class Card:
    def __init__(self, rank, suit):
        self.rank = rank
        self.suit = suit

    def __str__(self):
        return f"{self.rank} of {self.suit}"

    def __repr__(self):
        return f"Card({self.rank!r}, {self.suit!r})"
```

`__str__` gives the friendly text. It is used by `print(card)`, `str(card)` and f-strings. `__repr__` gives an unambiguous developer view, ideally text that looks like the code that creates the object. It is used by the interactive prompt, by `repr(card)`, and **when an object is shown inside a list or other container**. If you define only `__repr__`, `print` falls back to it. Both must **return** a string, not print one.

### Equality: `__eq__`

By default `a == b` means `a is b`. To compare by content, define `__eq__`:

```python
    def __eq__(self, other):
        if not isinstance(other, Card):
            return NotImplemented
        return (self.rank, self.suit) == (other.rank, other.suit)
```

Returning `NotImplemented` (not `False`) for a type you do not understand lets Python try the other side. Python derives `!=` from `__eq__` automatically. One catch: a class that defines `__eq__` without `__hash__` becomes **unhashable** (`hash(card)` raises `TypeError`), so it cannot go in a set or be a dictionary key. Objects that are equal must have equal hashes, so if you want hashing, define `__hash__` too, for example `hash((self.rank, self.suit))`, and only for objects that do not change.

### Ordering and arithmetic

`a < b` calls `a.__lt__(b)`. Once a class has `__lt__`, `sorted(list_of_objects)` works, because sorting only needs `<`. Likewise `a + b` calls `__add__`, which should usually return a **new** object and leave both operands alone. Related methods: `__le__`, `__gt__`, `__ge__`, `__sub__`, `__mul__`.

```python
class Vec:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __add__(self, other):
        return Vec(self.x + other.x, self.y + other.y)
```

### Acting like a collection

| syntax | calls |
|---|---|
| `len(obj)` | `obj.__len__()` |
| `obj[i]` | `obj.__getitem__(i)` |
| `x in obj` | `obj.__contains__(x)` |
| `bool(obj)` | `__bool__`, otherwise `__len__() != 0` |

### Do not overdo it

Define special methods when the meaning is natural (a `Vec` really can be added). Adding two `Student` objects is not meaningful, so do not define `__add__` there. For classes that mostly hold data, the standard library's `@dataclass` decorator writes `__init__`, `__repr__` and `__eq__` for you; knowing the methods underneath tells you what it generates.

@example
title: What does each syntax call?
problem: What does this program print?

```python
class Pair:
    def __init__(self, a, b):
        self.a = a
        self.b = b

    def __str__(self):
        return f"<{self.a},{self.b}>"

    def __eq__(self, other):
        return self.a == other.a and self.b == other.b

    def __len__(self):
        return 2

p = Pair(1, 2)
q = Pair(1, 2)
print(p)
print(p == q, p is q)
print(len(p))
```
step: `print(p)` calls `__str__`, which returns `<1,2>`.
step: `p == q` calls `__eq__`: both fields match, so it is `True`. `p is q` asks for identity, and they are two objects, so it is `False`.
step: `len(p)` calls `__len__`, which returns `2` regardless of the fields.
answer: The output is `<1,2>`, then `True False`, then `2`.

@example
title: Making a class sortable
problem: Give `Version(major, minor)` an `__lt__` method and use it to sort a list.
step: Compare version numbers as pairs: major first, minor only as a tie-breaker. Tuples already compare that way.
step: Write the method; return `NotImplemented` for foreign types:

```python
class Version:
    def __init__(self, major, minor):
        self.major = major
        self.minor = minor

    def __lt__(self, other):
        if not isinstance(other, Version):
            return NotImplemented
        return (self.major, self.minor) < (other.major, other.minor)
```
step: Sort a list: `sorted([Version(1, 10), Version(1, 2), Version(0, 9)])` puts `0.9` first, then `1.2`, then `1.10`, because `2 < 10` as numbers.

@mistakes
- Using `print` inside `__str__` instead of `return`; the method must hand back a string, and returning `None` raises `TypeError`.
- Expecting `==` to compare attributes without defining `__eq__`; the default is identity.
- Defining `__eq__` and then being surprised that the objects cannot go in a set or be dictionary keys.
- Mutating `self` inside `__add__` and returning it, which changes the left operand. `a + b` should build a new object.

```python
class Vec:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __add__(self, other):
        return Vec(self.x + other.x, self.y + other.y)

    def __eq__(self, other):
        if not isinstance(other, Vec):
            return NotImplemented
        return self.x == other.x and self.y == other.y

    def __str__(self):
        return f"({self.x}, {self.y})"
```
hint: `__add__` must build and return a new `Vec`; do not change `self`.

@practice code
prompt: Write a class `Money` with attribute `cents` (an int) set by `Money(cents)`. Define `__lt__` so money compares by `cents`, and `__eq__` so two `Money` objects are equal when their cents are equal. Then `sorted`, `max` and `>` should all work on `Money` objects, using only the methods you wrote.
starter:
```python
class Money:
    pass
```
tests:
```python
a = Money(500)
b = Money(250)
c = Money(500)
assert b < a
assert not (a < b)
assert a == c
assert a != b
assert a > b
assert [m.cents for m in sorted([a, b, Money(900), Money(1)])] == [1, 250, 500, 900]

```
model:
```python
class Money:
    def __init__(self, cents):
        self.cents = cents

    def __lt__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        return self.cents < other.cents

    def __eq__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        return self.cents == other.cents
```
hint: Compare the `cents` attributes in both methods.
hint: You do not need `__gt__`: for `a > b` Python tries the reflected `b < a` when `a` has no `__gt__`.
solution: `__lt__` returns `self.cents < other.cents` and `__eq__` returns `self.cents == other.cents`. `sorted` and `min` only need `<`, and `a > b` is answered by Python calling `b.__lt__(a)`.

Make `len(p)` give the number of songs, `p[i]` give the song at index `i` (negative indexes work like a list), and `"x" in p` say whether a title is present.
```python
class Playlist:
    pass
```
tests:
```python
titles = ["intro", "song", "outro"]
p = Playlist(titles)
assert len(p) == 3
assert p[0] == "intro"
assert p[-1] == "outro"
```

model:
```python
class Playlist:
    def __init__(self, songs):
        self._songs = list(songs)

    def __len__(self):
        return len(self._songs)

    def __getitem__(self, i):
        return self._songs[i]

    def __contains__(self, title):
        return title in self._songs
```
hint: Store `list(songs)` rather than `songs` itself, so the playlist has its own list.
hint: Each special method can simply delegate to the stored list.
solution: Copy the list with `list(songs)` in `__init__`. `__len__`, `__getitem__` and `__contains__` each forward to that list, which also gives the right `IndexError` for a bad index.

@quiz mc
prompt: This class defines `__eq__` but nothing else about hashing.

```python
class Tag:
    def __init__(self, name):
        self.name = name

    def __eq__(self, other):
        return isinstance(other, Tag) and self.name == other.name

seen = {Tag("a"), Tag("a")}
```
What happens when the last line runs?
choice: `seen` holds one `Tag`, because the two tags are equal
choice: `seen` holds two `Tag` objects, because they are different objects
choice*: It raises `TypeError`, because defining `__eq__` without `__hash__` makes `Tag` unhashable
choice: It raises `AttributeError`, because `Tag` has no `__len__`
hint: A set needs to hash its elements.
solution: Defining `__eq__` in a class sets its `__hash__` to `None` unless you also define `__hash__`, so `Tag` objects cannot be set members or dictionary keys. Adding `def __hash__(self): return hash(self.name)` would give the one-element set.
