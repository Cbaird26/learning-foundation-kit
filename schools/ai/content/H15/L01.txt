@article
So far your programs have kept data in separate variables and processed it with separate functions. That works for a handful of values, but a program about 30 students, 200 bank accounts or 50 enemies in a game needs a way to keep each thing's data and behavior together. **Object-oriented programming (OOP)** does exactly that.

### Classes and objects

A **class** is a blueprint: it says what data a kind of thing has and what it can do. An **object** (also called an **instance**) is one particular thing built from that blueprint. One class `Dog` can produce many dog objects, each with its own name.

```python
class Dog:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return self.name + " says woof"

rex = Dog("Rex")
fido = Dog("Fido")
print(rex.speak())
print(fido.name)
```

This prints `Rex says woof` and then `Fido`. Reading it piece by piece:

- `class Dog:` starts the definition. By convention class names use `CapitalizedWords`.
- `__init__` is the **initializer**. Python calls it automatically whenever you write `Dog("Rex")`, right after it creates a new empty object. Its job is to set up the object's starting data.
- `self` is the first parameter of every method. It is the object the method is working on. You never pass it yourself: in `rex.speak()`, Python passes `rex` as `self`.
- `self.name = name` creates an **attribute**, a variable stored inside the object. Every Dog has its own `name`.
- `speak` is a **method**: a function defined inside a class that acts on one object.

### Each object is separate

`rex` and `fido` are two objects. Changing `fido.name = "Max"` does not affect `rex`. Each call to `Dog(...)` builds a brand-new object.

### Names are references

A variable does not contain an object; it **refers** to it. So assignment copies the reference, not the object:

```python
a = Dog("Rex")
b = a          # b refers to the SAME object as a
b.name = "Zed"
print(a.name)  # Zed
print(a is b)  # True
```

Here there is only one Dog and two names for it (an **alias**). Use `is` to ask "are these the same object?". To get a second, independent object you must call the class again.

### Looking at an object

`type(rex)` is `Dog`, and `isinstance(rex, Dog)` is `True`. You can also read and change attributes from outside with dot notation (`rex.name`). In week 4 you will see why you often want to control that, but for now it is the simplest way to see what an object holds.

### Why bother?

Compare `rex.speak()` with a loose function `speak(name)`. The object carries its own data, so a method needs no extra arguments for it, and a program that stores a list of `Dog` objects can ask each one to `speak()` without knowing how they work inside. That idea, bundling data with the code that uses it, is the foundation of everything else in this course.

@example
title: Tracing objects and aliases
problem: What does this program print?

```python
class Pet:
    def __init__(self, name):
        self.name = name
        self.fed = False

    def feed(self):
        self.fed = True

p = Pet("Mia")
q = Pet("Leo")
r = p
r.feed()
print(p.fed, q.fed)
print(p is r, p is q)
```
step: `Pet("Mia")` creates object 1 with `name = "Mia"` and `fed = False`; `p` refers to it.
step: `Pet("Leo")` creates a separate object 2; `q` refers to it. `r = p` creates no new object: `r` is a second name for object 1.
step: `r.feed()` runs with `self` being object 1, so object 1's `fed` becomes `True`. Object 2 is untouched.
step: The first `print` shows `p.fed` (object 1, `True`) and `q.fed` (object 2, `False`).
step: `p is r` is `True` (same object) and `p is q` is `False`, so the second line is `True False`.
answer: The program prints `True False` and then `True False`.

@example
title: Writing a small class
problem: Write a class `Player` with a name and a score that starts at 0, and a method `add_points(n)` that adds `n` to the score.
step: Start the class and write `__init__`, which stores the name and gives the score its starting value:

```python
class Player:
    def __init__(self, name):
        self.name = name
        self.score = 0
```
step: The method takes `self` first, then its own parameter. It changes the attribute stored in the object:

```python
    def add_points(self, n):
        self.score += n
```
step: Use it. Each Player keeps its own score:

```python
a = Player("Ana")
b = Player("Bo")
a.add_points(5)
a.add_points(3)
print(a.score, b.score)
```
step: Ana's object ends at `8` and Bo's is still `0`, so this prints `8 0`.

@mistakes
- Forgetting `self` as the first parameter of a method, which gives an error such as "takes 1 positional argument but 2 were given" when you call it.
- Writing `name = name` instead of `self.name = name` in `__init__`; the value is thrown away when the method ends and the object gets no attribute.
- Thinking `b = a` makes a copy of an object. It only gives the same object a second name, so a change through `b` is visible through `a`.
- Calling the class without parentheses (`rex = Dog`), which makes `rex` another name for the class, not an object.

```python
class Rectangle:
```

```python
r = Rectangle(3, 4)
```

```python
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def perimeter(self):
```

@practice code
prompt: Write a class `Point` with attributes `x` and `y` set by `Point(x, y)`. Add a method `move(dx, dy)` that changes the point **in place** (adds `dx` to `x` and `dy` to `y`) and returns nothing, and a method `is_origin()` that returns `True` only when both coordinates are `0`.
starter:
```python
class Point:
    pass
```
tests:
```python
p = Point(1, 2)
p.move(3, -5)
assert p.x == 4
assert p.y == -3
assert p.is_origin() is False
q = Point(0, 0)
assert q.is_origin() is True
assert Point(0, 1).is_origin() is False
alias = p
alias.move(-4, 3)
assert p.is_origin() is True
assert p.move(0, 0) is None
```
model:
```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def move(self, dx, dy):
        self.x += dx
        self.y += dy

    def is_origin(self):
        return self.x == 0 and self.y == 0
```
hint: `move` should modify `self.x` and `self.y`, not create a new `Point`.
hint: `is_origin` needs both conditions to hold: use `and`.
solution: `move` updates the attributes with `+=` and has no `return`, so it returns `None`. Because the object itself changes, an alias sees the change too, which the test with `alias` checks. `is_origin` returns `self.x == 0 and self.y == 0`.

@quiz code
prompt: Write a class `Light` for a light switch. A new `Light()` is off: its attribute `is_on` is `False`. The method `toggle()` flips `is_on` and returns the new value. The attribute `toggles` counts how many times `toggle()` has been called on that light (it starts at `0`).
starter:
```python
class Light:
    pass
```
tests:
```python
a = Light()
assert a.is_on is False
assert a.toggles == 0
assert a.toggle() is True
assert a.toggle() is False
assert a.toggle() is True
assert a.toggles == 3
b = Light()
assert b.toggles == 0
assert b.is_on is False
```
model:
```python
class Light:
    def __init__(self):
        self.is_on = False
        self.toggles = 0

    def toggle(self):
        self.is_on = not self.is_on
        self.toggles += 1
        return self.is_on
```
hint: Set both attributes in `__init__`, so every new light starts fresh.
hint: `not self.is_on` gives the opposite value; assign it back to the attribute before returning.
solution: `__init__` sets `is_on = False` and `toggles = 0` for each new object. `toggle` assigns `not self.is_on` back to the attribute, adds 1 to the counter and returns the new state. Creating `b` afterwards shows that lights do not share counts.
