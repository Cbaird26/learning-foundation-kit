@article
A paper reports "a 1.3-billion-parameter model", and a second paper reports a model of "the same size" that has a different memory footprint and a different training cost. Both can be right, because a parameter count depends on conventions that papers often leave implicit: are the embedding matrices counted, are the input and output embeddings shared, are biases and normalization gains counted? A researcher who can count parameters from a configuration can check a claim in seconds and can see where a model's capacity lives. This lesson builds the counting from the architecture up.

### The model

A **language model** assigns a probability to a sequence of tokens by the chain rule, $p(t_1,\dots,t_n) = \prod_{i=1}^{n} p(t_i \mid t_{<i})$. A **decoder-only transformer** (the architecture family introduced by the transformer of Vaswani and colleagues, 2017, with the decoder stack used alone as in the GPT line of work) computes each factor as follows. Let $n$ be the sequence length and $d$ the model width.

1. **Embedding.** Each token index $t_i$ selects a row of a matrix $\mathbf{E} \in \mathbb{R}^{V \times d}$, where $V$ is the vocabulary size. Position information is added: either a learned matrix with $n_{\text{ctx}}$ rows, or a fixed scheme such as sinusoids (Vaswani and colleagues, 2017) or rotary embeddings (Su and colleagues, 2021) that have no parameters.
2. **Blocks.** The residual stream $\mathbf{X} \in \mathbb{R}^{n \times d}$ passes through $L$ identical blocks. In the common pre-norm arrangement, a block computes $\mathbf{X} \leftarrow \mathbf{X} + \operatorname{Attn}(\operatorname{LN}(\mathbf{X}))$ and then $\mathbf{X} \leftarrow \mathbf{X} + \operatorname{MLP}(\operatorname{LN}(\mathbf{X}))$, with layer normalization (Ba, Kiros and Hinton, 2016).
3. **Output.** A final layer norm and a matrix of shape $d \times V$ turn each row into logits, and a softmax gives $p(t_{i+1} \mid t_{\le i})$.

### Causal self-attention

With $h$ heads and head width $d_k = d/h$, head $j$ computes queries, keys and values $\mathbf{Q} = \mathbf{X}\mathbf{W}^Q_j$, $\mathbf{K} = \mathbf{X}\mathbf{W}^K_j$, $\mathbf{V} = \mathbf{X}\mathbf{W}^V_j$ and then

$$\operatorname{head}_j = \operatorname{softmax}\!\Big(\frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d_k}} + \mathbf{M}\Big)\mathbf{V}, \qquad M_{ab} = \begin{cases} 0 & b \le a \\ -\infty & b > a. \end{cases}$$

The **causal mask** $\mathbf{M}$ stops position $a$ from reading positions after it, so the loss at all $n$ positions can be computed in one parallel forward pass without leaking the answer. The heads are concatenated and multiplied by $\mathbf{W}^O \in \mathbb{R}^{d \times d}$. The division by $\sqrt{d_k}$ matters: if query and key entries are independent with mean 0 and variance 1, a dot product has variance $d_k$, so without scaling the softmax would saturate as $d_k$ grows and its gradients would vanish. The $n \times n$ score matrix per head is why attention cost grows quadratically in sequence length.

The MLP applies two linear maps with a nonlinearity between them: widths $d \to d_{\text{ff}} \to d$, with $d_{\text{ff}} = 4d$ in the original design. Gated variants change the number of matrices, so always read the configuration, not just the family name.

### Counting parameters

Conventions first. Here we count every weight matrix, state whether biases and layer-norm gains and shifts are included, and say whether the output matrix is **tied** to $\mathbf{E}$ (the same $V \times d$ matrix used for input and output). Per block:

| part | weights | biases | layer norm (gain and shift) |
|---|---|---|---|
| attention: $\mathbf{W}^Q,\mathbf{W}^K,\mathbf{W}^V,\mathbf{W}^O$ | $4d^2$ | $4d$ | |
| MLP | $2 d\, d_{\text{ff}}$ | $d_{\text{ff}} + d$ | |
| two layer norms | | | $4d$ |

Take $d = 512$, $L = 6$, $d_{\text{ff}} = 2048$, $V = 32{,}000$, $n_{\text{ctx}} = 1024$ with learned positions, tied embeddings, and a final layer norm.

| quantity | parameters |
|---|---|
| token embedding $V d$ | 16,384,000 |
| position embedding $n_{\text{ctx}} d$ | 524,288 |
| one block, weights only | 3,145,728 |
| one block, with biases and norms | 3,152,384 |
| six blocks, with biases and norms | 18,914,304 |
| final layer norm | 1,024 |
| **total, all counted** | **35,823,616** |
| total, matrices only | 35,782,656 |

The two conventions differ by 0.1 percent, so for large models the matrices decide the count. Untying the output would add another 16,384,000. Notice that nearly half of this small model sits in the embedding; in a model with $d = 4096$ and $L = 32$ the embedding is a small fraction, because blocks grow as $d^2$ and the embedding only as $d$. The count that matters for training cost is usually the non-embedding parameters, as we will see in the lessons on scaling.

### Counting compute and memory

A matrix multiplication of an $n \times a$ by an $a \times b$ matrix takes about $2nab$ floating-point operations, one multiply and one add per term. Each weight is used once per token in a forward pass, so the forward pass costs roughly $2N$ FLOPs per token for $N$ non-embedding weights, plus the attention scores, which cost about $4 n\, d$ per token per layer. Training adds a backward pass of about twice that, giving the "6 per parameter per token" rule used from lesson 3 on. Memory for activations of the score matrices is $h n^2$ entries per layer per sequence unless a fused algorithm avoids storing them (Dao and colleagues, 2022).

What is established and what is not: the architecture above and its counting are exact. Why the transformer works better than recurrent models at scale, and which of its components matter, is argued from experiments; many proposed modifications turn out to matter less than scale.

@example
title: Counting a tiny model
problem: A decoder-only model has $d = 64$, $L = 2$, $d_{\text{ff}} = 256$, $V = 1000$, learned positions with $n_{\text{ctx}} = 128$, tied embeddings, a final layer norm, and biases and layer norms counted. How many parameters does it have?
step: Embeddings: $V d = 64{,}000$ and positions $n_{\text{ctx}} d = 8{,}192$, so 72,192.
step: One block's attention: $4d^2 = 16{,}384$ weights plus $4d = 256$ biases, so 16,640.
step: One block's MLP: $2 d\, d_{\text{ff}} = 32{,}768$ weights plus $d_{\text{ff}} + d = 320$ biases, so 33,088. Two layer norms add $4d = 256$. One block has $16{,}640 + 33{,}088 + 256 = 49{,}984$.
step: Two blocks: 99,968. Add the final layer norm $2d = 128$ and the embeddings: $72{,}192 + 99{,}968 + 128 = 172{,}288$. Tying means no separate output matrix.
answer: 172,288 parameters (170,496 if only matrices are counted).

@example
title: Causal attention for one position
problem: In one head, the second token (position 2) has scaled scores $0$ against the first token and $\ln 2$ against itself. The value vectors are $\mathbf{v}_1 = (3, 0)$ and $\mathbf{v}_2 = (0, 6)$. What is the head's output at position 2?
step: Position 2 may read positions 1 and 2 only, so the softmax runs over the two scores $(0, \ln 2)$.
step: The exponentials are $1$ and $2$, so the weights are $1/3$ and $2/3$.
step: The output is $\tfrac13(3, 0) + \tfrac23(0, 6) = (1, 4)$.
answer: $(1, 4)$.

@mistakes
- Counting the tied embedding twice: if the output matrix shares $\mathbf{E}$, the $V \times d$ block appears once in the total.
- Forgetting $\mathbf{W}^O$: attention has four $d \times d$ matrices in total, not three.
- Mixing conventions when comparing papers: a count with biases and layer norms and a count of matrices only differ, and so do counts with and without embeddings. State yours.
- Applying the causal mask after the softmax instead of before: zeroing weights afterward leaves rows that do not sum to one.

@practice mc
prompt: Why are the attention scores divided by $\sqrt{d_k}$ before the softmax?
choice*: Without it, the variance of a query-key dot product grows with $d_k$, which pushes the softmax toward saturation and shrinks its gradients.
choice: It makes each row of attention weights sum to one.
choice: It implements the causal mask so that a position cannot read later positions.
choice: It reduces the number of parameters in the key matrix by a factor of $\sqrt{d_k}$.
hint: Think about the variance of a sum of $d_k$ products of independent unit-variance numbers.
solution: A dot product of two $d_k$-dimensional vectors with independent unit-variance entries has variance $d_k$, so large $d_k$ gives scores with large spread and a nearly one-hot softmax with tiny gradients. Dividing by $\sqrt{d_k}$ restores variance near 1. Row sums equal one because of the softmax itself, the mask is a separate additive term, and scaling changes no parameter count.

model:
```python
import math


def windowed_causal_weights(scores, w):
    """Softmax over the w most recent positions of each row; zero elsewhere."""
    n = len(scores)
    out = []
    for i in range(n):
        lo = max(0, i - w + 1)
        allowed = scores[i][lo:i + 1]
        m = max(allowed)
        exps = [math.exp(s - m) for s in allowed]
        total = 0.0
        for x in exps:
            total += x
        row = [0.0] * n
        for k, x in enumerate(exps):
            row[lo + k] = x / total
        out.append(row)
    return out
```
hint: For row `i` the allowed columns are `max(0, i - w + 1)` through `i`. Subtract the row maximum before exponentiating.
solution: Slice each row to its allowed columns, apply a stable softmax to that slice only, and write the results back into a row of zeros. The third test has scores of 1000, which overflow `exp` unless the maximum is subtracted first.

@quiz self
prompt: A colleague says the transformer language model "reads the whole prompt in parallel, so generating text is just as parallel." Explain what is parallel and what is not in training and in generation, and why the causal mask is essential to the first.
hint: Separate computing the loss on a known sequence from producing a new token whose value is not yet known.
solution: In training the whole sequence is known, so one forward pass computes the hidden states and the next-token loss at every position at once; the causal mask guarantees that position $a$ cannot read the token it is asked to predict, so the $n$ losses are valid and need no sequential loop. In generation each new token depends on the one just sampled, so tokens are produced one at a time, and each step must still attend to all earlier positions. Processing the given prompt can be parallel, which is why the cost splits into a parallel prompt phase and a sequential token phase, a point that returns in the lesson on inference. Without the mask, training would let each position copy its target and the model would learn nothing useful for generation.
rubric: States that training computes all positions' losses in one pass because the sequence is known.
rubric: States that generation is sequential because each token depends on the previous sample.
rubric: Explains that the mask prevents leaking the target, so parallel training is valid.
