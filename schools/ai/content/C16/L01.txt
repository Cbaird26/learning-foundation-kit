@article
A shop has five customers, and the only thing we know about each is how many euros they spent last month: 1, 2, 9, 10 and 12. Nobody told us which customers are "big spenders". Can a program discover two groups on its own? That is **unsupervised learning**: we have inputs $\mathbf{x}_1, \dots, \mathbf{x}_n$ and no labels, and we look for structure in the inputs alone. The simplest structure is a partition into $k$ **clusters**.

### The k-means objective

Each cluster $j$ gets a **center** (centroid) $\boldsymbol{\mu}_j$, and each point gets an assignment $z_i \in \{1, \dots, k\}$. The **k-means objective** is the within-cluster sum of squared distances,

$$J(z, \boldsymbol{\mu}) = \sum_{i=1}^{n} \lVert \mathbf{x}_i - \boldsymbol{\mu}_{z_i} \rVert_2^2 .$$

Finding the global minimum of $J$ is NP-hard in general, so we use a simple alternating method.

### Lloyd's algorithm

Start from $k$ initial centers and repeat two steps until the assignments stop changing:

1. **Assignment step.** Send each point to its nearest center: $z_i = \arg\min_j \lVert \mathbf{x}_i - \boldsymbol{\mu}_j \rVert_2^2$.
2. **Update step.** Move each center to the mean of its points: $\boldsymbol{\mu}_j = \frac{1}{|C_j|} \sum_{i \in C_j} \mathbf{x}_i$. If a cluster is empty, a common rule is to leave its center where it is.

Run it on the five customers with initial centers 1 and 2. Assignment: the point 1 goes to the center 1, and 2, 9, 10, 12 are all closer to 2 (ties go to the lower index). Update: $\mu_1 = 1$ and $\mu_2 = (2+9+10+12)/4 = 8.25$, so $J = 56.75$. Assignment again: the point 2 is now 1 away from $\mu_1$ and 6.25 from $\mu_2$, so it moves. Update: $\mu_1 = 1.5$ and $\mu_2 = (9+10+12)/3 \approx 10.333$, so $J \approx 5.1667$. A third pass changes nothing, and the algorithm stops.

### Why it converges, and to what

The mean is the point that minimizes the sum of squared distances to a set, so the update step cannot increase $J$ for fixed assignments; the assignment step cannot increase $J$ for fixed centers because each point picks its closest center. So $J$ never increases. There are only finitely many partitions and $J$ strictly decreases whenever the partition changes, so the algorithm terminates. It stops at a **local minimum** of $J$, not necessarily the global one.

Here is a concrete trap. Take the corners of a rectangle, $(0,0)$, $(4,0)$, $(0,2)$ and $(4,2)$, with initial centers $(2,0)$ and $(2,2)$. Every point is already at squared distance 4 from its own center and 8 from the other, so Lloyd's algorithm stops at once with $J = 16$. Starting from $(0,1)$ and $(4,1)$ gives $J = 4$. The result of k-means depends on its initialization, so practitioners run it several times and keep the lowest $J$.

### k-means++ seeding

**k-means++** (Arthur and Vassilvitskii, 2007) chooses starting centers that are spread out:

1. Pick the first center uniformly at random from the data.
2. For each point let $D(\mathbf{x})^2$ be its squared distance to the nearest center chosen so far.
3. Pick the next center from the data with probability proportional to $D(\mathbf{x})^2$.
4. Repeat until $k$ centers are chosen, then run Lloyd's algorithm.

Far-away points are much more likely to be chosen, but not certain, which protects against outliers dominating. Arthur and Vassilvitskii proved that the expected value of $J$ after seeding is within a factor $O(\log k)$ of the optimum, a guarantee that uniform random seeding lacks. For the customers with first center 1, the squared distances are $0, 1, 64, 81, 121$, which sum to 267, so the point 12 is chosen with probability $121/267 \approx 0.453$.

### In code

```python
def dist2(a, b):
    return sum((x - y) ** 2 for x, y in zip(a, b))

def lloyd_step(points, centers):
    labels = [min(range(len(centers)), key=lambda j: dist2(p, centers[j]))
              for p in points]
    new = []
    for j, c in enumerate(centers):
        members = [p for p, l in zip(points, labels) if l == j]
        if members:
            c = [sum(col) / len(members) for col in zip(*members)]
        new.append(c)
    return labels, new

pts = [[1.0], [2.0], [9.0], [10.0], [12.0]]
ctr = [[1.0], [2.0]]
for _ in range(3):
    labels, ctr = lloyd_step(pts, ctr)
    print(labels, ctr)
```

With NumPy the same step is two lines of broadcasting, and scikit-learn's `KMeans` uses k-means++ seeding by default and can run several restarts. Because k-means uses squared Euclidean distance, features on large scales dominate, so standardize them first.

step: Assignment with $\mu = (2, 20)$: the points 2, 4 and 10 are closer to 2 (distances 0, 2, 8 against 18, 16, 10), and the points 12 and 20 are closer to 20 (distances 8, 0 against 10, 18). Clusters: $\{2, 4, 10\}$ and $\{12, 20\}$.

@mistakes
- Treating the result as the global optimum: Lloyd's algorithm only reaches a local minimum, so different initializations can give different clusters with different $J$.
- Updating a center to the median or to the nearest data point: k-means uses the mean, because the mean is what minimizes squared distance.
- Clustering raw features on different scales: a feature measured in thousands swamps one measured in fractions, so standardize first.
- Crashing on an empty cluster: dividing by a zero count; decide a rule (keep the old center) before running.

```python
def assign(points, centers):
    """Index of the nearest center (squared Euclidean) for each point."""
    labels = []
    for p in points:
        best, best_d = 0, None
        for j, c in enumerate(centers):
            d = sum((x - y) ** 2 for x, y in zip(p, c))
            if best_d is None or d < best_d:
                best, best_d = j, d
        labels.append(best)
    return labels
```

model:
```python
def kmeans(points, centers, max_updates):
    """Lloyd's algorithm until the assignments repeat; return (centers, J, updates)."""
    centers = [list(c) for c in centers]
    labels, updates = None, 0
    while True:
        new = []
        for p in points:
            d = [sum((x - y) ** 2 for x, y in zip(p, c)) for c in centers]
            new.append(d.index(min(d)))
        stop = new == labels or updates == max_updates
        labels = new
        if stop:
            break
        for j in range(len(centers)):
            members = [p for p, l in zip(points, labels) if l == j]
            if members:
                centers[j] = [sum(col) / len(members) for col in zip(*members)]
        updates += 1
    J = sum(sum((x - y) ** 2 for x, y in zip(p, centers[l]))
            for p, l in zip(points, labels))
    return centers, J, updates
```
hint: Keep the previous pass's assignments, starting from `None`. In each pass compute the new assignments; stop if they equal the previous ones or the update budget is spent, and otherwise update the centers and count the update. Compute $J$ at the end from the last assignments.
solution: When a pass repeats the previous assignments, the centers would not move, so the algorithm has converged. The first test needs three updates and a fourth pass to see this, so a function that always makes `max_updates` updates returns the wrong count. With `max_updates` equal to 1, $J$ must use the assignments to the final centers ($230/9 \approx 25.56$), not the assignments made before the update. The tie test fails if the point 1.0 goes to the higher index, and the empty-cluster test checks that the center 100.0 stays where it is.

```python
def seed_probs(points, centers):
    """k-means++ probabilities: squared distance to the nearest center, normalized."""
    d2 = [min(sum((x - y) ** 2 for x, y in zip(p, c)) for c in centers)
          for p in points]
    total = sum(d2)
    return [d / total for d in d2]
```
hint: First compute, for each point, the minimum over centers of the squared distance; then divide each by the total.
solution: Each point's weight is $D(\mathbf{x})^2$, the squared distance to its nearest center, and the probabilities are these weights over their sum. The second test checks that distance is measured to the nearest of several centers, not to the first one; the third checks squared, not plain, distances.
