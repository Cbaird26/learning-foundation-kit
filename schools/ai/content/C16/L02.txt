@article
k-means needs the number of clusters in advance and finds round, similar-sized blobs. Two other families of methods relax those limits: **hierarchical clustering** builds a whole tree of clusterings, and **density-based clustering** lets clusters have any shape and leaves outliers unassigned.

### Agglomerative clustering

**Agglomerative** (bottom-up) clustering starts with every point as its own cluster and repeatedly merges the two closest clusters until one remains. The only choice is how to measure the distance $d(A, B)$ between two clusters, called the **linkage**:

| linkage | distance between clusters $A$ and $B$ |
|---|---|
| single | $\min_{a \in A,\, b \in B} d(a, b)$ |
| complete | $\max_{a \in A,\, b \in B} d(a, b)$ |
| average | $\frac{1}{\lvert A \rvert \lvert B \rvert} \sum_{a \in A} \sum_{b \in B} d(a, b)$ |

Take the one-dimensional points $1, 2, 4, 8, 9, 15$ with $d(a, b) = \lvert a - b \rvert$. The first merges are the same for every linkage: $\{8, 9\}$ and $\{1, 2\}$, each at height 1. Next, $\{1,2\}$ and $4$ merge: at height 2 for single linkage (closest pair 2 and 4), 3 for complete (farthest pair 1 and 4) and $(3+2)/2 = 2.5$ for average. The merge heights of the whole run are

| linkage | heights of the five merges |
|---|---|
| single | 1, 1, 2, 4, 6 |
| complete | 1, 1, 3, 7, 14 |
| average | 1, 1, 2.5, 6.17, 10.2 |

The record of merges and their heights is a **dendrogram**. Cutting it at a height $h$ gives a flat clustering: with single linkage and $h = 3$ we keep the merges at heights 1, 1 and 2 and get the clusters $\{1, 2, 4\}$, $\{8, 9\}$ and $\{15\}$.

**Single linkage** merges clusters through their closest pair, so a chain of points, each close to the next, links into one long cluster ("chaining"). **Complete linkage** looks at the farthest pair and prefers compact clusters of similar diameter. **Average linkage** is a compromise. Naive agglomerative clustering takes $O(n^3)$ time, or $O(n^2 \log n)$ with a priority queue, and needs the $n \times n$ distance matrix, so it suits thousands of points, not millions.

### DBSCAN

**DBSCAN** (Ester and colleagues, 1996) defines clusters as dense regions. It has two parameters: a radius $\varepsilon$ and a count $m$ (`min_pts`). The $\varepsilon$-neighborhood of a point contains every point within distance $\varepsilon$ of it, **including the point itself**.

- A point is a **core point** if its neighborhood has at least $m$ points.
- A point is **directly reachable** from a core point if it lies in that core point's neighborhood. A **cluster** is a maximal set of core points connected through such steps, plus the non-core points reachable from them, called **border points**.
- A point that belongs to no cluster is **noise**.

The algorithm scans the points in order. An unlabeled core point starts a new cluster, which is grown by repeatedly adding the neighbors of every core point reached; points first labeled noise can become border points later. On $1, 2, 4, 8, 9, 15$ with $\varepsilon = 2$ and $m = 3$, only the point 2 has three points in its neighborhood ($\{1, 2, 4\}$), so it is the only core point; the cluster is $\{1, 2, 4\}$ and the points 8, 9 and 15 are noise. DBSCAN needs no number of clusters, finds non-convex shapes such as two interleaved crescents, and flags outliers, but it struggles when clusters have very different densities, because one $\varepsilon$ cannot fit all of them. A borderline point can be reached from two clusters, in which case the result depends on scan order.

### In code

```python
def neighbors(points, i, eps):
    return [j for j, q in enumerate(points) if abs(points[i] - q) <= eps]

def dbscan(points, eps, min_pts):
    labels = [None] * len(points)
    cluster = 0
    for i in range(len(points)):
        if labels[i] is not None:
            continue
        if len(neighbors(points, i, eps)) < min_pts:
            labels[i] = -1
            continue
        labels[i] = cluster
        queue = neighbors(points, i, eps)
        while queue:
            j = queue.pop(0)
            if labels[j] == -1:
                labels[j] = cluster
            if labels[j] is not None:
                continue
            labels[j] = cluster
            if len(neighbors(points, j, eps)) >= min_pts:
                queue.extend(neighbors(points, j, eps))
        cluster += 1
    return labels

print(dbscan([1, 2, 4, 8, 9, 15], 2, 3))
```

This prints `[0, 0, 0, -1, -1, -1]`. In practice you would use `scipy.cluster.hierarchy` and `sklearn.cluster.DBSCAN`, which use spatial indexes to find neighbors quickly.

@mistakes
- Forgetting that the $\varepsilon$-neighborhood includes the point itself, which shifts every core-point count by one.
- Reading single linkage heights as cluster diameters: with chaining, a single-linkage cluster can be very long even though its merge heights are small.
- Using one $\varepsilon$ for clusters of very different density: a value that separates the dense clusters merges or drops the sparse ones.
- Treating DBSCAN noise as a cluster: the label $-1$ means "no cluster", and noise points are not similar to one another.

```python
def cluster_distance(A, B, method):
    """Single, complete or average linkage distance for 1-D clusters."""
    dists = [abs(a - b) for a in A for b in B]
    if method == "single":
        return min(dists)
    if method == "complete":
        return max(dists)
    return sum(dists) / len(dists)
```

```python
def dbscan(points, eps, min_pts):
    """DBSCAN for 1-D points; returns cluster labels, -1 for noise."""
    n = len(points)

    def nbrs(i):
        return [j for j in range(n) if abs(points[i] - points[j]) <= eps]

    labels = [None] * n
    cluster = 0
    for i in range(n):
        if labels[i] is not None:
            continue
        if len(nbrs(i)) < min_pts:
            labels[i] = -1
            continue
        labels[i] = cluster
        queue = nbrs(i)
        while queue:
            j = queue.pop(0)
            if labels[j] == -1:
                labels[j] = cluster
            if labels[j] is not None:
                continue
            labels[j] = cluster
            if len(nbrs(j)) >= min_pts:
                queue.extend(nbrs(j))
        cluster += 1
    return labels
```
hint: Keep a queue of points to visit. Label a point with the current cluster when it is reached, and add its neighbors to the queue only if it is a core point.
solution: A noise point stays `-1` unless a cluster reaches it, which turns it into a border point; only core points extend the queue, so border points never grow the cluster. The third test starts with non-core points that are claimed later, and the fifth and sixth check that the neighborhood counts the point itself.

model:
```python
def agglomerate(points, k, method):
    """Agglomerative clustering of 1-D points down to k clusters."""

    def linkage(A, B):
        dists = [abs(a - b) for a in A for b in B]
        if method == "single":
            return min(dists)
        if method == "complete":
            return max(dists)
        return sum(dists) / len(dists)

    clusters = [[p] for p in points]
    while len(clusters) > k:
        best = None
        for i in range(len(clusters)):
            for j in range(i + 1, len(clusters)):
                d = linkage(clusters[i], clusters[j])
                if best is None or d < best[0]:
                    best = (d, i, j)
        _, i, j = best
        clusters[i] = clusters[i] + clusters[j]
        del clusters[j]
    return sorted(sorted(c) for c in clusters)
```
hint: Keep a list of clusters, find the closest pair under the chosen linkage, merge it, and stop when the list has length `k`.
solution: Each round scans all pairs of clusters, merges the closest pair and removes the other one. The second and third tests use the same points with different linkages and need different answers, so a function that always uses the minimum fails the complete-linkage test.
