@article
Two programs can both be correct, yet one finishes in a blink and the other takes a year. **Algorithm efficiency** is about how much work a program does as its input gets larger.

### Count steps, not seconds

Seconds depend on the computer, the language and what else is running. Instead we count **basic steps**, such as comparisons or loop passes, as a function of the **input size** $n$ (the length of the list, say). Counting is exact, repeatable and the same on every machine. You can even let the program count for you with a counter variable:

```python
def count_comparisons(xs, target):
    steps = 0
    for x in xs:
        steps += 1            # one comparison
        if x == target:
            break
    return steps
```

### Best case, worst case

The same algorithm can take different numbers of steps on different inputs of the same size. For linear search the best case is 1 comparison (the target is first), and the **worst case** is $n$ comparisons (last or missing). We usually care most about the worst case, because it is a guarantee.

### Growth: how the steps scale

What matters is how the count grows as $n$ grows:

| Pattern | Example | Steps for $n = 10$ | $n = 100$ | $n = 1000$ |
|---|---|---|---|---|
| logarithmic | binary search | about 4 | about 7 | about 10 |
| linear | one loop over the list | 10 | 100 | 1,000 |
| quadratic | a loop inside a loop | 100 | 10,000 | 1,000,000 |

If you **double** $n$, a linear algorithm does about twice the work, a quadratic one about **four times** the work, and a logarithmic one only a single step more. Computer scientists write these classes as $O(\log n)$, $O(n)$ and $O(n^2)$ ("big-O", the *order of growth*), ignoring constant factors such as the difference between $n$ and $2n$, because for large $n$ the class matters far more than the constant.

### Counting nested loops

For a loop inside a loop, multiply when the inner loop always runs the same number of times: `for i in range(n): for j in range(n):` runs the body $n \cdot n = n^2$ times. When the inner loop depends on `i`, add up the passes: with `for j in range(i)` the inner body runs $0 + 1 + 2 + \dots + (n-1) = n(n-1)/2$ times, which is still about $n^2/2$, so still quadratic.

### Choosing a better algorithm

Checking whether a list has a duplicate by comparing every pair takes about $n^2/2$ comparisons. Using a **set** of items seen so far takes about $n$ steps, because a membership test `x in seen` on a set takes (on average) a constant number of steps, whereas `x in some_list` scans the list and takes up to $n$. Dictionaries have the same advantage for looking up a key. The price is extra memory for the set.

This is the central idea of the course's algorithm lessons: the right data structure or algorithm often matters more than any amount of clever tweaking. Before optimizing, make the program correct; then, if it is too slow, measure and count where the steps go.

@example
title: Counting a nested loop
problem: How many times does `count += 1` run for `n = 5`?

```python
count = 0
for i in range(5):
    for j in range(i):
        count += 1
```
step: When `i = 0`, `range(0)` is empty, so the inner loop runs 0 times.
step: For `i = 1, 2, 3, 4` the inner loop runs 1, 2, 3 and 4 times.
step: The total is $0 + 1 + 2 + 3 + 4 = 10$, which matches $n(n-1)/2 = 5 \cdot 4 / 2 = 10$.
answer: `10`

@example
title: Two ways to find a duplicate
problem: Compare the steps of two functions that test whether a list of 10 distinct items has a duplicate.
step: The pair method checks every pair of positions `i < j`. For 10 items that is $10 \cdot 9 / 2 = 45$ comparisons when there is no duplicate (the worst case):

```python
def has_dup_pairs(xs):
    for i in range(len(xs)):
        for j in range(i + 1, len(xs)):
            if xs[i] == xs[j]:
                return True
    return False
```
step: The set method visits each item once and asks whether it was seen before:

```python
def has_dup_set(xs):
    seen = set()
    for x in xs:
        if x in seen:
            return True
        seen.add(x)
    return False
```
step: For 10 distinct items it does 10 set lookups, against 45 comparisons. For 1000 items the counts are about 1,000 and 499,500, so the set method wins by a factor of nearly 500.

@mistakes
- Judging an algorithm by one timing on one input instead of counting how steps grow with $n$.
- Thinking that doubling the input doubles the work for every algorithm; for a quadratic algorithm it quadruples it.
- Forgetting that `x in some_list` is itself a loop, so a `for` loop containing it is a hidden nested loop.
- Optimizing before the program is correct and tested.

prompt: Write `two_sum(nums, target)` that finds two **different positions** `i < j` with `nums[i] + nums[j] == target` and returns the tuple `(i, j)`, or `None` if there is no such pair. If several pairs exist, return the one with the smallest `j`, and for that `j` the smallest `i`. Make one pass over the list, using a dictionary from value to the index where it was first seen. Example: `two_sum([2, 7, 11, 15], 9)` is `(0, 1)`.
starter:
```python
def two_sum(nums, target):
    pass
```
tests:
```python
assert two_sum([2, 7, 11, 15], 9) == (0, 1)
assert two_sum([3, 3], 6) == (0, 1)
assert two_sum([1, 2, 3], 7) is None
assert two_sum([3, 2, 4], 6) == (1, 2)
assert two_sum([1, 4, 2, 3, 5], 6) == (1, 2)
assert two_sum([5, 1], 10) is None
assert two_sum([], 3) is None
```
model:
```python
def two_sum(nums, target):
    first_seen = {}
    for j in range(len(nums)):
        need = target - nums[j]
        if need in first_seen:
            return (first_seen[need], j)
        if nums[j] not in first_seen:
            first_seen[nums[j]] = j
    return None
```
hint: For each position `j`, the partner you need is `target - nums[j]`. Ask whether it appeared earlier.
hint: Look up the partner in the dictionary before you store `nums[j]`, so an item is never paired with itself, and store only the first index of each value.
solution: Scan with index `j`. If `target - nums[j]` is already a key, the pair is `(its first index, j)`; this finds the smallest `j` first, and the first index of the partner is the smallest `i`. Only then record `nums[j]` (if new). Checking before storing prevents `[5, 1]` with target `10` from pairing the `5` with itself. The whole search takes about $n$ steps, compared with about $n^2/2$ for checking every pair.

@quiz code
prompt: Write `count_shifts(xs)` that returns how many times insertion sort moves an item one place to the right while sorting `xs`. In insertion sort each item is inserted into the sorted part on its left by shifting every larger item right; each such move counts as one shift. Do not change `xs`. For example, `count_shifts([3, 2, 1])` is `3`.
starter:
```python
def count_shifts(xs):
    pass
```
tests:
```python
assert count_shifts([3, 2, 1]) == 3
assert count_shifts([1, 2, 3]) == 0
assert count_shifts([2, 1, 3]) == 1
assert count_shifts([]) == 0
assert count_shifts([4, 1, 3, 2]) == 4
assert count_shifts([2, 2, 1]) == 2
data = [2, 1]
count_shifts(data)
assert data == [2, 1]
```
model:
```python
def count_shifts(xs):
    xs = list(xs)
    shifts = 0
    for i in range(1, len(xs)):
        item = xs[i]
        j = i - 1
        while j >= 0 and xs[j] > item:
            xs[j + 1] = xs[j]
            shifts += 1
            j -= 1
        xs[j + 1] = item
    return shifts
```
hint: Write insertion sort on a copy of the list, and add a counter.
hint: Add 1 to the counter inside the `while` loop, each time a larger item is moved right. Use `>`, so equal items are not shifted.
solution: Run insertion sort on a copy, adding 1 to `shifts` each time `xs[j + 1] = xs[j]` runs. The total equals the number of pairs that are out of order: 3 for `[3, 2, 1]`, 0 for a sorted list. Sorted input needs no shifts and reversed input needs the most, about $n^2/2$.

@quiz num
prompt: An algorithm's running time is proportional to $n^2$. It takes 50 steps when $n = 10$. How many steps does it take when $n = 40$? Give the number.
answer: 800
check: 50 * (40 // 10) ** 2
hint: How many times larger is 40 than 10, and what happens to $n^2$ when $n$ is multiplied by that factor?
solution: The input is 4 times larger, so a quadratic algorithm does $4^2 = 16$ times as much work: $50 \cdot 16 = 800$ steps.
