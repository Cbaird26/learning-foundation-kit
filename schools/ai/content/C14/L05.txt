@article
A shop keeps its customers in one table and its orders in another. To answer "how much has each customer spent?" you must put the two together. A **join** combines rows from two tables whenever they agree on a **key**: a column (or columns) that refers to the same entity in both tables. Joins are where wrangled data most often silently goes wrong, because a join that loses or duplicates rows still returns a table.

### Two small tables

```python
customers = [
    {"cust": 1, "name": "Ana"},
    {"cust": 2, "name": "Bo"},
    {"cust": 3, "name": "Cy"},
]
orders = [
    {"order": 10, "cust": 1, "amt": 30},
    {"order": 11, "cust": 1, "amt": 20},
    {"order": 12, "cust": 3, "amt": 50},
    {"order": 13, "cust": 4, "amt": 15},
]
```

Customer 2 has no orders, and order 13 belongs to a customer who is not in the customers table.

### Inner and left joins

An **inner join** keeps a pair of rows only when the keys match. Joining `customers` to `orders` on `cust` gives three rows: (Ana, 30), (Ana, 20), (Cy, 50). Bo is dropped (no orders) and order 13 is dropped (no customer). A **left join** keeps every row of the left table; where the right table has no match, the right columns are filled with missing values. The left join of `customers` with `orders` has four rows: Ana twice, Bo with `amt` set to `None`, and Cy. Order 13 is still dropped, because it is not in the left table. A **right join** is the mirror image, and a **full outer join** keeps unmatched rows from both sides.

```python
def left_join(left, right, key):
    cols = []
    for r in right:
        cols += [c for c in r if c != key and c not in cols]
    out = []
    for l in left:
        matches = [r for r in right if r[key] == l[key]]
        for r in matches:
            row = dict(l)
            row.update({c: v for c, v in r.items() if c != key})
            out.append(row)
        if not matches:
            row = dict(l)
            row.update({c: None for c in cols})
            out.append(row)
    return out
```

Choose the join by the question. To analyze only customers who have ordered, use an inner join. To count customers with zero orders you need the left join, because an inner join throws those customers away.

### How many rows?

The row count is a diagnostic. If a key value appears $a$ times in the left table and $b$ times in the right, an inner join produces $a \times b$ rows for that key. Suppose the left keys are $1, 2, 2, 3$ and the right keys are $2, 2, 3, 4$. Key 2 gives $2 \times 2 = 4$ rows and key 3 gives $1 \times 1 = 1$ row, so the inner join has 5 rows. The left join adds one row for the unmatched key 1, for 6 rows. A join can therefore have more rows than either input. When you expect a **one-to-many** join (each customer has many orders), the left table's key should be unique, and a **many-to-many** surprise usually means the key is not unique where you thought it was. Also check **key types**: the integer `1` and the string `"1"` never match, so a join that reads IDs as numbers on one side and text on the other returns nothing.

### Reshaping: wide and long

The same data can be **wide** (one row per store, one column per quarter) or **long** (one row per store and quarter). Long form is tidy: the quarter is a variable and is a column. **Melting** turns wide into long:

```python
wide = [{"store": "A", "q1": 5, "q2": 7}]
long = []
for row in wide:
    for col in ["q1", "q2"]:
        long.append({"store": row["store"], "quarter": col, "sales": row[col]})
print(long)
```

This prints two rows: `{'store': 'A', 'quarter': 'q1', 'sales': 5}` and the same for `q2` with sales 7. **Pivoting** goes the other way: for every row of a long table, put the value into the dictionary for its index and column,

```python
table = {}
for r in long:
    table.setdefault(r["store"], {})[r["quarter"]] = r["sales"]
```

which gives `{'A': {'q1': 5, 'q2': 7}}`. If two long rows share an index and column, a pivot must **aggregate** them (sum or mean) or fail; silently keeping the last one loses data. Wide tables suit reading and some matrix methods, while long tables suit grouping and plotting.

@example
title: Joining customers to orders
problem: Using the customers and orders tables above, compute the total amount spent by each customer with a left join, and compare the row counts of the inner and left joins.
step: List the matches by key. Customer 1 matches orders 10 and 11, customer 2 matches nothing, customer 3 matches order 12, and order 13 has customer 4, who is not in the left table.
step: Count rows. The inner join keeps $2 + 0 + 1 = 3$ rows. The left join keeps the same matches and adds one row for Bo, so it has 4 rows.
step: Group the left join by customer and sum `amt`, treating `None` as 0. Ana has $30 + 20 = 50$, Bo has 0, and Cy has 50.
step: Check for lost money. The joined amounts total $50 + 0 + 50 = 100$, but the orders table totals $30 + 20 + 50 + 15 = 115$. The difference, 15, is order 13, which has no matching customer. Finding that gap is exactly what the check is for.
answer: Ana 50, Bo 0, Cy 50; the inner join has 3 rows and the left join 4; order 13 (amount 15) has no customer.

@mistakes
- Using an inner join when you need to keep unmatched rows, so that customers with no orders vanish from a count.
- Joining on a key that is not unique and not noticing that the row count grew.
- Joining on keys of different types (`1` and `"1"`), which matches nothing.
- Pivoting a long table that has two rows for the same index and column, and keeping only the last.

model:
```python
def melt(rows, id_cols, value_cols, var_name, value_name):
    """Convert a wide table to long form."""
    out = []
    for row in rows:
        for col in value_cols:
            new = {c: row[c] for c in id_cols}
            new[var_name] = col
            new[value_name] = row[col]
            out.append(new)
    return out
```
hint: For each row, loop over the value columns and create one new dictionary per column.
solution: The output has one row for each pair of input row and value column, so a table with $n$ rows and $v$ value columns melts to $n v$ rows. Each new row copies the identifier columns and records which column the value came from.

model:
```python
def left_join(left, right, key):
    """Left join of two lists of dictionaries on one key column."""
    right_cols = []
    for r in right:
        right_cols += [c for c in r if c != key and c not in right_cols]
    out = []
    for l in left:
        matches = [r for r in right if r[key] == l[key]]
        for r in matches:
            row = dict(l)
            row.update({c: v for c, v in r.items() if c != key})
            out.append(row)
        if not matches:
            row = dict(l)
            row.update({c: None for c in right_cols})
            out.append(row)
    return out
```
hint: Collect the names of the right table's other columns first, so that unmatched left rows can be padded with `None`.
solution: Each left row yields its matches, or one padded row if there are none. The padding columns come from the right table's rows, so an empty right table adds nothing. The test with two matches for id 1 checks that a left join can return more rows than the left table has.
