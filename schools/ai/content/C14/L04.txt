@article
A small shop records its sales by region, item and units sold. Which region sells more? Which item is the top seller in each region? Almost every question about a table is one of three moves: keep some rows, put them in an order, or summarize groups of rows. These three operations, repeated and combined, are most of data analysis.

```python
rows = [
    {"region": "N", "item": "pen", "units": 10},
    {"region": "S", "item": "pen", "units": 4},
    {"region": "N", "item": "ink", "units": 3},
    {"region": "S", "item": "ink", "units": 8},
    {"region": "N", "item": "pad", "units": 7},
    {"region": "S", "item": "pad", "units": 5},
]
```

### Filtering and selecting

**Filtering** keeps the rows for which a **predicate** (a function that returns true or false) holds. In Python this is a list comprehension: `big = [r for r in rows if r["units"] >= 5]` keeps four of the six rows. **Selecting** keeps some columns: `[{"item": r["item"]} for r in rows]`. Combine conditions with `and`, `or` and `not`, and be careful with missing values: comparing `None` with a number raises an error in Python, so decide first what a missing value should do.

### Sorting

Python's `sorted(rows, key=...)` returns a new list ordered by the key. To sort by units from largest to smallest, use `reverse=True`. To sort by several columns, such as region ascending and then units descending, you can use one tuple key when all columns go the same direction, but mixed directions need another idea: Python's sort is **stable**, meaning rows with equal keys keep their original relative order. So sort by the *least* important key first and the most important key last:

```python
by_units = sorted(rows, key=lambda r: r["units"], reverse=True)
by_region = sorted(by_units, key=lambda r: r["region"])
print([(r["region"], r["units"]) for r in by_region])
```

This prints `[('N', 10), ('N', 7), ('N', 3), ('S', 8), ('S', 5), ('S', 4)]`. The second sort reorders by region but, by stability, leaves the rows within each region in descending order of units.

### Grouping: split, apply, combine

To compute a statistic per group you follow the **split-apply-combine** pattern (Wickham, 2011): **split** the rows into groups by a key, **apply** a function (count, sum, mean) to each group, and **combine** the results into a new table. A dictionary does the splitting:

```python
groups = {}
for r in rows:
    groups.setdefault(r["region"], []).append(r)

totals = {k: sum(r["units"] for r in g) for k, g in groups.items()}
print(totals)
```

This prints `{'N': 20, 'S': 17}`. Every row lands in exactly one group, so the group sizes add up to the number of rows. The mean units per group are $20/3 \approx 6.67$ for N and $17/3 \approx 5.67$ for S.

### Group means and weights

Group summaries combine in a particular way. The overall mean is the **size-weighted** average of the group means:

$$\bar{x} = \sum_g \frac{n_g}{n}\,\bar{x}_g .$$

If group A has three rows with mean 4 and group B has one row with mean 12, the overall mean is $(3 \cdot 4 + 1 \cdot 12)/4 = 6$, not the unweighted average of the group means, $(4 + 12)/2 = 8$. Reporting the second is a common error and is one way that aggregate numbers mislead: always report group sizes next to group statistics.

### Cautions

Filter before you group when the filter defines the population you care about, and group before you filter when the condition depends on the group (for example, keep groups with at least five rows). Sorting a table does not change it; it returns a new order, so assign the result. When grouping by a key that has missing values, decide whether they form their own group. Finally, keep the original table: you will want to check each summary against it.

@example
title: Filter, group and sum
problem: Using the six sales rows above, keep only the rows with at least 5 units, then find the number of rows and the total units for each region.
step: Filter with `units >= 5`. The rows kept are (N, pen, 10), (S, ink, 8), (N, pad, 7) and (S, pad, 5). The rows (S, pen, 4) and (N, ink, 3) are dropped.

@mistakes
- Averaging group means without weights, which equals the overall mean only when all groups have the same size.
- Sorting by the most important key first and the least important last, which loses the order you wanted for ties.
- Comparing a missing value (`None`) with a number inside a filter and crashing, or silently dropping rows you meant to keep.
- Forgetting that `sorted` returns a new list and that `list.sort()` returns `None`.

```python
def group_by_mean(rows, key, col):
    """Mean of col for each distinct value of key."""
    groups = {}
    for row in rows:
        groups.setdefault(row[key], []).append(row[col])
    return {k: sum(v) / len(v) for k, v in groups.items()}
```
hint: First collect the values of `col` into a list for each key, then divide each list's sum by its length.
solution: Splitting with `setdefault` builds one list of values per key, and a dictionary comprehension applies the mean to each list. Dividing by each group's own length, not the total number of rows, is the point of the last test.

tests:
```python
rows = [{"r": "N", "u": 3}, {"r": "S", "u": 9}, {"r": "N", "u": 7}, {"r": "S", "u": 1}]
out = sort_by(rows, [("r", False), ("u", True)])
assert [(x["r"], x["u"]) for x in out] == [("N", 7), ("N", 3), ("S", 9), ("S", 1)]
out = sort_by(rows, [("u", False)])
assert [x["u"] for x in out] == [1, 3, 7, 9]
ties = [{"k": 1, "id": "a"}, {"k": 0, "id": "b"}, {"k": 1, "id": "c"}]
assert [x["id"] for x in sort_by(ties, [("k", True)])] == ["a", "c", "b"]
assert [x["id"] for x in sort_by(ties, [("k", False)])] == ["b", "a", "c"]
assert [x["id"] for x in ties] == ["a", "b", "c"]
```
model:
```python
def sort_by(rows, keys):
    """Stable multi-key sort; keys are (column, descending) pairs."""
    result = list(rows)
    for col, descending in reversed(keys):
        result = sorted(result, key=lambda r, c=col: r[c], reverse=descending)
    return result
```
hint: Apply one stable sort per key, starting with the least important key, which is the last pair.
solution: Loop over the keys in reverse order and sort the whole list by each, so the most important key is applied last and ties keep the order from the earlier sorts. Python's `reverse=True` keeps equal rows in their original order, which the tie tests check, and copying the list first leaves the input unchanged.

```python
rows = [{"g": "a", "v": 5}, {"g": "b", "v": 1}, {"g": "a", "v": 9}, {"g": "a", "v": 7}]
assert top_n_per_group(rows, "g", "v", 2) == {"a": [9, 7], "b": [1]}
```

model:
```python
def top_n_per_group(rows, key, col, n):
    """The n largest values of col in each group, largest first."""
    groups = {}
    for row in rows:
        groups.setdefault(row[key], []).append(row[col])
    return {k: sorted(v, reverse=True)[:n] for k, v in groups.items()}
```
hint: Split into groups, sort each group's values from largest to smallest, and slice the first `n`.
solution: After splitting by key, a descending sort and a slice `[:n]` give the top values, and slicing past the end of a short list simply returns all of it. The `n=0` test needs an empty list for each group rather than a missing key.
