@article
A file arrives with one line that reads `Oslo,709000,"capital, fjord"`. If you split it on every comma you get four pieces instead of three, and the whole table slides out of alignment. Reading data is the first place where small details decide whether everything after it is right.

### CSV: comma-separated values

A **CSV** file is plain text. Each line is a row, and the first line usually names the columns:

```text
city,pop,note
Oslo,709000,"capital, fjord"
Bergen,285000,coast
```

The rules are short. Fields are separated by commas. A field that contains a comma, a double quote or a line break is wrapped in double quotes, and a double quote inside a quoted field is written twice (`""`). A **parser** reads the line one character at a time and keeps a flag, "inside quotes", that decides whether a comma separates fields or is part of the text:

```python
def parse_line(line):
    fields, current, in_quotes, i = [], [], False, 0
    while i < len(line):
        ch = line[i]
        if in_quotes:
            if ch == '"' and line[i + 1:i + 2] == '"':
                current.append('"')
                i += 1
            elif ch == '"':
                in_quotes = False
            else:
                current.append(ch)
        elif ch == '"':
            in_quotes = True
        elif ch == ",":
            fields.append("".join(current))
            current = []
        else:
            current.append(ch)
        i += 1
    fields.append("".join(current))
    return fields

print(parse_line('Oslo,709000,"capital, fjord"'))
```

This prints `['Oslo', '709000', 'capital, fjord']`. Note two facts: an empty line gives one empty field, and a trailing comma gives a trailing empty field. In practice you can use Python's `csv` module, which implements these rules and more, but you should know what it does.

### Everything is text

A CSV file stores no types. After parsing, every cell is a string, even `709000`. To use it you **convert** each cell: an empty cell becomes `None` (a missing value), a cell that looks like an integer becomes `int`, one that looks like a decimal becomes `float`, and anything else stays a string.

```python
def convert(cell):
    cell = cell.strip()
    if cell == "":
        return None
    for kind in (int, float):
        try:
            return kind(cell)
        except ValueError:
            pass
    return cell
```

Be careful with identifiers. The ZIP code `02139` converts to the integer `2139` and the leading zero is gone for good. Columns that are labels should stay strings, so conversion is best decided per column, not blindly for the whole file.

### JSON: nested records

**JSON** stores objects (dictionaries), arrays (lists), strings, numbers, `true`, `false` and `null`. Unlike CSV it keeps types, and it can nest:

```python
import json

text = '{"id": 7, "user": {"name": "Ana", "age": 31}, "tags": ["a", "b"]}'
record = json.loads(text)
print(record["user"]["age"], record["tags"][1])
```

This prints `31 b`. Nested data does not fit a rectangular table directly. The usual step is to **flatten** a record: replace each nested dictionary by columns whose names join the keys with a dot. The record above becomes `{"id": 7, "user.name": "Ana", "user.age": 31, "tags": ["a", "b"]}`. Lists are harder, because one record may have many items; they are either kept as a single value or turned into several rows, a reshaping we meet in week 5.

### Reporting what you loaded

After loading any file, report its **shape** (rows and columns) and the **type of each column**. For a table `rows` (a list of dictionaries) that is `(len(rows), len(rows[0]))` plus, for each column, the set of Python types of its values. A column whose values include both `int` and `None`, or both `str` and `float`, is a warning: some cells were not what you expected, and the next lesson cleans them. Make the habit automatic. Each time a file is loaded, print the shape, the first rows and the column types before doing anything else.

@example
title: Parsing a line with a comma and quotes
problem: Parse the CSV line `7,"Smith, J.","said ""hi"""` into fields, and say how many there are.
step: Start outside quotes and read `7`. The comma that follows separates fields, so the first field is `7`.
step: Read the opening quote. We are now inside quotes, so the comma in `Smith, J.` is part of the text. The closing quote ends the field. The second field is `Smith, J.`.
step: After the next comma, an opening quote begins the third field. Inside it, `said ` is copied, then the pair `""` becomes one literal `"`, then `hi`, then another pair becomes a literal `"`.
step: The final single quote closes the field. The third field is `said "hi"`, and the line has 3 fields.
answer: Three fields: `7`, `Smith, J.` and `said "hi"`.

@mistakes
- Splitting a line with `line.split(",")`, which breaks every quoted field that contains a comma.
- Converting every digit-only column to numbers, which destroys identifiers with leading zeros such as `02139`.
- Forgetting that an empty cell is not the number 0: it should become `None` so that it is not averaged.
- Assuming a JSON key exists in every record: nested and optional keys need `.get` or a check.

@practice code
prompt: Many data files use a separator other than the comma, such as `;` or a tab. Write `parse_line(line, sep)` that splits one line into a list of strings, where `sep` is a one-character field separator. A field wrapped in double quotes may contain the separator, and two double quotes inside a quoted field stand for one literal double quote. Any other character, including a comma when `sep` is not a comma, is ordinary text. An empty line gives `['']`. For example, `parse_line('a;"b;c";d', ';')` returns `['a', 'b;c', 'd']`.
starter:
```python
def parse_line(line, sep):
    return line.split(sep)
```
tests:
```python
assert parse_line('a;"b;c";d', ';') == ['a', 'b;c', 'd']
assert parse_line('x;;y', ';') == ['x', '', 'y']
assert parse_line('', ';') == ['']
assert parse_line('1\t"He said ""no"""\tok', '\t') == ['1', 'He said "no"', 'ok']
assert parse_line('p;q,r;', ';') == ['p', 'q,r', '']
assert parse_line('"1;2;3"', ';') == ['1;2;3']
```
model:
```python
def parse_line(line, sep):
    """Split a delimited line on sep, honoring double-quoted fields."""
    fields, current, in_quotes, i = [], [], False, 0
    while i < len(line):
        ch = line[i]
        if in_quotes:
            if ch == '"' and line[i + 1:i + 2] == '"':
                current.append('"')
                i += 1
            elif ch == '"':
                in_quotes = False
            else:
                current.append(ch)
        elif ch == '"':
            in_quotes = True
        elif ch == sep:
            fields.append("".join(current))
            current = []
        else:
            current.append(ch)
        i += 1
    fields.append("".join(current))
    return fields
```
hint: Keep a flag for being inside quotes; the separator ends a field only when the flag is off, and every other character is copied.
solution: Scan the characters once. Inside quotes, a doubled quote adds one literal quote (skip the second one) and a single quote turns the flag off; outside quotes, a quote turns it on and the separator ends the field. A comma is no longer special unless it is the separator. Append the last field after the loop, which also gives `['']` for an empty line and a trailing empty field after a final separator.

@practice code
prompt: Write `flatten(record)` that takes a dictionary whose values may be dictionaries (nested to any depth) and returns a flat dictionary. A nested key is joined to its parent with a dot, so `{"user": {"age": 31}}` becomes `{"user.age": 31}`. Values that are not dictionaries, including lists, are kept as they are. Keys appear in the order they are visited.
starter:
```python
def flatten(record):
    return dict(record)
```
tests:
```python
got = flatten({"id": 7, "user": {"name": "Ana", "age": 31}})
assert got == {"id": 7, "user.name": "Ana", "user.age": 31}
assert flatten({"a": {"b": {"c": 1}}}) == {"a.b.c": 1}
assert flatten({"t": [1, 2]}) == {"t": [1, 2]}
assert flatten({}) == {}
assert list(flatten({"x": 1, "y": {"z": 2}, "w": 3}).keys()) == ["x", "y.z", "w"]
```
model:
```python
def flatten(record, prefix=""):
    """Flatten nested dictionaries into dot-joined keys."""
    flat = {}
    for key, value in record.items():
        name = prefix + key
        if isinstance(value, dict):
            flat.update(flatten(value, name + "."))
        else:
            flat[name] = value
    return flat
```
hint: When a value is itself a dictionary, call the function again on it with the current name plus a dot as the prefix.
solution: Walk the items; a dictionary value is flattened recursively with the longer prefix, and any other value is stored under its full dotted name. The second test needs recursion more than one level deep, which a single loop over the top level does not do.

model:
```python
import csv


def _convert(cell):
    cell = cell.strip()
    if cell == "":
        return None
    for kind in (int, float):
        try:
            return kind(cell)
        except ValueError:
            pass
    return cell


def read_csv(name):
    """Read a CSV file into a list of typed row dictionaries."""
    with open(name) as f:
        lines = [row for row in csv.reader(f) if row]
    if not lines:
        return []
    header = lines[0]
    return [
        {h: _convert(c) for h, c in zip(header, row)} for row in lines[1:]
    ]
```
hint: Read all nonblank rows, take the first as the header, and convert each cell with a helper that tries `int`, then `float`.
solution: Skipping empty rows handles blank lines, and `zip(header, row)` pairs each cell with its column name. The helper tries `int` before `float`, so `1` becomes an integer and `2.5` a float; the quoted cell keeps its comma because the `csv` module handles the quotes.
