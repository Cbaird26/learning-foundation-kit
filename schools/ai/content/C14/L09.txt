@article
You want to predict whether a customer will buy from two numbers: age (20 to 70) and yearly income in dollars (20,000 to 200,000). A nearest-neighbor method compares customers by the distance between their feature values. A difference of 10 years of age is tiny next to a difference of \$10,000 of income, so income decides every comparison and age is ignored. The fix is **feature engineering**: transforming raw columns so that a model can use them well. This lesson covers three families of transformation.

### Scaling numeric features

**Standardization** (z-scores) rewrites each value as the number of standard deviations it lies from the mean:

$$z_i = \frac{x_i - \bar{x}}{\sigma}, \qquad \sigma = \sqrt{\frac{1}{n}\sum_i (x_i - \bar{x})^2}.$$

Here we use the population standard deviation, dividing by $n$, as many scalers do; the choice matters little for the idea. The scaled column has mean 0 and standard deviation 1. For incomes (in thousands) $30, 40, 50, 60, 120$, we have $\bar{x} = 60$, the squared deviations sum to $5000$, so $\sigma = \sqrt{1000} \approx 31.62$ and the z-scores are $-0.949, -0.632, -0.316, 0, 1.897$.

**Min-max scaling** maps the smallest value to 0 and the largest to 1: $x'_i = (x_i - x_{\min})/(x_{\max} - x_{\min})$. The same incomes become $0, 0.111, 0.222, 0.333, 1$. Min-max scaling keeps the shape of the distribution but is sensitive to outliers: one extreme value squeezes everyone else into a narrow band.

Scaling matters for methods that use distances (nearest neighbors, k-means), for methods trained by gradient descent (it makes the loss landscape rounder and lets one step size suit every feature), and for regularization (a penalty treats all coefficients alike, so the features must be on comparable scales). Decision trees split on one feature at a time and are not affected.

### Encoding categories

Models need numbers. **One-hot encoding** turns a category with $k$ values into $k$ columns of 0 and 1: for the categories `red`, `green`, `blue`, the value `green` becomes $(0, 1, 0)$. It adds no false order. **Ordinal encoding** maps ordered categories to integers (small $= 0$, medium $= 1$, large $= 2$) and is right only when the order is real, and the spacing is plausible. Encoding a nominal category such as a city as $1, 2, 3$ tells a linear model that city 3 is "more" than city 1, which is nonsense. A category that appears at prediction time but never in training needs a rule (all zeros, or an "other" column).

### Derived features

New columns computed from old ones often help more than any change of model:

- **Ratios and differences**: price per square meter, days since last purchase.
- **Transformations**: a logarithm compresses a right-skewed variable. The incomes above have a ratio of 4 between largest and smallest, while their natural logarithms $3.40, 3.69, 3.91, 4.09, 4.79$ differ by a factor of 1.4.
- **Bins**: age groups, when the effect is not linear.
- **Date parts**: month, weekday, hour, from a timestamp.
- **Missing indicators**: a 0/1 column that records that a value was absent, useful when absence itself carries information.
- **Interactions**: the product of two features, when their effect is joint.

Each derived feature should make sense for the question and be computable at prediction time, from information that will actually be available then (see week 10).

### Fit on training data only

A scaler has **parameters**, the mean and standard deviation, learned from data. They must be computed on the **training** rows only, then applied unchanged to the validation and test rows. Computing them on all the rows lets information about the test set seep into training, a mistake called leakage (week 10). The pattern is always *fit* on the training set, then *transform* every set with the fitted numbers:

```python
def fit_scaler(train):
    n = len(train)
    mean = sum(train) / n
    sd = (sum((x - mean) ** 2 for x in train) / n) ** 0.5
    return mean, sd

mean, sd = fit_scaler([30, 40, 50])
print([round((x - mean) / sd, 3) for x in [30, 40, 50, 120]])
```

The training mean is 40 and $\sigma = \sqrt{200/3} \approx 8.165$, so this prints `[-1.225, 0.0, 1.225, 9.798]`: the new value 120 lies far outside the training range, which is information, not an error to be hidden.

@example
title: Standardizing a column by hand
problem: Standardize the values 30, 40, 50, 60 and 120 (thousands of dollars) with the population standard deviation, and say which value is most unusual.
step: Compute the mean: $(30 + 40 + 50 + 60 + 120)/5 = 60$.
step: Compute the deviations from the mean: $-30, -20, -10, 0, 60$. Their squares are $900, 400, 100, 0, 3600$, with sum $5000$.
step: The population variance is $5000/5 = 1000$, so $\sigma = \sqrt{1000} \approx 31.62$.
step: Divide each deviation by $\sigma$: $-0.949, -0.632, -0.316, 0, 1.897$. The value 120 has the largest absolute z-score, 1.90, so it is the most unusual.
answer: z-scores $-0.949, -0.632, -0.316, 0, 1.897$; the value 120 is the most unusual.

@mistakes
- Computing the mean and standard deviation on the whole data set before splitting, which leaks information from the test rows.
- Encoding an unordered category as 1, 2, 3, which invents an order and a distance.
- Min-max scaling a column with a large outlier, so that all other values end up squeezed near 0.
- Scaling the target and forgetting to convert predictions back to the original units.

model:
```python
def standardize(values):
    """z-scores using the population standard deviation."""
    n = len(values)
    mean = sum(values) / n
    sd = (sum((x - mean) ** 2 for x in values) / n) ** 0.5
    if sd == 0:
        return [0.0] * n
    return [(x - mean) / sd for x in values]
```
hint: Compute the mean, then the population standard deviation, and return `(x - mean) / sd` for each value.
solution: The standardized column has mean 0 and population variance 1, which the last test checks. A constant column has standard deviation 0, so it must be handled before the division. Dividing by `n - 1` instead of `n` would fail the second test, where the standard deviation is exactly 2.

model:
```python
def one_hot(values, categories):
    """One-hot encode values over a fixed list of categories."""
    return [[1 if v == c else 0 for c in categories] for v in values]
```
hint: For each value, build a row with `1 if v == c else 0` for each category `c`, in the given order.
solution: Fixing the category list in advance makes the columns the same for training and new data, and an unseen value simply matches nothing and gives zeros. The order of `categories` decides the column order, which the last two tests check.

model:
```python
def scale_with_train(train, test):
    """Standardize both lists using the mean and std of the training list."""
    n = len(train)
    mean = sum(train) / n
    sd = (sum((x - mean) ** 2 for x in train) / n) ** 0.5
    if sd == 0:
        sd = 1.0
    return [(x - mean) / sd for x in train], [(x - mean) / sd for x in test]
```
hint: Compute the mean and standard deviation from `train` alone and use them for both lists.
solution: The test values are standardized with the training mean and standard deviation, so the test z-scores can lie far outside the range of the training ones, as the first and last tests show (3.67 and 3.0). Using the test list's own statistics would make its mean 0 regardless, and would leak and distort.
