@article
Two versions of a tutorial, A and B, are tested. Overall, 40% of learners finish version A and 79% finish version B, so B looks far better. But in each of two kinds of lesson, easy and hard, version A has the higher finishing rate. Both statements are true at once, and which one you should believe depends on how the learners were split. **Exploratory data analysis** (EDA), named and popularized by John Tukey in 1977, is the habit of looking at the data in many ways before concluding anything, precisely so that you find such things.

### A checklist

For a new table, work through these steps and write down what you see:

1. **Shape and types**: how many rows and columns; which columns are numeric or categorical.
2. **Missing values**: count them per column, and ask whether they are related to other columns.
3. **One variable at a time**: histograms and summaries for numeric columns, counts for categorical ones (`value_counts`).
4. **Two variables at a time**: correlations for numeric pairs, cross-tabulations for categorical pairs, group summaries for one of each.
5. **Anomalies**: outliers, impossible values, duplicate rows, suspicious constants.

EDA produces questions and hypotheses, not final conclusions. A pattern found by looking at many views of one data set may be chance, and confirming it takes new data or a proper test.

### Correlation

The **Pearson correlation coefficient** of paired values $(x_i, y_i)$ measures the strength of their **linear** relationship:

$$r = \frac{\sum_i (x_i - \bar{x})(y_i - \bar{y})}{\sqrt{\sum_i (x_i - \bar{x})^2}\,\sqrt{\sum_i (y_i - \bar{y})^2}} .$$

It always lies in $[-1, 1]$: $+1$ for an exact increasing line, $-1$ for an exact decreasing line, and near 0 when there is no linear trend. For study hours $x = 1, \dots, 5$ and scores $52, 55, 61, 64, 70$, we have $\bar{x} = 3$, $\bar{y} = 60.4$, $\sum (x_i - \bar{x})(y_i - \bar{y}) = 45$, $\sum (x_i - \bar{x})^2 = 10$ and $\sum (y_i - \bar{y})^2 = 205.2$, so $r = 45/\sqrt{10 \times 205.2} \approx 0.993$.

Know what correlation does not say. It does not mean causation: two variables may both depend on a third, such as ice cream sales and swimming accidents, which both rise in summer. It misses nonlinear patterns: for $x = -2, \dots, 2$ and $y = x^2$, there is a perfect relationship but $r = 0$. A single outlier can create or destroy a correlation. Always look at a scatter plot, or at a table of the points, as well as at $r$.

### Cross-tabulations and rates

A **cross-tabulation** counts the rows for each pair of categories. For the tutorial test, with finishing counts per group:

| lesson | version | finished | learners | rate |
|---|---|---|---|---|
| easy | A | 18 | 20 | 90% |
| easy | B | 170 | 200 | 85% |
| hard | A | 30 | 100 | 30% |
| hard | B | 4 | 20 | 20% |
| all | A | 48 | 120 | 40% |
| all | B | 174 | 220 | 79% |

### Simpson's paradox

Version A wins in both rows of lesson type, yet loses overall. The reason is the **mix**: most learners on A took hard lessons (100 of 120) and most on B took easy lessons (200 of 220), and hard lessons have low finishing rates for everyone. The overall rate is a weighted average of group rates, with weights equal to group sizes, and the weights differ between A and B. This is **Simpson's paradox**: a trend in aggregated data can disappear or reverse within subgroups.

Which table to trust depends on how the data arose. If learners chose their own lessons, the lesson type is a **confounder**, a variable related to both the version and the outcome, and comparing within lesson type is fairer. If lessons were assigned by a coin flip, the group sizes would be balanced and the overall rates would be comparable. EDA cannot tell you the mechanism, but it tells you to ask. Whenever you compare rates, show the group sizes and look for a variable that may split the groups unevenly.

@example
title: Correlation by hand
problem: Compute the Pearson correlation of $x = 1, 2, 3, 4$ and $y = 1, 3, 2, 4$.
step: Compute the means: $\bar{x} = 2.5$ and $\bar{y} = 2.5$.
step: Write the deviations. For $x$: $-1.5, -0.5, 0.5, 1.5$. For $y$: $-1.5, 0.5, -0.5, 1.5$.
step: Sum the products of the deviations: $2.25 - 0.25 - 0.25 + 2.25 = 4$. Sum the squares of the $x$ deviations: $2.25 + 0.25 + 0.25 + 2.25 = 5$, and the same for $y$: $5$.
step: Divide: $r = 4/\sqrt{5 \times 5} = 4/5 = 0.8$, a strong positive linear relationship.
answer: $r = 0.8$.

@mistakes
- Reading a high correlation as proof that one variable causes the other.
- Concluding that $r = 0$ means no relationship, when the relationship may be nonlinear.
- Comparing overall rates between groups without checking whether the groups differ in their mix of another variable.
- Exploring many views of the data, finding one striking pattern, and reporting it as if it had been the plan.

model:
```python
import math


def pearson(xs, ys):
    """Pearson correlation coefficient; 0.0 if either input is constant."""
    n = len(xs)
    mx, my = sum(xs) / n, sum(ys) / n
    sxy = sum((x - mx) * (y - my) for x, y in zip(xs, ys))
    sxx = sum((x - mx) ** 2 for x in xs)
    syy = sum((y - my) ** 2 for y in ys)
    if sxx == 0 or syy == 0:
        return 0.0
    return sxy / math.sqrt(sxx * syy)
```
hint: Compute the two means, then the sum of products of deviations and the two sums of squared deviations.
solution: The coefficient is the sum of products of deviations divided by the square root of the product of the sums of squares. A constant list has a zero sum of squares, so the function must return 0.0 before dividing, as the fifth test checks.

model:
```python
def missing_report(rows):
    """Number of None values in each column."""
    if not rows:
        return {}
    return {c: sum(1 for r in rows if r[c] is None) for c in rows[0]}
```
hint: Count, for each column, the rows whose value `is None`; an empty string or a zero is not missing.
solution: Take the column names from the first row and count the rows with `None` in each. Using `is None` rather than a truthiness test keeps zeros and empty strings from being counted, as the third test checks.

tests:
```python
rows = [
    {"v": "A", "ok": "yes"}, {"v": "A", "ok": "no"}, {"v": "B", "ok": "yes"},
    {"v": "A", "ok": "yes"}, {"v": "B", "ok": "yes"},
]
assert crosstab(rows, "v", "ok") == {"A": {"yes": 2, "no": 1}, "B": {"yes": 2}}

```
model:
```python
def crosstab(rows, a, b):
    """Counts of rows for each pair of values of columns a and b."""
    table = {}
    for row in rows:
        inner = table.setdefault(row[a], {})
        inner[row[b]] = inner.get(row[b], 0) + 1
    return table
```
hint: Use a dictionary of dictionaries and increase the count for the pair `(row[a], row[b])` as you loop.
solution: For each row, find or create the inner dictionary for its `a` value and add 1 to the entry for its `b` value. Swapping the two column names, as the second test does, transposes the table.
