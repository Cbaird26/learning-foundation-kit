@article
A survey table has an `age` column that contains `34`, ` 29`, `n/a`, `41` and `?`. The word "age" suggests a number, but this column is text with two different spellings of "I do not know". Any mean you compute without cleaning is either an error or wrong. Cleaning is the step that turns what was recorded into what was meant.

### Kinds of mess

Raw tables go wrong in a few recurring ways:

- **Missing values**, written as an empty cell, `NA`, `n/a`, `?`, `-`, `null`, or a sentinel such as `-999`.
- **Wrong types**: numbers stored with spaces, thousands separators (`1,250.5`) or units (`12 kg`).
- **Inconsistent labels**: `Male`, `male `, `M` for one category.
- **Duplicate rows**, often from joining or exporting twice.
- **Impossible values**: an age of 240, a negative count.

Cleaning must be done by **functions**, not by hand edits to the file. A function documents what you did, can be tested, and can be run again when the next file arrives.

### Converting to numbers

A reusable converter strips whitespace, maps every missing marker to `None`, removes thousands separators and returns `None` for anything that cannot be parsed:

```python
MISSING = {"", "na", "n/a", "nan", "null", "none", "?", "-"}

def to_float(text):
    t = text.strip()
    if t.lower() in MISSING:
        return None
    try:
        return float(t.replace(",", ""))
    except ValueError:
        return None

ages = [to_float(s) for s in ["34", " 29", "n/a", "41", "?"]]
print(ages)
```

This prints `[34.0, 29.0, None, 41.0, None]`. Note that `-` alone is missing but `-3.5` is a number, and that a converter which silently returns `None` for garbage can hide errors; count how many values became `None` and look at them.

### Handling missing values

You can **drop** rows with missing values, or **impute** (fill in) a replacement. Dropping is simple, but it loses data, and if the missing rows differ from the rest it also biases what remains. The simplest imputations replace each missing value by a column statistic:

- the **mean** of the observed values, $\bar{x} = \frac{1}{m}\sum_{i \in \text{obs}} x_i$, which is sensitive to outliers;
- the **median**, the middle observed value (the average of the two middle values when their number is even), which is not.

For the ages, the observed values are 34, 29, 41 with mean $104/3 \approx 34.67$. Filling both gaps with the mean leaves the mean at 34.67. But the sample variance $s^2 = \frac{1}{n-1}\sum (x_i - \bar{x})^2$ falls from $36.33$ (three values) to $18.17$ (five values): the filled values sit exactly at the center, add nothing to the sum of squares, and increase $n$. Imputation shrinks the apparent spread and so makes later estimates look more certain than they are. When values are missing for a reason related to the variable itself (high earners skipping an income question), no simple fill is right. Keep a **missing indicator** column (`age_missing` is 1 or 0) so that a model or analysis can see which values were filled.

### Labels and duplicates

Inconsistent labels are cleaned by normalizing: strip whitespace, convert to lowercase, collapse repeated spaces, then map synonyms to one name with a dictionary. After `s.strip().lower()`, `" Male"` and `"male "` agree, but `"M"` does not; a mapping `{"m": "male"}` handles that. **Duplicates** are found by choosing the columns that identify a row (a key) and keeping the first row for each key. Decide the key deliberately: two rows with the same customer ID and different dates are different orders.

### Reusable cleaning

Chain small functions: `to_float` for each numeric column, `normalize_label` for each categorical column, `dedupe` once at the end. Test each on a few hand-made inputs (a normal value, an empty string, a surprising one). A cleaning pipeline you can run twice with the same result is the deliverable of this block.

@example
title: Filling missing ages
problem: A column holds the strings `34`, ` 29`, `n/a`, `41`, `?`. Convert it, fill the missing values with the mean, and compare the sample variance before and after.
step: Convert with a function that strips spaces and maps `n/a` and `?` to `None`. The result is $[34, 29, \text{None}, 41, \text{None}]$ and the observed values are 34, 29 and 41.
step: Compute the mean of the observed values: $(34 + 29 + 41)/3 = 104/3 \approx 34.667$.
step: Fill both gaps with 34.667. The column becomes $[34, 29, 34.667, 41, 34.667]$ and its mean is still $34.667$, because the filled values equal the mean.
step: Compare the sample variances. Before (three values) the squared deviations are $0.444$, $32.111$ and $40.111$, which sum to $72.667$, so $s^2 = 72.667/2 = 36.33$. After filling, the sum is unchanged (the new values add 0) but $n - 1 = 4$, so $s^2 = 72.667/4 = 18.17$.
answer: Mean 34.67 before and after; sample variance falls from 36.33 to 18.17.

@mistakes
- Imputing with the mean and then reporting the standard deviation as if the data were complete: the spread is understated.
- Using a sentinel such as `-999` as if it were a real number, which drags every mean and plot.
- Normalizing labels by hand in a spreadsheet, so that the cleaning cannot be repeated or checked.
- Dropping duplicate rows by comparing every column when the real key is one ID column, or the reverse.

@practice code
prompt: Write `to_float(text, decimal)` that converts a messy string to a float, where `decimal` is either `"."` or `","` and is the character that marks the decimal point; the other character is a thousands separator and must be removed. Strip whitespace first. Return `None` if the stripped text, in any capitalization, is one of `""`, `"na"`, `"n/a"`, `"nan"`, `"null"`, `"none"`, `"?"` or `"-"`, and return `None` for any other text that is not a number. For example, `to_float("2.075,25", ",")` returns `2075.25` and `to_float("2,075.25", ".")` returns `2075.25`.
starter:
```python
def to_float(text, decimal):
    return float(text)
```
tests:
```python
def close(a, b):
    return a is not None and abs(a - b) < 1e-9

assert close(to_float("1.250,5", ","), 1250.5)
assert close(to_float("1,250.5", "."), 1250.5)
assert close(to_float(" 3,5 ", ","), 3.5)
assert close(to_float("-0,25", ","), -0.25)
assert close(to_float("1.234.567", ","), 1234567.0)
assert close(to_float("1.5", ","), 15.0)
assert close(to_float("1,5", "."), 15.0)
assert to_float("N/A", ",") is None
assert to_float("NaN", ".") is None
assert to_float(" ", ",") is None
assert to_float(" ? ", ".") is None
assert to_float("-", ",") is None
assert to_float("1,5,5", ",") is None
assert to_float("abc", ",") is None
```
model:
```python
MISSING = {"", "na", "n/a", "nan", "null", "none", "?", "-"}


def to_float(text, decimal):
    """Convert a messy string to a float, or None if it is missing or bad."""
    t = text.strip()
    if t.lower() in MISSING:
        return None
    if decimal == ",":
        t = t.replace(".", "").replace(",", ".")
    else:
        t = t.replace(",", "")
    try:
        return float(t)
    except ValueError:
        return None
```
hint: Handle the missing markers first. Then remove the thousands separator and, when the decimal character is a comma, turn it into a period before calling `float`; remove the thousands separator before you convert the decimal comma, or the two will collide.
solution: The two characters swap roles when `decimal` is `","`: periods are thousands separators and are deleted, and only then is the decimal comma turned into a period that `float` understands. A solution that only swaps the comma for a period fails the first test, because `"1.250,5"` becomes `"1.250.5"` and cannot be parsed. A solution that ignores `decimal`, like the article's function, fails the test with `" 3,5 "`, which it reads as 35. The tests with `"1.5"` and `"1,5"` check that the thousands separator is deleted, not kept as a decimal point (so a period in a comma-decimal text gives 15.0, and a comma in a period-decimal text gives 15.0). The remaining tests check the missing markers with either setting (`float` itself would turn `"NaN"` into a number, so the marker check must come first) and that `"1,5,5"`, which has two decimal commas, is rejected.

@practice code
prompt: Write `fill_missing(values, strategy)` that takes a list of numbers in which some entries are `None` and returns a new list in which each `None` is replaced by the mean (when `strategy` is `"mean"`) or the median (when `strategy` is `"median"`) of the entries that are not `None`. For an even number of observed values the median is the average of the two middle values. If every entry is `None`, return a copy unchanged. Do not modify the input list.
starter:
```python
def fill_missing(values, strategy):
    return values
```
tests:
```python
assert fill_missing([2, None, 3, 4, None, 15], "median") == [2, 3.5, 3, 4, 3.5, 15]
assert fill_missing([1, None, 2], "mean") == [1, 1.5, 2]
assert fill_missing([None, None], "mean") == [None, None]
v = [1, None]
assert fill_missing(v, "median") == [1, 1]
assert v == [1, None]
assert fill_missing([5, None, 1, 9], "median") == [5, 5, 1, 9]
```
model:
```python
def fill_missing(values, strategy):
    """Replace None entries by the mean or median of the observed entries."""
    observed = sorted(v for v in values if v is not None)
    if not observed:
        return list(values)
    if strategy == "mean":
        fill = sum(observed) / len(observed)
    else:
        mid = len(observed) // 2
        if len(observed) % 2:
            fill = observed[mid]
        else:
            fill = (observed[mid - 1] + observed[mid]) / 2
    return [fill if v is None else v for v in values]
```
hint: Sort the observed values; the median is the middle one, or the average of the two middle ones when the count is even.
solution: Collect and sort the observed values, compute the chosen statistic, and build a new list that substitutes it for `None`. The first test needs the even-count median, 3.5, and the unchanged input list in the fifth test shows the function did not modify its argument.

@quiz code
prompt: Write `dedupe(rows, key)` where `rows` is a list of dictionaries and `key` is a list of column names. Return a new list that keeps only the first row for each distinct combination of the values in the key columns, in the original order. For example, with `key=["id"]`, two rows that both have `id` 1 leave only the earlier one.
starter:
```python
def dedupe(rows, key):
    return list(rows)
```
tests:
```python
rows = [{"id": 1, "v": "a"}, {"id": 2, "v": "b"}, {"id": 1, "v": "c"}]
assert dedupe(rows, ["id"]) == [rows[0], rows[1]]
assert dedupe(rows, ["id", "v"]) == rows
assert dedupe([], ["id"]) == []
two = [{"a": 1, "b": 1}, {"a": 1, "b": 2}, {"a": 1, "b": 1}]
assert dedupe(two, ["a", "b"]) == [two[0], two[1]]
assert dedupe(two, ["a"]) == [two[0]]
```
model:
```python
def dedupe(rows, key):
    """Keep the first row for each distinct combination of key values."""
    seen = set()
    kept = []
    for row in rows:
        k = tuple(row[c] for c in key)
        if k not in seen:
            seen.add(k)
            kept.append(row)
    return kept
```
hint: Build a tuple of the key values for each row and remember the tuples you have seen.
solution: A set of key tuples records which combinations have appeared; a row is kept only when its tuple is new, which preserves order and keeps the first occurrence. Choosing the key columns is the real decision: the last two tests show the same rows are duplicates under one key and distinct under another.
