@article
A colleague hands you a file with a column called `score` and says it is ready to use. Is it a percentage or a count? Is 999 a real score or a code for "absent"? Who was measured, and when? A data set without documentation answers none of these, and the next person will guess. Documentation is the part of data science that lets other people, and you six months from now, trust the work.

### The data dictionary

A **data dictionary** describes the columns of one table. For each column it records:

| field | example for a column `age` |
|---|---|
| name | `age` |
| description | age of the respondent at the survey date |
| type | integer |
| unit | years |
| allowed values | whole numbers from 0 to 120 |
| missing-value code | empty cell (never 0 or -1) |
| source | question 3 of the intake form |

Also record the unit of observation of the table (one row per respondent), the key column that identifies a row, and any derived columns with the formula used. A dictionary is not decoration: it can be checked by code. Given rules for each column, a **validation** function lists the cells that break them (an age of 150, a sex of `x`), which turns the dictionary into a test you can rerun every time the data change.

```python
rules = {"age": ("range", 0, 120), "sex": ("allowed", ["f", "m"])}
rows = [{"age": 30, "sex": "f"}, {"age": 150, "sex": "x"}]
bad = []
for i, row in enumerate(rows):
    for col, rule in rules.items():
        v = row[col]
        if rule[0] == "range" and not rule[1] <= v <= rule[2]:
            bad.append((i, col))
        if rule[0] == "allowed" and v not in rule[1]:
            bad.append((i, col))
print(bad)
```

This prints `[(1, 'age'), (1, 'sex')]`.

### Profiling

A **profile** is a short automatic summary of each column: the number of values, how many are missing, how many distinct values there are, and the kind (numeric or text), plus the minimum and maximum for numeric columns. For ages $34, 29, \text{None}, 41, 29$ the profile has 5 values, 1 missing, 3 distinct values, and kind numeric. Profiles reveal problems early (a column with a single distinct value, a numeric column holding text) and belong in the documentation as a record of what the data looked like when you finished cleaning.

### The datasheet

A data dictionary describes columns; a **datasheet** describes the whole data set and how it came to be. Gebru and colleagues proposed datasheets for data sets in 2018, modeled on the spec sheets that accompany electronic components, with questions grouped into these sections:

1. **Motivation**: why the data set was created, by whom, and who paid for it.
2. **Composition**: what the rows represent, how many there are, whether it is a sample of a larger set, what is missing, and whether it contains personal or sensitive information.
3. **Collection process**: how the data were acquired, over what period, with what consent, and by what instrument.
4. **Preprocessing, cleaning and labeling**: what was done to the raw data (the functions of week 3), and whether the raw data are kept.
5. **Uses**: what tasks the data are suitable for, and what they should not be used for.
6. **Distribution**: how the data are shared, under what license and terms.
7. **Maintenance**: who maintains it, how errors are reported, and whether it will be updated.

You do not need a long document. Even a page that answers "who is in this data, who is not, and what would be a mistake to use it for?" prevents the failures of weeks 7 and 10.

### Coverage and missingness by group

Documentation should say who is missing. Overall, a column that is 10% missing may be 2% missing for one group and 25% for another, and then any analysis that drops missing rows quietly underrepresents the second group. A table of the **missing rate by group** is a simple, honest piece of documentation. For example, if the 40 rows from clinic A have 2 missing incomes and the 50 rows from clinic B have 20, the rates are 5% and 40%, and the overall rate of $22/90 \approx 24\%$ hides the difference.

### Versions and provenance

Keep the raw file unchanged, save the cleaning code, and give each released version an identifier and a date. A datasheet that says "cleaned with `clean.py`, version 3, from the raw export of March" lets a reader reproduce the table. Without provenance, a number in a report cannot be traced back to its source.

@example
title: Profiling a column and validating it
problem: The column `age` has the values 34, 29, None, 41, 29 and 130, and the dictionary says allowed values are whole numbers from 0 to 120 with `None` for missing. Profile the column and list the rows that break the rule.
step: Count the values: there are 6, of which 1 is missing (`None`), so 5 are present.
step: Count the distinct present values: 34, 29, 41 and 130, which is 4 distinct values. Since all present values are numbers, the kind is numeric.
step: Validate each present value against the range 0 to 120 inclusive. The values 34, 29, 41 and 29 pass. The value 130 fails, in row 5 (counting from 0). The missing value is not a violation, because the dictionary allows it.
step: Report: 6 values, 1 missing (16.7%), 4 distinct, numeric, 1 violation in row 5. The next step is to look at the source of the row and decide whether to fix it or mark it missing, and to record the decision in the datasheet.
answer: 6 values, 1 missing, 4 distinct, numeric; the value 130 in row 5 violates the allowed range.

@mistakes
- Using a number such as 999 or -1 for missing without recording it, so the next reader averages it.
- Writing a datasheet that describes only the best uses of the data and says nothing about who is missing or what it should not be used for.
- Documenting the cleaned data but discarding the raw data and the cleaning code, so the table cannot be reproduced.
- Reporting only the overall missing rate when the rate differs sharply between groups.

@practice code
prompt: Write `profile_column(values)` for a list of values in which missing entries are `None`. It returns a dictionary with the keys `"count"` (the length of the list), `"missing"` (the number of `None` entries), `"unique"` (the number of distinct entries that are not `None`) and `"kind"`. The kind is `"empty"` if no entry is present, `"numeric"` if every present entry is an `int` or `float` and not a `bool`, and `"text"` otherwise. For example, `profile_column([1, 2, 2, None])` returns `{"count": 4, "missing": 1, "unique": 2, "kind": "numeric"}`.
starter:
```python
def profile_column(values):
    return {}
```
tests:
```python
assert profile_column([1, 2, 2, None]) == {"count": 4, "missing": 1, "unique": 2, "kind": "numeric"}
assert profile_column(["a", None, "b"]) == {"count": 3, "missing": 1, "unique": 2, "kind": "text"}
assert profile_column([None, None]) == {"count": 2, "missing": 2, "unique": 0, "kind": "empty"}
assert profile_column([1, "a"])["kind"] == "text"
assert profile_column([]) == {"count": 0, "missing": 0, "unique": 0, "kind": "empty"}
assert profile_column([True, False])["kind"] == "text"
```
model:
```python
def profile_column(values):
    """Count, missing, distinct and kind of a column."""
    present = [v for v in values if v is not None]
    if not present:
        kind = "empty"
    elif all(isinstance(v, (int, float)) and not isinstance(v, bool) for v in present):
        kind = "numeric"
    else:
        kind = "text"
    return {
        "count": len(values),
        "missing": len(values) - len(present),
        "unique": len(set(present)),
        "kind": kind,
    }
```
hint: First separate the present values from the `None` entries; every other number comes from the present list.
solution: The present values give the number of distinct entries and decide the kind, while the missing count is the difference between the list length and the number present. The `bool` case matters because `True` is an `int` in Python, as the last test checks.

@practice code
prompt: Write `validate(rows, rules)` where `rows` is a list of dictionaries and `rules` maps a column name to either `("range", lo, hi)` (the value must satisfy `lo <= value <= hi`) or `("allowed", values)` (the value must be in the list `values`). Return the list of `(row_index, column)` pairs for the cells that break their rule, sorted by row index and then column name. A value of `None` (or a missing key) is never a violation.
starter:
```python
def validate(rows, rules):
    return []
```
tests:
```python
rules = {"age": ("range", 0, 120), "sex": ("allowed", ["f", "m"])}
rows = [{"age": 30, "sex": "f"}, {"age": 150, "sex": "x"}, {"age": None, "sex": "m"}]
assert validate(rows, rules) == [(1, "age"), (1, "sex")]
assert validate([{"age": 120}, {"age": 0}], rules) == []
assert validate([{"age": -1, "sex": None}], rules) == [(0, "age")]
assert validate([], rules) == []
assert validate([{"sex": "m", "age": 121}, {"sex": "q", "age": 5}], rules) == [(0, "age"), (1, "sex")]
```
model:
```python
def validate(rows, rules):
    """List (row_index, column) cells that violate their rule."""
    bad = []
    for i, row in enumerate(rows):
        for col, rule in rules.items():
            v = row.get(col)
            if v is None:
                continue
            if rule[0] == "range":
                ok = rule[1] <= v <= rule[2]
            else:
                ok = v in rule[1]
            if not ok:
                bad.append((i, col))
    return sorted(bad)
```
hint: Loop over rows and rules, skip `None`, apply the range or allowed test, and sort the violations at the end.
solution: Each present cell is checked by its rule, with inclusive bounds for ranges, and the violations are collected as `(row_index, column)` pairs. Sorting the pairs gives row-then-column order, which the last test needs because the rule dictionary is not visited in alphabetical order.

@quiz code
prompt: Write `missing_by_group(rows, group, col)` where `rows` is a list of dictionaries. It returns a dictionary that maps each value of `row[group]` to the fraction (a float between 0 and 1) of the rows in that group whose `row[col]` is `None`. An empty list gives `{}`. For example, a group with 2 rows of which 1 has `None` maps to `0.5`.
starter:
```python
def missing_by_group(rows, group, col):
    return {}
```
tests:
```python
rows = [
    {"clinic": "A", "income": 50}, {"clinic": "A", "income": None},
    {"clinic": "B", "income": 40}, {"clinic": "B", "income": 41},
    {"clinic": "B", "income": 42}, {"clinic": "B", "income": None},
]
got = missing_by_group(rows, "clinic", "income")
assert set(got) == {"A", "B"}
assert abs(got["A"] - 0.5) < 1e-9 and abs(got["B"] - 0.25) < 1e-9
assert missing_by_group([], "clinic", "income") == {}
got = missing_by_group([{"g": 1, "v": 0}, {"g": 1, "v": ""}], "g", "v")
assert abs(got[1]) < 1e-9
```
model:
```python
def missing_by_group(rows, group, col):
    """Fraction of rows with a missing value of col, for each group."""
    total = {}
    missing = {}
    for row in rows:
        g = row[group]
        total[g] = total.get(g, 0) + 1
        if row[col] is None:
            missing[g] = missing.get(g, 0) + 1
    return {g: missing.get(g, 0) / n for g, n in total.items()}
```
hint: Count the rows and the missing values per group, then divide the second by the first.
solution: Two dictionaries hold the number of rows and the number of missing values for each group, and the result divides them, using 0 for groups with no missing value. Zeros and empty strings are not missing, which the last test checks.
