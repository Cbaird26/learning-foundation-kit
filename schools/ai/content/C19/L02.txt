@article
A word-level vocabulary has two problems. Any word not seen in training ("unfriendliest") becomes an unknown token, and a vocabulary that covers a large corpus has hundreds of thousands of types, most of them rare. Characters have the opposite problem: no unknown words, but long sequences in which a single letter carries almost no meaning. **Subword tokenization** sits between them: frequent words are single tokens, and rare words are spelled out from pieces such as "un", "friend", "li", "est". **Byte-pair encoding** (BPE), adapted to subword units for neural machine translation by Sennrich, Haddow and Birch (2016), learns such a vocabulary from data with one simple loop.

### The algorithm

BPE starts from words written as sequences of characters, plus an end-of-word symbol `_` so that a piece at the end of a word differs from the same letters inside a word. Each distinct word comes with its frequency in the corpus. Then repeat:

1. Count every pair of adjacent symbols, weighting each pair by the frequency of the word it appears in.
2. Pick the pair with the highest count. **Tie-breaking rule used in this course:** among tied pairs, take the one that is smallest when the two symbols are compared as a Python tuple of strings (first symbol, then second; the character `_` sorts before lowercase letters).
3. Merge it: replace every occurrence of the pair, scanning each word from left to right, by one new symbol that joins the two. Record the merge.

After $k$ merges, the vocabulary is the starting alphabet plus $k$ new symbols, so **the number of merges sets the vocabulary size**.

### A small run

Corpus: `hug` 4 times, `hugs` 2, `bug` 3, `mug` 2. The starting symbols are `h u g s b m _` (7). The pair counts at the start include $(u, g) = 4 + 2 + 3 + 2 = 11$ and $(g, \_) = 4 + 3 + 2 = 9$, so the first merge is $(u, g)$. The table shows the first merges (each count is computed after the earlier merges):

| merge | pair | count | resulting words |
|---|---|---|---|
| 1 | $(u, g)$ | 11 | `h ug _`, `h ug s _`, `b ug _`, `m ug _` |
| 2 | $(ug, \_)$ | 9 | `h ug_`, `h ug s _`, `b ug_`, `m ug_` |
| 3 | $(h, ug\_)$ | 4 | `hug_`, `h ug s _`, `b ug_`, `m ug_` |

To segment a new word, **replay the merges in the order they were learned**. For `mugs`, start from `m u g s _`; merge 1 gives `m ug s _`, and no later merge applies, so the encoding is `m`, `ug`, `s`, `_`. A word never seen in training is covered by pieces learned from other words. If a character itself was never seen, a character-level BPE needs an unknown symbol; **byte-level** variants start from the 256 possible byte values, so every string can be encoded.

### In code

```python
from collections import Counter

def pair_counts(vocab):
    """vocab maps a tuple of symbols to a frequency."""
    counts = Counter()
    for symbols, freq in vocab.items():
        for pair in zip(symbols, symbols[1:]):
            counts[pair] += freq
    return counts

def merge_pair(vocab, pair):
    new_vocab = {}
    for symbols, freq in vocab.items():
        out, i = [], 0
        while i < len(symbols):
            if i + 1 < len(symbols) and (symbols[i], symbols[i + 1]) == pair:
                out.append(symbols[i] + symbols[i + 1])
                i += 2
            else:
                out.append(symbols[i])
                i += 1
        key = tuple(out)
        new_vocab[key] = new_vocab.get(key, 0) + freq
    return new_vocab

def train_bpe(words, num_merges):
    vocab = {tuple(w) + ("_",): f for w, f in words.items()}
    merges = []
    for _ in range(num_merges):
        counts = pair_counts(vocab)
        if not counts:
            break
        top = max(counts.values())
        best = min(p for p, c in counts.items() if c == top)
        merges.append(best)
        vocab = merge_pair(vocab, best)
    return merges

def encode(word, merges):
    vocab = {tuple(word) + ("_",): 1}
    for pair in merges:
        vocab = merge_pair(vocab, pair)
    return list(next(iter(vocab)))

merges = train_bpe({"hug": 4, "hugs": 2, "bug": 3, "mug": 2}, 6)
print(merges[:3])
print(encode("mugs", merges))
```

The program prints `[('u', 'g'), ('ug', '_'), ('h', 'ug_')]` and `['m', 'ug', 's', '_']`. `encode` wraps the word in a one-entry vocabulary so that it can reuse `merge_pair`. Production tokenizers add speed (priority queues, caches) and work on bytes, but they compute the same merges.

### Limits

BPE is greedy and frequency-driven. It does not know morphology: it may produce a piece like `ug` that is not a meaningful unit. Related methods choose pieces differently: WordPiece, used in BERT, picks merges that increase the likelihood of the training data, and the unigram language model method prunes a large starting vocabulary. All of them give frequent strings short codes and rare strings long ones.

@example
title: Three merges with a tie
problem: Run BPE for three merges on the corpus `low` 5, `lower` 2, `lowest` 3, `new` 4, using the end symbol `_` and the course tie-breaking rule.
step: Start: `l o w _` (5), `l o w e r _` (2), `l o w e s t _` (3), `n e w _` (4). Count pairs: $(l, o) = 5 + 2 + 3 = 10$, $(o, w) = 10$, $(w, \_) = 5 + 4 = 9$, $(w, e) = 5$, $(e, w) = 4$, and smaller ones. The top count 10 is shared by $(l, o)$ and $(o, w)$.
step: Break the tie: compare the tuples; `l` comes before `o`, so merge 1 is $(l, o)$. Words: `lo w _`, `lo w e r _`, `lo w e s t _`, `n e w _`.
step: Now $(lo, w) = 10$ is the unique maximum. Merge 2 is $(lo, w)$, giving `low _` (5), `low e r _` (2), `low e s t _` (3).
step: Counts: $(low, \_) = 5$, $(low, e) = 5$, and $(w, \_)$ is no longer a pair except in `n e w _`, where $(w, \_) = 4$. The tie between $(low, \_)$ and $(low, e)$ goes to $(low, \_)$ because `_` sorts before `e`. Merge 3 is $(low, \_)$.
answer: Merges: $(l, o)$, $(lo, w)$, $(low, \_)$.

@example
title: Segmenting an unseen word
problem: The learned merges, in order, are $(l,o)$, $(lo,w)$, $(low,\_)$, $(low,e)$, $(e,w)$, $(ew,\_)$. Segment the word `newest`.
step: Start from the characters and the end symbol: `n e w e s t _`.
step: Replay the merges in order. $(l,o)$, $(lo,w)$, $(low,\_)$ and $(low,e)$ find nothing.
step: $(e,w)$ matches the `e w` at positions 2 and 3: `n ew e s t _`. The next merge $(ew,\_)$ needs `ew` followed by `_`, but `ew` is followed by `e`, so nothing changes.
answer: `n`, `ew`, `e`, `s`, `t`, `_` (6 symbols).

@mistakes
- Counting a pair once per word instead of once per occurrence times the word's frequency.
- Segmenting a new word by the longest piece that fits instead of replaying the merges in learned order; the two procedures can give different results.
- Forgetting the end-of-word symbol, which makes the piece `s` at the end of "hugs" the same symbol as the `s` inside "bust" and loses the cue for plurals.
- Merging overlapping pairs: in `a a a`, the pair $(a, a)$ is merged left to right and gives `aa a`, not `a aa` and not `aaa`.

```python
from collections import Counter


def train_bpe_min_count(words, min_count):
    """Learn BPE merges until the best pair is rarer than min_count."""
    vocab = {tuple(w) + ("_",): f for w, f in words.items()}
    merges = []
    while True:
        counts = Counter()
        for symbols, freq in vocab.items():
            for pair in zip(symbols, symbols[1:]):
                counts[pair] += freq
        if not counts:
            break
        top = max(counts.values())
        if top < min_count:
            break
        best = min(p for p, c in counts.items() if c == top)
        merges.append(best)
        new_vocab = {}
        for symbols, freq in vocab.items():
            out, i = [], 0
            while i < len(symbols):
                if i + 1 < len(symbols) and (symbols[i], symbols[i + 1]) == best:
                    out.append(symbols[i] + symbols[i + 1])
                    i += 2
                else:
                    out.append(symbols[i])
                    i += 1
            key = tuple(out)
            new_vocab[key] = new_vocab.get(key, 0) + freq
        vocab = new_vocab
    return merges
```
hint: Turn the fixed number of merges into a loop that ends when there are no pairs left or the top count falls below `min_count`.
solution: The loop is the one from the article with a different stopping rule. Because the loop must also end when every word is a single symbol, test for an empty pair counter before looking at the maximum. The `{"aaa": 2, "ba": 1}` test checks the left-to-right, non-overlapping merge of `a a a`.

model:
```python
def encode_longest(word, vocab):
    """Greedy longest-match segmentation with an unknown fallback."""
    out = []
    i = 0
    while i < len(word):
        for j in range(len(word), i, -1):
            if word[i:j] in vocab:
                out.append(word[i:j])
                i = j
                break
        else:
            out.append("<unk>")
            i += 1
    return out
```
hint: At each position try the longest slice first, shrinking the end index until a slice is in the vocabulary; a `for ... else` handles the no-match case.
solution: Longest-match segmentation is greedy: it never looks ahead. The last test shows it: the longest match `ab` leaves `c` and `d`, three pieces, while `a` followed by `bcd` would need only two. That is one reason subword methods define their segmentation rule carefully.

```python
def merge_symbols(symbols, pair):
    """Replace non-overlapping adjacent occurrences of pair, left to right."""
    out = []
    i = 0
    while i < len(symbols):
        if i + 1 < len(symbols) and (symbols[i], symbols[i + 1]) == pair:
            out.append(symbols[i] + symbols[i + 1])
            i += 2
        else:
            out.append(symbols[i])
            i += 1
    return out
```

solution: The index jump of 2 after a merge is what prevents overlapping merges, so `a a a` becomes `aa a`. Building a new list leaves the input unchanged.

solution: BPE encoding replays the merges in learned order, so that the same word is always segmented the same way, whatever text surrounds it.
