@article
A trained language model gives, for each prefix, a probability distribution over the next token. It does not say what text to write. **Decoding** is the procedure that turns those distributions into an output sequence, and the choice matters as much as the model for the quality, diversity and cost of the output.

### The search problem

The model assigns a sequence $y_1\dots y_m$ the probability $\prod_t p(y_t \mid y_{<t})$. The most probable sequence is the **maximum a posteriori** (MAP) output, but there are $|V|^m$ candidates, so we search approximately. Our toy model has tokens $a, b, x, y, z$ and an end token `</s>`:

| prefix | next-token distribution |
|---|---|
| (empty) | a 0.6, b 0.4 |
| a | x 0.4, y 0.3, z 0.3 |
| b | `</s>` 0.9, x 0.1 |
| x, y or z | `</s>` 1.0 |

**Greedy decoding** takes the most probable token at each step, with ties broken by the alphabetically smaller token. Here it picks a (0.6), then x (0.4), then `</s>`: the sequence "a x" with probability $0.6 \times 0.4 = 0.24$. But the sequence "b" has probability $0.4 \times 0.9 = 0.36$, which is higher. A locally best first step can lead to poor continuations.

### Beam search

**Beam search** keeps the $B$ best partial sequences (by total log-probability) at every step. For each step: extend every unfinished hypothesis by every token, rank all extensions by log-probability (ties broken by the token sequence, alphabetically), keep the top $B$, and move those that ended with `</s>` to a finished list. Stop when no unfinished hypothesis remains or a maximum length is reached, then return the finished hypothesis with the highest score. With $B = 1$ it is greedy decoding. With $B = 2$ on our model: after step 1 the beam holds a (0.6) and b (0.4); after step 2 the candidates are "b `</s>`" (0.36), "a x" (0.24), "a y" and "a z" (0.18 each) and "b x" (0.04), so the beam keeps "b `</s>`", which finishes, and "a x". Step 3 finishes "a x `</s>`" (0.24). The best finished sequence is "b" with probability 0.36. Beam search is not exact either: a larger $B$ explores more but costs $B|V|$ candidate scores per step.

Raw probability favors short sequences, because each extra token multiplies by a number below 1. A common fix is **length normalization**: rank finished hypotheses by the average log-probability per token (including `</s>`) instead of the total. For our model, "b" scores $\ln 0.36 / 2 = -0.511$ and "a x" scores $\ln 0.24 / 3 = -0.476$, so with normalization the longer sequence wins.

```python
import math

def greedy(model, max_len):
    """model(prefix_tuple) -> {token: prob}. Ties go to the smaller token."""
    seq = []
    for _ in range(max_len):
        dist = model(tuple(seq))
        token = min(dist, key=lambda t: (-dist[t], t))
        if token == "</s>":
            break
        seq.append(token)
    return seq

def beam_search(model, width, max_len):
    beams, finished = [((), 0.0)], []
    for _ in range(max_len):
        cands = [(seq + (t,), lp + math.log(p))
                 for seq, lp in beams for t, p in model(seq).items() if p > 0]
        cands.sort(key=lambda c: (-c[1], c[0]))
        beams = []
        for c in cands[:width]:
            (finished if c[0][-1] == "</s>" else beams).append(c)
        if not beams:
            break
    finished += beams
    best = min(finished, key=lambda c: (-c[1], c[0]))[0]
    return [t for t in best if t != "</s>"]
```

### Sampling

Maximizing probability tends to give repetitive, generic text in open-ended generation; it suits translation or summarization, where there is a narrow set of good outputs, better than story writing. **Sampling** draws each token at random from the model's distribution, which gives diverse output but sometimes picks a very unlikely token. Three controls reshape the distribution before sampling:

- **Temperature** $T > 0$: $p_i \leftarrow p_i^{1/T} / \sum_j p_j^{1/T}$. For logits $z_i$ this is $\operatorname{softmax}(z_i/T)$. Low $T$ sharpens the distribution toward greedy decoding; $T = 1$ leaves it unchanged; high $T$ flattens it toward uniform.
- **Top-$k$**: keep the $k$ most probable tokens, set the rest to 0 and renormalize.
- **Top-$p$** (nucleus sampling, Holtzman and colleagues, 2019): keep the smallest set of most probable tokens whose cumulative probability is at least $p$, and renormalize. The number of tokens kept adapts to how confident the model is, unlike a fixed $k$.

Each controls the tradeoff between diversity and the risk of incoherent text, and the settings that work depend on the model and the task.

@example
title: Top-k and top-p filtering
problem: A next-token distribution is $a: 0.5$, $b: 0.3$, $c: 0.15$, $d: 0.05$. Apply top-$k$ with $k = 2$, and top-$p$ with $p = 0.9$.
step: Top-2 keeps $a$ and $b$, with total mass $0.8$. Renormalize: $a = 0.5/0.8 = 0.625$ and $b = 0.3/0.8 = 0.375$.
step: For top-$p$, sort and accumulate: $0.5$, then $0.8$ (still below 0.9), then $0.95$ (at least 0.9) after adding $c$. The nucleus is $\{a, b, c\}$ with mass $0.95$.
step: Renormalize: $a = 0.5263$, $b = 0.3158$, $c = 0.1579$; token $d$ gets probability 0.
answer: Top-2: $a = 0.625$, $b = 0.375$. Top-0.9: $a = 0.526$, $b = 0.316$, $c = 0.158$.

@example
title: Temperature
problem: Apply temperature $T = 0.5$ to the distribution $a: 0.5$, $b: 0.3$, $c: 0.15$, $d: 0.05$.
step: Raise each probability to the power $1/T = 2$: $0.25$, $0.09$, $0.0225$, $0.0025$.
step: The sum is $0.365$. Divide: $0.6849$, $0.2466$, $0.0616$, $0.0068$.
step: The most probable token gained mass (from $0.5$ to $0.685$): low temperature sharpens.
answer: $(0.685, 0.247, 0.062, 0.007)$.

@mistakes
- Believing that beam search finds the most probable sequence: it is a heuristic, exact only if the beam never discards the optimum.
- Ranking hypotheses of different lengths by total log-probability without thinking about the bias toward short ones.
- Applying the temperature after top-$k$ without renormalizing, or the reverse, and getting probabilities that do not sum to 1.
- Treating the highest-probability text as the best text: for open-ended generation it is often repetitive.

model:
```python
def top_p_filter(probs, p):
    """Nucleus filtering: smallest top set with cumulative probability >= p."""
    ordered = sorted(probs.items(), key=lambda kv: (-kv[1], kv[0]))
    kept, total = [], 0.0
    for token, prob in ordered:
        kept.append((token, prob))
        total += prob
        if total >= p - 1e-12:
            break
    return {token: prob / total for token, prob in kept}
```
hint: Sort by decreasing probability, add tokens one at a time to the kept list and to a running total, and stop right after the total reaches `p`.
solution: The token that crosses the threshold is included, because the nucleus is the smallest set whose mass is at least `p`. Dividing by the kept mass renormalizes. The tie-break rule matters in the last test, where `y` and `z` have equal probability.

```python
import math


def beam_search_norm(model, width, max_len):
    """Beam search that picks the best finished hypothesis by mean log-probability."""
    beams, finished = [((), 0.0)], []
    for _ in range(max_len):
        cands = [(seq + (t,), lp + math.log(p))
                 for seq, lp in beams for t, p in model(seq).items() if p > 0]
        cands.sort(key=lambda c: (-c[1], c[0]))
        beams = []
        for c in cands[:width]:
            (finished if c[0][-1] == "</s>" else beams).append(c)
        if not beams:
            break
    finished += beams
    best = min(finished, key=lambda c: (-c[1] / len(c[0]), c[0]))[0]
    return [t for t in best if t != "</s>"]
```
hint: Prune by total log-probability at each step, but choose the final answer by dividing each total by its length.
solution: Pruning and final selection use different scores. With this model the shorter sequence "q" has total probability 0.4, higher than the 0.3 of "p r", but its mean log-probability per token is lower, so normalization chooses "p r". Using the total instead returns `["q"]` for beam width 2.

model:
```python
import math


def temperature_probs(logits, T):
    """Softmax of logits / T, computed stably."""
    scaled = [z / T for z in logits]
    top = max(scaled)
    exps = [math.exp(s - top) for s in scaled]
    total = sum(exps)
    return [e / total for e in exps]
```
hint: Divide each logit by `T` first, subtract the largest scaled value, then exponentiate and normalize.
solution: Subtracting the maximum does not change a softmax but keeps the exponentials at most 1, so logits of 1000 do not overflow. Dividing by `T` before the softmax is the same as raising probabilities to the power $1/T$ and renormalizing.
