@article
Is a message spam? Is a review positive? Which topic does a news item belong to? Text classification assigns a label $y$ from a small set to a document $d$. Two classical methods are the best way to see the main ideas: a **generative** model of how documents are written (naive Bayes) and a **discriminative** model of the label given the document (logistic regression).

### Bag of words

Both methods start from the **bag-of-words** representation: forget word order and keep only which words occur, and how often. The document "good fun" and "fun good" are the same bag. It loses a lot, such as negation ("not good"), and still works well for many tasks.

### Naive Bayes

Bayes' rule gives $P(y \mid d) \propto P(y)\,P(d \mid y)$. The **naive** assumption is that the words are independent given the class, so for a document with words $w_1,\dots,w_m$:
$$\hat{y} = \arg\max_y \Big[\log P(y) + \sum_{i=1}^{m} \log P(w_i \mid y)\Big].$$
Parameters are estimated by counting. The prior is $P(y) = N_y/N$ (documents of class $y$ over all documents). The word probability uses add-one smoothing, as in week 3:
$$P(w \mid y) = \frac{\mathrm{count}(w, y) + 1}{\sum_{w'} \mathrm{count}(w', y) + |V|}.$$
Words not in the training vocabulary are ignored at test time. We add logs rather than multiply probabilities, which avoids underflow.

Training data (invented): positive: "great fun movie", "good fun", "good acting"; negative: "boring slow movie", "bad boring", "slow bad acting". The vocabulary has $|V| = 8$ words; the positive class has 7 word tokens and the negative class 8, and both priors are $1/2$. Classify "bad movie":

- positive: $\log\frac12 + \log\frac{0+1}{7+8} + \log\frac{1+1}{7+8} = -0.693 - 2.708 - 2.015 = -5.416$,
- negative: $\log\frac12 + \log\frac{2+1}{8+8} + \log\frac{1+1}{8+8} = -0.693 - 1.674 - 2.079 = -4.447$.

The negative score is larger, so the prediction is negative. The two scores are not probabilities; to get $P(y\mid d)$ we exponentiate and normalize.

### Logistic regression

Logistic regression models the label directly. For a binary label $y \in \{0,1\}$ and a feature vector $\mathbf{x}$ (for example word counts), $P(y = 1 \mid \mathbf{x}) = \sigma(\mathbf{w}^\top\mathbf{x} + b)$. The **cross-entropy loss** on one example is $\ell = -y\log \hat{p} - (1-y)\log(1-\hat{p})$ with $\hat p = \sigma(z)$, and its gradient is the simple expression
$$\frac{\partial \ell}{\partial \mathbf{w}} = (\hat{p} - y)\,\mathbf{x},\qquad \frac{\partial \ell}{\partial b} = \hat{p} - y.$$
(Derivation: $\frac{d\ell}{dz} = \hat p - y$ because $\sigma'(z) = \sigma(z)(1-\sigma(z))$, and $\partial z/\partial \mathbf{w} = \mathbf{x}$.) Gradient descent updates $\mathbf{w} \leftarrow \mathbf{w} - \eta(\hat p - y)\mathbf{x}$. Unlike naive Bayes, logistic regression does not assume independent features, so correlated words share the credit through the weights. Naive Bayes trains in one pass of counting and works well with little data; logistic regression usually wins with more data and correlated features, and it can be regularized.

```python
import math
from collections import Counter

def train_nb(docs):
    """docs: list of (text, label). Returns priors, word counts, vocabulary."""
    labels = Counter(label for _, label in docs)
    counts = {label: Counter() for label in labels}
    for text, label in docs:
        counts[label].update(text.split())
    vocab = {w for c in counts.values() for w in c}
    return labels, counts, vocab

def nb_scores(model, text):
    labels, counts, vocab = model
    n_docs = sum(labels.values())
    scores = {}
    for label in labels:
        total = sum(counts[label].values())
        s = math.log(labels[label] / n_docs)
        for w in text.split():
            if w in vocab:
                s += math.log((counts[label][w] + 1) / (total + len(vocab)))
        scores[label] = s
    return scores

def sgd_step(w, b, x, y, lr):
    z = sum(wi * xi for wi, xi in zip(w, x)) + b
    p = 1 / (1 + math.exp(-z))
    return [wi - lr * (p - y) * xi for wi, xi in zip(w, x)], b - lr * (p - y)
```

### Evaluation

With a positive class, a classifier's decisions fall into true positives (TP), false positives (FP) and false negatives (FN). **Precision** is $\mathrm{TP}/(\mathrm{TP}+\mathrm{FP})$, **recall** is $\mathrm{TP}/(\mathrm{TP}+\mathrm{FN})$, and **F1** is their harmonic mean $2PR/(P+R)$. **Accuracy** can mislead when classes are unbalanced: a filter that never flags spam is 95% accurate on a mailbox that is 5% spam, with recall 0.

@example
title: One logistic-regression step
problem: Features are the counts of (fun, boring, movie). The weights are $\mathbf{w} = (0.5, -0.5, 0)$ and $b = 0$. For the document "fun movie", $\mathbf{x} = (1, 0, 1)$ and $y = 1$. Take one gradient step with $\eta = 1$.
step: Score $z = 0.5\cdot 1 + (-0.5)\cdot 0 + 0 = 0.5$, so $\hat p = \sigma(0.5) = 0.6225$, and the loss is $-\log 0.6225 = 0.4741$.
step: The error is $\hat p - y = -0.3775$. The gradient is $-0.3775\,(1, 0, 1)$ for $\mathbf{w}$ and $-0.3775$ for $b$.
step: Update: $\mathbf{w} = (0.8775, -0.5, 0.3775)$ and $b = 0.3775$.
step: Check: now $z = 0.8775 + 0.3775 + 0.3775 = 1.6325$, $\hat p = 0.8365$ and the loss is $0.1785$, lower than before.
answer: $\mathbf{w} = (0.8775, -0.5, 0.3775)$, $b = 0.3775$, loss from $0.4741$ to $0.1785$.

@mistakes
- Multiplying probabilities of many words and getting 0 by underflow; add logarithms instead.
- Forgetting the $|V|$ in the denominator of the smoothed estimate, or using the vocabulary of one class only.
- Treating the naive Bayes scores as probabilities, or its probabilities as well calibrated: the independence assumption makes them overconfident.
- Reporting accuracy alone on unbalanced data.

model:
```python
import math
from collections import Counter


def nb_posteriors(docs, text, k):
    """Posterior class probabilities of a multinomial naive Bayes model."""
    n_docs = Counter(label for _, label in docs)
    counts = {label: Counter() for label in n_docs}
    for doc, label in docs:
        counts[label].update(doc.split())
    vocab = {w for c in counts.values() for w in c}
    scores = {}
    for label in n_docs:
        total = sum(counts[label].values())
        s = math.log(n_docs[label] / len(docs))
        for w in text.split():
            if w in vocab:
                s += math.log((counts[label][w] + k) / (total + k * len(vocab)))
        scores[label] = s
    top = max(scores.values())
    exps = {label: math.exp(s - top) for label, s in scores.items()}
    z = sum(exps.values())
    return {label: e / z for label, e in exps.items()}
```
hint: Compute one log score per label, then turn the scores into probabilities with a softmax after subtracting the maximum.
solution: The scores are log joint probabilities up to a constant, so the posterior is their softmax. Subtracting the largest score keeps the exponentials in a safe range: for the 1,000-word text, the raw scores are around $-1500$ and $-2600$, and a naive exponentiation underflows to 0 for both classes, so the normalization divides 0 by 0.

model:
```python
import math


def fit_logreg(X, y, lr, epochs):
    """Full-batch gradient descent for logistic regression."""
    n, d = len(X), len(X[0])
    w, b = [0.0] * d, 0.0
    for _ in range(epochs):
        gw, gb = [0.0] * d, 0.0
        for x, label in zip(X, y):
            z = sum(wi * xi for wi, xi in zip(w, x)) + b
            err = 1 / (1 + math.exp(-z)) - label
            for i in range(d):
                gw[i] += err * x[i] / n
            gb += err / n
        w = [wi - lr * g for wi, g in zip(w, gw)]
        b -= lr * gb
    return w, b
```
hint: Inside each epoch accumulate the average of $(\hat p - y)\mathbf{x}$ and of $\hat p - y$ over all examples before changing any parameter.
solution: A full-batch step uses the gradient at the same parameters for every example, then moves once. In the last test the two identical inputs have opposite labels, so the gradients cancel and the parameters stay at zero; a version that updates after each example would not stay there.

model:
```python
def precision_recall_f1(y_true, y_pred, positive):
    """Precision, recall and F1 for one class, with 0.0 for empty denominators."""
    tp = sum(1 for t, p in zip(y_true, y_pred) if t == positive and p == positive)
    fp = sum(1 for t, p in zip(y_true, y_pred) if t != positive and p == positive)
    fn = sum(1 for t, p in zip(y_true, y_pred) if t == positive and p != positive)
    precision = tp / (tp + fp) if tp + fp else 0.0
    recall = tp / (tp + fn) if tp + fn else 0.0
    f1 = 2 * precision * recall / (precision + recall) if precision + recall else 0.0
    return precision, recall, f1
```
hint: Count TP, FP and FN with three generator expressions, then guard each division.
solution: The three counts define everything. The all-negative case checks the guards: with no predicted and no true positives, all three values are defined to be 0.0.
