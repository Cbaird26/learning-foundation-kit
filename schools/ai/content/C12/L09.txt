@article
In a model with word embeddings, a common word's parameters receive a gradient at nearly every step, and a rare word's parameters only occasionally. A single learning rate is too large for the first group and too small for the second. **Adaptive methods** give every parameter its own step size, learned from the history of its gradients.

### AdaGrad

**AdaGrad** (Duchi, Hazan and Singer, 2011) accumulates the squared gradient of each coordinate and divides the step by its square root:

$$G_{k,j} = G_{k-1,j} + g_{k,j}^2, \qquad x_{k+1,j} = x_{k,j} - \frac{\eta}{\sqrt{G_{k,j}} + \varepsilon}\,g_{k,j},$$

where $\mathbf{g}_k = \nabla f(\mathbf{x}_k)$ and $\varepsilon$ is a tiny constant (such as $10^{-8}$) that prevents division by zero. Coordinates with large past gradients get small steps; coordinates with small gradients get relatively large steps. Take two coordinates with gradients $\mathbf{g}_1 = (2, 0.1)$ and $\mathbf{g}_2 = (1, 0.1)$ and ignore $\varepsilon$. At step 1 the update is $\eta\,(1, 1)$: every coordinate moves by exactly $\eta$, whatever its scale. At step 2, $G = (5, 0.02)$ and the steps are $\eta\,(1/\sqrt5,\; 0.1/\sqrt{0.02}) = \eta\,(0.447,\; 0.707)$: the coordinate with the large gradient has slowed down more. Since $G$ only grows, the effective step size only shrinks, which suits convex problems but can stall training too early on long runs.

### RMSProp

**RMSProp**, introduced in lecture slides by Tieleman and Hinton (2012), replaces the sum by an exponential moving average, so old gradients are forgotten:

$$v_{k,j} = \rho\,v_{k-1,j} + (1 - \rho)\,g_{k,j}^2, \qquad x_{k+1,j} = x_{k,j} - \frac{\eta}{\sqrt{v_{k,j}} + \varepsilon}\,g_{k,j},$$

with $\rho$ typically $0.9$ to $0.99$. Dividing by the root-mean-square of recent gradients normalizes the step: if a gradient keeps a steady size $g$, then $v \to g^2$ and the step approaches $\eta\,\operatorname{sign}(g)$.

### Adam

**Adam** (Kingma and Ba, 2014) keeps a moving average of the gradient (momentum) and of its square (scaling):

$$\mathbf{m}_k = \beta_1\mathbf{m}_{k-1} + (1 - \beta_1)\mathbf{g}_k, \qquad \mathbf{v}_k = \beta_2\mathbf{v}_{k-1} + (1 - \beta_2)\mathbf{g}_k^2,$$
$$\hat{\mathbf{m}}_k = \frac{\mathbf{m}_k}{1 - \beta_1^k}, \qquad \hat{\mathbf{v}}_k = \frac{\mathbf{v}_k}{1 - \beta_2^k}, \qquad \mathbf{x}_{k+1} = \mathbf{x}_k - \eta\,\frac{\hat{\mathbf{m}}_k}{\sqrt{\hat{\mathbf{v}}_k} + \varepsilon},$$

with squares and square roots taken coordinatewise and the usual defaults $\beta_1 = 0.9$, $\beta_2 = 0.999$, $\varepsilon = 10^{-8}$.

**Why the bias correction?** The averages start at $\mathbf{m}_0 = \mathbf{v}_0 = \mathbf{0}$. If the gradient were a constant $g$, then $m_k = (1 - \beta_1^k)\,g$: far too small for small $k$. Dividing by $1 - \beta_1^k$ removes this bias. At step 1, $\hat m_1 = g_1$ and $\hat v_1 = g_1^2$, so the first update is $\eta\,g_1/(|g_1| + \varepsilon) \approx \eta\,\operatorname{sign}(g_1)$ in every coordinate. With $g_1 = (2, -0.05)$ and then $g_2 = (1, -0.05)$, step 2 uses $\hat m_2 = (1.474, -0.05)$ and $\hat v_2 \approx (2.499, 0.0025)$, so the update factors are $(0.932, -1.000)$ times $\eta$. Two coordinates whose gradients differ by a factor of 20 still move by nearly the same amount.

| method | memory of gradient | per-coordinate scale | notes |
|---|---|---|---|
| AdaGrad | none | sum of squares (never forgets) | step size only decreases |
| RMSProp | none | moving average of squares | forgets old gradients |
| Adam | moving average (momentum) | moving average of squares, bias-corrected | defaults $\beta_1=0.9$, $\beta_2=0.999$ |

### What is and is not guaranteed

Adam's step size is roughly $\eta$ per coordinate, regardless of gradient scale, which makes $\eta$ easier to tune across problems, and it is widely used for training neural networks, for example transformers. But it is not a universal fix. Reddi, Kale and Kumar (2018) gave convex examples on which Adam does not converge and proposed a variant, AMSGrad, with a convergence guarantee. In practice adaptive methods can generalize differently from SGD with momentum, and the best choice depends on the model. A common refinement is AdamW, which applies weight decay separately from the adaptive scaling (Loshchilov and Hutter).

### In code

```python
import math

def adagrad(grad, x0, lr, steps, eps=1e-8):
    x = list(x0)
    acc = [0.0] * len(x)
    for _ in range(steps):
        g = grad(x)
        acc = [a + gi * gi for a, gi in zip(acc, g)]
        x = [xi - lr * gi / (math.sqrt(a) + eps)
             for xi, gi, a in zip(x, g, acc)]
    return x
```

With PyTorch, `torch.optim.Adam(params, lr=1e-3)` runs exactly the formulas above on every parameter tensor.

@example
title: Bias correction at step 2
problem: Adam with $\beta_1 = 0.9$ and $\beta_2 = 0.999$ sees the one-dimensional gradients $g_1 = 6$ and $g_2 = 6$. Find $m_2$, $\hat m_2$ and $\hat v_2$, and the update size in units of $\eta$ (ignore $\varepsilon$).
step: $m_1 = 0.1 \cdot 6 = 0.6$ and $m_2 = 0.9\cdot 0.6 + 0.1 \cdot 6 = 1.14$.
step: $\hat m_2 = m_2/(1 - 0.9^2) = 1.14/0.19 = 6$. The correction restores the true gradient.
step: $v_1 = 0.001\cdot 36 = 0.036$ and $v_2 = 0.999\cdot 0.036 + 0.001\cdot 36 = 0.071964$; $\hat v_2 = 0.071964/(1 - 0.999^2) = 0.071964/0.001999 = 36$.
step: The update is $\eta\,\hat m_2/\sqrt{\hat v_2} = \eta\cdot 6/6 = \eta$. Without the correction it would be $\eta \cdot 1.14/\sqrt{0.071964} \approx 4.25\,\eta$, an inflated step, because $m$ and $v$ are biased by different amounts.
answer: $m_2 = 1.14$, $\hat m_2 = 6$, $\hat v_2 = 36$, and the update has size exactly $\eta$.

@mistakes
- Thinking AdaGrad's step grows with gradient size: it divides by the square root of the accumulated squares, so each coordinate's first step has size $\eta$ whatever the scale.
- Leaving out the bias correction in Adam: early steps are then badly scaled, since $\mathbf{m}$ and $\mathbf{v}$ start at zero and are biased low by different factors.
- Treating $\varepsilon$ as a formality: it sits inside the denominator, so with tiny gradients a large $\varepsilon$ turns Adam into something close to momentum SGD.
- Assuming Adam always converges on convex problems because it is popular: counterexamples exist, and the learning rate still needs tuning.

model:
```python
import math

def rmsprop(grad, x0, lr, steps, rho=0.9, eps=1e-8):
    """RMSProp with a moving average of squared gradients."""
    x = list(x0)
    v = [0.0] * len(x)
    for _ in range(steps):
        g = grad(x)
        v = [rho * vi + (1 - rho) * gi * gi for vi, gi in zip(v, g)]
        x = [xi - lr * gi / (math.sqrt(vi) + eps)
             for xi, gi, vi in zip(x, g, v)]
    return x
```
hint: Update `v` with the current gradient before computing the step; with `rho = 0` the average is just the current squared gradient, so every coordinate moves by `lr` in the direction opposite to its gradient.
solution: The average must include the current gradient, otherwise the first step divides by zero. With a constant gradient $(3, 4)$ and $\rho = 0.9$, the first step is $0.1/\sqrt{0.1}$ in each coordinate and the second is $0.1/\sqrt{0.19}$: the factor $1 - \rho$ makes the early steps larger than $\eta$, because RMSProp has no bias correction. Forgetting the factor $1 - \rho$, or using the old average in the step, fails the first tests.

model:
```python
import math

def adam(grad, x0, lr, steps, beta1=0.9, beta2=0.999, eps=1e-8):
    """Adam with bias-corrected first and second moment estimates."""
    x = list(x0)
    m = [0.0] * len(x)
    v = [0.0] * len(x)
    for t in range(1, steps + 1):
        g = grad(x)
        m = [beta1 * mi + (1 - beta1) * gi for mi, gi in zip(m, g)]
        v = [beta2 * vi + (1 - beta2) * gi * gi for vi, gi in zip(v, g)]
        m_hat = [mi / (1 - beta1 ** t) for mi in m]
        v_hat = [vi / (1 - beta2 ** t) for vi in v]
        x = [xi - lr * mh / (math.sqrt(vh) + eps)
             for xi, mh, vh in zip(x, m_hat, v_hat)]
    return x
```
hint: Count `t` from 1 so that `1 - beta1**t` is never zero, and compute both corrected moments before the update.
solution: With a constant gradient the bias-corrected moments equal $g$ and $g^2$ exactly at every step, so each coordinate moves by $\eta\,\operatorname{sign}(g)$, regardless of its scale: the first two tests fail if the correction is omitted. The quadratic test checks that the method settles at the minimizer, and the step counter must start at 1.
