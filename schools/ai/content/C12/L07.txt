@article
To find the average height of a million people, you do not need to measure everyone before taking your first guess: after each person you can nudge your estimate toward what you just saw. The estimate wobbles, but it gets there at a tiny fraction of the cost. Training on a data set of millions of examples works the same way.

### The finite-sum objective

Training losses are averages over examples:

$$f(\mathbf{w}) = \frac{1}{n}\sum_{i=1}^{n} f_i(\mathbf{w}),$$

where $f_i$ is the loss on example $i$. The full gradient $\nabla f = \frac1n\sum_i\nabla f_i$ costs $n$ gradient evaluations. **Stochastic gradient descent** (SGD; the idea goes back to the stochastic approximation method of Robbins and Monro, 1951) picks a random index $i_k$ and steps along the gradient of that one term:

$$\mathbf{w}_{k+1} = \mathbf{w}_k - \eta_k\,\nabla f_{i_k}(\mathbf{w}_k).$$

With a **mini-batch** $\mathcal{B}_k$ of $B$ indices drawn uniformly, the step uses $\mathbf{g}_k = \frac1B\sum_{i\in\mathcal{B}_k}\nabla f_i(\mathbf{w}_k)$. One pass through the data is an **epoch**; it takes $\lceil n/B\rceil$ updates when the data are split into consecutive batches.

### Why it works: unbiasedness

If the index is uniform on $\{1,\dots,n\}$, then $\mathbb{E}[\nabla f_{i}(\mathbf{w})] = \frac1n\sum_i\nabla f_i(\mathbf{w}) = \nabla f(\mathbf{w})$. The stochastic gradient is an **unbiased estimate** of the full gradient, and so is a mini-batch average. Its **variance** is what hurts. If single-example gradients have covariance with total variance $\sigma^2$ (the expected squared distance from the mean gradient), a mini-batch of $B$ independent draws has variance $\sigma^2/B$. Quadrupling the batch halves the noise standard deviation, at four times the cost per step.

### A worked case: estimating a mean

Let $f_i(w) = \tfrac12(w - a_i)^2$ with data $a = (2, 4, 9, 1)$. Then $f(w) = \tfrac12\cdot\frac14\sum(w - a_i)^2$ is minimized at the mean $\bar a = 4$, and $\nabla f_i(w) = w - a_i$ has variance $\sigma^2 = \frac14\sum(a_i - \bar a)^2 = 9.5$ over the choice of $i$, at every $w$. Starting from $w = 0$ with $\eta = 0.5$ and visiting the examples in order, SGD gives

| step | example $a_i$ | SGD $w$ | full-batch GD $w$ |
|---|---|---|---|
| 1 | 2 | 1.0 | 2.0 |
| 2 | 4 | 2.5 | 3.0 |
| 3 | 9 | 5.75 | 3.5 |
| 4 | 1 | 3.375 | 3.75 |

Full-batch descent moves smoothly toward $4$; SGD jumps with the data, overshooting after the large value $9$.

### Constant step size leaves a noise floor

For this problem with uniformly random examples, the update is $w_{k+1} = (1 - \eta)w_k + \eta a_{i_k}$, so the error $e_k = w_k - \bar a$ satisfies $e_{k+1} = (1-\eta)e_k + \eta(a_{i_k} - \bar a)$. The noise terms are independent with variance $\sigma^2$, so in the long run $\operatorname{Var}(e) = \eta^2\sigma^2 / (1 - (1-\eta)^2) = \eta\sigma^2/(2 - \eta)$. With a mini-batch of size $B$ the noise variance is $\sigma^2/B$, giving $\eta\sigma^2/\big(B(2-\eta)\big)$. **A constant step size converges only to a neighborhood of the minimizer whose size shrinks with $\eta$ and with $B$.** For $\eta = 0.2$ and $B = 1$ the long-run variance is $0.2\cdot 9.5/1.8 \approx 1.06$.

The general picture, for a strongly convex and smooth $f$ with bounded gradient variance and a constant step $\eta$ small enough, is the same: the error decreases linearly at first (as in week 6) and then stalls at a level proportional to $\eta\sigma^2$. Exceptions are **interpolation** problems, where a single $\mathbf{w}$ makes every $\nabla f_i$ vanish, so the noise vanishes at the solution.

### Step-size schedules

To converge exactly we need $\eta_k \to 0$, but not too fast. The **Robbins–Monro conditions** are
$$\sum_{k}\eta_k = \infty \quad\text{and}\quad \sum_{k}\eta_k^2 < \infty .$$
The first lets the iterates travel any distance; the second makes the accumulated noise finite. The schedule $\eta_k = c/k$ satisfies both. For convex problems, SGD with $\eta_k \propto 1/\sqrt{k}$ and an averaged iterate has error $O(1/\sqrt{k})$, and for strongly convex problems a step of order $1/(\mu k)$ gives $O(1/k)$. Compared with full-batch gradient descent's linear rate these look slow, but each step costs $B$ rather than $n$ gradient evaluations. In practice, learning rates are decayed in stages or by a smooth schedule, and the batch size trades hardware efficiency against noise.

### In code

```python
def sgd_epoch(params, data, lr, batch_size):
    a, b = params
    for start in range(0, len(data), batch_size):
        batch = data[start:start + batch_size]
        errs = [a * x + b - y for x, y in batch]
        ga = sum(e * x for e, (x, y) in zip(errs, batch)) / len(batch)
        gb = sum(errs) / len(batch)
        a, b = a - lr * ga, b - lr * gb
    return [a, b]
```

Libraries shuffle the data every epoch and handle batches in tensors; the update rule is the one above.

title: Two SGD steps by hand
problem: Minimize $f(w) = \frac13\sum_{i=1}^{3}\tfrac12(w - a_i)^2$ with $a = (3, 6, 0)$ by SGD from $w_0 = 1$ with $\eta = 0.5$, using the examples in the order $a_1, a_2$. Then compute the full gradient at $w_0$ and compare.
step: The gradient of one term is $w - a_i$. Step 1 uses $a_1 = 3$: $w_1 = 1 - 0.5(1 - 3) = 2$.
step: Step 2 uses $a_2 = 6$: $w_2 = 2 - 0.5(2 - 6) = 4$.
step: The full gradient at $w_0 = 1$ is $w_0 - \bar a = 1 - 3 = -2$, since $\bar a = 3$. A full-batch step with $\eta = 0.5$ would give $w = 1 + 1 = 2$, the same as SGD's first step because $a_1 = \bar a$.
step: The second SGD step used the example $a_2 = 6$, which lies above the mean, so it overshot the minimizer $w^\star = 3$ to $4$; that is the noise of a single example.
answer: $w_1 = 2$ and $w_2 = 4$; the full gradient at $w_0$ is $-2$.

@mistakes
- Treating the stochastic gradient as the true gradient: a single step may point uphill for the full loss, and only the average over many steps follows the true gradient.
- Expecting a constant step size to converge to the exact minimizer: the iterates keep fluctuating at a level set by $\eta$ and $B$ unless the noise vanishes at the solution.
- Using a decay such as $\eta_k = 1/\sqrt{k}$ and claiming the Robbins–Monro conditions hold: $\sum\eta_k^2$ then diverges like the harmonic series.
- Comparing methods by number of updates instead of gradient evaluations: a batch of $B$ examples costs $B$ gradients per update.

model:
```python
def sgd_epoch(params, data, lr, batch_size):
    """One epoch of mini-batch SGD for y = a * x + b with squared loss."""
    a, b = params
    for start in range(0, len(data), batch_size):
        batch = data[start:start + batch_size]
        errs = [a * x + b - y for x, y in batch]
        ga = sum(e * x for e, (x, y) in zip(errs, batch)) / len(batch)
        gb = sum(errs) / len(batch)
        a -= lr * ga
        b -= lr * gb
    return [a, b]
```
hint: Loop over batch start indices with `range(0, len(data), batch_size)`; for each batch compute the errors with the current `a` and `b`, average $e\,x$ and $e$, then update.
solution: The gradient of $\tfrac12(ax + b - y)^2$ is $(e\,x, e)$ with $e = ax + b - y$, and a batch averages it over its own examples, dividing by the actual batch length so that a smaller last batch is still averaged correctly. The third test, with batch size 3, has a last batch of one example. Because the updates are sequential, the second batch sees the parameters after the first update.

@quiz self
prompt: You train a model with SGD and a constant learning rate. The training loss falls quickly, then stays at a noisy plateau well above what you know is achievable. Explain the cause, and give two different changes that would lower the plateau, with the cost of each.
hint: Think about the long-run variance $\eta\sigma^2/(B(2-\eta))$ and what each symbol represents.
solution: With a constant step size, SGD does not converge to the minimizer but to a neighborhood whose size grows with the step size $\eta$ and the gradient noise $\sigma^2/B$: the stochastic gradient does not vanish at the minimizer, so each step keeps kicking the iterates. One remedy is to decay the learning rate (for example a schedule like $1/k$, which meets the Robbins–Monro conditions): this lowers the plateau at the cost of slower progress later and an extra schedule to tune. Another remedy is a larger batch size, which divides the noise variance by $B$ at the cost of $B$ times more gradient evaluations per update. Averaging the iterates is a third option that reduces the fluctuation without changing the step.
rubric: Attributes the plateau to gradient noise with a constant step size, not to a bug or to convexity.
rubric: Names two valid remedies (smaller or decaying step, larger batch, iterate averaging) and links each to the noise formula.
rubric: States a concrete cost for each remedy.
