@article
**Divide and conquer** solves a problem in three steps:

1. **Divide** the input into smaller instances of the same problem.
2. **Conquer** each instance by a recursive call (a very small instance is solved directly).
3. **Combine** the sub-answers into the answer for the whole input.

The running time is a recurrence $T(n) = a\,T(n/b) + f(n)$, where $a$ is the number of subproblems, $n/b$ their size, and $f(n)$ the cost of dividing and combining. Last week's master theorem solves it. Correctness is proved by **strong induction on $n$**: assume the recursive calls are correct on smaller inputs, then show the combine step produces a correct answer.

### Fast exponentiation

Computing $x^n$ by $n - 1$ multiplications is slow. Use $x^n = (x^{n/2})^2$ for even $n$ and $x^n = x \cdot (x^{\lfloor n/2 \rfloor})^2$ for odd $n$:

```python
def power(x, n):
    """Return x**n for an integer n >= 0 using O(log n) multiplications."""
    if n == 0:
        return 1
    half = power(x, n // 2)
    if n % 2 == 0:
        return half * half
    return x * half * half
```

Only **one** recursive call is made (we square its result), so $T(n) = T(n/2) + \Theta(1) = \Theta(\log n)$ multiplications. Calling `power(x, n // 2)` twice instead would give $T(n) = 2T(n/2) + 1 = \Theta(n)$, no better than the naive loop.

### Merge sort and counting inversions

Merge sort divides the list in halves, sorts each, and **merges** two sorted lists in $\Theta(n)$ time by repeatedly taking the smaller front element. Its recurrence is $2T(n/2) + \Theta(n)$, so it takes $\Theta(n \log n)$ time. The merge step can compute more than a sorted list. An **inversion** is a pair of positions $i < j$ with $a[i] > a[j]$; the number of inversions measures how far a list is from sorted. When the merge takes an element from the right half while $k$ elements remain in the left half, that right element is smaller than each of those $k$ elements, creating exactly $k$ inversions across the halves. Adding the counts from the two recursive calls and from merging gives all inversions in $\Theta(n\log n)$, compared with $\Theta(n^2)$ for checking every pair.

### Maximum subarray

To find the largest sum of a contiguous block, note that the best block lies entirely in the left half, entirely in the right half, or crosses the midpoint. The crossing block is the best suffix of the left half plus the best prefix of the right half, found in $\Theta(n)$ time. So $T(n) = 2T(n/2) + \Theta(n) = \Theta(n \log n)$. (A single left-to-right scan solves this problem in $\Theta(n)$, a reminder that divide and conquer is a technique, not always the best one.)

### Multiplying faster

Multiplying two $n$-digit numbers with the school method takes $\Theta(n^2)$ digit operations. Split $x = x_1 B + x_0$ and $y = y_1 B + y_0$ with $B = 10^{n/2}$. Then
$$xy = x_1 y_1 B^2 + (x_1 y_0 + x_0 y_1) B + x_0 y_0,$$
which needs four half-size products. **Karatsuba's trick** uses
$$x_1 y_0 + x_0 y_1 = (x_1 + x_0)(y_1 + y_0) - x_1y_1 - x_0y_0,$$
so only **three** half-size products are needed, plus $\Theta(n)$ additions. Then $T(n) = 3T(n/2) + \Theta(n) = \Theta(n^{\log_2 3}) \approx \Theta(n^{1.585})$. Strassen's matrix multiplication uses the same idea: 7 products of $n/2 \times n/2$ matrices instead of 8, so $T(n) = 7T(n/2) + \Theta(n^2) = \Theta(n^{\log_2 7}) \approx \Theta(n^{2.807})$ against $\Theta(n^3)$.

@example
title: Karatsuba on a small product
problem: Compute $12 \times 34$ with Karatsuba's trick, using $B = 10$.
step: Split $x = 12$ into $x_1 = 1$, $x_0 = 2$ and $y = 34$ into $y_1 = 3$, $y_0 = 4$.
step: Compute the three products: $z_2 = x_1 y_1 = 3$, $z_0 = x_0 y_0 = 8$, and $(x_1 + x_0)(y_1 + y_0) = 3 \cdot 7 = 21$.
step: The middle term is $z_1 = 21 - z_2 - z_0 = 21 - 3 - 8 = 10$.
step: Combine: $xy = z_2 B^2 + z_1 B + z_0 = 300 + 100 + 8 = 408$.
answer: $408$

@example
title: Tracing fast exponentiation
problem: How does `power(3, 13)` compute $3^{13}$, and how many multiplications does it use?
step: `power(3, 13)` is odd: it needs `half = power(3, 6)`, then returns `3 * half * half`.
step: `power(3, 6)` needs `power(3, 3)` and squares it. `power(3, 3)` needs `power(3, 1)` and returns `3 * half * half`. `power(3, 1)` needs `power(3, 0) = 1` and returns `3 * 1 * 1 = 3`.
step: Unwinding: `power(3, 3) = 3 * 3 * 3 = 27`, `power(3, 6) = 27 * 27 = 729`, `power(3, 13) = 3 * 729 * 729 = 1594323`.
step: The depth is $\lfloor \log_2 13 \rfloor + 1 = 4$ levels with at most two multiplications each, far fewer than the 12 multiplications of the naive method.
answer: $3^{13} = 1594323$.

@mistakes
- Making two recursive calls where one suffices (`power(x, n // 2) * power(x, n // 2)`), which silently turns $\Theta(\log n)$ into $\Theta(n)$.
- Forgetting the odd case when halving (`n // 2` loses one factor of `x`).
- Counting split inversions with `<` where the merge uses `<=`: equal elements are not inversions, so ties must be taken from the left half first.
- Copying slices at every level and then quoting $\Theta(\log n)$ for binary search: slicing costs $\Theta(n)$ per call in Python; use index bounds instead.

```python
assert max_subarray([-2, 1, -3, 4, -1, 2, 1, -5, 4]) == 6
assert max_subarray([-3, -1, -2]) == -1

```
model:
```python
def max_subarray(a):
    def solve(lo, hi):
        if hi - lo == 1:
            return a[lo]
        mid = (lo + hi) // 2
        best_left = solve(lo, mid)
        best_right = solve(mid, hi)
        total = 0
        left_suffix = a[mid - 1]
        for i in range(mid - 1, lo - 1, -1):
            total += a[i]
            left_suffix = max(left_suffix, total)
        total = 0
        right_prefix = a[mid]
        for i in range(mid, hi):
            total += a[i]
            right_prefix = max(right_prefix, total)
        return max(best_left, best_right, left_suffix + right_prefix)

    return solve(0, len(a))
```
hint: A best block lies entirely in the left half, entirely in the right half, or crosses the middle.
hint: Alternatively, scan once keeping the best sum of a block that ends at the current position, and restart it at the current element when the running sum becomes smaller than that element.
solution: The divide-and-conquer model recurses on both halves and computes the best block crossing the midpoint as the best suffix of the left half plus the best prefix of the right half; the answer is the maximum of the three. Starting each best value from an actual element (not `0`) makes all-negative lists come out right.

tests:
```python
assert count_inversions([]) == 0
assert count_inversions([1, 2, 3]) == 0
assert count_inversions([3, 2, 1]) == 3
assert count_inversions([2, 4, 1, 3, 5]) == 3
```

model:
```python
def count_inversions(a):
    def sort_count(xs):
        if len(xs) <= 1:
            return list(xs), 0
        mid = len(xs) // 2
        left, x = sort_count(xs[:mid])
        right, y = sort_count(xs[mid:])
        merged = []
        i = j = 0
        cross = 0
        while i < len(left) and j < len(right):
            if left[i] <= right[j]:
                merged.append(left[i])
                i += 1
            else:
                merged.append(right[j])
                j += 1
                cross += len(left) - i
        merged.extend(left[i:])
        merged.extend(right[j:])
        return merged, x + y + cross

    return sort_count(a)[1]
```
hint: Sort recursively and count inversions inside each half; then count the pairs with one element in each half during the merge.
hint: When you take `right[j]` while `i` elements of `left` have been used, the remaining `len(left) - i` elements of `left` are all larger than it. Take from the left on ties.
solution: Return both the sorted half and its inversion count. In the merge, each time an element of the right half is placed before the remaining `len(left) - i` left elements, add that many cross inversions. Taking the left element when `left[i] <= right[j]` ensures equal values are not counted. The recurrence is $2T(n/2) + \Theta(n)$, so $\Theta(n\log n)$.

@practice self
prompt: Design a divide-and-conquer algorithm that finds both the minimum and the maximum of a list of $n$ distinct numbers, where $n$ is a power of 2, using as few comparisons as you can. Write the recurrence for the number of comparisons $T(n)$ and solve it exactly.
solution: Split the list into halves of size $n/2$. Recursively compute (min, max) of each half. The overall minimum is the smaller of the two minima and the overall maximum is the larger of the two maxima: 2 comparisons. For $n = 2$, one comparison decides which is the min and which the max. So $T(2) = 1$ and $T(n) = 2T(n/2) + 2$ for $n > 2$. Unrolling: $T(n) = 2^k T(n/2^k) + 2(2^{k} - 1)$ after $k$ levels; stopping at size 2, $k = \log_2 n - 1$, so $T(n) = \frac n2 \cdot 1 + 2(\frac n2 - 1) = \frac{3n}{2} - 2$. Induction check: $T(2) = 1 = 3 - 2$ and $T(n) = 2(\frac{3n}{4} - 2) + 2 = \frac{3n}{2} - 2$. This beats the $2n - 2$ comparisons of finding the minimum and the maximum separately.
hint: Solve each half recursively and compare the minima with each other and the maxima with each other.
hint: The base case is two elements, resolved by one comparison.

rubric: States the recurrence $T(2) = 1$, $T(n) = 2T(n/2) + 2$.

starter:
```python

    pass
```
tests:
```python
assert first_index([1, 2, 2, 2, 3], 2) == 1
assert first_index([], 5) == -1
assert first_index([4], 4) == 0
assert first_index([1, 3, 5, 7], 4) == -1
assert first_index([1, 3, 5, 7], 7) == 3
assert first_index([2, 2, 2, 2], 2) == 0
assert first_index([1, 2, 3], 0) == -1
```
model:
```python
def first_index(a, x):
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < x:
            lo = mid + 1
        else:
            hi = mid
    if lo < len(a) and a[lo] == x:
        return lo
    return -1
```
hint: Keep the invariant that every index below `lo` holds a value smaller than `x`, and every index at or above `hi` holds a value at least `x`.
hint: When `a[mid] < x` move `lo` to `mid + 1`; otherwise move `hi` to `mid`. When the range is empty, check `a[lo]`.
solution: This is the "lower bound" binary search: the range `[lo, hi)` always contains the first position holding a value at least `x`. It halves each step, so it takes $\Theta(\log n)$ time, and the final check decides whether that position really holds `x`.
