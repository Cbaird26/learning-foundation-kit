@article
Last week's DP had a one-dimensional state. Most interesting problems on sequences need two indices: a **prefix** of each input.

### Longest common subsequence

A **subsequence** keeps some elements in their original order (not necessarily adjacent): `"ace"` is a subsequence of `"abcde"`. For strings $x$ and $y$, let $L[i][j]$ be the length of the longest common subsequence of the first $i$ characters of $x$ and the first $j$ of $y$. Then $L[i][0] = L[0][j] = 0$ and
$$L[i][j] = \begin{cases} L[i-1][j-1] + 1 & \text{if } x_i = y_j, \\ \max(L[i-1][j],\, L[i][j-1]) & \text{otherwise.} \end{cases}$$
If the last characters match, some optimal common subsequence uses them both; if not, at least one of them is unused, so we drop one. There are $(m+1)(n+1)$ subproblems with $O(1)$ work each, so the time is $\Theta(mn)$.

```python
def lcs_length(x, y):
    L = [[0] * (len(y) + 1) for _ in range(len(x) + 1)]
    for i in range(1, len(x) + 1):
        for j in range(1, len(y) + 1):
            if x[i - 1] == y[j - 1]:
                L[i][j] = L[i - 1][j - 1] + 1
            else:
                L[i][j] = max(L[i - 1][j], L[i][j - 1])
    return L[len(x)][len(y)]
```

To recover the subsequence itself, walk back from $L[m][n]$: if the characters match, output the character and move diagonally; otherwise move to the neighbor with the larger value. Keeping the full table costs $\Theta(mn)$ space; keeping only two rows suffices for the length alone.

### Edit distance

The **edit distance** (Levenshtein distance) between $x$ and $y$ is the minimum number of single-character insertions, deletions and substitutions turning $x$ into $y$. Let $D[i][j]$ be the distance between the first $i$ characters of $x$ and the first $j$ of $y$. Then $D[i][0] = i$, $D[0][j] = j$, and
$$D[i][j] = \min\big(D[i-1][j] + 1,\; D[i][j-1] + 1,\; D[i-1][j-1] + [x_i \ne y_j]\big),$$
where the three cases are delete $x_i$, insert $y_j$, and match or substitute. Time and space $\Theta(mn)$.

### Longest increasing subsequence

Let $\ell[i]$ be the length of the longest strictly increasing subsequence **ending at** position $i$. Then $\ell[i] = 1 + \max(\{0\} \cup \{\ell[j] : j < i,\ a_j < a_i\})$ and the answer is $\max_i \ell[i]$. The two nested loops give $\Theta(n^2)$; a cleverer method using binary search runs in $\Theta(n\log n)$. The choice of "ending at $i$" as the state is typical: the right state often records the last element used.

### 0/1 knapsack

Items have weights $w_i$ and values $v_i$ (positive integers); choose a set with total weight at most $W$ that maximizes total value, taking each item at most once. Let $K[i][c]$ be the best value using only the first $i$ items with capacity $c$. Then $K[0][c] = 0$ and
$$K[i][c] = \begin{cases} K[i-1][c] & \text{if } w_i > c, \\ \max\big(K[i-1][c],\; v_i + K[i-1][c - w_i]\big) & \text{otherwise.}\end{cases}$$
The table has $(n+1)(W+1)$ entries, so the time is $\Theta(nW)$. This looks polynomial but is not: the input encodes $W$ in about $\log_2 W$ bits, so $W$ can be exponentially larger than the input length. An algorithm whose time is polynomial in the **numeric value** of the input is called **pseudo-polynomial**. Knapsack is NP-hard (see week 12), so no truly polynomial algorithm is known; the DP is practical when $W$ is moderate.

@example
title: Edit distance by hand
problem: Compute the edit distance from `"sun"` to `"sat"`.
step: Initialize the first row $0, 1, 2, 3$ and the first column $0, 1, 2, 3$.
step: Row for `s`: it matches the first `s` of `sat`, so $D[1][1] = 0$; then $D[1][2] = 1$ and $D[1][3] = 2$. The row is $1, 0, 1, 2$.
step: Row for `u`: $D[2][1] = 1$, $D[2][2] = \min(D[1][2] + 1, D[2][1] + 1, D[1][1] + 1) = 1$ (substitute `u` by `a`), $D[2][3] = 2$. The row is $2, 1, 1, 2$.
step: Row for `n`: $D[3][1] = 2$, $D[3][2] = 2$, and $D[3][3] = \min(D[2][3] + 1, D[3][2] + 1, D[2][2] + 1) = 2$ (substitute `n` by `t`).
answer: 2 (substitute `u` with `a` and `n` with `t`).

@example
title: A knapsack table
problem: Items $(w, v)$: $(2, 3)$, $(3, 4)$, $(4, 5)$, capacity $W = 5$. Find the best value.
step: With no items, every entry is 0. After item 1 $(2,3)$: capacities $0..5$ give $0, 0, 3, 3, 3, 3$.
step: Add item 2 $(3,4)$: at capacity 3, $\max(3, 4 + K[1][0]) = 4$; at capacity 4, $\max(3, 4 + K[1][1]) = 4$; at capacity 5, $\max(3, 4 + K[1][2]) = 7$. The row is $0, 0, 3, 4, 4, 7$.
step: Add item 3 $(4,5)$: capacity 4 gives $\max(4, 5 + K[2][0]) = 5$; capacity 5 gives $\max(7, 5 + K[2][1]) = 7$. The row is $0, 0, 3, 4, 5, 7$.
step: The answer is $K[3][5] = 7$, achieved by items 1 and 2 (weights $2 + 3 = 5$).
answer: 7

@mistakes
- Using `max(L[i-1][j], L[i][j-1])` even when the characters match, or taking `L[i-1][j-1] + 1` when they do not.
- Forgetting the row and column of base cases, so that an empty prefix has no defined value.
- Filling the knapsack table in a loop that reuses the same row in place and lets an item be used twice (that solves the unbounded knapsack instead).
- Calling the $\Theta(nW)$ knapsack algorithm "polynomial time". It is polynomial in $W$ but exponential in the number of bits of $W$.

model:
```python
def edit_distance(s, t):
    prev = list(range(len(t) + 1))
    for i in range(1, len(s) + 1):
        cur = [i]
        for j in range(1, len(t) + 1):
            cost = 0 if s[i - 1] == t[j - 1] else 1
            cur.append(min(prev[j] + 1, cur[j - 1] + 1, prev[j - 1] + cost))
        prev = cur
    return prev[len(t)]
```

model:
```python
def knapsack(weights, values, capacity):
    best = [0] * (capacity + 1)
    for w, v in zip(weights, values):
        for c in range(capacity, w - 1, -1):
            best[c] = max(best[c], v + best[c - w])
    return best[capacity]
```
hint: Let `K[i][c]` be the best value using the first `i` items with capacity `c`. Item `i` is either skipped or taken.
hint: With a single row, loop the capacity downward so that each item is used at most once.
solution: The model keeps one row and updates capacities from high to low, so `best[c - w]` still refers to the row before the current item; that enforces the 0/1 restriction. The time is $\Theta(nW)$ and the space $\Theta(W)$. Greedy by value-per-weight would answer 160 on the 220 test, which is why DP is needed.

@practice self
prompt: Design a dynamic program for the **longest strictly increasing subsequence** of a list $a_1, \dots, a_n$ of numbers. Define the subproblems, give the recurrence and base cases, state the evaluation order and running time, and explain how to recover the subsequence itself.
solution: State: $\ell[i]$ is the length of the longest strictly increasing subsequence that ends exactly at position $i$ (it uses $a_i$ as its last element). Recurrence: $\ell[i] = 1 + \max(\{0\} \cup \{\ell[j] : j < i \text{ and } a_j < a_i\})$. The base case is included: if no earlier element is smaller, $\ell[i] = 1$. Order: compute $\ell[1], \ell[2], \dots, \ell[n]$ left to right, since $\ell[i]$ depends only on smaller indices. The answer is $\max_i \ell[i]$ (0 for an empty list), because the best subsequence ends somewhere. Time: $n$ subproblems, each scanning up to $n$ earlier positions, so $\Theta(n^2)$; space $\Theta(n)$. To recover a subsequence, store for each $i$ the index $p[i]$ of the $j$ that achieved the maximum (or none), pick the $i$ with the largest $\ell[i]$, and follow $p$ backward, reversing the list at the end. Correctness: an increasing subsequence ending at $i$ either is the single element $a_i$ or ends with some $a_j < a_i$ preceded by an increasing subsequence ending at $j$; optimality of the prefix is by the usual cut-and-paste argument.
rubric: Defines the state as the longest increasing subsequence ending at index $i$, and gives the recurrence with the case of no smaller predecessor.
rubric: States the evaluation order, the answer as a maximum over all $i$, and the $\Theta(n^2)$ time.
rubric: Explains reconstruction with predecessor pointers.

model:
```python
def lis_length(a):
    best = []
    for i in range(len(a)):
        best.append(1)
        for j in range(i):
            if a[j] < a[i] and best[j] + 1 > best[i]:
                best[i] = best[j] + 1
    return max(best, default=0)
```
hint: Let `best[i]` be the length of the longest increasing subsequence ending at index `i`.
hint: For each `i`, look at every earlier `j` with `a[j] < a[i]` (strictly) and extend its subsequence by one. The answer is the maximum of `best`.
solution: `best[i]` starts at 1 and is raised by every earlier smaller element, giving $\Theta(n^2)$ time. The comparison must be strict (`<`) so that equal values cannot extend each other. `max(..., default=0)` handles the empty list.
