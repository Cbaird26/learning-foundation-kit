@article
Some recursions are exponentially slow only because they solve the same subproblem again and again. **Dynamic programming** (DP) fixes that by solving each distinct subproblem once and remembering its answer.

### The Fibonacci warm-up

The recursion $F(n) = F(n-1) + F(n-2)$ with $F(0) = 0$, $F(1) = 1$ calls itself twice per call. The number of calls $C(n) = 1 + C(n-1) + C(n-2)$ grows like the Fibonacci numbers themselves, which is $\Theta(\varphi^n)$ with $\varphi \approx 1.618$. But only $n+1$ distinct subproblems exist: $F(0), \dots, F(n)$. The calls are **overlapping subproblems**.

**Memoization** (top-down) keeps the recursion but stores each result in a dictionary:

```python
def fib_memo(n, memo=None):
    if memo is None:
        memo = {}
    if n < 2:
        return n
    if n not in memo:
        memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]
```

**Tabulation** (bottom-up) fills a table in an order in which each entry's dependencies are already filled:

```python
def fib_table(n):
    if n < 2:
        return n
    prev, cur = 0, 1
    for _ in range(n - 1):
        prev, cur = cur, prev + cur
    return cur
```

Both take $\Theta(n)$ arithmetic operations. The second keeps only the last two entries, so it uses $O(1)$ space; this **space optimization** is possible whenever later entries depend on only a few earlier ones. (The Python decorators `functools.cache` and `functools.lru_cache` memoize a function automatically, but you should know what they do.)

### Designing a DP

Follow the same recipe every time.

1. **Subproblems.** Define the state: what parameters identify a subproblem? Write it as a sentence: "$\text{dp}[i]$ is the minimum number of coins that sum to $i$."
2. **Recurrence.** Express a subproblem through smaller ones, by considering the choices for the "last step" or "first step".
3. **Base cases.** The smallest subproblems, solved directly.
4. **Order.** For tabulation, an order consistent with the dependencies (here: increasing $i$).
5. **Answer and time.** Which entry is the answer? **Time = (number of subproblems) × (work per subproblem).**

DP needs **optimal substructure**: an optimal solution contains optimal solutions to its subproblems. Memoization computes only the subproblems that are actually reached (good when many are not), and tabulation avoids deep recursion and function-call overhead; both have the same asymptotic time when all subproblems are needed.

### Example: minimum coins

For coins $c_1, \dots, c_k$, let $\text{dp}[a]$ be the fewest coins summing to amount $a$ ($\infty$ if impossible). Then $\text{dp}[0] = 0$ and
$$\text{dp}[a] = 1 + \min_{c_j \le a} \text{dp}[a - c_j].$$
There are $A + 1$ subproblems with $k$ choices each, so the time is $\Theta(kA)$ and the space $\Theta(A)$. Unlike greedy, this is correct for **every** coin set, because it tries every choice for the last coin instead of committing to the largest.

### Example: counting paths

The number of ways to go from the top-left to the bottom-right corner of a grid moving only right or down satisfies $\text{ways}[r][c] = \text{ways}[r-1][c] + \text{ways}[r][c-1]$ (the last move came from above or from the left), with $\text{ways}[0][0] = 1$. Blocked cells simply get 0. This takes $\Theta(mn)$ time for an $m \times n$ grid.

@example
title: Filling a coin-change table
problem: Use $\text{dp}[a] = 1 + \min_{c \le a} \text{dp}[a - c]$ with coins $\{1, 4, 5\}$ to find the fewest coins for amount 8.
step: Base case: $\text{dp}[0] = 0$. For $a = 1, 2, 3$ only coin 1 fits, so $\text{dp}[1] = 1$, $\text{dp}[2] = 2$, $\text{dp}[3] = 3$.
step: $\text{dp}[4] = 1 + \min(\text{dp}[3], \text{dp}[0]) = 1$, and $\text{dp}[5] = 1 + \min(\text{dp}[4], \text{dp}[1], \text{dp}[0]) = 1$.
step: $\text{dp}[6] = 1 + \min(\text{dp}[5], \text{dp}[2], \text{dp}[1]) = 2$ and $\text{dp}[7] = 1 + \min(\text{dp}[6], \text{dp}[3], \text{dp}[2]) = 3$.
step: $\text{dp}[8] = 1 + \min(\text{dp}[7], \text{dp}[4], \text{dp}[3]) = 1 + \min(3, 1, 3) = 2$, using $4 + 4$.
step: Greedy would take $5 + 1 + 1 + 1$, four coins, so the DP finds a better answer.
answer: 2 coins ($4 + 4$).

@example
title: A grid-path table
problem: Count right/down paths in a $3 \times 3$ grid from the top-left cell to the bottom-right cell, with no blocked cells.
step: The first row and first column each have exactly one path to every cell (only one direction is possible): the first row is $1, 1, 1$ and the first column is $1, 1, 1$.
step: Cell $(1,1)$ gets $1 + 1 = 2$. Cell $(1,2)$ gets $1$ (from above) $+ 2$ (from the left) $= 3$. Cell $(2,1)$ gets $2$ (from above) $+ 1$ (from the left) $= 3$.
step: Cell $(2,2)$ gets $\text{ways}[1][2] + \text{ways}[2][1] = 3 + 3 = 6$.
step: This agrees with the formula $\binom{4}{2} = 6$ (choose which 2 of the 4 moves go down).
answer: 6

@mistakes
- Adding memoization without checking that the state captures everything the answer depends on; a missing parameter gives wrong cached values.
- Initializing "impossible" as `0` instead of infinity (or a sentinel), so impossible subproblems look like free ones in a minimum.
- Filling a table in an order where an entry is read before it has been computed.
- Using a mutable default argument (`memo={}`) shared between calls, or recursing to depth $n$ for large $n$ and hitting Python's recursion limit.

model:
```python
def min_coins(coins, amount):
    inf = float("inf")
    dp = [0] + [inf] * amount
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a and dp[a - c] + 1 < dp[a]:
                dp[a] = dp[a - c] + 1
    return dp[amount] if dp[amount] != inf else -1
```
hint: Let `dp[a]` be the fewest coins for amount `a`, with `dp[0] = 0`.
hint: For each `a`, try every coin `c <= a` as the last coin: `dp[a] = 1 + min(dp[a - c])`. Use infinity for unreachable amounts, and convert it to `-1` at the end.
solution: Fill `dp[0..amount]` in increasing order; each entry is one more than the best entry reachable by removing one coin. Time $\Theta(k \cdot \text{amount})$ for $k$ coins. Starting entries at infinity means unreachable amounts never win a minimum.

model:
```python
def grid_paths(m, n, blocked):
    ways = [[0] * n for _ in range(m)]
    for r in range(m):
        for c in range(n):
            if (r, c) in blocked:
                continue
            if r == 0 and c == 0:
                ways[r][c] = 1
            else:
                above = ways[r - 1][c] if r > 0 else 0
                left = ways[r][c - 1] if c > 0 else 0
                ways[r][c] = above + left
    return ways[m - 1][n - 1]
```
hint: `ways[r][c]` counts paths to cell `(r, c)`; the last step came from above or from the left.
hint: A blocked cell has `0` paths. Guard the indices so that row `0` and column `0` do not read index `-1`.
solution: Fill the table row by row: `ways[0][0] = 1`, blocked cells stay `0`, and every other cell is the sum of the cell above and the cell to its left (treating cells outside the grid as `0`). The answer is the bottom-right entry. Time $\Theta(mn)$.

@practice self
prompt: Consider the coin set $\{1, 3, 4\}$ and the amount 6. (a) Show that the greedy "largest coin first" rule is not optimal. (b) Write the DP recurrence for the fewest coins, fill the table for amounts $0$ through $6$, and explain why DP succeeds where greedy fails.
solution: (a) Greedy takes 4, then cannot take 4 or 3 again (remaining 2), and takes 1 and 1: three coins. The coins $3 + 3$ make 6 with only two coins, so greedy is not optimal. (b) Let $\text{dp}[a]$ be the fewest coins for amount $a$. Then $\text{dp}[0] = 0$ and $\text{dp}[a] = 1 + \min\{\text{dp}[a - c] : c \in \{1,3,4\}, c \le a\}$. Table: $\text{dp}[0] = 0$; $\text{dp}[1] = 1$; $\text{dp}[2] = 1 + \text{dp}[1] = 2$; $\text{dp}[3] = 1 + \min(\text{dp}[2], \text{dp}[0]) = 1$; $\text{dp}[4] = 1 + \min(\text{dp}[3], \text{dp}[1], \text{dp}[0]) = 1$; $\text{dp}[5] = 1 + \min(\text{dp}[4], \text{dp}[2], \text{dp}[1]) = 2$; $\text{dp}[6] = 1 + \min(\text{dp}[5], \text{dp}[3], \text{dp}[2]) = 1 + \min(2, 1, 2) = 2$. DP succeeds because it considers every possible last coin and uses optimal answers to all smaller amounts, so it never commits to a locally attractive coin (4) that leads to a worse remainder. Greedy commits to one choice per step and has no way to undo it; it is correct only when the problem has the greedy-choice property, which this coin set lacks.

assert count_ways([1, 2, 5], 5) == 4

model:
```python
def count_ways(coins, amount):
    ways = [1] + [0] * amount
    for c in coins:
        for a in range(c, amount + 1):
            ways[a] += ways[a - c]
    return ways[amount]
```
hint: To count combinations instead of sequences, process one coin value at a time in the outer loop.
hint: With `ways[0] = 1`, for each coin `c` and each `a` from `c` up to `amount`, add `ways[a - c]` to `ways[a]`.
solution: Looping over coins on the outside and amounts on the inside counts each multiset of coins once, in the order of the coin list. If amounts were on the outside, each ordering such as `1+2` and `2+1` would be counted separately. Time $\Theta(k \cdot \text{amount})$.
