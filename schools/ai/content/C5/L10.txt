@article
Given a connected, undirected graph with edge weights, a **spanning tree** is a set of $V - 1$ edges that connects all vertices without a cycle. A **minimum spanning tree** (MST) is a spanning tree of minimum total weight. MSTs model the cheapest way to wire a network, and they are the standard first example of a problem where greedy algorithms are provably optimal. If all weights are distinct, the MST is unique.

### Why greedy works: the cut and cycle properties

A **cut** is a partition of the vertices into two non-empty sets $S$ and $V \setminus S$; an edge **crosses** the cut if its endpoints lie on different sides.

**Cut property.** For any cut, the lightest edge crossing it belongs to some MST (to every MST if it is the unique lightest crossing edge).

*Proof (exchange).* Let $e$ be a lightest crossing edge and $T$ an MST not containing $e$. Adding $e$ to $T$ creates exactly one cycle. That cycle crosses the cut an even number of times, so it contains another edge $f \ne e$ crossing the cut. Then $T' = T - f + e$ is a spanning tree, and $w(e) \le w(f)$, so $w(T') \le w(T)$. Hence $T'$ is also an MST, and it contains $e$. $\square$

**Cycle property.** If an edge is the unique heaviest edge on some cycle, it belongs to no MST. (Removing it from a tree that used it leaves two components, and another edge of the cycle reconnects them more cheaply.)

### Kruskal's algorithm

```text
sort the edges by weight
T = empty set
for each edge (u, v) in sorted order:
    if u and v are in different components of T:
        add (u, v) to T
```

Each added edge is the lightest edge crossing the cut between its component and the rest, so it is safe by the cut property. Sorting takes $O(E \log E) = O(E \log V)$ (because $E \le V^2$), and the component checks use a union–find structure, so the total time is $O(E \log V)$.

### Union–find (disjoint sets)

The structure maintains a partition of $\{0, \dots, n-1\}$ with two operations: `find(x)` returns the representative of $x$'s set, and `union(x, y)` merges two sets. Store each set as a tree via a `parent` array:

```python
def find(parent, x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]  # path halving
        x = parent[x]
    return x
```

Two optimizations make it nearly constant time. **Union by size** attaches the root of the smaller tree under the root of the larger, keeping trees shallow (height $O(\log n)$). **Path compression** (or halving, above) flattens the tree during `find`. Together, a sequence of $m$ operations on $n$ elements takes $O(m\,\alpha(n))$ time, where $\alpha$ is the inverse Ackermann function, which is at most 4 for any $n$ that fits in the universe. Either optimization alone gives $O(\log n)$ amortized per operation.

### Prim's algorithm

Grow a single tree from any start vertex. Keep a min-heap of edges leaving the tree; repeatedly pop the lightest edge whose far endpoint is outside the tree, add that vertex, and push its edges. Every chosen edge is the lightest crossing the cut (tree, rest), so it is safe. With a binary heap the time is $O(E \log V)$, the same as Kruskal's. Prim's algorithm resembles Dijkstra's: Dijkstra orders vertices by the distance from the source, Prim by the weight of the single edge linking them to the tree.

@example
title: Kruskal on a small graph
problem: Vertices $A..E$ with edges $AB\ 4$, $AC\ 1$, $BC\ 2$, $BD\ 5$, $CD\ 8$, $CE\ 10$, $DE\ 3$. Find an MST.
step: Sort: $AC\ 1$, $BC\ 2$, $DE\ 3$, $AB\ 4$, $BD\ 5$, $CD\ 8$, $CE\ 10$.
step: Take $AC$ (joins $A$, $C$), $BC$ (joins $B$ to $\{A, C\}$), $DE$ (joins $D$, $E$).
step: $AB$ would join two vertices already in the same component, so skip it. Take $BD\ 5$, which connects $\{A,B,C\}$ with $\{D,E\}$.
step: Four edges for five vertices: the tree is complete, and the total weight is $1 + 2 + 3 + 5 = 11$.
answer: Edges $AC, BC, DE, BD$ with total weight 11.

@example
title: Using the cut property
problem: A graph on $A..E$ has edges $AB\ 4$, $AC\ 1$, $BC\ 2$, $BD\ 5$, $CD\ 8$, $CE\ 10$, $DE\ 3$. Why must $AC$ (weight 1) be in the MST?
step: Take the cut $S = \{A\}$ versus the other vertices. Only $AB\ (4)$ and $AC\ (1)$ cross it.
step: $AC$ is the unique lightest crossing edge, so it belongs to every MST.
step: More generally, the lightest edge incident to any vertex is in some MST.
answer: $AC$ is the unique lightest edge crossing the cut $\{A\}$ versus the rest.

@mistakes
- Believing that the MST contains the shortest path between every pair of vertices. An MST minimizes total weight, not distances.
- Applying the cut property to a heaviest edge, or forgetting that ties can give several different MSTs.
- Not checking connectivity: Kruskal on a disconnected graph produces a spanning forest with fewer than $V - 1$ edges.
- Implementing `union` without first finding the two roots, which links non-root nodes and breaks the tree structure.

model:
```python
class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.components = n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, x, y):
        rx, ry = self.find(x), self.find(y)
        if rx == ry:
            return False
        if self.size[rx] < self.size[ry]:
            rx, ry = ry, rx
        self.parent[ry] = rx
        self.size[rx] += self.size[ry]
        self.components -= 1
        return True
```
hint: Keep a `parent` list (each element starts as its own parent) and a `size` list for the roots.
hint: In `union`, find both roots first; if they differ, hang the smaller tree under the larger and add the sizes.
solution: `find` follows parent pointers to the root, halving the path as it goes. `union` compares the two roots, attaches the smaller tree under the larger (union by size), and updates the component count. With both optimizations the amortized cost per operation is $O(\alpha(n))$.

```python
def kruskal(n, edges):
    parent = list(range(n))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    total = 0
    used = 0
    for u, v, w in sorted(edges, key=lambda e: e[2]):
        ru, rv = find(u), find(v)
        if ru != rv:
            parent[ru] = rv
            total += w
            used += 1
    return total if used == n - 1 else None
```
hint: Sort the edges by weight, then take an edge only if its endpoints are in different sets.
hint: A spanning tree has exactly `n - 1` edges; if you finish with fewer, the graph is disconnected.
solution: Process edges in increasing weight order, adding an edge when `find` shows that its endpoints are in different components, and merge them. If fewer than `n - 1` edges are added, return `None`. Time $O(m \log m)$ for sorting plus near-linear union–find work.

model:
```python
import heapq


def dijkstra_with_parents(graph, s):
    dist = {s: 0}
    parent = {s: None}
    heap = [(0, s)]
    done = set()
    while heap:
        d, u = heapq.heappop(heap)
        if u in done:
            continue
        done.add(u)
        for v, w in graph[u]:
            if v not in dist or d + w < dist[v]:
                dist[v] = d + w
                parent[v] = u
                heapq.heappush(heap, (d + w, v))
    return dist, parent
```
hint: Whenever you improve `dist[v]` through `u`, also record `parent[v] = u`.
hint: Skip heap entries for vertices that were already finalized (lazy deletion) and keep pushing `(distance, vertex)` pairs onto the heap.
solution: This is the standard heap-based Dijkstra with one extra dictionary. Each improvement pushes a new heap entry; stale entries are skipped when popped. The parent pointers form a shortest-path tree rooted at `s`. Time $O((V + E)\log V)$.

@practice self
prompt: Prove the cut property: if $e$ is a minimum-weight edge crossing a cut $(S, V \setminus S)$ of a connected weighted graph, then some minimum spanning tree contains $e$. Then explain in one or two sentences how this shows that Kruskal's algorithm only ever adds safe edges.
solution: Let $T$ be an MST. If $e \in T$ we are done. Otherwise $T + e$ contains exactly one cycle $C$, because $T$ is a tree that already connects the endpoints of $e$. The cycle $C$ passes through $e$, which crosses the cut, so $C$ must cross the cut again (a cycle crosses any cut an even number of times) using another edge $f \ne e$ that is in $T$. Define $T' = T + e - f$. Removing $f$ breaks the unique cycle, so $T'$ is connected and has $V - 1$ edges, so it is a spanning tree. Since $e$ is a lightest crossing edge and $f$ crosses the cut, $w(e) \le w(f)$, so $w(T') = w(T) + w(e) - w(f) \le w(T)$. As $T$ is minimum, $T'$ is an MST, and it contains $e$. For Kruskal: when it adds the edge $(u, v)$, the endpoints are in different components of the current forest $F$. Take the cut that separates $u$'s component from all other vertices. No edge of $F$ crosses it, and any edge lighter than $(u,v)$ that crosses it was considered earlier, and at that time its endpoints were in different components (components only grow), so it would have been added to $F$; but no edge of $F$ crosses the cut. Hence $(u,v)$ is a lightest crossing edge. Finally, safety needs the exchange argument in a slightly stronger form: suppose the current forest $F$ is contained in some MST $T$ and the new edge $e \notin T$. The edge $f$ that the argument removes from $T + e$ crosses the cut, so $f \notin F$ (no edge of $F$ crosses it), and $T' = T + e - f$ is an MST containing $F + e$. By induction on the number of edges added, $F$ is always contained in some MST, so every added edge is safe and the final spanning tree is an MST.
rubric: Adds $e$ to an MST $T$ and identifies the cycle that results.
rubric: Finds another edge $f$ on that cycle crossing the cut and shows that $T + e - f$ is a spanning tree of no greater weight.
rubric: Connects the property to Kruskal by exhibiting the cut that separates the new edge's component, with the new edge as lightest crossing edge.
hint: Add $e$ to a tree that does not contain it and look at the cycle that appears.
hint: A cycle that crosses a cut once must cross it again.

model:
```python
import heapq


def prim(graph):
    start = next(iter(graph))
    in_tree = {start}
    heap = [(w, v) for v, w in graph[start]]
    heapq.heapify(heap)
    total = 0
    while heap and len(in_tree) < len(graph):
        w, v = heapq.heappop(heap)
        if v in in_tree:
            continue
        in_tree.add(v)
        total += w
        for x, wx in graph[v]:
            if x not in in_tree:
                heapq.heappush(heap, (wx, x))
    return total
```
hint: Start from any vertex and keep a heap of `(weight, vertex)` pairs for edges that leave the tree.
hint: Pop the lightest entry; if its vertex is already in the tree, skip it, otherwise add it and push its edges to vertices outside the tree.
solution: Prim grows one tree. Each popped entry that reaches a new vertex is the lightest edge crossing the cut between the tree and the rest, so it is safe by the cut property. Entries for vertices already in the tree are stale and skipped. Time $O(E \log V)$.
