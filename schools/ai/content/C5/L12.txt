@article
So far every problem had an efficient algorithm. Some natural problems seem to have none, and complexity theory explains why we expect that.

### Decision problems and the class P

A **decision problem** asks a yes/no question about an input, such as "does this graph have a path from $s$ to $t$ of weight at most $k$?". Optimization problems convert to decision problems by adding a threshold ("is there a vertex cover of size at most $k$?"), and the two are about equally hard. **P** is the class of decision problems solvable by an algorithm whose running time is polynomial in the **input length** (the number of bits). Shortest paths, minimum spanning trees, maximum flow and bipartite matching are all in P. Note that the knapsack DP with time $\Theta(nW)$ is only pseudo-polynomial, since $W$ can be exponential in its bit length.

### The class NP

**NP** is the class of decision problems whose "yes" answers can be **verified** in polynomial time given a short **certificate** (a proof). It does not stand for "not polynomial"; it stands for nondeterministic polynomial time.

- **Vertex Cover:** is there a set of at most $k$ vertices touching every edge? Certificate: the set; the verifier checks its size and every edge.
- **SAT:** is a Boolean formula satisfiable? Certificate: a satisfying assignment, checked by evaluating the formula.
- **Hamiltonian cycle:** certificate: the cycle itself.

Every problem in P is in NP (the verifier can ignore the certificate and solve the problem), so $\text{P} \subseteq \text{NP}$. Whether $\text{P} = \text{NP}$ is the most famous open problem of the field. As of 2026 it is unresolved; most researchers believe $\text{P} \ne \text{NP}$, meaning that finding a solution can be much harder than checking one, but there is no proof.

### Reductions

A problem $A$ **reduces** to $B$ in polynomial time, written $A \le_p B$, if there is a polynomial-time function $f$ mapping instances of $A$ to instances of $B$ such that $x$ is a "yes" instance of $A$ **if and only if** $f(x)$ is a "yes" instance of $B$. Then a polynomial algorithm for $B$ gives one for $A$: compute $f(x)$ and ask $B$. So $B$ is **at least as hard** as $A$. Always check **both directions** of the "if and only if", and the direction of the reduction: to show that a new problem is hard, reduce a **known hard** problem **to** it.

A problem is **NP-hard** if every problem in NP reduces to it, and **NP-complete** if it is both NP-hard and in NP. The **Cook–Levin theorem** shows that SAT is NP-complete. From there, one reduction per problem builds a large family of NP-complete problems: 3-SAT, Independent Set, Vertex Cover, Clique, Hamiltonian Cycle, Subset Sum, graph 3-coloring, and the decision version of 0/1 knapsack. They are all equally hard: if any one has a polynomial algorithm, then $\text{P} = \text{NP}$; if any one provably has none, then none do.

### Two graph reductions

An **independent set** is a set of vertices with no edge between any two of them; a **vertex cover** touches every edge; a **clique** is a set of vertices pairwise joined by edges. In a graph with $n$ vertices:

- $S$ is an independent set **iff** $V \setminus S$ is a vertex cover. (Every edge has at most one endpoint in $S$ iff every edge has at least one endpoint outside $S$.) So (Independent Set, $k$) reduces to (Vertex Cover, $n - k$) on the same graph, and vice versa.
- $S$ is a clique in $G$ iff $S$ is an independent set in the **complement graph** (the graph with an edge exactly where $G$ has none).

The reduction from 3-SAT to Independent Set builds a triangle for each clause (one vertex per literal) and joins every literal vertex to the vertices of its negation. A formula with $m$ clauses is satisfiable iff the graph has an independent set of size $m$: at most one vertex per triangle can be chosen, and the chosen literals cannot contradict each other.

### What to do about NP-hard problems

NP-completeness is not a verdict of "give up". Practical options: exploit special structure (2-SAT is in P, vertex cover is easy on bipartite graphs and on trees); **approximation algorithms** with provable guarantees (taking both endpoints of the edges of a maximal matching gives a vertex cover at most twice the optimum); algorithms that are exponential only in a small parameter; heuristics and local search; and modern SAT solvers, which handle formulas with millions of variables from practical problems despite the worst-case hardness. Recognizing a problem as NP-hard stops you from searching for an exact polynomial algorithm.

@example
title: Verifying a certificate
problem: A graph has edges $\{1,2\}$, $\{2,3\}$, $\{3,4\}$, $\{4,1\}$, $\{2,4\}$. Is $\{2, 4\}$ a vertex cover of size at most 2?
step: The verifier checks the size: $|\{2,4\}| = 2 \le 2$.
step: It checks every edge for an endpoint in the set: $\{1,2\}$ contains 2, $\{2,3\}$ contains 2, $\{3,4\}$ contains 4, $\{4,1\}$ contains 4, $\{2,4\}$ contains both.
step: All edges are covered, so the certificate is accepted. The check took time linear in the size of the graph.
answer: Yes, $\{2, 4\}$ is a vertex cover of size 2.

@example
title: Independent Set reduces to Vertex Cover
problem: Show that Independent Set $\le_p$ Vertex Cover, illustrating it on the graph with vertices $1..4$ and edges $\{1,2\}$, $\{2,3\}$, $\{3,4\}$, $\{4,1\}$, $\{2,4\}$.
step: Reduction: map $(G, k)$ to $(G, n - k)$, with the same graph. Here $n = 4$.
step: Take $k = 2$: the set $\{1, 3\}$ is independent (no edge joins 1 and 3). Its complement $\{2, 4\}$ is a vertex cover of size $4 - 2 = 2$.
step: In general, if $S$ is independent, then each edge has at most one endpoint in $S$, so at least one in $V \setminus S$, which is therefore a cover of size $n - |S|$. Conversely, if $C$ is a cover, no edge lies inside $V \setminus C$, so $V \setminus C$ is independent.
step: The map is computable in polynomial time and preserves yes/no answers in both directions.
answer: $(G, k)$ has an independent set of size $k$ if and only if $(G, n-k)$ has a vertex cover of size $n - k$.

@mistakes
- Reducing in the wrong direction: to prove $B$ is hard you reduce a known NP-hard problem **to** $B$, not $B$ to it.
- Proving only one direction of the equivalence (a solution maps to a solution, but not back).
- Reading "NP" as "not polynomial", or concluding that NP-complete problems are known to need exponential time. That is exactly the open question.
- Treating the $\Theta(nW)$ knapsack algorithm as a polynomial algorithm and therefore a proof that $\text{P} = \text{NP}$.

model:
```python
def verify_3sat(clauses, assignment):
    for clause in clauses:
        satisfied = False
        for lit in clause:
            value = assignment[abs(lit)]
            if (lit > 0 and value) or (lit < 0 and not value):
                satisfied = True
                break
        if not satisfied:
            return False
    return True
```
hint: A literal `k > 0` is true when `assignment[k]` is `True`, and a literal `-k` is true when `assignment[k]` is `False`.
hint: Return `False` as soon as you find a clause in which no literal is true; if all clauses pass, return `True`.
solution: Check each clause for at least one true literal, using `abs(lit)` to find the variable. The time is linear in the formula length, which is what makes a satisfying assignment a valid short certificate.

```python
from itertools import combinations


def min_vertex_cover_size(n, edges):
    for k in range(n + 1):
        for chosen in combinations(range(n), k):
            cover = set(chosen)
            if all(u in cover or v in cover for u, v in edges):
                return k
    return n
```
hint: Try the sizes `k = 0, 1, 2, ...` in turn, and for each `k` try every set of `k` vertices.
hint: A set is a cover if every edge `(u, v)` has `u` or `v` in it. The first `k` for which some set works is the answer.
solution: Enumerate subsets by increasing size with `itertools.combinations`; the first size that has a covering subset is the minimum. There are $2^n$ subsets in total, which is why this does not scale and why NP-hardness matters.

@practice self
prompt: Prove that Independent Set $\le_p$ Vertex Cover: give the reduction, show that it runs in polynomial time, and prove both directions of correctness. Then explain in two or three sentences why such a reduction matters for a programmer who has a new problem to solve.
solution: Decision problems: INDEPENDENT-SET asks, for a graph $G$ with $n$ vertices and an integer $k$, whether $G$ has an independent set of size at least $k$; VERTEX-COVER asks whether $G$ has a vertex cover of size at most $k'$. Reduction: $f(G, k) = (G, n - k)$. It copies the graph and does one subtraction, so it runs in polynomial (linear) time. Correctness ($\Rightarrow$): suppose $S$ is an independent set with $|S| \ge k$. Every edge has at most one endpoint in $S$, so at least one endpoint in $C = V \setminus S$; hence $C$ is a vertex cover with $|C| = n - |S| \le n - k$. Correctness ($\Leftarrow$): suppose $C$ is a vertex cover with $|C| \le n - k$. Then no edge has both endpoints in $S = V \setminus C$, because that edge would not be touched by $C$; hence $S$ is independent and $|S| = n - |C| \ge k$. So $(G,k)$ is a yes-instance iff $(G, n-k)$ is. Why it matters: a polynomial algorithm for Vertex Cover would immediately give one for Independent Set, so Vertex Cover is at least as hard as Independent Set. Since Independent Set is known to be NP-hard (via 3-SAT), this transfers hardness to Vertex Cover; for a programmer it means that when a new problem can be shown to encode a known NP-hard problem, one should stop looking for an exact fast algorithm and turn to approximation, heuristics, special cases or small-parameter methods.
rubric: States the reduction $(G, k) \mapsto (G, n - k)$ and notes that it is computable in polynomial time.
rubric: Proves both directions: independent set gives cover and cover gives independent set, with the size arithmetic.
rubric: Explains that hardness is transferred along the reduction (to prove a problem hard, reduce a known hard problem to it), and what a practitioner does next.
hint: Use the fact that $S$ is independent exactly when $V \setminus S$ is a cover, and keep track of the sizes.
hint: To explain why it matters, say what a fast algorithm for the target problem would imply for the source problem.

```python
def clique_to_independent_set(n, edges):
    present = {(min(u, v), max(u, v)) for u, v in edges}
    return [(u, v) for u in range(n) for v in range(u + 1, n)
            if (u, v) not in present]
```
hint: Normalize each input edge so that the smaller vertex comes first.
hint: Loop over all pairs `u < v` in increasing order and keep the ones that were not present, which also gives a sorted result.
solution: Store the normalized edges in a set, then list every pair `u < v` not in it. The loops enumerate pairs in sorted order, and the work is $\Theta(n^2)$, polynomial in the input, as a reduction requires.
