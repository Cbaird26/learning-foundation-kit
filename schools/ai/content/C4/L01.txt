@article
Every program stores data and asks questions of it: *is this name present?*, *what is the next job?*, *which route is shortest?* A **data structure** is a way of organizing data in memory so that a chosen set of operations is fast. This course builds the standard ones and teaches you to choose among them.

### Abstract data types

An **abstract data type (ADT)** specifies a collection by the operations it supports and the behavior of those operations, without saying how they are implemented. A **data structure** is a concrete implementation of an ADT.

Take the **stack** ADT. It supports `push(x)`, `pop()` (remove and return the most recently pushed item), `peek()` (look at that item without removing it) and `is_empty()`. Nothing in that description says "list" or "array". You could implement it with a Python list, with linked nodes, or with a fixed array and a counter. Code that uses the stack is correct for any of them, and you may swap the implementation later without touching the callers. That separation is the point of an ADT.

Common ADTs you will meet: **list** (ordered sequence with positions), **stack** (last in, first out), **queue** (first in, first out), **deque** (insert and remove at both ends), **set** (membership, no duplicates), **map** or **dictionary** (keys to values), **priority queue** (remove the smallest or largest item first) and **graph**. Different data structures implement the same ADT with different costs: both a hash table and a balanced search tree can implement a map, but only the tree keeps the keys in sorted order.

### Big-O review

We compare implementations by how the number of basic operations grows with input size $n$. We write $f(n) = O(g(n))$ when there are constants $c > 0$ and $n_0$ with $f(n) \le c\,g(n)$ for all $n \ge n_0$. Big-O hides constant factors and lower-order terms, so $3n^2 + 50n + 7 = O(n^2)$.

The classes you need, from slowest growth to fastest: $O(1)$ constant, $O(\log n)$ logarithmic (halving the problem each step), $O(n)$ linear, $O(n \log n)$ (efficient sorting), $O(n^2)$ quadratic (a loop inside a loop), $O(2^n)$ exponential.

| Code shape | Cost |
|---|---|
| a fixed number of statements | $O(1)$ |
| `while n > 1: n //= 2` | $O(\log n)$ |
| one loop over `n` items | $O(n)$ |
| loop inside a loop, both over `n` | $O(n^2)$ |

Always name the **case** and the **model**. *Worst case* bounds every input of size $n$; *average case* assumes a distribution of inputs; *amortized* cost averages over a sequence of operations (next week). The model here counts basic operations such as comparisons and assignments, each costing one unit.

### Costs hide inside Python

A single line of Python can hide a loop. `x in some_list` scans the list, so it is $O(n)$; `x in some_set` is $O(1)$ on average. `lst.insert(0, x)` shifts every element, so it is $O(n)$; `lst.append(x)` is $O(1)$ amortized. `a + b` on lists copies both. Whenever you analyze code, ask what each call costs, not just how many loops you can see.

### An ADT in code

```python
class Stack:
    """Last in, first out. Backed by a Python list."""

    def __init__(self):
        self._items = []

    def push(self, x):
        self._items.append(x)

    def pop(self):
        if not self._items:
            raise IndexError("pop from empty stack")
        return self._items.pop()

    def is_empty(self):
        return not self._items
```

The leading underscore on `_items` marks it as internal. Callers use only `push`, `pop` and `is_empty`. Each operation is $O(1)$ (amortized for `push`). If you replaced the list by linked nodes tomorrow, no caller would change.

@example
title: Counting the work of nested loops
problem: How many times does `count += 1` run, as a function of `n`, and what is its big-O class?

```python
count = 0
for i in range(n):
    for j in range(i, n):
        count += 1
```
step: For a fixed `i`, the inner loop runs over `j = i, i+1, ..., n-1`, which is `n - i` values.
step: Sum over `i = 0, 1, ..., n-1`: the total is `n + (n-1) + ... + 1`.
step: That sum is $\frac{n(n+1)}{2} = \frac{n^2}{2} + \frac{n}{2}$. Check with `n = 4`: `4 + 3 + 2 + 1 = 10`, and $\frac{4 \cdot 5}{2} = 10$.
step: Drop the constant factor and the lower-order term: the count is $O(n^2)$.
answer: $\frac{n(n+1)}{2}$ executions, so $O(n^2)$.

@example
title: Choosing an implementation from operation costs
problem: A program stores a waiting line of up to 100000 jobs. It only adds jobs at the back and removes them from the front. Is a Python list a good implementation of this queue?
step: List the operations: `enqueue` adds at the back and `dequeue` removes from the front.
step: `lst.append(job)` is $O(1)$ amortized, so `enqueue` is cheap.
step: `lst.pop(0)` removes the first element and shifts all the others left, so `dequeue` is $O(n)$.
step: Draining a queue of `n` jobs would then cost about $n + (n-1) + \dots + 1 = O(n^2)$ shifts in total, which is slow for `n = 100000`.
step: A structure that is cheap at both ends (a linked list, a circular array or `collections.deque`) gives $O(1)$ for both operations. You will build these in the next weeks.
answer: No. A list makes `dequeue` $O(n)$; use a structure with $O(1)$ operations at both ends.

@mistakes
- Confusing the ADT with its implementation: "a stack is a list" describes one implementation, not the stack's behavior.
- Treating big-O as an exact running time. $O(n)$ code with a huge constant can be slower than $O(n^2)$ code for small `n`; big-O describes growth.
- Forgetting hidden loops: `in`, `list.insert`, `list.pop(0)`, slicing and `+` on lists each cost $O(n)$ or more.
- Giving a bound without a case, such as "searching is $O(1)$", when the claim only holds on average for a hash table and not in the worst case.

@practice code
prompt: Implement a `Stack` class backed by a Python list, with methods `push(x)`, `pop()`, `peek()`, `is_empty()` and `__len__()`. `pop()` removes and returns the most recently pushed item; `peek()` returns it without removing it. Both `pop()` and `peek()` raise `IndexError` on an empty stack.
starter:
```python
class Stack:
    def __init__(self):
        pass
```
tests:
```python
s = Stack()
assert s.is_empty()
assert len(s) == 0
s.push(1)
s.push(2)
assert s.peek() == 2
assert len(s) == 2
assert s.pop() == 2
assert s.pop() == 1
assert s.is_empty()
assert raises(IndexError, s.pop)
assert raises(IndexError, s.peek)
s.push("a")
assert s.pop() == "a"
```
model:
```python
class Stack:
    def __init__(self):
        self._items = []

    def push(self, x):
        self._items.append(x)

    def pop(self):
        if not self._items:
            raise IndexError("pop from empty stack")
        return self._items.pop()

    def peek(self):
        if not self._items:
            raise IndexError("peek at empty stack")
        return self._items[-1]

    def is_empty(self):
        return not self._items

    def __len__(self):
        return len(self._items)
```
hint: Store the items in a list attribute created in `__init__`, and let the end of the list be the top of the stack.
hint: `list.append` and `list.pop()` work at the end of the list. Check for emptiness yourself so that you raise `IndexError` with your own message.
solution: Keep a private list with the top at the end. `push` appends, `pop` removes the last item, and `peek` reads `self._items[-1]`; both raise `IndexError` when the list is empty. Every operation is $O(1)$ (amortized for `push`).

@practice code
prompt: Write `has_duplicate(items)` that returns `True` if some value occurs at least twice in the list `items`, and `False` otherwise. The items are hashable. Use a set so that the function runs in $O(n)$ expected time rather than comparing every pair.
starter:
```python
def has_duplicate(items):
    pass
```
tests:
```python
assert has_duplicate([1, 2, 3, 1]) is True
assert has_duplicate([]) is False
assert has_duplicate([5]) is False
assert has_duplicate(["a", "b", "c"]) is False
assert has_duplicate([1, 2, 1]) is True
assert has_duplicate([2, 2]) is True
```
model:
```python
def has_duplicate(items):
    seen = set()
    for x in items:
        if x in seen:
            return True
        seen.add(x)
    return False
```
hint: Remember the values you have already looked at.
hint: For each item, check whether it is already in the set before you add it.
solution: Scan once, keeping a set of values seen so far. Membership tests and insertions are $O(1)$ on average, so the whole scan is $O(n)$ expected time with $O(n)$ extra space. Comparing every pair would cost $O(n^2)$.

@quiz code
prompt: Write `two_sum_exists(nums, target)` that returns `True` if there are two different positions `i < j` with `nums[i] + nums[j] == target`, and `False` otherwise. It must run in $O(n)$ expected time (use a set); an item may not be paired with itself.
starter:
```python
def two_sum_exists(nums, target):
    pass
```
tests:
```python
assert two_sum_exists([2, 7, 11, 15], 9) is True
assert two_sum_exists([3], 6) is False
assert two_sum_exists([3, 3], 6) is True
assert two_sum_exists([], 0) is False
assert two_sum_exists([1, 2, 4], 8) is False
assert two_sum_exists([-5, 5, 9], 0) is True
```
model:
```python
def two_sum_exists(nums, target):
    seen = set()
    for x in nums:
        if target - x in seen:
            return True
        seen.add(x)
    return False
```
hint: For each `x`, the partner you need is `target - x`.
hint: Look for the partner among the items already seen, and add `x` to the set only after the check, so an item is never paired with itself.
solution: One pass with a set of earlier values. If `target - x` is already in the set, an earlier position holds the partner. Adding `x` after the check prevents pairing `x` with itself, and `[3]` with target `6` correctly gives `False`.
