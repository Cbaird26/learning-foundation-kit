@article
Lists, stacks and queues are linear: each element has one successor. Many data are hierarchical: a file system, an HTML page, an arithmetic expression, the call tree of a recursive function. A **tree** models this. It is a set of **nodes** connected by edges, with one distinguished **root**, such that every other node has exactly one **parent** and there are no cycles.

### Terminology

- A node's **children** are the nodes directly below it; nodes with the same parent are **siblings**. A node with no children is a **leaf**; the others are **internal** nodes.
- A **subtree** is a node together with all its descendants.
- The **depth** of a node is the number of edges from the root to it (the root has depth 0). The **height** of a node is the number of edges on the longest downward path to a leaf; the height of a tree is the height of its root. In this course a single node has height 0 and the **empty tree has height $-1$**. (Some texts count nodes instead of edges, so check the convention.)
- A **level** is the set of nodes at one depth.

A **binary tree** gives each node at most two children, called **left** and **right**. The order matters: a tree whose only child is a left child differs from one whose only child is a right child.

```python
class Node:
    def __init__(self, value, left=None, right=None):
        self.value = value
        self.left = left
        self.right = right
```

An empty tree is `None`. Most tree algorithms are recursive because a tree is defined recursively: a tree is empty, or a root with a left subtree and a right subtree.

### Counting facts

A binary tree of height $h$ has at most $2^i$ nodes at depth $i$, so at most $2^0 + 2^1 + \dots + 2^h = 2^{h+1} - 1$ nodes. Equivalently, a binary tree with $n$ nodes has height at least $\lfloor \log_2 n \rfloor$. It can also be as tall as $n - 1$, when every node has one child (a "linked list in disguise"). Later weeks keep the height near $\log_2 n$, because the cost of tree operations is $O(h)$.

A binary tree in which every internal node has two children is called **full**; such a tree with $L$ leaves has $2L - 1$ nodes.

### Depth-first traversals

A **traversal** visits every node once. The three depth-first orders differ in when the node is visited relative to its subtrees:

- **Preorder**: node, left subtree, right subtree.
- **Inorder**: left subtree, node, right subtree.
- **Postorder**: left subtree, right subtree, node.

```python
def inorder(node, out):
    if node is None:
        return
    inorder(node.left, out)
    out.append(node.value)
    inorder(node.right, out)
```

Each traversal takes $O(n)$ time, since each node is processed once with $O(1)$ work, and $O(h)$ extra space for the recursion stack. Preorder suits copying a tree and printing a directory listing; postorder suits computing something from the children's results, such as height or the size of a folder; inorder on a binary *search* tree gives sorted order (next week).

Python's recursion limit (1000 frames by default) is below the height of a degenerate tree with a few thousand nodes. The recursion can be replaced by an explicit stack. For **iterative inorder**: walk left pushing nodes; when you cannot go left, pop a node, visit it, and move to its right child.

### Breadth-first (level-order) traversal

Level order visits nodes level by level, left to right. It uses a **queue**: enqueue the root; repeatedly dequeue a node, visit it and enqueue its non-empty children. It runs in $O(n)$ time and $O(w)$ space where $w$ is the maximum width of the tree. This is the same idea as breadth-first search on graphs in week 11.

### Rebuilding a tree from traversals

A preorder sequence together with an inorder sequence (of distinct values) determines the binary tree uniquely: the first preorder value is the root, and its position in the inorder sequence splits the other values into left and right subtrees. Preorder and postorder alone do not determine a tree in general, because a lone child could be left or right.

@example
title: The four traversals of one tree
problem: Give all four traversal orders of the tree with root `A`, left child `B` (which has children `D` and `E`), and right child `C` (which has only a right child `F`).
step: Preorder visits the node first: `A`, then the left subtree `B D E`, then the right subtree `C F`. Result: `A B D E C F`.
step: Inorder: left subtree first (`D B E`, which is `D`, then `B`, then `E`), then `A`, then the right subtree (`C` has no left child, so `C F`). Result: `D B E A C F`.
step: Postorder visits the node last: left subtree `D E B`, right subtree `F C`, then `A`. Result: `D E B F C A`.
step: Level order reads the levels top to bottom: `A`, then `B C`, then `D E F`. Result: `A B C D E F`.
answer: Preorder `A B D E C F`; inorder `D B E A C F`; postorder `D E B F C A`; level order `A B C D E F`.

@example
title: Computing height recursively
problem: Write `height(node)` for the convention that an empty tree has height $-1$, and trace it on a root with one child that has one child.
step: The height of a tree is one more than the taller subtree's height: $h = 1 + \max(h_{\text{left}}, h_{\text{right}})$.
step: The base case is the empty tree: `height(None)` is `-1`. This choice makes a leaf come out right, since $1 + \max(-1, -1) = 0$.

```python
def height(node):
    if node is None:
        return -1
    return 1 + max(height(node.left), height(node.right))
```
step: Trace on `root -> mid -> leaf` (each a left child). `height(leaf)` is $1 + \max(-1, -1) = 0$.
step: `height(mid)` is $1 + \max(0, -1) = 1$, and `height(root)` is $1 + \max(1, -1) = 2$. The tree has three nodes in a chain, so its height is 2.
answer: The height is 2. The function visits each node once: $O(n)$ time, $O(h)$ stack space.

@mistakes
- Mixing up the height convention (edges versus nodes) and so being off by one; fix the convention first and make the empty tree consistent with it.
- Forgetting the `None` base case, or testing `node.left` before checking that `node` is not `None`.
- Confusing depth (distance from the root down to a node) with height (distance from a node down to its deepest leaf).
- Using recursion on a very deep tree and hitting Python's recursion limit; use an explicit stack for degenerate shapes.

model:
```python
class Node:
    def __init__(self, value, left=None, right=None):
        self.value = value
        self.left = left
        self.right = right


def preorder(root):
    if root is None:
        return []
    return [root.value] + preorder(root.left) + preorder(root.right)


def inorder(root):
    if root is None:
        return []
    return inorder(root.left) + [root.value] + inorder(root.right)


def postorder(root):
    if root is None:
        return []
    return postorder(root.left) + postorder(root.right) + [root.value]
```
hint: Each function returns the concatenation of three pieces: the left list, the right list and the node's own value in a one-item list.
hint: The three orders differ only in where `[root.value]` goes: first, in the middle or last.
solution: Preorder is `[value] + left + right`, inorder is `left + [value] + right` and postorder is `left + right + [value]`, with `[]` for the empty tree. Concatenating lists makes this $O(n \cdot h)$ in the worst case; passing one output list down, as in the article, is $O(n)$.

model:
```python
from collections import deque


class Node:
    def __init__(self, value, left=None, right=None):
        self.value = value
        self.left = left
        self.right = right


def level_order(root):
    if root is None:
        return []
    levels = []
    queue = deque([root])
    while queue:
        level = []
        for _ in range(len(queue)):
            node = queue.popleft()
            level.append(node.value)
            if node.left is not None:
                queue.append(node.left)
            if node.right is not None:
                queue.append(node.right)
        levels.append(level)
    return levels
```
hint: Start the queue with the root. At the start of each pass of the outer loop, the queue holds exactly one level.
hint: Take `len(queue)` nodes for the current level, appending their children to the queue as you go.
solution: Each outer pass handles one level: the queue length at its start is the level's size. Dequeuing those nodes records their values and enqueues the next level's nodes, left child before right child. Every node is enqueued and dequeued once, so the time is $O(n)$.

model:
```python
class Node:
    def __init__(self, value, left=None, right=None):
        self.value = value
        self.left = left
        self.right = right


def inorder_iter(root):
    out = []
    stack = []
    node = root
    while node is not None or stack:
        while node is not None:
            stack.append(node)
            node = node.left
        node = stack.pop()
        out.append(node.value)
        node = node.right
    return out
```
hint: Go as far left as possible, pushing every node you pass.
hint: When you cannot go left, pop a node, record it, then continue from its right child. Stop when the stack is empty and there is no current node.
solution: The stack holds the ancestors whose left subtrees are being explored. After finishing a node's left subtree we pop it, visit it, and move to its right subtree, which gives left, node, right order. Each node is pushed and popped once: $O(n)$ time and $O(h)$ space, with no recursion limit problems.

@quiz num
prompt: A binary tree in which every internal node has exactly two children has 10 leaves. How many nodes does it have in total?
answer: 19
check: 10 + (10 - 1)
hint: Each internal node has two children; count the edges in two ways: once as $n - 1$, once as 2 per internal node.
solution: With $I$ internal nodes and $L$ leaves, the edges number $n - 1 = L + I - 1$ and also $2I$. So $I = L - 1 = 9$, and $n = 10 + 9 = 19$, which is $2L - 1$.
