@article
A **binary search tree (BST)** is a binary tree in which every node holds a **key**, and for every node $x$:

- every key in $x$'s left subtree is **less than** $x$'s key, and
- every key in $x$'s right subtree is **greater than** $x$'s key.

(This course stores distinct keys. A tree that allows duplicates must choose a side for them consistently.) The condition is about the entire subtree, not just the children: a key in the right child's left subtree must still exceed the ancestor.

The BST implements the **sorted set** or **sorted map** ADT: `insert`, `contains`/`search` and `delete` like a hash table, plus ordered operations (minimum, maximum, successor, range queries, sorted iteration) that a hash table cannot do efficiently.

### Search and insert

Searching mimics binary search: compare the target with the node's key and go left or right, as in the code below. Insertion follows the same path until it falls off the tree, then attaches a new leaf there.

```python
class Node:
    def __init__(self, key):
        self.key = key
        self.left = None
        self.right = None

def search(root, key):
    node = root
    while node is not None and node.key != key:
        node = node.left if key < node.key else node.right
    return node

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    elif key > root.key:
        root.right = insert(root.right, key)
    return root          # equal key: already present
```

Each step moves one level down, so both operations take $O(h)$ time, where $h$ is the tree's height.

### Inorder traversal is sorted

By the BST property, an inorder traversal (left subtree, node, right subtree) outputs all smaller keys, then the node, then all larger keys, and by induction on the subtrees the output is increasing. A BST therefore sorts its keys in $O(n)$ after the tree is built. The minimum is the leftmost node and the maximum the rightmost, both found in $O(h)$.

The **inorder successor** of a node with a right subtree is the minimum of that subtree: go right once, then left as far as possible.

### Deletion

Deleting key $k$ first finds its node $z$, then there are three cases.

1. **$z$ is a leaf**: remove it (set the parent's link to `None`).
2. **$z$ has one child**: replace $z$ by that child (the parent links directly to it).
3. **$z$ has two children**: find its inorder successor $s$, the minimum of the right subtree (which has no left child). Copy $s$'s key into $z$, then delete $s$ from the right subtree; that deletion is case 1 or 2. Using the predecessor, the maximum of the left subtree, works equally well.

All three take $O(h)$.

### Height decides everything

Insert, search and delete all cost $O(h)$. The shape depends on insertion order. Inserting keys in a random order gives expected height $O(\log n)$. But inserting already-sorted keys $1, 2, 3, \dots, n$ makes each new key the right child of the previous one: a chain of height $n - 1$, and building it costs $1 + 2 + \dots + (n-1) = O(n^2)$. Real data is often partly sorted, so a plain BST cannot guarantee $O(\log n)$. The remedy is a **self-balancing** tree (next week) that restructures itself to keep $h = O(\log n)$ in the worst case.

### Summary

| Operation | Average (random order) | Worst case |
|---|---|---|
| search, insert, delete | $O(\log n)$ | $O(n)$ |
| minimum, maximum | $O(\log n)$ | $O(n)$ |
| inorder traversal | $O(n)$ | $O(n)$ |

step: Inorder (left, node, right): the left subtree of 8 gives 1, 3, 6; then 8; then the right subtree gives 10, 14.
answer: Height 2; inorder 1, 3, 6, 8, 10, 14 (sorted).

@example
title: Deleting a node with two children
problem: In the tree built above, delete the root 8.
step: The root has two children, so find its inorder successor: the minimum of the right subtree. Start at 10, which has no left child, so the successor is 10.
step: Copy the successor's key into the root: the root's key becomes 10.
step: Delete the original node 10 from the right subtree. It has one child (14), so case 2 replaces it by 14.
step: Result: root 10 with left subtree (3 with children 1 and 6) and right child 14. The inorder traversal is 1, 3, 6, 10, 14, still sorted.
answer: The new root is 10, with right child 14, and the left subtree is unchanged.

@mistakes
- Checking only a node's children against it when validating a BST. The bound applies to the whole subtree: use the allowed range $(\text{low}, \text{high})$ for each node.
- Deleting a two-child node by removing it outright and losing its subtrees, rather than replacing its key with the successor's.
- Forgetting to return the updated subtree root from a recursive insert or delete, so the parent's link is never updated.
- Quoting $O(\log n)$ for BST operations without the qualification "when the tree is balanced or the insertion order is random".

```python
class _Node:
    def __init__(self, key):
        self.key = key
        self.left = None
        self.right = None


class BST:
    def __init__(self):
        self._root = None
        self._size = 0

    def __len__(self):
        return self._size

    def insert(self, key):
        if self._root is None:
            self._root = _Node(key)
            self._size = 1
            return True
        node = self._root
        while True:
            if key == node.key:
                return False
            if key < node.key:
                if node.left is None:
                    node.left = _Node(key)
                    break
                node = node.left
            else:
                if node.right is None:
                    node.right = _Node(key)
                    break
                node = node.right
        self._size += 1
        return True

    def contains(self, key):
        node = self._root
        while node is not None:
            if key == node.key:
                return True
            node = node.left if key < node.key else node.right
        return False

    def inorder(self):
        out = []
        self._inorder(self._root, out)
        return out

    def _inorder(self, node, out):
        if node is not None:
            self._inorder(node.left, out)
            out.append(node.key)
            self._inorder(node.right, out)

    def height(self):
        return self._height(self._root)

    def _height(self, node):
        if node is None:
            return -1
        return 1 + max(self._height(node.left), self._height(node.right))
```

model:
```python
class Node:
    def __init__(self, key, left=None, right=None):
        self.key = key
        self.left = left
        self.right = right


def is_bst(root):
    def check(node, low, high):
        if node is None:
            return True
        if low is not None and node.key <= low:
            return False
        if high is not None and node.key >= high:
            return False
        return check(node.left, low, node.key) and check(node.right, node.key, high)

    return check(root, None, None)
```
hint: Pass down the range of keys that each subtree is allowed to contain.
hint: Going left, the node's key becomes the new upper bound; going right, it becomes the new lower bound. Both bounds are strict.
solution: Each recursive call carries `low` and `high` bounds inherited from all ancestors. A key violating them (including equal keys) makes the tree invalid. The tree `10 / 5 (right child 15)` fails because 15 is in the left subtree of 10 but is not below 10. An alternative is to check that an inorder traversal is strictly increasing.

model:
```python
class Node:
    def __init__(self, key, left=None, right=None):
        self.key = key
        self.left = left
        self.right = right


def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    elif key > root.key:
        root.right = insert(root.right, key)
    return root


def delete(root, key):
    if root is None:
        return None
    if key < root.key:
        root.left = delete(root.left, key)
    elif key > root.key:
        root.right = delete(root.right, key)
    else:
        if root.left is None:
            return root.right
        if root.right is None:
            return root.left
        successor = root.right
        while successor.left is not None:
            successor = successor.left
        root.key = successor.key
        root.right = delete(root.right, successor.key)
    return root
```
hint: Recurse left or right until you find the node; return the updated subtree root each time.
hint: A node with at most one child is replaced by that child. With two children, copy the minimum key of the right subtree into the node and delete that key from the right subtree.
solution: The recursion returns the new root of each subtree, which handles the leaf and one-child cases by returning the other child (or `None`). For two children, the successor is the leftmost node of the right subtree; its key moves up, and deleting it from the right subtree is an easier case. Deleting 50 from the example tree promotes 60.
