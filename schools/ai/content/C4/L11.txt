@article
A **graph** $G = (V, E)$ is a set of **vertices** (nodes) and a set of **edges** joining pairs of vertices. Graphs model road maps, social networks, the web, dependencies between tasks and circuits. In an **undirected** graph an edge $\{u, v\}$ has no direction; in a **directed** graph (digraph) an edge $(u, v)$ goes from $u$ to $v$. A **weighted** graph attaches a number (a cost, a distance) to each edge. Write $V$ for the number of vertices and $E$ for the number of edges (the notation $O(V + E)$ means $O(|V| + |E|)$).

### Vocabulary

Vertices joined by an edge are **adjacent**; the **degree** of a vertex is its number of incident edges. In an undirected graph the degrees sum to $2E$. A **path** is a sequence of vertices in which consecutive ones are adjacent; a **cycle** is a path that returns to its start without repeating edges. An undirected graph is **connected** if there is a path between every pair of vertices; otherwise it splits into **connected components**. A **tree** is a connected graph with no cycles. A **directed acyclic graph (DAG)** has no directed cycle. A simple undirected graph has at most $\binom{V}{2} = V(V-1)/2$ edges, so $E = O(V^2)$; a graph with $E$ close to $V$ is **sparse** and one with $E$ close to $V^2$ is **dense**.

### Representations

An **adjacency matrix** is a $V \times V$ table $A$ with $A[u][v] = 1$ (or the weight) if there is an edge from $u$ to $v$. Testing an edge is $O(1)$, but the matrix takes $O(V^2)$ space and listing a vertex's neighbors takes $O(V)$, even if it has few.

An **adjacency list** stores for each vertex the list of its neighbors. Space is $O(V + E)$ (an undirected edge appears twice), listing the neighbors of $u$ costs $O(\deg u)$, and testing an edge costs $O(\deg u)$. Most real graphs are sparse, so adjacency lists are the default. In Python, a dictionary maps each vertex to a list:

```python
graph = {
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A", "D"],
    "D": ["B", "C"],
}
```

An **edge list** (a list of pairs) is compact and convenient as input, but slow for neighbor queries.

### Breadth-first search

BFS explores a graph in rings around a **start** vertex: first the start, then its neighbors, then their unvisited neighbors, and so on. It uses a **queue** and a `visited` set (marking a vertex when it is *enqueued*, so no vertex enters the queue twice):

```python
from collections import deque

def bfs_distances(graph, start):
    dist = {start: 0}
    queue = deque([start])
    while queue:
        u = queue.popleft()
        for v in graph[u]:
            if v not in dist:
                dist[v] = dist[u] + 1
                queue.append(v)
    return dist
```

Each vertex is enqueued once and each adjacency list scanned once, so BFS runs in $O(V + E)$ time with $O(V)$ extra space. Because it visits vertices in order of distance, `dist[v]` is the **fewest edges** on any path from `start` to `v`. That makes BFS the algorithm for shortest paths in unweighted graphs; record each vertex's `parent` to rebuild a path. Vertices not reachable from `start` do not appear in the result, so BFS also finds the connected component of `start`.

### Depth-first search

DFS follows one path as deep as it can, then backtracks. It uses recursion (the call stack) or an explicit stack:

```python
def dfs(graph, u, visited, order):
    visited.add(u)
    order.append(u)
    for v in graph[u]:
        if v not in visited:
            dfs(graph, v, visited, order)
```

DFS also takes $O(V + E)$ time. It is the basis of cycle detection, topological sorting of DAGs, finding connected components (start a DFS from each unvisited vertex) and solving mazes and puzzles by backtracking. The recursion depth can reach $V$, which exceeds Python's default recursion limit on large paths, so for large graphs use an explicit stack.

### BFS versus DFS

BFS finds shortest paths in edges and needs memory proportional to the widest frontier; DFS uses memory proportional to the path depth and finds *a* path, not necessarily the shortest. With an adjacency matrix, both cost $O(V^2)$, because scanning a row costs $O(V)$. When the order in which neighbors are visited matters, both traversals follow the order of each adjacency list, and so different orders can give different, equally valid, traversals.

@example
title: BFS and DFS on the same graph
problem: Graph (undirected): `A: [B, C]`, `B: [A, D]`, `C: [A, D, E]`, `D: [B, C, F]`, `E: [C, F]`, `F: [D, E]`. Give the BFS order and distances and the recursive DFS order from `A`, visiting neighbors in the listed order.
step: BFS: dequeue `A` (distance 0), enqueue its unvisited neighbors `B` and `C` with distance 1. Dequeue `B`: enqueue `D` (distance 2). Dequeue `C`: `D` is already seen; enqueue `E` (distance 2).
step: Dequeue `D`: enqueue `F` (distance 3). Dequeue `E` and `F`: all their neighbors are seen. BFS order: `A B C D E F`; distances: `A` 0, `B` 1, `C` 1, `D` 2, `E` 2, `F` 3.
step: DFS from `A`: visit `A`, then its first neighbor `B`. From `B`, `A` is visited, so go to `D`. From `D`: `B` is visited, so go to `C`.
step: From `C`: `A` and `D` are visited, so go to `E`. From `E`: `C` is visited, so go to `F`. All vertices are visited. DFS order: `A B D C E F`.
answer: BFS order `A B C D E F` (with `F` at distance 3); DFS order `A B D C E F`.

@example
title: Counting connected components
problem: How can you count the connected components of an undirected graph given as an adjacency list?
step: Keep a `visited` set and a counter, both starting empty or at zero.
step: For each vertex in the graph, if it is not visited, we have found a new component: add 1 to the counter and run a DFS (or BFS) from that vertex, which marks every vertex in its component as visited.
step: Vertices already visited belong to a component counted earlier, so they are skipped.

```python
def count_components(graph):
    visited = set()
    count = 0
    for s in graph:
        if s not in visited:
            count += 1
            stack = [s]
            visited.add(s)
            while stack:
                u = stack.pop()
                for v in graph[u]:
                    if v not in visited:
                        visited.add(v)
                        stack.append(v)
    return count
```
step: Each vertex and each edge is processed a constant number of times, so the total cost is $O(V + E)$.
answer: Start a traversal from each unvisited vertex and count the starts; $O(V + E)$.

@mistakes
- Marking a vertex visited only when it is dequeued (BFS) rather than when it is enqueued, so it can be enqueued many times and the work grows beyond $O(V + E)$.
- Forgetting the `visited` set, so the search loops forever on any graph with a cycle (every undirected edge is a 2-cycle).
- Using an undirected graph's adjacency list with an edge stored in only one direction, which silently turns it into a directed graph.
- Claiming that DFS finds shortest paths. Only BFS does so in an unweighted graph.

model:
```python
from collections import deque


def shortest_path(graph, source, target):
    parent = {source: None}
    queue = deque([source])
    while queue:
        u = queue.popleft()
        if u == target:
            break
        for v in graph[u]:
            if v not in parent:
                parent[v] = u
                queue.append(v)
    if target not in parent:
        return None
    path = []
    node = target
    while node is not None:
        path.append(node)
        node = parent[node]
    path.reverse()
    return path
```
hint: Run BFS from `source`, storing `parent[v] = u` the first time `v` is discovered; the dictionary doubles as the visited set.
hint: If `target` is never discovered return `None`. Otherwise follow the parents from `target` back to `source` and reverse the list.
solution: BFS discovers each vertex first along a path with the fewest edges, so the parent links form a shortest-path tree. Walking from `target` to `source` through `parent` and reversing gives the path. The directed chain test checks that unreachable targets return `None`.
