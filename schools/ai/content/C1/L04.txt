@article
A **function** gives a name to a computation so you can reuse it and reason about it without rereading its body. This is **abstraction**: the caller needs to know *what* the function does, not *how*.

### Defining and calling

```python
def power(base, exp=2):
    """Return base raised to the non-negative integer exp."""
    result = 1
    for _ in range(exp):
        result *= base
    return result
```

`base` and `exp` are **parameters**; the values passed in a call are **arguments**. `exp=2` is a **default**: `power(5)` uses `exp = 2` and returns `25`, `power(2, 10)` returns `1024`, and a **keyword argument** names the parameter: `power(2, exp=3)`. Parameters with defaults must come after those without.

`return` ends the function and sends a value to the caller. A function that reaches its end without `return` gives back `None`. A common beginner error is to `print` a result instead of returning it: printed text goes to the screen and cannot be used by the next computation, while a returned value can be stored, compared or passed on.

### Scope

Each call creates a fresh **local scope**: parameters and any variable assigned inside the function exist only during that call. Python looks a name up in this order: local, enclosing function, global (module), built-in (the LEGB rule).

```python
x = 5
def f(x):
    x = x + 1     # changes only the local x
    return x
y = f(x)
print(x, y)       # 5 6
```

The global `x` is untouched because the `x` inside `f` is a different variable. If a function *assigns* to a name anywhere in its body, that name is local throughout the body, so reading it before the assignment raises `UnboundLocalError`. The `global` statement lets a function rebind a module-level name, but it makes code hard to reason about; pass values in as arguments and return results instead.

### Functions are values

A function can be passed as an argument, which is how general tools are built:

```python
def apply_twice(f, x):
    return f(f(x))
```

### Specifications

A **specification** is a contract between the author and the caller, written in the **docstring**. A good one states:

- **Requires** (preconditions): what the caller must guarantee, such as `x >= 0`.
- **Returns / effects** (postconditions): what the function guarantees if the preconditions hold, including what it does for edge cases and what it raises.

```python
def sqrt_bisect(x, eps=1e-6):
    """Return g with abs(g*g - x) < eps.

    Requires x >= 0 and eps > 0. Raises ValueError if x < 0.
    """
```

Writing the specification *first* tells you what to implement and which tests to write; if you cannot state it precisely, you do not yet understand the problem. When the caller breaks a precondition the function is free to do anything, but good code fails loudly with an exception (week 8) rather than returning garbage.

### Decomposition

Break a big problem into small functions, each with one clear job and a specification. Small functions are easier to test, reuse and trace.

@example
title: Following a call through scope
problem: What does this program print?

```python
def f(x):
    x = x * 2
    return x + 1

x = 3
y = f(x + 1)
print(x, y)
```
step: The module-level `x` is bound to `3`.
step: The call `f(x + 1)` first evaluates the argument `x + 1`, which is `4`.
step: Inside `f`, the *parameter* `x` is a new local variable bound to `4`. `x = x * 2` rebinds that local `x` to `8`, and the function returns `8 + 1 = 9`.
step: So `y` is `9`. The global `x` was never changed by `f`, so it is still `3`.
answer: `3 9`

@example
title: Writing a function from its specification
problem: Write `gcd(a, b)`, the greatest common divisor of non-negative integers `a` and `b` that are not both zero, using Euclid's algorithm: `gcd(a, 0)` is `a`, and otherwise `gcd(a, b)` equals `gcd(b, a % b)`.
step: The specification fixes the edge case: when `b` is `0` the answer is `a`.
step: Otherwise replace the pair `(a, b)` by `(b, a % b)`. The remainder is smaller than `b`, so `b` shrinks and the loop ends.
step: In code, with a simultaneous assignment:

```python
def gcd(a, b):
    while b != 0:
        a, b = b, a % b
    return a
```
step: Trace `gcd(12, 18)`: `(12, 18)`, then `(18, 12)`, then `(12, 6)`, then `(6, 0)`. The loop stops and `6` is returned.

@mistakes
- Printing a result instead of returning it, so the caller receives `None`.
- Assuming that assigning to a parameter changes the caller's variable. It rebinds only the local name.
- Reading a variable and later assigning it inside the same function without defining it first, which raises `UnboundLocalError`.
- Giving a parameter without a default after one with a default (`def f(a=1, b)` is a syntax error).

@practice code
prompt: Write `sqrt_bisect(x, eps=1e-6)` with this specification: requires `eps > 0`; returns `g` with `abs(g * g - x) < eps` found by bisection search; raises `ValueError` if `x < 0`. (Use `raise ValueError("x must be non-negative")` for the error.)
starter:
```python
def sqrt_bisect(x, eps=1e-6):
    pass
```
tests:
```python
r = sqrt_bisect(2)
assert abs(r * r - 2) < 1e-6
r = sqrt_bisect(0.04, 1e-8)
assert abs(r - 0.2) < 1e-3
r = sqrt_bisect(0)
assert abs(r * r) < 1e-6
r = sqrt_bisect(144, 1e-4)
assert abs(r * r - 144) < 1e-4
assert raises(ValueError, sqrt_bisect, -1)
```
model:
```python
def sqrt_bisect(x, eps=1e-6):
    if x < 0:
        raise ValueError("x must be non-negative")
    low, high = 0.0, max(1.0, x)
    guess = (low + high) / 2
    while abs(guess * guess - x) >= eps:
        if guess * guess < x:
            low = guess
        else:
            high = guess
        guess = (low + high) / 2
    return guess
```
hint: Check the precondition first and raise before doing any work.
hint: For the search itself, start with `low = 0.0` and `high = max(1.0, x)` and repeatedly move one end to the midpoint.
solution: Raise `ValueError` for negative `x`, then run the bisection loop from the lesson: the square of the midpoint decides whether `low` or `high` moves. The default `eps` makes the second argument optional.

@quiz code
prompt: Write `lcm(a, b)` that returns the least common multiple of two positive integers `a` and `b`. Do not use `math.lcm` or `math.gcd`; compute the greatest common divisor with Euclid's algorithm in a helper function. `lcm(4, 6)` is `12`.
starter:
```python
def lcm(a, b):
    pass
```
tests:
```python
assert lcm(4, 6) == 12
assert lcm(7, 13) == 91
assert lcm(5, 5) == 5
assert lcm(1, 9) == 9
assert lcm(21, 6) == 42
assert lcm(8, 32) == 32
```
model:
```python
def gcd(a, b):
    while b != 0:
        a, b = b, a % b
    return a


def lcm(a, b):
    return a // gcd(a, b) * b
```
hint: The product `a * b` equals the gcd times the lcm.
hint: Write a small `gcd` helper with the loop `(a, b) -> (b, a % b)`, then divide.
solution: Since `gcd(a, b) * lcm(a, b) == a * b`, the lcm is `a // gcd(a, b) * b`; dividing first keeps the numbers small and exact, because the gcd divides `a`.

@quiz mc
prompt: What happens when this program runs?

```python
count = 0

def bump():
    count = count + 1

bump()
print(count)
```
