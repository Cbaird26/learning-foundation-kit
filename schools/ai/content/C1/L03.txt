@article
### Strings

A `str` is an **immutable** sequence of characters. Positions are numbered from `0`; negative positions count from the end.

```python
s = "computation"
s[0]       # 'c'
s[-1]      # 'n'
s[3:7]     # 'puta'   (positions 3, 4, 5, 6)
s[-4:]     # 'tion'
s[::2]     # 'cmuain' (every second character)
len(s)     # 11
```

A slice `s[i:j]` includes position `i` and excludes position `j`; leaving a bound out means "to the end". Slicing never raises an error for out-of-range bounds, but a single index does: `s[11]` raises `IndexError`. Because strings are immutable, `s[0] = "X"` raises `TypeError`; build a new string instead, for example `"X" + s[1:]`.

Useful operations: `+` concatenates, `*` repeats, `in` tests for a substring (`"put" in s` is `True`), and methods return **new** strings: `s.upper()`, `s.lower()`, `s.strip()` (removes surrounding whitespace), `s.replace(old, new)`, `s.find(sub)` (the index of the first match, or `-1`), `s.count(sub)` and `s.split()` (a list of the whitespace-separated words). Character tests include `ch.isalpha()`, `ch.isdigit()` and `ch.isalnum()`. A `for` loop visits characters one by one:

```python
vowels = 0
for ch in "education":
    if ch in "aeiou":
        vowels += 1
```

Here `vowels` ends at `5`. Characters are themselves strings of length 1; `ord("a")` is `97` and `chr(97)` is `"a"`.

### Approximate answers

Many numbers have no exact finite representation: $\sqrt{2}$ is irrational, and floats are approximate anyway. So a numerical program returns a value *close enough* and says what that means. We pick a tolerance `epsilon` and accept a guess `g` when `abs(g * g - x) < epsilon`.

**Exhaustive enumeration** tries candidates in a fixed order with a fixed step, for instance `0, 0.0001, 0.0002, ...` up to `x`. It is simple, but the number of guesses grows with `x / step`, and a step that is too large can skip over every acceptable value.

### Bisection search

If the answer lies in an interval and you can tell whether a guess is too low or too high, you can **halve** the interval each time. For the square root of `x >= 0`, the root lies between `0` and `max(1, x)` (for `x < 1` the root is *larger* than `x`, hence the `1`):

```python
def sqrt_bisect(x, epsilon=1e-6):
    low, high = 0.0, max(1.0, x)
    guess = (low + high) / 2
    while abs(guess * guess - x) >= epsilon:
        if guess * guess < x:
            low = guess      # guess too small: the root is above it
        else:
            high = guess     # guess too big: the root is below it
        guess = (low + high) / 2
    return guess
```

The **invariant** is that the true root stays inside `[low, high]`; every pass halves the width of that interval. Starting from width `w`, after `k` passes the width is `w / 2**k`, so the number of passes grows like $\log_2(w/\text{precision})$: about 30 passes give a precision near one part in a billion, where enumeration with step `0.000001` would need about a billion guesses. This idea reappears as binary search in week 12.

Bisection needs a **monotonic** relationship (larger guess, larger square), which is why it works for roots of increasing functions. Also note that a float cannot always hit `abs(...) < epsilon` if `epsilon` is smaller than the spacing of floats near `x`; choose `epsilon` realistically, such as `1e-6`.

title: Slicing and indexing a string
problem: Let `word = "programming"`. Evaluate `word[3:7]`, `word[-3:]` and `word[::3]`.
step: Number the characters: p0 r1 o2 g3 r4 a5 m6 m7 i8 n9 g10.

answer: `'gram'`, `'ing'`, `'pgmn'`

@example
title: Tracing bisection by hand
problem: Run `sqrt_bisect(9)` by hand for the first five guesses and say where the root is bracketed.
step: Start: `low = 0`, `high = 9`, so the first guess is `4.5`.
step: `4.5 * 4.5 = 20.25 > 9`: too big, so `high = 4.5`. Next guess `(0 + 4.5) / 2 = 2.25`.
step: `2.25 * 2.25 = 5.0625 < 9`: too small, so `low = 2.25`. Next guess `(2.25 + 4.5) / 2 = 3.375`.
step: `3.375 * 3.375 = 11.390625 > 9`: too big, so `high = 3.375`. Next guess `2.8125`, which is too small, so `low = 2.8125` and the next guess is `3.09375`.
step: After each guess the interval has half the width: 9, 4.5, 2.25, 1.125, 0.5625. The root, 3, always stays inside it.
answer: guesses 4.5, 2.25, 3.375, 2.8125, 3.09375; the root 3 stays inside the shrinking interval

@mistakes
- Treating slices like indexes: `s[3:7]` has 4 characters, not 5, because the stop position is excluded.
- Trying to modify a string in place (`s[0] = "X"`) instead of building a new string.
- Starting bisection with `high = x` for a number below 1: the square root of `0.25` is `0.5`, which lies above `x`.
- Testing a float result with `==` instead of checking `abs(result - target) < epsilon`.

```python
def shift_text(text, k):
    result = ""
    for ch in text:
        if "a" <= ch <= "z":
            offset = (ord(ch) - ord("a") + k) % 26
            result += chr(ord("a") + offset)
        else:
            result += ch
    return result
```
hint: Convert a letter to a number 0 to 25 with `ord(ch) - ord("a")`, add `k`, and wrap with `% 26`.

solution: For each lowercase letter compute `(ord(ch) - ord("a") + k) % 26` and convert it back to a letter; append all other characters unchanged. The modulus handles wrap-around, negative shifts and shifts above 26.
