@article
Two correct programs can differ enormously in speed. Timing a program on one computer is unreliable, because the result depends on the machine, the language and the input. Instead we ask: **how does the number of basic steps grow as the input size `n` grows?** This is the program's **order of growth**, or **time complexity**.

### Counting steps

Count basic operations (an assignment, an arithmetic operation, a comparison, an index) as one step each, and let `n` be the size of the input.

```python
def total(nums):          # n = len(nums)
    result = 0            # 1 step
    for x in nums:        # n passes
        result += x       # 1 step per pass
    return result         # 1 step
```

That is about `n + 2` steps. Nested loops multiply: a loop of `n` passes that contains a loop of `n` passes does about `n * n` steps. If the inner loop runs `i` times on pass `i`, the total is $0 + 1 + \cdots + (n-1) = \frac{n(n-1)}{2}$, which is still of order $n^2$.

### Big-O

We care about growth for large `n`, not the exact constant. **Definition**: $f(n) = O(g(n))$ if there exist constants $c > 0$ and $n_0$ such that $0 \le f(n) \le c \cdot g(n)$ for all $n \ge n_0$.

Example: $3n^2 + 5n + 2 = O(n^2)$, because for $n \ge 1$ we have $5n \le 5n^2$ and $2 \le 2n^2$, so $3n^2 + 5n + 2 \le 10 n^2$ (take $c = 10$, $n_0 = 1$). Two rules follow: drop constant factors, and keep only the fastest-growing term. Big-O is an **upper bound**: a function that is $O(n)$ is also $O(n^2)$, but we state the tightest bound we can.

### Common orders of growth

| class | name | example |
|---|---|---|
| $O(1)$ | constant | index a list, look up a dictionary key (average) |
| $O(\log n)$ | logarithmic | halve the problem each step (binary search) |
| $O(n)$ | linear | one pass over the data |
| $O(n \log n)$ | linearithmic | efficient sorting |
| $O(n^2)$ | quadratic | a loop nested in a loop over the same data |
| $O(2^n)$ | exponential | naive recursive Fibonacci, all subsets |

For $n = 1000$: $\log_2 n$ is about 10, $n \log_2 n$ about 10 000, $n^2$ is 1 000 000, and $2^n$ has over 300 digits. An exponential algorithm is useless beyond small inputs.

A loop that halves its variable (`while n > 1: n = n // 2`) runs about $\log_2 n$ times. Sequential pieces *add* (so the larger wins); nested pieces *multiply*.

### Cases and models

Running time can depend on the input, not just its size, so we say which case: the **worst case** (the bound that holds for every input of size `n`; used by default), the **best case**, or the **average case** over some distribution of inputs. Linear search for a value in a list is $O(1)$ in the best case and $O(n)$ in the worst case. **Amortized** cost averages over a sequence of operations: appending to a list is amortized $O(1)$ although an occasional append copies the whole array.

### Costs of Python operations

| operation | cost |
|---|---|
| `xs[i]`, `len(xs)`, `xs.append(v)` | $O(1)$ (append amortized) |
| `v in xs`, `xs.index(v)`, `xs.insert(0, v)`, `xs.pop(0)` | $O(n)$ |
| `xs[i:j]` (a slice) | $O(j - i)$ |
| `sorted(xs)`, `xs.sort()` | $O(n \log n)$ |
| `k in d` or `d[k]` for a dictionary | $O(1)$ on average |
| `v in s` for a set | $O(1)$ on average |

A **set** is an unordered collection of distinct hashable items: `s = set()`, `s.add(v)`, `v in s`. Replacing a list by a set or dictionary for membership tests is the most common single improvement. For example, testing for duplicates by comparing every pair is $O(n^2)$, while remembering the items seen so far in a set is $O(n)$ on average.

### Space complexity

The same analysis applies to memory: a function that builds a new list of size `n` uses $O(n)$ extra space; one that keeps a few variables uses $O(1)$. Recursive functions use stack space proportional to their depth. Often one trades space for time, as memoization does.

@example
title: Counting steps in nested loops
problem: How many times does `count += 1` run for `n = 8`, and what is the order of growth as a function of `n`?

```python
count = 0
for i in range(n):
    for j in range(i):
        count += 1
```
step: On outer pass `i` the inner loop runs `i` times. For `n = 8`, `i` takes the values 0 to 7.
step: The total is $0 + 1 + 2 + \cdots + 7 = 28$, which agrees with $\frac{n(n-1)}{2} = \frac{8 \cdot 7}{2}$.
step: In general the count is $\frac{n^2 - n}{2}$. Drop the constant factor $\frac12$ and the lower-order term $n$.
step: The order of growth is $O(n^2)$.
answer: 28 times; $O(n^2)$

@example
title: Choosing a faster algorithm
problem: Compare two ways to decide whether a list `xs` has a repeated value, and give the time of each when there is no repeated value (the worst case for the number of passes; for hashing, averages are meant).

```python
def dup_slow(xs):
    for i in range(len(xs)):
        for j in range(i + 1, len(xs)):
            if xs[i] == xs[j]:
                return True
    return False

def dup_fast(xs):
    seen = set()
    for x in xs:
        if x in seen:
            return True
        seen.add(x)
    return False
```
step: `dup_slow` compares every pair. In the worst case (no duplicates) the inner loop runs $(n-1) + (n-2) + \cdots + 0 = \frac{n(n-1)}{2}$ times, so $O(n^2)$.
step: `dup_fast` makes one pass. Each iteration does a set membership test and an insertion, each $O(1)$ on average, so the expected time is $O(n)$ (the number of passes is at most $n$), using $O(n)$ extra space.
step: For $n = 100\,000$, `dup_slow` needs about $5 \times 10^9$ comparisons and `dup_fast` about $10^5$ set operations: the time bought with memory is a factor of tens of thousands.

@mistakes
- Keeping constants and lower terms: $3n^2 + 5n$ is $O(n^2)$, not $O(3n^2 + 5n)$.
- Using the wrong variable: two nested loops over *different* inputs of sizes `n` and `m` cost $O(nm)$, not $O(n^2)$.
- Treating `x in some_list` as free; it scans the list and is $O(n)$, so inside a loop it makes a quadratic algorithm.
- Reading big-O as the exact running time or as the best case: it is an upper bound on growth.

@quiz ms
prompt: Which of these statements about big-O are true?
choice*: $3n^2 + 5n + 2$ is $O(n^2)$
choice*: $n \log n$ is $O(n^2)$
choice: $2^n$ is $O(n^{10})$
choice: $O(1)$ means that exactly one operation is performed
choice*: A function that is $O(n)$ is also $O(n^2)$
hint: Big-O is an upper bound. Which function eventually exceeds any constant multiple of the other?
solution: $n^2$ eventually dominates $3n^2 + 5n + 2$ (up to a constant) and $n \log n$, and any linear function is bounded by a multiple of $n^2$. An exponential eventually exceeds every polynomial, so $2^n$ is not $O(n^{10})$, and $O(1)$ means a bound that does not depend on `n`, not a single operation.

tests:
```python
assert common_elements([1, 2, 2, 3], [2, 3, 3, 4]) == [2, 3]
assert common_elements([], [1, 2]) == []
assert common_elements([5, 1], [1, 5]) == [1, 5]

```
model:
```python
def common_elements(a, b):
    in_b = set(b)
    found = set()
    for x in a:
        if x in in_b:
            found.add(x)
    return sorted(found)
```
hint: Put the values of one list in a set so that each membership test is cheap.
solution: Build `set(b)`, scan `a` once and collect matching values in another set (which removes duplicates), and return `sorted(found)`. Set operations are $O(1)$ on average, so the cost is $O(n + m)$ plus $O(k \log k)$ to sort the `k` results.
