@article
A **program** is a precise description of a computation: a finite list of instructions that a machine can carry out without judgment. Python is an *interpreted* language: the interpreter reads your program and executes it statement by statement. These lessons work with any current Python 3 (3.15 is the newest release); everything here behaves the same in 3.10 and later.

### Values and types

Every value has a **type** that determines what you can do with it. The core types are:

| type | examples | notes |
|---|---|---|
| `int` | `42`, `-7`, `10**30` | whole numbers, arbitrary size, always exact |
| `float` | `3.14`, `2.0`, `1e-3` | approximate real numbers (64-bit IEEE 754) |
| `str` | `"hi"`, `'42'` | text; immutable sequence of characters |
| `bool` | `True`, `False` | result of comparisons |
| `NoneType` | `None` | the "no value" value |

`type(x)` tells you the type of `x`. Note that `"42"` and `42` are different values: one is text, the other a number.

### Arithmetic operators

`+ - * / // % **` are addition, subtraction, multiplication, true division, floor division, remainder and exponentiation.

- `/` **always** returns a `float`: `6 / 3` is `2.0`.
- `//` rounds the true quotient **down** (toward negative infinity): `7 // 2` is `3` but `-7 // 2` is `-4`.
- `%` is defined so that `(a // b) * b + a % b == a`. So `-7 % 2` is `1`, and the sign of the result follows the divisor.
- `**` raises to a power: `2 ** 10` is `1024`.

**Precedence** from tightest to loosest: `**`, unary minus, then `* / // %`, then `+ -`. Operators of equal rank group left to right, except `**`, which groups right to left: `2 ** 3 ** 2` is `2 ** 9`, which is `512`. Also `-2 ** 2` is `-4`, because `**` binds tighter than the minus sign. When in doubt, add parentheses.

### Variables and assignment

`x = 17` does not state an equation: it *binds the name* `x` to the value `17`. The right side is evaluated first, so `x = x + 1` is meaningful: take the current value, add one, and bind the name to the result. Swapping values is `a, b = b, a`.

### Floats are approximate

A `float` stores a binary fraction, and most decimal fractions have no exact binary form. In Python `0.1 + 0.2` evaluates to `0.30000000000000004`, and `0.1 + 0.2 == 0.3` is `False`. Never test floats for exact equality; compare with a tolerance, for example `math.isclose(a, b)` or `abs(a - b) < 1e-9`. When you need exact results (money in cents, counts), use `int`.

### Conversion, input and output

`int("42")` is `42`, `float("2.5")` is `2.5` and `str(7)` is `"7"`. `int(3.9)` truncates toward zero and gives `3`; `int(-3.9)` gives `-3`. `int("3.9")` raises `ValueError`. The built-in `input()` always returns a `str`, so convert it: `n = int(input())`.

An **f-string** inserts expressions into text: `f"{n} items"`. After a colon you can give a format: `{x:.2f}` prints a float with two decimals and `{n:02d}` prints an integer in at least two digits, padded with zeros.

### A first look at functions

A function packages a computation under a name. `return` sends a value back to the caller:

```python
def average(a, b):
    return (a + b) / 2

print(average(3, 4))   # 3.5
```

Week 4 studies functions in depth; for now you only need to read and write short ones.

@example
title: Tracing assignments and remainders
problem: What does this program print?

```python
x = 17
y = x // 5
x = x % 5
y = y * x
print(x, y)
```
step: Statements run in order. `x` is bound to `17`.
step: `y = x // 5` is `17 // 5`, which is `3`. So `y` is `3` and `x` is still `17`.
step: `x = x % 5` is `17 % 5`, which is `2`. Now `x` is `2`. (Check: `3 * 5 + 2 == 17`.)
step: `y = y * x` uses the *current* values: `3 * 2`, so `y` is `6`.
step: `print(x, y)` prints the two values separated by a space.
answer: `2 6`

@example
title: Applying precedence rules
problem: Evaluate `2 + 3 * 4 ** 2 // 5` and give the type of the result.
step: Highest precedence first: `4 ** 2` is `16`, giving `2 + 3 * 16 // 5`.
step: `*` and `//` have equal rank and group left to right, so `3 * 16` is `48` first.
step: Then `48 // 5` is `9`, because `48 / 5 = 9.6` rounds down.
step: Finally `2 + 9` is `11`. Every operand and operator here is an integer operation, so the type is `int`.
answer: `11`, an `int`

@mistakes
- Believing `/` returns an integer when the operands divide evenly: `6 / 3` is `2.0`, a `float`.
- Comparing floats with `==`, for example `0.1 + 0.2 == 0.3`, which is `False`.
- Forgetting that `input()` returns text, so `input() + 1` raises `TypeError` and `"2" + "3"` gives `"23"`.
- Reading `-7 // 2` as `-3`: floor division rounds down, so the answer is `-4`.

@quiz code
prompt: Write `clock(total)` that takes a non-negative integer number of seconds and returns a string `H:MM:SS`, where hours have no padding and minutes and seconds have two digits. For example `clock(3661)` is `"1:01:01"`. Hours may exceed 23.
starter:
```python
def clock(total):
    pass
```
tests:
```python
assert clock(3661) == "1:01:01"
assert clock(59) == "0:00:59"
assert clock(0) == "0:00:00"
assert clock(86399) == "23:59:59"
assert clock(36000) == "10:00:00"
```
model:
```python
def clock(total):
    hours = total // 3600
    minutes = total % 3600 // 60
    seconds = total % 60
    return f"{hours}:{minutes:02d}:{seconds:02d}"
```
hint: Peel off whole hours first, then whole minutes from what remains.
hint: The format `{value:02d}` pads an integer with a leading zero to two digits.
solution: Hours are `total // 3600`; minutes are the remainder after hours divided by 60, `total % 3600 // 60`; seconds are `total % 60`. The `:02d` format supplies the padding.
