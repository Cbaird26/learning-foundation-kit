@article
Straight-line code runs every statement once. Real programs need to **choose** and to **repeat**. This week covers both, and the skill that goes with them: tracing a program by hand.

### Conditionals

```python
if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
else:
    grade = "C"
```

Python tests the conditions from top to bottom and runs the **first** branch whose condition is true; the rest are skipped. That is why the order matters: with `score = 95`, the first test succeeds, so the `>= 80` test is never reached. Indentation (four spaces) marks which statements belong to a branch.

Conditions are **boolean expressions**: comparisons (`== != < <= > >=`) combined with `and`, `or` and `not`. Python allows chained comparisons: `0 <= x < 10` means `0 <= x and x < 10`. The operators `and` and `or` **short-circuit**: in `b != 0 and a / b > 1` the division is never evaluated when `b` is `0`. A condition may be any value: `0`, `0.0`, `""`, `None` and empty collections count as false; nearly everything else counts as true.

### `while` loops

```python
n = 100
count = 0
while n >= 10:
    n = n // 3
    count += 1
```

A `while` loop tests its condition before every pass and stops when it is false. To be sure a loop terminates, find a quantity that changes toward the exit condition on every pass. Here `n` shrinks, so the loop ends. A loop whose condition never becomes false is an **infinite loop**.

### `for` loops and `range`

`for` visits the items of a sequence one at a time. `range` produces integers: `range(5)` gives 0 to 4; `range(2, 8)` gives 2 to 7; `range(10, 0, -3)` gives 10, 7, 4, 1. The stop value is **excluded**, and `range(a, b)` has `b - a` items when `b > a`. Use `for` when you know the sequence in advance and `while` when you repeat until some condition changes.

```python
for ch in "abc":
    print(ch, end="")   # end="" suppresses the newline
```

prints `abc` on one line.

### `break`, `continue` and nesting

`break` leaves the innermost loop immediately; `continue` skips to its next pass. Loops can be **nested**: the inner loop runs completely for every pass of the outer loop, so `for i in range(3): for j in range(4):` runs the inner body 12 times.

### Tracing with a table

To trace a loop, write a table with one column per variable and one row per pass:

| pass | `n` before | `count` after |
|---|---|---|
| 1 | 100 | 1 (n = 33) |
| 2 | 33 | 2 (n = 11) |
| 3 | 11 | 3 (n = 3) |

After the third pass `n` is 3, which fails `n >= 10`, so the loop stops with `count = 3`. This is the discipline that finds bugs without running anything.

@example
title: Tracing a while loop
problem: What does this program print?

```python
n = 100
count = 0
while n >= 10:
    n = n // 3
    count += 1
print(count, n)
```
step: Before the loop `n = 100` and `count = 0`. The test `100 >= 10` is true.
step: Pass 1: `n` becomes `100 // 3 = 33` and `count` becomes `1`.
step: Pass 2: `33 >= 10` is true, `n` becomes `11`, `count` becomes `2`.
step: Pass 3: `11 >= 10` is true, `n` becomes `3`, `count` becomes `3`.
step: Now `3 >= 10` is false, so the loop ends and `print` runs once.
answer: `3 3`

@example
title: Ordering branches
problem: Write `fizzbuzz(n)` returning `"FizzBuzz"` if `n` is divisible by both 3 and 5, `"Fizz"` if only by 3, `"Buzz"` if only by 5, and otherwise `str(n)`.
step: A multiple of 15 is also a multiple of 3 and of 5, so that case must be tested first. Otherwise `"Fizz"` would be returned for 15.
step: Test divisibility with the remainder: `n % 3 == 0`.
step: Chain the tests with `elif` so exactly one branch runs:

```python
def fizzbuzz(n):
    if n % 15 == 0:
        return "FizzBuzz"
    elif n % 3 == 0:
        return "Fizz"
    elif n % 5 == 0:
        return "Buzz"
    else:
        return str(n)
```
step: Check: `fizzbuzz(9)` is `"Fizz"`, `fizzbuzz(10)` is `"Buzz"`, `fizzbuzz(30)` is `"FizzBuzz"` and `fizzbuzz(7)` is `"7"`.

@mistakes
- Putting the more general test first (`n % 3 == 0` before `n % 15 == 0`), so the specific branch can never run.
- An off-by-one error with `range`: `range(1, n)` stops at `n - 1`; use `range(1, n + 1)` to include `n`.
- Writing a `while` loop whose body never changes the variable in the condition, which loops forever.
- Using `=` (assignment) where `==` (comparison) is meant in a condition; Python reports a syntax error.

prompt: Write `is_prime(n)` for an integer `n` that returns `True` if `n` is prime and `False` otherwise. Integers below 2 are not prime. Use a loop with trial division by `2, 3, ...` up to the square root of `n`.
starter:
```python
def is_prime(n):
    pass
```
tests:
```python
assert is_prime(2) is True
assert is_prime(17) is True
assert is_prime(1) is False
assert is_prime(0) is False
assert is_prime(-7) is False
assert is_prime(25) is False
assert is_prime(49) is False
assert is_prime(97) is True
```
model:
```python
def is_prime(n):
    if n < 2:
        return False
    d = 2
    while d * d <= n:
        if n % d == 0:
            return False
        d += 1
    return True
```
hint: Handle `n < 2` first. Then look for any divisor `d` with `n % d == 0`.
hint: If `n` has a divisor larger than its square root, it also has one smaller, so it is enough to try `d` while `d * d <= n`.
solution: Return `False` as soon as a divisor is found; if the loop finishes with none, return `True`. The test `d * d <= n` includes the square root itself, which is needed for 25 and 49.

starter:
```python
def collatz_steps(n):
    pass
```
tests:
```python
assert collatz_steps(1) == 0
assert collatz_steps(2) == 1
assert collatz_steps(6) == 8
assert collatz_steps(7) == 16
assert collatz_steps(27) == 111
```
model:
```python
def collatz_steps(n):
    steps = 0
    while n != 1:
        if n % 2 == 0:
            n = n // 2
        else:
            n = 3 * n + 1
        steps += 1
    return steps
```
hint: You do not know in advance how many passes are needed, so use `while n != 1`.
solution: Keep a counter, apply the rule while `n` is not `1`, and add one per replacement. For `n = 1` the loop never runs and the answer is `0`.

starter:
```python
def count_divisors(n):
    pass
```
tests:
```python
assert count_divisors(1) == 1
assert count_divisors(12) == 6
assert count_divisors(13) == 2
assert count_divisors(36) == 9

```
model:
```python
def count_divisors(n):
    count = 0
    for d in range(1, n + 1):
        if n % d == 0:
            count += 1
    return count
```
hint: Try every candidate `d` from 1 to `n` and count those with `n % d == 0`.
hint: `range(1, n + 1)` includes `n` itself.
solution: Loop over `range(1, n + 1)` and add 1 to a counter whenever `d` divides `n`. For `n = 1` the loop tries only `d = 1`.
