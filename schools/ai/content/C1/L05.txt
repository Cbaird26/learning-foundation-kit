@article
### Tuples

A **tuple** is an immutable ordered sequence: `t = (3, "x", 2.5)`. You can index and slice it like a string, but not change it. A one-item tuple needs a trailing comma: `(5,)`. Tuples support **unpacking**, which is how functions return several values:

```python
def min_max(nums):
    return min(nums), max(nums)

lo, hi = min_max([4, 9, 2])   # lo is 2, hi is 9
a, b = b, a                   # swap: the right side is a tuple
```

### Lists

A **list** is a mutable ordered sequence: `xs = [4, 9, 2]`. It supports indexing and slicing like a string, plus changes in place:

| operation | effect | cost |
|---|---|---|
| `xs.append(v)` | add at the end | amortized $O(1)$ |
| `xs.insert(i, v)` | insert before position `i` | $O(n)$ |
| `xs.pop()` / `xs.pop(i)` | remove and return an item | $O(1)$ / $O(n)$ |
| `xs.remove(v)` | remove the first item equal to `v` | $O(n)$ |
| `xs.extend(ys)` | append all items of `ys` | $O(len(ys))$ |
| `xs.sort()` | sort in place, return `None` | $O(n \log n)$ |
| `sorted(xs)` | return a new sorted list | $O(n \log n)$ |

A frequent bug is `xs = xs.sort()`, which sets `xs` to `None`: the in-place methods `sort`, `append`, `reverse` and `extend` return `None`. A **list comprehension** builds a new list from a sequence: `[n * n for n in xs if n > 0]`.

### Objects, names and aliasing

A variable is a *name bound to an object*. Assignment copies the **binding**, not the object:

```python
a = [1, 2, 3]
b = a            # b is another name for the same list
b.append(4)
print(a)         # [1, 2, 3, 4]
```

`a` and `b` are **aliases**. `a is b` tests whether two names refer to the same object, while `a == b` tests whether the contents are equal. To get an independent (shallow) copy use `a[:]`, `a.copy()` or `list(a)`.

Mutation is visible through every alias, so the question to ask is always: *is this object mutable?* Numbers, strings and tuples are immutable: `s = s + "x"` builds a new string and rebinds `s`. Lists, dictionaries and most objects are mutable.

### Shallow versus deep copies

A shallow copy duplicates only the outer list; its items are the *same* objects. For nested lists this matters:

```python
grid = [[0] * 3] * 2       # BUG: two references to one row
grid[0][0] = 1             # [[1, 0, 0], [1, 0, 0]]
good = [[0] * 3 for _ in range(2)]   # two separate rows
```

`copy.deepcopy(x)` copies recursively. A tuple is immutable, but it may contain a mutable object: `t = (1, [2, 3])` and `t[1].append(4)` is allowed, because the tuple still holds the same list.

### Functions and mutation

Arguments are passed by binding the parameter name to the argument object, so a function that mutates a list parameter changes the caller's list. Decide whether a function **mutates** or **returns a new list**, and document it. Mutating functions conventionally return `None`.

Do not use a mutable default argument such as `def f(x, acc=[])`: the default list is created once and shared by all calls. Use `acc=None` and create the list inside.

@example
title: Aliasing through a function call
problem: What does this program print?

```python
def add_one(items):
    items.append(1)
    items = items + [99]
    return items

data = [5]
out = add_one(data)
print(data, out)
```
step: `data` is bound to the list `[5]`. The call binds the parameter `items` to the **same** list.
step: `items.append(1)` mutates that shared list, so it is now `[5, 1]`, and `data` sees the change.
step: `items = items + [99]` builds a **new** list `[5, 1, 99]` and rebinds only the local name `items`. The list that `data` refers to is not touched.
step: The function returns the new list, so `out` is `[5, 1, 99]`, while `data` is still `[5, 1]`.
answer: `[5, 1] [5, 1, 99]`

@example
title: Unpacking and slicing
problem: What are `first`, `rest` and `last` after the following statements?

```python
xs = [10, 20, 30, 40]
first, *rest = xs
last = xs[-1]
```
step: `first, *rest = xs` unpacks: `first` gets the first item and `*rest` collects the remaining items into a **new list**.
step: So `first` is `10` and `rest` is `[20, 30, 40]`.
step: `xs[-1]` is the last item, `40`. The list `xs` itself is unchanged.
answer: `first = 10`, `rest = [20, 30, 40]`, `last = 40`

@mistakes
- Writing `xs = xs.sort()` or `xs = xs.append(v)`, which rebinds `xs` to `None`.
- Using `[[0] * n] * m` to make a grid: every row is the same list object.
- Expecting `b = a` to copy a list; it creates an alias, so changes through `b` show up in `a`.
- Modifying a list while looping over it (removing items inside `for x in xs`), which skips elements; loop over a copy or build a new list.

```python
def reverse_in_place(items):
    i, j = 0, len(items) - 1
    while i < j:
        items[i], items[j] = items[j], items[i]
        i += 1
        j -= 1
```
hint: Swap the first and last items, then the second and second-to-last, and stop in the middle.
hint: Use two indexes `i` and `j` and loop while `i < j`; `items[i], items[j] = items[j], items[i]` swaps.
solution: Two indexes move toward each other, swapping the items they point at, until they meet. The function mutates the list and has no `return`, so it returns `None`.

prompt: Write `transpose(matrix)` that takes a non-empty rectangular list of rows (a list of lists, each row non-empty and the same length) and returns a **new** list of lists with rows and columns exchanged. For `[[1, 2, 3], [4, 5, 6]]` it returns `[[1, 4], [2, 5], [3, 6]]`. The input must not change.
starter:
```python
def transpose(matrix):
    pass
```
tests:
```python
m = [[1, 2, 3], [4, 5, 6]]
assert transpose(m) == [[1, 4], [2, 5], [3, 6]]
assert m == [[1, 2, 3], [4, 5, 6]]
assert transpose([[7]]) == [[7]]
assert transpose([[1, 2]]) == [[1], [2]]
assert transpose([[1], [2], [3]]) == [[1, 2, 3]]
t = transpose([[0, 0], [0, 0]])
t[0][0] = 9
assert t == [[9, 0], [0, 0]]
```
model:
```python
def transpose(matrix):
    rows = len(matrix)
    cols = len(matrix[0])
    result = []
    for c in range(cols):
        new_row = []
        for r in range(rows):
            new_row.append(matrix[r][c])
        result.append(new_row)
    return result
```
hint: The result has one row for every column of the input.
hint: For each column index `c`, build a new row from `matrix[r][c]` for every row index `r`. Create a fresh list for every row so the rows are not aliases.
solution: The outer loop runs over column indexes; the inner loop collects that column into a new list; each collected list becomes a row of the result. Creating `new_row` inside the outer loop keeps rows independent.

An empty list gives `[]`. `rotate_left([1, 2, 3, 4, 5], 2)` is `[3, 4, 5, 1, 2]`. The input must not change.
starter:
```python
def rotate_left(items, k):
    pass
```
tests:
```python
xs = [1, 2, 3, 4, 5]
assert rotate_left(xs, 2) == [3, 4, 5, 1, 2]
assert xs == [1, 2, 3, 4, 5]
assert rotate_left(xs, 0) == [1, 2, 3, 4, 5]

```
model:
```python
def rotate_left(items, k):
    if not items:
        return []
    k = k % len(items)
    return items[k:] + items[:k]
```
hint: Rotating by the length returns the original list, so reduce `k` modulo the length (but beware the empty list).
solution: After `k %= len(items)`, the rotated list is the tail `items[k:]` followed by the head `items[:k]`. Handle the empty list first, because `% 0` would raise `ZeroDivisionError`.
