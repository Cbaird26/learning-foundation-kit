@article
**Searching** finds an item in a collection; **sorting** puts items in order. Sorting is worth its cost because a sorted list can be searched far faster.

### Linear search

```python
def linear_search(xs, target):
    for i in range(len(xs)):
        if xs[i] == target:
            return i
    return -1
```

It works on any list, and takes $O(n)$ comparisons in the worst case (target last or missing).

### Binary search

If the list is **sorted**, compare the target with the middle item and discard half of the list each time:

```python
def binary_search(xs, target):
    lo, hi = 0, len(xs) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if xs[mid] == target:
            return mid
        if xs[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

The invariant is: *if the target is present, it lies in `xs[lo..hi]`*. Each pass halves the range, so at most $\lfloor \log_2 n \rfloor + 1$ items are examined: 20 for a million items. On an unsorted list the invariant is false and the search can miss an item that is present. The standard `bisect` module provides `bisect_left` and `bisect_right`, which find insertion points in sorted lists.

### Selection sort and insertion sort

**Selection sort** repeatedly finds the smallest remaining item and swaps it into place:

```python
def selection_sort(xs):
    for i in range(len(xs) - 1):
        m = i
        for j in range(i + 1, len(xs)):
            if xs[j] < xs[m]:
                m = j
        xs[i], xs[m] = xs[m], xs[i]
```

It always does $\frac{n(n-1)}{2}$ comparisons: $O(n^2)$ even if the list is sorted. **Insertion sort** grows a sorted prefix, inserting each next item into its place by shifting larger items right:

```python
def insertion_sort(xs):
    for i in range(1, len(xs)):
        key = xs[i]
        j = i - 1
        while j >= 0 and xs[j] > key:
            xs[j + 1] = xs[j]
            j -= 1
        xs[j + 1] = key
```

Its worst case is $O(n^2)$ (reverse-ordered input) but its best case is $O(n)$ (already sorted), and it is fast on nearly sorted data. Both sort **in place** (extra space $O(1)$).

### Merge sort

Merge sort is a divide-and-conquer algorithm: split the list in half, sort each half recursively, and **merge** the two sorted halves.

```python
def merge(a, b):
    result = []
    i = j = 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            result.append(a[i])
            i += 1
        else:
            result.append(b[j])
            j += 1
    return result + a[i:] + b[j:]

def merge_sort(xs):
    if len(xs) <= 1:
        return list(xs)
    mid = len(xs) // 2
    return merge(merge_sort(xs[:mid]), merge_sort(xs[mid:]))
```

Merging is linear in the total length. There are about $\log_2 n$ levels of recursion and each level does $O(n)$ work in total, so the running time is $O(n \log n)$ in every case, with $O(n)$ extra space. Any sorting algorithm that works only by comparing items needs $\Omega(n \log n)$ comparisons in the worst case, so merge sort is asymptotically optimal among them.

### Sorting in Python

Use the built-ins: `sorted(xs)` returns a new list, `xs.sort()` sorts in place and returns `None`. Both use Timsort, a hybrid of merge sort and insertion sort with $O(n \log n)$ worst case, $O(n)$ on already sorted data, and they are **stable**: items that compare equal keep their original order. The argument `key` is a function applied to each item to get its sort key, and `reverse=True` reverses the order:

```python
sorted(["bb", "a", "ccc"], key=len)        # ['a', 'bb', 'ccc']
sorted([3, 1, 2], reverse=True)            # [3, 2, 1]
sorted(["b", "A", "c"])                    # ['A', 'b', 'c'] (uppercase first)
```

Stability allows sorting by several criteria: sort by the secondary key first, then by the primary key.

@mistakes
- Running binary search on an unsorted list.
- Off-by-one errors in the loop condition and range updates: use `lo <= hi`, and `mid + 1` or `mid - 1` so that the range always shrinks.
- Writing `xs = xs.sort()`, which sets `xs` to `None`; use `xs.sort()` or `xs = sorted(xs)`.
- Assuming that a quadratic sort is fine for large inputs: for one million items, $n^2$ is about $10^{12}$ steps and $n \log n$ about $2 \times 10^7$.

@practice self
prompt: State the worst-case running time in big-O notation of each function below, in terms of `n = len(xs)` (or the value `n` for `f4`), and justify each answer in one sentence.

```python
def f1(xs):
    return xs[0] if xs else None

def f2(xs):
    total = 0
    for x in xs:
        total += x
    return total

def f3(xs):
    count = 0
    for a in xs:
        for b in xs:
            if a < b:
                count += 1
    return count

def f4(n):
    steps = 0
    while n > 1:
        n //= 2
        steps += 1
    return steps

def f5(xs):
    ys = sorted(xs)
    return ys[len(ys) // 2]
```
solution: `f1` is $O(1)$: one test and one index, whatever the length. `f2` is $O(n)$: one pass with constant work per item. `f3` is $O(n^2)$: the inner loop runs `n` times for each of the `n` outer passes. `f4` is $O(\log n)$: `n` is halved on every pass, so there are about $\log_2 n$ passes. `f5` is $O(n \log n)$: `sorted` costs $O(n \log n)$ and the index is $O(1)$, so the sort dominates (it also uses $O(n)$ extra space).
