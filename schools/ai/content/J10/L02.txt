@article
Long rows of bits are hard for people to read. `110010111010` is easy to mistype. Computers therefore group bits and people use a shorter notation.

### Bytes and nibbles

A group of **8 bits** is a **byte**. One byte has $2^8 = 256$ patterns, which stand for 0 to 255. Half a byte, 4 bits, is a **nibble**; it has 16 patterns, 0 to 15. File sizes are counted in bytes: a kilobyte (KB) is about a thousand bytes, a megabyte (MB) about a million.

### Hexadecimal

**Hexadecimal** (hex) is base 16. It needs 16 digits, so after 9 it uses letters:

| decimal | 10 | 11 | 12 | 13 | 14 | 15 |
|---|---|---|---|---|---|---|
| hex digit | A | B | C | D | E | F |

One hex digit stands for exactly one nibble, so **one byte is two hex digits**. To convert binary to hex, split the bits into groups of four from the right and convert each group:

`1011 1100` becomes `B` and `C`, so the byte is `BC`.

The first digit is worth 16 and the second 1, so `BC` is $11\times16 + 12 = 188$. Hex numbers are often written with a prefix such as `0x`: `0xBC`.

### Where you see hex

Web colours use three bytes (red, green, blue) written as six hex digits. `#FF8000` means red `FF` = 255 (full), green `80` = 128 (half) and blue `00` = 0 (none), which is orange. Each colour value therefore runs from 0 to 255, and the colour has 24 bits.

### Checking with Python

```python
print(hex(188))               # 0xbc
print(int("BC", 16))          # 188
print(f"{188:08b}")           # 10111100  (8 bits, padded with zeros)
print(f"{188:02X}")           # BC  (two hex digits, capital letters)
```

The `08b` in the f-string means "binary, at least 8 characters wide, padded with zeros". `02X` means "hex in capitals, at least 2 wide".

@example
title: Binary to hex and back
problem: Write the byte `11010110` in hexadecimal and in decimal.
step: Split into nibbles from the right: `1101` and `0110`.
step: `1101` is $8+4+1 = 13$, which is hex `D`. `0110` is $4+2 = 6$, which is hex `6`.
step: The byte is `D6` in hex.
step: In decimal it is $13\times16 + 6 = 214$.
answer: `D6` in hex and `214` in decimal

@example
title: Reading a colour
problem: What are the red, green and blue values of the colour `#1E90FF`?
step: Split the six digits into three bytes: `1E`, `90` and `FF`.
step: `1E` is $1\times16 + 14 = 30$.
step: `90` is $9\times16 + 0 = 144$.
step: `FF` is $15\times16 + 15 = 255$.
answer: red 30, green 144, blue 255

@mistakes
- Thinking `10` in hex means ten. Hex `10` is sixteen, because the first digit is worth 16.
- Splitting the bits into groups of four from the left instead of the right, which goes wrong when the number of bits is not a multiple of 4.
- Forgetting that `A` to `F` stand for 10 to 15, so `B7` is not "B and 7" but $11\times16 + 7$.
- Writing a byte with one hex digit. A full byte always has two (`0A`, not `A`).

def to_hex(n):
