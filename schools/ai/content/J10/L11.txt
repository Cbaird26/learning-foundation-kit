@article
Packets cross many routers owned by many people, so anyone along the way could read them. **Encryption** scrambles a message so that only the right person can read it.

### Ciphers and keys

The original message is the **plaintext**; the scrambled version is the **ciphertext**. A **cipher** is the method, and a **key** is the secret value that controls it. A very old example is the **Caesar cipher**: shift every letter along the alphabet by the key. With key 3, `A` becomes `D` and `HELLO` becomes `KHOOR`. Shifting back by 3 decrypts it.

```python
def caesar(text, shift):
    result = ""
    for ch in text:
        if "a" <= ch <= "z":
            result += chr((ord(ch) - 97 + shift) % 26 + 97)
        else:
            result += ch
    return result

print(caesar("hello", 3))    # khoor
print(caesar("khoor", -3))   # hello
```

The Caesar cipher is **not secure**: there are only 25 possible keys, so it can be undone by trying them all. Modern encryption uses keys that are hundreds of bits long, so trying every key is impossible in practice.

### Two kinds of modern encryption

In **symmetric encryption** the sender and receiver share the same secret key. It is fast, but how do two strangers agree on a key? **Public-key encryption** solves this: each person has a **public key** that anyone may know and a matching **private key** that stays secret. Anyone can lock a message with your public key, but only your private key can unlock it. **HTTPS** uses public-key methods to set up a connection and then fast symmetric encryption for the data; the padlock in the browser shows the connection is encrypted, not that the site is trustworthy.

### Passwords

Passwords prove who you are. Good habits:

- **Length beats cleverness.** A long passphrase, such as four or five random words joined together, is both strong and easier to remember than a short mix of symbols.
- **Use a different password for every site.** If one site leaks yours, attackers try it elsewhere.
- **Use a password manager** to remember them, and never share a password.
- **Turn on two-step verification** (also called multi-factor authentication), which asks for a second proof such as a code from your phone, so a stolen password alone is not enough.

Each extra character multiplies the number of possibilities: a 4-digit PIN has $10^4 = 10{,}000$ values, but 8 random lowercase letters have $26^8$, over 200 billion.

### How sites should store passwords

A well-built site never stores your password itself. It stores a **hash**: the output of a one-way function that is easy to compute but not practical to reverse. Equal inputs give equal hashes, so the site can check a login by hashing what you typed and comparing. Real sites also add a random **salt** and use a deliberately slow hashing method.

```python
import hashlib
print(hashlib.sha256(b"hello").hexdigest()[:8])   # 2cf24dba
```

@example
title: Encrypting with a Caesar cipher
problem: Encrypt `CAT` with a Caesar shift of 5 (capital letters, wrapping from Z back to A).
step: Letters have positions A = 0, B = 1, up to Z = 25.
step: `C` is 2, and $2 + 5 = 7$, which is `H`.
step: `A` is 0, giving 5, which is `F`. `T` is 19, giving 24, which is `Y`.
step: The ciphertext is `HFY`. To decrypt, shift back by 5.
answer: `HFY`

problem: Which is stronger, an 8-character password with lowercase letters only, or a passphrase of four random common words (about 20 characters)?
step: Compare the length: 8 characters against about 20.
step: Check how it was chosen: random words are not predictable, whereas short passwords often follow patterns.
step: The long, random passphrase is the stronger and easier one to remember.
answer: The passphrase of four random words.

@mistakes
- Believing a clever substitution cipher is secure. If there are few keys, or patterns remain, it can be broken.
- Thinking the padlock means a website is honest. It means the connection is encrypted; a scam site can have a padlock too.
- Reusing one password everywhere, which lets one leak open many accounts.
- Using personal details (names, birthdays, pet names) in passwords. They are easy to guess.

model:
```python
import hashlib


def fingerprint(text):
    digest = hashlib.sha256(text.encode()).hexdigest()
    return digest[:8]
```
hint: `hashlib` needs bytes, not a string.
hint: Use `hashlib.sha256(text.encode()).hexdigest()` to get the full hash and then take the first 8 characters with a slice.
solution: `text.encode()` turns the text into bytes, `sha256(...).hexdigest()` gives 64 hex characters, and `[:8]` keeps the first 8. The same input always gives the same hash, which is how a site can check a password without storing it.
