material: **photo_trip.py** (a toy picture of white `W` and blue `B` pixels, with the journey simulated in a few lines):

```python
from itertools import groupby

photo = [
    "WWWWBB",
    "WWWWBB",
    "WWBBBB",
    "BBBBBB",
]
COLORS = {"W": (255, 255, 255), "B": (0, 0, 255)}

pixels = sum(len(row) for row in photo)
print("pixels:", pixels, "raw bytes:", pixels * 3)


def rle(row):
    return "".join(str(len(list(g))) + k for k, g in groupby(row))


compressed = [rle(row) for row in photo]
print("compressed:", compressed)

message = "|".join(compressed)
packets = [(i // 8, message[i:i + 8]) for i in range(0, len(message), 8)]
print("packets:", packets)

received = "".join(piece for _, piece in sorted(reversed(packets)))
rows = received.split("|")


def unrle(code):
    out, num = "", ""
    for ch in code:
        if ch.isdigit():
            num += ch
        else:
            out += ch * int(num)
            num = ""
    return out


print("same photo:", [unrle(r) for r in rows] == photo)
print("first pixel:", COLORS[unrle(rows[0])[0]])
```

## Course review: how computers and the internet work

### Week by week

1. **Bits and binary.** A bit is 0 or 1. Binary place values are 1, 2, 4, 8, ... and $n$ bits give $2^n$ patterns (0 to $2^n - 1$).
2. **Hexadecimal and bytes.** A byte is 8 bits (0 to 255). One hex digit is 4 bits, so a byte is two hex digits; `A` to `F` are 10 to 15.
3. **Text, images and sound.** Characters have code points (ASCII, Unicode, UTF-8). An image is pixels of red, green and blue, and its raw size is width times height times 3 bytes. Sound is sampled at a sample rate.
4. **Compression.** Ratio is original over compressed. Lossless rebuilds the original (ZIP, PNG); lossy discards detail (JPEG, MP3). Run-length encoding writes count then symbol and can make patternless data longer.
5. **Logic gates.** NOT, AND, OR, XOR and NAND have truth tables; $n$ inputs give $2^n$ rows.
6. **Inside the computer.** CPU runs the fetch, decode, execute cycle; RAM is temporary working memory; storage keeps files. A half adder gives sum = XOR and carry = AND.
7. **Software.** The OS schedules processes, manages memory, files and devices. A program is a file; a process is a running program.
8. **Files.** Files are named byte sequences held in blocks, with formats and extensions. Opening a file loads it into RAM and a program decodes it.
9. **Packets and IP.** Messages are cut into numbered packets; routers forward them by IP address; TCP reorders and resends.
10. **The web.** URL, DNS (name to IP address), HTTP request and response with status codes, browser rendering.
11. **Encryption and passwords.** Plaintext, ciphertext and keys; public-key encryption; HTTPS; long, unique passphrases, a password manager, two-step verification; sites store hashes.
12. **Safety and society.** Phishing signs, reading the real domain, digital footprint, bias and the digital divide.

### Self-check

- I can work out the raw size of an image and the number of packets for a file.
- I can encode and decode run-length text and say when it fails.
- I can write the truth tables of the basic gates and the half adder.

- I can explain strong passwords and spot phishing.

### Common errors

- Reading binary remainders in the wrong order, or giving 256 as the largest 8-bit number.
- Forgetting the factor of 3 for colour, or rounding down when counting blocks and packets.
- Merging separate runs in run-length encoding.
- Mixing up OR and XOR, or sum and carry.
- Mixing up RAM and storage, or program and process.
- Calling the web and the internet the same thing, or judging a link by its first words.

For example `send_row("aaabcc", 3)` compresses to `"3a1b2c"` and returns `[(0, "3a1"), (1, "b2c")]`. An empty row gives an empty list. You may assume the row has no digits.

tests:
```python
assert send_row("aaabcc", 3) == [(0, "3a1"), (1, "b2c")]
assert send_row("WWWWBB", 4) == [(0, "4W2B")]
assert send_row("", 3) == []
assert send_row("a" * 12, 2) == [(0, "12"), (1, "a")]
assert send_row("abc", 4) == [(0, "1a1b"), (1, "1c")]
```
model:
```python
def send_row(row, size):
    code = ""
    i = 0
    while i < len(row):
        j = i
        while j < len(row) and row[j] == row[i]:
            j += 1
        code += str(j - i) + row[i]
        i = j
    packets = []
    for start in range(0, len(code), size):
        packets.append((start // size, code[start:start + size]))
    return packets
```
hint: Do the two jobs separately: first build the compressed string, then cut it up.
hint: Compress by finding each run of equal neighbours and writing its length and character. Then use `range(0, len(code), size)` and slices to make numbered packets.
solution: Build the run-length code by moving `j` to the end of each run, then slice that code into pieces of `size`, numbering each by `start // size`. Packets are cut from the compressed text, not from the original row, which the last test checks: `"abc"` compresses to the longer `"1a1b1c"`.

@exam num
prompt: A photo is 1000 pixels wide and 800 pixels tall, with 3 bytes per pixel and no compression. It is sent in packets that each carry at most 1500 bytes of payload. How many packets are needed?
answer: 1600
check: ceil(1000 * 800 * 3 / 1500)
hint: First work out the size of the photo in bytes: pixels times 3.
hint: Divide the size by 1500 and round up.
solution: The photo has $1000 \times 800 = 800000$ pixels, so $800000 \times 3 = 2400000$ bytes. Then $2400000 \div 1500 = 1600$ exactly, so 1600 packets are needed.
