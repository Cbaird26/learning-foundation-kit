@article
Last week's initialization keeps activations well scaled at the start, but nothing guarantees they stay that way: as the weights of early layers change, the distribution of inputs to later layers drifts, and training with large learning rates becomes fragile. **Normalization layers** insert a step that re-centers and rescales activations, so that every layer sees inputs of a controlled size throughout training. Two variants dominate.

### Batch normalization

**Batch normalization** (Ioffe and Szegedy, 2015) normalizes each feature using statistics computed across the examples of the current mini-batch. For a batch of $B$ examples with feature $j$ taking values $x_{1j}, \dots, x_{Bj}$:

$$\mu_j = \frac{1}{B}\sum_{i=1}^{B} x_{ij}, \qquad \sigma_j^2 = \frac{1}{B}\sum_{i=1}^{B} (x_{ij} - \mu_j)^2, \qquad \hat{x}_{ij} = \frac{x_{ij} - \mu_j}{\sqrt{\sigma_j^2 + \varepsilon}}, \qquad y_{ij} = \gamma_j \hat{x}_{ij} + \beta_j.$$

The small constant $\varepsilon$ (such as $10^{-5}$) avoids division by zero. Every feature of $\hat{x}$ has mean 0 and variance about 1 over the batch. The **learnable** scale $\gamma_j$ and shift $\beta_j$ let the network undo the normalization if that is best, so the layer can still represent any mean and variance. Take three examples with three features, written as rows:

$$\mathbf{X} = \begin{pmatrix} 1 & 2 & 6 \\ 2 & 4 & 0 \\ 3 & 0 & 3 \end{pmatrix}.$$

Column 1 is $(1, 2, 3)$ with $\mu = 2$ and $\sigma^2 = 2/3$, so $\hat{x} \approx (-1.2247, 0, 1.2247)$. Column 2 is $(2, 4, 0)$ with $\mu = 2$ and $\sigma^2 = 8/3$, giving $(0, 1.2247, -1.2247)$. Column 3 is $(6, 0, 3)$ with $\mu = 3$ and $\sigma^2 = 6$, giving $(1.2247, -1.2247, 0)$.

**Inference.** At test time a prediction should not depend on the other examples in the batch (a single example has no batch). So training maintains **running averages** of the batch means and variances, for instance $\bar{\mu} \leftarrow m\,\bar{\mu} + (1 - m)\,\mu_{\text{batch}}$ with $m$ near 0.9 to 0.99, and inference uses the fixed $\bar{\mu}, \bar{\sigma}^2$ in place of the batch statistics. This train-versus-inference difference is a classic source of bugs (frameworks switch with `model.train()` and `model.eval()`). Batch normalization also couples the examples in a batch, which makes very small batches problematic: with $B = 1$ the variance is 0 and every output equals $\beta$.

### Layer normalization

**Layer normalization** (Ba, Kiros and Hinton, 2016) normalizes each *example* across its own features, so it uses no batch statistics at all:

$$\mu_i = \frac{1}{d}\sum_{j=1}^{d} x_{ij}, \qquad \sigma_i^2 = \frac{1}{d}\sum_{j=1}^{d}(x_{ij} - \mu_i)^2, \qquad y_{ij} = \gamma_j\,\frac{x_{ij} - \mu_i}{\sqrt{\sigma_i^2 + \varepsilon}} + \beta_j.$$

For the first row of $\mathbf{X}$, $(1, 2, 6)$, we get $\mu = 3$ and $\sigma^2 = 14/3 = 4.667$, so the normalized row is $(-0.9258, -0.4629, 1.3887)$; the second row $(2, 4, 0)$ gives $(0, 1.2247, -1.2247)$. Because the computation is per example, layer normalization behaves identically in training and inference, works with a batch size of one, and suits sequence models; it is the normalization used in transformers (C19 onward).

| | batch norm | layer norm |
|---|---|---|
| statistics over | the batch, per feature | the features, per example |
| depends on other examples | yes | no |
| training vs inference | differ (running averages) | same |
| typical use | convolutional networks | transformers, recurrent networks |

### Why it helps

Normalization keeps pre-activations in a range where activation functions are not saturated, makes the loss less sensitive to the scale of the weights in the layer before it, and typically allows larger learning rates. The original motivation was reducing "internal covariate shift", the change in layer input distributions during training; later work argues that its benefit comes mostly from smoothing the loss landscape or from other effects, and the explanation is still debated. What is not in dispute is that it makes many deep networks much easier to train.

### In code

```python
import math

def layer_norm(x, gamma, beta, eps=1e-5):
    d = len(x)
    mu = sum(x) / d
    var = sum((v - mu) ** 2 for v in x) / d
    return [g * (v - mu) / math.sqrt(var + eps) + b
            for v, g, b in zip(x, gamma, beta)]

row = layer_norm([1.0, 2.0, 6.0], [1.0] * 3, [0.0] * 3)
print([round(v, 4) for v in row])
```

This prints `[-0.9258, -0.4629, 1.3887]`. PyTorch provides `torch.nn.BatchNorm1d` and `torch.nn.LayerNorm`, which also keep $\gamma$ and $\beta$ as learnable parameters.

title: Batch norm of one feature, with a scale and shift
problem: A feature takes the values $(2, 4, 6, 8)$ in a batch of four. Compute the batch-normalized values with $\varepsilon = 0$, and then the outputs for $\gamma = 3$, $\beta = 1$.
step: Mean: $\mu = 20/4 = 5$.
step: Variance: $\sigma^2 = (9 + 1 + 1 + 9)/4 = 5$, so $\sigma = 2.2361$.
step: Normalized values: $(-3, -1, 1, 3)/2.2361 = (-1.3416, -0.4472, 0.4472, 1.3416)$.
step: Scale and shift: $y = 3\hat{x} + 1 = (-3.0249, -0.3416, 2.3416, 5.0249)$.
answer: $\hat{x} = (-1.342, -0.447, 0.447, 1.342)$ and $y = (-3.025, -0.342, 2.342, 5.025)$.

@example
title: Layer norm and scale invariance
problem: Show that layer normalization of the vector $(2, 4, 6)$ and of $(20, 40, 60)$ give the same result when $\varepsilon = 0$, $\gamma = 1$, $\beta = 0$.
step: For $(2, 4, 6)$: $\mu = 4$, $\sigma^2 = (4 + 0 + 4)/3 = 8/3$, so the normalized vector is $(-2, 0, 2)/1.633 = (-1.2247, 0, 1.2247)$.
step: For $(20, 40, 60)$: $\mu = 40$, $\sigma^2 = (400 + 0 + 400)/3 = 800/3$, so $\sigma = 16.33$ and the vector is $(-20, 0, 20)/16.33 = (-1.2247, 0, 1.2247)$.
step: Multiplying the input by a constant multiplies both the centered values and $\sigma$ by that constant, which cancels.
answer: Both give $(-1.2247, 0, 1.2247)$: normalization removes the scale of its input.

@mistakes
- Using batch statistics at inference: a prediction then depends on which other examples are in the batch (and breaks for a batch of one). Use the running averages.
- Normalizing over the wrong axis: batch norm averages over the examples for each feature (down a column of a data matrix with one example per row), and layer norm averages over the features of each example (along a row).
- Leaving out $\varepsilon$, which gives a division by zero for a constant feature (or a one-example batch).
- Thinking $\gamma$ and $\beta$ are hyperparameters: they are learned parameters, updated by backpropagation like any weight.

model:
```python
import math

def batch_norm(X, gamma, beta, eps):
    """Batch normalization over the rows of X, one statistic per column."""
    n = len(X)
    d = len(X[0])
    means = [sum(row[j] for row in X) / n for j in range(d)]
    variances = [sum((row[j] - means[j]) ** 2 for row in X) / n for j in range(d)]
    return [[gamma[j] * (row[j] - means[j]) / math.sqrt(variances[j] + eps)
             + beta[j] for j in range(d)] for row in X]
```
hint: First compute the list of column means, then the list of column variances (dividing by the number of rows), then build each output row entry by entry.
solution: The statistics are per column and shared by all rows, which is what makes the examples in a batch depend on each other. The last test checks that every normalized column has mean 0 and variance 1; a version that divides by $n - 1$ or normalizes along rows fails it.

model:
```python
import math

def update_running(running, batch_stat, m):
    """Exponential moving average of a batch statistic, elementwise."""
    return [m * r + (1 - m) * b for r, b in zip(running, batch_stat)]

def bn_inference(x, mean, var, gamma, beta, eps):
    """Batch normalization of one example using stored statistics."""
    return [g * (v - mu) / math.sqrt(s + eps) + b
            for v, mu, s, g, b in zip(x, mean, var, gamma, beta)]
```
hint: Both are one list comprehension over `zip`; the running average puts weight `m` on the old value and `1 - m` on the new batch statistic.
solution: The moving average forgets old batches at rate $1 - m$, and inference then reuses the stored statistics instead of computing new ones, so one example is enough. The last test uses `eps = 1`: $(5 - 1)/\sqrt{3 + 1} = 2$.

@quiz self
prompt: Explain two reasons why a model that trains well with batch normalization at batch size 64 may behave badly at batch size 1 during training, and explain how layer normalization avoids both problems. Also say what you must do for batch normalization at test time.
hint: Think about what the batch variance is for a single example, and what the statistics depend on.
solution: First, the batch statistics of a batch of one example are degenerate: the variance over the batch is 0 and the normalized value is 0 for every feature, so the output is just $\beta$ and carries no information about the input. Second, even for small batches greater than one, the mean and variance are noisy estimates, so the outputs of an example depend strongly on which other examples happened to share its batch, which adds noise and creates a mismatch with the running averages used later. Layer normalization uses the features of each example only, so its output does not depend on the batch size or on the other examples, and it behaves identically in training and at test time. For batch normalization at test time, use the running averages of the mean and variance accumulated during training (switch the layer to evaluation mode) rather than the statistics of the test batch.
