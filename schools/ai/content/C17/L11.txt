@article
You can make a network deeper by stacking more layers, but a surprising thing happened when researchers tried it: beyond a certain depth, plain stacks got *worse*, and not only on test data. Their training error was higher than that of a shallower network, even though the deeper network could in principle imitate the shallow one by learning identity layers. Optimization, not capacity, was the problem. **Residual networks** (He and colleagues, 2015) fixed it with one small change.

### The residual block

A plain block computes $\mathbf{y} = F(\mathbf{x})$. A **residual block** adds its input back:

$$\mathbf{y} = \mathbf{x} + F(\mathbf{x}),$$

where $F$ is a small network (for example a linear layer followed by ReLU, or two such layers). The extra path from $\mathbf{x}$ to $\mathbf{y}$ is the **shortcut** or **skip connection**. The block only has to learn a *correction* $F$, and if $F \approx 0$ the block is the identity, which is easy to represent: set the weights of $F$'s last layer to zero. For a block with $F(\mathbf{x}) = \operatorname{ReLU}(\mathbf{W}\mathbf{x} + \mathbf{b})$ and $\mathbf{x} = (2, -1)$, $\mathbf{W} = \begin{pmatrix} 1 & -1 \\ -1 & 0.5 \end{pmatrix}$, $\mathbf{b} = (-1, 1)$: $\mathbf{W}\mathbf{x} + \mathbf{b} = (2, -1.5)$, so $F = (2, 0)$ and $\mathbf{y} = (4, -1)$. The addition requires $F(\mathbf{x})$ and $\mathbf{x}$ to have the same shape; when a block changes the width, the shortcut uses a learned linear projection $\mathbf{W}_s \mathbf{x}$ instead.

### Why gradients survive

Differentiate $\mathbf{y} = \mathbf{x} + F(\mathbf{x})$. The Jacobian is

$$\frac{\partial \mathbf{y}}{\partial \mathbf{x}} = \mathbf{I} + \frac{\partial F}{\partial \mathbf{x}}.$$

Backpropagating through the block multiplies the upstream gradient by this matrix, so the upstream gradient arrives at $\mathbf{x}$ *unchanged* plus whatever flows through $F$. Compare a scalar chain of $L$ blocks whose layer function has derivative $f'$ at every layer. A plain stack multiplies the gradient by $f'$ per layer, giving $(f')^L$; a residual stack multiplies by $1 + f'$, giving $(1 + f')^L$. With $f' = 0.1$:

| depth $L$ | plain $(f')^L$ | residual $(1+f')^L$ |
|---|---|---|
| 5 | $10^{-5}$ | 1.6105 |
| 10 | $10^{-10}$ | 2.5937 |
| 20 | $10^{-20}$ | 6.7275 |

The plain stack's gradient vanishes; the residual stack's does not, because of the identity term. Expanding the product of $L$ blocks $\prod_l (\mathbf{I} + \mathbf{J}_l)$ gives a sum over all subsets of blocks that the gradient passes *through*, including the empty subset: a path that skips every block and carries the gradient directly from the output to the input. That is why very deep residual networks (hundreds of layers) train. The same factor can also exceed 1 and compound if the $f'$ are large, which is why normalization layers (Week 9) and careful scaling of the last layer in each block are used together with skip connections.

### Where residual connections appear

Convolutional residual networks place two convolutions inside $F$, with batch normalization. Transformers wrap both the attention sub-layer and the feed-forward sub-layer in residual connections together with layer normalization: the model's "residual stream" is the running sum of all blocks' outputs. A residual connection is also what makes it reasonable to initialize a deep model so that it starts as nearly the identity.

### In code

```python
def residual_block(x, W, b):
    f = [max(0.0, sum(w * v for w, v in zip(row, x)) + c)
         for row, c in zip(W, b)]
    return [xi + fi for xi, fi in zip(x, f)]

y = residual_block([2.0, -1.0], [[1.0, -1.0], [-1.0, 0.5]], [-1.0, 1.0])
print(y)

g_plain = g_res = 1.0
for _ in range(10):
    g_plain *= 0.1
    g_res *= 1 + 0.1
print(g_plain, round(g_res, 4))
```

The first print shows `[4.0, -1.0]`; the second shows about `1e-10` and `2.5937`. In PyTorch a residual block is a module whose `forward` returns `x + self.f(x)`.

@example
title: A block that starts as the identity
problem: A residual block has $F(\mathbf{x}) = \mathbf{W}\mathbf{x}$ with $\mathbf{W} = \mathbf{0}$. What are its output and its Jacobian, and why is this a good starting point for a deep stack?
step: Output: $\mathbf{y} = \mathbf{x} + \mathbf{0}\mathbf{x} = \mathbf{x}$.
step: Jacobian: $\mathbf{I} + \mathbf{W} = \mathbf{I}$.
step: A stack of such blocks computes the identity and passes gradients through unchanged, so the whole network starts in a well-behaved state, and each block learns a small correction away from it.
answer: The block is the identity with Jacobian $\mathbf{I}$; the stack starts neither amplifying nor shrinking signals or gradients.

@mistakes
- Adding tensors of different shapes: the skip connection needs $F(\mathbf{x})$ and $\mathbf{x}$ to have the same dimension, or a projection on the shortcut.
- Thinking the shortcut has parameters to learn: an identity shortcut has none; only a projection shortcut (used to change width) does.
- Putting the activation after the addition when the design calls for it before (or the reverse) without considering the effect: where the nonlinearity and the normalization sit relative to the addition changes how well the identity path carries signals.
- Saying residual connections "solve" vanishing gradients entirely: they give gradients a short path, but the layers inside $F$ still need good initialization and scale control.

model:
```python
def residual_block2(x, W1, b1, W2, b2):
    """Residual block y = x + W2 ReLU(W1 x + b1) + b2."""
    h = [max(0.0, sum(w * v for w, v in zip(row, x)) + c)
         for row, c in zip(W1, b1)]
    f = [sum(w * v for w, v in zip(row, h)) + c for row, c in zip(W2, b2)]
    return [xi + fi for xi, fi in zip(x, f)]
```
hint: Compute the hidden list `h` with the ReLU first, then the branch output `f` from `h` with the second layer (and its bias, but no ReLU), and add `f` to `x` entry by entry.
solution: The ReLU is applied only to the hidden layer, the second layer is linear with its own bias, and the original `x` is added at the end. The first test has an inactive hidden unit but a nonzero output bias, which a solution that drops `b2` gets wrong; the second has a negative branch output, which a solution that applies a ReLU after the second layer gets wrong.

model:
```python
def chain_grad(fprimes, residual):
    """Gradient through a chain of layers, plain or residual."""
    g = 1.0
    for fp in fprimes:
        g *= (1.0 + fp) if residual else fp
    return g
```
hint: Start from 1.0 and multiply by `1 + fp` (residual) or `fp` (plain) for each layer.
solution: A residual layer's local derivative is $1 + f'$, a plain layer's is $f'$. The last test shows that a layer with $f' = -1$ can cancel the identity path exactly, so residual connections help but do not guarantee that gradients survive for every $F$.

@quiz self
prompt: A colleague claims that residual connections work "because they make the network deeper without adding parameters". Explain what is right and wrong with this, and give the correct reason using the Jacobian of a block. Also say why zeroing the last layer's weights in each block is a sensible initialization.
hint: Skip connections add no parameters (an identity shortcut), but that is not why they help; think about $\mathbf{I} + \partial F/\partial \mathbf{x}$ and about what the block computes when $F = 0$.
solution: It is true that an identity shortcut adds no parameters and nothing to learn, but that is not the reason residual networks train better: a plain network of the same depth has the same number of parameters in $F$. The reason is the optimization benefit of the identity path: the block's Jacobian is $\mathbf{I} + \partial F/\partial\mathbf{x}$, so backpropagation passes the upstream gradient through the block unchanged and adds the contribution through $F$. Over $L$ blocks the gradient therefore has a direct path from the output to every block, whereas a plain stack's gradient is a product of $L$ factors that can shrink or blow up geometrically. Zeroing the weights of the last layer in $F$ makes $F = 0$, so each block is the identity at the start, with Jacobian $\mathbf{I}$; the whole deep stack begins as a well-behaved function and each block learns a small correction.
