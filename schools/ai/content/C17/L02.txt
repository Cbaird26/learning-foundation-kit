@article
A network predicts a probability of 0.018 that an image is a cat, and it is a cat. How wrong is that, and how hard should the weights be pushed? A **loss function** turns "how wrong" into one number that training can reduce. Which loss we choose decides both the number and the size of the push.

### Squared error for regression

For a real-valued target $y$ and prediction $\hat{y}$, the squared error is $\ell(\hat{y}, y) = (\hat{y} - y)^2$, and the **mean squared error** over $n$ examples is $L = \frac{1}{n}\sum_i (\hat{y}_i - y_i)^2$. Its derivative with respect to the prediction is $\partial \ell / \partial \hat{y} = 2(\hat{y} - y)$. Minimizing it estimates the conditional mean of $y$ (Week 5 of C12 derived this for linear models), and it is the right loss when the noise in $y$ is roughly Gaussian.

### Cross-entropy for classification

For classification we want the network to output probabilities. For two classes, a sigmoid output $p = \sigma(z)$ is read as $P(y = 1 \mid \mathbf{x})$, and the **binary cross-entropy** (negative log-likelihood of the label) is

$$\ell(p, y) = -\,y \log p - (1 - y)\log(1 - p).$$

For $y = 1$ this is $-\log p$: the loss is 0 at $p = 1$ and grows without bound as $p \to 0$. With $p = 0.8$ and $y = 1$, the loss is $-\log 0.8 \approx 0.2231$ nats.

For $K$ classes the network produces $K$ real numbers $\mathbf{z}$, the **logits**, and the **softmax** turns them into a probability vector:

$$p_k = \operatorname{softmax}(\mathbf{z})_k = \frac{e^{z_k}}{\sum_j e^{z_j}}.$$

For the logits $(2, 1, 0.1)$ the softmax is $(0.6590, 0.2424, 0.0986)$, which sums to 1. With a one-hot label $\mathbf{y}$ (a 1 at the true class $c$), the **softmax cross-entropy** is

$$\ell(\mathbf{z}, \mathbf{y}) = -\sum_k y_k \log p_k = -\log p_c .$$

If class 0 is true, the loss is $-\log 0.6590 \approx 0.4170$. Minimizing it over a data set is maximum likelihood estimation of a categorical model.

### The gradient is $\mathbf{p} - \mathbf{y}$

Differentiate $\ell = -z_c + \log\sum_j e^{z_j}$ with respect to $z_k$. The first term gives $-1$ if $k = c$ and 0 otherwise, which is $-y_k$; the second gives $e^{z_k}/\sum_j e^{z_j} = p_k$. So

$$\frac{\partial \ell}{\partial z_k} = p_k - y_k .$$

For logits $(0.5, -0.5, 1.5)$ and true class 2 the softmax is $(0.2447, 0.0900, 0.6652)$ and the gradient is $(0.2447, 0.0900, -0.3348)$. The gradient pushes down the logits of wrong classes in proportion to their probability and pushes up the true class's logit by the missing probability. The same result holds for the sigmoid with binary cross-entropy: $\partial \ell/\partial z = p - y$.

### Why not squared error for classification?

Take a sigmoid output with $z = -4$ and label $y = 1$, so $p = 0.0180$, a confident mistake. With cross-entropy, $\partial \ell/\partial z = p - y = -0.982$, a large corrective push. With squared error $(p - y)^2$, the chain rule gives $2(p - y)\,p(1 - p) = -0.0347$: the factor $p(1-p)$ is the sigmoid's slope, which is nearly zero when the unit is saturated, so the more wrong the network is, the less it learns. The logarithm in cross-entropy exactly cancels that factor. This is why cross-entropy is the standard loss for classification.

### Computing it stably

Computing $e^{z}$ overflows for large logits (`math.exp(1000)` raises an error). Subtracting $m = \max_j z_j$ from every logit leaves the softmax unchanged, because the factor $e^{-m}$ cancels, and keeps every exponent at most 0. Cross-entropy is then $\log\sum_j e^{z_j} - z_c$ with the **log-sum-exp** computed as $m + \log\sum_j e^{z_j - m}$.

```python
import math

def softmax(z):
    m = max(z)
    e = [math.exp(v - m) for v in z]
    s = sum(e)
    return [v / s for v in e]

def cross_entropy(z, c):
    return -math.log(softmax(z)[c])

p = softmax([0.5, -0.5, 1.5])
grad = [pk - (1 if k == 2 else 0) for k, pk in enumerate(p)]
print([round(v, 4) for v in grad], round(cross_entropy([0.5, -0.5, 1.5], 2), 4))
```

This prints `[0.2447, 0.09, -0.3348] 0.4076`. Frameworks provide the fused, stable version as a single function (`torch.nn.functional.cross_entropy` takes logits and class indices).

@example
title: Mean squared error and binary cross-entropy on three examples
problem: A network predicts $(2.5, 0, 2)$ for targets $(3, -0.5, 2)$. Separately, a sigmoid classifier outputs $p = (0.9, 0.2, 0.6)$ for labels $(1, 0, 1)$. Compute the mean squared error of the first and the mean binary cross-entropy of the second.
step: Squared errors: $(-0.5)^2 = 0.25$, $0.5^2 = 0.25$, $0^2 = 0$, so $\text{MSE} = 0.5/3 \approx 0.1667$.
step: Per-example cross-entropy: $-\log 0.9 = 0.1054$; for $y = 0$ the loss is $-\log(1 - 0.2) = 0.2231$; and $-\log 0.6 = 0.5108$.
step: The mean is $(0.1054 + 0.2231 + 0.5108)/3 \approx 0.2798$.
answer: MSE $\approx 0.1667$; mean cross-entropy $\approx 0.2798$ nats.

@mistakes
- Applying softmax and then feeding the probabilities to a loss that expects logits (or applying softmax twice): frameworks' cross-entropy functions take raw logits.
- Using $\log_2$ in one place and the natural logarithm in another: in this course $\log$ is natural, so the loss is in nats, and a value in bits differs by a factor $\ln 2$.
- Writing the binary cross-entropy for $y = 0$ as $-\log p$; for a negative example the loss is $-\log(1 - p)$.
- Computing softmax without subtracting the maximum logit, which overflows for logits in the hundreds.

```python
import math

def softmax(z):
    """Numerically stable softmax: subtract the maximum logit first."""
    m = max(z)
    e = [math.exp(v - m) for v in z]
    s = sum(e)
    return [v / s for v in e]
```
hint: Subtract the largest logit from every logit before exponentiating, then divide each exponential by their sum.
solution: Subtracting the maximum changes no probability, because it multiplies numerator and denominator by the same factor, but it keeps every exponent at most 0 so `math.exp` cannot overflow. The shift-invariance test compares logits that differ by a constant 100.

model:
```python
import math

def ce_loss_and_grad(z, c):
    """Softmax cross-entropy loss and its gradient p - y with respect to z."""
    m = max(z)
    e = [math.exp(v - m) for v in z]
    s = sum(e)
    p = [v / s for v in e]
    loss = -math.log(p[c])
    grad = [pk - (1.0 if k == c else 0.0) for k, pk in enumerate(p)]
    return loss, grad
```
hint: Compute the stable softmax $\mathbf{p}$; the loss is $-\log p_c$ and the gradient is $\mathbf{p}$ with 1 subtracted from entry $c$.
solution: The loss only involves the true class's probability, and the gradient is the probability vector minus the one-hot label. The gradient of any example sums to 0, which the last test checks, because the probabilities sum to 1 and the label sums to 1.

model:
```python
import math

def mean_ce(logits_list, labels):
    """Average stable softmax cross-entropy over a batch."""
    total = 0.0
    for z, c in zip(logits_list, labels):
        m = max(z)
        lse = m + math.log(sum(math.exp(v - m) for v in z))
        total += lse - z[c]
    return total / len(labels)
```
hint: For each example the loss is $\log\sum_j e^{z_j} - z_c$; compute the log-sum-exp after subtracting the maximum, then average.
solution: Using $\ell = \text{logsumexp}(\mathbf{z}) - z_c$ avoids forming probabilities and stays stable for large logits. The last test would overflow in a naive implementation.
