@article
A network's loss can be a function of millions of numbers, yet we need its derivative with respect to every one of them, quickly and without algebra errors. The trick is that every function we build is a long chain of tiny operations (add, multiply, exponentiate), and each tiny operation has a derivative we know. The **chain rule** glues those small derivatives together. A **computational graph** is the bookkeeping that makes the gluing mechanical.

### Computations as graphs

Take the loss of a one-weight linear model on one example: $L = (w x + b - t)^2$. Break it into steps, each one operation:

$$a = w x, \qquad z = a + b, \qquad e = z - t, \qquad L = e^2 .$$

The graph has a node for every quantity (the inputs $w, x, b, t$ and the intermediate values $a, z, e, L$) and an edge from each operation's inputs to its output. With $w = 2$, $x = 3$, $b = 1$, $t = 5$ the **forward pass** evaluates the nodes in order: $a = 6$, $z = 7$, $e = 2$, $L = 4$.

### The chain rule, backward

If $L$ depends on $u$ only through $v = g(u)$, the chain rule says
$$\frac{\partial L}{\partial u} = \frac{\partial L}{\partial v}\,\frac{\partial v}{\partial u}.$$
The **backward pass** walks the graph from the output to the inputs. At each node it already knows $\partial L/\partial(\text{node})$, the **upstream gradient**, and multiplies by the node's **local derivative** to get the gradient for each of its inputs. For the graph above:

| node | local rule | $\partial L/\partial \text{node}$ |
|---|---|---|
| $L = e^2$ | start | $1$ |
| $e$ | $\times\, 2e = 4$ | $4$ |
| $z$ (from $e = z - t$) | $\times\, 1$ | $4$ |
| $b$ and $a$ | $z = a + b$, local derivative 1 each | $4$ and $4$ |
| $w$ | $a = wx$, local derivative $x = 3$ | $12$ |
| $x$ | local derivative $w = 2$ | $8$ |

So $\partial L/\partial w = 12$. The rules for the common operations are: for a sum, the gradient is copied to both inputs; for a product $c = uv$, the gradient to $u$ is $v$ times the upstream gradient and to $v$ it is $u$ times it; for $c = f(u)$, multiply by $f'(u)$.

### Nodes used more than once

When a value feeds several operations, $L$ depends on it along several paths, and the **multivariable chain rule** says to add the contributions. For $y = x \cdot x + 3x$ at $x = 2$, the node $x$ is used three times (twice in the product, once in $3x$): the product gives $x + x = 4$ and the other term gives 3, so $dy/dx = 7$, which matches $2x + 3$. In code this is why gradients are *accumulated* with `+=`, never assigned with `=`.

### Finite differences as a check

The **central finite difference** estimates a derivative by evaluating the function on both sides of the point:

$$\frac{\partial f}{\partial x_i} \approx \frac{f(\mathbf{x} + \epsilon\,\mathbf{e}_i) - f(\mathbf{x} - \epsilon\,\mathbf{e}_i)}{2\epsilon},$$

where $\mathbf{e}_i$ is the unit vector along coordinate $i$. Its error shrinks like $\epsilon^2$ (the one-sided version's error shrinks only like $\epsilon$), but too small an $\epsilon$ loses digits to rounding. A typical choice is $\epsilon = 10^{-5}$ in double precision. Finite differences are too slow for training (two function evaluations per parameter) but are the standard **gradient check** for a hand-written backward pass.

### In code

```python
import math

def sigmoid(z):
    return 1 / (1 + math.exp(-z))

def forward_backward(w, b, x, t):
    z = w * x + b
    a = sigmoid(z)
    loss = (a - t) ** 2
    dz = 2 * (a - t) * a * (1 - a)
    return loss, dz * x, dz

loss, dw, db = forward_backward(0.5, -0.25, 2.0, 1.0)
eps = 1e-5
num = (forward_backward(0.5 + eps, -0.25, 2.0, 1.0)[0]
       - forward_backward(0.5 - eps, -0.25, 2.0, 1.0)[0]) / (2 * eps)
print(round(loss, 4), round(dw, 4), round(num, 4))
```

This prints `0.1029 -0.2796 -0.2796`. PyTorch does exactly this bookkeeping for you with `loss.backward()`; next week we build that machinery ourselves.

@example
title: Backward through a sigmoid neuron
problem: A neuron computes $z = wx + b$, $a = \sigma(z)$ and the loss $L = (a - t)^2$. For $w = 0.5$, $x = 2$, $b = -0.25$, $t = 1$, compute $\partial L/\partial w$ and $\partial L/\partial b$.
step: Forward: $z = 0.5 \cdot 2 - 0.25 = 0.75$, $a = \sigma(0.75) \approx 0.6792$, $L = (0.6792 - 1)^2 \approx 0.1029$.
step: Backward through the loss: $\partial L/\partial a = 2(a - t) = 2(-0.3208) = -0.6416$.
step: Through the sigmoid, whose derivative is $a(1 - a) \approx 0.6792 \cdot 0.3208 = 0.2179$: $\partial L/\partial z = -0.6416 \cdot 0.2179 \approx -0.1398$.
step: Through the affine step: $\partial L/\partial b = \partial L/\partial z \cdot 1 = -0.1398$ and $\partial L/\partial w = \partial L/\partial z \cdot x = -0.1398 \cdot 2 \approx -0.2796$.
answer: $\partial L/\partial w \approx -0.2796$ and $\partial L/\partial b \approx -0.1398$.

@example
title: A graph with a shared input, checked numerically
problem: Let $f(x, y) = xy + x^2$. Compute $\partial f/\partial x$ and $\partial f/\partial y$ at $(3, 2)$ with the chain rule, then check $\partial f/\partial x$ with a central difference using $\epsilon = 0.1$.
step: Graph: $p = xy$, $q = x \cdot x$, $f = p + q$. Forward: $p = 6$, $q = 9$, $f = 15$.
step: Backward: $f$ is a sum, so $\partial f/\partial p = \partial f/\partial q = 1$.
step: Input $y$ is used once: $\partial f/\partial y = x \cdot 1 = 3$. Input $x$ is used in $p$ (contributing $y \cdot 1 = 2$) and twice in $q$ (contributing $x + x = 6$), so $\partial f/\partial x = 2 + 6 = 8$.
step: Check: $f(3.1, 2) = 6.2 + 9.61 = 15.81$ and $f(2.9, 2) = 5.8 + 8.41 = 14.21$, so the difference is $(15.81 - 14.21)/0.2 = 8.0$, which matches (a quadratic's central difference is exact).
answer: $\partial f/\partial x = 8$ and $\partial f/\partial y = 3$.

@mistakes
- Assigning a gradient (`grad = ...`) instead of accumulating it (`grad += ...`): a value used on two paths then keeps only one path's contribution.
- Multiplying the gradients of two paths instead of adding them at a node used twice.
- Using the wrong local derivative for a product: $\partial(uv)/\partial u$ is $v$, the other factor, not $u$.
- Choosing $\epsilon$ extremely small (such as $10^{-12}$) for a gradient check: rounding error then dominates and the check fails for a correct gradient.

```python
def numerical_grad(f, xs, eps=1e-5):
    """Central finite-difference gradient of f at xs."""
    grad = []
    for i in range(len(xs)):
        up = list(xs)
        down = list(xs)
        up[i] += eps
        down[i] -= eps
        grad.append((f(up) - f(down)) / (2 * eps))
    return grad
```
hint: For each index, copy the list, add `eps` to one copy and subtract it from the other, and divide the difference of the two function values by `2 * eps`.
solution: Perturb one coordinate at a time on copies of the point so the original list is untouched. The cubic test separates the central difference from a one-sided difference: the one-sided error $\epsilon f''/2 = 6 \times 10^{-5}$ exceeds the tolerance, while the central error is about $10^{-10}$.

model:
```python
import math

def neuron_loss_grads(w, b, x, t):
    """Loss of a sigmoid neuron and its gradients, by the chain rule."""
    z = w * x + b
    a = 1 / (1 + math.exp(-z))
    loss = (a - t) ** 2
    dz = 2 * (a - t) * a * (1 - a)
    return loss, dz * x, dz
```
hint: Go backward: $\partial L/\partial a = 2(a - t)$, then multiply by $a(1-a)$ to get $\partial L/\partial z$, then by $x$ for $w$ and by 1 for $b$.
solution: The backward pass multiplies local derivatives: the square gives $2(a - t)$, the sigmoid gives $a(1 - a)$, and the affine step gives $x$ for $w$ and 1 for $b$. The last two tests compare against central finite differences, which is exactly the gradient check from the article.

model:
```python
def chain_derivative(fs, dfs, x):
    """Derivative of a composition by a forward pass and a backward pass."""
    values = [x]
    for f in fs:
        values.append(f(values[-1]))
    grad = 1.0
    for i in range(len(fs) - 1, -1, -1):
        grad *= dfs[i](values[i])

    return grad
```
hint: Store the inputs to each function in a list during the forward pass; each derivative `dfs[i]` must be evaluated at the input of `fs[i]`, not at its output.
solution: The derivative of the composition is the product of each $f_i'$ evaluated at the input that $f_i$ saw in the forward pass. The empty composition is the identity with derivative 1, and the test with $v^3$ followed by doubling would fail if derivatives were evaluated at the outputs.
