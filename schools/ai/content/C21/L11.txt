@article
So far the agent learned values and then acted greedily. A different idea is to learn the policy directly: parameterize $\pi(a \mid s; \boldsymbol{\theta})$ and adjust $\boldsymbol{\theta}$ to increase expected return. This handles continuous actions, can represent stochastic policies, and changes action probabilities smoothly instead of flipping a greedy argmax.

### A softmax policy

With one preference $\theta_a$ per action (the bandit case, or one such vector per state),

$$\pi(a) = \frac{e^{\theta_a}}{\sum_c e^{\theta_c}}.$$

Its log-probability is $\ln \pi(a) = \theta_a - \ln\sum_c e^{\theta_c}$, so differentiating with respect to a preference $\theta_b$ gives

$$\frac{\partial \ln \pi(a)}{\partial \theta_b} = \mathbb{1}[a = b] - \pi(b).$$

Raising the chosen action's preference raises its probability, and the other actions' probabilities fall in proportion to their current size.

### The policy gradient for a bandit

Let $J(\boldsymbol{\theta}) = \sum_a \pi(a)\,q(a)$ be the expected reward. Using the **log-derivative trick** $\nabla \pi = \pi\,\nabla \ln \pi$,

$$\nabla J = \sum_a q(a)\,\nabla\pi(a) = \sum_a \pi(a)\,q(a)\,\nabla \ln \pi(a) = \mathbb{E}\big[\,R\;\nabla \ln \pi(A)\,\big].$$

So a single sampled action and reward give an unbiased estimate of the gradient: $R\,\nabla \ln\pi(A)$. Ascending it gives the update

$$\theta_b \leftarrow \theta_b + \alpha\,R\,\big(\mathbb{1}[A = b] - \pi(b)\big).$$

**A baseline.** For any number $b$ that does not depend on the action, $\sum_a b\,\nabla\pi(a) = b\,\nabla \sum_a \pi(a) = b\,\nabla 1 = 0$. So we may subtract it: $\nabla J = \mathbb{E}[(R - b)\,\nabla \ln \pi(A)]$. The expectation is unchanged, but a good baseline (the average reward so far is common) reduces the variance of the estimate, because it makes the weight positive for better-than-average actions and negative for worse ones. This is the gradient bandit algorithm.

### REINFORCE

For an episodic MDP the **policy gradient theorem** says that the gradient of the expected return is proportional to the expected sum over states and actions of $q_\pi(s, a)\,\nabla \pi(a \mid s)$, where states are weighted by how often $\pi$ visits them. Sampling this expectation and replacing $q_\pi(S_t, A_t)$ by the observed return gives REINFORCE (Williams, 1992). After each complete episode, for $t = 0, \dots, T-1$:

$$\boldsymbol{\theta} \leftarrow \boldsymbol{\theta} + \alpha\,\gamma^{t}\,G_t\,\nabla_{\boldsymbol{\theta}} \ln \pi(A_t \mid S_t; \boldsymbol{\theta}).$$

In our tabular softmax version, the preference of action $b$ in state $S_t$ changes by $\alpha\,\gamma^t\,G_t\,(\mathbb{1}[A_t = b] - \pi(b \mid S_t))$. Updates are applied in time order and each uses the current parameters. REINFORCE needs complete episodes and its updates have high variance, since $G_t$ sums many random rewards. Subtracting a state-dependent baseline $b(S_t)$ from $G_t$ again leaves the expected gradient unchanged.

### Actor-critic

An **actor-critic** method keeps two things: the **actor**, the policy, and the **critic**, a value function $V(s)$ learned by TD. The critic's TD error $\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)$ serves as an estimate of how much better the action was than expected (the **advantage**). Each step:

$$V(S_t) \leftarrow V(S_t) + \alpha_w\,\delta_t, \qquad \theta_b \leftarrow \theta_b + \alpha_\theta\,\delta_t\,\big(\mathbb{1}[A_t = b] - \pi(b \mid S_t)\big).$$

Compared with REINFORCE, actor-critic updates every step, works in continuing tasks, and has much lower variance, at the price of bias from an imperfect critic. Modern deep methods build on this structure; PPO (Schulman and colleagues, 2017) keeps each policy update small by clipping the ratio of new to old action probabilities.

### In code

```python
import math

def softmax(theta):
    m = max(theta)
    e = [math.exp(t - m) for t in theta]
    z = sum(e)
    return [x / z for x in e]

def reinforce_bandit_step(theta, a, r, baseline, alpha):
    """Gradient bandit update after action a and reward r."""
    p = softmax(theta)
    return [t + alpha * (r - baseline) * ((1.0 if k == a else 0.0) - p[k])
            for k, t in enumerate(theta)]

theta = [0.0, 0.0, 0.0]
theta = reinforce_bandit_step(theta, 1, 2.0, 1.0, 0.1)
print([round(t, 4) for t in theta])
```

This prints `[-0.0333, 0.0667, -0.0333]`: the chosen action's preference rises by $0.1 \times 1 \times \tfrac23$ and the others fall by $0.1 \times 1 \times \tfrac13$. Subtracting the maximum inside `softmax` avoids overflow without changing the result. In PyTorch, `loss = -(G - b) * log_prob` and `loss.backward()` produce the same update with automatic differentiation.

title: One REINFORCE step with a baseline
problem: A 3-armed bandit has softmax preferences $\boldsymbol{\theta} = (0, 0, 0)$. The agent samples arm 2, receives reward 4, and uses a baseline of 1 and $\alpha = 0.3$. (a) Compute the update of all three preferences. (b) What is the new probability of arm 2? (c) Show that the baseline does not change the expected update for arm 2 when all three rewards of this bandit are fixed at $(1, 3, 4)$ for arms 0, 1, 2 and the policy is uniform.
step: The policy is uniform, $\pi = (\tfrac13, \tfrac13, \tfrac13)$, and $R - b = 3$. For arm 2 (chosen), $\mathbb{1} - \pi = \tfrac23$ so $\Delta\theta_2 = 0.3 \times 3 \times \tfrac23 = 0.6$.
step: For the other arms $\mathbb{1} - \pi = -\tfrac13$ so $\Delta\theta_0 = \Delta\theta_1 = 0.3 \times 3 \times (-\tfrac13) = -0.3$. The new preferences are $(-0.3, -0.3, 0.6)$.
step: New probability of arm 2: $e^{0.6}/(2e^{-0.3} + e^{0.6}) = 1.822/(1.481 + 1.822) = 0.5515$, up from $0.3333$.
step: For (c), the expected update of $\theta_2$ is $\alpha\sum_a \pi(a)\,(r_a - b)(\mathbb{1}[a = 2] - \tfrac13)$ with $\pi(a) = \tfrac13$. Collect the terms: it equals $\alpha\cdot\tfrac13\big[(1 - b)(-\tfrac13) + (3 - b)(-\tfrac13) + (4 - b)(\tfrac23)\big]$.
step: The coefficient of $b$ inside the bracket is $\tfrac13 + \tfrac13 - \tfrac23 = 0$, and the rest is $\tfrac{-1 - 3 + 8}{3} = \tfrac43$. So the expected update is $\tfrac{4}{9}\alpha$ for every $b$: the baseline changes individual updates but not their average.
answer: (a) The preferences become $(-0.3, -0.3, 0.6)$. (b) The probability of arm 2 becomes $0.5515$. (c) The expected update is unchanged by the baseline because $\sum_a \pi(a)\,\nabla\ln\pi(a) = 0$.

@mistakes
- Updating with the gradient of $\pi(a)$ instead of $\ln\pi(a)$: the log form is what makes $R\,\nabla\ln\pi$ an unbiased estimate of the gradient.
- Letting the baseline depend on the action taken, which does bias the gradient; it may depend on the state but not on $A_t$.
- Using the immediate reward instead of the return $G_t$ in REINFORCE for tasks with delayed reward.
- Forgetting the $-\pi(b)$ term in the softmax gradient, so that only the chosen action's preference changes.
- Updating the actor with the TD error before updating the critic, or with a stale $V(S_{t+1})$ at a terminal state (which must be 0).

model:
```python
import math

def run_reinforce(rewards, theta0, alpha, us, use_baseline):
    """Gradient bandit algorithm driven by a supplied list of uniforms."""
    theta = list(theta0)
    chosen = []
    total, count = 0.0, 0
    for u in us:
        m = max(theta)
        e = [math.exp(t - m) for t in theta]
        z = sum(e)
        p = [x / z for x in e]
        a = len(p) - 1
        cum = 0.0
        for k, pk in enumerate(p):
            cum += pk
            if u < cum:
                a = k
                break
        r = rewards[a]
        b = total / count if (use_baseline and count > 0) else 0.0
        for k in range(len(theta)):
            theta[k] += alpha * (r - b) * ((1 if k == a else 0) - p[k])
        total += r
        count += 1
        chosen.append(a)
    return theta, chosen
```
hint: Compute `p` before changing any preference, sample by walking through the cumulative sums, and keep a running total of past rewards for the baseline.
solution: The baseline uses only earlier rewards, so at step 0 it is 0. Without a baseline every reward is positive or zero, so the preference of any sampled arm with positive reward rises, including the mediocre arm 0; with the baseline, arms that are worse than average are pushed down. The two runs choose different arms from step 3 onward, because their preferences differ.

```python
import math

def reinforce_episode_update(theta, episode, alpha, gamma):
    """REINFORCE with a tabular softmax policy."""
    theta = {s: dict(d) for s, d in theta.items()}
    returns = [0.0] * len(episode)
    g = 0.0
    for t in range(len(episode) - 1, -1, -1):
        g = episode[t][2] + gamma * g
        returns[t] = g
    for t, (s, a, r) in enumerate(episode):
        acts = list(theta[s])
        prefs = [theta[s][b] for b in acts]
        m = max(prefs)
        e = [math.exp(x - m) for x in prefs]
        z = sum(e)
        for b, eb in zip(acts, e):
            p = eb / z
            theta[s][b] += alpha * gamma ** t * returns[t] * (
                (1 if b == a else 0) - p)
    return theta
```
hint: Copy the nested dictionary, compute the returns backward, and for each step compute the softmax from the current copy before changing that state's preferences.
solution: The factor `gamma ** t` discounts the later steps of the episode, and the step at time 2 sees the preferences of state `s` already changed by the step at time 0, which is why the test values are not simply additive. The single-step test with $\gamma = 0.9$ and $t = 0$ has factor 1, a return of 1 and a uniform policy, so the chosen preference rises by $0.5$.

model:
```python
import math

def actor_critic_step(theta, V, s, a, r, s2, alpha_theta, alpha_w, gamma):
    """One-step actor-critic update; returns the TD error."""
    v2 = V[s2] if s2 is not None else 0.0
    delta = r + gamma * v2 - V[s]
    acts = list(theta[s])
    prefs = [theta[s][b] for b in acts]
    m = max(prefs)
    e = [math.exp(x - m) for x in prefs]
    z = sum(e)
    V[s] += alpha_w * delta
    for b, eb in zip(acts, e):
        theta[s][b] += alpha_theta * delta * ((1 if b == a else 0) - eb / z)
    return delta
```
hint: Compute `delta` and the softmax probabilities from the values before any change; then update the critic and the actor with the same `delta`.
solution: The TD error plays the role of the return minus a baseline: positive means the action did better than the critic expected. In the second test the critic expected 3 but the episode ended with reward 1, so $\delta = -2$ and the probability of the chosen action falls sharply. The last test has $\delta = 0$, so nothing changes.
