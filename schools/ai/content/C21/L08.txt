@article
Monte Carlo waits for the end of an episode before it learns anything. If you are driving and the road ahead is blocked, you do not wait until the end of the trip to revise your estimate of how long it will take; you update as soon as you see the delay. **Temporal-difference** (TD) learning, introduced by Sutton (1988), does exactly that: it updates the estimate of a state from the very next reward and the current estimate of the next state. It combines MC's learning from experience with DP's bootstrapping.

### TD(0)

Recall $v_\pi(s) = \mathbb{E}[R_{t+1} + \gamma\,v_\pi(S_{t+1}) \mid S_t = s]$. Replace the expectation by one sample and the unknown $v_\pi(S_{t+1})$ by the current estimate $V(S_{t+1})$:

$$V(S_t) \leftarrow V(S_t) + \alpha\,\big[\,\underbrace{R_{t+1} + \gamma V(S_{t+1})}_{\text{TD target}} - V(S_t)\,\big].$$

The bracket is the **TD error**, $\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)$, with $V(\text{terminal}) = 0$. A positive $\delta_t$ means things went better than expected. Each update uses one transition, so TD works online, step by step, in continuing tasks as well as episodic ones. For a fixed policy, TD(0) converges to $v_\pi$ if the step size shrinks appropriately; with a small constant $\alpha$ it converges in the mean.

Bias and variance. The MC target $G_t$ is an unbiased sample of $v_\pi(S_t)$, but depends on a long chain of random events, so its variance is high. The TD target depends on one random reward and one random next state, so its variance is lower, but it is **biased** while $V(S_{t+1})$ is wrong. This is the same bias-variance trade-off you know from supervised learning, and in practice TD is often faster on stochastic tasks.

### $n$-step returns

Interpolate between the two targets with the **$n$-step return**

$$G_{t:t+n} = R_{t+1} + \gamma R_{t+2} + \cdots + \gamma^{n-1} R_{t+n} + \gamma^{n} V(S_{t+n}),$$

which uses $n$ real rewards and then bootstraps. If the episode ends before $t + n$, it is the ordinary return $G_t$. With $n = 1$ it is the TD(0) target, and as $n$ grows it approaches the MC target. Intermediate $n$ often works best. (TD($\lambda$) averages all $n$-step returns with weights $(1 - \lambda)\lambda^{n-1}$.)

### A random walk

Five states A, B, C, D, E sit in a row; the episode starts in C, and each step moves left or right with probability $\tfrac12$. Stepping off the right end of E gives reward 1 and ends the episode; stepping off the left end of A gives reward 0 and ends it. With $\gamma = 1$ the true values are $v(A), \dots, v(E) = \tfrac16, \tfrac26, \tfrac36, \tfrac46, \tfrac56$, the probability of finishing on the right. Both methods start with $V = 0.5$ everywhere and $\alpha = 0.1$ and see these three episodes, in order: C, D, E, right; then C, B, A, left; then C, D, C, D, E, right. After all three:

| state | A | B | C | D | E |
|---|---|---|---|---|---|
| true $v$ | 0.167 | 0.333 | 0.500 | 0.667 | 0.833 |
| TD(0) | 0.450 | 0.500 | 0.500 | 0.505 | 0.595 |
| every-visit MC | 0.450 | 0.450 | 0.591 | 0.636 | 0.595 |

After the first episode TD changed only E, because only the last step carried a nonzero TD error, while MC updated every state visited at once. TD passes information backward one state per visit; MC passes it all the way back at the end of each episode, with more noise: C's MC estimate rose after the first episode and then jumped again in the third, on one lucky trajectory.

### What TD(0) converges to in a fixed data set

If you repeatedly present the same finite batch of experience, batch MC converges to the values that minimize the squared error to the observed returns, while batch TD(0) converges to the values that would be exactly right if the observed transitions were the true model (the **certainty-equivalence** estimate). TD(0) can therefore be more efficient with limited data.

### In code

```python
def walk(path, end_reward):
    """Transitions (state, reward, next_state) of a path through A..E."""
    steps = [(path[i], 0.0, path[i + 1]) for i in range(len(path) - 1)]
    steps.append((path[-1], end_reward, None))
    return steps

def td0(episodes, gamma, alpha, init):
    V = {s: init for s in 'ABCDE'}
    for episode in episodes:
        for s, r, s2 in episode:
            target = r + gamma * (V[s2] if s2 is not None else 0.0)
            V[s] += alpha * (target - V[s])
    return V

eps = [walk('CDE', 1.0), walk('CBA', 0.0), walk('CDCDE', 1.0)]
V = td0(eps, 1.0, 0.1, 0.5)
print([round(V[s], 3) for s in 'ABCDE'])
```

This prints `[0.45, 0.5, 0.5, 0.505, 0.595]`, the TD row of the table. The terminal state is represented by `None` and has value 0.

@example
title: TD updates and n-step returns by hand
problem: (a) A walk has $V(\text{A}) = 0.4$ and $V(\text{B}) = 0.8$ with $\gamma = 1$ and $\alpha = 0.5$. The agent moves from A to B and receives reward 0.2. Apply the TD(0) update to A. (b) An episode has rewards $R_1 = 3$, $R_2 = 0$, $R_3 = 4$ and ends after three steps. The estimates are $V(S_1) = 5$ and $V(S_2) = 1$, and $\gamma = 0.5$. Compute the 1-step, 2-step and 3-step returns from $S_0$.
step: The TD error is $\delta = 0.2 + 1 \times 0.8 - 0.4 = 0.6$.
step: The update is $V(\text{A}) \leftarrow 0.4 + 0.5 \times 0.6 = 0.7$.
step: One-step return: $G_{0:1} = 3 + 0.5 \times V(S_1) = 3 + 2.5 = 5.5$.
step: Two-step return: $G_{0:2} = 3 + 0.5 \times 0 + 0.25 \times V(S_2) = 3 + 0.25 = 3.25$.
step: Three-step return: the episode ends at step 3, so there is no bootstrap term and $G_{0:3} = 3 + 0 + 0.25 \times 4 = 4$, the ordinary Monte Carlo return.
answer: (a) $V(\text{A}) = 0.7$. (b) The returns are $5.5$, $3.25$ and $4$.

@mistakes
- Using $V(S_{t+1})$ for a terminal next state: it is 0, and the final reward alone forms the target.
- Updating from the TD error without the step size, or using $G_t$ in place of the bootstrapped target.
- Bootstrapping from the value of the wrong state, or from $V(S_t)$ itself instead of $V(S_{t+1})$.
- Concluding that TD is "wrong because it is biased": its bias vanishes as the estimates converge, and its lower variance often makes it learn faster.

```python
def td_errors(transitions, V, gamma):
    """TD error of every transition under the fixed estimates V."""
    errors = []
    for s, r, s2 in transitions:
        nxt = V[s2] if s2 is not None else 0.0
        errors.append(r + gamma * nxt - V[s])
    return errors
```
hint: Look up `V[s2]` only when `s2` is not `None`; otherwise the next value is 0.0.
solution: Each transition contributes reward plus discounted next value minus the current value. The terminal transitions test the `None` case: the target is just the reward, so the error is $1 - 0.9 = 0.1$ for state E in the first test.

model:
```python
def n_step_return(rewards, values, gamma, t, n):
    """n-step return from time t, truncated at the end of the episode."""
    T = len(rewards)
    m = min(n, T - t)
    g = sum(gamma ** i * rewards[t + i] for i in range(m))
    if t + n < T:
        g += gamma ** n * values[t + n]
    return g
```
hint: Add up `m` discounted rewards, and add the bootstrap term `gamma ** n * values[t + n]` only if the episode has not ended by time `t + n`.
solution: When the episode ends within `n` steps, the return is the plain Monte Carlo return, with no bootstrap term. The tests for `n = 4` and `n = 5` from time 0 agree because `t + n >= T`, and the test at `t = 3` ends the episode within one step.

model:
```python
def batch_td0(episodes, gamma, alpha, passes, v0):
    """Batch TD(0): sum the increments over all data, then apply them."""
    V = {s: v0 for ep in episodes for s, _, _ in ep}
    for _ in range(passes):
        inc = {s: 0.0 for s in V}
        for ep in episodes:
            for s, r, s2 in ep:
                nxt = V[s2] if s2 is not None else 0.0
                inc[s] += alpha * (r + gamma * nxt - V[s])
        for s in V:
            V[s] += inc[s]
    return V
```
hint: Use two dictionaries: the values `V` that stay fixed during a pass and an increment dictionary that you add to `V` after the pass.
solution: The increments in a pass are computed from the values at its start, so state A's first pass sees `V['B'] = 0` and does not move. After many passes the values approach the certainty-equivalence estimate: state B ended with reward 1 in two of three visits, so $V(B) = 2/3$, and A always leads to B, so $V(A) = 2/3$ as well.
