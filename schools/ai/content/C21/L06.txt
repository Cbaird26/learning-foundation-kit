@article
Policy iteration spends many sweeps evaluating each policy, even though the policy is about to change. Why wait for a perfect evaluation of a policy you are going to throw away? **Value iteration** takes the idea to its extreme: it improves after every single sweep, by folding the maximum over actions into the update itself.

### The update

Start from any $v_0$ (all zeros is fine) and repeat, for every non-terminal state $s$,

$$v_{k+1}(s) = \max_a \sum_{s', r} p(s', r \mid s, a)\,\big[\, r + \gamma\, v_k(s') \,\big].$$

This is the Bellman optimality equation turned into an assignment: the right-hand side applied to $v_k$ defines an operator $T$, and $v_{k+1} = T v_k$. Terminal states keep the value 0.

### Why it converges

For $\gamma < 1$ the operator $T$ is a **contraction** in the max norm: $\lVert T u - T w \rVert_\infty \le \gamma\,\lVert u - w \rVert_\infty$ for any two value functions. The optimal value function is its unique fixed point, $v_* = T v_*$, so $\lVert v_{k+1} - v_* \rVert_\infty \le \gamma\,\lVert v_k - v_* \rVert_\infty$ and $v_k \to v_*$ geometrically from any start. The same argument applies to episodic tasks that always terminate.

In practice we stop when the largest change in a sweep, $\Delta = \max_s |v_{k+1}(s) - v_k(s)|$, falls below a threshold $\theta$. The contraction property turns this into a guarantee: $\lVert v_{k+1} - v_* \rVert_\infty \le \dfrac{\gamma\,\Delta}{1 - \gamma}$. With $\gamma = 0.9$ and $\theta = 0.01$ the error is below $0.09$; a discount factor near 1 means a stricter threshold is needed for the same accuracy.

### Extracting the policy

Value iteration returns values, not a policy. The policy that is greedy with respect to the final values,

$$\pi(s) = \arg\max_a \sum_{s', r} p(s', r \mid s, a)\,\big[\, r + \gamma\, v(s') \,\big],$$

is optimal when $v = v_*$ and near-optimal when $v$ is close. We break ties toward the first action in the listed order, replacing the incumbent only when a later action is strictly better.

### Variants

**In-place** (Gauss–Seidel) value iteration overwrites $v(s)$ immediately, so later states in a sweep use fresh values. **Asynchronous** methods update states in any order, as long as every state keeps being updated; they can focus effort on states that matter. All of these are instances of **generalized policy iteration**: an evaluation process and an improvement process that push each other toward $v_*$ and $\pi_*$. Each sweep costs $O(|\mathcal{S}|^2 |\mathcal{A}|)$ operations for dense dynamics.

### A corridor with a hazard

Five cells in a row, numbered $0, \dots, 4$. Cell 0 is a hazard (terminal): entering it gives reward $-10$. Cell 4 is the goal (terminal): entering it gives $+10$. In cells 1, 2 and 3 the actions are `L` (move left), `R` (move right) and `stay`, and every move that does not end the episode gives reward $-1$ (staying also gives $-1$). With $\gamma = 0.9$, value iteration from zeros gives

| sweep | $v(1)$ | $v(2)$ | $v(3)$ |
|---|---|---|---|
| 1 | −1 | −1 | 10 |
| 2 | −1.9 | 8 | 10 |
| 3 | 6.2 | 8 | 10 |
| 4 | 6.2 | 8 | 10 |

Information about the goal travels one cell per sweep, like a wave moving left. At sweep 4 nothing changes, so $v_* = (6.2, 8, 10)$, and the greedy policy is `R` in every cell.

### In code

```python
GAMMA = 0.9

def outcome(cell, move):
    """(next_cell, reward) for moving by `move`; 0 is hazard, 4 is goal."""
    n = cell + move
    if n == 0:
        return (n, -10.0)
    if n == 4:
        return (n, 10.0)
    return (n, -1.0)

P = {c: {'L': [(1.0,) + outcome(c, -1)],
         'R': [(1.0,) + outcome(c, 1)],
         'stay': [(1.0, c, -1.0)]} for c in (1, 2, 3)}

def backup(P, v, gamma):
    """One synchronous Bellman optimality sweep."""
    return {s: max(sum(p * (r + gamma * v.get(s2, 0.0)) for p, s2, r in outs)
                   for outs in P[s].values()) for s in P}

v = {c: 0.0 for c in P}
for k in range(1, 4):
    v = backup(P, v, GAMMA)
    print(k, [v[c] for c in (1, 2, 3)])
```

The three printed rows match the first three rows of the table. `v.get(s2, 0.0)` gives terminal cells the value 0.

@example
title: One optimality backup and an error bound
problem: In state $s$, action $a_1$ (listed first) moves to $x$ with reward 1; action $a_2$ moves to $y$ with probability 0.6 (reward 0) and to $z$ with probability 0.4 (reward $-2$); action $a_3$ ends the episode with reward 3. Let $\gamma = 0.5$, $v_k(x) = 4$, $v_k(y) = 10$, $v_k(z) = 0$. (a) Compute $v_{k+1}(s)$ and the greedy action. (b) If the last sweep of value iteration with $\gamma = 0.9$ changed no value by more than $0.004$, how far from $v_*$ can the values be?
step: The action values: $q(a_1) = 1 + 0.5 \times 4 = 3$. $q(a_2) = 0.6\,(0 + 0.5 \times 10) + 0.4\,(-2 + 0.5 \times 0) = 3 - 0.8 = 2.2$. $q(a_3) = 3 + 0 = 3$.
step: The backup takes the maximum: $v_{k+1}(s) = 3$. Actions $a_1$ and $a_3$ tie, and with ties going to the first listed action the greedy choice is $a_1$.
step: For (b), the bound is $\gamma\Delta/(1 - \gamma) = 0.9 \times 0.004 / 0.1 = 0.036$.
step: So after that sweep every value is within $0.036$ of its optimal value, even though no value moved by more than $0.004$ in the last sweep.
answer: (a) $v_{k+1}(s) = 3$ with greedy action $a_1$. (b) The error is at most $0.036$.

@mistakes
- Taking the maximum of the immediate rewards instead of the maximum of the whole one-step value $\sum p\,(r + \gamma v(s'))$.
- Giving terminal states a nonzero stored value, or letting them be updated like other states.
- Reading $\Delta < \theta$ as "the error is below $\theta$": the guarantee is $\gamma\theta/(1-\gamma)$, which is much larger when $\gamma$ is close to 1.
- Using the greedy policy of an early $v_k$ as if it were optimal: it is only as good as the values it was computed from.

```python
def value_iteration(P, gamma, theta):
    """Synchronous value iteration; returns (values, number of sweeps)."""
    v = {s: 0.0 for s in P}
    sweeps = 0
    while True:
        new_v = {}
        for s in P:
            new_v[s] = max(sum(p * (r + gamma * v.get(s2, 0.0))
                               for p, s2, r in outs)
                           for outs in P[s].values())
        sweeps += 1
        delta = max(abs(new_v[s] - v[s]) for s in P)
        v = new_v
        if delta < theta:
            return v, sweeps
```
hint: Build the new dictionary from the old one, compare the two to get the largest change, and count the sweep before checking whether to stop.
solution: Each sweep applies the optimality backup to every state using only the previous values. On the corridor the goal reward reaches the first cell in 3 sweeps and the fourth sweep changes nothing, so exactly 4 sweeps are counted. The test with `gamma = 0.0` needs two sweeps: the first computes the best immediate reward and the second changes nothing.

```python
def value_iteration_inplace(P, gamma, sweeps, order):
    """In-place value iteration with a fixed visiting order."""
    v = {s: 0.0 for s in P}
    for _ in range(sweeps):
        for s in order:
            v[s] = max(sum(p * (r + gamma * v.get(s2, 0.0))
                           for p, s2, r in outs)
                       for outs in P[s].values())
    return v
```
hint: Read and write the same dictionary `v`, so each update immediately affects the states visited after it.
solution: Visiting cells from the goal outward lets the news travel through the whole corridor in one sweep, giving the optimal values after a single pass; visiting in the opposite order moves it only one cell per sweep and gives the values $(-1, -1, 10)$. A synchronous implementation would give the same answer for both orders, and the two orders are what the first two tests distinguish.

```python
def greedy_path(P, v, gamma, s0, max_steps):
    """States visited by the greedy policy for v in a deterministic MDP."""
    path = [s0]
    s = s0
    for _ in range(max_steps):
        if s not in P:
            break
        best_a, best_q = None, None
        for a, outs in P[s].items():
            _, s2, r = outs[0]
            q = r + gamma * v.get(s2, 0.0)
            if best_q is None or q > best_q:
                best_a, best_q = a, q
        s = P[s][best_a][0][1]
        path.append(s)
    return path
```
hint: At each state compute `reward + gamma * v.get(next, 0.0)` for every action, keep the first best, move, and append the new state.
solution: The path follows the one-step lookahead best action. With empty `v` all non-terminal values are 0, so only the immediate rewards matter: next to the goal the agent takes the +10, while in cell 2 the actions `L`, `R` and `stay` tie and the first listed one, `L`, is chosen (in cell 1 it then avoids the hazard's $-10$). In the last test the actions tie and the first listed action `x` is chosen.
