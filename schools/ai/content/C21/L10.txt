@article
A table holds one number per state. Backgammon has about $10^{20}$ positions and a camera image has more pixel combinations than there are atoms in the universe, so a table cannot be filled, and visiting a state teaches us nothing about its neighbors. **Function approximation** represents the value function by a parameter vector $\mathbf{w}$ with far fewer entries than states, $\hat v(s, \mathbf{w}) \approx v_\pi(s)$, so that experience in one state generalizes to similar states.

### Linear value functions

Describe each state by a **feature vector** $\mathbf{x}(s) = (x_1(s), \dots, x_d(s))$ and let

$$\hat v(s, \mathbf{w}) = \mathbf{w}^\top \mathbf{x}(s).$$

The tabular case is the special case where $\mathbf{x}(s)$ is a one-hot vector, so each weight is one state's value. **State aggregation** gives one weight to a group of states. Features such as a constant 1 and the position along a line let a single pair of weights describe a whole range of states.

### Semi-gradient TD(0)

To fit $\hat v$ we would like to do gradient descent on the squared error $\big(v_\pi(S_t) - \hat v(S_t, \mathbf{w})\big)^2$. The true $v_\pi$ is unknown, so we substitute the TD target, which itself contains $\hat v(S_{t+1}, \mathbf{w})$:

$$\mathbf{w} \leftarrow \mathbf{w} + \alpha\,\big[\,R_{t+1} + \gamma\,\hat v(S_{t+1}, \mathbf{w}) - \hat v(S_t, \mathbf{w})\,\big]\,\nabla_{\mathbf{w}} \hat v(S_t, \mathbf{w}).$$

For a linear function $\nabla_{\mathbf{w}} \hat v(S_t, \mathbf{w}) = \mathbf{x}(S_t)$, so the update is $\mathbf{w} \leftarrow \mathbf{w} + \alpha\,\delta_t\,\mathbf{x}(S_t)$. It is called a **semi-gradient** method because the target depends on $\mathbf{w}$ but we differentiate only through the prediction, treating the target as a constant; it is not the gradient of any fixed loss. For linear approximation and on-policy sampling, semi-gradient TD(0) converges (with decreasing step sizes) to a well-defined point called the TD fixed point, whose error is bounded in terms of the best linear fit.

For action values, $\hat q(s, a, \mathbf{w}) = \mathbf{w}^\top \mathbf{x}(s, a)$ and the semi-gradient Q-learning update is $\mathbf{w} \leftarrow \mathbf{w} + \alpha\,[\,R_{t+1} + \gamma \max_{a'} \hat q(S_{t+1}, a', \mathbf{w}) - \hat q(S_t, A_t, \mathbf{w})\,]\,\mathbf{x}(S_t, A_t)$.

### The deadly triad

Combining three ingredients can make learning diverge: **function approximation**, **bootstrapping** (targets that use current estimates) and **off-policy** training. Each pair is safe in some form, but all three together are not guaranteed to be, because an update that raises $\hat v$ at one state can raise the target at another, and the errors can feed on each other. Q-learning with a function approximator has all three.

### Deep Q-networks

A **deep Q-network** (DQN; Mnih and colleagues, 2013 and 2015) uses a neural network $q(s, a; \boldsymbol{\theta})$, taking an Atari game screen as input, for the action-value function, trained with semi-gradient Q-learning and two stabilizers aimed at the triad:

- **Experience replay.** Store transitions $(s, a, r, s', \text{done})$ in a buffer and train on random minibatches from it. This breaks the correlation between consecutive samples and reuses each transition many times.
- **Target network.** Compute targets with a separate copy $\boldsymbol{\theta}^-$ of the parameters that is updated to equal $\boldsymbol{\theta}$ only every $C$ steps. The target $y = r + \gamma \max_{a'} q(s', a'; \boldsymbol{\theta}^-)$ then stays fixed between syncs; for a terminal transition $y = r$.

Each minibatch step minimizes $\frac{1}{B}\sum_i \ell\big(y_i - q(s_i, a_i; \boldsymbol{\theta})\big)$, where $\ell$ is the squared error or the **Huber loss** (quadratic for small errors, linear for large ones, which limits the size of gradients). Many later variants (double Q-learning, prioritized replay, dueling networks) refine this recipe.

For a linear $q(s, a; \mathbf{w}) = \mathbf{w}^\top \mathbf{x}(s, a)$ with the squared error, one step with learning rate $\alpha$ is $\mathbf{w} \leftarrow \mathbf{w} + \frac{\alpha}{B}\sum_i (y_i - \mathbf{w}^\top \mathbf{x}_i)\,\mathbf{x}_i$. Counting parameters of a network with layer sizes $4 \to 8 \to 2$ and biases: $4 \cdot 8 + 8 + 8 \cdot 2 + 2 = 58$. Practitioners implement the same thing with PyTorch, where automatic differentiation computes $\nabla_{\boldsymbol{\theta}} q$:

```text
# a has shape (B,); done is 0.0 or 1.0
y = r + gamma * target_net(s2).max(dim=1).values * (1 - done)
q = q_net(s).gather(1, a.unsqueeze(1)).squeeze(1)
loss = huber(q - y.detach())
```

### In code

```python
def dot(a, b):
    return sum(p * q for p, q in zip(a, b))

def td0_linear_step(w, x, r, x2, gamma, alpha):
    """Semi-gradient TD(0) step; x2 is None when the next state is terminal."""
    v2 = dot(w, x2) if x2 is not None else 0.0
    delta = r + gamma * v2 - dot(w, x)
    return [wi + alpha * delta * xi for wi, xi in zip(w, x)]

w = [0.0, 0.0]
w = td0_linear_step(w, [1, 2], 1.0, [1, 3], 0.9, 0.1)
w = td0_linear_step(w, [1, 3], 0.0, None, 0.9, 0.1)
print([round(v, 4) for v in w])
```

This prints `[0.03, -0.01]`. The features are $(1, s)$: a constant and the position of the state.

title: A semi-gradient step and a DQN target
problem: (a) A linear value function has features $\mathbf{x}(s) = (1, s)$ and weights $\mathbf{w} = (0.1, 0.2)$. The agent moves from $s = 2$ to $s' = 3$ with reward 1, $\gamma = 0.9$ and $\alpha = 0.1$. Apply semi-gradient TD(0). (b) In a DQN step the target network gives $q(s', a_1; \boldsymbol{\theta}^-) = 3$ and $q(s', a_2; \boldsymbol{\theta}^-) = 5$; the transition has $r = 2$, is not terminal, and the online network gives $q(s, a; \boldsymbol{\theta}) = 4$. With $\gamma = 0.9$, compute the target, the error, the squared loss and the Huber loss with threshold 1.
step: Evaluate the features: $\mathbf{x}(2) = (1, 2)$ and $\mathbf{x}(3) = (1, 3)$. Then $\hat v(2) = 0.1 + 0.4 = 0.5$ and $\hat v(3) = 0.1 + 0.6 = 0.7$.
step: The TD error is $\delta = 1 + 0.9 \times 0.7 - 0.5 = 1.13$.
step: The update adds $\alpha\delta\,\mathbf{x}(2) = 0.113 \times (1, 2) = (0.113, 0.226)$, so $\mathbf{w} = (0.213, 0.426)$.
step: For (b), the target is $y = 2 + 0.9 \times \max(3, 5) = 6.5$ and the error is $y - q = 6.5 - 4 = 2.5$. The squared loss is $2.5^2 = 6.25$.
step: The Huber loss with threshold $\kappa = 1$ and $|e| = 2.5 > \kappa$ is $\kappa\,(|e| - \kappa/2) = 2.5 - 0.5 = 2.0$. Its gradient with respect to the prediction has magnitude 1, not 5.
answer: (a) $\mathbf{w} = (0.213, 0.426)$. (b) Target 6.5, error 2.5, squared loss 6.25, Huber loss 2.0.

@mistakes
- Forgetting the feature vector in the update: the weight change is $\alpha\delta\,\mathbf{x}(s)$, not a scalar added to every weight.
- Differentiating through the target as well: semi-gradient methods treat $R + \gamma \hat v(S', \mathbf{w})$ as a constant.
- Bootstrapping from a terminal next state: the target of a terminal transition is just the reward.
- Updating the target network after every step, which removes its stabilizing effect, or never updating it.
- Sampling a replay minibatch in order instead of at random, which brings back the correlation that replay is meant to break.

model:
```python
def fit_linear_td(episodes, feats, gamma, alpha, w):
    """Semi-gradient TD(0) with a linear value function."""
    w = list(w)
    for episode in episodes:
        for s, r, s2 in episode:
            x = feats[s]
            v = sum(wi * xi for wi, xi in zip(w, x))
            v2 = 0.0
            if s2 is not None:
                v2 = sum(wi * xi for wi, xi in zip(w, feats[s2]))
            delta = r + gamma * v2 - v
            w = [wi + alpha * delta * xi for wi, xi in zip(w, x)]
    return w
```
hint: Copy `w` first. For each transition compute both values with the current weights, form `delta`, and then update all weights at once.
solution: The update changes every weight in proportion to its feature, and both values in `delta` use the weights from before the update. With one-hot features the function reproduces tabular TD(0): the last test gives the same numbers as updating a table with $\alpha = 0.5$. The empty-list test checks that the input list is not changed.

```python
def dqn_targets(batch, feat, actions, w_target, gamma):
    """Targets r + gamma * max_a' q(s', a'; w_target), or r when done."""
    targets = []
    for s, a, r, s2, done in batch:
        if done:
            targets.append(r)
        else:
            best = max(sum(w * x for w, x in zip(w_target, feat[(s2, b)]))
                       for b in actions)
            targets.append(r + gamma * best)
    return targets
```
hint: For a non-terminal transition take the maximum over all actions of the dot product of `w_target` with the features of `(s2, action)`, and do not touch `s2` when `done` is true.
solution: The target network supplies the next-state values, and a terminal transition has target equal to its reward. In the first transition the best next value is $\max(1.5, 3.5) = 3.5$, so the target is $1 + 0.9 \times 3.5 = 4.15$. The last test makes every next-state value negative: the maximum is $-2$ (the larger of $-2$ and $-3$), so a solution that starts its running maximum at 0 fails.

model:
```python
def minibatch_update(w, batch, feat, actions, w_target, gamma, alpha):
    """One averaged gradient step on the squared TD error (linear q)."""
    grad = [0.0] * len(w)
    for s, a, r, s2, done in batch:
        if done:
            y = r
        else:
            y = r + gamma * max(
                sum(wt * x for wt, x in zip(w_target, feat[(s2, b)]))
                for b in actions)
        x = feat[(s, a)]
        err = y - sum(wi * xi for wi, xi in zip(w, x))
        for i in range(len(w)):
            grad[i] += err * x[i]
    return [wi + alpha * g / len(batch) for wi, g in zip(w, grad)]
```
hint: Accumulate `err * x[i]` for every transition using the unchanged `w`, then divide by the batch size and apply the step once.
solution: Every transition's error is computed with the same weights, the contributions are averaged over the batch, and only then is `w` changed; updating sequentially inside the loop would give different numbers. The single-transition test with `alpha = 1.0` moves the first weight by the whole error $2.65$, since only that feature is active.
