@article
Last lesson we solved $(\mathbf{I} - \gamma\mathbf{P}_\pi)\mathbf{v} = \mathbf{r}_\pi$ exactly. That costs time cubic in the number of states, and it stops being practical for large state spaces. **Dynamic programming** (DP) takes a different route: treat the Bellman equation as an update rule and apply it over and over. DP needs a complete model of the MDP (the dynamics $p$), so it is *planning*, not yet learning from experience, but every later method imitates it.

### The gridworld used in this lesson

A gridworld has states $(r, c)$, the actions `U`, `D`, `L`, `R` (always listed in this order), and deterministic moves: a move off the grid leaves the agent where it is. Every move gives reward $-1$, and the terminal cells have no actions, so the agent wants to reach a terminal cell quickly.

### Iterative policy evaluation

Start with any $v_0$ (usually all zeros) and replace the equation by an update:

$$v_{k+1}(s) = \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a)\,\big[\, r + \gamma\, v_k(s') \,\big] \quad\text{for every state } s.$$

This is a **synchronous** sweep: every new value is computed from the old array $v_k$. The true $v_\pi$ is a fixed point of the update. When $\gamma < 1$ the update is a **contraction** in the max norm: $\lVert v_{k+1} - v_\pi \rVert_\infty \le \gamma\, \lVert v_k - v_\pi \rVert_\infty$, so the error shrinks at least geometrically, and the Banach fixed-point theorem guarantees convergence to $v_\pi$ from any start. (For an episodic task with $\gamma = 1$ it converges when the policy reaches a terminal state with probability 1.) We stop when the largest change in a sweep is below a threshold $\theta$.

An **in-place** sweep uses one array and overwrites $v(s)$ as soon as it is computed, so later states in the sweep already see updated values. It also converges, often faster, but the intermediate values depend on the order in which states are visited.

For the $2 \times 2$ grid with terminal cell $(0, 0)$, $\gamma = 1$ and the uniform random policy, synchronous sweeps from zero give

| sweep $k$ | $v_k(0,1)$ | $v_k(1,0)$ | $v_k(1,1)$ |
|---|---|---|---|
| 1 | −1 | −1 | −1 |
| 2 | −1.75 | −1.75 | −2 |
| 3 | −2.375 | −2.375 | −2.875 |
| 4 | −2.906 | −2.906 | −3.625 |
| $\infty$ | −6 | −6 | −8 |

The limit solves $a = -1 + \tfrac{1}{4}(2a + b)$ and $b = -1 + \tfrac14(2a + 2b)$, so $a = -6$ and $b = -8$.

### Policy improvement

Given $v_\pi$, can we find a better policy? Compare the value of following $\pi$ with the value of choosing a different action once and then following $\pi$. The **policy improvement theorem** says: if $\pi'$ is a policy with $q_\pi(s, \pi'(s)) \ge v_\pi(s)$ for every state $s$, then $v_{\pi'}(s) \ge v_\pi(s)$ for every state, with strict inequality somewhere if the inequality is strict somewhere. The **greedy** policy $\pi'(s) = \arg\max_a q_\pi(s, a)$ satisfies the condition, so it is never worse than $\pi$. If the greedy policy ties with $\pi$ everywhere, then $v_\pi$ satisfies the Bellman optimality equation and $\pi$ is optimal.

Floating-point values can tie only approximately, so when we implement improvement we **keep the current action if its value is within $10^{-9}$ of the best**; otherwise we switch to the first action (in the listed order) that attains the best value. This stable rule prevents a policy from flipping between equal actions forever.

### Policy iteration

**Policy iteration** alternates: evaluate the current policy until the change falls below $\theta$, then improve it greedily, and stop when the policy no longer changes. A finite MDP has finitely many deterministic policies, and each improvement strictly improves the value until the policy is optimal, so the loop ends after finitely many iterations, usually very few.

### In code

```python
ACTIONS = [('U', (-1, 0)), ('D', (1, 0)), ('L', (0, -1)), ('R', (0, 1))]

def make_grid(rows, cols, terminals, step=-1.0):
    """P[s][a] = [(1.0, next_state, step)] for every non-terminal cell."""
    P = {}
    for r in range(rows):
        for c in range(cols):
            if (r, c) in terminals:
                continue
            P[(r, c)] = {}
            for a, (dr, dc) in ACTIONS:
                nr, nc = r + dr, c + dc
                if not (0 <= nr < rows and 0 <= nc < cols):
                    nr, nc = r, c
                P[(r, c)][a] = [(1.0, (nr, nc), step)]
    return P

def sweep(P, pi, v, gamma):
    """One synchronous Bellman expectation sweep."""
    return {s: sum(pi[s].get(a, 0.0) *
                   sum(p * (r + gamma * v.get(s2, 0.0)) for p, s2, r in outs)
                   for a, outs in P[s].items()) for s in P}

P = make_grid(2, 2, {(0, 0)})
pi = {s: {a: 0.25 for a in 'UDLR'} for s in P}
v = {s: 0.0 for s in P}
for k in range(2):
    v = sweep(P, pi, v, 1.0)
print([v[s] for s in sorted(v)])
```

This prints `[-1.75, -1.75, -2.0]`, the second row of the table. Practitioners vectorize the sweep with NumPy, but the idea is the same.

title: One sweep and one improvement step by hand
problem: In state $s$, action $a_1$ moves to a state $x$ with reward 1, and action $a_2$ ends the episode with reward 5. Take $\gamma = 0.9$ and $v_k(x) = 2$. (a) With the policy that picks each action with probability 0.5, compute $v_{k+1}(s)$ from one synchronous sweep. (b) Which action does the greedy improvement step choose, and what does it change?
step: The two actions have one-step values $q(s, a_1) = 1 + 0.9 \times 2 = 2.8$ and $q(s, a_2) = 5 + 0 = 5$ (a terminal state has value 0).
step: Part (a): $v_{k+1}(s) = 0.5 \times 2.8 + 0.5 \times 5 = 3.9$.
step: Part (b): greedy picks the larger $q$, which is $a_2$, because $5 > 2.8$. The improved policy ends the episode at once instead of mixing the two actions.
step: Check against the policy improvement theorem: $q(s, a_2) = 5 \ge 3.9 = v_{k+1}(s)$, so the new policy is at least as good in this state.
answer: $v_{k+1}(s) = 3.9$, and the greedy step switches to $a_2$.

@mistakes
- Updating in place but analyzing the result as if it were synchronous: after one in-place sweep, the numbers depend on the order of the states.
- Forgetting that terminal states have value 0, so their neighbors' updates use $v(s') = 0$ and not a stored estimate.
- Breaking ties by always taking the last or a random best action, which can make policy iteration cycle between equal actions; use a stable rule.
- Stopping policy evaluation after one sweep and calling it exact: the threshold $\theta$ controls the error, and a loose $\theta$ can give a wrong improvement.

```python
def evaluate_inplace(P, pi, gamma, sweeps, order):
    """In-place iterative policy evaluation with a fixed visiting order."""
    v = {s: 0.0 for s in P}
    for _ in range(sweeps):
        for s in order:
            total = 0.0
            for a, outcomes in P[s].items():
                w = pi[s].get(a, 0.0)
                total += w * sum(p * (r + gamma * v.get(s2, 0.0))
                                 for p, s2, r in outcomes)
            v[s] = total
    return v
```
hint: Do not copy the dictionary at the start of a sweep; read from and write to the same `v`, so later states see new values.
solution: Each visit computes the expected one-step backup from the current `v` and writes it back at once. On the chain, visiting the states from last to first propagates the terminal reward all the way back in a single sweep, while the forward order moves it only one state per sweep; a synchronous implementation would give the same answer for both orders, so the second test catches it.

```python
def policy_iteration(P, gamma, theta):
    """Policy iteration with stable tie-breaking."""
    policy = {s: next(iter(P[s])) for s in P}
    while True:
        v = {s: 0.0 for s in P}
        while True:
            new_v = {s: sum(p * (r + gamma * v.get(s2, 0.0))
                            for p, s2, r in P[s][policy[s]]) for s in P}
            delta = max(abs(new_v[s] - v[s]) for s in P)
            v = new_v
            if delta < theta:
                break
        changed = False
        for s in P:
            q = {a: sum(p * (r + gamma * v.get(s2, 0.0)) for p, s2, r in o)
                 for a, o in P[s].items()}
            best = max(q.values())
            if q[policy[s]] < best - 1e-9:
                policy[s] = next(a for a in P[s] if q[a] >= best - 1e-9)
                changed = True
        if not changed:
            return policy, v
```
hint: The outer loop evaluates and improves; the inner loop is a synchronous sweep until the change is below `theta`. Only switch an action when the current one is clearly worse than the best.
solution: Evaluating a deterministic policy only needs its own action's outcomes. The improvement step switches an action only when the current one falls more than $10^{-9}$ below the best, so the loop ends when the policy is greedy for its own value function. The starting policy on the corridor takes `U`, which leaves the agent in place forever, so the first evaluation gives $-10$ everywhere and the improvement step must repair it.

```python
def improve_policy(P, v, gamma, policy):
    """Greedy improvement with stable tie-breaking."""
    new_policy = {}
    for s in P:
        q = {a: sum(p * (r + gamma * v.get(s2, 0.0)) for p, s2, r in outs)
             for a, outs in P[s].items()}
        best = max(q.values())
        if q[policy[s]] >= best - 1e-9:
            new_policy[s] = policy[s]
        else:
            new_policy[s] = next(a for a in P[s] if q[a] >= best - 1e-9)
    return new_policy
```

solution: The rule changes an action only when it is clearly suboptimal. In state $(1, 1)$ the actions `U` and `L` tie, so a current `L` stays and a current `D` becomes `U`, the first tied action. The last test shows that the improved policy is stable when improved again.
