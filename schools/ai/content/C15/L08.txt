@article
Last week's fully grown tree fit its training set perfectly and still disagreed with itself: change a few training points and the tree can look completely different. That instability is **variance**. If we could train many trees on many fresh data sets and average their votes, the noise in each would partly cancel. We have only one data set, but we can imitate fresh ones by resampling it.

### Bootstrap and bagging

A **bootstrap sample** of a data set of size $n$ draws $n$ examples **with replacement**. Each example is missed by one draw with probability $1 - 1/n$, so it is absent from the whole sample with probability $(1 - 1/n)^n$. For $n = 5$ this is $0.8^5 = 0.328$; as $n$ grows it approaches $e^{-1} \approx 0.368$. So a bootstrap sample contains about 63.2 percent of the distinct examples, and the other 36.8 percent are its **out-of-bag** (OOB) examples.

**Bagging** (bootstrap aggregating; Breiman, 1996) fits one model on each of $B$ bootstrap samples and combines them: the average for regression, a majority vote for classification. The trees are grown deep, so each has low bias and high variance.

### Why averaging helps

Suppose $B$ predictors each have variance $\sigma^2$ at a point, and every pair has correlation $\rho$. The variance of their average is

$$\operatorname{Var}\!\left(\frac{1}{B}\sum_{b=1}^{B}\hat f_b\right) = \frac{1}{B^2}\Big(B\sigma^2 + B(B-1)\rho\sigma^2\Big) = \rho\,\sigma^2 + \frac{1-\rho}{B}\,\sigma^2 .$$

Only the second term shrinks with $B$. With $\sigma^2 = 4$ and $\rho = 0.5$ the variance is $4$ for one tree, $2.2$ for $B = 10$, $2.02$ for $B = 100$, and it never goes below $\rho\sigma^2 = 2$. The expectation of the average equals each model's expectation, so bagging leaves the bias about where it was: it helps models that are accurate on average but unstable, and does little for a stable model such as a linear fit. Trees grown on overlapping bootstrap samples are correlated, which sets the floor $\rho\sigma^2$.

### Random forests

A **random forest** (Breiman, 2001) lowers $\rho$. At every split in every tree, only a random subset of $m$ of the $p$ features is considered as candidates. A single dominant feature then cannot be used at the top of every tree, and the trees become less alike. Common defaults, mentioned in the textbook reading, are about $\sqrt{p}$ features for classification and $p/3$ for regression; $m = p$ gives plain bagging. Smaller $m$ decorrelates the trees but makes each one weaker, so $m$ is a hyperparameter. Adding more trees never causes overfitting in the sense of a rising variance term, though the floor stays; the forest's bias is that of one deep tree.

### Out-of-bag error

Each tree has about 37 percent of the examples out of bag, so we can score an example using only the trees that never trained on it: collect their votes and compare the majority with the true label. The fraction of mistakes is the **OOB error**, a nearly free estimate of test error close in spirit to cross-validation. Examples that happen to be in every bootstrap sample are skipped.

Take six points $x = 1, \dots, 6$ with labels $0,0,1,0,1,1$, and five stumps (one-split trees) fit on the bootstrap index lists in the code below. Three stumps split at $2.5$ and two at $4.5$; each predicts 0 on the left and 1 on the right. Point $x = 3$ (index 2) is out of bag only for the stump on the fifth sample (split at $4.5$), which predicts 0 against the true label 1; point $x = 4$ (index 3) is out of bag only for the stump on the second sample (split at $2.5$), which predicts 1 against the true 0. The other four points are correct, so the OOB error is $2/6 = 0.333$.

```python
x = [1, 2, 3, 4, 5, 6]
y = [0, 0, 1, 0, 1, 1]
samples = [[5, 5, 3, 2, 1, 0], [5, 2, 2, 0, 5, 1], [2, 0, 3, 1, 5, 1],
           [4, 2, 3, 4, 3, 1], [0, 4, 5, 0, 5, 3]]

def gini(labels):
    n = len(labels)
    if n == 0:
        return 0.0
    return 1 - sum((labels.count(c) / n) ** 2 for c in set(labels))

def majority(labels):
    return max(sorted(set(labels)), key=labels.count)

def fit_stump(xs, ys):
    values = sorted(set(xs))
    best = None
    for lo, hi in zip(values, values[1:]):
        t = (lo + hi) / 2
        left = [c for v, c in zip(xs, ys) if v <= t]
        right = [c for v, c in zip(xs, ys) if v > t]
        score = len(left) * gini(left) + len(right) * gini(right)
        if best is None or score < best[0] - 1e-12:
            best = (score, t, majority(left), majority(right))
    if best is None:
        return (0.0, majority(ys), majority(ys))
    return best[1:]

def vote(stump, v):
    t, lo, hi = stump
    return lo if v <= t else hi

stumps = [fit_stump([x[i] for i in idx], [y[i] for i in idx])
          for idx in samples]
print(stumps)

wrong = 0
for i in range(len(x)):
    oob = [s for s, idx in zip(stumps, samples) if i not in idx]
    votes = [vote(s, x[i]) for s in oob]
    pred = majority(votes)
    wrong += pred != y[i]
    print(i, votes, pred, y[i])
print("OOB error:", wrong / len(x))
```

The sample lists are written out so the output is the same on every run; in practice they come from `random.Random(seed).randrange(n)` called $n$ times. In a library a forest also reports **feature importance**, for instance the drop in accuracy when one feature's values are shuffled; treat it with care, because correlated features share importance, and importances describe the model rather than causal effects.

@example
title: How much does averaging help?
problem: $B$ trees each have prediction variance $\sigma^2 = 4$ at a point, with pairwise correlation $\rho = 0.5$. Compute the variance of their average for $B = 1, 10, 100$, and its limit as $B \to \infty$.
step: Use $\operatorname{Var} = \rho\sigma^2 + \frac{1-\rho}{B}\sigma^2$ with $\rho\sigma^2 = 2$ and $(1 - \rho)\sigma^2 = 2$.
step: For $B = 1$: $2 + 2/1 = 4$, the variance of one tree, as it should be.
step: For $B = 10$: $2 + 2/10 = 2.2$. For $B = 100$: $2 + 2/100 = 2.02$.
step: As $B \to \infty$ the second term vanishes, leaving $\rho\sigma^2 = 2$. Going from 10 to 100 trees buys only $0.18$; the way to go lower is to reduce $\rho$, which is what random feature selection does.
answer: $4$, $2.2$, $2.02$, with limit $2$.

@example
title: Out-of-bag error by hand
problem: Four training points have labels $y = (0, 1, 1, 0)$. Three models were trained on bootstrap index lists $[0,0,1,3]$, $[1,2,2,3]$ and $[0,2,3,3]$. Their predictions on all four points are $(0,1,1,0)$, $(0,1,1,1)$ and $(0,0,1,0)$. Compute the OOB error.
step: Find the OOB models for each point. Point 0 is absent from the second list only. Point 1 is absent from the third only. Point 2 is absent from the first only. Point 3 appears in every list, so it is skipped.
step: Point 0: the second model predicts 0, true label 0, correct.
step: Point 1: the third model predicts 0, true label 1, wrong.
step: Point 2: the first model predicts 1, true label 1, correct.
step: Three points were scored and one was wrong, so the OOB error is $1/3 \approx 0.333$. The skipped point is not counted as an error or a success.
answer: OOB error $= 1/3$.

@mistakes
- Averaging models trained on the same data: without resampling or other randomness the trees are identical and nothing is gained.
- Believing that more trees overfit: the variance term $\rho\sigma^2$ stays, but adding trees does not make the forest worse; the cost is time and memory.
- Counting skipped points (never out of bag) as errors when computing the OOB error, or voting with trees that did train on the point.
- Reading feature importance as causal: a feature that stands in for another correlated feature can look important or unimportant for reasons unrelated to cause.

```python
def _class_weights(labels, weights):
    totals = {}
    for c, w in zip(labels, weights):
        totals[c] = totals.get(c, 0.0) + w
    return totals

def _impurity(totals):
    total = sum(totals.values())
    if total == 0:
        return 0.0
    return total - sum(v * v for v in totals.values()) / total

def _heaviest(totals):
    return max(sorted(totals), key=lambda c: totals[c])

def fit_weighted_stump(xs, ys, ws):
    """Best single threshold split by weighted Gini impurity."""
    values = sorted(set(xs))
    best = None
    for lo, hi in zip(values, values[1:]):
        t = (lo + hi) / 2
        left = _class_weights([c for v, c in zip(xs, ys) if v <= t],
                              [w for v, w in zip(xs, ws) if v <= t])
        right = _class_weights([c for v, c in zip(xs, ys) if v > t],
                               [w for v, w in zip(xs, ws) if v > t])
        score = _impurity(left) + _impurity(right)
        if best is None or score < best[0] - 1e-12:
            best = (score, t, _heaviest(left), _heaviest(right))
    if best is None:
        m = _heaviest(_class_weights(ys, ws))
        return (xs[0], m, m)
    return best[1:]
```
hint: Accumulate the total weight of each class on each side (a dictionary works), compute $W - \sum_k W_k^2/W$ for both sides, and take the label with the largest class weight; with all weights equal to 1 this is the unweighted stump from the article.
solution: Replacing counts by weights changes both the impurity and the majority label. In the fourth test the heavy example at 4 pulls the best threshold from $2.5$ to $4.5$, and in the fifth it flips the labels of both leaves relative to the unweighted tie at $1.5$. The constant-feature test shows that the heaviest class wins even when it has fewer examples.

```python
def majority_vote(all_preds):
    """Per-example majority label across models; ties go to the smallest."""
    n = len(all_preds[0]) if all_preds else 0
    result = []
    for i in range(n):
        column = [preds[i] for preds in all_preds]
        result.append(max(sorted(set(column)), key=column.count))
    return result
```
hint: For each example collect the column of votes `[preds[i] for preds in all_preds]`, then take the label with the highest count, scanning labels in sorted order.
solution: `max` returns the first of equal maxima, so scanning the sorted labels sends ties to the smallest label, which the third test checks. The votes must be collected per example (column), not per model (row).

model:
```python
def oob_error(samples, preds, y):
    """Out-of-bag error of an ensemble, ignoring never-out-of-bag points."""
    scored = 0
    wrong = 0
    for i in range(len(y)):
        votes = [p[i] for s, p in zip(samples, preds) if i not in s]
        if not votes:
            continue
        label = max(sorted(set(votes)), key=votes.count)
        scored += 1
        wrong += label != y[i]
    return wrong / scored if scored else None
```
hint: For each example `i`, keep only the predictions of models with `i not in samples[m]`; if none remain, skip it.
solution: Only models that never saw the example may vote, which keeps the estimate honest. In the first test, example 3 has two OOB votes, 0 and 1, which tie and go to 0 (correct), while examples 0 and 2 are wrong and example 1 is right, giving $2/4$. The second test has every example in the only sample, so nothing can be scored.
