@article
Four points sit at the corners of a square. The two on one diagonal are labeled $+1$ and the two on the other diagonal $-1$. No straight line separates them: this is the XOR pattern. But if we add the product $x_1 x_2$ as a third feature, the classes separate by the sign of that new feature alone. Mapping the data into a richer feature space makes a linear method nonlinear. The **kernel trick** gets that power without ever building the features.

### Feature maps and kernels

Let $\boldsymbol{\phi}$ map an input to a feature vector. A **kernel** is the inner product of two mapped inputs,

$$k(\mathbf{x}, \mathbf{x}') = \boldsymbol{\phi}(\mathbf{x})^\top\boldsymbol{\phi}(\mathbf{x}').$$

For two inputs, the map $\boldsymbol{\phi}(\mathbf{x}) = (x_1^2, \sqrt{2}\,x_1x_2, x_2^2)$ gives $\boldsymbol{\phi}(\mathbf{x})^\top\boldsymbol{\phi}(\mathbf{x}') = x_1^2x_1'^2 + 2x_1x_2x_1'x_2' + x_2^2x_2'^2 = (\mathbf{x}^\top\mathbf{x}')^2$. So the homogeneous polynomial kernel $(\mathbf{x}^\top\mathbf{x}')^2$ equals a dot product in a three-dimensional space, and costs only one dot product in the original space to evaluate. The inhomogeneous kernel $(\mathbf{x}^\top\mathbf{x}' + 1)^d$ corresponds to all monomials of degree up to $d$, a space of dimension $\binom{p + d}{d}$ for $p$ inputs. The **RBF** (Gaussian) kernel

$$k(\mathbf{x}, \mathbf{x}') = \exp\!\big(-\gamma\lVert\mathbf{x} - \mathbf{x}'\rVert^2\big)$$

corresponds to an infinite-dimensional feature space, yet takes one line to compute. It is 1 when the points coincide and decays toward 0 with distance, at a rate set by $\gamma$.

### Which functions are kernels

A symmetric function $k$ is a valid kernel exactly when, for every finite set of points, the **Gram matrix** $K_{ij} = k(\mathbf{x}_i, \mathbf{x}_j)$ is positive semidefinite (this is Mercer's condition). The matrix $\begin{pmatrix}1 & 2\\ 2 & 1\end{pmatrix}$ has eigenvalues $3$ and $-1$, so it can never be a Gram matrix. Sums and products of kernels, and positive multiples of them, are kernels.

### The dual form uses only kernels

Last week the SVM solution was $\mathbf{w} = \sum_i\alpha_i y_i\mathbf{x}_i$, so predictions use only dot products. The dual problem maximizes $\sum_i\alpha_i - \tfrac{1}{2}\sum_{i,j}\alpha_i\alpha_j y_i y_j\,\mathbf{x}_i^\top\mathbf{x}_j$ subject to $0 \le \alpha_i \le C$ and $\sum_i\alpha_i y_i = 0$. Replace every $\mathbf{x}_i^\top\mathbf{x}_j$ by $K_{ij}$ and the whole method runs in the feature space, with decision function

$$f(\mathbf{x}) = \sum_{i}\alpha_i y_i\,k(\mathbf{x}_i, \mathbf{x}) + b.$$

The weight vector $\mathbf{w}$ itself may be infinite-dimensional, but it is never formed. The price is memory and time: the Gram matrix has $n^2$ entries and prediction costs one kernel evaluation per support vector.

### A kernel method in a few lines

The **perceptron** (Rosenblatt, 1958) keeps a weight vector and adds $y_i\mathbf{x}_i$ whenever it misclassifies example $i$. Because the weights are always a sum of such additions, we can store only how many times each example was added, a count $\alpha_i$, and write the score as $\sum_j\alpha_j y_j K_{ji}$. That is the **kernel perceptron**: for each example in turn, if $y_i f(\mathbf{x}_i) \le 0$, increment $\alpha_i$. If the data are separable in the feature space, it stops after finitely many mistakes.

On the XOR points $(1,1), (-1,-1)$ labeled $+1$ and $(1,-1), (-1,1)$ labeled $-1$, the kernel $(\mathbf{x}^\top\mathbf{x}')^2$ gives $K = 4$ between the two points of a class and $0$ between points of different classes. The perceptron makes one mistake on $(1,1)$ and one on $(1,-1)$, then everything is correct: $\boldsymbol{\alpha} = (1, 0, 1, 0)$. The decision function is $f(\mathbf{x}) = (x_1 + x_2)^2 - (x_1 - x_2)^2 = 4x_1x_2$, the sign of the product, so $f(2, 0.5) = 4$ and $f(-2, 1) = -8$.

```python
import math

X = [[1, 1], [-1, -1], [1, -1], [-1, 1]]
y = [1, 1, -1, -1]

def dot(a, b):
    return sum(u * v for u, v in zip(a, b))

def poly2(a, b):
    return dot(a, b) ** 2

def rbf(a, b, gamma=0.5):
    return math.exp(-gamma * sum((u - v) ** 2 for u, v in zip(a, b)))

def gram(X, k):
    return [[k(a, b) for b in X] for a in X]

for row in gram(X, rbf):
    print([round(v, 4) for v in row])

def kernel_perceptron(K, y, epochs):
    n = len(y)
    alpha = [0] * n
    for _ in range(epochs):
        mistakes = 0
        for i in range(n):
            f = sum(alpha[j] * y[j] * K[j][i] for j in range(n))
            if y[i] * f <= 0:
                alpha[i] += 1
                mistakes += 1
        if mistakes == 0:
            break
    return alpha

alpha = kernel_perceptron(gram(X, poly2), y, 10)
print(alpha)

def predict(x):
    return sum(a * t * poly2(p, x) for a, t, p in zip(alpha, y, X))

print(predict([2, 0.5]), predict([-2, 1]), predict([-1.5, -3]))
```

The RBF Gram matrix of the four points has ones on the diagonal, $e^{-2} \approx 0.1353$ between neighbors on a side (squared distance 4) and $e^{-4} \approx 0.0183$ between diagonal opposites (squared distance 8).

### Choosing the kernel and its parameters

Flexibility grows with the degree $d$ and with $\gamma$. A very large $\gamma$ makes the Gram matrix nearly the identity: every point is similar only to itself, the model memorizes the training set and generalizes poorly. A very small $\gamma$ makes the RBF kernel nearly constant over the data, and the classifier becomes almost linear. Together with $C$, these are hyperparameters to choose by cross-validation (week 12). Practitioners usually standardize features first, since the RBF kernel uses plain Euclidean distance.

@example
title: A kernel is a dot product in feature space
problem: Verify that $(\mathbf{x}^\top\mathbf{x}')^2 = \boldsymbol{\phi}(\mathbf{x})^\top\boldsymbol{\phi}(\mathbf{x}')$ for $\mathbf{x} = (1, -2)$ and $\mathbf{x}' = (2, 1)$, with $\boldsymbol{\phi}(\mathbf{x}) = (x_1^2, \sqrt{2}x_1x_2, x_2^2)$.
step: Compute the kernel directly: $\mathbf{x}^\top\mathbf{x}' = 2 - 2 = 0$, so $(\mathbf{x}^\top\mathbf{x}')^2 = 0$.
step: Map the points: $\boldsymbol{\phi}(\mathbf{x}) = (1, -2\sqrt{2}, 4)$ and $\boldsymbol{\phi}(\mathbf{x}') = (4, 2\sqrt{2}, 1)$.
step: Take the dot product: $1 \cdot 4 + (-2\sqrt{2})(2\sqrt{2}) + 4 \cdot 1 = 4 - 8 + 4 = 0$.
step: The two agree. The direct route used two numbers and one multiplication; the feature route needed six numbers, and for the RBF kernel the feature route would be infinite.
answer: Both equal $0$.

@example
title: First epoch of the kernel perceptron
problem: Points $x = 0, 1, 3$ with labels $+1, -1, +1$ (no line on the number line separates them) use the kernel $k(x, x') = (xx' + 1)^2$. Compute the Gram matrix and run the first epoch of the kernel perceptron, then the start of the second.
step: The Gram matrix has entries $(x_ix_j + 1)^2$: rows $(1, 1, 1)$, $(1, 4, 16)$ and $(1, 16, 100)$.
step: Example 1 ($x = 0$): all $\alpha = 0$, so $f = 0$ and $y f = 0 \le 0$: a mistake, $\alpha_1 = 1$.
step: Example 2 ($x = 1$): $f = \alpha_1 y_1 K_{12} = 1$, but $y_2 = -1$, so $y f = -1$: a mistake, $\alpha_2 = 1$.
step: Example 3 ($x = 3$): $f = (1)(1)(1) + (1)(-1)(16) = -15$ and $y_3 = +1$: a mistake, $\alpha_3 = 1$.
step: Second epoch: example 1 has $f = 1 - 1 + 1 = 1 > 0$, which is correct; example 2 has $f = 1 - 4 + 16 = 13$ against $y_2 = -1$, a mistake, so $\alpha_2 = 2$. The data are separable by a quadratic, but with a small margin, so the perceptron needs many more epochs.
answer: After epoch 1, $\boldsymbol{\alpha} = (1, 1, 1)$; in epoch 2 the first mistake is example 2, giving $\boldsymbol{\alpha} = (1, 2, 1)$ so far.

@mistakes
- Computing $\boldsymbol{\phi}$ explicitly for large or infinite feature spaces: the point of a kernel is to evaluate $k(\mathbf{x}, \mathbf{x}')$ directly.
- Using a function whose Gram matrix is not positive semidefinite as a kernel: optimization problems that assume convexity can then fail or give meaningless answers.
- Not standardizing features before an RBF kernel, so one large-scale feature dominates every distance.
- Setting $\gamma$ very large and reading perfect training accuracy as a good model: the Gram matrix is nearly the identity and the model memorizes.

model:
```python
def kernel_perceptron(K, y, epochs):
    """Kernel perceptron on a precomputed Gram matrix; returns the counts."""
    n = len(y)
    alpha = [0] * n
    for _ in range(epochs):
        mistakes = 0
        for i in range(n):
            f = sum(alpha[j] * y[j] * K[j][i] for j in range(n))
            if y[i] * f <= 0:
                alpha[i] += 1
                mistakes += 1
        if mistakes == 0:
            break
    return alpha
```
hint: The score for example $i$ uses the counts as they are at that moment, including updates made earlier in the same epoch; a point with score exactly 0 counts as a mistake.
solution: Updating `alpha` immediately, within the epoch, is part of the algorithm: the second test only matches if example 2's mistake is seen by example 3. The score of exactly 0 at the start is why every first visit is a mistake. After four epochs every training point has $y f > 0$, which the final loop confirms.

```python
def kernel_predict(X, y, alpha, kernel, x):
    """Kernel decision value from the dual coefficients."""
    total = 0.0
    for xi, yi, ai in zip(X, y, alpha):
        if ai != 0:
            total += ai * yi * kernel(xi, x)
    return total
```
hint: Loop over the training points, skip those with a zero multiplier, and add $\alpha_i y_i k(\mathbf{x}_i, \mathbf{x})$ for the rest.
solution: Only support vectors, the points with nonzero multipliers, contribute, which is why prediction cost depends on their number. The counting test checks that zero-multiplier points are skipped entirely.
