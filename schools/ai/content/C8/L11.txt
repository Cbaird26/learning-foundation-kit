@article
Probability goes from a known model to data: given a fair coin, what will we see? **Statistics** goes the other way: given data, what can we say about the unknown model? The simplest case is estimating an unknown parameter such as a mean or a success probability.

### Estimators and bias

A **parameter** is a fixed unknown number describing a population (the true mean $\mu$, or the true conversion rate $p$). An **estimator** is a function of the sample, so it is itself a random variable. Its value on a particular sample is an **estimate**. An estimator $\hat\theta$ is **unbiased** if $E[\hat\theta] = \theta$ for every value of the parameter.

For i.i.d. observations $X_1, \dots, X_n$ with mean $\mu$ and variance $\sigma^2$:

- The sample mean $\bar X = \frac1n\sum X_i$ is unbiased for $\mu$, with standard error $\sigma/\sqrt n$.
- The **sample variance** $S^2 = \frac{1}{n-1}\sum (X_i - \bar X)^2$ is unbiased for $\sigma^2$. Dividing by $n$ instead underestimates $\sigma^2$ on average, because the deviations are measured from $\bar X$, which is closer to the data than $\mu$ is. Python's `statistics.variance` and `statistics.stdev` use the divisor $n - 1$, while `pvariance` and `pstdev` use $n$.
- For Bernoulli data, the proportion $\hat p = k/n$ (successes over trials) is unbiased for $p$ and is also the **maximum likelihood estimate**, the value of $p$ that makes the observed data most probable. Its standard error is $\sqrt{p(1-p)/n}$.

Since $\sigma$ and $p$ are unknown, we plug in estimates: the **estimated standard error** of the mean is $s/\sqrt n$ and of a proportion is $\sqrt{\hat p(1 - \hat p)/n}$.

### Confidence intervals

A point estimate gives no sense of its precision. A **confidence interval** (CI) is a range computed from the data. By the central limit theorem, $\bar X$ is approximately $N(\mu, \sigma^2/n)$, so $\bar X$ lies within $1.96$ standard errors of $\mu$ with probability about $0.95$. Turning this around gives the **95% confidence interval**

$$\bar x \pm 1.96\,\frac{s}{\sqrt n}.$$

For other levels replace $1.96$ by the matching normal quantile: about $1.645$ for 90% and $2.576$ for 99%. For a proportion the usual (Wald) interval is

$$\hat p \pm 1.96\sqrt{\frac{\hat p(1 - \hat p)}{n}}.$$

It is unreliable when $n$ is small or $\hat p$ is near 0 or 1 (it can even leave $[0, 1]$).

**Small samples.** When $n$ is small and the data are roughly normal, replace $1.96$ by a critical value of the Student $t$ distribution with $n - 1$ degrees of freedom, which is larger: about $2.262$ for $n = 10$ and $2.064$ for $n = 25$. The $t$ interval accounts for the extra uncertainty from estimating $\sigma$ by $s$.

### Interpreting a confidence level

The parameter is fixed; the interval is random. "95% confidence" is a statement about the **procedure**: if you repeated the whole sampling process many times, about 95% of the intervals built this way would contain the true value. It does **not** mean that a particular computed interval contains $\mu$ with probability 95%, nor that 95% of the data lie in it. A wider interval comes from a higher confidence level, more variable data or a smaller sample; quadrupling $n$ halves the width.

### The bootstrap

When no simple formula exists (for a median, say), the **bootstrap** resamples the observed data *with replacement* many times, recomputes the statistic on each resample, and uses the spread of those values, for example their 2.5th and 97.5th percentiles, as an interval. It is easy to program and works for many statistics, but it still needs a representative sample.

@example
title: A confidence interval for a mean
problem: A sample of $n = 25$ page-load times has mean $12.4$ s and sample standard deviation $3$ s. Give an approximate 95% confidence interval for the true mean.
step: The estimated standard error is $s/\sqrt{n} = 3/5 = 0.6$.
step: The margin of error is $1.96 \times 0.6 = 1.176$.
step: The interval is $12.4 \pm 1.176$, that is $(11.224,\ 13.576)$.
step: With only 25 observations a $t$ interval is more appropriate: the critical value is $2.064$, which gives $12.4 \pm 1.238$, or about $(11.16,\ 13.64)$, slightly wider.
answer: about $(11.22,\ 13.58)$ with the normal approximation

@example
title: A confidence interval for a proportion
problem: In an experiment, 90 of 200 visitors click a button. Give an approximate 95% confidence interval for the true click rate.
step: $\hat p = 90/200 = 0.45$.
step: The estimated standard error is $\sqrt{0.45 \cdot 0.55/200} = \sqrt{0.0012375} \approx 0.0352$.
step: The margin of error is $1.96 \times 0.0352 \approx 0.069$.
step: The interval is $0.45 \pm 0.069$, about $(0.381,\ 0.519)$.
answer: about $(0.381,\ 0.519)$

@mistakes
- Dividing by $n$ instead of $n - 1$ for the sample variance, which underestimates the population variance.
- Reading a 95% interval as "95% probability that this interval contains the parameter", or as the range containing 95% of the observations.
- Using the standard deviation of the data where the standard error $s/\sqrt{n}$ belongs when describing the uncertainty of a mean.
- Using the Wald interval for a proportion with very few successes or failures.

model:
```python
import math


def mean_confidence_interval(data, z=1.96):
    n = len(data)
    if n < 2:
        raise ValueError("need at least two values")
    mean = sum(data) / n
    var = sum((x - mean) ** 2 for x in data) / (n - 1)
    margin = z * math.sqrt(var / n)
    return (mean - margin, mean + margin)
```
hint: Compute the mean, then the sample variance with divisor `n - 1`.
hint: The margin is `z * sqrt(var / n)`; return `(mean - margin, mean + margin)`.
solution: Check the length first, compute the mean and the unbiased sample variance, and form the margin `z * sqrt(var / n)`. For `[10, 12, 14, 16, 18]` the mean is 14, $s^2 = 10$, the standard error is $\sqrt{10/5} \approx 1.414$ and the margin is about $2.772$.

model:
```python
import math


def proportion_ci(successes, n, z=1.96):
    if n <= 0 or successes < 0 or successes > n:
        raise ValueError("invalid counts")
    p = successes / n
    margin = z * math.sqrt(p * (1 - p) / n)
    return (max(0.0, p - margin), min(1.0, p + margin))
```
hint: Validate the arguments first, then compute `p = successes / n`.
hint: The margin is `z * sqrt(p * (1 - p) / n)`. Clip the ends with `max(0.0, ...)` and `min(1.0, ...)`.
solution: After validation, compute the Wald margin and clip. With 1 success in 10 the raw interval's low end is negative ($0.1 - 0.186$), so it is clipped to 0.0; this shows why the Wald interval is poor for small counts.
