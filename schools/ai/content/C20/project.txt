## Week-by-week review

**Weeks 1 and 2: images and filters.** An image is an array: `img[r][c]`, row-major, 8-bit values; color images have channels. Gray from RGB: $Y = 0.299R + 0.587G + 0.114B$. Point operations: threshold, contrast stretch $(p - p_{\min})/(p_{\max} - p_{\min}) \cdot 255$, histogram equalization. Filtering is correlation, $\sum I(r+i, c+j)K(i,j)$; convolution flips the kernel. Valid output $(H - k + 1)$; with padding $p$ and stride $s$, $\lfloor (H + 2p - k)/s \rfloor + 1$. Box and Gaussian blur, unsharp mask $I + a(I - \text{blur})$, median filter.

**Weeks 3 and 4: edges, features, CNNs.** Sobel $G_x, G_y$, magnitude $\sqrt{G_x^2 + G_y^2}$, direction $\operatorname{atan2}(G_y, G_x)$. Harris response $\det\mathbf{M} - k(\operatorname{trace}\mathbf{M})^2$: corner positive, edge negative, flat near 0. Descriptor matching with the ratio test. A conv layer has $C_{\text{out}}(C_{\text{in}}k_hk_w + 1)$ parameters; ReLU, max pooling, flatten, softmax; receptive field $r_l = r_{l-1} + (k_l - 1)j_{l-1}$.

**Weeks 5 and 6: training and boxes.** Label-preserving augmentation (flip a box: $(W - x_2, y_1, W - x_1, y_2)$), standardization with training-set statistics, mixup, schedules, early stopping with patience, transfer learning. Boxes $(x_1, y_1, x_2, y_2)$, exclusive versus inclusive edges; IoU $= \text{inter}/(\text{area}_A + \text{area}_B - \text{inter})$; anchors; encoding $t_x, t_y, \log(g_w/a_w), \log(g_h/a_h)$.

**Weeks 7 and 8: NMS, metrics, segmentation.** Greedy NMS (sort by score, suppress IoU strictly above $\tau$, per class). TP/FP/FN by greedy matching; precision, recall, $F_1$; AP with the precision envelope; mAP and COCO-style averaging over IoU thresholds. Semantic versus instance versus panoptic segmentation; mask IoU, Dice, mIoU; connected components.

**Weeks 9 and 10: transformers and generation.** Patchify: $N = (H/p)(W/p)$ patches, $+1$ class token; embedding $\mathbf{W}\mathbf{x} + \mathbf{b}$ plus positions; attention $\operatorname{softmax}(\mathbf{q}^\top\mathbf{k}/\sqrt{d})$. InfoNCE; masked image modeling. Diffusion: $\bar{\alpha}_t = \prod(1 - \beta_s)$, $\mathbf{x}_t = \sqrt{\bar\alpha}\,\mathbf{x}_0 + \sqrt{1 - \bar\alpha}\,\boldsymbol\epsilon$; risks and layered safeguards.

**Weeks 11 and 12: geometry, robustness, responsibility.** Pinhole $u = fX/Z + c_x$, extrinsics $\mathbf{R}\mathbf{P} + \mathbf{t}$, stereo $Z = fB/d$, depth error $\approx Z^2\Delta d/(fB)$, block matching. Subgroup accuracy, FPR/FNR, intervals $1.96\sqrt{\hat p(1 - \hat p)/n}$, shift, spurious correlations, adversarial examples, model cards, face analysis risks.

## Common errors

Mixing `img[r][c]` with $(x, y)$; forgetting to flip for convolution; skipping the clamp at 0 in IoU; using inclusive and exclusive edges together; running NMS across classes; counting a duplicate as a true positive; averaging group accuracies instead of pooling.

model:
```python
def find_boxes(img, thr):
    """Bounding boxes of 4-connected components of pixels >= thr."""
    h, w = len(img), len(img[0])
    seen = [[False] * w for _ in range(h)]
    boxes = []
    for r in range(h):
        for c in range(w):
            if img[r][c] >= thr and not seen[r][c]:
                seen[r][c] = True
                stack = [(r, c)]
                x1 = x2 = c
                y1 = y2 = r
                while stack:
                    y, x = stack.pop()
                    x1, x2 = min(x1, x), max(x2, x)
                    y1, y2 = min(y1, y), max(y2, y)
                    for dy, dx in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                        ny, nx = y + dy, x + dx
                        if (0 <= ny < h and 0 <= nx < w
                                and img[ny][nx] >= thr and not seen[ny][nx]):
                            seen[ny][nx] = True
                            stack.append((ny, nx))
                boxes.append((x1, y1, x2 + 1, y2 + 1))
    return boxes
```
hint: Scan for an unvisited foreground pixel, flood-fill its component while tracking the smallest and largest row and column, and add one to the largest ones for the exclusive edges.
solution: This combines thresholding (week 1), connected components (week 8) and the box convention (week 6). The diagonal test shows that 4-connectivity keeps diagonal neighbors apart, and the exclusive-edge convention makes a one-pixel component the box $(x, y, x + 1, y + 1)$.

@exam self
prompt: A team builds a detector for bright rectangular parts on a conveyor belt using thresholding and connected components. On a test day it finds that the detector merges two parts that touch at a corner into one box, reports a false part whenever a bright speck of dust appears, and misses parts when the lighting is dimmer. For each of the three failures, explain its cause in terms of the method, propose a fix within the classical pipeline, and explain how a convolutional detector trained with augmentation would address it and what it would not solve.
hint: Think about connectivity and the threshold, then about what a learned filter and training data can add.
solution: Merged parts: 8-connectivity treats diagonal neighbors as connected, so corner-touching parts form one component; using 4-connectivity separates corner-touching parts but not parts that share an edge, and a classical fix is to add a shape test (compare component area with the expected part size and split large components, for example with erosion or a distance transform). A convolutional detector with anchors predicts one box per object from learned appearance, so two touching parts produce two boxes after non-maximum suppression, as long as their IoU stays below the suppression threshold; heavily overlapping parts remain hard. False part from dust: a single bright pixel passes the threshold and forms a one-pixel component; fix with a minimum area filter, a median filter before thresholding, or a size test. A network learns to ignore specks when it sees such examples labeled as background, but it can also learn shortcuts and produce confident false positives on kinds of dust it has never seen, so the training data must include them. Dim lighting: a fixed threshold ignores local contrast, so dimmer parts fall below it; fix with a threshold relative to the local background (adaptive thresholding) or by normalizing brightness. A network trained with brightness and contrast augmentation, and with data from dim conditions, becomes less sensitive to illumination, but it will still fail in lighting conditions far outside the training range, so it must be evaluated under shift, with results reported per lighting condition.
