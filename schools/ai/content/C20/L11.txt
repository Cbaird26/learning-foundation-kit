@article
A photograph throws away one dimension: every point along a ray from the camera lands on the same pixel. Yet two eyes, or two cameras, recover depth. The geometry of how 3-D points become pixels, and how two views undo that loss, is the subject of **3-D vision**.

### Conventions used in this course

In **camera coordinates** the origin is the camera center, $X$ points right, $Y$ points down, and $Z$ points forward along the optical axis, so visible points have $Z > 0$. A pixel is $(u, v)$ with $u$ the column and $v$ the row, measured from the top-left corner of the image. The **principal point** $(c_x, c_y)$ is where the optical axis meets the image. Units: the focal length $f$ is in pixels, 3-D positions in meters.

### The pinhole model

In the **pinhole camera**, a point $(X, Y, Z)$ in camera coordinates projects to

$$u = f\,\frac{X}{Z} + c_x, \qquad v = f\,\frac{Y}{Z} + c_y.$$

Farther points (larger $Z$) land closer to the principal point, which is perspective: a person twice as far away appears half as large. Doubling all of $X, Y, Z$ leaves the pixel unchanged, so one image cannot tell a small near object from a large far one: this is **scale ambiguity**. The field of view across the image width $W$ is $2\arctan\!\big(W/(2f)\big)$; for $W = 640$ and $f = 500$ it is about $65.2^\circ$.

In homogeneous coordinates the projection becomes a matrix product: $\lambda\,(u, v, 1)^\top = \mathbf{K}\,(X, Y, Z)^\top$ with the **intrinsic matrix** $\mathbf{K} = \begin{bmatrix} f & 0 & c_x \\ 0 & f & c_y \\ 0 & 0 & 1 \end{bmatrix}$ and $\lambda = Z$. For $f = 500$, $(c_x, c_y) = (320, 240)$ and the point $(1, 0.5, 5)$, $\mathbf{K}\mathbf{X} = (500 + 1600,\ 250 + 1200,\ 5) = (2100, 1450, 5)$, and dividing by 5 gives the pixel $(420, 290)$.

A point known in **world coordinates** is first moved into camera coordinates by the **extrinsic parameters**, a rotation matrix $\mathbf{R}$ and a translation $\mathbf{t}$: $\mathbf{P}_c = \mathbf{R}\mathbf{P}_w + \mathbf{t}$. The full model is $\lambda \tilde{\mathbf{u}} = \mathbf{K}[\mathbf{R} \mid \mathbf{t}]\tilde{\mathbf{P}}_w$. Real lenses also bend straight lines, so calibration estimates distortion coefficients as well, from images of a known pattern such as a checkerboard.

### Stereo and depth

Two cameras with parallel axes, separated sideways by a **baseline** $B$, see the same point at different columns. The difference $d = u_{\text{left}} - u_{\text{right}}$ is the **disparity**, and by similar triangles

$$Z = \frac{f\,B}{d}.$$

Large disparity means a near point and disparity 0 means a point at infinity. With $f = 500$ pixels, $B = 0.1$ m and $d = 10$ pixels, $Z = 5$ m. Once $Z$ is known the point is recovered by **back-projection**: $X = (u - c_x)Z/f$ and $Y = (v - c_y)Z/f$. Differentiating $Z = fB/d$ shows that a disparity error $\Delta d$ gives a depth error of about $Z^2\,\Delta d/(fB)$: at $Z = 5$ it is $25/50 = 0.5$ m per pixel. Depth gets less precise quadratically with distance, and a longer baseline or longer focal length helps.

To find $d$ we need to know which pixel in the right image matches a given pixel in the left image. After **rectification** the match lies on the same row, so the search is one-dimensional. **Block matching** compares the window around the left pixel with windows in the right image at columns $c, c - 1, \dots, c - d_{\max}$ and picks the disparity with the smallest sum of squared differences (SSD). It fails in textureless regions (all windows look alike), at repeated patterns and near occlusions, where a point is visible in only one camera.

### Beyond two views

With many photos of a scene, **structure from motion** estimates camera poses and 3-D points together, and SLAM does so from a moving camera in real time. Neural radiance fields (NeRF; Mildenhall and colleagues, 2020) represent a scene as a network that gives color and density at each 3-D point and render new viewpoints by integrating along rays. A single image can also be used to guess depth: a network trained on many scenes learns cues such as size and perspective, but the scale ambiguity means the result is a guess unless the network has learned typical sizes.

### In code

```python
def project(P, f, cx, cy):
    """Project camera-coordinate point (X, Y, Z) with Z > 0 to a pixel."""
    X, Y, Z = P
    return (f * X / Z + cx, f * Y / Z + cy)

print(project((1.0, 0.5, 5.0), 500, 320, 240))
print(500 * 0.1 / 10)
```

step: Rotate: $\mathbf{R}\mathbf{P}_w = (0\cdot1 + 0\cdot0 + 1\cdot2,\ 0,\ -1\cdot 1 + 0 + 0) = (2, 0, -1)$.
step: Translate: $\mathbf{P}_c = (2, 0, -1) + (0, 0, 5) = (2, 0, 4)$. The depth is $4 > 0$, so the point is in front of the camera.
step: Project: $u = 500 \cdot 2/4 + 320 = 570$ and $v = 500 \cdot 0/4 + 240 = 240$.

@example
title: Depth from disparity and its error
problem: Cameras have $f = 700$ pixels and $B = 0.12$ m. A point has disparity $21$ pixels. Find its depth, and the depth change if the disparity is off by one pixel.
step: $Z = fB/d = 700 \cdot 0.12/21 = 84/21 = 4$ m.
step: With $d = 22$, $Z = 84/22 \approx 3.818$ m; with $d = 20$, $Z = 4.2$ m.
step: The first-order estimate is $Z^2\,\Delta d/(fB) = 16/84 \approx 0.19$ m per pixel, close to the actual changes of $0.18$ and $0.2$ m.
answer: $Z = 4$ m; a one-pixel disparity error changes it by about $0.19$ m.
@mistakes
- Projecting a point with $Z \le 0$: points behind the camera give meaningless pixels, so check the depth first.
- Mixing up the order of the extrinsic transform: first rotate and translate the world point into camera coordinates, then apply $\mathbf{K}$.
- Treating disparity as proportional to depth: disparity is inversely proportional ($Z = fB/d$), so equal disparity steps give very unequal depth steps.

```python
def project_points(points, f, cx, cy):
    """Pinhole projection; points at or behind the camera give None."""
    pixels = []
    for X, Y, Z in points:
        if Z <= 0:
            pixels.append(None)
        else:
            pixels.append((f * X / Z + cx, f * Y / Z + cy))
    return pixels
```
hint: Test the depth first; only divide by `Z` when it is positive.
solution: Points with `Z = 0` would divide by zero and points with negative `Z` project to a mirrored position, so both map to `None`. The output list keeps one entry per input point, in order.

```python
def world_to_pixel(Pw, R, t, f, cx, cy):
    """Extrinsic transform followed by pinhole projection."""
    Pc = [sum(R[i][j] * Pw[j] for j in range(3)) + t[i] for i in range(3)]
    if Pc[2] <= 0:
        return None
    return (f * Pc[0] / Pc[2] + cx, f * Pc[1] / Pc[2] + cy)
```
hint: Compute each coordinate of `R @ Pw + t` with a sum over the three columns, then check the depth before projecting.
solution: The rotation is applied before the translation, and the depth check uses the transformed point, not the original world point; the third test has a world point with positive `Z` that ends up behind the camera after the translation.

model:
```python
def match_disparity(left, right, r, c, half, max_d):
    """Disparity with the smallest SSD over a (2*half+1)^2 window."""
    width = len(right[0])
    best_d, best_ssd = None, None
    for d in range(max_d + 1):
        cc = c - d
        if cc - half < 0 or cc + half >= width:
            continue
        ssd = 0
        for i in range(-half, half + 1):
            for j in range(-half, half + 1):
                diff = left[r + i][c + j] - right[r + i][cc + j]
                ssd += diff * diff
        if best_ssd is None or ssd < best_ssd:
            best_d, best_ssd = d, ssd
    return best_d
```
hint: Loop over `d`, skip the shifts that fall outside the image, compute the SSD of the two windows, and keep the smallest with a strict comparison so ties keep the smaller `d`.
solution: Scanning disparities in increasing order and updating only on a strictly smaller SSD gives the tie rule. In the textureless test every shift matches equally well, so the smallest disparity wins, which shows why block matching cannot determine depth in flat regions.

@quiz ms
prompt: Which statements about the pinhole camera and stereo are true? Select all that apply.
choice*: Scaling all three coordinates $(X, Y, Z)$ of a point by the same positive factor leaves its pixel unchanged.
choice*: For a fixed disparity error, the depth error grows with the square of the depth.

hint: Check the projection formula for scaling, differentiate $Z = fB/d$ with respect to $d$, and recompute $Z$ for a doubled $f$.
solution: The ratios $X/Z$ and $Y/Z$ do not change when all coordinates are scaled, which is scale ambiguity. $\Delta Z \approx Z^2\,\Delta d/(fB)$. Flat windows give equal SSD at many disparities. Doubling $f$ at a fixed disparity doubles $Z = fB/d$, not halves it.
