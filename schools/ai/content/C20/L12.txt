@article
A model scores 94% accuracy on its test set. Is it good? That depends on who is in the test set and what the world looks like when the model is used. This lesson is about asking those two questions with numbers.

### Conventions used in this course

A test set is given as three parallel lists of equal length: `preds` (predicted labels), `labels` (true labels) and `groups` (a group name for each example, for instance a lighting condition, a camera type or a demographic group recorded for auditing). For binary tasks the labels are 0 and 1, with 1 the positive class.

### Evaluating by subgroup

Overall accuracy averages over the whole test set, so a small group barely moves it. Suppose group A has 200 examples with 92% accuracy and group B has 50 examples with 80%. The overall accuracy is $(184 + 40)/250 = 89.6\%$, which looks fine, while group B's error rate is 20%, two and a half times group A's 8%. The remedy is **disaggregated evaluation**: report each subgroup's accuracy, its error rates, and the gap between best and worst group. In binary tasks the error rates differ in kind: the **false positive rate** $\mathrm{FP}/(\mathrm{FP} + \mathrm{TN})$ and the **false negative rate** $\mathrm{FN}/(\mathrm{FN} + \mathrm{TP})$ can differ between groups even when accuracy is similar, and which error is more harmful depends on the use (a wrongly flagged person versus a missed detection).

Small groups give uncertain estimates. With $n$ examples and accuracy $\hat{p}$, a normal-approximation 95% interval is $\hat{p} \pm 1.96\sqrt{\hat{p}(1 - \hat{p})/n}$. For $\hat{p} = 0.85$ and $n = 40$ the half-width is $0.111$: the true accuracy could plausibly be anywhere from 74% to 96%. A gap between two small groups may be noise, and a missing gap may be hidden by it, so report group sizes and intervals. Several fairness criteria (equal error rates across groups, equal predictive value across groups) cannot in general all hold at once when the groups have different base rates (Kleinberg, Mullainathan and Raghavan, 2016; Chouldechova, 2017), so choosing which to prioritize is a judgment that belongs to the people affected by the system as well as the engineers.

### Robustness

**Distribution shift** means the data in use differ from the training data: different cameras, weather, lighting, geography or time. Models can be brittle to **corruptions** such as noise, blur and compression, which benchmarks apply to test images at several severities. **Spurious correlations** are shortcuts: if photographs of one class were mostly taken against a certain background, a network may learn the background, and fail when the correlation breaks; disaggregating by background exposes this.

**Adversarial examples** (Szegedy and colleagues, 2013) are inputs with small, deliberately chosen perturbations that change a model's prediction. The fast gradient sign method (Goodfellow, Shlens and Szegedy, 2014) moves each input coordinate by $\varepsilon$ in the direction that most increases the loss. A toy example makes the mechanism visible: take a linear classifier on two features with score $s = \mathbf{w}^\top\mathbf{x} + b$ and weights $\mathbf{w} = (1, -2)$, $b = 0$, and the input $\mathbf{x} = (1, 0.2)$, with $s = 0.6 > 0$. Moving each coordinate by $0.3$ against the sign of its weight gives $\mathbf{x}' = (0.7, 0.5)$ and $s' = -0.3 < 0$: the class flips although no coordinate moved by more than 0.3. In high dimension the effect is stronger, because many tiny changes add up. Defenses such as adversarial training, input preprocessing and certified bounds reduce the problem in some settings but none is a complete solution, and a defense should be evaluated against attacks designed to defeat it. We study these ideas only on tiny models; attacking a deployed system you do not own is both unethical and often illegal.

### Face analysis and responsible use

Three tasks are often confused. **Face detection** finds where faces are. **Face recognition** compares faces: *verification* asks whether two images show the same person (1-to-1), and *identification* searches a gallery for a match (1-to-N). **Attribute or emotion inference** guesses properties from a face. Published audits have documented that error rates of face analysis systems can differ across demographic groups: a 2018 study (Buolamwini and Gebru) of commercial gender-classification systems found the largest errors for darker-skinned women, and a 2019 evaluation by the US National Institute of Standards and Technology found that false positive and false negative rates in face recognition varied across algorithms and demographic groups. Whether the scientific basis for inferring inner emotional states from facial expressions is sound is contested among researchers, which is one reason regulators treat that use cautiously.

Informed people disagree about face recognition by the police. Supporters point to finding missing persons and suspects of serious crimes; critics point to mass surveillance, chilling effects on assembly and speech, and the harms of misidentification. The law differs by place. The EU AI Act prohibits (from 2 February 2025) several practices, among them building face-recognition databases by untargeted scraping of images, inferring emotions in workplaces and schools (with narrow exceptions) and real-time remote biometric identification in public spaces for law enforcement (with narrow exceptions); other uses of biometric identification are classed as high-risk. Laws and standards change, so check the current text.

Good practice around vision systems includes: asking first whether the system is needed and who bears the cost of its errors; collecting data with consent and minimizing what is kept; documenting the intended use and limits in a **model card** (Mitchell and colleagues, 2019) and the data in a datasheet for the data set (Gebru and colleagues); testing by subgroup and under shift before deployment and monitoring afterward; keeping a human able to review and overturn consequential decisions; and giving affected people a way to contest outcomes.

### In code

```python
def subgroup_accuracy(preds, labels, groups):
    """Return {group: accuracy} for parallel lists of predictions,
    true labels and group names."""
    correct, total = {}, {}
    for p, y, g in zip(preds, labels, groups):
        total[g] = total.get(g, 0) + 1
        correct[g] = correct.get(g, 0) + (1 if p == y else 0)
    return {g: correct[g] / total[g] for g in total}

preds = [1, 0, 1, 1, 0, 0]
labels = [1, 0, 0, 1, 0, 1]
groups = ['x', 'x', 'x', 'y', 'y', 'y']
print(subgroup_accuracy(preds, labels, groups))
```

With pandas this is `df.groupby('group').apply(lambda d: (d.pred == d.label).mean())`; the loop shows what it does.

title: Disaggregated accuracy and an interval
problem: A test set has 100 examples of group A (90 correct) and 25 of group B (18 correct). Report the overall accuracy, each group's accuracy, and a 95% normal-approximation interval half-width for group B.
step: Overall: $(90 + 18)/125 = 108/125 = 0.864$. Group A: $0.9$. Group B: $18/25 = 0.72$.
step: The gap between groups is $0.9 - 0.72 = 0.18$, although the overall accuracy of 86.4% hides it.
step: Half-width for group B: $1.96\sqrt{0.72 \cdot 0.28/25} = 1.96\sqrt{0.008064} = 1.96 \cdot 0.0898 \approx 0.176$.
step: The interval is about $0.72 \pm 0.176$, from 54% to 90%: with only 25 examples the gap is suggestive, but the interval for group B reaches almost to group A's 90%, so more data from group B is needed before concluding.
answer: Overall 0.864, A 0.90, B 0.72, with a half-width of about 0.176 for B.
@example
title: A toy adversarial perturbation
problem: A linear classifier has $\mathbf{w} = (2, -1)$, $b = -1$ and predicts class 1 when $s = \mathbf{w}^\top\mathbf{x} + b > 0$. For $\mathbf{x} = (1.5, 0.5)$, find the smallest budget among $\varepsilon \in \{0.25, 0.5, 1\}$ for which moving each coordinate by $\varepsilon$ against the sign of its weight flips the class.
step: The score is $2(1.5) - 0.5 - 1 = 1.5 > 0$, so the class is 1. To lower the score, decrease $x_1$ (its weight is positive) and increase $x_2$ (its weight is negative).
step: Moving by $\varepsilon$ changes the score by $-\varepsilon\,(|2| + |-1|) = -3\varepsilon$.
step: The new score is $1.5 - 3\varepsilon$: for $\varepsilon = 0.25$ it is $0.75$, for $0.5$ it is $0$ (not greater than 0, so the class becomes 0), and for 1 it is $-1.5$.
step: The smallest budget in the list that flips the class is $\varepsilon = 0.5$, which sets the score exactly to the decision boundary.
answer: $\varepsilon = 0.5$.
@mistakes
- Reporting only overall accuracy: a small group barely changes it, so a large subgroup gap can hide behind a high average.
- Reading a gap between two small groups as proof of bias, or no gap as proof of fairness, without group sizes or intervals.
- Treating a defense against one attack as a guarantee: a defense must be tested against attacks adapted to it, and none is complete.

```python
def group_error_rates(preds, labels, groups):
    """Per-group (false positive rate, false negative rate)."""
    stats = {}
    for p, y, g in zip(preds, labels, groups):
        s = stats.setdefault(g, [0, 0, 0, 0])  # fp, neg, fn, pos
        if y == 0:
            s[1] += 1
            s[0] += 1 if p == 1 else 0
        else:
            s[3] += 1
            s[2] += 1 if p == 0 else 0
    out = {}
    for g, (fp, neg, fn, pos) in stats.items():
        out[g] = (fp / neg if neg else None, fn / pos if pos else None)
    return out
```
hint: Keep four counts per group (false positives, negatives, false negatives, positives) and divide at the end, guarding against zero denominators.
solution: The two rates have different denominators: negatives for the false positive rate and positives for the false negative rate. A group with no examples of one kind has an undefined rate, which the last two tests check.

model:
```python
def fgsm_linear(w, b, x, eps):
    """One signed-gradient step on a linear classifier's score."""
    def score(v):
        return sum(wi * vi for wi, vi in zip(w, v)) + b

    def sign(a):
        return (a > 0) - (a < 0)

    s = score(x)
    y = 1 if s > 0 else -1
    x_adv = [xi - eps * y * sign(wi) for xi, wi in zip(x, w)]
    return x_adv, (score(x_adv) > 0) != (s > 0)
```
hint: Compute the score, set `y` from its sign, move every coordinate by `eps` against `y * sign(w[i])`, and compare the classes before and after.
solution: For a linear model the score changes by `-eps * y * sum(abs(w))` under this step, which is the largest change possible with each coordinate moved by at most `eps`. A coordinate with weight 0 does not move, as the third test shows, and the fourth test attacks an input that starts in class 0.

model:
```python
def worst_group_report(preds, labels, groups):
    """Overall accuracy, the worst group and the best-minus-worst gap."""
    total, correct = {}, {}
    for p, y, g in zip(preds, labels, groups):
        total[g] = total.get(g, 0) + 1
        correct[g] = correct.get(g, 0) + (1 if p == y else 0)
    acc = {g: correct[g] / total[g] for g in total}
    overall = sum(correct.values()) / sum(total.values())
    worst = min(sorted(acc), key=lambda g: acc[g])
    return overall, worst, max(acc.values()) - acc[worst]
```
hint: Count correct predictions and examples per group, then take the minimum over the groups in sorted order so ties go to the alphabetically first name.
solution: `min` returns the first minimal element it meets, so iterating over sorted group names breaks ties alphabetically. The overall accuracy pools all examples, which is not the mean of group accuracies when the groups differ in size.
