@article
A model with 7 billion parameters needs 14 GB in 16-bit precision just for its weights, more than many devices have. Three standard techniques make models smaller and faster: **quantization** stores numbers with fewer bits, **pruning** removes weights, and **distillation** trains a small model to imitate a large one. Each saves resources and each costs some accuracy, so each must be measured.

### Quantization

Memory scales with bits per parameter. Taking 1 GB as $10^9$ bytes, a model with $7 \times 10^9$ parameters needs 28 GB in fp32 (4 bytes), 14 GB in fp16 (2 bytes), 7 GB in int8 (1 byte) and 3.5 GB at 4 bits (0.5 byte), plus a small overhead for scale factors.

**Symmetric quantization** maps real weights to signed integers with one **scale** $s$ per tensor (or per row or channel). With $b$ bits the integers run from $-q_{\max}$ to $q_{\max}$, where $q_{\max} = 2^{b-1} - 1$ (127 for 8 bits, 7 for 4 bits). Choose $s = \max_i |w_i| / q_{\max}$, so the largest weight maps to $\pm q_{\max}$, and store

$$q_i = \operatorname{round}(w_i / s), \qquad \hat{w}_i = s\, q_i .$$

Rounding to the nearest integer moves each weight by at most $s/2$, so the **quantization error** satisfies $|w_i - \hat{w}_i| \le s/2$. With weights $0.5, -0.3, 0.05, -1.6$ and $b = 8$: $s = 1.6/127 \approx 0.0126$, the integers are $40, -24, 4, -127$, and the largest error is on $0.5$, which becomes $0.5039$, an error of $0.0039 \le s/2 = 0.0063$.

```python
def quantize(weights, bits=8):
    """Symmetric quantization; returns (integers, scale)."""
    qmax = 2 ** (bits - 1) - 1
    scale = max(abs(w) for w in weights) / qmax
    q = [max(-qmax, min(qmax, round(w / scale))) for w in weights]
    return q, scale

def dequantize(q, scale):
    return [v * scale for v in q]

q, s = quantize([0.5, -0.3, 0.05, -1.6])
print(q, round(s, 4))          # [40, -24, 4, -127] 0.0126
```

Two caveats follow from the formula. One large outlier weight raises $s$ and so raises the error for all the other weights, which is why per-channel scales help. And fewer bits mean a larger $s$: going from 8 bits to 4 multiplies $s$ by $127/7 \approx 18$. **Asymmetric quantization** adds a **zero point** to represent ranges that are not centered at zero, such as activations after a ReLU. Quantization after training (**post-training quantization**) needs no retraining; **quantization-aware training** simulates rounding during training to recover accuracy at very low bit widths.

### Pruning

**Magnitude pruning** sets the smallest-magnitude weights to zero, on the heuristic that they matter least; a model is usually fine-tuned afterwards. The **sparsity** is the fraction of weights that are zero. **Unstructured** pruning zeros individual weights, which saves storage in a sparse format but, on typical dense hardware, does not by itself make a matrix multiplication faster, since the zeros are still multiplied unless sparse kernels are used. **Structured** pruning removes whole rows, channels, attention heads or layers, which shrinks the dense matrices and speeds up ordinary hardware, usually at a larger accuracy cost for the same number of parameters removed.

### Distillation

In **knowledge distillation** (Hinton, Vinyals and Dean, 2015) a small **student** is trained on the outputs of a large **teacher**. The teacher's logits $z_i$ are turned into soft targets with a **temperature** $T$:

$$p_i = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}} .$$

With $T = 1$ this is the usual softmax. A higher $T$ flattens the distribution and reveals which wrong classes the teacher finds similar to the right one, information a hard label does not carry. For logits $(2, 1, 0)$ the probabilities are $(0.665, 0.245, 0.090)$ at $T = 1$ and $(0.506, 0.307, 0.186)$ at $T = 2$. The student is trained on a mix of the cross-entropy to the soft targets (scaled by $T^2$ to keep gradient sizes comparable) and the ordinary cross-entropy to the true labels.

### Measure everything

Compare each compressed model with the original on held-out data, and also on latency and memory on the target hardware: a smaller model that is not faster in practice has not solved the problem.

title: Four-bit quantization and its error
problem: Quantize the weights $0.62, -0.2, 0.34, -1.4$ symmetrically to 4 bits. Give the scale, the integers, the dequantized weights, the largest error and the mean squared error.
step: With $b = 4$, $q_{\max} = 2^3 - 1 = 7$. The largest magnitude is $1.4$, so $s = 1.4/7 = 0.2$.
step: Integers: $0.62/0.2 = 3.1 \to 3$; $-0.2/0.2 = -1$; $0.34/0.2 = 1.7 \to 2$; $-1.4/0.2 = -7$.
step: Dequantized values $s q_i$: $0.6, -0.2, 0.4, -1.4$.
step: Errors $|w_i - \hat{w}_i|$: $0.02, 0, 0.06, 0$. The largest is $0.06$, which is below the bound $s/2 = 0.1$.
step: Mean squared error: $(0.02^2 + 0 + 0.06^2 + 0)/4 = (0.0004 + 0.0036)/4 = 0.001$.
answer: Scale 0.2, integers $3, -1, 2, -7$, largest error 0.06, mean squared error 0.001.
@mistakes
- Quantizing with a scale chosen from the data you later test on, or using a scale computed per batch at serving time without checking it matches calibration.
- Letting one outlier weight set the scale for a whole tensor, which wastes most of the integer range; use per-channel scales or clip outliers.
- Expecting unstructured pruning to speed up dense matrix multiplication; zeros are still multiplied unless the hardware and library use sparse kernels.
- Reporting only accuracy for a compressed model and not measuring latency and memory on the target hardware.

model:
```python
def quant_error(weights, bits):
    """Max absolute error and mean squared error of symmetric quantization."""
    qmax = 2 ** (bits - 1) - 1
    biggest = max(abs(w) for w in weights)
    if biggest == 0:
        return 0.0, 0.0
    scale = biggest / qmax
    max_err = 0.0
    total = 0.0
    for w in weights:
        q = max(-qmax, min(qmax, round(w / scale)))
        err = abs(w - q * scale)
        max_err = max(max_err, err)
        total += err * err
    return max_err, total / len(weights)
```
hint: Compute the scale from the largest magnitude, quantize and dequantize each weight, and keep the largest error and the sum of squared errors in a loop.
solution: The scale makes the largest weight map exactly to the top integer, so its error is zero; every other weight is off by at most half a scale step. Fewer bits mean a larger scale and larger errors, which the 8-, 4- and 2-bit tests show; the all-zero case needs a guard because the scale would be zero.

```python
def prune_magnitude(weights, sparsity):
    """Zero the smallest-magnitude weights; ties are pruned by lower index."""
    k = int(sparsity * len(weights))
    order = sorted(range(len(weights)), key=lambda i: abs(weights[i]))
    pruned = set(order[:k])
    return [0.0 if i in pruned else w for i, w in enumerate(weights)]
```
hint: Sort the indices by absolute value (Python's sort is stable, so ties keep index order), and zero the first `k` of them.
solution: A stable sort of the indices by `abs(weight)` puts the smallest entries first and keeps lower indices ahead on ties, so zeroing the first `k` implements the rule; the second test checks the tie rule. Building a new list leaves the input untouched.

model:
```python
import math

def soft_targets(logits, temperature):
    """Temperature softmax with the maximum subtracted for stability."""
    top = max(logits)
    exps = [math.exp((z - top) / temperature) for z in logits]
    total = 0.0
    for e in exps:
        total += e
    return [e / total for e in exps]
```
hint: Divide each shifted logit by the temperature inside `exp`, then divide each exponential by their sum.
solution: Subtracting the largest logit changes no probability (it cancels in the ratio) but keeps every exponent at or below zero, so a logit of 1000 does not overflow, which the third test checks. A higher temperature divides the gaps between logits, flattening the distribution, as the second test shows.

@quiz self
prompt: You have a trained classifier and need to cut its memory by about 4 times and its latency on a given device. Compare quantization to 8 bits, unstructured magnitude pruning, and distillation into a smaller student as ways to do this, and describe what you would measure to decide.
hint: Consider what each method changes (bits, zeros, architecture) and which of them is guaranteed to reduce dense computation.
solution: Quantizing from fp32 to int8 cuts weight memory by 4 times with no change in architecture, usually with small accuracy loss, and speeds up inference if the hardware has fast integer kernels; it is the lowest-effort option. Unstructured pruning saves memory only through a sparse format, which stores an index with each remaining weight: with a 32-bit index per fp32 value, 75% sparsity keeps a quarter of the weights at twice the cost each, only a 2 times reduction, and a 4 times reduction needs 87.5% sparsity (smaller indices or bitmask formats need less). It gives no latency gain on dense hardware without sparse kernels, so it helps memory more than speed. Distillation into a student with fewer layers or smaller width reduces both memory and computation on any hardware, but needs a training run and a teacher, and the student may lose accuracy. To decide, measure on a held-out set the accuracy (and per-slice accuracy) of the original and each compressed model, plus memory and latency percentiles on the target device with realistic batch sizes. A reasonable plan is to try 8-bit quantization first and distill if the latency target is still missed.
