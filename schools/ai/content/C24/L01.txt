@article
A mail service wants to "reduce spam". That sentence is not yet a machine learning problem. To make it one, you must say what the model sees (the **input**, for example the text and sender of an email), what it must output (the **target**: spam or not spam), when the prediction is needed (before delivery, within 50 milliseconds), and what a mistake costs. Machine learning engineering starts here, because every later choice (data, model, monitoring) inherits the framing.

### Objective, loss and metric are three different things

The **training loss** is what the optimizer minimizes, such as cross-entropy; it must be differentiable. The **evaluation metric** is what you report to decide whether a model is good enough, such as recall at a fixed precision; it need not be differentiable. The **business objective** is what the organization cares about, such as fewer user complaints. They are related but not identical, and a model can improve the first two while the third stays flat. Write all three down.

### A concrete case

Suppose a validation set holds 200 emails, of which 20 are spam. A model flags some emails; comparing flags with the truth gives the **confusion matrix**:

| | actual spam | actual not spam |
|---|---|---|
| flagged | TP = 12 | FP = 6 |
| not flagged | FN = 8 | TN = 174 |

From these four counts:

$$\text{accuracy} = \frac{TP + TN}{n} = \frac{186}{200} = 0.93,\quad \text{precision} = \frac{TP}{TP + FP} = \frac{12}{18} \approx 0.667,\quad \text{recall} = \frac{TP}{TP + FN} = \frac{12}{20} = 0.6 .$$

The **F1 score** is the harmonic mean of precision $P$ and recall $R$: $F_1 = 2PR/(P + R) \approx 0.632$. Accuracy of 0.93 sounds strong, but a **baseline** that never flags anything is right on 180 of 200 emails: accuracy $0.90$. The model's gain over the baseline is 3 points, and the baseline has recall 0. Always compute a trivial baseline first (the majority class, the previous day's value, a hand-written rule, a linear model) so that you know what "good" means.

### Metrics should carry costs

If a missed spam message costs the user 1 unit of annoyance and a wrongly hidden real message costs 10, the two errors are not equal. A simple **expected cost** is $C = c_{FP}\,FP + c_{FN}\,FN$. With $c_{FP} = 10$ and $c_{FN} = 1$, the model above costs $10 \cdot 6 + 1 \cdot 8 = 68$ units, never flagging costs $20$, and flagging everything costs $1800$. Here the baseline that never flags wins. A model must beat the baselines on the metric that reflects costs, not merely on accuracy.

### Thresholds are decisions

Most models output a score. A **threshold** $t$ turns it into a decision: predict positive when the score is at least $t$. Raising $t$ trades recall for precision. Choose $t$ on **validation data**, never on the test set: the test set exists to give an unbiased estimate of the final system, and once you tune on it, it is no longer unbiased.

### In code

```python
def confusion_counts(preds, labels):
    """Return (tp, fp, fn, tn) for 0/1 predictions and 0/1 labels."""
    tp = fp = fn = tn = 0
    for p, y in zip(preds, labels):
        if p == 1 and y == 1:
            tp += 1
        elif p == 1:
            fp += 1
        elif y == 1:
            fn += 1
        else:
            tn += 1
    return tp, fp, fn, tn

labels = [1, 0, 0, 1, 0, 0, 0, 0]
always_no = [0] * len(labels)
print(confusion_counts(always_no, labels))   # (0, 0, 2, 6)
```

Practitioners compute the same counts with a metrics library, but writing them out once makes clear what each number means and which cases need care (a model that flags nothing has precision $0/0$).
@example
title: Metrics and a baseline from counts
problem: On 500 validation cases, 50 are positive. A model gives TP = 30, FP = 10 and FN = 20. Compute accuracy, precision, recall and F1, and compare accuracy with the baseline that always predicts the negative class.
step: Find the missing count: $TN = 500 - 30 - 10 - 20 = 440$.
step: Accuracy is $(30 + 440)/500 = 0.94$. Precision is $30/(30 + 10) = 0.75$. Recall is $30/(30 + 20) = 0.6$.
step: F1 is $2 (0.75)(0.6)/(0.75 + 0.6) = 0.9/1.35 \approx 0.667$.
step: The always-negative baseline is right on the 450 negatives, so its accuracy is $450/500 = 0.90$. The model's accuracy gain is only 4 points, but the baseline finds none of the 50 positives, while the model finds 60% of them.
answer: Accuracy 0.94, precision 0.75, recall 0.6, F1 about 0.667; the baseline has accuracy 0.90 and recall 0.
@mistakes
- Reporting accuracy on imbalanced data without the majority-class baseline: 90% accuracy can mean the model learned nothing.
- Choosing the threshold, or any other setting, by looking at the test set; use validation data and touch the test set once.
- Treating the training loss as the product goal: a lower cross-entropy does not guarantee a lower business cost.
- Dividing by zero in precision or recall when there are no predicted or no actual positives; decide and document what to return.

model:
```python
def prf(preds, labels):
    """Precision, recall and F1, using 0.0 when a denominator is zero."""
    tp = sum(1 for p, y in zip(preds, labels) if p == 1 and y == 1)
    fp = sum(1 for p, y in zip(preds, labels) if p == 1 and y == 0)
    fn = sum(1 for p, y in zip(preds, labels) if p == 0 and y == 1)
    precision = tp / (tp + fp) if tp + fp else 0.0
    recall = tp / (tp + fn) if tp + fn else 0.0
    denom = precision + recall
    f1 = 2 * precision * recall / denom if denom else 0.0
    return precision, recall, f1
```
hint: Count tp, fp and fn first, then guard each division with a check that the denominator is not zero.
solution: Count the three kinds of outcome, then compute each ratio only when its denominator is positive. The second and third tests have no predicted or no actual positives, the cases that make a naive version raise `ZeroDivisionError`; the last test has high recall and low precision, so F1 is below the average of the two.

model:
```python
def best_threshold(scores, labels, cost_fp, cost_fn):
    """Threshold with the lowest cost; ties go to the smallest threshold."""
    best_t, best_cost = None, None
    for t in sorted(set(scores)) + [float('inf')]:
        fp = sum(1 for s, y in zip(scores, labels) if s >= t and y == 0)
        fn = sum(1 for s, y in zip(scores, labels) if s < t and y == 1)
        cost = cost_fp * fp + cost_fn * fn
        if best_cost is None or cost < best_cost:
            best_t, best_cost = t, cost
    return best_t
```
hint: Loop over the candidates in increasing order, compute FP and FN for each, and replace the best only when the cost is strictly smaller.
solution: Evaluating candidates in increasing order and requiring a strictly smaller cost to replace the best makes ties go to the smallest threshold. The `float('inf')` candidate lets the function choose to flag nothing, as the fourth test requires.
