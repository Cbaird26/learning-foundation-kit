### Week by week

**Week 1, framing.** A product goal becomes an input, a target, a training loss and an evaluation metric; the metric should carry costs. Accuracy, precision $TP/(TP+FP)$, recall $TP/(TP+FN)$, F1 $=2PR/(P+R)$, expected cost $c_{FP}FP + c_{FN}FN$. Always compute trivial baselines. Choose thresholds on validation data.

**Week 2, data.** Pipeline stages and checks: schema, range, completeness, uniqueness, distribution. Return all errors, budget the fraction of bad rows. Leakage, time-based splits, duplicates, train/serve skew.

**Week 3, reproducibility.** Seeds and separate generators; versions of code, data and settings; run records and configuration fingerprints; report mean and sample standard deviation over seeds.

**Week 4, tests.** Unit, edge-case, property, invariance, regression and integration tests; tolerances for floats; central finite differences $(f(x+h)-f(x-h))/2h$ for gradients; testing a wrapper's validation, determinism and output range.

**Week 5, one device.** Bytes per parameter: 4 (fp32), 2 (fp16, bf16), 1 (int8); Adam training state 16 bytes per parameter; compute $\approx 6ND$; time $=\text{FLOPs}/(\text{peak}\times\text{utilization}\times\text{devices})$; loss scaling for fp16; checkpointing costs about $8ND$.

**Week 6, many devices.** Data parallelism averages gradients; ring all-reduce sends $2(p-1)S/p$ bytes per device; effective batch size; scaling efficiency; sharding gives $2+2+12/d$ bytes per parameter; pipeline bubble $(p-1)/(m+p-1)$.

**Week 7, efficiency.** Symmetric quantization $s=\max|w|/q_{\max}$, error at most $s/2$; magnitude pruning, unstructured against structured; distillation with temperature softmax.

**Week 8, serving.** Batch, online and streaming; nearest-rank percentiles; Little's law $L=\lambda W$; batching trades latency for throughput.

**Week 9, monitoring.** Four metric layers; delayed labels and cohorts; control limits, EWMA, persistence rules; SLOs and error budgets.

**Week 10, drift.** Covariate shift, label shift, concept drift; $\text{PSI}=\sum(a_i-e_i)\ln(a_i/e_i)$ with baseline bins and a floor; the KS statistic.

**Week 11, experiments.** Shadow, canary, A/B; stable salted-hash assignment; the two-proportion z statistic; $n\approx 2(1.96+0.84)^2p(1-p)/\delta^2$.

**Week 12, operations.** Cost and energy with stated assumptions; model cards; detect, mitigate, resolve, learn; MTTD and MTTR; blameless postmortems with owned action items.

- Can you write a validation function and say which check catches which failure?

### Common errors

Reporting accuracy on imbalanced data without a baseline; tuning on the test set; shuffling time-ordered data; seeding only some randomness; comparing floats with `==`; counting only weights in memory; using peak throughput as real throughput; averaging percentiles; reading a high PSI as proof of lower accuracy; peeking at an A/B test; blaming a person in a postmortem.

prompt: Write `monitor_window(baseline, current, edges, psi_limit, latencies, p95_slo_ms)` for one monitoring window. For example, with no drift and a p95 within the limit the list is empty.

model:
```python
import math

def monitor_window(baseline, current, edges, psi_limit, latencies, p95_slo_ms):
    """Return the alerts ("drift", "latency") raised by one monitoring window."""
    def proportions(values):
        counts = [0] * (len(edges) + 1)
        for v in values:
            i = 0
            while i < len(edges) and v >= edges[i]:
                i += 1
            counts[i] += 1
        return [max(c / len(values), 1e-4) for c in counts]

    e = proportions(baseline)
    a = proportions(current)
    psi = 0.0
    for ei, ai in zip(e, a):
        psi += (ai - ei) * math.log(ai / ei)
    ordered = sorted(latencies)
    p95 = ordered[(95 * len(ordered) + 99) // 100 - 1]
    alerts = []
    if psi > psi_limit:
        alerts.append("drift")
    if p95 > p95_slo_ms:
        alerts.append("latency")
    return alerts
```
hint: Compute the two statistics separately, the PSI from floored bin proportions and the p95 by nearest rank, then compare each with its limit, drift first.
solution: The PSI uses baseline edges for both samples and floors empty bins so the logarithm stays finite; the p95 is the 19th of 20 sorted latencies, which is 40 here. Equal values do not alert (the sixth test: p95 equals the limit 40), and the last test has a PSI of about 7.25, above even a limit of 5.
@exam num
prompt: A model with $10^9$ parameters is trained on $3 \times 10^{10}$ tokens using the approximation of $6ND$ FLOPs. It runs on 16 devices, each with a peak of $10^{14}$ FLOP/s at 40% utilization, with perfect sharing of the work. At an assumed price of \$2 per device-hour, what is the cost of the run in dollars?
answer: 2500
unit: dollars
tol: 1
check: 6 * 1e9 * 3e10 / (1e14 * 0.4 * 16) / 3600 * 16 * 2
hint: Find the FLOPs, divide by the effective throughput of all 16 devices to get seconds, convert to hours, and multiply by the number of devices and the price.
solution: The compute is $6 \times 10^9 \times 3 \times 10^{10} = 1.8 \times 10^{20}$ FLOPs. The effective throughput is $16 \times 10^{14} \times 0.4 = 6.4 \times 10^{14}$ FLOP/s, so the run takes $2.8125 \times 10^{5}$ s, or 78.125 hours. That is $16 \times 78.125 = 1{,}250$ device-hours, which cost $1250 \times 2 = \$2{,}500$.
@exam self
prompt: A bank has trained a model that predicts loan default. Using what you learned in this course, write a deployment and monitoring plan of about one page: how you would validate the training data, make training reproducible, choose and size the serving design, roll the model out, monitor it given that defaults are known only after 12 months, and respond to an incident in which the model's approval rate suddenly doubles.
hint: Give one concrete mechanism for each stage and one number or rule where you can, such as a budget, a limit, a persistence rule or a sample size.
solution: Data: a validation step checks schema, ranges, completeness and duplicates, fails when the fraction of bad rows exceeds a budget (for example 1%), and splits by time so that the test period follows the training period, with no features from after the application. Reproducibility: a configuration fingerprint, seeds for every random choice, a run record with code version, data version and settings, and results reported as a mean and spread over several seeds. Serving: applications are scored when they arrive, so online prediction with a p99 latency target (for example 200 ms), replicas sized by Little's law at moderate utilization, a timeout and a conservative fallback rule, and the previous model kept for rollback. Rollout: shadow mode to compare scores and latency, then a canary at a small share with a one-sided test on errors and latency, then an A/B test with a stable salted-hash assignment, a pre-chosen primary metric and sample size, and no peeking. Monitoring: system metrics, data-quality metrics, the distribution of scores and the approval rate (all label-free), PSI on key inputs with a limit of 0.25 and a persistence rule, and accuracy by monthly cohort when 12-month outcomes arrive, with earlier delinquency signals as proxies. Incident: if the approval rate doubles, alert fires on the approval-rate metric; triage severity (financial exposure), mitigate first by rolling back or switching to the fallback, then diagnose with the data-quality and PSI dashboards (for example a changed upstream field), fix the cause, and write a blameless postmortem with a timeline, root cause and action items that each have an owner, a date and a check, such as a validation gate for that field.
