@review
### Week by week

- **Week 1, floating point.** A double has a 53-bit significand; the gap between neighbors in $[2^k, 2^{k+1})$ is $2^{k-52}$; each operation has relative error at most $u = 2^{-53}$. Compare floats with a tolerance. Beware absorption, cancellation and overflow.
- **Week 2, vectors.** Dot product, the L1, L2 and L-infinity norms, distance, cosine similarity; Cauchy–Schwarz and the triangle inequality; scale before squaring.
- **Week 3, matrices.** Shape rule $(m \times n)(n \times p)$, $C_{ij} = \sum_k A_{ik}B_{kj}$, cost $mnp$ multiplications; choose the cheaper order of a chain.
- **Week 4, vectorization.** Contiguous buffer, shape and strides, broadcasting from the right; same operations, less interpreter overhead.
- **Week 5, linear systems.** Forward elimination, back substitution, partial pivoting, cost $\tfrac23 n^3$; determinant from the pivots.
- **Week 6, conditioning.** $\kappa(\mathbf{A}) = \lVert\mathbf{A}\rVert\lVert\mathbf{A}^{-1}\rVert$; relative error up to $\kappa$ times the relative data error; conditioning belongs to the problem, stability to the algorithm.
- **Week 7, least squares.** Normal equations $\mathbf{X}^\top\mathbf{X}\mathbf{w} = \mathbf{X}^\top\mathbf{y}$ square the condition number; QR solves $\mathbf{R}\mathbf{w} = \mathbf{Q}^\top\mathbf{y}$.
- **Week 8, power iteration.** Multiply and normalize; the rate is $|\lambda_2/\lambda_1|$; Rayleigh quotient; deflation.
- **Week 9, derivatives.** Forward error $O(h)$, central error $O(h^2)$, best $h$ near $10^{-8}$ and $5 \times 10^{-6}$; relative-error gradient check.
- **Week 10, randomness.** Seeds, LCGs, cumulative-sum and inverse-transform sampling, Fisher–Yates shuffle, property-based tests.
- **Week 11, Monte Carlo.** $\mathrm{SE} = \sigma/\sqrt{n}$, $\sqrt{\hat p(1-\hat p)/n}$ for probabilities, four times the samples to halve the error.
- **Week 12, data.** Parse, handle missing values, standardize with training statistics, one-hot encode with one level dropped, seeded split.

### Common errors

Comparing floats with `==`; reseeding inside a loop; standardizing before splitting; forgetting to swap the right-hand side with the rows; trusting a small residual when $\kappa$ is large; using a gradient check only at the origin; dividing by $n$ instead of $\sqrt{n}$ in a standard error.

def reference(xs, ys):
    n = len(xs)
    mx, my = sum(xs) / n, sum(ys) / n
    w1 = sum((x - mx) * (y - my) for x, y in zip(xs, ys)) / sum((x - mx) ** 2 for x in xs)
    return my - w1 * mx, w1

w0, w1 = fit_line_from_csv("x,y\n1,2.2\n2,3.9\n3,6.1\n4,8.2\n5,9.8\n")

model:
```python
import math

def fit_line_from_csv(text):
    """Least-squares line through (x, y) pairs in CSV text, using QR."""
    lines = [ln for ln in text.splitlines() if ln.strip()]
    xs = []
    ys = []
    for ln in lines[1:]:
        a, b = ln.split(",")
        xs.append(float(a))
        ys.append(float(b))
    n = len(xs)
    r11 = math.sqrt(n)
    q1 = [1.0 / r11] * n
    r12 = sum(q * x for q, x in zip(q1, xs))
    v = [x - r12 * q for x, q in zip(xs, q1)]
    r22 = math.sqrt(sum(t * t for t in v))
    q2 = [t / r22 for t in v]
    c1 = sum(q * y for q, y in zip(q1, ys))
    c2 = sum(q * y for q, y in zip(q2, ys))
    w1 = c2 / r22
    w0 = (c1 - r12 * w1) / r11
    return w0, w1
```
hint: Parse the pairs, then orthogonalize: `q1` is the normalized column of ones, `r12` is its dot product with `x`, and `q2` is the normalized remainder of `x`. Solve the 2-by-2 triangular system from the bottom.
solution: The column of ones has norm $\sqrt{n}$, so $r_{11} = \sqrt{n}$ and $\mathbf{q}_1 = \mathbf{1}/\sqrt{n}$; the second column gives $r_{12} = \mathbf{q}_1^\top\mathbf{x}$ and $r_{22} = \lVert\mathbf{x} - r_{12}\mathbf{q}_1\rVert$. Back substitution on $\mathbf{R}\mathbf{w} = \mathbf{Q}^\top\mathbf{y}$ gives $w_1 = (\mathbf{q}_2^\top\mathbf{y})/r_{22}$ and then $w_0$. The data near 1000 test the numerical care of the factorization, and the blank line tests the parsing.

@exam self
prompt: A teammate trains a linear model with a hand-derived gradient and reports good test error. Reading the code you find that (a) the features are standardized using the mean and standard deviation of the whole data set before the train/test split, (b) the weights are computed by `inv(X.T @ X) @ X.T @ y` for features that include a house's area in square meters and the same area in square feet, (c) the gradient was never checked, and (d) a simulation of 100 trials reports a probability of 0.31 with no error estimate. Write a short review that explains the numerical or data problem in each of (a) to (d) and gives one concrete fix for each.
hint: Think of leakage, conditioning and rank, the finite-difference check at seeded random points, and the standard error of a proportion.
solution: (a) Statistics computed before the split leak information from the test rows into preprocessing, so the test error is optimistic; split first, compute means and standard deviations on the training rows only, and apply them to the test rows. (b) Area in square meters and in square feet are exactly proportional columns, so $\mathbf{X}^\top\mathbf{X}$ is singular (or, after rounding, wildly ill-conditioned) and inverting it is meaningless; drop one column, and solve with a pivoted solver or a QR factorization instead of forming the inverse. (c) An unchecked gradient may contain a sign or factor error; compare it with central differences with a step near $10^{-5}$ at several seeded random points and require a relative error below about $10^{-7}$. (d) With $\hat{p} = 0.31$ and $n = 100$, the standard error is $\sqrt{0.31 \cdot 0.69/100} \approx 0.046$, so the 95% interval is about $0.31 \pm 0.09$; report it, and use about four times as many trials to halve it.

rubric: Proposes a finite-difference check at several random points with a relative-error threshold for (c).
rubric: Computes or states the standard error $\sqrt{\hat p(1-\hat p)/n} \approx 0.046$ and a confidence interval for (d), or says that more trials are needed.
