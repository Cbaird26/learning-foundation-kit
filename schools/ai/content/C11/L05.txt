@article
Linear regression, Gaussian processes, Newton's method and many other algorithms end in the same step: solve $\mathbf{A}\mathbf{x} = \mathbf{b}$ for a square matrix $\mathbf{A}$. You learned to do this by hand with row operations. A computer does the same, but its rounding makes one detail essential: which row to use next.

### Gaussian elimination

The idea is to turn the system into a triangular one. **Forward elimination** works column by column. For column $k$, pick a row with a nonzero entry in that column, called the **pivot**, and use it to eliminate the entries below it: for each row $i > k$ subtract the multiple $m_{ik} = a_{ik}/a_{kk}$ of the pivot row from row $i$, applying the same operation to $b_i$. After the last column the matrix $\mathbf{U}$ is upper triangular and we have a new right-hand side $\mathbf{c}$, with the same solutions as the original system. **Back substitution** then solves $\mathbf{U}\mathbf{x} = \mathbf{c}$ from the bottom up:
$$x_i = \frac{1}{u_{ii}}\Big(c_i - \sum_{j > i} u_{ij} x_j\Big), \qquad i = n, n-1, \ldots, 1.$$

### Why the pivot must be chosen carefully

Take the system $10^{-20} x_1 + x_2 = 1$, $\; x_1 + x_2 = 2$, whose solution is very close to $x_1 = 1$, $x_2 = 1$. Eliminating with the first row as pivot uses the multiplier $m = 10^{20}$. The second row becomes $(1 - 10^{20}) x_2 = 2 - 10^{20}$, and in double precision both $1 - 10^{20}$ and $2 - 10^{20}$ round to $-10^{20}$ (absorption, Lesson 1). Then $x_2 = 1$ is fine, but back substitution computes $x_1 = (1 - 1)/10^{-20} = 0$: completely wrong. The information in the second equation was destroyed by the huge multiplier.

**Partial pivoting** fixes this: at column $k$, search rows $k, \ldots, n$ for the entry of largest absolute value and swap that row into position $k$. Then every multiplier satisfies $|m_{ik}| \le 1$, so the rows are never amplified. In the example the swap puts $[1, 1]$ first with multiplier $10^{-20}$, and the solver returns $x_1 = x_2 = 1$. Partial pivoting is what practical solvers use (as part of the **LU factorization**, which stores the multipliers so that many right-hand sides can share one elimination). If every candidate pivot is zero, or nearly so, the matrix is singular and the solver should report it.

```python
def eliminate(A, b):
    """Forward elimination with partial pivoting. Returns (U, c, swaps)."""
    n = len(A)
    U = [row[:] for row in A]
    c = b[:]
    swaps = 0
    for k in range(n):
        p = max(range(k, n), key=lambda r: abs(U[r][k]))
        if abs(U[p][k]) < 1e-12:
            raise ValueError("matrix is singular")
        if p != k:
            U[k], U[p] = U[p], U[k]
            c[k], c[p] = c[p], c[k]
            swaps += 1
        for i in range(k + 1, n):
            m = U[i][k] / U[k][k]
            for j in range(k, n):
                U[i][j] -= m * U[k][j]
            c[i] -= m * c[k]
    return U, c, swaps
```

### Cost and by-products

Step $k$ updates about $(n-k)^2$ entries, each with one multiplication and one subtraction, so elimination costs about $\tfrac{2}{3}n^3$ flops and back substitution only about $n^2$. For $n = 1000$ that is roughly $6.7 \times 10^8$ flops. Because elimination dominates, solving for many right-hand sides should reuse the factorization.

The **determinant** is a free by-product: $\det \mathbf{A} = (-1)^{s} \prod_i u_{ii}$, where $s$ is the number of row swaps. A zero pivot means $\det \mathbf{A} = 0$.

One more rule: to solve $\mathbf{A}\mathbf{x} = \mathbf{b}$, never compute $\mathbf{A}^{-1}$ and multiply. Forming the inverse costs about three times as much as one solve and is usually less accurate. In code, `np.linalg.solve(A, b)` is the right call; `np.linalg.inv(A) @ b` is the wrong one.

@example
title: Elimination with pivoting by hand
problem: Solve $x_1 + 2x_2 + x_3 = 8$, $\; 3x_1 + x_2 + 2x_3 = 11$, $\; 2x_1 + 4x_2 + 5x_3 = 25$ with partial pivoting.
step: Column 1: the largest entry in absolute value is 3 (row 2), so swap rows 1 and 2. The rows are now $[3, 1, 2 \mid 11]$, $[1, 2, 1 \mid 8]$, $[2, 4, 5 \mid 25]$.
step: Eliminate with multipliers $1/3$ and $2/3$: row 2 becomes $[0, \tfrac53, \tfrac13 \mid \tfrac{13}{3}]$ and row 3 becomes $[0, \tfrac{10}{3}, \tfrac{11}{3} \mid \tfrac{53}{3}]$.
step: Column 2: the candidates are $\tfrac53$ and $\tfrac{10}{3}$, so swap. The multiplier is $\tfrac{5/3}{10/3} = \tfrac12$, and the new third row is $[0, 0, -\tfrac32 \mid -\tfrac92]$.
step: Back substitution: $x_3 = (-\tfrac92)/(-\tfrac32) = 3$; $x_2 = (\tfrac{53}{3} - \tfrac{11}{3}\cdot 3)/\tfrac{10}{3} = 2$; $x_1 = (11 - 1\cdot 2 - 2\cdot 3)/3 = 1$.
step: Check in the original first equation: $1 + 4 + 3 = 8$. The determinant is $(-1)^2 \cdot 3 \cdot \tfrac{10}{3} \cdot (-\tfrac32) = -15$.
answer: $\mathbf{x} = [1, 2, 3]$ and $\det\mathbf{A} = -15$.

@mistakes
- Pivoting only when the pivot is exactly zero: a tiny nonzero pivot is just as dangerous, as the $10^{-20}$ example shows.
- Forgetting to swap the right-hand side along with the rows of the matrix.
- Computing the inverse to solve a system: it costs more and loses accuracy, and the factorization gives everything you need.
- Looking only at the pivot's absolute size across all rows: partial pivoting searches only the rows at or below the current one; rows above are already finished.

```python
def back_substitute(U, c):
    """Solve U x = c for upper triangular U, from the last row up."""
    n = len(U)
    x = [0.0] * n
    for i in range(n - 1, -1, -1):
        s = c[i]
        for j in range(i + 1, n):
            s -= U[i][j] * x[j]
        x[i] = s / U[i][i]
    return x
```
hint: Loop `i` from the last row down to 0; subtract `U[i][j] * x[j]` for the already-known `j > i`, then divide by `U[i][i]`.
solution: Row $i$ involves only $x_i$ and the unknowns below it, which are already solved when we reach it, so each row yields one new value. The 4-by-4 test uses row sums so that every unknown equals 1.

```python
def solve(A, b):
    """Solve A x = b by Gaussian elimination with partial pivoting."""
    n = len(A)
    U = [[float(v) for v in row] for row in A]
    c = [float(v) for v in b]
    for k in range(n):
        p = max(range(k, n), key=lambda r: abs(U[r][k]))
        if abs(U[p][k]) < 1e-12:
            raise ValueError("matrix is singular")
        U[k], U[p] = U[p], U[k]
        c[k], c[p] = c[p], c[k]
        for i in range(k + 1, n):
            m = U[i][k] / U[k][k]
            for j in range(k, n):
                U[i][j] -= m * U[k][j]
            c[i] -= m * c[k]
    x = [0.0] * n
    for i in range(n - 1, -1, -1):
        s = c[i]
        for j in range(i + 1, n):
            s -= U[i][j] * x[j]
        x[i] = s / U[i][i]
    return x
```
hint: Copy `A` and `b` first. For each column pick the row with the largest absolute entry at or below the diagonal, swap it up (with `b`), eliminate below, then back-substitute.
solution: This combines forward elimination with row swaps and the bottom-up substitution. The first test fails without pivoting (it returns 0 for the first unknown), the second needs a swap because the first pivot is 0, and the singular matrix makes the second pivot vanish.

```python
def determinant(A):
    """Determinant by Gaussian elimination with partial pivoting."""
    n = len(A)
    U = [[float(v) for v in row] for row in A]
    det = 1.0
    for k in range(n):
        p = max(range(k, n), key=lambda r: abs(U[r][k]))
        if abs(U[p][k]) < 1e-12:
            return 0.0
        if p != k:
            U[k], U[p] = U[p], U[k]
            det = -det
        det *= U[k][k]
        for i in range(k + 1, n):
            m = U[i][k] / U[k][k]
            for j in range(k, n):
                U[i][j] -= m * U[k][j]
    return det
```
hint: Start `det` at 1.0; flip its sign on every swap and multiply by each pivot as you go.
solution: Row operations of the form "subtract a multiple of another row" leave the determinant unchanged and each swap flips its sign, so the determinant of the original matrix is the signed product of the pivots on the diagonal of $\mathbf{U}$. The first test needs a swap, which fixes the sign.
