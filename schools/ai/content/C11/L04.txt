@article
Suppose you must compute the squared distance from one point to each of a million points. A Python loop works, and it is slow. The same computation written with NumPy, the standard array library, typically runs tens to hundreds of times faster, yet it does exactly the same arithmetic. This lesson explains why, by building the key ideas in plain Python. (The site's Python has no NumPy, so the NumPy lines below are shown for reference.)

### Why loops are slow and arrays are fast

A Python list of floats holds pointers to separate float objects. Each `a * b` in a loop makes the interpreter look up the objects, check their types, run the multiplication and allocate a new object. An **array** instead stores all elements as raw numbers of one type in a single contiguous block of memory. An operation such as `x * y` is then one call into compiled code that loops over the block without any per-element interpretation. **Vectorization** means writing computations as whole-array operations so that all loops run in that compiled code. It changes the speed per operation, never the number of operations or the results (up to the order in which sums are accumulated).

### Shape and strides

An array is a flat buffer plus a **shape** such as `(3, 4)` and **strides**: for each axis, how many elements to skip in the buffer to move one step along that axis. In **row-major** order (the default), the last axis changes fastest. For shape $(d_0, d_1, d_2)$ the strides are $(d_1 d_2,\; d_2,\; 1)$, and the element at index $(i_0, i_1, i_2)$ lives at buffer position
$$i_0 s_0 + i_1 s_1 + i_2 s_2 .$$
For a matrix of shape $(3, 4)$ the strides are $(4, 1)$, and the element in row 2, column 1 is at position $2 \cdot 4 + 1 \cdot 1 = 9$. Strides explain a famous trick: the transpose of a $(3, 4)$ array can be a **view** of the same buffer with shape $(4, 3)$ and strides $(1, 4)$; no data is copied. Reshaping a contiguous array to another shape with the same number of elements is also free.

```python
def strides_of(shape):
    strides = []
    step = 1
    for d in reversed(shape):
        strides.append(step)
        step *= d
    return tuple(reversed(strides))

class Array:
    def __init__(self, data, shape):
        self.data = list(data)
        self.shape = tuple(shape)
        self.strides = strides_of(shape)

    def get(self, *index):
        pos = sum(i * s for i, s in zip(index, self.strides))
        return self.data[pos]

M = Array(range(12), (3, 4))
print(M.strides, M.get(2, 1))   # (4, 1) 9
```

### Broadcasting

**Broadcasting** lets arrays of different shapes be combined elementwise without copying the smaller one. Line up the two shapes from the right, padding the shorter one on the left with 1s. Each pair of sizes must be equal or contain a 1; the result takes the larger size of each pair. Otherwise the operation raises an error. Shapes $(5, 3)$ and $(3,)$ become $(5, 3)$: a vector is added to every row. Shapes $(4, 1)$ and $(1, 3)$ become $(4, 3)$, which is how an outer sum is built. Shapes $(4, 3)$ and $(4,)$ fail, because 3 and 4 clash; a per-row quantity needs shape $(4, 1)$.

### What vectorized code looks like

Standardizing each column of a data matrix `X` with one example per row, or computing every squared distance from the rows of `X` to the rows of `Y` through the expanded formula of Lesson 2, becomes:

```text
Xs = (X - X.mean(axis=0)) / X.std(axis=0)
D2 = (X**2).sum(axis=1)[:, None] + (Y**2).sum(axis=1)[None, :] - 2 * X @ Y.T
```

Here `[:, None]` turns a shape $(n,)$ array into $(n, 1)$ so that broadcasting builds an $n \times m$ table. The only heavy step, `X @ Y.T`, is one matrix product that the library hands to optimized code. Remember the warning of Lesson 2: that expanded form can lose accuracy through cancellation, and tiny negative results should be clipped to 0.

### Two ways to multiply, one cost

The product $\mathbf{C} = \mathbf{A}\mathbf{B}$ can be organized in two ways. The **inner-product** way computes each $C_{ij}$ as a dot product of row $i$ of $\mathbf{A}$ with column $j$ of $\mathbf{B}$. The **outer-product** way adds up $n$ matrices: $\mathbf{C} = \sum_{k=1}^{n} \mathbf{a}_k \mathbf{b}_k^\top$, where $\mathbf{a}_k$ is column $k$ of $\mathbf{A}$ and $\mathbf{b}_k^\top$ is row $k$ of $\mathbf{B}$. Each outer product costs $mp$ multiplications, so the total is $nmp$: the same as before. The two differ only in memory access order, and that is the lever libraries pull to run fast.

@mistakes
- Believing that vectorization does less arithmetic: it does the same operations in compiled code, so its gain is removing interpreter overhead.
- Expecting `(4, 3) + (4,)` to work: broadcasting aligns shapes from the right, so the 4 meets the 3; use shape `(4, 1)` for a per-row vector.
- Assuming a transpose or reshape copies data: these are usually views that share memory, so changing one changes the other.
- Mixing up row-major and column-major strides: in row-major order the last axis has stride 1.

```python
def flat_index(index, shape):
    """Row-major buffer position of a multi-index."""
    pos = 0
    stride = 1
    for i in range(len(shape) - 1, -1, -1):
        if not 0 <= index[i] < shape[i]:
            raise IndexError("index out of range")
        pos += index[i] * stride
        stride *= shape[i]
    return pos
```
hint: Walk the axes from last to first, keeping a running stride that starts at 1 and is multiplied by each axis size.
solution: The stride of an axis is the product of the sizes of all later axes, so walking backwards accumulates it. Each index is multiplied by its stride and added. The checks reject indices that would silently point into a neighboring row.

model:
```python
def broadcast_shape(a, b):
    """Shape that results from broadcasting shapes a and b."""
    n = max(len(a), len(b))
    pa = (1,) * (n - len(a)) + tuple(a)
    pb = (1,) * (n - len(b)) + tuple(b)
    out = []
    for x, y in zip(pa, pb):
        if x != y and x != 1 and y != 1:
            raise ValueError("incompatible shapes")
        out.append(max(x, y))
    return tuple(out)
```
hint: Pad both shapes on the left with 1s to a common length, then check each pair of sizes and keep the larger.
solution: After padding, each axis is independent: sizes must match unless one is 1, and the result keeps the non-1 size, which is the maximum. The failing cases show that `(4, 3)` with `(4,)` clashes on the last axis and that `(2, 3)` with `(3, 2)` clash on both.

model:
```python
def matmul_outer(A, B):
    """Matrix product as a sum of n outer products (k loop outermost)."""
    m, n, p = len(A), len(B), len(B[0])
    C = [[0.0] * p for _ in range(m)]
    for k in range(n):
        for i in range(m):
            for j in range(p):
                C[i][j] += A[i][k] * B[k][j]
    return C
```
hint: The same three loops as before, but with `k` outermost: each pass over `k` adds `A[i][k] * B[k][j]` to every entry.
solution: Fixing `k` and looping over all `i` and `j` adds the outer product of column `k` of `A` and row `k` of `B`. Summing over `k` gives the same entries as the inner-product method, using the same $mnp$ multiplications; only the order of operations changed.
