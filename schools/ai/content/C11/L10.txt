@article
Training a neural network starts from random weights, splits data at random, and shuffles mini-batches. Yet a good experiment must be **reproducible**: someone else running your code should get the same numbers. These fit together because a computer never produces truly random numbers. It produces **pseudorandom** ones: a deterministic procedure whose output looks random.

### Generators and seeds

A **pseudorandom number generator** holds a state, updates it by a fixed rule, and outputs a function of the state. The initial state is set by a **seed**: the same seed gives the same sequence, every time. The simplest example is the **linear congruential generator** (LCG),
$$x_{k+1} = (a x_k + c) \bmod m, \qquad u_k = x_k / m \in [0, 1).$$
With $a = 5$, $c = 1$, $m = 8$ and seed $x_0 = 1$ the states are $6, 7, 4, 5, 2, 3, 0, 1, 6, \ldots$ and the outputs $u$ are $0.75, 0.875, 0.5, 0.625, 0.25, 0.375, 0, 0.125$. The sequence **repeats** after at most $m$ steps; its length is the **period**. The Hull–Dobell theorem gives conditions for the full period $m$: $c$ and $m$ share no factor, $a - 1$ is divisible by every prime factor of $m$, and by 4 if $m$ is. Here $m = 8$, $a - 1 = 4$ and $c = 1$ satisfy them, so all eight values appear.

Simple LCGs have defects (for $m = 2^k$ the low-order bits cycle with a short period, and consecutive outputs are correlated), so libraries use better generators. Python's `random` module uses the Mersenne Twister, with a period of $2^{19937} - 1$. Practice for reproducible work:

- Create a generator object with a seed, `rng = random.Random(42)`, and **pass it to functions** that need randomness, rather than relying on hidden global state. Calling `rng.random()` advances only that generator.
- Seed once at the start, not repeatedly inside a loop (reseeding with the same seed repeats the same numbers).
- Record the seed with the results. With NumPy the equivalent is `np.random.default_rng(42)`; deep-learning libraries have their own seeds, and all must be set.

### From uniform numbers to other distributions

Everything starts from $U \sim \mathrm{Uniform}[0, 1)$.

**Discrete distributions.** For probabilities $p_0, \ldots, p_{K-1}$, form the cumulative sums $P_j = p_0 + \cdots + p_j$ and return the first index $j$ with $u < P_j$. Index $j$ is chosen exactly when $u$ lands in an interval of length $p_j$. Guard the last index in code, because the sums may total $0.9999999$ instead of 1.

**Inverse transform sampling.** If $F$ is the cumulative distribution function of a continuous variable and $F^{-1}$ its inverse, then $F^{-1}(U)$ has distribution $F$. For the exponential distribution with rate $\lambda$, $F(x) = 1 - e^{-\lambda x}$, so $x = -\ln(1 - u)/\lambda$. With $\lambda = 0.5$ and $u = 0.9$ this gives $x = -\ln(0.1)/0.5 \approx 4.605$.

**Normal variables.** The **Box–Muller transform** turns two independent uniforms into two independent standard normals: $z_1 = \sqrt{-2\ln u_1}\cos(2\pi u_2)$ and $z_2 = \sqrt{-2\ln u_1}\sin(2\pi u_2)$ (use $1 - u_1$ in place of $u_1$ to avoid $\ln 0$).

### Shuffling and splitting

To shuffle a list uniformly, use **Fisher–Yates**: for $i$ from $n-1$ down to 1, pick $j$ uniformly from $0, \ldots, i$ and swap items $i$ and $j$. Every one of the $n!$ orders then has probability $1/n!$. The tempting variant that picks $j$ from the whole list at every step is biased: it produces $n^n$ equally likely sequences of swaps, and for $n \ge 3$ the number $n^n$ is not divisible by $n!$ (the factor $n - 1$ divides $n!$ but not $n^n$), so some orders must be likelier than others. A train/test split is a shuffle followed by cutting the list.

```python
import random

def fisher_yates(items, rng):
    out = list(items)
    for i in range(len(out) - 1, 0, -1):
        j = rng.randrange(i + 1)
        out[i], out[j] = out[j], out[i]
    return out

rng = random.Random(7)
a = fisher_yates(range(6), rng)
b = fisher_yates(range(6), random.Random(7))
print(sorted(a) == list(range(6)), a == b)   # True True
```

### Testing random code

Tests must not depend on particular random values, which differ between libraries and versions. Check **properties**: the output is a permutation of the input, values lie in range, the same seed gives the same result, and frequencies over many draws are near the truth within several standard errors (Lesson 11).

@example
title: Sampling a discrete distribution
problem: Categories $0, 1, 2$ have probabilities $0.5, 0.3, 0.2$. Which category is returned for the uniform draws $u = 0.62$ and $u = 0.95$?
step: The cumulative sums are $P_0 = 0.5$, $P_1 = 0.8$, $P_2 = 1.0$, which split $[0, 1)$ into $[0, 0.5)$, $[0.5, 0.8)$ and $[0.8, 1.0)$.
step: For $u = 0.62$: it is not below $0.5$ but is below $0.8$, so the answer is category 1.
step: For $u = 0.95$: it is not below $0.8$ and is below $1.0$, so the answer is category 2.
answer: $u = 0.62$ gives category 1 and $u = 0.95$ gives category 2.

@example
title: Inverse transform for a simple density
problem: A variable $X$ on $[0, 1]$ has cumulative distribution function $F(x) = x^2$. Give a rule that turns a uniform $u$ into a draw of $X$, and evaluate it at $u = 0.36$.
step: Solve $u = F(x) = x^2$ for $x$: $x = F^{-1}(u) = \sqrt{u}$, which lies in $[0, 1]$ for every $u$.
step: At $u = 0.36$ the draw is $\sqrt{0.36} = 0.6$.
step: Check: $P(X \le 0.6) = F(0.6) = 0.36$, which is the probability that $U \le 0.36$, as it must be.
answer: $X = \sqrt{U}$, which gives $0.6$ at $u = 0.36$.

@mistakes
- Reseeding inside a loop: every iteration then produces the same "random" numbers.
- Using a global random state in library code: a hidden call elsewhere changes your results; pass a generator explicitly.
- Shuffling by swapping each item with a random position anywhere in the list: this is biased; Fisher–Yates picks only among positions up to the current one.
- Writing tests that assert specific random values: they break when the generator or the library version changes; test properties instead.

def lcg(seed, n, a=1664525, c=1013904223, m=2**32):
    """First n outputs, scaled to [0, 1), of a linear congruential generator."""

    out = []
    for _ in range(n):

    return out

model:
```python
def sample_discrete(probs, rng):
    """Draw an index with the given probabilities using cumulative sums."""
    u = rng.random()
    total = 0.0
    for j, p in enumerate(probs):
        total += p
        if u < total:
            return j
    return len(probs) - 1
```
hint: Draw `u` once, then walk through the probabilities adding them up and stop at the first partial sum that exceeds `u`.
solution: The cumulative sums cut $[0, 1)$ into intervals whose lengths are the probabilities, so index `j` is returned with probability `probs[j]`. The final `return` guards the case where rounding makes the total slightly below 1. The frequency tests allow several standard errors, so they pass for any good generator.

model:
```python
import math
import random

def max_gradient_error(f, grad, dim, trials, seed):
    """Largest relative gradient-check error over random points in [-1, 1]^dim."""
    rng = random.Random(seed)
    worst = 0.0
    for _ in range(trials):
        x = [rng.uniform(-1, 1) for _ in range(dim)]
        g = grad(x)
        num = []
        for i in range(dim):
            up = list(x)
            down = list(x)
            up[i] += 1e-5
            down[i] -= 1e-5
            num.append((f(up) - f(down)) / 2e-5)
        diff = math.sqrt(sum((a - b) ** 2 for a, b in zip(g, num)))
        denom = math.sqrt(sum(a * a for a in g)) + math.sqrt(sum(b * b for b in num))
        err = diff / denom if denom > 0 else 0.0
        worst = max(worst, err)
    return worst
```
hint: Create the generator once, loop over trials, build each random point, and compute the central-difference gradient and the relative error as in the gradient-check lesson.
solution: Checking at several random points makes it unlikely that a bug is hidden by a special point such as the origin. The wrong gradient omits a term in its last component, which produces a large relative error at almost every random point.

x = 2
