A neural-network layer maps an input vector $\mathbf{x}$ to $\mathbf{W}\mathbf{x}$. Training a network on a batch of inputs multiplies matrices with thousands of rows and columns, billions of times. Before anyone optimizes that, you should be able to write the product with two loops and know exactly how much arithmetic it does.

### Matrices as lists of rows

An $m \times n$ matrix has $m$ rows and $n$ columns. In Python we store it as a list of $m$ rows, each a list of $n$ floats, so `A[i][j]` is the entry in row $i$, column $j$ (both counted from 0). The **shape** is `(len(A), len(A[0]))`. A matrix with one example per row, the convention of this course for data, has shape (number of examples, number of features).

The **transpose** $\mathbf{A}^\top$ swaps rows and columns: $(\mathbf{A}^\top)_{ji} = A_{ij}$, so an $m \times n$ matrix becomes $n \times m$. In Python, `[list(col) for col in zip(*A)]` does it, because `zip(*A)` pairs up the first entries of all rows, then the second entries, and so on.

### The matrix product

If $\mathbf{A}$ is $m \times n$ and $\mathbf{B}$ is $n \times p$ (the inner sizes must match), then $\mathbf{C} = \mathbf{A}\mathbf{B}$ is $m \times p$ with
$$C_{ij} = \sum_{k=1}^{n} A_{ik} B_{kj}.$$
Entry $(i,j)$ is the dot product of row $i$ of $\mathbf{A}$ with column $j$ of $\mathbf{B}$. For $\mathbf{A} = \begin{bmatrix} 2 & 0 \\ 1 & 3 \end{bmatrix}$ and $\mathbf{B} = \begin{bmatrix} 1 & 4 \\ 5 & 2 \end{bmatrix}$:
$$\mathbf{A}\mathbf{B} = \begin{bmatrix} 2\cdot1 + 0\cdot5 & 2\cdot4 + 0\cdot2 \\ 1\cdot1 + 3\cdot5 & 1\cdot4 + 3\cdot2 \end{bmatrix} = \begin{bmatrix} 2 & 8 \\ 16 & 10 \end{bmatrix}.$$
Matrix multiplication is associative, $(\mathbf{A}\mathbf{B})\mathbf{C} = \mathbf{A}(\mathbf{B}\mathbf{C})$, and distributes over addition, but it is **not commutative**: $\mathbf{B}\mathbf{A}$ may differ from $\mathbf{A}\mathbf{B}$, or may not even exist. Also $(\mathbf{A}\mathbf{B})^\top = \mathbf{B}^\top \mathbf{A}^\top$. The matrix-vector product is the special case $p = 1$.

```python
def transpose(A):
    return [list(col) for col in zip(*A)]

def matmul(A, B):
    m, n, p = len(A), len(B), len(B[0])
    C = [[0.0] * p for _ in range(m)]
    for i in range(m):
        for j in range(p):
            for k in range(n):
                C[i][j] += A[i][k] * B[k][j]
    return C

print(matmul([[2, 0], [1, 3]], [[1, 4], [5, 2]]))   # [[2.0, 8.0], [16.0, 10.0]]
```

### Counting the cost

The three loops run $m \cdot p \cdot n$ times, and each pass does one multiplication and one addition. So the product costs $mnp$ multiplications and $mp(n-1)$ additions, about $2mnp$ **floating-point operations** (flops). For two $n \times n$ matrices that is $n^3$ multiplications: doubling $n$ multiplies the work by 8. A product of two $1000 \times 1000$ matrices needs $10^9$ multiplications, which takes minutes in pure Python and a fraction of a second in a compiled library. (Faster algorithms such as Strassen's use fewer than $n^3$ multiplications, but libraries use them rarely, because the cost of memory access matters as much as the count.)

Counting operations also tells you how to **parenthesize**. Let $\mathbf{A}$ and $\mathbf{B}$ be $100 \times 100$ and $\mathbf{x}$ a vector of length 100. Computing $(\mathbf{A}\mathbf{B})\mathbf{x}$ forms a matrix product first, costing $100^3 + 100^2 = 1{,}010{,}000$ multiplications. Computing $\mathbf{A}(\mathbf{B}\mathbf{x})$ uses two matrix-vector products, costing $100^2 + 100^2 = 20{,}000$. The answers agree in exact arithmetic (and nearly agree in floating point), but one is 50 times cheaper. The rule of thumb: when a chain ends in a vector, multiply from the vector side.

### Memory order

A list of rows is stored row by row, so reading `A[i][k]` as `k` increases walks along one row, which is fast, while `B[k][j]` walks down a column, which jumps between rows. Libraries therefore reorder loops or work with a transposed copy so that the innermost loop reads consecutive entries. In pure Python the effect is modest, but the same reasoning explains most of the speed differences you will see in Lesson 4.

@example
title: A product by hand and its cost
problem: Compute $\mathbf{A}\mathbf{B}$ for $\mathbf{A} = \begin{bmatrix} 1 & 0 & 2 \\ 3 & 1 & -1 \end{bmatrix}$ and $\mathbf{B} = \begin{bmatrix} 2 & 1 \\ 0 & 4 \\ 1 & -2 \end{bmatrix}$, and count the multiplications.
step: Shapes: $\mathbf{A}$ is $2 \times 3$ and $\mathbf{B}$ is $3 \times 2$; the inner sizes match, so $\mathbf{A}\mathbf{B}$ is $2 \times 2$.
step: Row 1 of $\mathbf{A}$ with the columns of $\mathbf{B}$: $1\cdot2 + 0\cdot0 + 2\cdot1 = 4$ and $1\cdot1 + 0\cdot4 + 2\cdot(-2) = -3$.
step: Row 2: $3\cdot2 + 1\cdot0 + (-1)\cdot1 = 5$ and $3\cdot1 + 1\cdot4 + (-1)(-2) = 9$.
step: Cost: $mnp = 2 \cdot 3 \cdot 2 = 12$ multiplications (one per term written above).
answer: $\mathbf{A}\mathbf{B} = \begin{bmatrix} 4 & -3 \\ 5 & 9 \end{bmatrix}$ with 12 multiplications.

@example
title: Choosing the order of a chain
problem: $\mathbf{A}$ is $10 \times 100$, $\mathbf{B}$ is $100 \times 5$ and $\mathbf{C}$ is $5 \times 50$. Compare the multiplications needed for $(\mathbf{A}\mathbf{B})\mathbf{C}$ and $\mathbf{A}(\mathbf{B}\mathbf{C})$.
step: $(\mathbf{A}\mathbf{B})$ is $10 \times 5$ and costs $10 \cdot 100 \cdot 5 = 5000$.
step: Multiplying that $10 \times 5$ result by $\mathbf{C}$ costs $10 \cdot 5 \cdot 50 = 2500$, for a total of $7500$.
step: $(\mathbf{B}\mathbf{C})$ is $100 \times 50$ and costs $100 \cdot 5 \cdot 50 = 25{,}000$; then $\mathbf{A}$ times it costs $10 \cdot 100 \cdot 50 = 50{,}000$, for a total of $75{,}000$.
answer: The first order needs 7500 multiplications and the second needs 75,000, ten times more, for the same result.

@mistakes
- Multiplying matrices elementwise: `A[i][j] * B[i][j]` is the Hadamard product, not the matrix product.
- Using `[[0] * p] * m` to create the result: this makes `m` references to the same row, so writing one row changes them all; build each row separately.
- Assuming $\mathbf{A}\mathbf{B} = \mathbf{B}\mathbf{A}$, or forgetting that the inner sizes must match.
- Counting only the work of one entry: there are $mp$ entries, each needing $n$ multiplications.

model:
```python
def matmul(A, B):
    """Matrix product of lists of rows, checking that the shapes match."""
    m, n, p = len(A), len(B), len(B[0])
    if len(A[0]) != n:
        raise ValueError("shape mismatch")
    C = [[0.0] * p for _ in range(m)]
    for i in range(m):
        for j in range(p):
            for k in range(n):
                C[i][j] += A[i][k] * B[k][j]
    return C
```
hint: Check `len(A[0]) == len(B)` first. Then for each `i` and `j`, add up `A[i][k] * B[k][j]` over `k` into `C[i][j]`.
solution: The three loops are exactly the formula $C_{ij} = \sum_k A_{ik}B_{kj}$. The identity test checks the indexing, the shape test catches a transposed index, and the noncommuting pair shows that the order of arguments matters.

model:
```python
def matmul_count(A, B):
    """Return (A @ B, number of scalar multiplications used)."""
    m, n, p = len(A), len(B), len(B[0])
    C = [[0 for _ in range(p)] for _ in range(m)]
    mults = 0
    for i in range(m):
        for j in range(p):
            for k in range(n):
                C[i][j] += A[i][k] * B[k][j]
                mults += 1
    return C, mults
```
hint: Add one to a counter in the innermost loop, right where the multiplication happens.
solution: The innermost body runs $m \cdot p \cdot n$ times, so the counter must end at $mnp$ whatever the entries are; the test with an all-zero matrix catches code that skips zeros. Starting `C` from integer zeros keeps integer inputs exact, so the comparison with integer lists is exact.
