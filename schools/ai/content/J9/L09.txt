@article
A **function** is a named block of code that you can use again and again. You have already called functions such as `print`, `len` and `int`. Now you will write your own, so that a long program can be built from small, well-named pieces.

```python
def double(x):
    return x * 2

print(double(4))    # 8
print(double(10))   # 20
```

The word `def` starts a **definition**. After it come the function's name, its **parameters** in parentheses, and a colon. The indented lines are the **body**. Defining a function does not run it: the body runs only when you **call** the function, such as `double(4)`. The value you pass in, `4`, is an **argument**, and the parameter `x` holds it during that call.

### return versus print

`return` ends the function and hands a value back to the caller, so the call itself becomes that value. That is why `print(double(4))` works: `double(4)` is `8`, and then `print` shows it.

A function that only prints does not give anything back:

```python
def show_double(x):
    print(x * 2)

result = show_double(4)   # prints 8
print(result)             # prints None
```

If a function finishes without reaching a `return`, it gives back the special value `None`, which means "nothing". Use `return` when another part of the program needs the answer, and `print` only for showing things to the user.

### Several parameters and default values

A function can take several parameters, separated by commas. The arguments are matched in order:

```python
def greet(name, greeting="Hello"):
    return f"{greeting}, {name}!"

print(greet("Maya"))          # Hello, Maya!
print(greet("Maya", "Hi"))    # Hi, Maya!
```

A parameter with `=` has a **default value** that is used when the caller leaves it out. Parameters with defaults go last.

### Local variables

A variable created inside a function is **local**: it exists only while the function runs.

```python
def add_tax(price):
    total = price * 2
    return total

add_tax(5)
print(total)   # NameError: total is not defined
```

Each call gets fresh local variables, so a function cannot accidentally change a variable of the same name outside it. Pass values in with parameters and get them out with `return`.

### Decisions inside functions

A function may have more than one `return`, usually in an `if`. The first `return` that runs ends the function immediately, so the lines after it are skipped. Make sure that every path ends in a `return`, or the caller will get `None`.

@example
title: Following a function call
problem: What does this program print?

```python
def f(a, b):
    return a * 10 + b

print(f(3, 4))
print(f(4, 3))
```
step: `f(3, 4)` sets `a` to `3` and `b` to `4`, so it returns `3 * 10 + 4`, which is `34`.
step: `f(4, 3)` sets `a` to `4` and `b` to `3`, so it returns `43`.
step: The order of the arguments matters, because they match the parameters by position.
step: The program prints `34` and then `43`.
answer: `34`, `43`

@example
title: Writing a function from a description
problem: Write `rectangle_area(width, height)` that returns the area of a rectangle.
step: Name the function and its two parameters in the `def` line.
step: The answer is a value the caller will use, so `return` it rather than printing it:

```python
def rectangle_area(width, height):
    return width * height
```
step: Test it with a call whose answer you know: `rectangle_area(3, 5)` returns `15`.
step: Because the function returns a value, you can use it inside other expressions, such as `rectangle_area(2, 3) + rectangle_area(1, 1)`, which is `7`.

@mistakes
- Using `print` where you needed `return`. The caller then receives `None` and cannot calculate with the result.
- Writing the `return` inside a loop or an `if` too early, so the function ends before it finished its job.
- Forgetting to call the function: `double` without parentheses and an argument is just the function's name.
- Expecting a variable made inside a function to exist outside it.

def is_even(n):

@practice code
prompt: Write `ticket_price(age, is_student=False)`. Children under 5 pay `0`. Otherwise students and people aged 65 or more pay `8`, and everyone else pays `12`. The function returns the price as a number.
starter:
```python
def ticket_price(age, is_student=False):
    pass
```
tests:
```python
assert ticket_price(3) == 0
assert ticket_price(30) == 12
assert ticket_price(30, True) == 8
assert ticket_price(70) == 8
assert ticket_price(4, True) == 0
assert ticket_price(5) == 12
```
model:
```python
def ticket_price(age, is_student=False):
    if age < 5:
        return 0
    if is_student or age >= 65:
        return 8
    return 12
```
hint: Check the free case first, because it beats the student discount.
hint: After the free case, one condition with `or` covers both discounts.
solution: Return `0` for ages under 5 first, so a young student still pays nothing. Then `is_student or age >= 65` gives `8`, and the final `return 12` handles everyone else. Because a `return` ends the function, no `else` is needed.

@quiz code
prompt: Write a function `average(a, b, c)` that returns the average of three numbers.
starter:
```python
def average(a, b, c):
    pass
```
tests:
```python
assert average(3, 6, 9) == 6
assert average(1, 1, 4) == 2
assert average(0, 0, 3) == 1
assert average(-3, 0, 3) == 0
```
model:
```python
def average(a, b, c):
    return (a + b + c) / 3
```
hint: The average is the total divided by the number of values.
hint: Put the sum in parentheses before dividing.
solution: `(a + b + c) / 3` adds first, then divides. Writing `a + b + c / 3` would divide only `c`, which fails the tests.
