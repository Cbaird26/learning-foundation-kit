@article
A result that only its authors can obtain is a rumor. Reproducibility is what turns a claim into something others can build on, and it is also a gift to your future self, who will not remember which flags you used six months ago.

### Terms

Terms vary between fields and papers, so check how a source uses them. In this course: a result is **reproducible** if someone else can obtain it using your code and data; it is **replicable** if an independent effort, with newly collected data or an independent implementation, reaches the same conclusion. Reproducibility is the minimum; replication is the stronger test that the finding is about the world and not about one pipeline.

### Why results fail to reproduce

- **Missing details**: hyperparameters, preprocessing, data splits, the random seeds, library versions, tuning ranges.
- **Variance**: Henderson and colleagues (2018) showed that small implementation differences and seed variation can change which method wins. Bouthillier and colleagues (2021) argue that comparisons should account for the sources of variance.
- **Nondeterminism**: some GPU operations, parallel data loading and library updates give different results from identical code. Aim for statistically equivalent results, with a documented note when bitwise equality is not possible.
- **Unequal comparisons**: baselines tuned less than the method.
- **Data leakage**: information from the test set reaching training. Kapoor and Narayanan (2023) surveyed fields that use machine learning and found leakage to be a common cause of results that did not reproduce, and proposed practices for avoiding it.

### Data leakage

**Leakage** happens when something in the training process contains information about the test targets that will not be available in real use. Common forms: duplicates or near-duplicates across the split; preprocessing (scaling, feature selection, imputation) fitted on all data before splitting; time series split at random so the model sees the future; splitting by example when examples from one person, patient or document belong together; and a feature that is a proxy for the label. Its effect is arithmetic. If a fraction $f$ of the test set also appears in training, and the model scores $a_{\text{dup}}$ on those items and $a_{\text{clean}}$ on the rest, the measured accuracy is
$$ a = f\,a_{\text{dup}} + (1-f)\,a_{\text{clean}}, $$
which is higher than the honest $a_{\text{clean}}$ whenever the model has memorized the duplicates.

### The checklist idea

Pineau and colleagues (2021) describe the reproducibility program at a major machine learning conference: a checklist for authors, encouragement to submit code, and a study of the program's outcomes. A checklist prompts authors to state their claims, give the details of models and data, report the number of runs and error bars, and describe compute. The exact checklists, code policies and ethics requirements differ across venues and change from year to year, so read the current ones before you submit.

### What a good release contains

1. **Code** at a tagged version, with a README giving the exact commands.
2. **Environment**: library versions, a lock file or container, and the hardware used.
3. **Configuration** files for every reported experiment, including seeds.
4. **Data** or exact instructions to obtain it, with a **license** statement; some data cannot be shared because of privacy, consent or licensing, and then you document how others can request access.
5. **Evaluation scripts** that produce the paper's tables, and raw per-seed results.
6. **Trained models** where releasing them is permitted and safe.
7. **Expected results and run time**, so a reader knows whether their rerun matches.

Deposit the release in a stable archive that gives a permanent identifier, and state a software license. Open science is a spectrum: some work cannot be fully open (private data, safety concerns, proprietary components), and the honest course is to document what is withheld and why. Institutions and funders may set rules on data management and sharing; learn them early.

### Your own habit

Set seeds, log configurations, keep a single command that reproduces each figure, and rerun your own pipeline from a clean checkout before you submit. If you cannot reproduce your own result, no one else will.

@example
title: How much can leakage inflate a score?
problem: A test set has 10,000 items. A check shows that 8% of them also appear in the training set. A model scores 99% on those duplicates and 80% on the remaining items. What accuracy would be reported, and how much of it is due to leakage?
step: Write the fractions: the duplicates are $f = 0.08$ and the clean items $1 - f = 0.92$.
step: Compute the reported accuracy: $a = 0.08 \times 0.99 + 0.92 \times 0.80 = 0.0792 + 0.736 = 0.8152$, that is 81.52%.
step: The honest accuracy on unseen items is the clean-subset score, 80%. The leak adds $81.52 - 80 = 1.52$ points.
step: Compare with typical method differences: a gain of one or two points claimed by a new method is the same size as this inflation, so a leak of this kind could create or erase a published improvement.
answer: 81.52% reported against an honest 80%: the leak inflates the score by 1.52 points.

@mistakes
- Fitting a scaler or feature selection on the whole data set before splitting, which leaks test statistics into training.
- Releasing code with no environment or seed information and calling it reproducible.
- Splitting by example when the data have groups (patients, users, documents), so the same group appears on both sides.
- Treating a checklist as a formality: it is a prompt to check each item for your own work before the reviewer does.

@practice num
prompt: A test set has 2,000 items. A check finds that 15% also appear in the training set. The model scores 96% on those duplicates and 70% on the rest. By how many percentage points does the leak inflate the overall accuracy above the score on the clean items? Give your answer to one decimal place.
answer: 3.9
tol: 0.01
unit: points
check: (0.15 * 0.96 + 0.85 * 0.70 - 0.70) * 100
hint: Compute the overall accuracy as a weighted average, then subtract the clean-item accuracy.
solution: The overall accuracy is $0.15 \times 0.96 + 0.85 \times 0.70 = 0.144 + 0.595 = 0.739$, or 73.9%. The honest score on unseen items is 70%, so the inflation is 3.9 points. Equivalently, the inflation is $0.15 \times (96 - 70) = 3.9$.

@practice mc
prompt: Which of these is an example of data leakage?
choice*: Standardizing every feature with the mean and standard deviation computed on the whole data set, and only then splitting it into training and test sets.
choice: Fixing the random seed for the train/test split and reporting the seed.
choice: Choosing hyperparameters on a validation set that was held out from training.
choice: Reporting the standard deviation of the test score across seeds.
hint: Look for a step where information about the test items reaches the training process.
solution: Computing statistics on the full data uses test items to shape the features that the model trains on. Fixing a seed, tuning on validation data kept separate from the test set, and reporting variability are all good practice.

prompt: A reproducibility audit scores 25 checklist items: 15 are fully satisfied, 6 are partly satisfied and 4 are not satisfied. If a fully satisfied item counts 1, a partly satisfied item 0.5 and an unsatisfied item 0, what is the audit score as a fraction of the maximum?
answer: 0.72

solution: The points are $15 + 3 + 0 = 18$ out of 25, a score of $18/25 = 0.72$. Such a score summarizes completeness; it does not say whether the unmet items are minor or fatal, so read the list as well.

@practice self
prompt: Write the reproducibility plan (180 to 250 words) for a project that fine-tunes a pretrained language model on a public data set, with 5 seeds, a hyperparameter search and a comparison to two baselines. Cover code, environment, configurations and seeds, data and license, evaluation scripts, what you will report, and anything you cannot release and why.
solution: Code will live in a version-controlled repository; the paper will cite a tagged release archived with a permanent identifier and a stated open-source license. A README will give the exact commands to reproduce each table and figure. The environment will be pinned by a lock file and a container recipe, listing library versions and the hardware used. Each reported run has a configuration file including its seed; the 5 seeds are fixed and shared across methods, and I will report that nondeterministic GPU operations may cause small differences between reruns on other hardware. The data set is public; the plan links to its source and states its license and any terms of use, and I will release the preprocessing and splitting scripts and the split indices so the splits are identical. The hyperparameter search ranges, budget and the best settings for each method (including both baselines, which get the same budget) will be tabulated. Per-seed results and the evaluation script that creates the tables will be released. The fine-tuned checkpoints will be released if the base model's license allows redistribution; if it does not, I will release the adapter or the training recipe and say why. I will rerun the full pipeline from a clean checkout before submission and follow the venue's current checklist.
hint: Walk through the release list: code, environment, configurations and seeds, data and license, evaluation, trained models, and what is withheld.
rubric: Covers code, pinned environment, configurations with seeds, data splits and license.
rubric: Gives equal documented tuning for baselines and reports per-seed results.
rubric: States what cannot be released and why, and mentions rerunning from a clean checkout and the venue's checklist.

@quiz num
prompt: A test set has 5,000 items, 12% of which also appear in the training set. A model scores 97% on those duplicates and 74% on the other items. What overall accuracy would be reported, as a percent to two decimal places?
answer: 76.76
tol: 0.01
unit: %
check: (0.12 * 0.97 + 0.88 * 0.74) * 100
hint: Weight the two subset accuracies by their shares of the test set.
solution: $0.12 \times 0.97 + 0.88 \times 0.74 = 0.1164 + 0.6512 = 0.7676$, so 76.76%. The honest accuracy is 74%, so the leak adds 2.76 points.
