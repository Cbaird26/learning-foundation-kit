@article
Every programmer wishes for a tool that reads a program and says whether it will ever stop running. Turing proved in 1936 that no such tool can exist, whatever the programming language and however clever the designer, provided that the language can compute everything a Turing machine can. This is the first great limit theorem about computation, and it is proved by the same device as Cantor's theorem.

### Decidable and semi-decidable sets

A set $S$ of natural numbers (or of strings) is **decidable** if some Turing machine halts on every input and halts with the answer "yes" for members of $S$ and "no" for non-members. $S$ is **semi-decidable** (computably enumerable) if some machine halts on exactly the members of $S$; on non-members it may run forever. A set is decidable if and only if both it and its complement are semi-decidable: run the two machines in alternation, and one of them must eventually halt.

Fix an enumeration $M_0, M_1, \ldots$ of all Turing machines, with $e$ a code for $M_e$ (next week we construct such codes). The **halting set** is $K = \{(e, x) : M_e \text{ halts on input } x\}$.

### The halting theorem

**Theorem (Turing 1936).** The halting set $K$ is not decidable: no Turing machine halts on every pair $(e, x)$ and answers correctly whether $M_e$ halts on $x$.

| P1 | If some machine $H$ decides the halting set, then there is a machine $D$ such that, for every $e$, $D$ halts on $e$ if and only if $H$ answers "no" on $(e, e)$. |
| P2 | If $H$ decides the halting set and $D$ is a machine as described in P1, with code $d$, then $D$ halts on $d$ if and only if $D$ does not halt on $d$. |
| P3 | It is not the case that $D$ halts on $d$ if and only if $D$ does not halt on $d$. |
| C | So no machine decides the halting set. |

The argument is valid: P1 and P2 give "if $H$ exists then $D$ halts on $d$ iff it does not", P3 denies this, so $H$ does not exist.

*Justification of P1.* Given $H$, build $D$: on input $e$, run $H$ on $(e, e)$; if $H$ answers "yes", enter an endless loop; if $H$ answers "no", halt. This is a legitimate machine (it can be written out as a transition table, or, by the Church-Turing thesis, described informally as an algorithm). *P2:* $H$ answers "no" on $(d, d)$ iff $D = M_d$ does not halt on $d$, since $H$ is correct. So $D$ halts on $d$ iff $H$ says "no" on $(d, d)$ iff $D$ does not halt on $d$. P3 is propositional logic: no sentence is equivalent to its own negation.

In Python the same argument reads: suppose `halts(prog, arg)` always returns the right `True` or `False`. Define

```python
def d(prog):
    if halts(prog, prog):
        while True:
            pass
    return "done"
```

Then $d(d)$ halts if and only if `halts(d, d)` is `False`, that is, if and only if $d(d)$ does not halt. So `halts` cannot exist.

The structure is Cantor's: arrange the halting behavior of all machines on all inputs in a table (row $e$, column $x$, entry "halts" or "loops"). The machine $D$ is built to disagree with row $e$ at the diagonal place $e$, so its behavior is not the behavior in any row; yet the table was supposed to contain a row for every machine, $D$ included.

### Semi-decidability

$K$ is semi-decidable: given $(e, x)$, simulate $M_e$ on $x$ (with a universal machine) and halt when it halts. So $K$ is semi-decidable but not decidable. It follows that its complement is not even semi-decidable: if it were, $K$ would be decidable by the alternation trick. A simulator with a step limit, as in `halts_within(program, input, n)`, can confirm halting but can never confirm non-halting.

### Reductions and Rice's theorem

To show a set $B$ undecidable, **reduce** a known undecidable set $A$ to it: give an algorithm that turns every instance of $A$ into an instance of $B$ with the same answer. If $B$ were decidable, so would $A$ be. For example, "does $M_e$ halt on the empty input?" is undecidable: from $(e, x)$, build a machine $N$ that ignores its input, writes $x$ on the tape and runs $M_e$; $N$ halts on the empty input iff $M_e$ halts on $x$.

**Rice's theorem.** Let $\mathcal{S}$ be any set of partial computable functions that is neither empty nor the set of all partial computable functions. Then $\{e : \text{the function computed by } M_e \text{ is in } \mathcal{S}\}$ is undecidable.

So every nontrivial question about what a program *does* (rather than about how it is written) is undecidable: whether it computes the constant function $0$, whether it ever outputs 7, whether two programs compute the same function.

### Logic and decision problems

Church and Turing independently showed in 1936 that the validity of first-order sentences is undecidable, which answered Hilbert's *Entscheidungsproblem* negatively. By completeness, validity is semi-decidable: enumerate all derivations and halt when you find one for the sentence. So first-order validity is semi-decidable and not decidable, like $K$. For propositional logic, truth tables decide validity. Another bridge to next week: a consistent, complete theory with a decidable set of axioms is decidable (enumerate derivations until you find a proof of $A$ or of $\neg A$), so the undecidability results already suggest that arithmetic cannot be both complete and effectively axiomatized.

@example
title: Diagonalizing a halting table
problem: A table shows whether four programs $p_0, \ldots, p_3$ halt (H) or loop (L) on inputs $0, 1, 2, 3$.

| program | input 0 | input 1 | input 2 | input 3 |
|---|---|---|---|---|
| $p_0$ | H | H | L | H |
| $p_1$ | L | H | L | L |
| $p_2$ | H | L | H | H |
| $p_3$ | L | L | H | L |

The program $D$ is defined by: on input $i$, $D$ halts if and only if $p_i$ loops on input $i$. Give the behavior of $D$ on inputs $0$ to $3$, and say how it differs from each row.
step: The diagonal entries are $p_0$ on 0: H; $p_1$ on 1: H; $p_2$ on 2: H; $p_3$ on 3: L.
step: $D$ halts on $i$ exactly when the diagonal entry is L. So $D$ loops on 0, loops on 1, loops on 2, and halts on 3: the pattern L, L, L, H.
step: Compare with row $p_0$: $D$ loops on 0 but $p_0$ halts there. Row $p_1$: $D$ loops on 1, $p_1$ halts. Row $p_2$: $D$ loops on 2, $p_2$ halts. Row $p_3$: $D$ halts on 3, $p_3$ loops.
step: So $D$ differs from every listed program at its own index. If the table were a list of all programs, $D$ would be a program missing from it: the same contradiction as in the halting theorem, here shown on a finite fragment.
answer: $D$ behaves L, L, L, H on inputs 0 to 3, so it differs from $p_i$ on input $i$ for each $i$.

@example
title: A reduction
problem: Show that the set $E = \{e : M_e \text{ halts on the empty input}\}$ is undecidable, using the undecidability of the halting set $K$.
step: Suppose a machine $T$ decides $E$.
step: Given any pair $(e, x)$, effectively construct a machine $N_{e,x}$ that ignores its input, writes $x$ on its tape and then runs $M_e$. The construction is mechanical: it just adds finitely many states that write $x$.
step: $N_{e,x}$ halts on the empty input if and only if $M_e$ halts on $x$.
step: So running $T$ on the code of $N_{e,x}$ decides whether $M_e$ halts on $x$. That decides $K$, contradicting the halting theorem. Hence $E$ is undecidable.
answer: $E$ is undecidable, because a decider for $E$ would decide $K$.

@mistakes
- Reading the theorem as "we cannot tell whether any program halts". Many programs are easily seen to halt or to loop; what fails is a single algorithm that is correct on all programs.
- Thinking that simulation decides halting: running the program for a long time shows halting if it happens, but no amount of running shows that the program loops.
- Treating the diagonal machine $D$ as a physical object: it is defined from the hypothetical decider $H$, and the proof shows that no such $H$ exists.
- Confusing "undecidable" (no algorithm) with "unprovable" or "unknown". A set is undecidable regardless of what anyone knows.

tests:
```python

        ('q0', '0'): ('halt', '0', 'R'),
        ('q0', '_'): ('q0', '_', 'R')}

```
model:
```python
def halts_within(delta, tape, limit):
    """True if the machine halts within limit steps on this input."""
    cells = dict(enumerate(tape))
    state, head = 'q0', 0
    for _ in range(limit):
        if state == 'halt':
            return True
        state, write, move = delta[(state, cells.get(head, '_'))]
        cells[head] = write
        head += 1 if move == 'R' else -1
    return state == 'halt'


def halting_inputs(delta, inputs, limit):
    """The inputs on which the machine halts within limit steps."""
    return [w for w in inputs if halts_within(delta, w, limit)]
```
hint: First write a helper that simulates the machine on one input for at most `limit` steps and reports whether it reached `'halt'`.
hint: Then filter `inputs` with that helper, keeping the original order.
solution: Simulate each input for at most `limit` steps, checking afterwards whether the state is `'halt'`; a machine that has not halted by then is simply left out. The test with limit 10 and limit 11 shows the point of the theorem in miniature: a bounded simulation can confirm halting but, when it reports nothing, it does not tell you whether the machine would halt later.

choice*: That a machine $H$ decides the halting set, so $D$ can consult $H$ on the pair $(e, e)$.
choice: That every machine halts on every input.
choice: That the set of machines is uncountable.

solution: $D$ is defined by calling the supposed decider $H$ on $(e, e)$ and doing the opposite of what it predicts. The proof ends in a contradiction, which shows that $H$ does not exist. The set of machines is countable, and the Church-Turing thesis is used only to see that $D$ is a machine.
