@article
What is an algorithm? For centuries mathematicians used the word for any finite, mechanical, step-by-step procedure, and nobody needed a definition. In the 1930s the question became pressing: Hilbert's *Entscheidungsproblem* asked for a procedure that decides whether a first-order sentence is valid, and to show that there is *no* such procedure one has to say exactly what a procedure is. In 1936 Turing gave an answer by analyzing what a human clerk does when calculating: write finitely many symbols on paper, look at a bounded part of it, and change a bounded part, guided by a finite stock of "states of mind". The result is the **Turing machine**.

### The definition

A **Turing machine** $M$ consists of:

- a finite set $Q$ of **states**, with a start state $q_0 \in Q$ and a halting state $q_{\text{halt}} \in Q$;
- a finite **tape alphabet** $\Gamma$ containing a **blank** symbol $\_$;
- a **transition function** $\delta$ that assigns to some pairs $(q, a)$ with $q \ne q_{\text{halt}}$ and $a \in \Gamma$ a triple $(q', b, D)$: the new state $q'$, the symbol $b$ to write, and a direction $D \in \{L, R\}$.

The tape is a two-way infinite row of cells, all blank except for finitely many. A **configuration** records the current state, the contents of the tape and the position of the head. In one **step** from a configuration with state $q$ and scanned symbol $a$ where $\delta(q, a) = (q', b, D)$, the machine writes $b$ in the scanned cell, moves the head one cell in direction $D$ and enters $q'$. A **computation** on input $w$ starts with $w$ written on the tape, the head on its first symbol and state $q_0$. It **halts** if it ever enters $q_{\text{halt}}$; otherwise it runs forever. A (partial) function $f$ on the natural numbers is **Turing computable** if some machine, started on a standard encoding of $n$ (say $n$ consecutive 1s), halts with the encoding of $f(n)$ on the tape when $f(n)$ is defined, and never halts otherwise.

Everything is finite and local: one rule per state-symbol pair, one cell at a time. Yet the model is robust. Machines with several tapes, with two-dimensional tapes, with several heads or with nondeterminism compute exactly the same functions (though perhaps more slowly).

### Computing with a transition table

Write a machine as a table. Here is a bit-flipping machine: in state $q_0$ reading $0$, write $1$, move $R$, stay in $q_0$; reading $1$, write $0$, move $R$, stay in $q_0$; reading a blank, halt. On the input $110$ it halts with $001$ after four steps (three flips and the final blank). In Python the table is a dictionary `{('q0', '0'): ('q0', '1', 'R'), ...}` from (state, symbol) pairs to triples, and a simulator is a short loop; a machine that never halts is detected only by a step limit.

### Universal machines and other models

Machines can be written down as finite strings, and strings can be coded by numbers (next week's topic is the coding in earnest). Turing proved that there is a **universal Turing machine** $U$: given a code of a machine $M$ and an input $w$, it simulates $M$ on $w$. So a single fixed machine can run every program: the stored-program computer in theory. Independently of Turing, Church (the $\lambda$-calculus), Gödel, Herbrand and Kleene (general recursive functions), Post, and others, proposed other definitions of computability. All these definitions turned out to compute exactly the same functions.

### The Church-Turing thesis

**Church-Turing Thesis.** A function on the natural numbers is effectively calculable (computable by some algorithm, in the informal sense of a finite mechanical procedure) if and only if it is Turing computable.

| P1 | A statement can be proved in the ordinary mathematical sense only if each of its terms has been given a precise mathematical definition. |
| P2 | "Effectively calculable" has no precise mathematical definition: it is an informal, pre-theoretic notion. |
| P3 | The Church-Turing thesis uses the term "effectively calculable". |
| C | So the Church-Turing thesis cannot be proved in the ordinary mathematical sense. |

The argument is valid. P2 is the standard reason for the word "thesis". The usual objection targets P1: Gandy (1980) and, in a different style, Sieg gave axiomatic analyses of mechanical computation (of what a human computer or a discrete mechanical device can do) from which Turing computability can be proved. Those who accept that these axioms capture the informal notion treat this as close to a proof; others reply that this sharpens the notion by adopting the axioms, so that the original gap simply moves to the axioms. The thesis is accepted because of the convergence of independently proposed definitions, Turing's analysis of the human computer, and the absence of any counterexample. We distinguish it from the *physical* Church-Turing thesis, which says something about what physical processes can compute; that question is empirical and open.

We shall use the thesis in two ways: to claim that an informal procedure is computable by describing it, and, with the theorem of next week, to infer that no algorithm at all can solve certain problems.

@example
title: Tracing a Turing machine
problem: The machine $S$ has states $q_0, q_1, \text{halt}$ with rules $(q_0, 1) \mapsto (q_0, 1, R)$, $(q_0, \_) \mapsto (q_1, \_, L)$, $(q_1, 1) \mapsto (q_1, 1, L)$ and $(q_1, \_) \mapsto (\text{halt}, \_, R)$. Started on the tape $11$ with the head on the left $1$, how many steps does it take before halting?
step: Step 1: state $q_0$ reads $1$ (position 0), writes $1$, moves right to position 1.
step: Step 2: $q_0$ reads $1$ (position 1), writes $1$, moves right to position 2, which is blank.
step: Step 3: $q_0$ reads a blank, so the machine enters $q_1$ and moves left to position 1.
step: Steps 4 and 5: $q_1$ reads $1$ at position 1 and moves left; $q_1$ reads $1$ at position 0 and moves left to position $-1$, a blank.
step: Step 6: $q_1$ reads a blank and enters the halting state. In all $6$ steps, with the tape still $11$.
answer: $6$ steps; the machine runs to the right end, turns, and runs back to the left end of the block.

@example
title: Is the thesis a theorem?
problem: A student says: "The Church-Turing thesis is just a theorem we have not found a proof of yet." Evaluate this.
step: A theorem is a statement that is proved from definitions and axioms. Its terms must be mathematically defined. "Turing computable" is defined precisely by the machine model.
step: "Effectively calculable" is not defined mathematically: it names the intuitive idea of a finite mechanical procedure. A statement that links an informal notion to a formal one cannot be proved by calculation alone.
step: So the student is wrong about what kind of statement the thesis is. It is a claim that a formal notion captures an informal one, and it is supported by evidence: independently proposed formalizations coincide, Turing's analysis of a human computer, and no function has been found that is computable in the informal sense but not Turing computable.
answer: The thesis is not a theorem waiting for a proof; it connects an informal notion to a formal one and rests on convergent evidence (and, for some, on axiomatic analyses of computation).

@mistakes
- Saying that Turing machines are a model of real computers' hardware. They are an idealization with unbounded memory and no concern for speed; their point is what is computable at all.
- Calling the Church-Turing thesis a proven theorem, or dismissing it as a mere guess. It is a thesis that connects an informal notion to a precise one and has strong support.
- Forgetting that a machine may never halt: "the machine computes a partial function", and for some inputs the output is undefined.
- Assuming that a longer program or a bigger machine can compute more. Extra tapes, heads or states compute the same class of functions.

model:
```python
def run_tm(delta, tape, max_steps):
    """Run a Turing machine for at most max_steps steps."""
    cells = dict(enumerate(tape))
    state, head = 'q0', 0
    for _ in range(max_steps):
        if state == 'halt':
            break
        symbol = cells.get(head, '_')
        state, write, move = delta[(state, symbol)]
        cells[head] = write
        head += 1 if move == 'R' else -1
    if state != 'halt':
        return None
    marked = [i for i, c in cells.items() if c != '_']
    if not marked:
        return ''
    return ''.join(cells.get(i, '_')
                   for i in range(min(marked), max(marked) + 1))
```
hint: Store the tape as a dictionary from positions to symbols and read missing cells as `'_'`.
hint: Loop at most `max_steps` times; in each pass look up the rule, write, move the head and change state. Check the state after the loop to decide between returning the tape and `None`.
solution: Keep the tape in a dictionary so it can grow in both directions. Each pass of the loop is one step of the machine. After the loop, the machine has halted exactly when its state is `'halt'`, including the case where it halts on the very last permitted step. The result is read off between the leftmost and rightmost non-blank cell. The test with a leftward move checks that cells with negative positions are handled.

@practice self
prompt: Explain in four or five sentences why the Church-Turing thesis is called a thesis rather than a theorem, and give one piece of evidence that supports it.
hint: Ask which of the two notions in the thesis has a precise mathematical definition.
solution: A theorem is proved from precise definitions, but the thesis equates a precisely defined class of functions (the Turing computable ones) with an informal notion, what can be computed by a finite mechanical procedure, which has no mathematical definition. So there is nothing to prove in the ordinary sense; the thesis is a claim that the formal definition captures the informal idea. It is supported by evidence. Independently proposed formalizations (Turing machines, the $\lambda$-calculus, general recursive functions) were proved to compute exactly the same functions, Turing's analysis of the human computer yields the machine model, and no one has found a procedure that everyone accepts as effective but which no machine can carry out. Some philosophers add that axiomatic analyses of mechanical computation, such as Gandy's, come close to proving the thesis from stated principles.
rubric: Says that "effectively calculable" is informal and lacks a mathematical definition, so the thesis is not provable in the ordinary sense.
rubric: Gives a correct piece of evidence, such as the equivalence of independently proposed formalizations.

model:
```python
def steps_taken(delta, tape, limit):
    """Number of steps until the machine halts, or None past the limit."""
    cells = dict(enumerate(tape))
    state, head = 'q0', 0
    for count in range(limit + 1):
        if state == 'halt':
            return count
        if count == limit:
            return None
        state, write, move = delta[(state, cells.get(head, '_'))]
        cells[head] = write
        head += 1 if move == 'R' else -1
    return None
```
hint: Count steps as you simulate, and check for the halting state before taking another step.
hint: If the machine halts after exactly `limit` steps, that still counts as halting within the limit.
solution: Simulate step by step with a counter. Before each step, test whether the state is `'halt'` and, if so, return the counter; stop with `None` when the counter reaches the limit without having halted. The tests at limits 5 and 4 check the boundary: halting on exactly the last allowed step counts as halting.
