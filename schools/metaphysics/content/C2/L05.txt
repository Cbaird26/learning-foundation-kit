@article
A program that evaluates formulas needs the formulas as data. A string such as `"P and Q or R"` is a poor choice: does it mean $(P \wedge Q) \vee R$ or $P \wedge (Q \vee R)$? Writing a program to settle that is a parsing problem in its own right. A **tree** has no such ambiguity: each connective is a node, and its parts hang below it. Python's nested tuples are a natural way to write trees.

### The representation used in this course

From now on a formula is one of the following.

| formula | Python value |
|---|---|
| a sentence letter $P$ | the string `'P'` |
| $\neg A$ | `('not', A)` |
| $A \wedge B$ | `('and', A, B)` |
| $A \vee B$ | `('or', A, B)` |
| $A \to B$ | `('imp', A, B)` |
| $A \leftrightarrow B$ | `('iff', A, B)` |

Here `A` and `B` stand for formulas, written in the same way. The formula $(P \to Q) \wedge \neg R$ becomes `('and', ('imp', 'P', 'Q'), ('not', 'R'))`. As a tree it has the following nodes:

| node | what it is | children |
|---|---|---|
| 1 | `and` (the main connective) | nodes 2 and 5 |
| 2 | `imp` | nodes 3 and 4 |
| 3 | the letter `P` | none |
| 4 | the letter `Q` | none |
| 5 | `not` | node 6 |
| 6 | the letter `R` | none |

The **main connective** is the one at the top of the tree, and the formula is a conjunction because that is its main connective. The tuple's nesting records the grouping, so there is nothing to parse.

### Taking formulas apart

The test `isinstance(f, str)` is `True` exactly when `f` is a sentence letter. Otherwise `f[0]` is the name of the main connective, and `f[1]` and (for the binary connectives) `f[2]` are the immediate parts. Unpacking is often clearer: `op, a, b = f` for a binary formula, and `op, a = f` for a negation. Indexing can go deeper: for `f = ('and', ('imp', 'P', 'Q'), ('not', 'R'))`, the value `f[1][2]` is `'Q'`.

### Building formulas and rewriting them

A function that returns a tuple builds a formula, and a function that takes a tuple apart and returns a new one rewrites it. The contrapositive of a conditional is a rewrite:

```python
def contrapositive(f):
    op, a, b = f
    return ('imp', ('not', b), ('not', a))
```

Tuples cannot be changed, so a rewrite always builds a new tuple and leaves the old one alone.

### Same tuple, same formula; but not the converse

Two tuples are equal (`==`) exactly when they are the same tree. That is **syntactic identity**. It is much stronger than **logical equivalence**, which asks only whether two formulas have the same truth value on every row. Consider this argument.

| P1 | If two formulas are the same tuple, then they are logically equivalent. |
| P2 | `('and', 'P', 'Q')` and `('and', 'Q', 'P')` are not the same tuple. |
| C | So $P \wedge Q$ and $Q \wedge P$ are not logically equivalent. |

Premise P1 is true, and so is P2, but the argument is invalid: it has the form $A \to B,\ \neg A \vdash \neg B$, **denying the antecedent**. Its conclusion is false, since both formulas are true exactly when $P$ and $Q$ are both true. The lesson for programming is that `f == g` tests whether two formulas are written identically, and an equivalence test needs truth tables (week 8).

@example
title: Encoding a formula as a tuple
problem: Write $\neg(P \vee Q) \to (\neg P \wedge \neg Q)$ as a nested tuple.
step: Find the main connective. The formula is a conditional, so it has the shape `('imp', A, B)` with $A = \neg(P \vee Q)$ and $B = \neg P \wedge \neg Q$.
step: $A$ is a negation of $P \vee Q$, so $A$ is `('not', ('or', 'P', 'Q'))`.
step: $B$ is a conjunction of two negations, so $B$ is `('and', ('not', 'P'), ('not', 'Q'))`.
step: Put the parts together: `('imp', ('not', ('or', 'P', 'Q')), ('and', ('not', 'P'), ('not', 'Q')))`.
answer: `('imp', ('not', ('or', 'P', 'Q')), ('and', ('not', 'P'), ('not', 'Q')))`

@example
title: Writing a rewriting function
problem: Write `contrapositive(f)` for a conditional formula `f`, and use it on `('imp', 'P', 'Q')`.
step: A conditional is a tuple with three items: the name `'imp'`, the antecedent and the consequent. Unpack them: `op, a, b = f`.
step: The contrapositive of $A \to B$ is $\neg B \to \neg A$, so negate each part and swap them.
step: Build the new tuple:

```python
def contrapositive(f):
    op, a, b = f
    return ('imp', ('not', b), ('not', a))
```
step: For `('imp', 'P', 'Q')` we have `a = 'P'` and `b = 'Q'`, so the result is `('imp', ('not', 'Q'), ('not', 'P'))`, which is $\neg Q \to \neg P$.
answer: `contrapositive(('imp', 'P', 'Q'))` returns `('imp', ('not', 'Q'), ('not', 'P'))`.

@mistakes
- Writing a binary connective with the wrong number of parts, such as `('and', 'P')` or `('not', 'P', 'Q')`: every tuple needs its operator name and exactly one (for `not`) or two (for the others) formulas.
- Forgetting the quotes: `('not', P)` refers to a variable `P`, while `('not', 'P')` contains the letter.
- Confusing the grouping of $\neg(P \wedge Q)$, which is `('not', ('and', 'P', 'Q'))`, with $\neg P \wedge Q$, which is `('and', ('not', 'P'), 'Q')`.
- Treating `f == g` as a test of logical equivalence; it tests only whether the two trees are identical.

```python
def conj(fs):

```
tests:

model:
```python
def conj(fs):
    result = fs[0]
    for g in fs[1:]:
        result = ('and', result, g)
    return result
```
hint: Start from the first formula and wrap each later formula around what you have.
hint: Loop over `fs[1:]` and replace `result` by `('and', result, g)` each time.
solution: Begin with `fs[0]`. For every later formula `g`, build a new conjunction whose left part is everything so far and whose right part is `g`. A one-item list never enters the loop, so it returns its single formula.
