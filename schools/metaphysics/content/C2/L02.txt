@article
Last week comparisons such as `5 > 3` produced the values `True` and `False`. Python's three logical operators combine such values, and they behave exactly like the connectives you met in propositional logic.

### and, or, not

| `p` | `q` | `p and q` | `p or q` | `not p` |
|---|---|---|---|---|
| `True` | `True` | `True` | `True` | `False` |
| `True` | `False` | `False` | `True` | `False` |
| `False` | `True` | `False` | `True` | `True` |
| `False` | `False` | `False` | `False` | `True` |

Python's `or` is the **inclusive** or of logic: it is true when both sides are true. Precedence, from tightest to loosest, is: comparisons (`==`, `<`, ...), then `not`, then `and`, then `or`. So `not p or q and r` means `(not p) or (q and r)`. A frequent surprise follows from this order: `not p == q` means `not (p == q)`, because `==` binds tighter than `not`. When in doubt, add parentheses; they cost nothing.

### Short-circuit evaluation

Python evaluates `a and b` left to right and stops as soon as the answer is settled. If `a` is `False`, then `b` is never evaluated; if `a` is `True` in `a or b`, the same holds. This is useful: `x != 0 and 10 // x > 1` is safe even when `x` is `0`, because the division is never reached. Be aware that `and` and `or` actually return one of their operands, so `0 or 5` is `5`; with real truth values the result is always a `bool`, and we will keep to truth values.

### The conditional and its relatives

There is no operator for the material conditional $P \to Q$, but you know it is false only when $P$ is true and $Q$ false, so it equals $\neg P \vee Q$:

```python
implies = (not p) or q      # P -> Q
iff = p == q                # P <-> Q: same truth value
xor = p != q                # exclusive or: different truth values
```

Because `False` counts as `0` and `True` as `1`, the expression `p <= q` also gives the conditional, but `(not p) or q` says what it means.

### Making decisions

An `if` statement runs its indented block only when its condition is `True`; `elif` adds further conditions, tried in order, and `else` catches the rest:

```python
if n < 0:
    print("negative")
elif n == 0:
    print("zero")
else:
    print("positive")
```

Exactly one block runs. The indentation (four spaces) is part of the syntax, and each condition line ends with a colon. To read data, `input()` returns the next line the user types as a **string**, so `n = int(input())` converts it to a number, and `answer = input() == "yes"` turns it into a truth value.

### Functions: a first look

Several exercises this week ask for a **function**, which packages an expression under a name. `def` starts it, the indented block is its body, and `return` hands back the result:

```python
def implies(p, q):
    return (not p) or q
```

The call `implies(True, False)` evaluates to `False`. The placeholder `pass` in a starter means "nothing here yet"; replace it with a `return` line. Week 3 covers functions in detail.

### An argument about a program

| P1 | If `p and q` is `True`, then `p` is `True`. |
| P2 | In this run of the program, `p` is `False`. |
| C | So in this run, `p and q` is `False`. |

This is **modus tollens**, so it is valid. Premise P1 is true by the table above: the only row where `p and q` is `True` has `p` true. So whenever P2 holds, the argument is sound, and you can run `print(False and q)` with any `q` to see the conclusion confirmed.

@example
title: Evaluating with precedence
problem: Let `p = False`, `q = True` and `r = False`. Find the value of `not p or q and r`, and say which parts Python evaluates.
step: Insert the parentheses that precedence implies: `not` binds tighter than `and`, and `and` tighter than `or`, so the expression is `(not p) or (q and r)`.
step: `not p` is `not False`, which is `True`.
step: Because the left side of `or` is `True`, Python short-circuits: the result is `True` and `q and r` is never evaluated. (Evaluating it anyway gives `True and False`, which is `False`, so the answer would not change.)
answer: `True`

@example
title: Choosing among four cases with elif
problem: With `p = False` and `q = True`, what does this program print? What does each `elif` really test?

```python
if p and q:
    print("both")
elif p:
    print("only P")
elif q:
    print("only Q")
else:
    print("neither")
```
step: `p and q` is `False`, so the first block is skipped.
step: `elif p` is tried next: `p` is `False`, so it is skipped too.
step: `elif q` is tried: `q` is `True`, so `only Q` is printed and the rest of the chain is skipped.
step: The `elif p` test never needs to say "and not q": it is reached only when `p and q` was false, so a true `p` there means `p` is true and `q` is false.
answer: It prints `only Q`.

@mistakes
- Writing `if x == 1 or 2:` to mean "x is 1 or 2". The `2` is a separate operand of `or`, not something compared with `x`, and it counts as true; write `x == 1 or x == 2`.
- Assuming `not p == q` means `(not p) == q`. It means `not (p == q)`.
- Using `if` for every case when only one block should run: separate `if` statements can all run, while an `if`/`elif` chain runs at most one.
- Forgetting that `input()` returns a string: `input() > 5` raises an error; convert with `int(input())` first.

def xor(p, q):

def xor(p, q):

@quiz num
prompt: The Python expression `(p and q) or not r` has three truth-value inputs, so there are 8 combinations. For how many of them is it `True`?
answer: 5

@quiz code
prompt: Write a function `majority(p, q, r)` that returns `True` when at least two of its three truth-value arguments are `True`.
starter:
```python
def majority(p, q, r):
    pass
```
tests:
```python
assert majority(True, True, False) == True
assert majority(False, True, True) == True
assert majority(True, False, True) == True
assert majority(True, False, False) == False
assert majority(False, False, False) == False
assert majority(True, True, True) == True
```
model:
```python
def majority(p, q, r):
    return (p and q) or (p and r) or (q and r)
```

solution: At least two are true exactly when `p and q`, or `p and r`, or `q and r` holds, so the function returns the `or` of the three pairs.
