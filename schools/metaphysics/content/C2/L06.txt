@article
A formula is a tree whose subtrees are formulas, and the truth value of a compound formula depends on the truth values of its parts. A function that handles a compound formula by calling itself on its parts mirrors that structure exactly. This technique, **recursion**, is the most important idea of the course.

### Valuations as dictionaries

A **valuation** assigns a truth value to every sentence letter. Python stores such an assignment in a **dictionary**, a collection of key-value pairs: `v = {'P': True, 'Q': False}`. Then `v['P']` is `True`, and asking for a key that is missing, such as `v['R']`, raises a `KeyError`. Week 11 treats dictionaries and sets in more depth; this is all we need now.

### Recursion

A **recursive** function calls itself. To be useful it needs a **base case**, which is answered directly, and a **recursive case**, which reduces the problem to smaller instances of the same problem. A small example, not about logic:

```python
def power2(n):
    if n == 0:
        return 1              # base case
    return 2 * power2(n - 1)  # recursive case
```

`power2(3)` calls `power2(2)`, which calls `power2(1)`, which calls `power2(0)`; that returns `1`, and the calls return `2`, `4` and `8` on the way back. It terminates because every call has a smaller `n`. A recursion over formulas terminates because every part of a formula is smaller than the whole.

### The evaluator

For formulas the base case is a sentence letter, and the recursive cases are the five connectives:

```python
def evaluate(f, v):
    """Truth value of formula f under the valuation v."""
    if isinstance(f, str):
        return v[f]
    op = f[0]
    if op == 'not':
        return not evaluate(f[1], v)
    a = evaluate(f[1], v)
    b = evaluate(f[2], v)
    if op == 'and':
        return a and b
    if op == 'or':
        return a or b
    if op == 'imp':
        return (not a) or b
    return a == b          # op == 'iff'
```

Each connective's rule is its truth table: `imp` is the function from week 3 and `iff` compares the two values. Other recursive functions over formulas have the same skeleton: one case for letters, one for `not`, and one for the binary connectives. You can often write the part for the five binary connectives once, because the parts are `f[1:]`.

### Why the evaluator is correct

We can argue for correctness by **structural induction**: every formula is built from letters by finitely many applications of the connectives.

| P1 | `evaluate` returns the correct truth value for every sentence letter. |
| P2 | If `evaluate` returns the correct value for formulas $A$ and $B$, then it returns the correct value for $\neg A$, $A \wedge B$, $A \vee B$, $A \to B$ and $A \leftrightarrow B$. |
| C | So `evaluate` returns the correct value for every formula. |

The argument is valid by the principle of structural induction. P1 holds because the base case looks the letter up in the valuation. P2 holds because each recursive case applies the connective's truth table to the (by hypothesis correct) values of the parts. So the argument is sound, and we may trust the evaluator on formulas of any size.

@example
title: Tracing a recursive evaluation
problem: Evaluate `('imp', 'P', ('not', 'Q'))` with `v = {'P': True, 'Q': True}`, listing the calls to `evaluate`.
step: The top call is `evaluate(('imp', 'P', ('not', 'Q')), v)`. The formula is not a string and its connective is `imp`, so the function first evaluates both parts.
step: `a = evaluate('P', v)`: `'P'` is a string, so the base case returns `v['P']`, which is `True`.
step: `b = evaluate(('not', 'Q'), v)` calls `evaluate('Q', v)`, which returns `True`; then the `not` case returns `not True`, which is `False`.
step: Back in the top call, `imp` returns `(not a) or b`, which is `(not True) or False`, which is `False`. In all, `evaluate` was called four times: for the conditional, for `P`, for the negation and for `Q`.
answer: `False`, after four calls

@example
title: A recursive function that measures formulas
problem: Write `depth(f)`, the greatest number of connectives on a path from the top of the tree to a letter. A letter has depth 0; for example `('imp', ('and', 'P', 'Q'), 'R')` has depth 2.
step: The base case is a letter: its depth is `0`.
step: For a negation, the depth is one more than the depth of its part: `1 + depth(f[1])`.
step: For a binary connective, the depth is one more than the larger of the depths of the two parts:

```python
def depth(f):
    if isinstance(f, str):
        return 0
    if f[0] == 'not':
        return 1 + depth(f[1])
    return 1 + max(depth(f[1]), depth(f[2]))
```
step: Check the example: the left part `('and', 'P', 'Q')` has depth 1, the right part `'R'` has depth 0, so the whole has depth `1 + max(1, 0) = 2`.
answer: The function above; `depth(('imp', ('and', 'P', 'Q'), 'R'))` is `2`.

@mistakes
- Omitting the base case, so the function keeps calling itself on a letter until Python raises a `RecursionError`.
- Calling `evaluate(f, v)` on the whole formula inside the recursive case instead of on a part, so the recursion never gets smaller.
- Treating the formula as a string and trying to search it for connectives; the tuple already shows the structure.
- Forgetting to pass the valuation `v` down in the recursive calls, which causes a `NameError` or a wrong answer.

```python
def substitute(f, name, g):
    if isinstance(f, str):
        return g if f == name else f
    return (f[0],) + tuple(substitute(part, name, g) for part in f[1:])
```

solution: A letter equal to `name` becomes `g`; any other letter stays. For a compound formula, substitute recursively in every part and put the same connective back in front, which works uniformly for `not` and the binary connectives.
