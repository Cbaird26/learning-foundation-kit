material: **Specification.** The program analyzes plain text. A *word* is a maximal run of letters (characters for which `str.isalpha()` is true), converted to lowercase; digits and punctuation separate words. Required functions:

- `words(text)` returns the list of words in order of appearance. `words("It's 5 o'clock!")` is `["it", "s", "o", "clock"]`.
- `word_counts(ws)` returns a dictionary mapping each word of the list `ws` to its number of occurrences.
- `top_words(counts, k)` returns the `k` most frequent words as a list of `(word, count)` tuples, sorted by count from high to low and, for equal counts, alphabetically. If there are fewer than `k` words, return all of them. Raise `ValueError` if `k < 0`.
- `sentences(text)` returns the number of sentences, defined as the number of `.`, `!` or `?` characters that are followed by whitespace or the end of the text.
- `summary(text)` returns a dictionary with the keys `"words"` (total words), `"distinct"` (distinct words), `"sentences"` and `"avg_word_length"` (total letters divided by total words as a float; `0.0` for no words).

Subclass `PlainReport` renders one `key: value` line for each summary entry followed by one `word: count` line for each top word. Subclass `TableReport` renders the same data as lines of the form `| key | value |`.

@review
**Week 1: expressions and types.** Values have types (`int`, `float`, `str`, `bool`). `/` gives a float, `//` floors, `%` satisfies `(a // b) * b + a % b == a`. Floats are approximate: compare with a tolerance. `input()` returns a string.

**Week 2: branching and iteration.** `if`/`elif`/`else` run the first true branch, so order tests from specific to general. Use `while` when the number of passes is not known, `for` with `range` (stop excluded) otherwise. Trace loops with a table.

**Week 3: strings and bisection.** Strings are immutable; slices `s[i:j]` exclude `j`. Approximations need a tolerance. Bisection halves the interval that contains the answer: about $\log_2$ of the width over the precision passes.

**Week 4: functions.** `return` is not `print`. Names are looked up locally, then enclosing, then globally. Specify a function with its preconditions and guarantees.

**Week 5: tuples, lists, aliasing.** `b = a` creates an alias; mutation is visible through every alias. Copy with `a[:]` or `a.copy()`; use `deepcopy` for nested data. `sort()` returns `None`.

**Week 6: dictionaries.** Keys are hashable, lookup is $O(1)$ on average. Counting uses `get(key, 0) + 1`; grouping builds a list per key. Build new nested containers instead of reusing inner ones.

**Week 7: recursion.** A base case plus a recursive case on a smaller instance. Naive Fibonacci is exponential; a memo makes it linear.

**Week 8: testing and exceptions.** Test typical, boundary and edge cases. `finally` always runs. Catch narrow exceptions; raise `ValueError` for bad values.

**Week 9: classes.** `self`, `__init__`, instance versus class attributes, special methods (`__repr__`, `__eq__`, `__add__`), and keeping invariants.

**Week 10: inheritance.** Override methods, call `super()`, rely on polymorphism, and choose composition for has-a relationships.

**Week 11: big-O.** Count steps, drop constants and lower terms. Nested loops multiply, halving gives a logarithm, `x in list` is $O(n)$, `x in set` is $O(1)$ on average.

**Week 12: searching and sorting.** Binary search needs sorted data and takes $O(\log n)$. Insertion and selection sort are $O(n^2)$; merge sort is $O(n \log n)$; Python's sort is stable.

**Self-check.** Can you: trace a loop and a recursive call by hand? Predict what two aliases do? Write a docstring that states preconditions? Choose tests that break a wrong solution? State the cost of a function and justify it? Explain a class hierarchy to someone else?

**Most common errors.** Off-by-one with `range` and slices; starting a maximum at 0; printing instead of returning; mutating an argument by accident; a missing base case; a bare `except`; forgetting `super().__init__`; using a list where a set or dictionary makes membership tests fast.

@exam code
prompt: Write `top_words(text, k)` that returns a list of `(word, count)` tuples for the `k` most frequent words of `text`. A word is a maximal run of letters (characters where `str.isalpha()` is true), converted to lowercase; any other character separates words. Sort by count from high to low and, for equal counts, alphabetically. If there are fewer than `k` distinct words, return all of them; `k = 0` gives `[]`.
starter:
```python
def top_words(text, k):
    pass
```
tests:
```python
text = "The cat and the hat. The CAT sat!"
assert top_words(text, 2) == [("the", 3), ("cat", 2)]
assert top_words(text, 4) == [("the", 3), ("cat", 2), ("and", 1), ("hat", 1)]
assert len(top_words(text, 10)) == 5
assert top_words("", 3) == []
assert top_words("Don't stop", 3) == [("don", 1), ("stop", 1), ("t", 1)]
assert top_words(text, 0) == []
assert top_words("a1b2a", 2) == [("a", 2), ("b", 1)]
```
model:
```python
def top_words(text, k):
    counts = {}
    word = ""
    for ch in text.lower() + " ":
        if ch.isalpha():
            word += ch
        elif word:
            counts[word] = counts.get(word, 0) + 1
            word = ""
    ranked = sorted(counts.items(), key=lambda pair: (-pair[1], pair[0]))
    return ranked[:k]
```
hint: Split the problem: first build the list of words by scanning characters, then count, then sort.
hint: To sort by count descending and then by word ascending, use `sorted(counts.items(), key=...)` with a key that returns the tuple `(-count, word)`.
solution: Scan the lowercased text, appending letters to the current word and ending the word at the first non-letter (a trailing space flushes the last word). Count words in a dictionary, sort the `(word, count)` pairs by the key `(-count, word)`, and slice the first `k`. Counting is $O(n)$ for `n` characters and sorting the distinct words is $O(d \log d)$.

@exam code
prompt: Write the exception class `OutOfStock` (a subclass of `Exception`) and a class `Inventory` that keeps item quantities and prices (in whole cents). `add(name, qty, price)` raises `ValueError` if `qty <= 0`; otherwise it adds `qty` units of `name` and sets its price to `price`. `remove(name, qty)` raises `KeyError` if `name` is unknown and `OutOfStock` if fewer than `qty` units are in stock; a failed call changes nothing; an item whose quantity reaches zero is deleted. `quantity(name)` returns the units in stock (`0` for an unknown name), `value()` returns the sum of `quantity * price` over all items, and `names()` returns the sorted list of item names.
starter:
```python
class OutOfStock(Exception):
    pass
```
tests:
```python
inv = Inventory()
inv.add("pen", 10, 150)
inv.add("ink", 2, 900)
assert inv.value() == 3300
inv.add("pen", 5, 200)
assert inv.quantity("pen") == 15
assert inv.value() == 4800
inv.remove("pen", 3)
assert inv.quantity("pen") == 12
assert raises(OutOfStock, inv.remove, "ink", 3)
assert inv.quantity("ink") == 2
assert raises(KeyError, inv.remove, "cup", 1)
assert raises(ValueError, inv.add, "cup", 0, 100)
assert inv.names() == ["ink", "pen"]
inv.remove("ink", 2)
assert inv.names() == ["pen"]
assert inv.quantity("ink") == 0
assert inv.value() == 2400
other = Inventory()
assert other.names() == []
assert other.value() == 0
```
model:
```python
class OutOfStock(Exception):
    pass


class Inventory:
    def __init__(self):
        self._stock = {}
        self._price = {}

    def add(self, name, qty, price):
        if qty <= 0:
            raise ValueError("qty must be positive")
        self._stock[name] = self._stock.get(name, 0) + qty
        self._price[name] = price

    def remove(self, name, qty):
        if name not in self._stock:
            raise KeyError(name)
        if qty > self._stock[name]:
            raise OutOfStock(name)
        self._stock[name] -= qty
        if self._stock[name] == 0:
            del self._stock[name]
            del self._price[name]

    def quantity(self, name):
        return self._stock.get(name, 0)

    def value(self):
        total = 0
        for name in self._stock:
            total += self._stock[name] * self._price[name]
        return total

    def names(self):
        return sorted(self._stock)
```
hint: Keep two dictionaries inside the object, created in `__init__`: one for quantities and one for prices.
hint: Validate and raise before changing anything, so a failed `remove` leaves the inventory unchanged.
solution: Store quantities and prices in per-object dictionaries. `add` validates, then increases the quantity and sets the price; `remove` checks the unknown name, then the shortage, and only then subtracts, deleting an item that reaches zero. `value` sums over the items and `names` returns `sorted` keys. Because the dictionaries are created in `__init__`, inventories do not share data.

@exam code
prompt: Write `can_make(nums, target)` that returns `True` if some subset of the list `nums` of non-negative integers (possibly the empty subset, each position used at most once) has a sum equal to the non-negative integer `target`, and `False` otherwise. Use recursion: either the first item is used or it is not. The input list must not change.
starter:
```python
def can_make(nums, target):
    pass
```
tests:
```python
data = [3, 34, 4, 12, 5, 2]
assert can_make(data, 9) is True
assert can_make(data, 30) is False
assert can_make(data, 0) is True
assert data == [3, 34, 4, 12, 5, 2]
assert can_make([], 5) is False
assert can_make([], 0) is True
assert can_make([5], 5) is True
assert can_make([1, 1], 2) is True
assert can_make([4], 2) is False
assert can_make([2, 2, 2], 5) is False
```
model:
```python
def can_make(nums, target):
    if target == 0:
        return True
    if not nums or target < 0:
        return False
    first = nums[0]
    rest = nums[1:]
    return can_make(rest, target - first) or can_make(rest, target)
```
hint: The base cases are `target == 0` (the empty subset works) and an empty list with a positive target.
hint: Otherwise there are two choices for the first item: use it (reduce the target by it) or skip it. Return `True` if either choice works.
solution: With `target == 0` the empty subset works; with no items left (or a negative target) it is impossible. Otherwise try using the first item, `can_make(rest, target - first)`, and skipping it, `can_make(rest, target)`. Each level makes two calls, so the worst-case time is $O(2^n)$ for `n` items, which is why larger inputs need memoization or dynamic programming.
