## Week-by-week key ideas

**Week 1, integers.** A bit pattern has no meaning without a representation. Unsigned $n$-bit values are $0$ to $2^n-1$; two's complement covers $-2^{n-1}$ to $2^{n-1}-1$, negation is invert and add 1, sign extension copies the top bit, and signed overflow means equal operand signs with a different result sign.

**Week 2, floating point.** Binary32 has 1, 8 and 23 bits (bias 127); binary64 has 1, 11 and 52 (bias 1023). Normal values are $(-1)^s\,1.f\times2^{e-bias}$; exponent 0 gives zeros and subnormals; the all-ones exponent gives infinities and NaN. Results are rounded to nearest, ties to even, so arithmetic is approximate and not associative.

**Week 3, Boolean algebra.** Truth tables, sum of products, the identities (especially De Morgan, absorption and combining), Karnaugh maps, and NAND as a universal gate.

**Week 4, circuits.** Full adder, ripple-carry adder (delay linear in the width), subtraction as $A+\bar B+1$, multiplexers, decoders; SR latch, D flip-flop (edge triggered), registers with load enable, and the clock period as clock-to-Q plus critical path plus setup.

**Week 5, ISA.** RV32I registers and ABI names, `x0` is zero, the R, I, S, B, U and J formats and how to encode and decode them.

**Week 6, assembly.** Arithmetic, shifts, `slt` versus `sltu`, loads and stores with base plus offset, little-endian order, branches (signed and unsigned) and loops.

**Week 7, functions.** `jal`/`ret`, argument and result registers, caller-saved versus callee-saved registers, prologue and epilogue, the downward-growing stack and recursion.

**Week 8, C to assembly.** Statement patterns, array indexing with scaling, pointers, structure layout and padding.

**Week 9, single-cycle datapath.** Components, control signals, instruction paths, and the clock period set by the slowest instruction (`lw`).

**Week 10, pipelining.** Five stages, $k+n-1$ cycles, structural, data and control hazards, forwarding, the load-use stall and branch handling.

**Week 11, caches.** Locality, tag, index and offset, direct-mapped versus set-associative caches, LRU, write policies, the three Cs, and AMAT.

**Week 12, performance.** CPU time = IC x CPI x clock period, weighted CPI, Amdahl's law, misleading metrics and benchmarking.

## Most common errors

Forgetting the bias or the implicit 1 in floating point; mixing signed and unsigned branches; not scaling array indexes; not saving `ra` or callee-saved registers; unbalanced `sp`; forgetting the load-use stall; computing the tag without removing the index bits; and applying Amdahl's law with the wrong fraction.

```python
def disassemble_r(word):
    rd = (word >> 7) & 0x1F
    funct3 = (word >> 12) & 0x7
    rs1 = (word >> 15) & 0x1F
    rs2 = (word >> 20) & 0x1F
    funct7 = word >> 25
    names = {
        (0, 0x00): "add", (0, 0x20): "sub", (1, 0x00): "sll",
        (2, 0x00): "slt", (3, 0x00): "sltu", (4, 0x00): "xor",
        (5, 0x00): "srl", (5, 0x20): "sra", (6, 0x00): "or",
        (7, 0x00): "and",
    }
    return f"{names[(funct3, funct7)]} x{rd}, x{rs1}, x{rs2}"
```

prompt: A program executes $2\times10^{9}$ instructions on a processor clocked at 2 GHz ($2\times10^{9}$ cycles per second). Without memory stalls the base CPI is 1.2. 35% of the instructions are loads or stores, 4% of those accesses miss in the cache, and each miss stalls the processor for 50 cycles (instruction fetches never stall). How many seconds does the program take? Give a decimal accurate to 0.001.
answer: 1.9
tol: 0.001
check: 2e9 * (1.2 + 0.35 * 0.04 * 50) / 2e9
hint: First compute the CPI including memory stalls: base CPI plus accesses per instruction times miss rate times penalty.
hint: Then use time = instruction count x CPI / frequency.
solution: Stall cycles per instruction are $0.35\times0.04\times50=0.7$, so the CPI is $1.2+0.7=1.9$. The time is $2\times10^9\times1.9/(2\times10^9)=1.9$ s.

prompt: Consider `lw x6, 8(x5)` followed directly by `add x7, x6, x6` on the five-stage pipeline of the course with full forwarding. (a) Give the fields of the machine word for the `lw` (opcode, funct3, rd, rs1 and the immediate) and its hexadecimal value. (b) Say what happens in each of the five stages for the `lw`. (c) Explain why the `add` needs a stall even with forwarding, and draw the diagram of the two instructions with total cycles.
solution: (a) `lw` is I-type with opcode `0x03`, funct3 `2`, rd `6`, rs1 `5` and immediate `8`, giving the word `0x0082A303`. (b) IF fetches the word at the PC. ID decodes it, reads `x5` and sign-extends the immediate 8. EX adds `x5 + 8` in the ALU to form the address. MEM reads the data memory at that address. WB writes the loaded value into `x6`. (c) The loaded data exists only at the end of MEM, but the `add` needs `x6` at the start of its EX stage, which would be one cycle too early, so the `add` stalls one cycle in ID and then receives the value by forwarding from the MEM/WB register:

```text
            1   2   3   4   5   6   7
lw  x6,..   IF  ID  EX  MEM WB
add x7,..       IF  ID  s   EX  MEM WB
```

The two instructions take 7 cycles: 6 for an ideal pipeline plus 1 stall.
