@article
Assembly language is a readable spelling of machine instructions. This lesson covers the three things nearly every program needs: computing on registers, moving data to and from memory, and changing the order of execution.

### Arithmetic and logic

The R-type instructions `add`, `sub`, `and`, `or`, `xor`, `sll`, `srl`, `sra`, `slt` and `sltu` take two source registers and a destination: `add t0, t1, t2` means `t0 = t1 + t2`. Most have an immediate form: `addi`, `andi`, `ori`, `xori`, `slli`, `srli`, `srai`, `slti`, `sltiu`. There is no `subi`, since `addi t0, t1, -5` does the job. Arithmetic wraps modulo $2^{32}$ and never traps.

Shifts: `sll` shifts left filling with zeros; `srl` shifts right filling with zeros (**logical**); `sra` shifts right copying the sign bit (**arithmetic**, correct for signed values). Only the low 5 bits of the shift amount are used. Shifting left by $k$ multiplies by $2^k$, which is how array indexes are scaled.

`slt rd, rs1, rs2` sets `rd` to 1 if `rs1 < rs2` comparing as **signed** numbers and 0 otherwise; `sltu` compares as **unsigned**. The pseudo-instructions `li rd, imm` (load immediate), `mv rd, rs` (copy) and `neg` save typing.

### Memory

Memory is an array of bytes, each with its own address. A load or store computes the address `rs1 + offset`, where the offset is a signed 12-bit immediate: `lw t0, 8(a0)` loads the 32-bit word at address `a0 + 8` into `t0`, and `sw t0, 8(a0)` stores it. For smaller data there are `lb`/`lbu` (load a byte, sign- or zero-extended), `lh`/`lhu` (16 bits) and `sb`/`sh` (store the low byte or halfword). Words should be aligned to multiples of 4.

RISC-V is **little-endian**: the least significant byte of a word is at the lowest address. If the word `0x12345678` is stored at address 0x100, then address 0x100 holds `0x78`, 0x101 holds `0x56`, 0x102 holds `0x34` and 0x103 holds `0x12`.

To read element `i` of an array of 4-byte integers whose base address is in `a0`, scale the index and add: `slli t1, t0, 2` then `add t1, a0, t1` then `lw t2, 0(t1)`.

### Branches and loops

Conditional branches compare two registers and jump to a label if the condition holds: `beq`, `bne`, `blt`, `bge` (signed) and `bltu`, `bgeu` (unsigned). The target is encoded as a signed offset from the branch's own address, so code stays valid wherever it is loaded. There is no branch-on-greater-than; swap the operands (`bgt a, b, L` is `blt b, a, L`). `j label` is an unconditional jump, a pseudo-instruction for `jal x0, label`.

An `if (a < b) { ... }` becomes a branch that skips the body when the condition is false, so you test the **opposite** condition: `bge a, b, skip`. A loop has a test at the top (or bottom) and a jump back. Here is a complete function that sums an array of `n` integers (`a0` holds the address, `a1` holds `n`, and the sum is returned in `a0`; `ret` is explained next week):

```text
sum_array:
    li   t0, 0          # sum = 0
    li   t1, 0          # i = 0
loop:
    bge  t1, a1, done   # if i >= n, leave the loop
    slli t2, t1, 2      # t2 = i * 4
    add  t2, a0, t2     # t2 = address of a[i]
    lw   t3, 0(t2)      # t3 = a[i]
    add  t0, t0, t3     # sum += a[i]
    addi t1, t1, 1      # i += 1
    j    loop
done:
    mv   a0, t0         # return value
    ret
```

### Tracing

To trace a program, keep a table of the registers that change and step through one instruction at a time, applying the instruction exactly. Remember that after a taken branch execution continues at the label, otherwise at the next instruction. Tracing by hand is the way to find bugs the assembler cannot see.

@example
title: Tracing the array-sum loop
problem: Trace `sum_array` for the array `[4, -1, 7]` with `a1 = 3`. What does it return?
step: Initially `t0 = 0` (sum), `t1 = 0` (i). Test: `0 >= 3` is false, so the body runs: `t3 = a[0] = 4`, `t0 = 4`, `t1 = 1`.
step: `1 >= 3` is false: `t3 = -1`, `t0 = 3`, `t1 = 2`.
step: `2 >= 3` is false: `t3 = 7`, `t0 = 10`, `t1 = 3`.
step: `3 >= 3` is true, so `bge` jumps to `done`, `a0 = t0 = 10`, and `ret` returns.
answer: `10`

@example
title: Bytes, endianness and sign extension
problem: The word `0xA1B2C3D4` is stored at address 0x1000, and `t6` holds 0x1000. What do `lbu t0, 1(t6)` and `lb t1, 1(t6)` load?
step: Little-endian order puts the bytes at 0x1000, 0x1001, 0x1002, 0x1003 as `D4`, `C3`, `B2`, `A1`.
step: Both instructions read the byte at address `0x1000 + 1 = 0x1001`, which is `0xC3`.
step: `lbu` zero-extends: `t0 = 0x000000C3 = 195`.
step: `lb` sign-extends from bit 7, which is 1: `t1 = 0xFFFFFFC3 = -61`.
answer: `t0 = 195`, `t1 = -61`

@mistakes
- Testing the same condition as the `if` instead of its opposite when branching around the body.
- Using `blt` on values that are really unsigned (addresses, sizes), which treats large values as negative; use `bltu`.
- Forgetting to scale an array index by the element size (adding `i` instead of `4 * i` for `int` data).
- Assuming big-endian byte order when reasoning about the bytes of a stored word.

```python
def branch_taken(op, a, b):
```

tests:
```python
assert branch_taken("beq", 5, 5) is True
assert branch_taken("bne", 5, 5) is False
assert branch_taken("blt", 0xFFFFFFFF, 1) is True

assert branch_taken("bge", 1, 0xFFFFFFFF) is True
```

model:
```python
def signed(x):
    return x - (1 << 32) if x & 0x80000000 else x


def branch_taken(op, a, b):
    if op == "beq":
        return a == b
    if op == "bne":
        return a != b
    if op == "blt":
        return signed(a) < signed(b)
    if op == "bge":
        return signed(a) >= signed(b)
    if op == "bltu":
        return a < b
    return a >= b
```
hint: First write a helper that converts an unsigned 32-bit value to its signed meaning: subtract $2^{32}$ when bit 31 is set.
hint: Use the converted values for `blt` and `bge`, and the raw values for `bltu` and `bgeu`.
solution: Convert each operand to signed form with `x - (1 << 32)` when bit 31 is set, and compare those for `blt` and `bge`. Unsigned branches compare the raw numbers. Always return a real `bool` from a comparison.

model:
```python
MASK = 0xFFFFFFFF


def signed(x):
    return x - (1 << 32) if x & 0x80000000 else x


def alu(op, a, b):
    shamt = b & 31
    if op == "add":
        r = a + b
    elif op == "sub":
        r = a - b
    elif op == "and":
        r = a & b
    elif op == "or":
        r = a | b
    elif op == "xor":
        r = a ^ b
    elif op == "sll":
        r = a << shamt
    elif op == "srl":
        r = a >> shamt
    elif op == "sra":
        r = signed(a) >> shamt
    elif op == "slt":
        r = int(signed(a) < signed(b))
    else:
        r = int(a < b)
    return r & MASK
```
hint: Compute the result as an ordinary Python integer and mask it with `0xFFFFFFFF` at the end so that it wraps.
hint: Python's `>>` on a negative integer is already an arithmetic shift, so for `sra` convert `a` to its signed value first. Use `b & 31` as the shift amount.
solution: Compute each operation on Python integers, converting to signed values for `sra` and `slt`, and mask the result to 32 bits at the end. The mask turns $-1$ into `0xFFFFFFFF` and wraps overflowing sums.

@quiz num
prompt: What value is in `a0` when this program finishes?

```text
    li   a0, 1
    li   t0, 0
    li   t1, 6
again:
    slli a0, a0, 1
    addi t0, t0, 1
    bne  t0, t1, again
```
answer: 64
check: 1 << 6
hint: The loop body runs until `t0` reaches 6. What does `slli a0, a0, 1` do to `a0`?
solution: Each pass doubles `a0`. The body runs 6 times (`t0` goes 1 to 6, and `bne` stops when `t0 == 6`), so `a0 = 1 * 2^6 = 64`.
