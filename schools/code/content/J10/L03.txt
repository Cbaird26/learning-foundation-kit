@article
A computer only stores bits, so every kind of information needs an agreed way to become numbers. The trick is always the same: **choose a code that everyone shares**.

### Text

Each character gets a number called its **code point**. The old standard **ASCII** gives 128 characters their numbers: `A` is 65, `B` is 66, `a` is 97, and the space is 32. **Unicode** extends this idea to over a hundred thousand characters from writing systems all over the world, plus emoji. The most common way to store Unicode in files is **UTF-8**, which uses 1 byte for ASCII characters and 2 to 4 bytes for others. In Python, `ord` gives a character's code and `chr` goes back:

```python
print(ord("A"))                      # 65
print(chr(97))                       # a
print([ord(c) for c in "Hi"])        # [72, 105]
```

### Images

A digital image is a grid of tiny squares called **pixels**. Each pixel's colour is stored as three numbers from 0 to 255: how much **red**, **green** and **blue** light to mix. `(255, 0, 0)` is pure red, `(0, 0, 0)` is black and `(255, 255, 255)` is white. Three bytes per pixel is 24 bits, so such a pixel can have $256^3 = 16{,}777{,}216$ different colours.

The **resolution** is the number of pixels across and down. An uncompressed image needs

$$\text{bytes} = \text{width} \times \text{height} \times 3.$$

A photo of 4000 by 3000 pixels is 12 million pixels, about 36 MB before any compression.

### Sound

Sound is a smooth wave of air pressure. To store it, the computer **samples** the wave: it measures the height many times per second and stores each measurement as a number. The **sample rate** is how many measurements are taken per second. Audio CDs use 44,100 samples per second. More samples per second and more bits per sample give a more accurate copy, but also a bigger file.

### The big idea

Once something is numbers, a computer can store it, copy it, send it and change it. A photo, a song and a message are all just long lists of bytes, and what they *mean* depends on which code the program uses to read them.

@example
title: Turning a word into numbers
problem: What numbers stand for the text `Hi!` in ASCII, and what are they in binary?
step: Look up each character: `H` is 72, `i` is 105 and `!` is 33.
step: Write each number as 8 bits: 72 = 64 + 8 = `01001000`.
step: 105 = 64 + 32 + 8 + 1 = `01101001`, and 33 = 32 + 1 = `00100001`.
step: The message is three bytes: `01001000 01101001 00100001`.
answer: 72, 105, 33

@example
title: How big is a small image?
problem: An uncompressed picture is 100 pixels wide and 50 pixels tall. Each pixel uses 3 bytes. How many bytes is the picture?
step: Count the pixels: $100 \times 50 = 5000$.
step: Multiply by 3 bytes per pixel: $5000 \times 3 = 15000$.
step: In Python, `100 * 50 * 3` gives `15000`.
answer: 15000 bytes

@mistakes
- Thinking the character `"7"` and the number 7 are the same thing. The character `"7"` has code 55.
- Forgetting the factor of 3 (red, green and blue) when working out an image's size.
- Mixing up the number of pixels with the number of bytes.
- Believing a higher sample rate makes a sound louder. It makes the stored copy more accurate, not louder.

```python
def to_codes(text):
    codes = []
    for ch in text:
        codes.append(ord(ch))
    return codes

def gray(pixel):

```

solution: Unpack the tuple, add the three values and divide with `//`. For `(10, 20, 31)` the sum is 61 and `61 // 3` is 20. Using `/` would give a decimal such as 20.33.
