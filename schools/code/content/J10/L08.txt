@article
Everything you save is a **file**: a named sequence of bytes. A photo, a song, a school essay and a game are all files. To keep thousands of files organised, the operating system groups them into **folders** (also called directories). A folder can hold files and other folders, so the folders form a tree. The **path** of a file shows where it lives, for example `documents/school/notes.txt`.

### File formats

The bytes in a file mean nothing without a **file format**, an agreed way to interpret them. The **extension** at the end of the name (`.txt`, `.png`, `.mp3`, `.py`) hints at the format so the OS can pick a program to open it. A **text file** holds characters (ASCII or UTF-8) that you can read in any text editor. A **binary file** holds bytes in a special layout, such as a compressed photo, and looks like nonsense in a text editor. Renaming `photo.png` to `photo.txt` does not change the bytes; it only makes the computer guess wrongly.

```python
with open("notes.txt", "w") as f:       # create or overwrite a file
    f.write("buy milk\n")
    f.write("call Sam\n")

with open("notes.txt") as f:            # read it back
    for line in f:
        print(line.strip())
```

The first block writes two lines, and the second reads them back and prints `buy milk` and `call Sam`. A `with` block closes the file for you.

### Blocks and the file system

Storage is split into equal pieces called **blocks** (or clusters), commonly 4096 bytes. A **file system** keeps a table with each file's name, size, dates and the blocks that hold its data; this information about the file is **metadata**. A file always uses whole blocks, so a file of 10,000 bytes needs $\lceil 10000 / 4096 \rceil = 3$ blocks. Large files may sit in blocks that are not next to each other, and the table says where to find them.

When you **delete** a file the system usually just removes its entry and marks the blocks as free to reuse; the bytes stay on the drive until something overwrites them.

### What happens when you open a file

1. You double-click the file. The OS looks the name up in the file system's table.
2. It uses the extension to choose a program, and starts that program as a process.
3. The OS reads the file's blocks from storage into RAM.
4. The program interprets the bytes according to the file format, for example turning them into pixels, and shows the result.

@example
title: Counting blocks
problem: A drive uses blocks of 1000 bytes. How many blocks does a 2500-byte file use?
step: Divide the size by the block size: $2500 \div 1000 = 2.5$.
step: A file can only use whole blocks, so round **up**.
step: The file uses 3 blocks, and the last one is only half full.
answer: 3 blocks

@example
title: Opening a photo
problem: Describe what happens when you double-click `beach.jpg`.
step: The OS finds the entry for `beach.jpg` in the file system and learns which blocks hold it.
step: From the extension `.jpg` it picks an image viewer and starts it as a process.
step: The OS copies the file's blocks from storage into RAM for the viewer.
step: The viewer decompresses the data into pixels and the screen shows the picture.
answer: Find the file, start a program, load the bytes into RAM, decode them and display them.

@mistakes
- Believing a file's extension changes its contents. It is only a label that tells the computer which program to try.
- Rounding down when counting blocks. A partly filled block is still used by the file.
- Thinking deleting a file instantly erases its bytes. Usually only the table entry is removed.
- Mixing up storage and RAM: opening a file copies data from storage into RAM; it does not move the file.

def blocks_needed(size, block_size):
