@article
The **internet** is the network that moves packets. The **web** is one service that runs on it: pages and files that your **browser** asks for and displays. Email and online games also use the internet, but they are not the web.

### URLs

A **URL** is a web address, such as `https://www.example.com/shop/hats.html`. It has parts:

- the **scheme** (`https`), the protocol to use;
- the **host** or domain name (`www.example.com`), which computer to ask;
- the **path** (`/shop/hats.html`), which page or file on that computer.

### DNS: names to numbers

Packets travel to IP addresses, but people prefer names. The **Domain Name System (DNS)** is the internet's phone book: given a name such as `www.example.com`, it returns the IP address. Your device asks a DNS resolver, and the answer is **cached** (kept for a while) so that the next lookup is quicker.

```python
dns_server = {"www.example.com": "203.0.113.7"}
cache = {}

def resolve(name):
    if name not in cache:
        cache[name] = dns_server[name]
    return cache[name]

print(resolve("www.example.com"))   # 203.0.113.7
```

### HTTP: asking and answering

The browser talks to the web server with **HTTP** (HyperText Transfer Protocol). It sends a **request**, and the server sends back a **response**:

```text
GET /shop/hats.html HTTP/1.1
Host: www.example.com
```

`GET` means "give me this page". Browsers use `POST` to send data, such as a form. The response starts with a **status code** that tells you what happened:

| code | meaning |
|---|---|
| 200 | OK, here is the page |
| 301 | moved to another URL |
| 404 | not found |
| 500 | the server had an error |

After the status come headers and then the **body**, usually **HTML**, the language that describes a page's structure. The browser reads the HTML, fetches linked files such as **CSS** (the style) and images, runs **JavaScript** (the page's code), and draws the result. **HTTPS** is HTTP sent through an encrypted connection (next week).

### The whole trip

Typing a URL starts a chain: the browser checks its cache, uses DNS to get the IP address, opens a connection to that address, sends the HTTP request in packets, receives the response as packets, and puts the page on your screen.

@example
title: Tracing a page load
problem: You type `https://www.example.com/index.html` and press Enter. List what happens.
step: The browser splits the URL: scheme `https`, host `www.example.com`, path `/index.html`.
step: It asks DNS for the IP address of `www.example.com` and gets, say, `203.0.113.7`.
step: It opens a connection to that address and sends the request `GET /index.html`, broken into packets.
step: The server sends back status `200` and the HTML, also in packets.
step: The browser reassembles the data, reads the HTML, fetches the CSS and images it mentions, and draws the page.
answer: URL split, DNS lookup, connection, HTTP request, HTTP response, rendering.

@example
title: Reading status codes
problem: A link shows "404" and another shows "500". What is the difference?
step: 404 means the server worked, but the page at that path does not exist.
step: 500 means the server itself failed while trying to handle the request.
step: Codes starting with 4 are problems with the request; codes starting with 5 are problems on the server.
answer: 404 is "not found" and 500 is a server error.

@mistakes
- Saying the web and the internet are the same thing. The web is only one service that uses the internet.
- Thinking DNS stores web pages. It only turns names into IP addresses.
- Believing a 404 means the whole website is down. It means only that one path was not found.
- Forgetting that the request and response travel as packets, like any other data on the internet.

@practice code
prompt: Write `resolve(name, cache, dns_server)` that simulates a DNS lookup. `cache` and `dns_server` are dictionaries from domain name to IP address (strings). If `name` is in `cache`, return that address. Otherwise look it up in `dns_server`: if found, store it in `cache` and return it; if not found, return `None` and leave `cache` unchanged.
starter:
```python
def resolve(name, cache, dns_server):
    pass
```
tests:
```python
server = {"a.com": "1.1.1.1", "b.com": "2.2.2.2"}
cache = {}
assert resolve("a.com", cache, server) == "1.1.1.1"
assert cache == {"a.com": "1.1.1.1"}
assert resolve("zzz.com", cache, server) is None
assert cache == {"a.com": "1.1.1.1"}
cache2 = {"b.com": "9.9.9.9"}
assert resolve("b.com", cache2, server) == "9.9.9.9"
```
model:
```python
def resolve(name, cache, dns_server):
    if name in cache:
        return cache[name]
    address = dns_server.get(name)
    if address is not None:
        cache[name] = address
    return address
```
hint: Look in the cache first, because that is the fast path.
hint: Use `dns_server.get(name)`, which gives `None` for an unknown name. Only store the answer in `cache` when it is not `None`.
solution: Return the cached address if there is one. Otherwise ask the server with `.get`, save a found address in the cache and return it; an unknown name returns `None` without touching the cache. The last test shows that a cached value is returned even if the server holds a different one.
