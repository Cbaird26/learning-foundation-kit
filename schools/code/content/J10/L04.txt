@article
A photo can take 36 MB uncompressed. Sending thousands of them would be slow and expensive. **Compression** stores the same information in fewer bits. The **compression ratio** is the original size divided by the compressed size: shrinking 40 bytes to 10 gives a ratio of 4.

### Lossless and lossy

**Lossless** compression lets you rebuild the original **exactly**. ZIP files and PNG images use it. It is needed for text, programs and anything where one wrong bit matters.

**Lossy** compression throws away details that people are unlikely to notice, so the original cannot be rebuilt exactly. JPEG photos, MP3 music and most video use it. It makes files much smaller, but compressing the same file again and again keeps losing quality.

### Spotting patterns: run-length encoding

Compression works by finding patterns. In **run-length encoding** (RLE), a **run** is a row of the same symbol. Instead of writing the symbol each time, write the **count** and then the symbol:

`aaabcc` becomes `3a1b2c`.

RLE is lossless: from `3a1b2c` you can rebuild `aaabcc`. It works well on data with long runs, such as a simple drawing with large blocks of one colour.

```python
def rle_encode(text):
    result = ""
    i = 0
    while i < len(text):
        j = i
        while j < len(text) and text[j] == text[i]:
            j += 1
        result += str(j - i) + text[i]
        i = j
    return result

print(rle_encode("aaabcc"))   # 3a1b2c
```

The inner loop moves `j` to the end of the run that starts at `i`, so the run length is `j - i`.

### When compression fails

RLE has a weakness. The text `abcd` has no runs, and encodes as `1a1b1c1d`, which is **twice as long**. No method can shrink every possible input; good methods make common patterns smaller and accept that rare inputs may grow slightly. Real tools such as ZIP use cleverer ideas than RLE, but the principle is the same: find patterns and write them more briefly.

@example
title: Encoding and decoding by hand
problem: Compress `wwwwbbbw` with run-length encoding, then decode `2x5y` back.
step: Split `wwwwbbbw` into runs: `wwww`, `bbb`, `w`.
step: Write the count and the symbol for each run: `4w`, `3b`, `1w`.
step: The result is `4w3b1w`. It has 6 characters instead of 8, so the ratio is $8 \div 6 \approx 1.33$.
step: To decode `2x5y`, repeat each symbol by its count: `xx` then `yyyyy`, giving `xxyyyyy`.
answer: `4w3b1w` and `xxyyyyy`

@example
title: When RLE makes things longer
problem: What happens when RLE encodes `abab`?
step: Every run has length 1, so there are four runs: `a`, `b`, `a`, `b`.
step: Encode each: `1a1b1a1b`.
step: The result has 8 characters and the original had 4, so the compressed version is **twice as big**.
answer: It gets longer: `1a1b1a1b`

@mistakes
- Merging all the same letters, not just neighbours: `aabbaa` is `2a2b2a`, not `4a2b`, because only runs next to each other count.
- Forgetting the count of 1 for a symbol that appears once. Without it, `3a1b2c` could not be decoded reliably.
- Saying lossy compression is always bad. It is the right choice for photos and music, where small details are not noticed.
- Expecting compression to always help. Data with no patterns may not shrink at all.

assert rle_decode("") == ""

model:
```python
def rle_decode(code):
    result = ""
    number = ""
    for ch in code:
        if ch.isdigit():
            number += ch
        else:
            result += ch * int(number)
            number = ""
    return result
```
hint: A count can have more than one digit, so collect digits until you reach the symbol.
hint: Keep the digits in a string called `number`. When you see a non-digit, repeat it `int(number)` times and reset `number` to an empty string.
solution: Collect digit characters into `number`; when a non-digit arrives, add it `int(number)` times to the result and clear `number`. Reading only one digit would break `12x`.
