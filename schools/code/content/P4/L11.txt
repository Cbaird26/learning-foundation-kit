@article
Dynamic programming (DP) has a reputation as the hardest interview topic. It is much more manageable once you see that it is **recursion plus a cache**, and that a short checklist gets you to the answer.

### When DP applies

Two properties: **optimal substructure** (the best answer is built from best answers to smaller versions) and **overlapping subproblems** (the same smaller version is needed many times). The signals in the wording are "minimum cost", "maximum value", "number of ways", "is it possible", over a sequence, a string pair or a grid. If subproblems do not repeat, plain recursion or a greedy method is enough; if the task is "list all solutions", use backtracking.

### The five-step recipe

1. **State.** What is the smallest set of numbers that describes a subproblem? (The first `i` items; the cell `(r, c)`; the first `i` characters of one string and the first `j` of another.)
2. **Meaning.** Write one sentence: "`dp[i]` is the best value using the first `i` items."
3. **Transition.** How does `dp[i]` come from smaller states? This is the recurrence.
4. **Base cases.** The smallest states you can answer directly.
5. **Order and answer.** Evaluate so that dependencies are ready, and say which state holds the final answer.

### Top-down and bottom-up

**Top-down** writes the recursion and caches results:

```python
from functools import lru_cache


def climb(n):
    @lru_cache(maxsize=None)
    def ways(k):
        if k <= 1:
            return 1
        return ways(k - 1) + ways(k - 2)

    return ways(n)
```

Without the cache this recursion takes exponential time; with it, each `k` is computed once, so $O(n)$ time and $O(n)$ space. Mind Python's recursion limit for deep `n`. **Bottom-up** fills a table in order and avoids recursion:

```python
def climb_table(n):
    dp = [1] * (n + 1)
    for k in range(2, n + 1):
        dp[k] = dp[k - 1] + dp[k - 2]
    return dp[n]
```

Because `dp[k]` only needs the last two values, you can keep two variables and use $O(1)$ space. Saying "I can compress the table" is an easy way to show depth.

### The common patterns

| Pattern | State | Typical transition |
|---|---|---|
| Linear sequence | `dp[i]` over the first `i` items | house robber: `max(dp[i-1], dp[i-2] + nums[i])` |
| Unbounded choice | `dp[a]` for amount `a` | coin change: `min(dp[a - c] + 1)` over coins `c` |
| Grid paths | `dp[r][c]` | `grid[r][c] + min(dp[r-1][c], dp[r][c-1])` |
| Two strings | `dp[i][j]` for prefixes | match: `dp[i-1][j-1] + 1`; else `max` of dropping one character |
| Subsequence | `dp[i]` ending at `i` | longest increasing subsequence: `1 + max(dp[j])` over `j < i` with smaller values |
| Partition or knapsack | `dp[i][w]` or `dp[w]` | take or skip an item |

### Complexity: count the states

Time is typically (number of states) times (work per transition). For the coin change table, there are `amount + 1` states and `len(coins)` choices per state: $O(\text{amount} \cdot |\text{coins}|)$. For longest common subsequence of strings with lengths `m` and `n`, there are `(m + 1)(n + 1)` states with constant work: $O(mn)$ time and space, reducible to $O(\min(m, n))$ space by keeping only the previous row.

### Greedy traps

Coin change with coins `[1, 3, 4]` and amount `6`: greedy takes `4 + 1 + 1` (three coins) but the optimum is `3 + 3` (two). When "obviously take the largest" might fail, DP checks all options.

### Talking through it

Start with the brute-force recursion and say why it repeats work, then add the cache. State your sentence for `dp[i]` aloud, give the base case, and trace a tiny input. Interviewers value that explanation more than a memorized table.

@example
title: Climbing stairs: from recursion to a table
problem: You can climb 1 or 2 steps at a time. In how many distinct ways can you climb 5 steps?
step: **State and meaning.** `ways(k)` is the number of ways to reach step `k`.
step: **Transition.** The last move was a 1-step from `k - 1` or a 2-step from `k - 2`, so `ways(k) = ways(k - 1) + ways(k - 2)`.
step: **Base cases.** `ways(0) = 1` (stand still) and `ways(1) = 1`.
step: **Evaluate in order.** `ways(2) = 2`, `ways(3) = 3`, `ways(4) = 5`, `ways(5) = 8`.
step: **Space.** Only the last two values are needed:

```python
def climb(n):
    prev, cur = 1, 1
    for _ in range(n - 1):
        prev, cur = cur, prev + cur
    return cur if n >= 1 else 1
```

Time $O(n)$, space $O(1)$. Without caching, the plain recursion would repeat the same calls, taking exponential time.
answer: `8`

@example
title: Minimum path sum in a grid
problem: Moving only right or down from the top-left to the bottom-right of the grid `[[1, 2, 5], [3, 2, 1]]`, what is the smallest total of the cells visited?
step: **State.** `dp[r][c]` is the cheapest cost to reach cell `(r, c)`.
step: **Transition.** A cell is entered from above or from the left: `dp[r][c] = grid[r][c] + min(dp[r-1][c], dp[r][c-1])`. In the first row or column only one predecessor exists.
step: **First row:** `1`, `1 + 2 = 3`, `3 + 5 = 8`. **First column:** `1`, then `1 + 3 = 4`.
step: **Cell (1, 1):** `2 + min(3, 4) = 5`. **Cell (1, 2):** `1 + min(8, 5) = 6`.
step: The answer is the bottom-right state, `dp[1][2] = 6`, which comes from the path through cells `(0, 0)`, `(0, 1)`, `(1, 1)` and `(1, 2)`, with values `1 + 2 + 2 + 1`.
answer: `6`

@mistakes
- Jumping to a table without writing what a state means, then mixing up indices.
- Wrong base cases, such as forgetting that amount `0` needs `0` coins, or that an empty string matches with length `0`.
- Using a greedy choice where it is not valid (coin change with arbitrary denominations).
- Forgetting that memoization needs hashable arguments, or hitting the recursion limit for large inputs; switch to bottom-up.

prompt: Write `house_robber(nums)`: houses in a row hold the amounts in `nums`, and you cannot take from two adjacent houses. Return the maximum total you can take. An empty list gives `0`.
starter:
```python
def house_robber(nums):
    pass
```
tests:
```python
assert house_robber([1, 2, 3, 1]) == 4
assert house_robber([2, 7, 9, 3, 1]) == 12
assert house_robber([]) == 0
assert house_robber([5]) == 5
assert house_robber([2, 1, 1, 2]) == 4
```
model:
```python
def house_robber(nums):
    take, skip = 0, 0
    for x in nums:
        take, skip = skip + x, max(take, skip)
    return max(take, skip)
```
hint: For each house you either take it (then you add its amount to the best total ending two houses back) or skip it.
hint: Keep only two running values: the best total if you take the current house, and the best if you skip it.
solution: Pattern: one-dimensional DP with `dp[i] = max(dp[i-1], dp[i-2] + nums[i])`, compressed to two variables. In `[2, 1, 1, 2]` the best is `2 + 2 = 4`, skipping the middle. Time $O(n)$, space $O(1)$.

@practice code
prompt: Write `coin_change(coins, amount)` that returns the fewest coins from `coins` (each denomination may be used any number of times) needed to make exactly `amount`, or `-1` if it is impossible. An amount of `0` needs `0` coins.
starter:
```python
def coin_change(coins, amount):
    pass
```
tests:
```python
assert coin_change([1, 2, 5], 11) == 3
assert coin_change([2], 3) == -1
assert coin_change([1], 0) == 0
assert coin_change([1, 3, 4], 6) == 2
assert coin_change([5, 10], 15) == 2
```
model:
```python
def coin_change(coins, amount):
    inf = amount + 1
    dp = [0] + [inf] * amount
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a:
                dp[a] = min(dp[a], dp[a - c] + 1)
    return dp[amount] if dp[amount] != inf else -1
```
hint: Let `dp[a]` be the fewest coins for amount `a`, with `dp[0] = 0`.
hint: For each amount, try every coin `c` that fits and take the best of `dp[a - c] + 1`; use a large sentinel for "impossible".
solution: Pattern: unbounded-choice DP. The test `[1, 3, 4]` with amount 6 defeats the greedy choice (4 + 1 + 1), since the optimum is 3 + 3. Time $O(\text{amount} \cdot |\text{coins}|)$, space $O(\text{amount})$.

@practice code
prompt: Write `lcs_length(a, b)` that returns the length of the longest common subsequence of strings `a` and `b` (characters in the same relative order, not necessarily adjacent).
starter:
```python
def lcs_length(a, b):
    pass
```
tests:
```python
assert lcs_length("abcde", "ace") == 3
assert lcs_length("abc", "def") == 0
assert lcs_length("", "abc") == 0
assert lcs_length("AGGTAB", "GXTXAYB") == 4
assert lcs_length("abc", "abc") == 3
```
model:
```python
def lcs_length(a, b):
    prev = [0] * (len(b) + 1)
    for i in range(1, len(a) + 1):
        cur = [0] * (len(b) + 1)
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                cur[j] = prev[j - 1] + 1
            else:
                cur[j] = max(prev[j], cur[j - 1])
        prev = cur
    return prev[len(b)]
```
hint: Let `dp[i][j]` be the answer for the first `i` characters of `a` and the first `j` of `b`.
hint: If the last characters match, extend `dp[i-1][j-1]` by 1; otherwise take the larger of `dp[i-1][j]` and `dp[i][j-1]`.
solution: Pattern: two-string DP over prefixes. Only the previous row is needed, so space is $O(\min(m, n))$ if the shorter string is used for columns (here $O(n)$); time is $O(mn)$.

prompt: Write `word_break(s, words)` that returns `True` if the string `s` can be split into a sequence of one or more words from the list `words` (words may be reused), and `False` otherwise. The empty string can always be split.
starter:
```python
def word_break(s, words):
    pass
```
tests:
```python
assert word_break("applepie", ["apple", "pie"]) is True
assert word_break("aaaaab", ["a", "aa"]) is False
assert word_break("sunflowerseed", ["sun", "flower", "seed", "sunflower"]) is True
assert word_break("", ["a"]) is True
assert word_break("abcd", ["ab", "abc", "cd"]) is True
assert word_break("abcx", ["ab", "abc", "cd"]) is False
```
model:
```python
def word_break(s, words):
    word_set = set(words)
    dp = [False] * (len(s) + 1)
    dp[0] = True
    for i in range(1, len(s) + 1):
        for j in range(i):
            if dp[j] and s[j:i] in word_set:
                dp[i] = True
                break
    return dp[len(s)]
```
hint: Let `dp[i]` mean "the first `i` characters can be split into words".
hint: `dp[i]` is true if some `j < i` has `dp[j]` true and `s[j:i]` is a word.
solution: Pattern: prefix DP with a set for word lookup. `dp[0]` is true for the empty prefix. There are $O(n^2)$ pairs `(j, i)`, each slice and lookup costs up to $O(n)$, so time is $O(n^3)$ in the worst case with $O(n)$ space for the table.

@quiz code
prompt: Write `lis_length(nums)` that returns the length of the longest strictly increasing subsequence of `nums` (not necessarily contiguous). The empty list gives `0`.
starter:
```python
def lis_length(nums):
    pass
```
tests:
```python
assert lis_length([3, 1, 4, 1, 5, 9, 2, 6]) == 4
assert lis_length([]) == 0
assert lis_length([5, 4, 3]) == 1
assert lis_length([2, 2, 2]) == 1
assert lis_length([1, 2, 3, 4]) == 4
```
model:
```python
from bisect import bisect_left


def lis_length(nums):
    tails = []
    for x in nums:
        i = bisect_left(tails, x)
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    return len(tails)
```
hint: The simple version uses `dp[i]` = the longest increasing subsequence ending at index `i`, taking the best earlier `j` with a smaller value.
hint: For $O(n \log n)$, keep `tails[k]`, the smallest possible last value of an increasing subsequence of length `k + 1`, and place each number with binary search.
solution: Pattern: subsequence DP, here in its binary-search form. `bisect_left` replaces the first tail that is at least `x`, which keeps equal values from extending a subsequence (strictness). The list `tails` is not the subsequence itself, only its length is meaningful. Time $O(n \log n)$, space $O(n)$; the quadratic DP is $O(n^2)$ time.
