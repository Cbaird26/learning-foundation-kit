@article
Arrays and strings are the most common interview material, and hashing is the single most useful technique for them. Your reflex should be this: *when I find myself searching for something inside a loop, can I store what I need in a dictionary or set instead?*

### Why hashing works

A Python `dict` or `set` is a hash table. Insertion, lookup and deletion take $O(1)$ **average** time. The worst case is $O(n)$ if many keys collide, and interviewers like to hear you say so, but you do not need to design around it. Keys must be **hashable**: integers, strings and tuples of hashable values work; lists and sets do not. If you need a list as a key, convert it to a tuple.

### Four patterns

**1. Frequency counting.** Count occurrences with `collections.Counter`, or a plain dictionary and `counts[x] = counts.get(x, 0) + 1`. It solves anagram checks, "most common element" and "first unique character".

**2. Complement lookup.** To find two items that sum to a target, for each `n` ask "have I already seen `target - n`?" Store seen values with their indices. One pass, $O(n)$ time, $O(n)$ space, instead of $O(n^2)$ pairs.

**3. Canonical keys for grouping.** Items that are "the same" in some sense should map to the same key. All anagrams share the same sorted-letter string, so `"".join(sorted(word))` is a key for grouping. Pick the key so that equal groups collide and different groups do not.

**4. Prefix sums with a hash map.** Define `prefix[i]` as the sum of the first `i` items. The sum of the subarray from `i` to `j-1` is `prefix[j] - prefix[i]`. A subarray ends at the current position with sum `k` exactly when an earlier prefix equals `current_prefix - k`. So keep a dictionary counting how many times each prefix has occurred:

```python
def count_subarrays_sum(nums, k):
    seen = {0: 1}      # the empty prefix
    prefix = 0
    total = 0
    for n in nums:
        prefix += n
        total += seen.get(prefix - k, 0)
        seen[prefix] = seen.get(prefix, 0) + 1
    return total
```

This handles negative numbers, which a sliding window cannot (you will see why next week). It is $O(n)$ time and $O(n)$ space. Note the order: look up `prefix - k` before inserting the current prefix, otherwise `k = 0` would count an empty subarray.

### Strings in Python

Strings are immutable. Building one with `s += ch` in a loop can be quadratic in the worst case; collect pieces in a list and call `"".join(parts)`. Slicing `s[i:j]` copies, so it costs $O(j - i)$. `ord(ch) - ord("a")` maps a lowercase letter to 0 to 25, which lets you use a 26-slot array instead of a dictionary when the alphabet is fixed.

### How to talk about it

In an interview, say: "The brute force is nested loops, $O(n^2)$. The inner loop is just searching, so I will replace it with a dictionary lookup, trading $O(n)$ extra space for $O(n)$ time." Then name the key and the value you store. That sentence alone shows the interviewer you know the pattern.

### Quick checklist before you code

- What is the key, and what is the value?
- What do I insert, and when: before or after the lookup?
- What happens with duplicates, empty input and negative numbers?
- Is the key hashable?

@example
title: Two sum with a dictionary
problem: Given `nums = [4, 9, 1, 7]` and `target = 10`, find the indices `[i, j]` with `i < j` such that `nums[i] + nums[j] == target`.
step: Brute force tries every pair: $O(n^2)$. The inner loop only searches for `target - nums[i]`, so replace it with a dictionary from value to index.
step: Scan left to right. At index 0, `n = 4`: we need `6`; the dictionary is empty. Store `{4: 0}`.
step: Index 1, `n = 9`: we need `1`, not present. Store `{4: 0, 9: 1}`.
step: Index 2, `n = 1`: we need `9`, and `9` is at index 1. The answer is `[1, 2]`.
step: As code:

```python
def two_sum(nums, target):
    seen = {}
    for i, n in enumerate(nums):
        j = seen.get(target - n)
        if j is not None:
            return [j, i]
        seen[n] = i
    return []
```

Looking up before inserting also means an item is never paired with itself. Time $O(n)$ average, space $O(n)$.
answer: `[1, 2]`

@example
title: Counting subarrays with a prefix-sum dictionary
problem: How many contiguous subarrays of `[2, -2, 3, 0]` sum to `3`?
step: Start with `seen = {0: 1}`, `prefix = 0`, `total = 0`.
step: `n = 2`: prefix becomes `2`. We need an earlier prefix of `2 - 3 = -1`: none. Record `2`. `seen = {0: 1, 2: 1}`.
step: `n = -2`: prefix `0`. Need `-3`: none. Record `0` again: `seen = {0: 2, 2: 1}`.
step: `n = 3`: prefix `3`. Need `0`, which has occurred 2 times, so `total = 2`. These are the subarrays `[2, -2, 3]` and `[3]`. Record `3`.
step: `n = 0`: prefix `3`. Need `0`: 2 more, so `total = 4`. These are `[2, -2, 3, 0]` and `[3, 0]`.
answer: `4`

@mistakes
- Inserting the current item into the dictionary before the lookup, which lets an item pair with itself (two sum) or counts an empty subarray (prefix sums).
- Forgetting the initial `{0: 1}` entry in prefix sums, so subarrays that start at index 0 are missed.
- Using a list or another unhashable value as a dictionary key; convert it to a tuple.
- Sorting a string inside a loop and forgetting the cost: sorting a word of length $L$ costs $O(L \log L)$, which belongs in your complexity.

```python
from collections import defaultdict


def group_anagrams(words):
    groups = defaultdict(list)
    for w in words:
        groups["".join(sorted(w))].append(w)
    return list(groups.values())
```

starter:

```python
def longest_consecutive(nums):
    pass
```
tests:
```python
assert longest_consecutive([100, 4, 200, 1, 3, 2]) == 4
assert longest_consecutive([]) == 0
assert longest_consecutive([0, 3, 7, 2, 5, 8, 4, 6, 0, 1]) == 9
assert longest_consecutive([5, 5, 5]) == 1
assert longest_consecutive([-2, -1, 0, 10]) == 3
```
model:
```python
def longest_consecutive(nums):
    values = set(nums)
    best = 0
    for v in values:
        if v - 1 not in values:
            length = 1
            while v + length in values:
                length += 1
            best = max(best, length)
    return best
```
hint: Put all values in a set so that membership tests are $O(1)$.
hint: Only start counting from a value `v` whose predecessor `v - 1` is not in the set.
solution: Pattern: hash set with "run starts". Each run is counted once, from its smallest element, so the inner `while` loops together touch each value at most once. Time $O(n)$ average, space $O(n)$. Sorting would be simpler but costs $O(n \log n)$.
