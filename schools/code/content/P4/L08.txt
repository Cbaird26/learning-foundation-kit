@article
A graph is a set of **vertices** connected by **edges**. Edges can be **directed** (one-way) or **undirected**, and a graph is **connected** if every vertex can reach every other. Interview problems often hide a graph: a grid of cells, courses with prerequisites, words that differ by one letter, a network of friends. Spotting the graph is half the solution.

### Representing a graph

For interviews the default is an **adjacency list**: a dictionary from each vertex to a list of its neighbors. For `n` vertices and `m` edges, it uses $O(n + m)$ space, and iterating over a vertex's neighbors costs the number of neighbors. An adjacency matrix uses $O(n^2)$ space, which only pays off for dense graphs. Grids need no explicit structure: the neighbors of `(r, c)` are `(r±1, c)` and `(r, c±1)`, checked against the bounds.

```python
from collections import defaultdict

graph = defaultdict(list)
for a, b in [(0, 1), (0, 2), (1, 3)]:
    graph[a].append(b)
    graph[b].append(a)      # omit for a directed edge
```

### Breadth-first search (BFS)

BFS explores in layers: first the start, then everything one edge away, then two edges away. It uses a **queue** and a **visited set**. Because it reaches vertices in order of distance, the first time it reaches a vertex is by a **shortest path in an unweighted graph**.

```python
from collections import deque


def bfs_distance(graph, start, goal):
    seen = {start}
    queue = deque([(start, 0)])
    while queue:
        node, dist = queue.popleft()
        if node == goal:
            return dist
        for nxt in graph.get(node, []):
            if nxt not in seen:
                seen.add(nxt)
                queue.append((nxt, dist + 1))
    return -1
```

Mark a vertex visited when you **enqueue** it, not when you dequeue it; otherwise the same vertex can enter the queue many times. Time is $O(n + m)$ and space is $O(n)$.

### Depth-first search (DFS)

DFS goes as deep as possible before backtracking. It uses recursion (the call stack) or an explicit stack. It is the natural fit for **reachability, connected components, flood fill and cycle detection**, and it does **not** give shortest paths. Also $O(n + m)$ time. Recursion depth can reach $n$, so for long chains an iterative version avoids Python's recursion limit.

### Grids and connected regions

To count islands in a grid, scan every cell; when you find an unvisited land cell, start a search that marks the whole island visited, and add one to the count. Each cell is processed a constant number of times: $O(R \cdot C)$.

### Topological sort

A **topological order** of a directed graph lists every vertex before the vertices it points to. One exists exactly when the graph has no directed cycle (it is a DAG). It models "do X before Y" (build steps, course prerequisites). **Kahn's algorithm**:

1. Compute each vertex's **in-degree** (the number of prerequisites).
2. Put all vertices with in-degree 0 in a queue.
3. Remove a vertex from the queue, append it to the order, and decrement the in-degree of its neighbors; any that reach 0 join the queue.
4. If the order contains fewer than `n` vertices, a cycle blocked the rest, so no valid order exists.

Time $O(n + m)$. A DFS-based version (record vertices in postorder and reverse) also works.

### Choosing between them

| Question | Tool |
|---|---|
| Fewest steps in an unweighted graph or grid | BFS |
| Is there a path? How many components? Flood fill | DFS or BFS |
| Order with dependencies, or detect a cycle in them | Topological sort |
| Shortest path with weights | Dijkstra's algorithm (BFS with a heap in place of the queue; see the next lesson on heaps) |

### Talking through it

Name the vertices and edges: "Each course is a vertex, and a prerequisite is a directed edge from the prerequisite to the course." State the representation and the complexity: "$O(V + E)$ time and space." Then ask: directed or undirected, and can there be cycles or duplicates?

@example
title: BFS shortest path trace
problem: In the undirected graph `A: [B, C]`, `B: [A, D]`, `C: [A, D]`, `D: [B, C, E]`, `E: [D]`, find the fewest edges from `A` to `E`.
step: Start: `seen = {A}`, `queue = [(A, 0)]`.
step: Dequeue `A` (0). Its unseen neighbors `B` and `C` are marked and enqueued at distance 1.
step: Dequeue `B` (1): its neighbors are `A` (seen) and `D`, which is new, so enqueue `(D, 2)`. Dequeue `C` (1): `D` is already seen, so nothing is added.
step: Dequeue `D` (2): `E` is new, so enqueue `(E, 3)`.
step: Dequeue `E` (3): this is the goal, so return `3`. The path is `A → B → D → E`, or via `C`, both of length 3.
answer: `3`

@example
title: Kahn's algorithm on a build order
problem: Tasks 0 to 3 with dependencies "0 before 1", "0 before 2", "1 before 3", "2 before 3". Produce a valid order.
step: In-degrees: task 0 has 0, tasks 1 and 2 have 1 each, task 3 has 2. The queue starts as `[0]`.
step: Remove 0, add it to the order. Decrement tasks 1 and 2 to 0, so both join the queue: `[1, 2]`.
step: Remove 1: order `[0, 1]`; task 3 drops from 2 to 1. Remove 2: order `[0, 1, 2]`; task 3 drops to 0 and joins the queue.
step: Remove 3: order `[0, 1, 2, 3]`. All four tasks are included, so there was no cycle.
step: If we added the dependency "3 before 0", every in-degree would be at least 1, the queue would start empty, and the order would have 0 tasks, fewer than 4, proving a cycle.
answer: `[0, 1, 2, 3]` (task 1 and 2 could swap).

@mistakes
- Marking vertices visited on dequeue instead of enqueue, so the queue fills with duplicates and BFS slows down.
- Using DFS to claim a shortest path in an unweighted graph; only BFS guarantees it.
- Forgetting the visited set in a graph that may have cycles, causing an infinite loop.
- Getting the direction of a prerequisite edge backwards, which reverses the order.

prompt: Write `num_islands(grid)` where `grid` is a list of strings of `"1"` (land) and `"0"` (water). Return the number of islands, where an island is a group of land cells connected horizontally or vertically (not diagonally). An empty grid gives `0`.
starter:
```python
def num_islands(grid):
    pass
```
tests:
```python
assert num_islands(["11000", "11000", "00100", "00011"]) == 3
assert num_islands([]) == 0
assert num_islands(["1"]) == 1
assert num_islands(["101", "010", "101"]) == 5
assert num_islands(["111", "101", "111"]) == 1
```
model:
```python
def num_islands(grid):
    if not grid:
        return 0
    rows, cols = len(grid), len(grid[0])
    seen = set()

    def fill(r, c):
        stack = [(r, c)]
        seen.add((r, c))
        while stack:
            cr, cc = stack.pop()
            for nr, nc in ((cr + 1, cc), (cr - 1, cc), (cr, cc + 1), (cr, cc - 1)):
                if (0 <= nr < rows and 0 <= nc < cols
                        and grid[nr][nc] == "1" and (nr, nc) not in seen):
                    seen.add((nr, nc))
                    stack.append((nr, nc))

    count = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == "1" and (r, c) not in seen:
                count += 1
                fill(r, c)
    return count
```
hint: Scan every cell; each time you meet land that has not been visited, you have found a new island.
hint: When you find one, search outward (DFS or BFS) and mark all connected land as visited.
solution: Pattern: flood fill over a grid, counting components. Every cell is pushed at most once, so time is $O(R \cdot C)$ and space is $O(R \cdot C)$ for the visited set. The diagonal test `["101", "010", "101"]` has five islands.

@practice code
prompt: There are `n` courses numbered `0` to `n - 1`. Each pair `[a, b]` in `prereqs` means course `b` must be taken before course `a`. Write `course_order(n, prereqs)` that returns a list of all courses in a valid order, or `[]` if the prerequisites contain a cycle. Any valid order is accepted.
starter:
```python
def course_order(n, prereqs):
    pass
```
tests:
```python
pairs = [[1, 0], [2, 0], [3, 1], [3, 2]]
order = course_order(4, pairs)
assert sorted(order) == [0, 1, 2, 3]
assert all(order.index(b) < order.index(a) for a, b in pairs)
assert course_order(2, [[0, 1], [1, 0]]) == []
assert sorted(course_order(3, [])) == [0, 1, 2]
assert course_order(1, []) == [0]
chain = [[1, 2], [0, 1]]
assert course_order(3, chain) == [2, 1, 0]
```
model:
```python
from collections import deque


def course_order(n, prereqs):
    graph = [[] for _ in range(n)]
    indegree = [0] * n
    for a, b in prereqs:
        graph[b].append(a)
        indegree[a] += 1
    queue = deque(i for i in range(n) if indegree[i] == 0)
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for nxt in graph[node]:
            indegree[nxt] -= 1
            if indegree[nxt] == 0:
                queue.append(nxt)
    return order if len(order) == n else []
```
hint: Build edges from each prerequisite `b` to the course `a` that needs it, and count each course's in-degree.
hint: Start with courses of in-degree 0; when you take one, lower the in-degree of the courses that depend on it.
solution: Pattern: topological sort with Kahn's algorithm. If fewer than `n` courses were taken, the remaining ones sit on a cycle, so return `[]`. Time $O(n + m)$ for `m` prerequisites, space $O(n + m)$.

starter:
```python

    pass
```
tests:
```python
assert count_components(5, [[0, 1], [1, 2], [3, 4]]) == 2
assert count_components(4, []) == 4
assert count_components(1, []) == 1
assert count_components(3, [[0, 1], [1, 2], [0, 2]]) == 1
assert count_components(0, []) == 0
```
model:
```python
def count_components(n, edges):
    graph = [[] for _ in range(n)]
    for a, b in edges:
        graph[a].append(b)
        graph[b].append(a)
    seen = [False] * n
    count = 0
    for start in range(n):
        if seen[start]:
            continue
        count += 1
        seen[start] = True
        stack = [start]
        while stack:
            node = stack.pop()
            for nxt in graph[node]:
                if not seen[nxt]:
                    seen[nxt] = True
                    stack.append(nxt)
    return count
```
hint: Build an adjacency list, then start a search from every vertex not yet visited.
hint: Each new search start means one more component.
solution: Pattern: DFS over components (a union-find structure would also work). Each vertex and edge is processed a constant number of times: $O(n + m)$ time, $O(n + m)$ space.

@quiz mc
prompt: Kahn's algorithm finishes with fewer than `n` vertices in its output order. What does that mean?
