@review
## Week-by-week key ideas

- **Week 1, process and practice.** Know the stages of a hiring loop. Use the seven-step method (clarify, examples, brute force, optimize, code, test, analyze) every time. Keep a pattern log and review it on a spaced schedule.
- **Week 2, hashing.** Frequency counts, complement lookup, canonical keys, prefix sums with a dictionary. Average $O(1)$ lookups turn nested loops into one pass.
- **Week 3, two pointers and windows.** Opposite-end pointers need sorted data. Variable windows need a monotone condition and run in $O(n)$ because each index enters and leaves once.
- **Week 4, stacks.** Match nesting, evaluate expressions, undo work. A monotonic stack finds next greater or smaller items in $O(n)$ amortized.
- **Week 5, binary search.** Fix an invariant first. The lower-bound template finds boundaries; binary search on the answer needs a monotonic yes-or-no test.
- **Week 6, linked lists.** Dummy heads remove edge cases; reversal needs the four-line pointer dance; fast and slow pointers find middles and cycles.
- **Week 7, trees.** Recursion with a base case and a combine step; BFS with a queue for levels; the BST property needs bounds, not just parent checks.
- **Week 8, graphs.** Adjacency lists; BFS for fewest steps; DFS for components; Kahn's algorithm for ordering and cycle detection.
- **Week 9, heaps and intervals.** A size-$k$ min-heap gives top-$k$ in $O(n \log k)$; intervals are sorted by start and swept.
- **Week 10, backtracking.** Choose, explore, unchoose; copy the path; prune early.
- **Week 11, dynamic programming.** State, meaning, transition, base cases, order. Count the states for complexity.
- **Week 12, behavioral and offers.** STAR with "I"; five stories; résumé bullets with numbers; compare total compensation and negotiate honestly.

## Most common errors

- Coding before clarifying the problem.
- Forgetting empty input, off-by-one boundaries and duplicates.
- Using the wrong tool: a sliding window with negative numbers, DFS for shortest paths, greedy where DP is needed.
- Saving a reference instead of a copy in backtracking.
- Claiming a nested loop is quadratic without checking whether each element is processed once.
- Silent solving, and behavioral answers with no result.

@exam code
prompt: A project has `n` tasks numbered `0` to `n - 1`. Each pair `[a, b]` in `prereqs` means task `b` must finish before task `a` starts, and `duration[i]` is how long task `i` takes. Tasks with no unfinished prerequisites run in parallel without limit. Write `earliest_finish(n, prereqs, duration)` that returns the earliest time at which all tasks can be finished, or `-1` if the prerequisites contain a cycle. With no tasks, the answer is `0`.
starter:
```python
def earliest_finish(n, prereqs, duration):
    pass
```
tests:
```python
assert earliest_finish(3, [[1, 0], [2, 1]], [3, 2, 4]) == 9
assert earliest_finish(3, [[1, 0], [2, 0]], [1, 5, 2]) == 6
assert earliest_finish(2, [[0, 1], [1, 0]], [1, 1]) == -1
assert earliest_finish(4, [], [2, 7, 1, 3]) == 7
assert earliest_finish(0, [], []) == 0
assert earliest_finish(3, [[1, 2], [2, 1]], [5, 1, 1]) == -1
assert earliest_finish(4, [[1, 0], [2, 0], [3, 1], [3, 2]], [1, 2, 5, 1]) == 7
```
model:
```python
from collections import deque


def earliest_finish(n, prereqs, duration):
    graph = [[] for _ in range(n)]
    indegree = [0] * n
    for a, b in prereqs:
        graph[b].append(a)
        indegree[a] += 1
    start = [0] * n
    queue = deque(i for i in range(n) if indegree[i] == 0)
    done = 0
    best = 0
    while queue:
        node = queue.popleft()
        done += 1
        end = start[node] + duration[node]
        best = max(best, end)
        for nxt in graph[node]:
            start[nxt] = max(start[nxt], end)
            indegree[nxt] -= 1
            if indegree[nxt] == 0:
                queue.append(nxt)
    return best if done == n else -1
```
hint: Order the tasks with a topological sort, so every task is processed after all of its prerequisites.
hint: A task can start when its slowest prerequisite finishes: keep `start[task]` as the maximum finish time of its prerequisites.
solution: Patterns: Kahn's topological sort combined with dynamic programming over a DAG (the longest path by duration). When a task is dequeued all its prerequisites are done, so its start time is final. If fewer than `n` tasks are processed, there is a cycle. Time $O(n + m)$, space $O(n + m)$.

@exam code
prompt: A person is in meetings during the day, given as `[start, end]` pairs of hours (the list may be unsorted and the meetings may overlap or extend outside the working day). Write `max_free_gap(meetings, day_start, day_end)` that returns the length of the longest stretch of free time inside `[day_start, day_end]`. Parts of meetings outside the working day are ignored. With no meetings, the whole day is free.
starter:
```python
def max_free_gap(meetings, day_start, day_end):
    pass
```
tests:
```python
assert max_free_gap([[9, 10], [10, 12], [13, 14]], 9, 17) == 3
assert max_free_gap([], 8, 18) == 10
assert max_free_gap([[8, 18]], 8, 18) == 0
assert max_free_gap([[7, 9], [16, 20]], 8, 18) == 7
assert max_free_gap([[10, 12], [11, 15]], 9, 17) == 2
assert max_free_gap([[1, 2]], 8, 18) == 10
```
model:
```python
def max_free_gap(meetings, day_start, day_end):
    busy = []
    for s, e in sorted(meetings):
        s = max(s, day_start)
        e = min(e, day_end)
        if s >= e:
            continue
        if busy and s <= busy[-1][1]:
            busy[-1][1] = max(busy[-1][1], e)
        else:
            busy.append([s, e])
    best = 0
    cur = day_start
    for s, e in busy:
        best = max(best, s - cur)
        cur = e
    return max(best, day_end - cur)
```
hint: Clip each meeting to the working day, then merge overlapping meetings after sorting by start.
hint: The free gaps lie between the working-day start, the merged busy blocks and the working-day end.
solution: Patterns: sort and merge intervals, then sweep for gaps. Clipping first makes meetings outside the day vanish (`s >= e`). Do not forget the gap after the last busy block. Time $O(n \log n)$, space $O(n)$.

@exam self
prompt: For each of the three problems below, name the pattern, the main data structure, and the time and space complexity of your approach, and give the brute force it improves on. (a) Given a string, find the length of the longest substring in which no character appears more than twice. (b) Given a stream of tasks, each with a value, and a rule that only the `k` most valuable tasks can be kept at any time as new tasks arrive, report the total value of the best `k` after each new task. (c) Given a grid of 0s and 1s, find the number of steps in the shortest path from the top-left to the bottom-right cell moving only through 1s in four directions, or report that none exists.
solution: (a) Pattern: variable-size sliding window. Keep a dictionary of character counts for the window and shrink from the left while any count exceeds 2 (when the character just added reaches 3, move `left` until its count is back to 2). Brute force: check every substring, $O(n^3)$ or $O(n^2)$ with early exit. Window: $O(n)$ time, $O(k)$ space for the alphabet. (b) Pattern: top-k with a size-`k` min-heap and a running sum. Push each new value and add it to the sum; if the heap exceeds `k`, pop the smallest and subtract it. Brute force: re-sort all items after each arrival, $O(n^2 \log n)$ overall. Heap: $O(\log k)$ per task, $O(n \log k)$ total, $O(k)$ space. (c) Pattern: BFS on a grid. Use a queue of `(row, col, steps)` and a visited set; mark cells when enqueued; the first time the bottom-right cell is dequeued, its step count is the minimum; if the queue empties, report none. Brute force: DFS enumerating all paths, exponential. BFS: $O(R \cdot C)$ time and space.

hint: For each, state the brute force first, then the structure that removes the repeated work.

rubric: Describes the data structure and the key operation for each, such as shrinking while a count exceeds 2, popping the smallest when the heap exceeds `k`, and marking cells visited on enqueue.
