@article
Trees are where recursion earns its place in interviews. A binary tree node has a value, a `left` child and a `right` child, and an empty child is `None`:

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right
```

Vocabulary you should use precisely: the **root** has no parent; a **leaf** has no children; the **height** of a tree is the number of edges on the longest root-to-leaf path (some sources count nodes, so say which); **depth** is the distance from the root.

### The recursive template

Almost every tree problem fits this shape: *solve for the left subtree, solve for the right subtree, combine with the current node.* You need only two decisions:

- **Base case.** What is the answer for `None`? (Depth 0, sum 0, "valid" `True`.)
- **Combine.** How do the two subresults and `node.val` give the answer for this node?

```python
def max_depth(node):
    if node is None:
        return 0
    return 1 + max(max_depth(node.left), max_depth(node.right))
```

Time is $O(n)$, since each node is visited once. Space is $O(h)$ for the call stack, where $h$ is the height. For a balanced tree that is $O(\log n)$; for a degenerate, list-like tree it is $O(n)$, and Python's recursion limit (about 1000 frames by default) can be hit. Mention this and offer an iterative version with an explicit stack if depth could be large.

### Traversals

| Order | Visit | Typical use |
|---|---|---|
| Preorder | node, left, right | Copy or serialize a tree |
| Inorder | left, node, right | Sorted output of a BST |
| Postorder | left, right, node | Compute from children (height, delete) |
| Level order | by depth, left to right | Shortest path, per-level answers |

The first three are depth-first and differ only in where the visit sits relative to the recursive calls. **Level order** is breadth-first and uses a queue (`collections.deque`): take everything currently in the queue (one level), record it, and enqueue the children. It is $O(n)$ time and $O(w)$ space for the maximum width $w$.

### Binary search trees

A **binary search tree (BST)** satisfies: for every node, *all* values in its left subtree are smaller and *all* values in its right subtree are larger (we treat duplicates as not allowed here). Two consequences:

- **Inorder traversal visits values in sorted order.** That is a useful check and a way to get the k-th smallest.
- **Search, insert and delete take $O(h)$.** Go left or right by comparison. For a balanced tree $h$ is $O(\log n)$; for a tree built by inserting already sorted values it is $O(n)$. Self-balancing trees (AVL, red-black) guarantee $O(\log n)$, but you are rarely asked to implement one.

### The classic trap: validating a BST

Checking only that each node is greater than its left child and smaller than its right child is **wrong**. The tree `5 (left 4, right 6 (left 3, right 7))` passes that local test, yet `3` is in the right subtree of `5`. The fix is to pass down a valid range: every node must lie strictly between a lower and an upper bound, and moving left tightens the upper bound to the parent's value, moving right tightens the lower bound. Alternatively, run an inorder traversal and check the sequence strictly increases.

### Talking through it

For tree problems say: "I will recurse. Base case is an empty node returning ... . At each node I combine ... . Time is linear and the stack uses space proportional to the height." Then name the unbalanced worst case before the interviewer asks.

@example
title: Three depth-first traversals
problem: List the preorder, inorder and postorder traversals of the tree with root `1`, left child `2` (which has children `4` and `5`) and right child `3`.
step: Preorder visits the node first, then left, then right. Start `1`, go left to `2`, then its children `4`, `5`, then back to the right child `3`: `1, 2, 4, 5, 3`.
step: Inorder visits left, node, right. The leftmost node is `4`, then its parent `2`, then `5`, then root `1`, then `3`: `4, 2, 5, 1, 3`.
step: Postorder visits both subtrees before the node: `4`, `5`, then `2`, then `3`, then root `1`: `4, 5, 2, 3, 1`.
step: All three visit each node once, so each is $O(n)$ time; the stack depth is the tree height.
answer: Preorder `1, 2, 4, 5, 3`; inorder `4, 2, 5, 1, 3`; postorder `4, 5, 2, 3, 1`.

@example
title: Root-to-leaf path sum by recursion
problem: Write `has_path_sum(node, target)` that returns whether some root-to-leaf path has values summing to `target`.
step: Think subtree by subtree: a path sum for the whole tree is `node.val` plus a path sum of `target - node.val` in one of the children.
step: Base case for `None`: no path exists, return `False`. Careful: only a **leaf** ends a path, so an empty child must not count as a successful end.
step: At a leaf, the path works exactly when `node.val == target`.
step: Otherwise recurse into both children with the reduced target and combine with `or`:

```python
def has_path_sum(node, target):
    if node is None:
        return False
    if node.left is None and node.right is None:
        return node.val == target
    rest = target - node.val
    return has_path_sum(node.left, rest) or has_path_sum(node.right, rest)
```

step: Check on a root `5` with a single left child `3` and `target = 5`: the root is not a leaf, so we look at the left child with target `0`; `3 == 0` is false, and the missing right child returns `False`. The answer is `False`, which is right, because the path must end at a leaf. Time $O(n)$, space $O(h)$.
answer: `False` for that tree and target `5`; the base cases are what make it correct.

@mistakes
- Validating a BST by comparing each node only with its direct children instead of passing down lower and upper bounds.
- Treating an empty child as a path end in problems about root-to-leaf paths.
- Forgetting the empty tree (`root is None`) in the base case.
- Claiming recursion is $O(1)$ space; the call stack costs $O(h)$.

model:
```python
from collections import deque


class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


def level_order(root):
    if root is None:
        return []
    result = []
    queue = deque([root])
    while queue:
        level = []
        for _ in range(len(queue)):
            node = queue.popleft()
            level.append(node.val)
            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)
        result.append(level)
    return result
```
hint: Use a queue and process one whole level at a time.
hint: At the start of each outer iteration, `len(queue)` is the number of nodes on the current level.
solution: Pattern: breadth-first search with a queue, taking a snapshot of the level size. Time $O(n)$, space $O(w)$ for the widest level `w`. Use `deque`, since `list.pop(0)` would add an $O(n)$ cost per removal.

model:
```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


def is_valid_bst(root):
    def check(node, low, high):
        if node is None:
            return True
        if not (low < node.val < high):
            return False
        return (check(node.left, low, node.val)
                and check(node.right, node.val, high))

    return check(root, float("-inf"), float("inf"))
```
hint: Comparing a node only with its parent is not enough; every ancestor constrains it.
hint: Pass down a `(low, high)` range; going left makes `high` the node's value, going right makes `low` the node's value.
solution: Pattern: recursion with bounds. The tree with root 5 and a `3` under the right child fails because `3` is not above the lower bound `5` inherited from the root. Time $O(n)$, space $O(h)$. An inorder traversal checked for strict increase is an alternative.

model:
```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


def lca_bst(root, p, q):
    node = root
    while node:
        if p < node.val and q < node.val:
            node = node.left
        elif p > node.val and q > node.val:
            node = node.right
        else:
            return node.val
    return None
```
hint: If both values are smaller than the current node, the answer is in the left subtree.
hint: If both are larger, go right; otherwise the current node separates them (or equals one of them) and is the answer.
solution: Pattern: BST navigation by comparison. The first node where the two values do not fall on the same side is the lowest common ancestor. Time $O(h)$, space $O(1)$ with the loop.
