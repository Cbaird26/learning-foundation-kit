@article
Two families of problems share this lesson because they share a theme: *order matters, and sorting or a priority queue gives it to you cheaply.*

### Heaps and priority queues

A **heap** is a tree stored in an array that always lets you read the smallest (min-heap) or largest (max-heap) element in $O(1)$ and remove it in $O(\log n)$. Python's `heapq` module provides a **min-heap** on a plain list:

```python
import heapq

h = []
heapq.heappush(h, 5)       # O(log n)
heapq.heappush(h, 2)
smallest = heapq.heappop(h)  # O(log n), returns 2
h[0]                       # peek at the minimum, O(1)
heapq.heapify(items)       # turn a list into a heap in O(n)
```

There is no max-heap in `heapq`; the standard trick is to push negated values (`-x`) or tuples such as `(-count, item)`. Tuples compare element by element, so `(priority, item)` pairs order by priority first. A heap is **not** sorted: only `h[0]` is guaranteed to be the minimum.

### Top-k with a size-k heap

To find the `k` largest items of `n`, keep a **min-heap of size `k`**. For each item, push it; if the heap grows past `k`, pop the smallest. After the scan the heap holds the `k` largest, and its root is the `k`-th largest. This costs $O(n \log k)$ time and $O(k)$ space, better than sorting at $O(n \log n)$ when `k` is small, and it works on a stream you cannot store. `heapq.nlargest(k, items)` and `heapq.nsmallest(k, items, key=...)` do this for you; knowing how it works is what the interviewer wants.

Other heap uses: **merge `k` sorted lists** (heap holds the front item of each list, $O(N \log k)$ for `N` total items), the **running median** (a max-heap for the lower half and a min-heap for the upper half), and **Dijkstra's algorithm** for weighted shortest paths (heap of `(distance, vertex)`).

### Intervals

An interval is a pair `[start, end]`. The key move for almost every interval problem is: **sort by start time**, then sweep, comparing each interval with the last one you kept. Two sorted intervals overlap when the next start is at most the current end (decide with the interviewer whether touching endpoints count as overlap).

**Merging:**

```python
def merge(intervals):
    merged = []
    for start, end in sorted(intervals):
        if merged and start <= merged[-1][1]:
            merged[-1][1] = max(merged[-1][1], end)
        else:
            merged.append([start, end])
    return merged
```

Note the `max`: a long interval can swallow a later short one. Time is $O(n \log n)$ because of the sort; the sweep is $O(n)$. Space is $O(n)$ for the output.

**How many at once?** For "minimum meeting rooms", sort the meetings by start and keep a min-heap of the **end times** of rooms in use. For each meeting, if the earliest end is at or before the new start, that room is free: pop it. Push the new end. The final heap size is the number of rooms ever needed. $O(n \log n)$ time.

### Other interval tools

- **Free gaps** between busy intervals: after merging, the gaps are between one interval's end and the next one's start.
- **Greedy scheduling**: to keep the most non-overlapping intervals, sort by **end** time and take each interval that starts after the last chosen end.
- **Insert an interval** into a sorted list: copy the ones before, merge the overlapping ones, copy the rest, in $O(n)$.

### Choosing the tool

| Need | Tool | Cost |
|---|---|---|
| Smallest or largest, repeatedly, with insertions | Heap | $O(\log n)$ per operation |
| `k` largest from a big input | Size-`k` min-heap | $O(n \log k)$ |
| Full ranking, one time | Sort | $O(n \log n)$ |
| Overlaps and merging | Sort by start, then sweep | $O(n \log n)$ |

### Talking through it

For intervals: "I will sort by start so overlapping intervals are adjacent, then sweep keeping the last merged interval." For heaps: "I only ever need the current minimum, so a heap gives me that in $O(\log n)$ without keeping everything sorted."

@example
title: The k-th largest item with a size-k min-heap
problem: Find the 3rd largest value in `[4, 1, 7, 3, 8, 5]` using a min-heap of size 3.
step: Push `4`, `1`, `7`. The heap now holds three items, with minimum `1`: `{1, 4, 7}`.
step: Next `3`: push it, giving four items, then pop the smallest (`1`). The heap is `{3, 4, 7}`.
step: Next `8`: push, then pop `3`. Heap `{4, 7, 8}`. Next `5`: push, then pop `4`. Heap `{5, 7, 8}`.
step: The heap holds the three largest values, and its root (the minimum of those) is the 3rd largest.

```python
import heapq


def kth_largest(nums, k):
    heap = []
    for x in nums:
        heapq.heappush(heap, x)
        if len(heap) > k:
            heapq.heappop(heap)
    return heap[0]
```

Time $O(n \log k)$, space $O(k)$.
answer: `5`

@example
title: Can one person attend every meeting?
problem: Given meetings `[[9, 10], [10, 12], [11, 13]]`, decide whether any two overlap. A meeting ending at 10 and another starting at 10 do not overlap.
step: Sort by start time: the list is already in order. Compare each meeting with the one before it.
step: `[10, 12]` starts at 10, and the previous meeting ends at 10. Touching is allowed, so no overlap.
step: `[11, 13]` starts at 11, but the previous meeting ends at 12. Since `11 < 12`, they overlap, and the answer is no.
step: In code:

```python
def can_attend(meetings):
    ordered = sorted(meetings)
    for i in range(1, len(ordered)):
        if ordered[i][0] < ordered[i - 1][1]:
            return False
    return True
```

Sorting dominates: $O(n \log n)$ time, $O(n)$ for the sorted copy.
answer: `False`, because `[10, 12]` and `[11, 13]` overlap.

@mistakes
- Assuming a `heapq` list is sorted. Only `h[0]` is the minimum; iterating the list does not give sorted order.
- Trying to use `heapq` as a max-heap without negating the values.
- Merging intervals without sorting first, or replacing the end with `end` instead of `max(previous_end, end)`.
- Mishandling touching intervals: decide whether `[1, 4]` and `[4, 5]` merge, and use `<=` or `<` consistently.

import heapq


def min_meeting_rooms(meetings):
    ends = []
    for start, end in sorted(meetings):
        if ends and ends[0] <= start:
            heapq.heapreplace(ends, end)
        else:
            heapq.heappush(ends, end)
    return len(ends)

@quiz code
prompt: Write `top_k_frequent(nums, k)` that returns the `k` most frequent values of `nums`, ordered by frequency from highest to lowest, with ties broken by the smaller value first. Assume `k` is at most the number of distinct values. Use a heap-based selection so the time is better than sorting all distinct values when `k` is small.
starter:
```python
import heapq
from collections import Counter


def top_k_frequent(nums, k):
    pass
```
tests:
```python
assert top_k_frequent([1, 1, 1, 2, 2, 3], 2) == [1, 2]
assert top_k_frequent([4, 4, 5, 5, 6], 2) == [4, 5]
assert top_k_frequent([7], 1) == [7]
assert top_k_frequent([3, 1, 1, 3, 2], 1) == [1]
assert top_k_frequent([-1, -1, 2, 2, 2, 3], 2) == [2, -1]
```
model:
```python
import heapq
from collections import Counter


def top_k_frequent(nums, k):
    counts = Counter(nums)
    return heapq.nsmallest(k, counts, key=lambda x: (-counts[x], x))
```
hint: Count frequencies with a dictionary first.
hint: Selecting the `k` smallest by the key `(-count, value)` gives highest count first and the smaller value on ties.
solution: Pattern: frequency counting plus heap-based top-k. Counting is $O(n)$, and `heapq.nsmallest` with a size-`k` heap takes $O(d \log k)$ for `d` distinct values. Space is $O(d)$.
