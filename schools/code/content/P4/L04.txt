@article
A **stack** is last in, first out. In Python a list is a perfectly good stack: `append` pushes and `pop()` pops, both $O(1)$ amortized. (Do not use `list.pop(0)` as a queue: it is $O(n)$. Use `collections.deque` for queues.)

### When a stack is the right tool

Reach for a stack when the most recent unfinished thing is the one you must deal with next. The recurring shapes are:

- **Nested structure.** Brackets, HTML tags, function calls, directory paths with `..`. Push an opener; when a closer arrives, it must match the top.
- **Expression evaluation.** Reverse Polish notation pushes operands and, on an operator, pops two, applies it and pushes the result.
- **Undo and cancel.** Remove adjacent duplicates, backspace characters, collapsing "asteroid collisions": push, and when the new item cancels the top, pop.
- **Depth-first search without recursion.** An explicit stack replaces the call stack, which avoids recursion limits.

### The monotonic stack

Many problems ask, for each position, about the next (or previous) element that is greater or smaller: next warmer day, next greater price, nearest smaller value, largest rectangle in a histogram. The brute force scans ahead from every position, $O(n^2)$.

A **monotonic stack** keeps its contents in sorted order (say, decreasing from bottom to top). You process the items left to right. For each new item `x`, while the top of the stack is smaller than `x`, `x` is the answer for that top, so pop it and record the result. Then push `x`. Items waiting on the stack are exactly those that have not yet found their answer.

```python
def next_greater_index(nums):
    answer = [-1] * len(nums)
    stack = []                      # indices, values decreasing
    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x:
            answer[stack.pop()] = i
        stack.append(i)
    return answer
```

**Why is this $O(n)$?** The `while` loop sits inside a `for` loop, but each index is pushed exactly once and popped at most once. Across the whole run there are at most `n` pushes and `n` pops, so the total work is $O(n)$ **amortized**, even though one iteration may pop many items. Space is $O(n)$ in the worst case, for example a strictly decreasing list that never pops.

### Values or indices?

Store **indices** when the answer involves distance (days until a warmer day, the width of a rectangle) or when you need to write into a result array by position. Store **values** when only the values matter. Storing indices is the safer default: you can always look the value up with `nums[stack[-1]]`.

### Direction and strictness

Decide before coding: are you looking at the next or previous element, greater or smaller, strictly or not? "Next strictly greater" pops while `nums[top] < x`. "Next greater or equal" pops while `nums[top] <= x`. If you scan right to left, the stack holds candidates for items to the left. Writing one tiny example with duplicates settles the question.

### A stack with constant-time minimum

A classic design question: support `push`, `pop`, `top` and `get_min` all in $O(1)$. Store with each item the minimum of everything at or below it. The minimum is then always on the top entry, and popping automatically restores the previous minimum.

### How to talk about it

"I need the nearest item to the right that is larger, so I will keep a stack of positions still waiting for an answer, in decreasing order. When a bigger value arrives, it resolves everything smaller on top of the stack." Then add: "Each index is pushed and popped once, so it is linear."

@example
title: Daily temperatures with a monotonic stack
problem: For `temps = [73, 74, 75, 71, 69, 72, 76, 73]`, find for each day how many days to wait for a warmer temperature (`0` if never).
step: Keep a stack of day indices whose answer is still unknown; their temperatures are decreasing. Start with an empty stack and `answer = [0] * 8`.
step: Day 0 (73): stack empty, push 0. Day 1 (74): top is day 0 (73) which is colder, so `answer[0] = 1 - 0 = 1`; push 1. Day 2 (75): pops day 1 (`answer[1] = 1`); push 2.
step: Days 3 (71) and 4 (69) are each colder than the top, so they just push: stack is days `2, 3, 4`.
step: Day 5 (72): pops day 4 (69), `answer[4] = 1`; pops day 3 (71), `answer[3] = 2`; day 2 (75) is warmer, so stop; push 5.
step: Day 6 (76): pops day 5 (`answer[5] = 1`) and day 2 (`answer[2] = 4`); push 6. Day 7 (73): push. Days 6 and 7 stay at `0`.
answer: `[1, 1, 4, 2, 1, 1, 0, 0]`

@example
title: Removing adjacent duplicates with a stack
problem: Repeatedly delete two equal adjacent characters from `"abbaca"` until none remain. What is left?
step: Scan left to right keeping a stack of surviving characters. Push `a`; stack `[a]`.
step: Next `b`: top is `a`, different, push. Next `b`: top is `b`, equal, so pop both: stack `[a]`.
step: Next `a`: top is `a`, equal, so pop: stack `[]`. Next `c`: push: `[c]`. Next `a`: top is `c`, different, push: `[c, a]`.
step: In code:

```python
def remove_duplicates(s):
    stack = []
    for ch in s:
        if stack and stack[-1] == ch:
            stack.pop()
        else:
            stack.append(ch)
    return "".join(stack)
```

Each character is pushed at most once and popped at most once: $O(n)$ time and space.
answer: `"ca"`

@mistakes
- Calling `pop()` or reading `stack[-1]` on an empty stack, which raises `IndexError`; test `while stack and ...` first.
- Returning `True` for brackets as soon as the loop ends without checking that the stack is empty, so `"(("` passes.
- Getting strictness wrong with duplicate values (`<` versus `<=` when popping).
- Claiming a monotonic stack is $O(n^2)$ because of the nested loop, instead of explaining the amortized push-and-pop count.

tests:
```python

assert is_valid("(]") is False
assert is_valid("([)]") is False
assert is_valid("{[]}") is True
assert is_valid("") is True

```
model:
```python
def is_valid(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
        else:
            stack.append(ch)
    return not stack
```
hint: Push every opener. When you see a closer, the top of the stack must be its matching opener.
hint: A closer on an empty stack is invalid, and leftover openers at the end are invalid too.
solution: Pattern: stack for nested matching. Map each closer to its opener, pop on a closer and compare, and return `not stack` at the end so that `"(("` fails. Time $O(n)$, space $O(n)$.

model:
```python
def eval_rpn(tokens):
    ops = {"+", "-", "*", "/"}
    stack = []
    for t in tokens:
        if t in ops:
            b = stack.pop()
            a = stack.pop()
            if t == "+":
                stack.append(a + b)
            elif t == "-":
                stack.append(a - b)
            elif t == "*":
                stack.append(a * b)
            else:
                stack.append(int(a / b))
        else:
            stack.append(int(t))
    return stack[0]
```
hint: Push numbers. On an operator, pop two operands, apply the operator and push the result.
hint: The second operand popped is the left operand, so for `-` and `/` compute `a - b` where `b` was popped first. Use `int(a / b)` to truncate toward zero.
solution: Pattern: stack evaluation. Note that `//` floors toward negative infinity (`7 // -2` is `-4`), so `int(a / b)` is needed. Time $O(n)$, space $O(n)$.

assert stock_span([]) == []
assert stock_span([5, 5, 5]) == [1, 2, 3]

model:
```python
def stock_span(prices):
    spans = []
    stack = []  # indices with strictly decreasing prices
    for i, p in enumerate(prices):
        while stack and prices[stack[-1]] <= p:
            stack.pop()
        spans.append(i + 1 if not stack else i - stack[-1])
        stack.append(i)
    return spans
```
hint: The span ends at the previous day whose price is strictly greater.
hint: Keep a stack of indices with decreasing prices; pop while the top price is less than or equal to today's.
solution: Pattern: monotonic stack for the previous greater element. After popping, the top (if any) is the nearest earlier day with a higher price, so the span is `i - top`; with an empty stack it is `i + 1`. Time $O(n)$ amortized, space $O(n)$.

@quiz code
prompt: Implement a class `MinStack` with methods `push(x)`, `pop()` (returns the removed value), `top()` and `get_min()`, all in $O(1)$ time. Duplicated minimum values must be handled correctly.
starter:
```python
class MinStack:
    pass
```
tests:
```python
s = MinStack()
s.push(5)
s.push(3)
s.push(7)
assert s.get_min() == 3
assert s.top() == 7
assert s.pop() == 7
assert s.get_min() == 3
assert s.pop() == 3
assert s.get_min() == 5
s.push(5)
s.push(2)
assert s.pop() == 2
assert s.get_min() == 5
assert s.pop() == 5
assert s.get_min() == 5
```
model:
```python
class MinStack:
    def __init__(self):
        self._items = []  # (value, minimum at or below this entry)

    def push(self, x):
        if self._items:
            m = min(x, self._items[-1][1])
        else:
            m = x
        self._items.append((x, m))

    def pop(self):
        return self._items.pop()[0]

    def top(self):
        return self._items[-1][0]

    def get_min(self):
        return self._items[-1][1]
```
hint: Store with every item the minimum of the stack up to and including that item.
solution: Pattern: augmented stack. Each entry carries the minimum of itself and everything beneath it, so `get_min` reads the top entry and `pop` restores the previous minimum automatically, including when the minimum value appears twice. Every operation is $O(1)$; space is $O(n)$.

@quiz mc
prompt: A function uses a monotonic stack, with a `while` loop inside a `for` loop over `n` items. What is its worst-case time complexity?
choice: $O(n^2)$, because of the nested loops.
choice*: $O(n)$ amortized, because each item is pushed once and popped at most once.

solution: One iteration can pop many items, but every item is popped at most once overall, so total pops are at most $n$ and total pushes are exactly $n$. The total is $O(n)$ amortized, with $O(n)$ space.
