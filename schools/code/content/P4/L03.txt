@article
Many array and string problems ask about pairs or contiguous ranges. A brute force checks every pair or every range, which is $O(n^2)$ or worse. Two pointers and sliding windows cut this to $O(n)$ by exploiting structure: sortedness, or the fact that ranges overlap.

### Opposite-end pointers

When the array is **sorted**, put one pointer at each end. Look at the pair, and let the comparison tell you which pointer to move. For "find two numbers that sum to `target`": if the sum is too small, the left number is too small to be part of any answer with the current right number, so move `lo` right; if too large, move `hi` left. Each step discards one element for good, so the loop runs at most `n` times: $O(n)$ time, $O(1)$ space. The same shape solves palindrome checks, "container with most water" and merging two sorted arrays.

### Fast and slow pointers on arrays

Both pointers start at the left and move in the same direction at different speeds. The classic use is **in-place compaction**: `slow` marks where the next kept item goes, `fast` scans. For removing duplicates from a sorted array, copy `nums[fast]` to `nums[slow]` whenever it differs from the last kept item.

### Fixed-size windows

If you need a statistic over every block of `k` consecutive items, do not recompute it each time. Slide: add the entering item, subtract the leaving item.

```python
window = sum(nums[:k])
best = window
for i in range(k, len(nums)):
    window += nums[i] - nums[i - k]
    best = max(best, window)
```

That is $O(n)$ instead of $O(nk)$.

### Variable-size windows

Often the question is "the longest (or shortest) contiguous range satisfying a condition". Keep a window `[left, right]` and some state about its contents (a count, a sum, a dictionary). The template:

1. Expand `right` one step and add `nums[right]` to the state.
2. While the window is **invalid** (for a "longest" problem) or **valid** (for a "shortest" problem), shrink it: remove `nums[left]` from the state and advance `left`.
3. Record the answer.

Each index enters the window once and leaves at most once, so the total work is $O(n)$ even though there is a loop inside a loop. This is a point worth saying aloud: a nested `while` does not automatically mean $O(n^2)$.

### When a window works

A window needs **monotonicity**: growing the window can only push the state in one direction, and shrinking pushes it back. "Sum at least `target`" with positive numbers is monotone. With negative numbers it is not: adding an element might lower the sum, so you cannot know whether to shrink. For that case, switch to prefix sums with a hash map, as in the last lesson. "At most `k` distinct characters" is monotone because removing a character never increases the distinct count.

### Choosing quickly

| Clue in the problem | Pattern |
|---|---|
| Sorted array, a pair or triple | Opposite-end pointers |
| Modify an array in place, keep order | Fast and slow pointers |
| "Contiguous", "substring", "subarray", with a limit | Sliding window |
| Contiguous with negative numbers and a target sum | Prefix sums and a hash map |

### Talking through it

Say what each pointer means ("`left` is the start of the current valid window"), what invariant holds ("the window never has repeated characters") and why the loop terminates (`right` increases every iteration). Interviewers listen for the invariant.

@example
title: Removing duplicates from a sorted array in place
problem: Given the sorted list `[0, 0, 1, 1, 1, 2, 2, 3]`, move the distinct values to the front in place and return how many there are.
step: Let `slow` be the index where the next distinct value goes, starting at `1` because the first item is always kept. `fast` scans from index 1.
step: `fast = 1`: value `0` equals `nums[slow - 1] = 0`; skip. `fast = 2`: value `1` differs from `0`, so write `nums[1] = 1` and set `slow = 2`.
step: `fast = 3, 4`: value `1` equals the last kept `1`; skip. `fast = 5`: value `2` is new, so `nums[2] = 2`, `slow = 3`. `fast = 6`: another `2`; skip.
step: `fast = 7`: value `3` is new, so `nums[3] = 3` and `slow = 4`. The list starts with `[0, 1, 2, 3]`.
step: As code, which is $O(n)$ time and $O(1)$ extra space:

```python
def dedupe_sorted(nums):
    if not nums:
        return 0
    slow = 1
    for fast in range(1, len(nums)):
        if nums[fast] != nums[slow - 1]:
            nums[slow] = nums[fast]
            slow += 1
    return slow
```
answer: `4`, with the first four items `[0, 1, 2, 3]`.

@example
title: Longest substring with at most two distinct characters
problem: Find the length of the longest substring of `"eceba"` that has at most two distinct characters.
step: Keep a dictionary `counts` of characters in the window `[left, right]`. The window is invalid when `len(counts) > 2`.
step: Expand: `e`, `c`, `e` give `counts = {e: 2, c: 1}`; the window `"ece"` is valid, length 3.
step: Expand `b`: `counts = {e: 2, c: 1, b: 1}` has 3 distinct, so shrink. Remove `e` (count 1), remove `c` (count 0, delete the key). Now `left = 2`, window `"eb"`. Longest so far stays 3.
step: Expand `a`: three distinct again; remove `e`, leaving window `"ba"`, length 2.
step: In code:

```python
def longest_two_distinct(s):
    counts = {}
    left = 0
    best = 0
    for right, ch in enumerate(s):
        counts[ch] = counts.get(ch, 0) + 1
        while len(counts) > 2:
            counts[s[left]] -= 1
            if counts[s[left]] == 0:
                del counts[s[left]]
            left += 1
        best = max(best, right - left + 1)
    return best
```

Each character enters and leaves once: $O(n)$ time, $O(1)$ space because the dictionary holds at most three keys.
answer: `3`

@mistakes
- Using a sliding window with negative numbers for a "sum at least target" problem; the window is no longer monotone.
- Forgetting to delete a key whose count reached zero, so `len(counts)` overstates the distinct characters.
- Computing the window length as `right - left` instead of `right - left + 1`.
- Moving the wrong pointer in the opposite-end pattern, for example moving `hi` when the sum is too small.

@practice code
prompt: Write `pair_sum_sorted(nums, target)` for a list `nums` sorted in ascending order. Return `[i, j]` with `i < j` and `nums[i] + nums[j] == target`, or `[]` if no pair exists. Use $O(1)$ extra space.
starter:
```python
def pair_sum_sorted(nums, target):
    pass
```
tests:
```python
assert pair_sum_sorted([1, 3, 4, 6, 9], 12) == [1, 4]
assert pair_sum_sorted([1, 3, 4, 6, 9], 13) == [2, 4]
assert pair_sum_sorted([2, 5], 8) == []
assert pair_sum_sorted([], 1) == []
assert pair_sum_sorted([-4, -1, 2, 3], -2) == [0, 2]
```
model:
```python
def pair_sum_sorted(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        s = nums[lo] + nums[hi]
        if s == target:
            return [lo, hi]
        if s < target:
            lo += 1
        else:
            hi -= 1
    return []
```
hint: Start one pointer at each end and look at the sum of the two items.
hint: If the sum is too small, only moving the left pointer can increase it; if too large, move the right pointer.
solution: Pattern: opposite-end two pointers on sorted data. Every iteration discards one element, so the loop runs at most `n - 1` times: $O(n)$ time, $O(1)$ space. The loop condition `lo < hi` stops the same item being used twice.

@practice code
prompt: Write `longest_unique(s)` that returns the length of the longest substring of `s` with no repeated characters. The empty string gives `0`. Aim for $O(n)$ time.
starter:
```python
def longest_unique(s):
    pass
```
tests:
```python
assert longest_unique("abcabcbb") == 3
assert longest_unique("") == 0
assert longest_unique("bbbbb") == 1
assert longest_unique("pwwkew") == 3
assert longest_unique("abba") == 2
```
model:
```python
def longest_unique(s):
    last = {}
    start = 0
    best = 0
    for i, ch in enumerate(s):
        if ch in last and last[ch] >= start:
            start = last[ch] + 1
        last[ch] = i
        best = max(best, i - start + 1)
    return best
```
hint: Remember the last index at which each character appeared.
hint: When a character repeats inside the current window, move the window start just past its previous index, but never backwards.
solution: Pattern: variable-size sliding window with a last-seen dictionary. The check `last[ch] >= start` matters for `"abba"`: when the final `a` arrives, its old index is outside the window, so the start must not move back. Time $O(n)$, space $O(k)$ for the alphabet.

@quiz code
prompt: Write `min_subarray_len(target, nums)` for a list of positive integers. Return the length of the shortest contiguous subarray whose sum is at least `target`, or `0` if no subarray qualifies. Aim for $O(n)$ time.
starter:
```python
def min_subarray_len(target, nums):
    pass
```
tests:
```python
assert min_subarray_len(7, [2, 3, 1, 2, 4, 3]) == 2
assert min_subarray_len(4, [1, 4, 4]) == 1
assert min_subarray_len(11, [1, 1, 1, 1]) == 0
assert min_subarray_len(15, [1, 2, 3, 4, 5]) == 5
assert min_subarray_len(5, []) == 0
```
model:
```python
def min_subarray_len(target, nums):
    best = len(nums) + 1
    left = 0
    total = 0
    for right, n in enumerate(nums):
        total += n
        while total >= target:
            best = min(best, right - left + 1)
            total -= nums[left]
            left += 1
    return best if best <= len(nums) else 0
```
hint: Expand the right end, adding to a running sum.
hint: While the sum is already at least `target`, record the length and shrink from the left.
solution: Pattern: variable-size window for a "shortest" answer, which shrinks while the window is valid. Each index enters and leaves once: $O(n)$ time, $O(1)$ space. The sentinel `len(nums) + 1` distinguishes "no answer" from a real length.

@quiz mc
prompt: A teammate proposes a sliding window to count subarrays of `[4, -2, 3, -1, 2]` that sum to exactly 5. What is wrong with that plan?
choice: Sliding windows only work on strings, not on lists of numbers.
choice*: Negative numbers mean the sum is not monotone as the window grows, so there is no safe rule for when to shrink; prefix sums with a hash map work instead.
choice: Sliding windows always take $O(n^2)$ time.
choice: The target must be zero for sliding windows to work.
hint: Ask whether adding an item always increases the sum.
solution: With negative values, extending the window can lower the sum and shrinking can raise it, so the window rule breaks. A prefix-sum dictionary handles any integers in $O(n)$ time. Sliding windows work on lists of numbers and are linear when monotone.
