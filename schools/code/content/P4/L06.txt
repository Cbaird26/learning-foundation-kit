@article
Linked lists show up in interviews not because anyone uses them much in daily Python, but because they test whether you can reason carefully about references and edge cases. Every question is a variation on the same few moves, so learn the moves.

### The node

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next
```

A list is just a reference to its first node, the **head**; the end is the node whose `next` is `None`. There is no index: reaching item `k` costs $O(k)$. Inserting or deleting after a node you already hold costs $O(1)$.

### Three habits that prevent bugs

1. **Draw it.** Sketch boxes and arrows, and redraw after each pointer change.
2. **Save before you overwrite.** Reassigning `node.next` loses the rest of the list unless you stored it first.
3. **Check the edges.** Empty list, one node, two nodes, and operating on the head or the tail.

### The dummy head

Deleting or inserting at the head is a special case, because there is no previous node. Create `dummy = ListNode(0, head)` and work from there; at the end return `dummy.next`. The head becomes an ordinary node, and one set of code handles all positions. Use the same trick when building a result list: keep a `tail` pointer, append to `tail.next`, and return `dummy.next`.

### Reversal

Reverse by walking once and flipping each arrow, keeping three references:

```python
def reverse_list(head):
    prev = None
    while head:
        nxt = head.next    # save the rest
        head.next = prev   # flip the arrow
        prev = head        # advance prev
        head = nxt         # advance head
    return prev
```

It is $O(n)$ time and $O(1)$ space. Memorize the order of the four lines, because every other list problem uses a piece of it. A recursive version takes $O(n)$ stack space, which you should mention.

### Fast and slow pointers

Move `slow` one step and `fast` two steps at a time.

- **Middle.** When `fast` reaches the end, `slow` is at the middle.
- **Cycle detection (Floyd's algorithm).** If there is a cycle, `fast` eventually laps `slow` and they meet; if there is no cycle, `fast` reaches `None`. It uses $O(1)$ space, while a visited set uses $O(n)$.
- **nth from the end.** Advance `fast` by `n` steps first, then move both together; when `fast` hits the end, `slow` is `n` from the end. With a dummy head, start both at the dummy so that `slow` stops just before the node to delete.

### Merging two sorted lists

Compare the two heads, attach the smaller to the tail, advance that list, and when one list runs out attach the remainder of the other. Time $O(n + m)$, space $O(1)$ because you reuse nodes. The merge step is also the heart of merge sort on a linked list.

### Linked lists versus arrays

| Operation | Array (Python list) | Singly linked list |
|---|---|---|
| Access by index | $O(1)$ | $O(n)$ |
| Insert or delete at the front | $O(n)$ | $O(1)$ |
| Insert after a known node | $O(n)$ | $O(1)$ |
| Cache behavior | Good (contiguous) | Poor (scattered nodes) |

In practice arrays win most of the time. When an interviewer asks why you would still choose a linked list, the honest answer is constant-time splicing when you already hold the node, as in an LRU cache built on a doubly linked list plus a dictionary.

### Talking through it

Say which pointers you hold and what each means: "`prev` is the reversed part, `head` is the unprocessed part, `nxt` saves the tail so we do not lose it." Then trace a three-node list on paper before you finish.

@example
title: Removing all nodes with a given value using a dummy head
problem: Remove every node with value `2` from the list `2 → 2 → 3 → 2 → 4`.
step: The head itself must be removed, which is the case a dummy head handles. Create `dummy = ListNode(0, head)` and let `prev = dummy`.
step: Look at `prev.next`. It holds `2`, so skip it by setting `prev.next = prev.next.next`; `prev` does not move. Repeat: the next node is again `2`, skipped. Now `prev.next` holds `3`.
step: `3` stays, so advance `prev` to it. `prev.next` holds `2`: skip it. Now `prev.next` holds `4`: keep, advance. `prev.next` is `None`, so stop.
step: In code:

```python
def remove_value(head, val):
    dummy = ListNode(0, head)
    prev = dummy
    while prev.next:
        if prev.next.val == val:
            prev.next = prev.next.next
        else:
            prev = prev.next
    return dummy.next
```

The result is `3 → 4`. One pass: $O(n)$ time, $O(1)$ space.
answer: `3 → 4`

@example
title: Finding the middle node with fast and slow pointers
problem: Find the middle of `1 → 2 → 3 → 4 → 5`. For an even length, return the second of the two middle nodes.
step: Start `slow = fast = head` (node 1). Each round, `slow` moves 1 and `fast` moves 2, as long as `fast` and `fast.next` exist.
step: Round 1: `slow` is node 2, `fast` is node 3. Round 2: `slow` is node 3, `fast` is node 5.
step: `fast.next` is `None`, so the loop stops. `slow` is node 3, the middle.
step: For `1 → 2 → 3 → 4` the same loop ends with `fast` becoming `None`, and `slow` at node 3, the second middle.

```python
def middle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow
```

`fast` covers $n$ nodes in about $n/2$ rounds: $O(n)$ time, $O(1)$ space.
answer: Node `3`.

@mistakes
- Overwriting `node.next` before saving the rest of the list, which loses every following node.
- Forgetting to handle an empty list or a one-node list, so `head.next` raises `AttributeError` on `None`.
- Advancing `prev` after a deletion, which skips a node that could also need deleting.
- Using `while fast.next and fast:` in the wrong order, or testing `fast.next.next` without checking `fast.next`.

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


def merge_sorted(a, b):
    dummy = ListNode()
    tail = dummy
    while a and b:
        if a.val <= b.val:
            tail.next = a
            a = a.next
        else:
            tail.next = b
            b = b.next
        tail = tail.next
    tail.next = a if a else b
    return dummy.next
```
hint: Use a dummy head and a `tail` pointer that always marks the end of the merged list.
hint: Attach the smaller front node to `tail`, advance that list, and when one list is empty attach the other as the remainder.
solution: Pattern: dummy head plus two-pointer merge. No nodes are created besides the dummy, so space is $O(1)$ and time is $O(n + m)$. Using `<=` keeps equal items in their original order (stability).

model:
```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            return True
    return False
```
hint: Move one pointer one step at a time and another two steps at a time.
hint: If they ever point at the same node, there is a cycle; if the fast pointer reaches `None`, there is none.
solution: Pattern: fast and slow pointers (Floyd's cycle detection). Inside a cycle the fast pointer gains one node per round on the slow one, so they must meet. Time $O(n)$, space $O(1)$. Compare with `is`, not `==`, to test node identity.

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


def remove_nth_from_end(head, n):
    dummy = ListNode(0, head)
    fast = slow = dummy
    for _ in range(n):
        fast = fast.next
    while fast.next:
        fast = fast.next
        slow = slow.next
    slow.next = slow.next.next
    return dummy.next
```
hint: Use a dummy head so that removing the real head is not a special case.
hint: Move `fast` forward `n` steps, then move `fast` and `slow` together until `fast.next` is `None`; `slow` then sits just before the node to delete.
solution: Pattern: dummy head with a gap of `n` between two pointers. The gap means that when `fast` is on the last node, `slow` is just before the target. Time $O(L)$ for length `L` in one pass, space $O(1)$.

@quiz mc
prompt: A singly linked list has a cycle somewhere. Which method detects it using only $O(1)$ extra space?
choice: Store every visited node in a set and check each new node against it.
choice: Reverse the list and compare it to the original.
choice*: Advance one pointer one node per step and another two nodes per step, and check whether they ever meet.
choice: Count the nodes until `next` is `None`.
hint: Which option stores nothing that grows with the list?
solution: Floyd's fast and slow pointers keep two references, so the extra space is constant. A visited set works but uses $O(n)$ space, counting never ends on a cycle, and reversing does not make sense with a cycle.
