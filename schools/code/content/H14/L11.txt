@article
Programs that work with data about people have effects far beyond the screen. This lesson connects the data skills you have built (files, dictionaries, summaries) to questions about privacy, fairness and responsibility, which are part of computer science too.

### How personal data is collected and used

Data about a person comes from what they type into forms, from what their devices record (location, purchases, searches, which videos they watch), and from other people (a friend tags a photo). **Metadata**, data *about* data such as when and where a message was sent, can reveal a lot even without the content. Collected data is used to run services, to improve products, to show targeted advertising and for research such as public health studies. Many of these uses benefit people. The same data can also be sold, leaked in a breach, or used in ways a person never expected.

### Removing names is not enough

A data set may have *direct identifiers* (name, email address, ID number) and *quasi-identifiers*: ordinary fields such as postal code, age and gender that are not unique alone but can be **combined** with other information to single out one person. When someone matches an "anonymous" record to a real person, that is **re-identification**. Removing the name column is therefore often not enough.

One way to measure this risk is **k-anonymity**: a data set is *k-anonymous* for chosen fields if every combination of values of those fields is shared by at least $k$ records. If some combination appears only once ($k = 1$), the person with those values is unique. Computing it is a grouping problem, which you can solve with the dictionary patterns from lesson 5: count the records for each combination and take the smallest count. A larger $k$ is safer, though k-anonymity is not a guarantee: other fields or outside data can still reveal facts.

### Reducing the risk

- **Data minimization:** collect and keep only what you need for a stated purpose; data you never collected cannot leak.
- **Generalization:** replace exact values with ranges, such as an age band `30-39` instead of an age, or the first digits of a postal code instead of the whole code.
- **Dropping identifiers** that analysis does not need.
- **Access control and security:** limit who can read the data, and protect it when stored and sent.
- **Consent and transparency:** tell people what is collected and why, and let them choose where possible.

Laws and regulations also apply, which differ between places: examples include the European Union's GDPR, and in the United States, COPPA for children's data online and FERPA for student education records. This lesson is not legal advice.

### Bias and fairness

A data set may leave out groups of people or record them unevenly, which is called **sampling bias**. A program built from biased data, or from rules that ignore some users' needs, can treat groups unfairly, and the effects can be hard to see from inside the system. The **digital divide**, unequal access to devices, connectivity and skills, means that the benefits of computing are not shared equally either.

### Many perspectives

Reasonable people weigh these questions differently. Data sharing can speed up medical research and make services useful; it can also expose people to surveillance, discrimination or fraud. Automation can save work and create jobs; it can also remove them. As a programmer you make choices that matter here: what to collect, what to keep, and how to describe the limits of what your analysis shows.

@example
title: Checking a data set with a group-size count
problem: After removing names, a school survey has four records of the form (postal code, age, club): (30301, 15, chess), (30301, 15, art), (30302, 16, chess), (30301, 17, chess). How can the data be made safer, and how do you know?
step: Group by the pair (postal code, age). The groups are (30301, 15) with 2 records, (30302, 16) with 1 and (30301, 17) with 1. The smallest group has size 1, so $k = 1$: anyone who knows that a classmate is 16 and lives in 30302 learns that person's club.
step: Generalize the age to bands (`10-19`). Now the groups are (30301, 10-19) with 3 records and (30302, 10-19) with 1. Still $k = 1$, because of the postal code 30302.
step: Also generalize the postal code to its first four digits, `3030`. All four records now share (`3030`, `10-19`), so $k = 4$.
step: The price is detail: the analysis can no longer tell ages 15 and 17 apart, or the two postal codes. That trade-off between usefulness and privacy is a decision to make deliberately, based on the question the data must answer.

@example
title: Generalizing an age into a band
problem: Write `age_band(age)` that turns an age such as 34 into the string `"30-39"`.
step: Find the start of the band: `age // 10 * 10`. For 34 this is `3 * 10 = 30`.
step: The band ends 9 above its start, so the end is `start + 9`.
step: Build the string with an f-string:

```python
def age_band(age):
    start = age // 10 * 10
    return f"{start}-{start + 9}"
```
step: Check: `age_band(34)` is `"30-39"`, `age_band(30)` is `"30-39"`, and `age_band(9)` is `"0-9"`.

@mistakes
- Believing that deleting the name column makes a data set anonymous.
- Keeping exact values (full birth date, home address) when a range would answer the question.
- Treating a data set as neutral: who is missing from it, or measured badly, affects every conclusion.
- Presenting privacy and convenience as simple opposites, instead of weighing a specific purpose, the data collected and the safeguards.

@practice code
prompt: Write `min_group_size(records, keys)` where `records` is a list of dictionaries and `keys` is a list of field names. Group the records by the tuple of their values for the fields in `keys`, and return the size of the smallest group: this number is the `k` of k-anonymity for those fields. An empty list of records gives `0`. If `keys` is empty, all records form one group.
starter:
```python
def min_group_size(records, keys):
    pass
```
tests:
```python
people = [
    {"zip": "303", "age": "10-19", "club": "chess"},
    {"zip": "303", "age": "10-19", "club": "art"},
    {"zip": "303", "age": "20-29", "club": "art"},
    {"zip": "304", "age": "10-19", "club": "chess"},
]
assert min_group_size(people, ["zip", "age"]) == 1
assert min_group_size(people, ["club"]) == 2
assert min_group_size(people, []) == 4
assert min_group_size([], ["zip"]) == 0
assert min_group_size(people[:2], ["zip", "age"]) == 2
```
model:
```python
def min_group_size(records, keys):
    counts = {}
    for record in records:
        combo = tuple(record[k] for k in keys)
        counts[combo] = counts.get(combo, 0) + 1
    if not counts:
        return 0
    return min(counts.values())
```
hint: Count how many records share each combination of values. A tuple of the values can be a dictionary key.
hint: Build `combo = tuple(record[k] for k in keys)` for each record, count it in a dictionary, and return the smallest count (0 if there are no records).
solution: The counting pattern with tuples as keys: each record contributes 1 to the count of its combination of values. The answer is `min(counts.values())`, and an empty record list needs the special answer `0`. With no keys, every record has the empty tuple as its combination, so there is one group of all the records.

@quiz code
prompt: Write `drop_fields(records, fields)` where `records` is a list of dictionaries and `fields` is a list of key names. Return a **new** list of **new** dictionaries, each like the original but without the keys named in `fields`. A key that is missing from a record is ignored. The original records must not change.
starter:
```python
def drop_fields(records, fields):
    pass
```
tests:
```python
people = [{"name": "a", "age": 15, "club": "x"}, {"name": "b", "age": 16}]
clean = drop_fields(people, ["name", "club"])
assert clean == [{"age": 15}, {"age": 16}]
assert people[0] == {"name": "a", "age": 15, "club": "x"}
assert drop_fields([], ["name"]) == []
assert drop_fields(people, []) == people
assert drop_fields(people, []) is not people
assert drop_fields([{"id": 1}], ["id"]) == [{}]
```
model:
```python
def drop_fields(records, fields):
    cleaned = []
    for record in records:
        copy = {}
        for key, value in record.items():
            if key not in fields:
                copy[key] = value
        cleaned.append(copy)
    return cleaned
```
hint: Build a new dictionary for each record, copying only the keys that are not in `fields`.
hint: Loop over `record.items()` and keep a pair when `key not in fields`. Append each new dictionary to a new list.
solution: For every record make an empty dictionary and copy over each key and value whose key is not listed in `fields`. Building new dictionaries leaves the originals unchanged, and a key that is not present is never copied, so nothing special is needed for missing keys.
