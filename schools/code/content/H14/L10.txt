@article
A **simulation** is a program that imitates a real or imagined process, so you can study it by running it many times. When the process involves chance, such as dice, card shuffles or customers arriving, the program needs random numbers.

### The random module

```python
import random

random.randint(1, 6)        # an integer from 1 to 6, both ends included
random.random()             # a float with 0.0 <= x < 1.0
random.choice(["a", "b"])   # one item chosen from a non-empty list
random.shuffle(cards)       # reorders the list in place, returns None
random.sample(cards, 3)     # a list of 3 different items, chosen without repeats
```

Be careful with `randint(1, 6)`: unlike `range`, **both ends are included**, so it can return 1 and 6. `random.shuffle(xs)` changes `xs` and returns `None`, so `xs = random.shuffle(xs)` is the same kind of bug as `xs = xs.sort()`.

### Pseudo-random numbers and seeds

Computers produce **pseudo-random** numbers: a fixed formula generates a long sequence that *looks* random. The sequence starts from a number called the **seed**. `random.seed(42)` sets it, and the same seed gives the same sequence again, which is useful when you want to repeat a run to find a bug. Without a seed Python starts from an unpredictable value. Do not use the `random` module for security (passwords, tokens); the `secrets` module exists for that.

### Estimating a probability

The **probability** of an event is the fraction of the time it happens in the long run. To estimate it, run the experiment many times and count:

```python
import random

def roll_two():
    return random.randint(1, 6) + random.randint(1, 6)

trials = 10_000
sevens = 0
for _ in range(trials):
    if roll_two() == 7:
        sevens += 1
print(sevens / trials)    # close to 0.1667, but a little different each run
```

(The `_` is a normal variable name that means "I do not use this value".) The exact probability of a total of 7 is $6/36 = 1/6 \approx 0.1667$, because 6 of the 36 equally likely pairs of dice add up to 7. A simulation gives an *estimate*: it varies from run to run, and with more trials the estimate usually lies closer to the true value (the **law of large numbers**). With 100 trials the answer can be quite far off; with 10,000 it is typically within about 0.01.

### Writing simulations you can test

A function that rolls dice inside its own logic is hard to test, because its result is random. Separate the **game rules** from the **randomness** by passing the random part in as a function:

```python
def play_double(roll):
    first = roll()
    second = roll()
    return first == second
```

In a real simulation you call `play_double(lambda: random.randint(1, 6))`. In a test you pass a fake roller that returns known values, so every outcome is predictable and you can `assert` the exact result. A short function `estimate_probability(game, trials)` can then repeat any such game and return the fraction of wins.

### Why simulate at all?

Some questions are easy to solve exactly (two dice), and some are hard (a board game with hundreds of rules, the spread of a disease, traffic). A simulation lets you answer them by experiment, and checking it on a case with a known answer first (like the dice) shows that the code is right.

@example
title: The exact answer by counting outcomes
problem: What is the exact probability that two fair dice have total 8?
step: There are $6 \cdot 6 = 36$ equally likely ordered outcomes.
step: List the ones with total 8: (2,6), (3,5), (4,4), (5,3), (6,2). That is 5 outcomes.
step: The probability is $5/36 \approx 0.139$.
step: A simulation of 10,000 rolls should give a value near 0.139, such as 0.14, though not exactly this number.
answer: $5/36$

@example
title: A testable game function
problem: Test `play_double(roll)` without using random numbers.
step: The function calls `roll()` twice and compares the two values.
step: For a test, build a roller that returns values from a list, one per call:

```python
values = iter([3, 3])
assert play_double(lambda: next(values)) is True

values = iter([2, 5])
assert play_double(lambda: next(values)) is False
```
step: `iter` makes an iterator and each `next(values)` gives the following value, so the first roller returns 3 and then 3. The result is `True`, and the second case gives `2` and `5`, so `False`.
step: Because the outcome of every call is fixed, the tests are repeatable, even though in the real simulation the game is random.

@mistakes
- Using `randint(1, 6)` as if the upper end were excluded, or `randint(0, 6)` for a die.
- Writing `xs = random.shuffle(xs)`, which stores `None`.
- Running too few trials and trusting the estimate; with 10 trials the result is mostly noise.
- Calling the random function several times where one value is needed, for example `if random.randint(1, 6) == 6 or random.randint(1, 6) == 6`, which rolls two dice.

@practice code
prompt: Write `estimate_probability(game, trials)`, where `game` is a function with no arguments that returns `True` for a win and `False` for a loss. Call `game()` exactly `trials` times and return the fraction of the calls that returned `True`, as `wins / trials`. `trials` is at least 1.
starter:
```python
def estimate_probability(game, trials):
    pass
```
tests:
```python
import random
assert estimate_probability(lambda: True, 10) == 1.0
assert estimate_probability(lambda: False, 10) == 0.0
state = {"calls": 0}
def every_second():
    state["calls"] += 1
    return state["calls"] % 2 == 0
assert estimate_probability(every_second, 10) == 0.5
assert state["calls"] == 10
p = estimate_probability(lambda: random.randint(1, 6) == 6, 5000)
assert 0.1 < p < 0.25
```
model:
```python
def estimate_probability(game, trials):
    wins = 0
    for _ in range(trials):
        if game():
            wins += 1
    return wins / trials
```
hint: Count the wins in an accumulator that starts at 0.
hint: Loop `trials` times, add 1 when `game()` is true, and divide by `trials` at the end.
solution: A counting loop: call `game()` once per trial, add 1 to `wins` for each `True`, and return `wins / trials` after the loop. Because the function takes the game as an argument, the same estimator works for dice, cards or any other `True`/`False` experiment.

model:
```python
import random


def shuffled_copy(xs):
    result = list(xs)
    random.shuffle(result)
    return result
```
hint: `random.shuffle` changes a list in place, so first make a copy.
hint: Copy with `list(xs)`, shuffle the copy, and return the copy (not the result of `shuffle`, which is `None`).
solution: `result = list(xs)` makes an independent list, `random.shuffle(result)` reorders it in place, and the function returns `result`. Returning the value of `random.shuffle(...)` would return `None`.
