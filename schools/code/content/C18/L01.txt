@article
An **agent** is anything that perceives its environment through sensors and acts on it through actuators. Mathematically, an agent is a function from the **percept sequence** (everything it has perceived so far) to an **action**. An agent is **rational** when, for each percept sequence, it chooses the action expected to maximize its performance measure, given what it knows. Rationality is not omniscience: a rational agent can still be unlucky.

### Task environments and PEAS

To design an agent you first describe its **task environment** with **PEAS**: the **P**erformance measure, the **E**nvironment, the **A**ctuators and the **S**ensors. For an automated warehouse robot: performance is items delivered per hour with few collisions; the environment is the warehouse floor; actuators are wheels and a gripper; sensors are cameras and wheel encoders.

Environments are classified along standard dimensions:

| Property | One end | Other end |
|---|---|---|
| Observability | fully observable | partially observable |
| Determinism | deterministic | stochastic |
| Episodes | episodic | sequential |
| Change | static | dynamic |
| State and time | discrete | continuous |
| Agents | single-agent | multi-agent |

Chess without a clock is fully observable, deterministic, sequential, static, discrete and multi-agent. Poker is partially observable and stochastic. Driving a car is partially observable, stochastic, sequential, dynamic, continuous and multi-agent. The hardest real problems sit at the harder end of every row.

### Agent architectures

- A **simple reflex agent** maps the current percept to an action by condition-action rules. It fails when the percept does not reveal the state.
- A **model-based reflex agent** keeps an internal state, updated from a model of how the world changes and how actions affect it.
- A **goal-based agent** chooses actions by considering whether they lead to a goal. Search and planning belong here.
- A **utility-based agent** maximizes a utility function, which handles trade-offs and uncertainty.
- A **learning agent** improves its own performance from experience.

### Problem formulation

For a fully observable, deterministic, discrete environment, a problem is defined by five things:

1. the **initial state**;
2. **actions(s)**: the actions applicable in state $s$;
3. the **transition model** **result(s, a)**: the state that results from doing action $a$ in $s$;
4. a **goal test**;
5. a **step cost** $c(s, a, s')$, with the **path cost** being the sum of step costs.

The initial state, actions and transition model implicitly define the **state space**: a directed graph whose nodes are states and whose edges are actions. A **solution** is a sequence of actions from the initial state to a goal state; an **optimal** solution has the lowest path cost.

Choosing the **abstraction** is part of the work. A route-finding problem uses "in city X" as a state and ignores the weather and the radio. A good formulation keeps what matters and drops the rest, so that the state space is small enough to search.

### A worked formulation in code

Two jugs hold at most 3 and 5 litres. A state is a pair `(a, b)` of the litres in each jug. The six actions are: fill a jug, empty a jug, pour one jug into the other until the source is empty or the target is full.

```python
def pour(src, dst, dst_cap):
    amount = min(src, dst_cap - dst)
    return src - amount, dst + amount
```

`pour(4, 2, 5)` moves `min(4, 3) = 3` litres and returns `(1, 5)`.

@example
title: Formulating the two-jug problem
problem: Formulate the problem of measuring exactly 4 litres in the 5-litre jug, using jugs of capacity 3 and 5, both initially empty.
step: State: a pair `(a, b)` with `0 <= a <= 3` and `0 <= b <= 5`. There are $4 \times 6 = 24$ states.
step: Initial state: `(0, 0)`.
step: Actions: fill A, fill B, empty A, empty B, pour A into B, pour B into A. Each is always applicable, but some do not change the state, such as filling a full jug.
step: Transition model: for example `result((1, 4), pour A into B) = (0, 5)`, because `min(1, 5 - 4) = 1` litre moves.
step: Goal test: `b == 4`. Step cost: 1 per action, so path cost is the number of actions.
answer: Initial `(0, 0)`, six actions, pour rule above, goal `b == 4`, unit step cost.

@example
title: Classifying an environment
problem: Classify the task environment of an agent that plays a real-time online card game against several opponents who hide their cards.
step: Observability: opponents' cards are hidden, so it is partially observable.
step: Determinism: shuffling and opponents' choices make outcomes uncertain, so it is stochastic.
step: Episodes: earlier plays change later hands and information, so it is sequential.
step: Change and agents: the clock runs while the agent thinks, so it is dynamic, and there are several players, so it is multi-agent.
answer: Partially observable, stochastic, sequential, dynamic, discrete, multi-agent.

@mistakes
- Defining the state to include irrelevant detail, which makes the state space far larger than needed.
- Forgetting that the goal test is a predicate on states: a goal can be many states (any state with `b == 4`), not a single state.
- Confusing a rational agent with an omniscient one: rationality is judged by the expected performance given the percepts, not by the actual outcome.
- Counting the step cost twice, or treating path cost as the number of states instead of the sum of step costs.

@practice code
prompt: Write `successors(state, cap_a, cap_b)` for the two-jug problem. `state` is a pair `(a, b)` of litres in jugs of capacity `cap_a` and `cap_b`. Return a sorted list of the distinct states reachable by one action (fill A, fill B, empty A, empty B, pour A into B, pour B into A), excluding `state` itself. Pouring stops when the source is empty or the target is full.
starter:
```python
def successors(state, cap_a, cap_b):
    pass
```
tests:
```python
assert successors((0, 0), 3, 5) == [(0, 5), (3, 0)]
assert successors((3, 5), 3, 5) == [(0, 5), (3, 0)]
assert successors((3, 0), 3, 5) == [(0, 0), (0, 3), (3, 5)]
assert successors((1, 4), 3, 5) == [(0, 4), (0, 5), (1, 0), (1, 5), (3, 2), (3, 4)]
```
model:
```python
def successors(state, cap_a, cap_b):
    a, b = state
    to_b = min(a, cap_b - b)
    to_a = min(b, cap_a - a)
    result = {
        (cap_a, b),
        (a, cap_b),
        (0, b),
        (a, 0),
        (a - to_b, b + to_b),
        (a + to_a, b - to_a),
    }
    result.discard(state)
    return sorted(result)
```
hint: Build the six results as tuples and put them in a set to remove duplicates.
hint: The amount poured from A into B is `min(a, cap_b - b)`; from B into A it is `min(b, cap_a - a)`.
solution: Compute the six successor states, collect them in a set, discard the state itself (actions that change nothing), and return the sorted list. In `(1, 4)`, pouring A into B moves `min(1, 1) = 1` litre, giving `(0, 5)`.

@quiz code
prompt: A robot is on an `n` by `n` grid, with positions `(row, col)` where row 0 is the top row and `(0, 0)` is the top-left corner. Write `moves(pos, walls, n)` that returns the list of legal directions in the order `"N"`, `"S"`, `"E"`, `"W"`. `"N"` decreases the row, `"S"` increases it, `"E"` increases the column and `"W"` decreases it. A move is legal if the destination is on the grid and not in the set `walls`.
starter:
```python
def moves(pos, walls, n):
    pass
```
tests:
```python
assert moves((1, 1), set(), 3) == ["N", "S", "E", "W"]
assert moves((0, 0), set(), 3) == ["S", "E"]
assert moves((2, 2), set(), 3) == ["N", "W"]
assert moves((1, 1), {(0, 1), (1, 2)}, 3) == ["S", "W"]
assert moves((0, 0), {(0, 1), (1, 0)}, 2) == []
```
model:
```python
def moves(pos, walls, n):
    row, col = pos
    steps = [("N", -1, 0), ("S", 1, 0), ("E", 0, 1), ("W", 0, -1)]
    legal = []
    for name, dr, dc in steps:
        r, c = row + dr, col + dc
        if 0 <= r < n and 0 <= c < n and (r, c) not in walls:
            legal.append(name)
    return legal
```
hint: Store each direction with its row and column change.
hint: A destination is legal only if both coordinates are in `range(n)` and it is not in `walls`.
solution: Loop over the four directions in the required order, compute the destination, and keep the direction when the destination is inside the grid and not a wall. This is exactly the `actions(s)` function of the formulation.
