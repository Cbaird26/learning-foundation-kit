@article
Everything so far gave the agent a model: a state space, rules or probabilities. **Machine learning (ML)** instead builds the model from data. In **supervised learning** the data are examples $(x, y)$ of inputs and correct outputs, and the goal is a function $f$ that predicts $y$ for **new** inputs. **Classification** predicts a category and **regression** a number. **Unsupervised learning** finds structure in unlabeled data, and reinforcement learning (last week) learns from rewards.

### Training, testing and overfitting

A learner chooses $f$ from a family of functions to minimize a **loss** on the **training set**, for example squared error $\frac1m\sum_i (f(x_i) - y_i)^2$. The real goal is low error on unseen data, so we hold out a **test set** that is used only once at the end, and a **validation set** (or **cross-validation**) to choose settings such as model size. A very flexible model can memorize noise: **overfitting** means low training error but high test error. Too rigid a model **underfits**. This is the **bias-variance trade-off**. Remedies: more data, simpler models, **regularization** (penalizing large weights) and early stopping. Never tune on the test set, and beware of **data leakage** (information from the test set reaching training).

For binary classification, with TP, FP, FN and TN counts:
$$\text{accuracy} = \frac{TP + TN}{TP + FP + FN + TN},\quad \text{precision} = \frac{TP}{TP + FP},\quad \text{recall} = \frac{TP}{TP + FN}.$$
Accuracy misleads when classes are imbalanced: a rule that always answers "no" on a rare condition is highly accurate and useless.

### Models and gradient descent

**$k$-nearest neighbors** classifies a point by the majority label of its $k$ closest training points. **Linear and logistic regression**, **decision trees** and **neural networks** are other model families. A **neural network** composes layers of units, each computing a weighted sum of its inputs followed by a nonlinear activation. Its weights are trained by **gradient descent**, repeatedly moving the weights $w$ against the gradient of the loss with learning rate $\eta$:
$$w \leftarrow w - \eta \,\nabla_w L(w).$$
**Backpropagation** computes all the gradients efficiently with the chain rule. The **softmax** function turns a vector of scores into a probability distribution, $\text{softmax}(z)_i = e^{z_i} / \sum_j e^{z_j}$.

### Large language models

A **language model** assigns probabilities to the next **token** (a word or word piece) given the preceding text. A **large language model (LLM)** is a very large neural network, usually a **transformer** built on **self-attention**, which lets every position weigh information from earlier positions. It is first **pretrained** on a huge text corpus by minimizing the error of its next-token predictions (no human labels are needed), then often **fine-tuned** on example instructions and on human preference judgments. To generate text, the model repeatedly computes a probability distribution over tokens with softmax, picks one (always the most likely, or randomly with a **temperature**) and appends it.

Its limits follow from this design. The model optimizes plausibility of text, not truth, so it can state falsehoods fluently and confidently (often called **hallucination**). It reproduces patterns and **biases** of its training data. It can **memorize** and repeat training text, including private data. Text placed in its input is not reliably separated from instructions, so **prompt injection** by untrusted content is a security risk when a model has tools or access to data. It is sensitive to wording, and its behavior cannot be fully verified by testing. Systems that use LLMs therefore need evaluation on held-out cases, human oversight for consequential decisions, and defense in depth.

### Ethics and governance

Key issues are **fairness** (different groups can receive systematically different error rates; several formal fairness criteria exist and cannot all hold at once when base rates differ), **accountability** and **transparency** (who is responsible for an automated decision, and can it be explained?), **privacy**, **safety and reliability**, **misuse** (the same capability can serve defense and attack), effects on **work**, and **environmental cost** of training and running large models. Societies disagree about the right response: some favor binding rules tied to the risk of a use (as in the European Union's risk-based AI regulation), others sector-specific law or industry standards and voluntary commitments; people also disagree about how to balance innovation, safety and rights. A practitioner's job is to document data and model limits, test for harm across groups, keep humans accountable and choose where not to deploy.

@example
title: One gradient descent step
problem: Fit the line $\hat y = w x$ to the data $(1, 2)$ and $(2, 3)$ by minimizing $L(w) = \frac{1}{2}\left[(w - 2)^2 + (2w - 3)^2\right]$. Start at $w = 0$ with learning rate $\eta = 0.1$ and do one gradient descent step.
step: Differentiate: $L'(w) = (w - 2) + 2(2w - 3)$.
step: At $w = 0$: $L'(0) = (0 - 2) + 2(0 - 3) = -2 - 6 = -8$.
step: Update: $w \leftarrow 0 - 0.1 \cdot (-8) = 0.8$.
step: Check the loss fell: $L(0) = \frac12(4 + 9) = 6.5$ and $L(0.8) = \frac12(1.44 + 1.96) = 1.7$.
answer: $w = 0.8$, and the loss decreased from 6.5 to 1.7.

@example
title: Metrics for a classifier
problem: A classifier gives $TP = 30$, $FP = 10$, $FN = 5$ and $TN = 55$ on a test set. Compute accuracy, precision and recall.
step: The test set has $30 + 10 + 5 + 55 = 100$ examples.
step: Accuracy $= (30 + 55)/100 = 0.85$.
step: Precision $= 30/(30 + 10) = 0.75$: of the items flagged positive, three quarters are really positive.
step: Recall $= 30/(30 + 5) = 6/7 \approx 0.857$: of the really positive items, about 86% were found.
answer: Accuracy 0.85, precision 0.75, recall about 0.857.

@mistakes
- Measuring performance on the training data and reporting it as the expected performance on new data.
- Tuning hyperparameters on the test set, which makes the test score optimistic.
- Judging a classifier on accuracy alone when one class is rare.
- Treating fluent LLM output as evidence of correctness, or assuming that a model "looked up" a fact rather than generating plausible text.

tests:
```python
train = [((0, 0), "a"), ((0, 1), "a"), ((5, 5), "b"),
         ((6, 5), "b"), ((5, 6), "b")]
assert knn_predict(train, (1, 0), 1) == "a"
```

model:
```python
def knn_predict(train, query, k):
    def dist2(point):
        return (point[0] - query[0]) ** 2 + (point[1] - query[1]) ** 2

    nearest = sorted(train, key=lambda item: dist2(item[0]))[:k]
    votes = {}
    for _, label in nearest:
        votes[label] = votes.get(label, 0) + 1
    best = max(votes.values())
    return min(label for label, count in votes.items() if count == best)
```
hint: `sorted` is stable, so sorting by distance keeps the original order for equal distances.
hint: Count the labels of the first `k` sorted points, find the highest count, and among the labels with that count return the smallest.
solution: Sort by squared distance (no square root is needed to compare), keep `k` points and take a majority vote. With `k = 5` all points vote and `b` has three votes against two, so the answer changes with `k`.

@practice code
prompt: Write `softmax(scores)` that takes a list of numbers and returns a list of probabilities `e**z / sum(e**z)` computed in a numerically stable way (subtract the largest score before exponentiating, so that very large scores do not overflow). Use `math.exp`. The output must have the same length as the input and sum to 1.
starter:
```python
import math


def softmax(scores):
    pass
```
tests:
```python
p = softmax([0, 0])
assert abs(p[0] - 0.5) < 1e-9 and abs(p[1] - 0.5) < 1e-9
p = softmax([1, 2, 3])
assert abs(p[0] - 0.09003057) < 1e-6
assert abs(p[1] - 0.24472847) < 1e-6
assert abs(p[2] - 0.66524096) < 1e-6
p = softmax([1000, 1000])
assert abs(p[0] - 0.5) < 1e-9
assert abs(sum(softmax([-3, 0.5, 2, 7])) - 1.0) < 1e-9
assert softmax([5.0]) == [1.0]
```
model:
```python
import math


def softmax(scores):
    top = max(scores)
    exps = [math.exp(s - top) for s in scores]
    total = sum(exps)
    return [e / total for e in exps]
```
hint: `softmax` is unchanged if you subtract the same number from every score.
hint: Subtract `max(scores)` first, exponentiate, then divide each value by the sum.
solution: Subtracting the maximum shifts every exponent to at most 0, so `math.exp` cannot overflow, and the ratios (and so the probabilities) are unchanged. For `[1000, 1000]` a naive implementation would overflow.

@quiz code
prompt: Build a tiny language model. Write `greedy_continue(tokens, start, n)`. `tokens` is a list of strings. Count, for every token, how often each other token immediately follows it in `tokens` (a bigram model). Starting from the token `start`, repeatedly append the most frequent follower of the current token (ties go to the alphabetically smallest follower) until `n` tokens have been generated or the current token has no follower, and return the list of generated tokens (not including `start`).
starter:
```python
def greedy_continue(tokens, start, n):
    pass
```
tests:
```python
toks = "the cat sat on the mat the cat ran".split()
assert greedy_continue(toks, "the", 5) == ["cat", "ran"]
assert greedy_continue(toks, "on", 5) == ["the", "cat", "ran"]
assert greedy_continue(toks, "the", 1) == ["cat"]
assert greedy_continue(toks, "ran", 3) == []
assert greedy_continue(toks, "dog", 3) == []
assert greedy_continue(toks, "sat", 0) == []
```
model:
```python
def greedy_continue(tokens, start, n):
    follow = {}
    for a, b in zip(tokens, tokens[1:]):
        counts = follow.setdefault(a, {})
        counts[b] = counts.get(b, 0) + 1
    out = []
    current = start
    while len(out) < n and current in follow:
        counts = follow[current]
        best = max(counts.values())
        current = min(t for t, c in counts.items() if c == best)
        out.append(current)
    return out
```
hint: `zip(tokens, tokens[1:])` gives every pair of neighbouring tokens.
hint: Store counts in a dict of dicts, then at each step choose the follower with the highest count, breaking ties with `min`.
solution: A bigram model estimates the next-token distribution from counts. Always picking the most likely token is greedy decoding. After `the`, `cat` follows twice and `mat` once; after `cat`, `ran` and `sat` tie, and `ran` comes first alphabetically; `ran` is the last token of the data and has no follower, so generation stops. Large language models do the same next-token prediction with a far richer model of the context.

@quiz ms
prompt: Which statements about large language models are true?
choice*: They are trained to predict the next token from the preceding tokens
choice*: Fluent, confident output does not guarantee that a statement is true
choice*: They can reproduce biased associations present in their training text
choice*: Untrusted text in a model's input can act as instructions (prompt injection), which matters when the model can use tools or private data

hint: Think about the training objective and what it does and does not reward.
solution: The training objective rewards plausible continuations, which explains fluent but sometimes false output, inherited bias, and the weak separation between data and instructions. An LLM has no built-in verified fact database unless a system adds retrieval, and even then the output still needs checking.
