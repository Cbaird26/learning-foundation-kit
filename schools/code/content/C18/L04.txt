@article
Systematic search keeps paths in memory because the **path** is the answer. In many problems only the **final state** matters: a placement of queens, a circuit layout, a schedule. **Local search** keeps a single current state (or a few) and repeatedly moves to a neighbouring state, using $O(1)$ extra memory. It is not systematic and is usually incomplete, but it finds good states in huge spaces. The state space is viewed as a **landscape** with an **objective function** to maximize (or a cost to minimize).

### Hill climbing

**Steepest-ascent hill climbing** moves to the best neighbour and stops when no neighbour is strictly better.

```python
def hill_climb(value, neighbors, state):
    while True:
        best = max(neighbors(state), key=value, default=state)
        if value(best) <= value(state):
            return state
        state = best
```

It can get stuck on:

- a **local maximum**: higher than all neighbours, lower than the global maximum;
- a **plateau**: a flat region (a **shoulder** has an uphill edge); with a strict-improvement rule the search stops;
- a **ridge**: a sequence of local maxima that single moves cannot climb.

Common remedies are **random restarts** (run from many random initial states; with a positive success probability $p$ per run, the expected number of runs is $1/p$), allowing **sideways moves** with a cap, and **stochastic hill climbing**, which chooses randomly among uphill moves.

### Simulated annealing

Simulated annealing accepts a random neighbour. If it is better, accept it. If it is worse by $\Delta = \text{value(new)} - \text{value(old)} < 0$, accept it with probability
$$p = e^{\Delta / T},$$
where the **temperature** $T > 0$ is lowered over time (the **cooling schedule**). At high $T$ the walk is nearly random; as $T \to 0$ it behaves like hill climbing. For a maximization problem, a larger loss and a lower temperature both make acceptance less likely. With a sufficiently slow schedule, simulated annealing converges to a global optimum with probability approaching 1, though that schedule is too slow to be practical.

### Other local methods

**Local beam search** keeps $k$ states and each step keeps the $k$ best successors of all of them; unlike $k$ independent runs, the states share information. **Genetic algorithms** keep a population, select fit individuals, combine pairs by **crossover** and apply random **mutation**. For continuous states with a differentiable objective, **gradient descent** (or ascent) moves along the gradient; the same local-minimum issues appear.

### $n$-queens as a local search problem

Represent a state as a tuple where `state[c]` is the row of the queen in column `c`; this rules out column conflicts. The cost is the number of pairs of queens that attack each other (same row, or same diagonal: $|r_i - r_j| = |i - j|$). A solution has cost 0. The **min-conflicts** heuristic repeatedly moves a conflicted queen within its column to the row with the fewest conflicts, and it solves even million-queen instances quickly.

### When the path matters: A* on a grid

On a grid with walls, 4-neighbour moves and unit cost, the Manhattan distance to the goal is an admissible and consistent heuristic, so A* finds a shortest path, usually expanding far fewer cells than breadth-first search.

@example
title: Counting conflicts in 4-queens
problem: For the state `(1, 1, 3, 3)` (row of the queen in each of columns 0 to 3), how many attacking pairs are there?
step: Check the six pairs of columns. Columns 0 and 1 have rows 1 and 1: same row, attack.
step: Columns 2 and 3 have rows 3 and 3: same row, attack.
step: Columns 0 and 2: rows differ by 2 and columns differ by 2, so they share a diagonal and attack. Columns 1 and 3 behave the same way: rows 1 and 3, columns 1 and 3, so they attack.
step: Columns 0 and 3 (row difference 2, column difference 3) and columns 1 and 2 (row difference 2, column difference 1) do not attack.
answer: 4 attacking pairs.

@example
title: Simulated annealing acceptance
problem: A move reduces the objective by 3. What is the probability of accepting it at temperature $T = 2$, and at $T = 0.5$?
step: For a loss, $\Delta = -3$ and the probability is $e^{\Delta/T}$.
step: At $T = 2$: $e^{-3/2} = e^{-1.5} \approx 0.223$.
step: At $T = 0.5$: $e^{-3/0.5} = e^{-6} \approx 0.0025$.
step: The same bad move is about 90 times less likely at the lower temperature, which is why cooling turns the search from exploring into hill climbing.
answer: About 0.223 at $T = 2$ and about 0.0025 at $T = 0.5$.

@mistakes
- Assuming hill climbing finds the global optimum: it stops at the first local maximum it reaches.
- Using $e^{|\Delta|/T}$ (a positive exponent) for a worse move, which gives a probability above 1.
- Using $f = g + h$ with a Manhattan heuristic on a grid that allows diagonal moves at cost 1, where it is not admissible.
- Treating the number of conflicts as the number of conflicted queens; the objective counts attacking pairs, so three queens in one row give 3 pairs.

model:
```python
import heapq


def astar_grid(grid, start, goal):
    rows, cols = len(grid), len(grid[0])

    def h(cell):
        return abs(cell[0] - goal[0]) + abs(cell[1] - goal[1])

    frontier = [(h(start), 0, start)]
    best_g = {start: 0}
    while frontier:
        f, g, cell = heapq.heappop(frontier)
        if cell == goal:
            return g
        if g > best_g[cell]:
            continue
        r, c = cell
        for nr, nc in ((r - 1, c), (r + 1, c), (r, c - 1), (r, c + 1)):
            if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] != "#":
                new_g = g + 1
                if new_g < best_g.get((nr, nc), new_g + 1):
                    best_g[(nr, nc)] = new_g
                    heapq.heappush(
                        frontier, (new_g + h((nr, nc)), new_g, (nr, nc)))
    return -1
```
hint: The frontier holds tuples `(f, g, cell)`, with `f = g + h(cell)`.
hint: Record the best `g` found for every cell; push a neighbour only when it improves that record, and skip stale heap entries.
solution: This is A* with unit costs. Manhattan distance never overestimates on a 4-connected grid, so the first time the goal leaves the frontier its `g` is the shortest distance. If the frontier empties, the goal cannot be reached.

model:
```python
def best_neighbor(state):
    def cost(s):
        n = len(s)
        return sum(
            1
            for i in range(n)
            for j in range(i + 1, n)
            if s[i] == s[j] or abs(s[i] - s[j]) == j - i
        )

    best, best_cost = state, cost(state)
    for col in range(len(state)):
        for row in range(len(state)):
            if row == state[col]:
                continue
            candidate = state[:col] + (row,) + state[col + 1:]
            c = cost(candidate)
            if c < best_cost:
                best, best_cost = candidate, c
    return best
```
hint: Generate all `n * (n - 1)` neighbours by changing one entry of the tuple.
hint: Update the best candidate only on a strictly lower cost, scanning columns and then rows in increasing order, so that ties keep the earliest.
solution: Scan the neighbours in column-then-row order and replace the incumbent only when the cost is strictly lower, which gives the required tie-breaking and returns `state` when it is a local minimum. The state `(0, 2, 1, 3)` has cost 2 and no neighbour with lower cost, so it is a local minimum that is not a solution.
