@article
Last week's functions were small. Recursion becomes valuable for problems that split into smaller copies of themselves in less obvious ways. Four patterns cover a surprising amount of ground.

### Pattern 1: halve the problem (binary search)

To find a value in a **sorted** list, look at the middle item. If it is the target you are done; if the target is smaller, search only the left half; otherwise search only the right half. An empty range means "not found".

```python
def binary_search(items, target, lo=0, hi=None):
    if hi is None:
        hi = len(items) - 1
    if lo > hi:
        return -1
    mid = (lo + hi) // 2
    if items[mid] == target:
        return mid
    if target < items[mid]:
        return binary_search(items, target, lo, mid - 1)
    return binary_search(items, target, mid + 1, hi)
```

Passing `lo` and `hi` instead of slicing keeps the returned index meaningful for the original list and avoids copying. Each call halves the range, so the worst case is about $\log_2 n$ comparisons: $O(\log n)$ against $O(n)$ for a plain scan. A million sorted items need about 20 comparisons.

### Pattern 2: overlapping subproblems (memoization)

The Fibonacci numbers satisfy $F(n) = F(n-1) + F(n-2)$ with $F(0) = 0$ and $F(1) = 1$. Written directly, the recursion recomputes the same values again and again: `fib(5)` calls `fib(3)` twice, `fib(2)` three times, and the number of calls grows exponentially, roughly as $1.6^n$. **Memoization** stores each answer the first time it is computed:

```python
def fib(n, memo=None):
    if memo is None:
        memo = {}
    if n < 2:
        return n
    if n not in memo:
        memo[n] = fib(n - 1, memo) + fib(n - 2, memo)
    return memo[n]
```

Now each `n` is computed once, so the time is $O(n)$. The standard library's `functools.cache` decorator does the same for any function with hashable arguments. This is the doorway to *dynamic programming*, which you will meet in algorithms courses.

### Pattern 3: choices (subsets and backtracking)

To list all subsets of a list, take the first item and ask: for every subset of the *rest*, there are two subsets of the whole: one without the first item and one with it.

```python
def subsets(items):
    if not items:
        return [[]]
    rest = subsets(items[1:])
    return rest + [[items[0]] + s for s in rest]
```

A list of $n$ items has $2^n$ subsets, so the output itself doubles with every item: recursion is not slow here, the answer is just huge. The same shape of reasoning (try each choice, recurse on what remains) is called **backtracking** and solves permutations, puzzles and mazes.

### Pattern 4: the Towers of Hanoi

Three pegs hold disks of different sizes, all on the first peg with the largest at the bottom. You may move one disk at a time and never place a larger disk on a smaller one. To move $n$ disks from peg `A` to peg `C` using `B`: move $n-1$ disks `A` to `B`, move the biggest disk `A` to `C`, then move the $n-1$ disks `B` to `C`. The number of moves satisfies $M(n) = 2M(n-1) + 1$, which gives $M(n) = 2^n - 1$.

```python
def hanoi(n, src, dst, via):
    if n == 0:
        return
    hanoi(n - 1, src, via, dst)
    print("move", src, "to", dst)
    hanoi(n - 1, via, dst, src)
```

### Pattern 5: exploring a grid region

A **flood fill** visits every cell connected to a starting cell. Recurse into the four neighbors that are inside the grid, have the right value, and have not been visited yet; a set of visited positions prevents infinite loops. Paint programs and game maps use this idea.

### How to choose

If the input shrinks by a constant factor (halving), expect logarithmic depth. If each call makes two calls on slightly smaller inputs, check whether subproblems repeat; if they do, memoize.

@example
title: Tracing a binary search
problem: Search for `7` in `[1, 3, 5, 7, 9, 11]` with the recursive `binary_search`. Which indexes are examined, and what is returned?
step: First call: `lo = 0`, `hi = 5`, so `mid = 2` and `items[2]` is `5`. The target `7` is larger, so search the right half with `lo = 3`.
step: Second call: `lo = 3`, `hi = 5`, so `mid = 4` and `items[4]` is `9`. The target is smaller, so search the left half with `hi = 3`.
step: Third call: `lo = 3`, `hi = 3`, so `mid = 3` and `items[3]` is `7`: found.
step: The function returns index `3` after examining indexes `2`, `4` and `3`, three comparisons for six items.
answer: Indexes 2, 4, 3 are examined and `3` is returned.

@example
title: Counting subsets
problem: What does `subsets([1, 2])` return?
step: Base case: `subsets([])` returns `[[]]`, the list holding the one empty subset.
step: `subsets([2])`: its rest is `subsets([])` = `[[]]`. The result is the rest `[[]]` plus `2` added to each: `[[2]]`, so `[[], [2]]`.
step: `subsets([1, 2])`: its rest is `[[], [2]]`. Adding `1` to the front of each gives `[[1], [1, 2]]`.
step: Combine: `[[], [2], [1], [1, 2]]`, four subsets, as expected for $2^2$.
answer: `[[], [2], [1], [1, 2]]`

@mistakes
- Slicing in a recursive binary search (`items[mid + 1:]`), then returning an index relative to the slice instead of the original list.
- Writing the wrong update for the halves: `mid` instead of `mid + 1` or `mid - 1` makes some searches loop forever.
- Using naive recursion for Fibonacci with `n` around 40 and waiting minutes; the repeated work grows exponentially.
- Using a default argument `memo={}` for a cache and leaving values from earlier calls behind; create the dictionary inside the function or use `functools.cache`.

@practice mc
prompt: Why is this function very slow for `n = 40`?

```python
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
```
choice*: It computes the same smaller Fibonacci values over and over, so the number of calls grows exponentially
choice: Python limits recursion to 40 calls, so it has to restart
choice: The function has no base case
choice: Recursive functions are always slower than loops by a factor of about 40
hint: How many times is `fib(2)` computed when you compute `fib(5)`?
solution: The two recursive calls overlap heavily: `fib(n - 1)` itself calls `fib(n - 2)`, and so on, so the same subproblems are recomputed. The call count grows exponentially. Storing results (memoization) makes it linear.

```python
def binary_search(items, target, lo=0, hi=None):
    if hi is None:
        hi = len(items) - 1
    if lo > hi:
        return -1
    mid = (lo + hi) // 2
    if items[mid] == target:
        return mid
    if target < items[mid]:

    return binary_search(items, target, mid + 1, hi)
```

model:
```python
def region_size(grid, r, c):
    value = grid[r][c]
    seen = set()

    def visit(i, j):
        if not (0 <= i < len(grid) and 0 <= j < len(grid[0])):
            return 0
        if (i, j) in seen or grid[i][j] != value:
            return 0
        seen.add((i, j))
        return (1 + visit(i - 1, j) + visit(i + 1, j)
                + visit(i, j - 1) + visit(i, j + 1))

    return visit(r, c)
```
hint: Use a helper function `visit(i, j)` and a set of positions already counted.
hint: `visit` returns `0` for a position outside the grid, already seen, or holding a different value; otherwise it marks the position and adds 1 plus the four neighbor calls.
solution: Marking each position in `seen` before recursing stops the search from going back and forth between neighbors. Every cell of the region is counted exactly once, and cells outside the grid or with another value contribute `0`.

```python
def replay(n, moves):
    pegs = {"A": list(range(n, 0, -1)), "B": [], "C": []}
    for src, dst in moves:
        if not pegs[src]:
            return None
        disk = pegs[src].pop()
        if pegs[dst] and pegs[dst][-1] < disk:
            return None
        pegs[dst].append(disk)
    return pegs
```

model:
```python
def hanoi_moves(n, src, dst, via):
    if n == 0:
        return []
    return (hanoi_moves(n - 1, src, via, dst)
            + [(src, dst)]
            + hanoi_moves(n - 1, via, dst, src))
```
hint: Move `n - 1` disks out of the way, move the biggest disk, then move the `n - 1` disks on top of it.
hint: In the first recursive call the destination is `via`; in the last, the source is `via`. Join the three lists with `+`.
solution: The moves are: (1) `n - 1` disks from `src` to `via`, using `dst` as the spare; (2) the single move `(src, dst)`; (3) `n - 1` disks from `via` to `dst`, using `src` as the spare. The base case `n == 0` has no moves.
