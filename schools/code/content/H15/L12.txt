@article
A Python list keeps its items side by side in one block of memory. That makes `xs[i]` fast, but inserting or deleting at the front forces every other item to shift. A **linked list** takes a different approach: each item lives in its own small object called a **node**, and each node holds a reference to the next node.

```python
class Node:
    def __init__(self, value, next_node=None):
        self.value = value
        self.next = next_node
```

A chain `1 -> 2 -> 3` is built like this:

```python
head = Node(1, Node(2, Node(3)))
```

The variable `head` refers to the first node. The last node's `next` is `None`, which marks the end. To use the list you must start at the head and follow references; there is no way to jump straight to item number 5.

### Traversal

```python
cur = head
while cur is not None:
    print(cur.value)
    cur = cur.next
```

Visiting all `n` nodes takes $O(n)$. Finding the item at position `k` takes $O(k)$, unlike $O(1)$ for a Python list. This is the main trade-off.

### Insertion and removal

- **Insert at the front** is $O(1)$: make a new node whose `next` is the old head, then make it the new head: `head = Node(value, head)`.
- **Remove the front** is $O(1)$: `head = head.next`.
- **Remove a node in the middle**: find the *previous* node `prev` and set `prev.next = prev.next.next`. The removed node is no longer reachable, so Python reclaims it. Finding the previous node costs $O(n)$.

Always handle the special cases: an empty list (`head is None`) and removal of the head itself, which has no previous node.

### A list class

Wrapping the nodes in a class hides the pointer work. A tail reference lets you add at the end in $O(1)$:

```python
class LinkedList:
    def __init__(self):
        self.head = None
        self.tail = None
        self._size = 0

    def append(self, value):
        node = Node(value)
        if self.head is None:
            self.head = node
        else:
            self.tail.next = node
        self.tail = node
        self._size += 1

    def __len__(self):
        return self._size

    def __iter__(self):
        cur = self.head
        while cur is not None:
            yield cur.value
            cur = cur.next
```

Because `__iter__` is a generator, `for x in linked_list` and `list(linked_list)` both work. The class keeps three pieces of state in agreement: `head`, `tail` and `_size`. Most linked-list bugs are one of these getting out of date after an operation, so after each change ask what happens to all three.

### Reversing in place

Reversing walks the chain once and flips each `next` reference, keeping track of the previous node:

```python
prev = None
cur = self.head
while cur is not None:
    nxt = cur.next
    cur.next = prev
    prev = cur
    cur = nxt
```

Save `cur.next` *before* overwriting it, or the rest of the list is lost. Afterwards `prev` is the new head. In the class above, also set `self.tail = self.head` before the loop (the old first node becomes the last), and finish with `self.head = prev`.

### Stacks and queues on linked lists

- A **stack** pushes and pops at the head: both are $O(1)$.
- A **queue** adds at the tail and removes at the head: both are $O(1)$ if you keep a tail reference. Removing from the head when the queue becomes empty must also reset the tail to `None`.

### Linked list or array list?

Use Python's `list` in almost every program: it is compact and fast in practice. Linked lists matter because the *idea*, objects connected by references, is the basis of trees and graphs, and because they give guaranteed $O(1)$ insertion and removal at the head (and insertion at the tail, with a tail reference) without shifting.

@example
title: Removing a node
problem: Remove the node holding `2` from the chain `1 -> 2 -> 3 -> None` and say what traversing prints afterwards.
step: Start with `head` pointing to node `1`. The node before `2` is the node holding `1`.
step: Set `head.next = head.next.next`. The right side is the node holding `3`, so node `1` now points directly to node `3`.
step: Node `2` is no longer referenced by any node or variable, so it is unreachable and is garbage collected.
step: Traversing from `head` visits `1`, then `3`, then reaches `None`, so it prints `1` and `3`.
answer: It prints `1` then `3`.

@example
title: Appending with a tail reference
problem: Why does `append` need a special case for an empty list?
step: In a non-empty list the new node goes after the current tail: `self.tail.next = node`.
step: In an empty list there is no tail node (`self.tail` is `None`), so `self.tail.next` would fail with `AttributeError`.
step: So the empty case instead sets `self.head = node`. In both cases the new node becomes the tail, and the size grows by one.
step: Check with two appends, `1` then `2`: the first sets `head` and `tail` to node 1, the second links node 1 to node 2 and moves `tail` to node 2. Traversal gives `1, 2`.

@mistakes
- Overwriting `cur.next` before saving it when reversing, which loses the rest of the list.
- Forgetting the empty-list and remove-the-head cases, which crash with `AttributeError` on `None`.
- Updating `head` but not `tail`, so after the last item is removed the tail still refers to a deleted node.
- Looping with `while cur.next is not None` and then reading `cur.value` of an empty list, where `cur` itself is `None`.

```python
class Node:
    def __init__(self, value, next_node=None):
        self.value = value
        self.next = next_node


class LinkedStack:
    def __init__(self):
        self._head = None
        self._size = 0

    def push(self, item):
        self._head = Node(item, self._head)
        self._size += 1

    def pop(self):
        if self._head is None:
            raise IndexError("pop from empty stack")
        node = self._head
        self._head = node.next
        self._size -= 1
        return node.value

    def peek(self):
        if self._head is None:
            raise IndexError("peek at empty stack")
        return self._head.value

    def is_empty(self):
        return self._head is None

    def __len__(self):
        return self._size


class LinkedQueue:
    def __init__(self):
        self._head = None
        self._tail = None
        self._size = 0

    def enqueue(self, item):
        node = Node(item)
        if self._tail is None:
            self._head = node
        else:
            self._tail.next = node
        self._tail = node
        self._size += 1

    def dequeue(self):
        if self._head is None:
            raise IndexError("dequeue from empty queue")
        node = self._head
        self._head = node.next
        if self._head is None:
            self._tail = None
        self._size -= 1
        return node.value

    def peek(self):
        if self._head is None:
            raise IndexError("peek at empty queue")
        return self._head.value

    def is_empty(self):
        return self._head is None

    def __len__(self):
        return self._size
```
hint: The stack only touches the head: push puts a new node in front, pop removes the front node.
hint: The queue adds at the tail and removes at the head. When a dequeue empties the queue, set the tail back to `None`, or the next enqueue will link to a node that is gone.
solution: `LinkedStack` pushes and pops at the head. `LinkedQueue` appends at the tail (`self._tail.next = node`) and removes at the head; if the head becomes `None` the tail must also become `None`. The final tests enqueue after emptying, which fails if the tail was left pointing at the old last node.

```python
class Node:
    def __init__(self, value, next_node=None):
        self.value = value
        self.next = next_node


class LinkedList:
    def __init__(self):
        self.head = None
        self.tail = None
        self._size = 0

    def append(self, value):
        node = Node(value)
        if self.head is None:
            self.head = node
        else:
            self.tail.next = node
        self.tail = node
        self._size += 1

    def __len__(self):
        return self._size

    def __iter__(self):
        cur = self.head
        while cur is not None:
            yield cur.value
            cur = cur.next

    def remove(self, value):
        prev = None
        cur = self.head
        while cur is not None:
            if cur.value == value:
                if prev is None:
                    self.head = cur.next
                else:
                    prev.next = cur.next
                if cur is self.tail:
                    self.tail = prev
                self._size -= 1
                return True
            prev = cur
            cur = cur.next
        return False
```
hint: Walk the list keeping both the current node and the previous node.
hint: If the match is the head (no previous node), move `head`; otherwise link `prev.next` past it. If the match was the tail, the tail becomes `prev` (which is `None` when the list becomes empty).
solution: Keep `prev` and `cur`. On a match, bypass `cur` by setting `head` (when `prev is None`) or `prev.next`. If `cur` was the tail, set `tail = prev`. Decrease the size and return `True`; if the loop ends without a match, return `False`. The tests append after removing the last node, which checks that `tail` was repaired.
