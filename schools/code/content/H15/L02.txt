### Instance attributes and `__init__`

An **instance attribute** belongs to one object. It is usually created in `__init__`, so every object starts in a sensible state. Parameters can have defaults, exactly as in ordinary functions:

```python
class Account:
    def __init__(self, owner, balance=0):
        if balance < 0:
            raise ValueError("opening balance cannot be negative")
        self.owner = owner
        self.balance = balance
```

`Account("Ana")` starts with `0`, and `Account("Bo", 50)` starts with `50`. Validating in `__init__` means an object can never exist in an invalid state.

### Two kinds of methods

Some methods **change state** (a *mutator*) and some only **report** it (an *accessor*). Keep the difference clear in your head:

```python
    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("deposit must be positive")
        self.balance += amount

    def is_overdrawn(self):
        return self.balance < 0
```

`deposit` changes the balance and returns nothing. `is_overdrawn` only answers a question. A method may also call another method of the same object through `self`, such as `self.deposit(10)` inside a method named `add_bonus`.

### Raising exceptions for bad requests

When a method cannot do what was asked, raise an exception instead of silently doing something else. A `withdraw` that is asked for more than the balance can raise `ValueError`, and the **object is left unchanged**: check first, then change.

### Class attributes

An attribute assigned directly in the class body, not through `self`, is a **class attribute**. It is shared by all instances:

```python
class Account:
    bank_name = "First Python Bank"   # one copy for the class
    count = 0

    def __init__(self, owner):
        self.owner = owner            # one copy per object
        Account.count += 1
```

`Account.count` is `1` after one account is created, `2` after two. All objects can read `bank_name`. Notice `Account.count += 1`: to change the shared value you name the class. Writing `self.count += 1` would instead create a new instance attribute that hides the class one.

### The shared-list trap

Never use a mutable object (a list or dictionary) as a class attribute when each object needs its own:

```python
class Bad:
    items = []                 # ONE list shared by every Bad

    def add(self, x):
        self.items.append(x)   # modifies the shared list
```

After `a = Bad(); b = Bad(); a.add(1)`, the list `b.items` is also `[1]`. The fix is to create the list in `__init__`: `self.items = []`. The same warning applies to default arguments: `def __init__(self, items=[])` shares one list across all calls. Use `items=None` and create a fresh list inside.

### Designing the state

When writing a class, ask: what does each object need to remember (attributes), and what questions and changes do users need (methods)? A `BankAccount` needs an owner and a balance, and operations to deposit, withdraw and report. Everything else is detail. The deliverable for this block is to write exactly such a class and test it, and the practice items below help you build it.

@example
title: Instance versus class attributes
problem: What does this program print?

```python
class Ticket:
    sold = 0

    def __init__(self, seat):
        self.seat = seat
        Ticket.sold += 1

a = Ticket("A1")
b = Ticket("B7")
print(Ticket.sold, a.sold, a.seat, b.seat)
```
step: `sold` is a class attribute: there is one copy, stored on `Ticket`, starting at `0`.
step: Each `Ticket(...)` call runs `__init__`, which adds 1 to `Ticket.sold`. After two tickets, `sold` is `2`.
step: `a.sold` has no instance attribute of that name, so Python looks in the class and finds the shared `2`.
step: `seat` is an instance attribute, so `a.seat` is `A1` and `b.seat` is `B7`.
answer: `2 2 A1 B7`

@example
title: A method that checks before it changes
problem: Add a `withdraw(amount)` method to `Account` that raises `ValueError` if the amount is not positive or exceeds the balance, and otherwise subtracts it.
step: Reject bad input first, before touching any state:

```python
def withdraw(self, amount):
    if amount <= 0:
        raise ValueError("amount must be positive")
    if amount > self.balance:
        raise ValueError("insufficient funds")
    self.balance -= amount
```
step: Because the checks come before the subtraction, a failed call leaves `balance` exactly as it was.
step: Trace it with `balance = 30`: `withdraw(50)` raises, and the balance is still `30`. Then `withdraw(10)` succeeds and the balance becomes `20`.

@mistakes
- Putting a mutable default such as `items=[]` in a parameter list or a class body, so every object shares one list.
- Changing the balance first and checking afterwards, which leaves the object damaged when the exception is raised.
- Writing `self.count += 1` for a class-wide counter; it creates an instance attribute instead of updating `Class.count`.
- Printing a result inside a method that other code wants to use; return the value and let the caller decide what to do with it.

```python
class Bag:
```

```python
class Bag:
    def __init__(self):
        self.items = []

    def add(self, x):
        self.items.append(x)

    def count(self):

    def contains(self, x):
```

@practice code
prompt: Extend the idea of an account: write a class `Wallet` with `Wallet(cash=0)` storing the cash amount. `spend(amount)` subtracts and returns the new cash if enough is available; otherwise it raises `ValueError` and leaves the cash unchanged. `spend` also raises `ValueError` for an amount that is zero or negative. Also keep a list `history` (a new empty list for every wallet) to which each **successful** spend appends the amount.
starter:
```python
class Wallet:
    pass
```
tests:
```python
w = Wallet(100)
assert w.spend(30) == 70
assert w.spend(70) == 0
assert w.cash == 0
assert w.history == [30, 70]
assert raises(ValueError, w.spend, 1)
assert w.cash == 0
assert w.history == [30, 70]
v = Wallet()
assert v.cash == 0
assert v.history == []
assert raises(ValueError, v.spend, -5)
x = Wallet(10)
assert raises(ValueError, x.spend, 0)
assert x.history == []
```
model:
```python
class Wallet:
    def __init__(self, cash=0):
        self.cash = cash
        self.history = []

    def spend(self, amount):
        if amount <= 0:
            raise ValueError("amount must be positive")
        if amount > self.cash:
            raise ValueError("not enough cash")
        self.cash -= amount
        self.history.append(amount)
        return self.cash
```
hint: Do both checks before changing `cash` or `history`.
hint: A failed spend must not append to `history`, so append only after the subtraction succeeds.
solution: Validate first (`amount <= 0` and `amount > self.cash` both raise), then subtract, record and return the new cash. Creating `history` in `__init__` gives each wallet its own list.
