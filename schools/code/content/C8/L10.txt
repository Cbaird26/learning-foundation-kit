@article
Paging makes every memory reference two: one to read the page table entry and one for the data (more with multi-level tables). Two ideas fix the cost and also let programs use more memory than the machine has.

### The TLB

The **translation lookaside buffer (TLB)** is a small, fast, hardware cache of recent VPN-to-PFN translations. On each reference the hardware first looks in the TLB. A **hit** gives the PFN immediately. A **miss** requires a page table walk (extra memory accesses), after which the translation is cached. The TLB works because of **locality**: **temporal locality** (a recently used item is likely to be used again) and **spatial locality** (nearby items are used together). Walking an array touches the same page many times, so almost every reference after the first on a page hits.

x86 hardware walks the page table itself on a miss; some architectures (such as classic MIPS) trap to the OS, which fills the TLB in software. On a **context switch** the TLB's translations belong to the old process, so the OS either flushes the TLB or tags each entry with an **address-space identifier (ASID)** so that entries of different processes can coexist.

With TLB lookup time $t$, memory access time $m$, hit rate $h$ and a single-level page table, the **effective access time** is

$$\text{EAT} = h\,(t + m) + (1 - h)\,(t + 2m).$$

For $t = 10$ ns, $m = 100$ ns, $h = 0.9$: $0.9 \times 110 + 0.1 \times 210 = 120$ ns.

### Demand paging and page faults

A process's pages need not all be in RAM. A PTE's **present bit** says whether the page is in memory. A reference to a non-present page causes a **page fault**, a trap to the OS, which finds the page on disk (swap space or the program file), picks a free frame, reads the page in, updates the PTE and restarts the instruction. This is **demand paging**: pages are loaded only when used. Disk access takes millions of nanoseconds, so even a tiny fault rate hurts. If a fault costs $f$ ns and happens with probability $p$ per reference, $\text{EAT} = (1-p)\,m + p\,f$. With $m = 100$ ns, $f = 8$ ms $= 8{,}000{,}000$ ns and $p = 0.001$, the EAT is $99.9 + 8000 = 8099.9$ ns: about 81 times slower.

### Page replacement

When RAM is full, a fault requires choosing a **victim** page to evict. If the victim is **dirty** (modified), it must first be written to disk; a clean page can simply be discarded. The goal is to minimize faults. We evaluate policies on a **reference string** (the sequence of page numbers accessed).

- **FIFO:** evict the page that has been resident longest. Simple, but it can evict a heavily used page.
- **LRU (least recently used):** evict the page unused for the longest time, betting that the past predicts the future. LRU is a **stack algorithm**: giving it more frames never increases faults.
- **OPT (optimal, Belady's algorithm):** evict the page whose next use is farthest in the future. It needs knowledge of the future, so it is unimplementable in a real system but is the benchmark against which others are measured.
- **Clock:** an approximation of LRU. Frames are arranged in a circle with a hand. Each page has a reference bit that the hardware sets on use. On a fault, the hand sweeps: if the bit is 1 it is cleared and the hand moves on; the first page with bit 0 is evicted.

**Belady's anomaly:** for FIFO, adding frames can increase the number of faults. On the reference string 1 2 3 4 1 2 5 1 2 3 4 5, FIFO has 9 faults with 3 frames and 10 faults with 4. LRU and OPT never behave this way.

When processes together demand more pages than RAM holds, they fault constantly and the CPU waits for the disk: **thrashing**. The remedy is to give each process enough frames for its **working set** (the pages it currently uses) or to run fewer processes.

@example
title: FIFO versus LRU
problem: Three frames, empty at the start. Reference string 3 1 2 3 4 1 3. Count faults under FIFO and under LRU.
step: References 3, 1, 2 each fault (frames fill with 3, 1, 2). Reference 3 is a hit.
step: Reference 4 faults. FIFO evicts 3, the oldest in memory (frames 1, 2, 4). LRU evicts 1, which has not been used since the earliest (frames 2, 3, 4).
step: FIFO: reference 1 is a hit; reference 3 faults, evicting 1. Total FIFO faults: 3, 1, 2, 4, 3 = 5.
step: LRU: reference 1 faults, evicting 2 (frames 3, 4, 1); reference 3 is a hit. Total LRU faults: 3, 1, 2, 4, 1 = 5.
answer: FIFO 5 faults, LRU 5 faults

@example
title: Effective access time with a TLB
problem: TLB lookup 20 ns, memory access 80 ns, TLB hit rate 95%, single-level page table. Find the EAT.
step: A hit costs one TLB lookup plus one memory access: 20 + 80 = 100 ns.
step: A miss costs a lookup, a page-table access and the data access: 20 + 80 + 80 = 180 ns.
step: EAT = 0.95 × 100 + 0.05 × 180 = 95 + 9 = 104 ns.
answer: 104 ns

@mistakes
- Believing more memory always reduces FIFO faults: Belady's anomaly shows it can increase them.
- Treating OPT as a practical policy: it needs the future reference string and serves as a bound.
- Forgetting that a TLB miss is not a page fault: the page may be in RAM, and the walk simply refills the TLB.
- Ignoring the dirty bit: evicting a dirty page costs a disk write as well as the read of the new page.

model:
```python
from collections import deque


def fifo_faults(refs, frames):
    resident = deque()
    faults = 0
    for page in refs:
        if page in resident:
            continue
        faults += 1
        if len(resident) == frames:
            resident.popleft()
        resident.append(page)
    return faults
```
hint: A queue of resident pages: new pages join at the back, victims leave from the front.
hint: A hit does not change the queue under FIFO.
solution: On a miss, count a fault, evict the oldest page (front of the queue) if memory is full, and append the new page. On a hit nothing changes. The Belady string gives 9 faults with 3 frames and 10 with 4.

model:
```python
def lru_faults(refs, frames):
    resident = []  # least recently used first
    faults = 0
    for page in refs:
        if page in resident:
            resident.remove(page)
        else:
            faults += 1
            if len(resident) == frames:
                resident.pop(0)
        resident.append(page)
    return faults
```
hint: Keep the resident pages in order of last use, oldest first.
hint: On every reference (hit or miss), move the page to the most-recent end; on a miss with full memory, remove the front.
solution: Unlike FIFO, a hit refreshes the page's position, so the list is ordered by recency of use. On a miss with full memory, evict the front (the least recently used). For `[1, 2, 1, 3, 1, 2]` with 2 frames: 1 and 2 fault, the second 1 hits, 3 faults and evicts 2, the next 1 hits, and 2 faults and evicts 3, so there are 4 faults.

model:
```python
def opt_faults(refs, frames):
    resident = []
    faults = 0
    for i, page in enumerate(refs):
        if page in resident:
            continue
        faults += 1
        if len(resident) == frames:
            def next_use(p):
                for j in range(i + 1, len(refs)):
                    if refs[j] == p:
                        return j
                return len(refs)
            resident.remove(max(resident, key=next_use))
        resident.append(page)
    return faults
```
hint: For each resident page, find the position of its next use after the current index.
hint: Evict the page with the largest next-use position; use the length of the string if it never appears again.
solution: On a fault with full memory, scan forward in `refs` to find each resident page's next use and evict the page used farthest away (or never). OPT never does worse than any other policy on the same string.
