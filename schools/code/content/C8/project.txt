material: **Scheduler specification.** Time is an integer number of ticks. A decision is made at time 0 and whenever a job completes or uses up a quantum; jobs that have arrived by that time are added to the ready structure before a preempted job is put back. There is no preemption when a job arrives. If no job is ready, the CPU idles until the next arrival. Policies:

- `fifo`: run jobs to completion in order of arrival.
- `sjf`: non-preemptive; among arrived jobs choose the smallest burst, with ties broken by earlier arrival.
- `rr`: quantum 3 by default; a job runs for `min(quantum, remaining)`, and if unfinished goes to the back of the queue.
- `mlfq`: three queues with quanta 2, 4 and 8 (queue 0 has the highest priority); new jobs enter queue 0; the front job of the highest non-empty queue runs for `min(quantum of its queue, remaining)`; if unfinished it moves to the back of the next lower queue (the lowest queue stays the lowest); no priority boost and no I/O.

Turnaround is completion minus arrival, response is first-run minus arrival, and waiting is turnaround minus burst.

## Week-by-week key ideas

1. **Processes and the kernel.** The OS virtualizes the CPU and memory and manages resources. Limited direct execution uses user and kernel mode, system calls through the trap table, and the timer interrupt. A process is ready, running or blocked; a context switch saves and restores registers.
2. **Process API.** `fork` returns 0 in the child and the child's PID in the parent; `exec` replaces the program; `wait` collects the exit status. Process trees from repeated `fork` have $2^n$ processes. Shell redirection works by rearranging descriptors between `fork` and `exec`.
3. **Scheduling.** Turnaround is completion minus arrival; response is first run minus arrival. FIFO has the convoy effect; SJF minimizes average turnaround when all jobs arrive together and STCF when they arrive at different times (both need job lengths in advance); round robin helps response, MLFQ learns behavior with its five rules, lottery gives proportional share.
4. **Threads.** Threads share the address space and have private stacks and registers. Interleavings explain nondeterminism: $\binom{m+n}{m}$ for two threads.
5. **Locks.** `counter++` is load, add, store; a critical section needs mutual exclusion. Test-and-set, compare-and-swap and ticket locks differ in fairness and cost.
6. **Condition variables and semaphores.** Always `while` around `wait`; a semaphore initialized to 1 is a lock, to 0 an ordering signal, to $N$ a resource count. Fix lost update, check-then-act and lazy-initialization races with one lock around the whole sequence.
7. **Classic problems.** Bounded buffer: `empty = MAX`, `full = 0`, `mutex = 1`, with the counting semaphore taken before the mutex. Readers-writers and dining philosophers; atomicity and order violations.
8. **Deadlock.** Four conditions; prevention (lock ordering, trylock), avoidance (banker's algorithm and safe states), detection (cycle in the wait-for graph).
9. **Address spaces and paging.** VPN and offset, page tables, PTE bits, multi-level tables, internal fragmentation.
10. **Virtual memory.** TLB and effective access time, page faults, FIFO, LRU, OPT and Clock, Belady's anomaly, thrashing.
11. **Storage and file systems.** Disk time is seek plus rotation plus transfer; SSDs erase blocks and use a flash translation layer; inodes, bitmaps, directories and multi-level pointers; path lookup costs $1 + 2k$ reads.
12. **Crash consistency, protection, virtualization.** Journaling (write the journal, commit, checkpoint, free) and replay; permission bits (owner, group, other); hypervisors versus containers.

## Common errors

- Forgetting that `fork` returns twice and that the parent and child continue from the same point.
- Computing turnaround from time 0 rather than from arrival.
- Using `if` instead of `while` with a condition variable.
- Taking the mutex before the counting semaphore in the bounded buffer.
- Treating an unsafe state as a deadlock.
- Mixing up pages and frames, or forgetting that the offset is copied unchanged.
- Updating LRU recency only on faults, not on hits.
- Using the full rotation instead of half a rotation for average rotational delay.

prompt: Write `clock_faults(refs, frames)` that returns the number of page faults for the reference string `refs` (a list of page numbers) using the Clock algorithm with `frames` frames (at least 1) and empty memory at the start. The frames form a circle and a hand starts at frame 0. Each frame has a reference bit. A hit sets the page's bit to 1. On a fault, while the frame under the hand is occupied and its bit is 1, clear the bit and advance the hand; then load the new page into that frame, set its bit to 1, and advance the hand.
starter:
```python
def clock_faults(refs, frames):

```
tests:
```python
assert clock_faults([], 2) == 0
assert clock_faults([5, 5, 5], 1) == 1
assert clock_faults([1, 2, 3, 1, 4, 5, 1, 2], 3) == 7
assert clock_faults([1, 2, 1, 3, 1, 4], 2) == 5
assert clock_faults([1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5], 3) == 9
assert clock_faults(list(range(10)), 4) == 10
```
model:
```python
def clock_faults(refs, frames):
    slots = [None] * frames
    bits = [0] * frames
    hand = 0
    faults = 0
    for page in refs:
        if page in slots:
            bits[slots.index(page)] = 1
            continue
        faults += 1
        while slots[hand] is not None and bits[hand] == 1:
            bits[hand] = 0
            hand = (hand + 1) % frames
        slots[hand] = page
        bits[hand] = 1
        hand = (hand + 1) % frames
    return faults
```
hint: Keep two parallel lists, the page in each frame and its reference bit, and an index `hand`.
hint: The sweep loop ends at the first frame that is empty or has bit 0; that frame receives the new page.
solution: A hit only sets a bit. A fault sweeps from the hand, clearing bits of recently used pages (second chance) until it finds an empty frame or one with bit 0, loads the page there, sets its bit and advances. Because a newly loaded page has bit 1 and the sweep clears bits as it goes, the loop always terminates within one extra turn of the circle.

prompt: A system uses a two-level page table, so a TLB miss costs two page-table accesses before the data access. The TLB lookup takes 10 ns, a memory access takes 100 ns, and the TLB hit rate is 95%. What is the effective access time in ns?
answer: 120
check: 0.95 * (10 + 100) + 0.05 * (10 + 2 * 100 + 100)
tol: 0.01
unit: ns
hint: A hit costs lookup plus data access; a miss costs lookup plus two table accesses plus the data access.
solution: A hit costs $10 + 100 = 110$ ns and a miss costs $10 + 200 + 100 = 310$ ns, so the EAT is $0.95 \times 110 + 0.05 \times 310 = 104.5 + 15.5 = 120$ ns.

@exam self
prompt: A web server accepts connections in one thread and hands each to a pool of worker threads through a bounded queue of capacity 16. Design the synchronization of the queue, and answer: (a) which primitives you use, with initial values; (b) what deadlock you avoid by the order of operations; (c) how the scheduler's policy affects the latency of a short request that arrives while workers are busy with long ones; (d) what happens to the server's memory behavior if the number of workers is too large for the machine's RAM.
solution: (a) Use a mutex (or semaphore initialized to 1) to protect the queue's indexes, a semaphore `empty` initialized to 16 that counts free slots, and a semaphore `full` initialized to 0 that counts queued connections. The acceptor does `wait(empty)`, `wait(mutex)`, enqueue, `post(mutex)`, `post(full)`; a worker does `wait(full)`, `wait(mutex)`, dequeue, `post(mutex)`, `post(empty)`. (b) Waiting on the counting semaphore before taking the mutex means no thread sleeps while holding the mutex; if the acceptor took the mutex first and then blocked on a full queue, workers could not dequeue and the system would deadlock (hold-and-wait with circular wait). (c) With a policy such as FIFO or a long round-robin quantum, a short request waits behind long ones (convoy effect), so its response time is poor; a scheduler that favors short or interactive work (MLFQ or shortest-first) or a smaller quantum gives faster response at the cost of more context switches, and a bounded queue limits how long the backlog can grow. (d) If the workers' combined working sets exceed RAM, pages are evicted and constantly faulted back in: thrashing, with the CPU mostly waiting on the disk. The fix is a smaller pool sized to the available memory and cores.
hint: Start from the bounded buffer, then think about which operation order could block while holding a lock.
hint: For (c) and (d), name the effect (convoy effect, thrashing) and the remedy.
