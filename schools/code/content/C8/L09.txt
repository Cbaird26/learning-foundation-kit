@article
Early systems loaded one program into memory at a time. Sharing memory between programs safely needs an abstraction: the **address space**, the program's private view of memory. Inside it live the program's **code**, its **heap** (dynamically allocated data, growing toward higher addresses) and its **stack** (function frames, growing toward lower addresses). The addresses the program uses are **virtual addresses**; the OS and hardware translate them to **physical addresses** in RAM on every memory reference. This gives three goals: **transparency** (the program thinks it has the whole machine), **efficiency** and **protection** (a process cannot touch another's memory or the kernel's).

### From base and bounds to paging

The simplest scheme gives each process a **base** register and a **bounds** register: physical address = virtual address + base, and any address beyond the bounds raises an exception. It wastes the space between heap and stack and requires the whole address space to be contiguous in RAM. **Segmentation** uses one base and bounds per segment (code, heap, stack), but still suffers from **external fragmentation**: free memory splits into pieces too small to use.

**Paging** removes this problem by dividing the virtual address space into fixed-size **pages** and physical memory into **frames** of the same size. Any page can go into any frame, so a free frame is always usable. A per-process **page table** records where each page lives.

### Translating an address

Let the page size be $2^k$ bytes (commonly 4 KB, so $k = 12$). A virtual address splits into two parts:

- the **virtual page number (VPN)**: the high bits, `vaddr >> k`;
- the **offset**: the low $k$ bits, `vaddr & (2**k - 1)`.

The page table maps the VPN to a **page frame number (PFN)**. The physical address is the PFN followed by the unchanged offset: `paddr = (pfn << k) | offset`. A **page table entry (PTE)** holds the PFN and control bits: **valid** (is this page mapped at all), **present** (is it in RAM or swapped out), **protection** bits (read, write, execute), a **user/supervisor** bit, a **dirty** bit (modified since loaded) and a **reference/accessed** bit (used recently). Accessing an invalid page or violating protection traps to the OS, which typically kills the process with a segmentation fault.

For a 32-bit virtual address and 4 KB pages, the VPN has $32 - 12 = 20$ bits, so a **linear** page table has $2^{20}$ entries. With 4-byte PTEs that is $2^{20} \times 4 = 4$ MB **per process**, mostly for pages the process never uses.

### Multi-level page tables

A **multi-level page table** pages the page table itself: the VPN is split into a **page directory index** and a **page table index**. Only the second-level tables that contain valid entries are allocated; entries in the directory for unused regions are marked invalid. With 4 KB pages and 4-byte PTEs, one page holds $4096/4 = 1024$ entries, so a 32-bit address splits as 10 bits (directory), 10 bits (page table) and 12 bits (offset). The cost is an extra memory access during translation, which the TLB (next week) hides. 64-bit x86 uses four levels with 8-byte entries: each 4 KB table holds 512 entries, so each level indexes with 9 bits, and with the 12-bit offset the usable virtual address is 48 bits; a fifth level extends it to 57 bits.

### Fragmentation

Paging has no external fragmentation, but a process rarely fills its last page. This **internal fragmentation** averages half a page per region. A 10,000-byte region with 4,096-byte pages needs 3 pages (12,288 bytes), wasting $12288 - 10000 = 2288$ bytes. Larger pages mean smaller tables and fewer TLB misses but more internal fragmentation.

@example
title: Translating one address
problem: 4 KB pages. The page table maps VPN 3 to PFN 0x1F. Translate the virtual address 0x00003A7C.
step: The offset is the low 12 bits (three hex digits): 0xA7C. The rest is the VPN: 0x00003A7C >> 12 = 3.
step: Look up VPN 3: the PFN is 0x1F.
step: Physical address = (0x1F << 12) | 0xA7C. Shifting by 12 bits adds three hex zeros, giving 0x1F000, and OR-ing the offset gives 0x1FA7C.
answer: 0x1FA7C

@example
title: A two-level walk
problem: 32-bit addresses, 4 KB pages, 10-bit directory index, 10-bit table index. Split the virtual address 0x00403123.
step: Offset: the low 12 bits of 0x00403123 are 0x123.
step: Shift right by 12: 0x00403. The table index is its low 10 bits: 0x403 AND 0x3FF = 0x003 = 3.
step: The directory index is the remaining high bits: 0x403 >> 10 = 1.
step: The hardware reads directory entry 1, finds the second-level table, reads its entry 3 for the PFN, and appends the offset 0x123. If either entry is invalid, the access faults.
answer: directory 1, table 3, offset 0x123

@mistakes
- Adding the offset to the page number instead of concatenating it: the offset passes through unchanged.
- Forgetting that the page table is per process and that the size of a linear table depends on the whole virtual address space, not on how much memory the process uses.
- Mixing up pages (virtual) and frames (physical).
- Saying paging eliminates all fragmentation: it removes external fragmentation but causes internal fragmentation.

model:
```python
def translate(vaddr, page_table, page_size):
    vpn = vaddr // page_size
    offset = vaddr % page_size
    if vpn >= len(page_table) or page_table[vpn] is None:
        raise ValueError("page fault")
    return page_table[vpn] * page_size + offset
```
hint: `vaddr // page_size` is the page number and `vaddr % page_size` is the offset.

solution: Split the address into VPN and offset with division and remainder, validate the entry, then compute `frame * page_size + offset`. With power-of-two sizes this is the same as shifting and masking.

model:
```python
def translate2(vaddr, directory):
    offset = vaddr & 0xFFF
    table_index = (vaddr >> 12) & 0x3FF
    dir_index = (vaddr >> 22) & 0x3FF
    table = directory.get(dir_index)
    if table is None or table_index not in table:
        raise ValueError("page fault")
    return (table[table_index] << 12) | offset
```
hint: Mask and shift: offset is the low 12 bits, the table index the next 10, the directory index the top 10.
solution: Extract the three fields with shifts and masks, look up the second-level table in the directory, then the frame in that table, and finally append the 12-bit offset. A missing entry at either level is a fault.

@practice self
prompt: Explain why a two-level page table usually uses much less memory than a linear one for a typical process, and give the memory a linear table needs for a 32-bit address space with 4 KB pages and 4-byte entries. State one cost of the two-level scheme.
solution: A linear table must have an entry for every virtual page, here $2^{20}$ entries of 4 bytes, which is 4 MB for every process, even though a typical process uses only a small part of its address space (code and data near the bottom, stack near the top, and a huge unused gap between them). In a two-level table, the directory has 1024 entries, and a second-level table (one 4 KB page of 1024 entries) is allocated only for directory entries whose region contains valid pages; the unused gap needs no second-level tables. A small process may need just the directory plus two or three tables: a few tens of KB. The cost is that translation needs an additional memory access (one per level), which is why the TLB matters.
hint: Ask which parts of the address space need table entries in each scheme.
rubric: Computes the linear table size: $2^{20} \times 4$ bytes = 4 MB.
rubric: Explains that second-level tables are allocated only for regions in use, so the unused gap costs almost nothing.
rubric: States a cost, such as extra memory accesses per translation (mitigated by the TLB).

def split_address(vaddr, offset_bits):
