@article
Exact distributions are often hard to compute, but we frequently need only a guarantee: "the chance this algorithm takes more than ten times its expected time is at most 10%". **Tail bounds** give such guarantees from very little information.

### Markov's inequality

If $X \ge 0$ and $a > 0$, then

$$P(X \ge a) \le \frac{E[X]}{a}.$$

*Why:* $a \cdot I_{\{X \ge a\}} \le X$ pointwise because $X$ is non-negative, and taking expectations gives $a\,P(X \ge a) \le E[X]$. The condition $X \ge 0$ is essential. Markov uses only the mean, so it is weak but universal: a non-negative variable with mean $200$ exceeds $1000$ with probability at most $200/1000 = 0.2$.

### Chebyshev's inequality

If $X$ has mean $\mu$ and variance $\sigma^2$, then for every $a > 0$,

$$P\big(|X - \mu| \ge a\big) \le \frac{\sigma^2}{a^2}.$$

*Why:* apply Markov to the non-negative variable $(X - \mu)^2$ with threshold $a^2$. In terms of standard deviations, the probability of being at least $k\sigma$ from the mean is at most $1/k^2$, for any distribution with finite variance. Chebyshev also proves the weak law of large numbers: for $\bar X_n$, $P(|\bar X_n - \mu| \ge \varepsilon) \le \sigma^2/(n\varepsilon^2) \to 0$.

### The union bound

For any events $A_1, \dots, A_m$ (independent or not),

$$P\Big(\bigcup_{i=1}^m A_i\Big) \le \sum_{i=1}^m P(A_i).$$

It is the cheapest way to bound the probability that *something* goes wrong. If $n$ keys are hashed into $m$ slots, there are $\binom{n}{2}$ pairs, each colliding with probability $1/m$, so $P(\text{any collision}) \le \binom{n}{2}/m$. With $m = n^2$ this is below $1/2$.

### Chernoff bounds

When $X$ is a **sum of independent Bernoulli variables** (the success probabilities may differ), with $\mu = E[X]$, its tails are exponentially small, far better than Chebyshev's polynomial bound. For $\delta > 0$,

$$P\big(X \ge (1 + \delta)\mu\big) \le \exp\!\left(-\frac{\delta^2 \mu}{2 + \delta}\right),$$

and for $0 < \delta < 1$,

$$P\big(X \le (1 - \delta)\mu\big) \le \exp\!\left(-\frac{\delta^2 \mu}{2}\right).$$

These come from applying Markov to $e^{tX}$ and optimizing over $t$. The independence assumption matters: it lets the expectation of $e^{tX}$ factor into a product.

### Repeating randomized algorithms

Suppose a randomized algorithm with **one-sided error** answers wrongly with probability at most $\varepsilon$ on each independent run, and a wrong answer can be detected by comparing runs in one direction (for instance a primality-style test that never errs on a prime). Running it $k$ times independently and combining the results fails with probability at most $\varepsilon^k$: the failure probability decays exponentially in the work. With $\varepsilon = 1/2$, twenty runs give failure probability below one in a million.

@example
title: Markov versus Chebyshev
problem: A server's response time $X$ in milliseconds has mean 200 and standard deviation 50. Bound $P(X \ge 1000)$ with Markov, and bound $P(|X - 200| \ge 100)$ with Chebyshev.
step: Response times are non-negative, so Markov applies: $P(X \ge 1000) \le 200/1000 = 1/5$.
step: Chebyshev with $\sigma^2 = 2500$ and $a = 100$ gives $P(|X - 200| \ge 100) \le 2500/10000 = 1/4$.
step: Both bounds are guaranteed for every distribution with these moments, which is why they are loose for any particular one.
answer: Markov: $1/5$; Chebyshev: $1/4$

@example
title: Chernoff versus Chebyshev for coin tosses
problem: A fair coin is tossed 1000 times. Bound the probability of at least 600 heads using Chebyshev and using the Chernoff bound.
step: $X \sim \mathrm{Binomial}(1000, 1/2)$ has $\mu = 500$ and $\mathrm{Var}(X) = 250$. We need $P(X \ge 600)$, so $\delta = 0.2$.
step: Chebyshev: $P(X \ge 600) \le P(|X - 500| \ge 100) \le 250/100^2 = 0.025$.
step: Chernoff: $P(X \ge 600) \le \exp\!\big(-\frac{0.2^2 \cdot 500}{2.2}\big) = \exp(-9.09) \approx 1.1 \times 10^{-4}$.
step: Chernoff is more than 200 times smaller, and the gap grows exponentially as the number of tosses increases.
answer: Chebyshev: $0.025$; Chernoff: about $1.1 \times 10^{-4}$

@mistakes
- Applying Markov's inequality to a variable that can be negative.
- Using Chebyshev's bound with the variance instead of $\sigma^2/a^2$ (dividing by $a$ instead of $a^2$), or forgetting that it bounds the two-sided deviation.
- Applying a Chernoff bound to dependent variables, or confusing the upper-tail and lower-tail forms.
- Multiplying failure probabilities of repeated runs that are not independent.

@practice mc
prompt: Which application of Markov's inequality is valid?
choice*: A non-negative variable with mean 8 satisfies $P(X \ge 16) \le 1/2$.
choice: A temperature in degrees Celsius with mean 8 satisfies $P(X \ge 16) \le 1/2$, since the inequality works for any variable.
choice: A non-negative variable with mean 8 satisfies $P(X \ge 16) \ge 1/2$.
hint: Markov's inequality needs non-negativity and gives an upper bound.
solution: Markov gives $P(X \ge a) \le E[X]/a$ only for non-negative variables: $8/16 = 1/2$. A temperature can be negative, so the inequality is not guaranteed, and Markov never gives a lower bound.

@practice code
prompt: A randomized algorithm errs on each independent run with probability `err` (with $0 <$ `err` $< 1$), and the failure probability after `k` runs is bounded by `err ** k`. Write `min_repetitions(err, target)` that returns the smallest integer `k >= 1` with `err ** k <= target`, where $0 <$ `target` $< 1$. Use a loop that multiplies a running bound by `err`.
starter:
```python
def min_repetitions(err, target):
    pass
```
tests:
```python
assert min_repetitions(0.5, 1 / 1024) == 10
assert min_repetitions(0.5, 0.3) == 2
assert min_repetitions(0.5, 0.5) == 1
assert min_repetitions(0.5, 0.01) == 7
assert min_repetitions(0.25, 0.25 ** 5) == 5
assert min_repetitions(0.25, 0.9) == 1
```
model:
```python
def min_repetitions(err, target):
    k = 1
    bound = err
    while bound > target:
        bound *= err
        k += 1
    return k
```
hint: Start with one run (`k = 1`, bound `err`) and keep multiplying while the bound is still above `target`.
hint: Use `while bound > target:` so that a bound exactly equal to `target` is accepted.
solution: Multiply the bound by `err` once for each additional run until it is at most `target`, counting runs. For `err = 0.5` and `target = 0.01`, the bounds are $0.5, 0.25, \dots, 1/128 \approx 0.0078$, so $7$ runs suffice.
