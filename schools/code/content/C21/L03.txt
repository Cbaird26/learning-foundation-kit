@article
Physical clocks on different machines drift and can be synchronized only to within some error (protocols such as NTP achieve milliseconds on a good network). So we cannot reliably order events on different machines by wall-clock time. What we can observe is **causality**: a message must be sent before it is received.

### Happened-before

The **happened-before** relation $a \to b$ is the smallest relation such that:

1. If $a$ and $b$ are events in the same process and $a$ occurs before $b$, then $a \to b$.
2. If $a$ is the sending of a message and $b$ is its receipt, then $a \to b$.
3. If $a \to b$ and $b \to c$, then $a \to c$ (transitivity).

Two events with neither $a \to b$ nor $b \to a$ are **concurrent**, written $a \parallel b$. Concurrent does not mean simultaneous; it means no chain of messages connects them, so neither could have influenced the other.

### Lamport clocks

Each process keeps an integer counter $C$, initially 0.

- **Local event or send:** $C \leftarrow C + 1$. A send carries the new value as the message's timestamp $t$.
- **Receive** a message with timestamp $t$: $C \leftarrow \max(C, t) + 1$.

The event's timestamp is the value of $C$ right after the event.

**Guarantee (clock condition):** if $a \to b$ then $L(a) < L(b)$. **The converse is false**: $L(a) < L(b)$ does not imply $a \to b$. Two concurrent events can get any ordering of timestamps, and can even be equal. To break ties and get a *total* order consistent with causality, order by the pair $(L, \text{process id})$. This total order is the basis of Lamport's mutual exclusion algorithm and of replicated logs.

```python
class LamportClock:
    def __init__(self):
        self.time = 0

    def tick(self):                  # local event or send
        self.time += 1
        return self.time

    def receive(self, ts):
        self.time = max(self.time, ts) + 1
        return self.time
```

### Vector clocks

To *detect* concurrency we need more information. In a system of $n$ processes, each process $i$ keeps a vector $V$ of $n$ counters, initially all 0.

- **Local event or send:** $V[i] \leftarrow V[i] + 1$ (a send carries a copy of $V$).
- **Receive** a message carrying $W$: first $V[k] \leftarrow \max(V[k], W[k])$ for every $k$, then $V[i] \leftarrow V[i] + 1$.

Compare vectors componentwise: $V \le W$ if $V[k] \le W[k]$ for all $k$, and $V < W$ if $V \le W$ and $V \ne W$. Then:

$$a \to b \iff V(a) < V(b), \qquad a \parallel b \iff V(a) \not< V(b) \text{ and } V(b) \not< V(a).$$

Vector clocks therefore characterize causality exactly, at the cost of $n$ integers per message. Systems use them (or close relatives such as version vectors) to detect conflicting concurrent updates to a replicated object.

@example
title: Lamport timestamps for a trace
problem: P1 does a local event a, sends message m to P2 (event b), then does a local event c. P2 does a local event d, receives m (event e), then sends message n to P1 (event f). P1 then receives n (event g). Give every Lamport timestamp.
step: P1: a gets 1, the send b gets 2 (and carries timestamp 2), c gets 3.
step: P2: d gets 1. The receive e of m (timestamp 2) gets $\max(1, 2) + 1 = 3$.
step: The send f gets 4 and carries 4.
step: P1 receives n at event g: $\max(3, 4) + 1 = 5$.
step: Result: a=1, b=2, c=3, d=1, e=3, f=4, g=5. Note d=1 and a=1 are equal even though a and d are concurrent.
answer: a=1, b=2, c=3, d=1, e=3, f=4, g=5

@example
title: Vector clocks and concurrency
problem: Three processes P0, P1, P2 use vectors $[v_0, v_1, v_2]$. P0 does a local event x, then sends a message to P1 (event y). P1 receives it (event z). Meanwhile P2 does a local event w. Compare x with z and w with z.
step: P0: x is $[1,0,0]$; the send y is $[2,0,0]$ and carries that vector.
step: P1 starts at $[0,0,0]$. At the receive z: componentwise max with $[2,0,0]$ gives $[2,0,0]$, then increment its own entry: $[2,1,0]$.
step: P2: w is $[0,0,1]$.
step: $x = [1,0,0] < z = [2,1,0]$ componentwise, so $x \to z$.
step: $w = [0,0,1]$ and $z = [2,1,0]$: $w[2] = 1 > 0$ but $w[0] = 0 < 2$, so neither is smaller and $w \parallel z$.

@mistakes
- Concluding $a \to b$ from $L(a) < L(b)$; Lamport timestamps only guarantee the opposite direction.
- Forgetting to take the maximum before incrementing on a receive, or incrementing only when sending.
- Treating "concurrent" as "at the same physical time"; it means causally unrelated.
- In a vector clock, comparing only one component instead of all of them.

```python
class LamportClock:
    def __init__(self):
        self.time = 0

    def tick(self):
```

model:
```python
def compare(a, b):
    if a == b:
        return "equal"
    if all(x <= y for x, y in zip(a, b)):
        return "before"
    if all(x >= y for x, y in zip(a, b)):
        return "after"
    return "concurrent"
```
hint: Handle equality first, then test "every entry less than or equal".
hint: Use `all(x <= y for x, y in zip(a, b))` for "before", the mirror test for "after", and call everything else concurrent.
solution: After excluding equal vectors, `a` is before `b` exactly when all entries of `a` are at most those of `b`; the mirror condition gives "after"; if neither holds, some entry is larger on each side, so the events are concurrent.

@quiz ms
prompt: Which statements about logical clocks are true?
choice*: If $a \to b$, then the Lamport timestamp of $a$ is smaller than that of $b$.
choice: If the Lamport timestamp of $a$ is smaller than that of $b$, then $a \to b$.

solution: Lamport timestamps respect causality in one direction only, so a smaller timestamp does not imply happened-before, and concurrent events may have equal timestamps.
