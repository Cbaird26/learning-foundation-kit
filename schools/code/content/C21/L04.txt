@article
Many distributed tasks need one process at a time to hold a resource (**mutual exclusion**) or need one process designated to coordinate (a **leader**). With no shared memory and no shared clock, both are solved by exchanging messages.

### Requirements for mutual exclusion

- **Safety:** at most one process is in the critical section at any time.
- **Liveness:** every request is eventually granted (no deadlock, no starvation).
- **Fairness (ordering):** requests are granted in the order they were made, usually defined by happened-before or Lamport order.

### Algorithms

**Centralized.** One coordinator holds a queue. A process sends REQUEST, receives GRANT, and later sends RELEASE: **3 messages** per entry. It is simple and fair, but the coordinator is a single point of failure and a bottleneck.

**Ricart-Agrawala (distributed).** To enter, process $P_i$ timestamps a request with a Lamport clock value and sends REQUEST$(t_i, i)$ to the other $N-1$ processes; it enters after receiving a REPLY from all of them. A process that receives a request answers as follows:

- if it is in the critical section (HELD), it **defers** the reply until it leaves;
- if it does not want the section (RELEASED), it replies immediately;
- if it also wants the section (WANTED), it compares timestamps as pairs $(t, \text{id})$: the **smaller pair wins**. It replies immediately if the other request is smaller, and defers if its own is smaller.

Cost: $N-1$ requests plus $N-1$ replies, so **$2(N-1)$ messages** per entry. Ties between equal timestamps are broken by process id, which makes the order total. The price is that all $N$ processes must be alive: one crashed process that never replies blocks everyone.

**Token ring.** Processes form a logical ring and pass a unique token; only the holder may enter. Cost per entry ranges from 0 to $N-1$ messages, and the token circulates even when nobody wants it. Losing the token (a crashed holder) requires detection and regeneration.

### Leader election

Election algorithms pick one process, normally the one with the highest id, and tell everyone.

**Bully algorithm.** A process $P$ that notices the leader is gone sends ELECTION to all processes with *higher* ids. If none answers, $P$ wins and sends COORDINATOR to all. If a higher process answers OK, $P$ stops, and that process starts its own election. The highest-id live process always ends up as leader (it "bullies" the others).

**Ring election (Chang-Roberts).** Processes are in a ring and each sends its id clockwise. A process receiving id $x$ forwards it if $x$ is larger than its own id, discards it if smaller, and declares itself leader if $x$ equals its own id (the message went all the way around). If all processes start simultaneously, the number of election messages is between $2N-1$ and $N(N+1)/2$ for $N$ distinct ids: the best case has ids increasing in the direction of travel, the worst case ids decreasing.

```python
def hops(ids, i):
    """Messages caused by the id at ring position i."""
    n = len(ids)
    for k in range(1, n + 1):
        j = (i + k) % n
        if ids[j] > ids[i] or k == n:
            return k
```

In real systems, leaders are usually chosen with a consensus-based coordination service and a **lease** (a leadership grant that expires unless renewed), which handles the delayed-message and partition cases that simple election algorithms ignore (Lessons 7 and 8).

@example
title: Ricart-Agrawala conflict
problem: Processes P1 and P2 both want the critical section. P1's request is $(5, 1)$ and P2's request is $(5, 2)$. Each receives the other's request while WANTED. Who enters first, and who defers?
step: Compare the pairs: $(5, 1) < (5, 2)$ because the timestamps tie and 1 < 2, so P1's request wins.
step: P2 receives $(5, 1)$ from P1: P1's request is smaller than P2's own, so P2 replies immediately.
step: P1 receives $(5, 2)$ from P2: P2's request is larger than its own, so P1 defers its reply.
step: P1 has all replies and enters. When P1 leaves, it sends the deferred reply, and P2 enters.
answer: P1 enters first; P2 waits for the deferred reply

@example
title: Ring election message count
problem: Six processes sit on a ring in the order of travel with ids 4, 6, 2, 5, 1, 3. All start an election at once. How many election messages are sent (not counting the final announcement)?
step: Each id travels clockwise until it reaches a process with a larger id (discarded there, counting that last hop), or goes all the way around.
step: 4 goes to 6: 1 message. 6 passes 2, 5, 1, 3, 4 and returns to itself: 6 messages.
step: 2 goes to 5: 1. 5 goes to 1 (smaller, forwarded), 3 (smaller, forwarded), 4 (smaller, forwarded), then 6 (larger, discarded): 4 messages.
step: 1 goes to 3: 1. 3 goes to 4: 1.
step: Total: $1 + 6 + 1 + 4 + 1 + 1 = 14$. The elected leader is 6.
answer: 14

@mistakes
- Granting access to a process that holds a smaller Lamport timestamp than your own pending request, or ignoring the process-id tie-breaker.
- Counting Ricart-Agrawala cost as $N$ instead of $2(N-1)$, or forgetting that a crashed participant blocks it.
- Thinking the bully algorithm lets a lower-id process win: the highest-id live process always wins.
- Assuming simple election algorithms handle network partitions; they can elect two leaders, one per side.

tests:
```python
assert ring_messages([3, 1, 2]) == 5
assert ring_messages([1, 2, 3]) == 5
assert ring_messages([3, 2, 1]) == 6
assert ring_messages([4, 6, 2, 5, 1, 3]) == 14
```

model:
```python
def ring_messages(ids):
    n = len(ids)
    total = 0
    for i in range(n):
        for k in range(1, n + 1):
            j = (i + k) % n
            if ids[j] > ids[i] or k == n:
                total += k
                break
    return total
```
hint: For each position, walk clockwise and count hops until you meet a larger id.
hint: Use `(i + k) % n` for the position `k` steps ahead. The largest id never meets a larger one, so stop at `k == n`.
solution: For each starting position, count steps until a larger id is found, capped at `n` for the maximum. Summing gives the total; descending ids give $n(n+1)/2$ messages, for example 15 for five processes.

```python
def token_ring_order(n, holder, wanting):
    order = []
    for k in range(n):
```
