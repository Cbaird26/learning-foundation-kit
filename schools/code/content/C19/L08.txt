@article
A single deep tree has high variance; a single shallow tree has high bias. **Ensembles** combine many trees to fix either problem. The two main families work in opposite ways.

### Bagging

**Bagging** (bootstrap aggregating) trains each model on a **bootstrap sample**: $n$ examples drawn **with replacement** from the $n$ training examples. The models' predictions are averaged (regression) or voted (classification). A given example is missing from a bootstrap sample with probability $(1 - 1/n)^n$, which tends to $e^{-1} \approx 0.368$. So each model sees about 63.2% of the distinct examples and the rest are its **out-of-bag (OOB)** examples. Scoring each example only with the models that did not see it gives the **OOB error**, a cross-validation-like estimate that costs no extra training.

Why does averaging help? Suppose $B$ models each have prediction variance $\sigma^2$ and pairwise correlation $\rho$. Their average has variance
$$\rho\,\sigma^2 + \frac{1 - \rho}{B}\,\sigma^2.$$
The second term vanishes as $B$ grows, but the first does not: **correlated models cannot average away their shared error**. Averaging leaves bias unchanged, so bagging suits low-bias, high-variance learners such as deep trees.

### Random forests

Bagged trees are correlated because a few strong features dominate the top splits in every tree. A **random forest** adds a second source of randomness: at each split only a random subset of $m$ of the $d$ features may be considered (the classic recommendations are $m \approx \sqrt{d}$ for classification and $d/3$ for regression; libraries differ, and scikit-learn's regression forests consider all features by default). Weaker features then get used, the trees disagree more, $\rho$ falls, and the average improves. Adding more trees never causes overfitting by itself, it only reduces the second variance term, though it costs time. Forests also give **feature importance** scores (for example the total impurity decrease contributed by each feature), which should be read with care when features are correlated.

### Boosting

**Boosting** builds the ensemble sequentially, each new model correcting the errors of the current one, and its aim is to reduce bias with **weak learners** (shallow trees, often depth 1 to 4). In **gradient boosting** with squared error:

1. Start with the constant model $F_0(x) = \bar{y}$.
2. For $m = 1, \dots, M$: compute the residuals $r_i = y_i - F_{m-1}(x_i)$, fit a small tree $h_m$ to the residuals, and set $F_m = F_{m-1} + \nu\,h_m$.

The **learning rate** (shrinkage) $\nu \in (0, 1]$ makes each step cautious. For squared error the residuals are the negative gradient of the loss with respect to the predictions, which is why the method is "gradient" boosting, and other losses use their own negative gradients. **AdaBoost** is the older classification variant: it increases the weights of misclassified examples so that the next learner concentrates on them, and combines the learners in a weighted vote.

Unlike a forest, a boosted model can overfit if $M$ is too large, so $M$, $\nu$ and the tree depth are tuned together on validation data, often with early stopping. A smaller $\nu$ needs more rounds but usually generalizes better.

### Choosing

Random forests are easy to tune, parallelize across trees, and give an OOB estimate. Boosted trees often reach slightly higher accuracy on tabular data after more careful tuning. Both lose the readability of a single tree.

@example
title: One round of gradient boosting
problem: Data: $x = (1, 2, 3, 4)$, $y = (1, 2, 6, 7)$. Use a stump (one split) at the threshold $2.5$ and learning rate $\nu = 0.5$. Find $F_1$ and the MSE before and after.
step: $F_0 = \bar{y} = 4$ for every input. The MSE is $(9 + 4 + 4 + 9)/4 = 6.5$.
step: The residuals are $r = (-3, -2, 2, 3)$.
step: The stump predicts the mean residual in each region: $(-3 - 2)/2 = -2.5$ for $x \le 2.5$ and $(2 + 3)/2 = 2.5$ for $x > 2.5$.
step: With $\nu = 0.5$: $F_1 = 4 + 0.5(-2.5) = 2.75$ for $x \le 2.5$ and $4 + 0.5(2.5) = 5.25$ otherwise.
step: The errors are $-1.75, -0.75, 0.75, 1.75$, so the MSE is $(3.0625 + 0.5625 + 0.5625 + 3.0625)/4 = 1.8125$.
answer: $F_1 = (2.75, 2.75, 5.25, 5.25)$; the MSE drops from $6.5$ to $1.8125$.

@example
title: How many examples does a bootstrap sample miss?
problem: For $n = 10$, what is the probability that a particular example is absent from a bootstrap sample, and how many examples are out-of-bag on average?
step: Each of the 10 draws misses the example with probability $9/10$.
step: The draws are independent, so the probability that all miss it is $(0.9)^{10} \approx 0.3487$.
step: By linearity of expectation, the expected number of OOB examples is $10 \times 0.3487 \approx 3.5$.
step: As $n$ grows, $(1 - 1/n)^n \to e^{-1} \approx 0.368$, so about a third of the data is out-of-bag for every tree.
answer: $\approx 0.349$, so about $3.5$ examples are out-of-bag.

@mistakes
- Believing that more trees in a random forest cause overfitting; it is boosting with too many rounds that overfits.
- Sampling a bootstrap without replacement, which just reproduces the full data set (or a subset) instead of a resample.
- Using strongly pruned, high-bias trees in a bagged ensemble: averaging does not reduce bias.
- Reading feature importance as causal effect, or trusting it when features are strongly correlated.

```python
def ensemble_vote(predictions):
    result = []
    for votes in zip(*predictions):
        counts = {}
        for v in votes:
            counts[v] = counts.get(v, 0) + 1
        best = max(counts.values())
        result.append(min(c for c, n in counts.items() if n == best))
    return result
```

model:
```python
def boost_step(xs, ys, current, threshold, lr):
    res = [y - c for y, c in zip(ys, current)]
    left = [r for x, r in zip(xs, res) if x <= threshold]
    right = [r for x, r in zip(xs, res) if x > threshold]
    left_mean = sum(left) / len(left) if left else 0.0
    right_mean = sum(right) / len(right) if right else 0.0
    return [
        c + lr * (left_mean if x <= threshold else right_mean)
        for x, c in zip(xs, current)
    ]
```
hint: First compute the residuals, then the mean residual of each side of the threshold.
solution: Residuals tell the stump what is left to explain. Its prediction is each region's mean residual, shrunk by `lr` and added to the current prediction. With the threshold below all `x`, the single region has mean residual 0 here, so nothing changes.

```python
def oob_indices(n, sample_indices):
    seen = set(sample_indices)
    return [i for i in range(n) if i not in seen]
```
hint: A set makes the membership test fast and ignores repeats.
