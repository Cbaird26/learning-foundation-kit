@article
A model's error on its own training data is optimistic, so we estimate performance on data it has never seen. The discipline is simple to state and easy to break: **any data used to make a decision about the model cannot also be used to measure it.**

### Training, validation and test sets

Split the data randomly into three parts. The **training set** fits the parameters. The **validation set** compares models and **tunes hyperparameters** (the degree of a polynomial, $\lambda$, the number of neighbors). The **test set** is used once, at the end, to report the final performance. If you peek at the test set to choose a model, it becomes a second validation set and the reported error is optimistic. For data with a time order, split by time (train on the past, test on the future) instead of at random.

### Cross-validation

When data are scarce, a single validation set is noisy and wastes examples. In **$k$-fold cross-validation** you partition the training data into $k$ folds. For each fold $j$, train on the other $k - 1$ folds and score on fold $j$. The **CV estimate** is the average of the $k$ scores. Typical values are $k = 5$ or $10$; $k = n$ is leave-one-out. Each model is trained $k$ times, so the cost is about $k$ times that of one fit. For classification, **stratified** folds keep the class proportions in each fold.

### Data leakage

**Leakage** is any way information from the validation or test examples enters training. Common cases: standardizing or selecting features using the whole data set before splitting; near-duplicate examples (the same patient, the same photo) landing on both sides of the split; and a feature that is only recorded after the outcome. All preprocessing must be fitted inside each training fold and then applied to the held-out fold.

### The confusion matrix and its metrics

For binary classification with positive class 1, count the outcomes: **TP** (true positives), **FP** (false positives), **FN** (false negatives) and **TN** (true negatives).

| | predicted 1 | predicted 0 |
|---|---|---|
| actual 1 | TP | FN |
| actual 0 | FP | TN |

$$\text{accuracy} = \frac{TP + TN}{n},\quad \text{precision} = \frac{TP}{TP + FP},\quad \text{recall} = \frac{TP}{TP + FN},\quad F_1 = \frac{2PR}{P + R} = \frac{2TP}{2TP + FP + FN}.$$
**Precision** answers "of the cases I flagged, how many were real?"; **recall** (sensitivity, true positive rate) answers "of the real cases, how many did I find?". The **false positive rate** is $FP/(FP + TN)$, and specificity is $TN/(TN + FP)$. $F_1$ is the harmonic mean of precision and recall. Define precision or recall as 0 when its denominator is 0. Accuracy misleads on imbalanced classes; which of precision and recall matters more depends on the costs of the two kinds of error (missing a cancer versus a false alarm).

Raising the decision threshold of a probabilistic classifier never increases recall (it lowers it or leaves it unchanged) and usually, though not always, raises precision. The **ROC curve** plots the true positive rate against the false positive rate over all thresholds, and the **AUC** (area under it) equals the probability that a randomly chosen positive example scores higher than a randomly chosen negative one (ties count one half). For regression, report RMSE $=\sqrt{\mathrm{MSE}}$ or the mean absolute error alongside the baseline.

### Uncertainty of an estimate

A test accuracy $\hat p$ measured on $n$ independent examples has standard error about $\sqrt{\hat p(1 - \hat p)/n}$, and an approximate 95% confidence interval is $\hat p \pm 1.96\,\mathrm{SE}$. With $\hat p = 0.9$ and $n = 400$, $\mathrm{SE} = 0.015$ and the interval is $0.90 \pm 0.029$. Two models whose accuracies differ by less than this are not clearly different when measured separately; a paired comparison on the same test examples (such as McNemar's test) can detect smaller differences. Always report metrics with their uncertainty, not as bare numbers.

@example
title: Metrics from a confusion matrix
problem: A classifier produces $TP = 40$, $FP = 10$, $FN = 20$ and $TN = 30$. Compute accuracy, precision, recall and $F_1$.
step: There are $n = 40 + 10 + 20 + 30 = 100$ examples.
step: Accuracy $= (40 + 30)/100 = 0.70$.
step: Precision $= 40/(40 + 10) = 0.80$ and recall $= 40/(40 + 20) = 2/3$.
step: $F_1 = 2TP/(2TP + FP + FN) = 80/(80 + 10 + 20) = 80/110 = 8/11 \approx 0.727$.
step: Check with the harmonic mean: $2(0.8)(2/3)/(0.8 + 2/3) = (16/15)/(22/15) = 8/11$.
answer: accuracy $0.70$, precision $0.80$, recall $2/3$, $F_1 = 8/11$.

@example
title: Splitting data into folds
problem: Show the test folds of 4-fold cross-validation on $n = 10$ examples (indices $0$ to $9$), using contiguous folds whose sizes differ by at most one.
step: $10 = 4\cdot 2 + 2$, so the first two folds get 3 examples and the last two get 2.

step: For fold 3 (the third), the training set is everything else: $\{0,1,2,3,4,5,8,9\}$.
step: Every example is tested exactly once and trained on $k - 1 = 3$ times. The four validation scores are averaged.

@mistakes
- Choosing hyperparameters by test-set error and then reporting that same test error as the final performance.
- Fitting the scaler (or feature selection) on all the data before cross-validation, which leaks validation information into training.
- Quoting accuracy alone on imbalanced data, or mixing up precision and recall (precision divides by predicted positives, recall by actual positives).
- Reporting a single cross-validation number without any measure of its variability.

```python
def confusion_counts(y_true, y_pred):
    tp = fp = fn = tn = 0
    for t, p in zip(y_true, y_pred):
        if t == 1 and p == 1:
            tp += 1
        elif t == 0 and p == 1:
            fp += 1
        elif t == 1 and p == 0:
            fn += 1
        else:
            tn += 1
    return (tp, fp, fn, tn)
```
hint: Look at each pair `(t, p)` and increase exactly one of four counters.
solution: A positive prediction is a true positive when the label is 1 and a false positive when it is 0; a negative prediction is a false negative when the label is 1 and a true negative otherwise.

```python
def precision_recall_f1(y_true, y_pred):
    tp = fp = fn = 0
    for t, p in zip(y_true, y_pred):
        if p == 1 and t == 1:
            tp += 1
        elif p == 1:
            fp += 1
        elif t == 1:
            fn += 1
    precision = tp / (tp + fp) if tp + fp else 0.0
    recall = tp / (tp + fn) if tp + fn else 0.0
    f1 = 2 * tp / (2 * tp + fp + fn) if tp else 0.0
    return (precision, recall, f1)
```
hint: Count tp, fp and fn first; precision is tp/(tp+fp) and recall is tp/(tp+fn).
hint: $F_1 = 2TP/(2TP + FP + FN)$ avoids dividing by $P + R$, which can be 0. If there are no true positives, $F_1$ is 0.
solution: Count the three outcomes, guard each division against a zero denominator, and compute $F_1$ as `2*tp / (2*tp + fp + fn)`, which is 0 whenever `tp` is 0.

model:
```python
def kfold_indices(n, k):
    base, extra = divmod(n, k)
    folds = []
    start = 0
    for j in range(k):
        size = base + (1 if j < extra else 0)
        test = list(range(start, start + size))
        train = list(range(0, start)) + list(range(start + size, n))
        folds.append((train, test))
        start += size
    return folds
```
hint: `divmod(n, k)` gives the base fold size and the number of larger folds.
hint: Walk through the folds keeping a `start` index; the test block is `range(start, start + size)` and the training set is everything before and after it.
solution: Compute the sizes with `divmod`, build each contiguous test block, and let the training set be the indices before and after it. Every index appears in exactly one test block, so every example is validated once.

@quiz mc
prompt: A data scientist standardizes all 1000 examples (using the mean and standard deviation of the full data set) and then runs 5-fold cross-validation of a model. What is wrong with this procedure?
choice: Nothing: standardization does not use the labels, so it cannot affect the estimate.
choice*: The scaler used information from the held-out folds, which is leakage, so the estimate can be optimistic; the scaler should be fitted on the training folds inside each split.

choice: The estimate is pessimistic, because the training folds contain the held-out examples.

solution: The mean and standard deviation computed on all data depend on the held-out examples, so information about them reaches the training folds. The effect is often small for simple scaling, but the correct practice is to fit all preprocessing on the training fold only.
