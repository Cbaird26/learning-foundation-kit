@article
**HTML** (HyperText Markup Language) describes the *structure and meaning* of content; CSS describes appearance and JavaScript describes behavior. A page that is correct HTML works in every browser, can be navigated with a keyboard, is read aloud correctly by a screen reader and is indexed sensibly by search engines. That is **semantic HTML**: choose each element for what the content *is*, not for how it looks by default.

### The document skeleton

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Reading list</title>
  </head>
  <body>
    <header><h1>Reading list</h1></header>
    <nav aria-label="Main"><a href="/">Home</a></nav>
    <main>
      <article>
        <h2>Currently reading</h2>
        <p>Two books this month.</p>
      </article>
    </main>
    <footer><p>Updated weekly.</p></footer>
  </body>
</html>
```

`lang` lets screen readers choose a pronunciation. `charset="utf-8"` avoids garbled text. The `viewport` meta tag is required for responsive layouts on phones (week 4). The `<title>` is the first thing a screen-reader user hears and what appears in tabs and search results.

### Landmarks and sectioning

Elements such as `header`, `nav`, `main`, `aside`, `footer` and `section` (with an accessible name) create **landmarks** that assistive technology lists so users can jump around. Use exactly one `main` per page. `article` is a self-contained item (a post, a card), and `section` is a thematic grouping that normally has a heading. A `div` or `span` has no meaning; use them only when no semantic element fits.

### Headings

Headings `h1` to `h6` form an outline. Screen-reader users move through a page by headings, so do not skip levels (an `h2` followed by an `h4`) and do not choose a level for its size; resize with CSS instead. Normally there is one `h1` naming the page.

### Text alternatives

Every `img` needs an `alt` attribute. If the image carries information, describe its *purpose*: `alt="Bar chart: sales doubled in 2025"`. If it is purely decorative, write `alt=""` so that assistive technology skips it. A missing `alt` is different from an empty one: with no `alt`, a screen reader may read out the file name.

### Links, buttons and forms

Use `a href` to navigate and `button` to act. A clickable `div` is not focusable, has no role and does not react to the Enter and Space keys, and rebuilding all of that by hand is error-prone. Link text must make sense out of context (`Read the report`, not `click here`).

Every form control needs a programmatically associated **label**:

```html
<label for="email">Email address</label>
<input id="email" name="email" type="email" autocomplete="email" required>
```

A placeholder is not a label: it disappears while typing and often has low contrast. Group related controls with `fieldset` and `legend`. In tables, use `caption`, `th` with `scope`, and keep tables for tabular data, not layout.

### ARIA and the first rule

ARIA attributes (`role`, `aria-label`, `aria-expanded`, ...) adjust the accessibility tree. The first rule of ARIA is to prefer a native element that already has the behavior; use ARIA only to fill genuine gaps, because wrong ARIA is worse than none.

### WCAG 2.2 in practice

WCAG 2.2 (2023) is the current W3C recommendation. At level AA, normal text needs a **contrast ratio** of at least 4.5:1 against its background, large text (about 24 CSS px, or 18.66 px bold) at least 3:1. The ratio is $(L_1 + 0.05)/(L_2 + 0.05)$, where $L_1 \ge L_2$ are relative luminances from 0 (black) to 1 (white); black on white is 21:1. WCAG 2.2 added criteria such as a minimum pointer target size of 24 by 24 CSS pixels (2.5.8) and focus that is not hidden behind other content (2.4.11). Also make everything reachable and visible when focused with the keyboard: never remove the focus outline without replacing it.

@example
title: From div soup to semantic HTML
problem: Rewrite this markup so that it is semantic and accessible.

```html
<div class="top"><div class="big">Trail guide</div></div>
<div class="menu"><span onclick="go()">Maps</span></div>
<img src="map.png">
```
step: The page title is a heading, and the top block is a header: `<header><h1>Trail guide</h1></header>`.
step: The menu is navigation, and a control that navigates is a link: `<nav aria-label="Main"><a href="/maps">Maps</a></nav>`.
step: The image needs a text alternative that states its purpose: `<img src="map.png" alt="Map of the three main trails">`.
step: Put the unique content inside one `main` element. The result has landmarks, a real heading, a keyboard-operable link and an accessible image.

@example
title: Labelling a form field
problem: Make this field accessible: `<input type="text" placeholder="Your name">`.
step: A placeholder is not a label, so add a `label` element with visible text.
step: Connect them: the label's `for` must equal the input's `id`.
step: Add a `name` for form submission and `autocomplete="name"` so browsers can fill it in:

```html
<label for="full-name">Your name</label>
<input id="full-name" name="name" type="text" autocomplete="name">
```
step: Clicking the label now focuses the input, and screen readers announce "Your name, edit text".

@mistakes
- Choosing heading levels for their size (an `h4` because it looks right) and skipping levels, which breaks the outline.
- Leaving out `alt` entirely, or writing `alt="image"`; use a purposeful description, or `alt=""` for decoration.
- Using a placeholder instead of a `label`, or a `div` with a click handler instead of a `button`.
- Adding ARIA roles on top of elements that already have the right native meaning.

page = '<img src="a.png" alt="A cat"><p>x</p><img src="b.png">'

model:
```python
import re


def images_missing_alt(html):
    missing = []
    for tag in re.findall(r"<img\b[^>]*>", html):
        if re.search(r"\salt=", tag) is None:
            missing.append(re.search(r'src="([^"]*)"', tag).group(1))
    return missing
```
hint: `re.findall(r"<img\b[^>]*>", html)` returns each whole `<img ...>` tag as a string.
hint: Look for `alt=` preceded by whitespace, so that `data-alt=` does not match.
solution: Find every image tag, test each for the pattern `\salt=` (whitespace before `alt`, so `data-alt` is rejected) and collect the `src` of those without it.

@practice code
prompt: Write `contrast_ratio(fg, bg)` that returns the WCAG contrast ratio of two colors given as six-digit hex strings such as `"#767676"` (any letter case). For each channel, let `c` be the value 0-255 divided by 255; its linear value is `c / 12.92` if `c <= 0.04045`, else `((c + 0.055) / 1.055) ** 2.4`. The relative luminance is `0.2126 * R + 0.7152 * G + 0.0722 * B` of the linear values. The ratio is `(lighter + 0.05) / (darker + 0.05)`, where `lighter` and `darker` are the larger and smaller luminance, so the order of the arguments does not matter.
starter:
```python
def contrast_ratio(fg, bg):
    pass
```
tests:
```python
assert round(contrast_ratio("#000000", "#ffffff"), 2) == 21.0
assert round(contrast_ratio("#ffffff", "#000000"), 2) == 21.0
assert round(contrast_ratio("#767676", "#ffffff"), 2) == 4.54
assert round(contrast_ratio("#777777", "#FFFFFF"), 2) == 4.48
assert round(contrast_ratio("#0000ff", "#ffffff"), 2) == 8.59
assert round(contrast_ratio("#336699", "#336699"), 2) == 1.0
```
model:
```python
def luminance(hex_color):
    digits = hex_color.lstrip("#")
    linear = []
    for i in (0, 2, 4):
        c = int(digits[i:i + 2], 16) / 255
        if c <= 0.04045:
            linear.append(c / 12.92)
        else:
            linear.append(((c + 0.055) / 1.055) ** 2.4)
    r, g, b = linear
    return 0.2126 * r + 0.7152 * g + 0.0722 * b


def contrast_ratio(fg, bg):
    a, b = luminance(fg), luminance(bg)
    lighter, darker = max(a, b), min(a, b)
    return (lighter + 0.05) / (darker + 0.05)
```
hint: Write a helper that returns the luminance of one color, then combine two luminances.
hint: `int("76", 16)` converts a two-digit hex string to a number; slice the string as `digits[0:2]`, `digits[2:4]`, `digits[4:6]`.
solution: Convert each channel to its linear value with the given formula, weight them to get the luminance, then divide the lighter luminance plus 0.05 by the darker plus 0.05. `#767676` on white is the darkest gray that still passes the 4.5:1 AA threshold for normal text, which the test checks.

@quiz code
prompt: Write `heading_outline_ok(levels)` that takes the heading levels of a page in document order, for example `[1, 2, 3, 2]`, and returns `True` if the outline is well formed: the first heading is level 1, and no heading is more than one level deeper than the heading before it (going back up by any amount is fine). An empty list is well formed.
starter:
```python
def heading_outline_ok(levels):
    pass
```
tests:
```python
assert heading_outline_ok([1, 2, 3, 2, 3]) is True
assert heading_outline_ok([1, 3]) is False
assert heading_outline_ok([2, 3]) is False
assert heading_outline_ok([1, 2, 3, 1, 2]) is True
assert heading_outline_ok([1, 2, 4]) is False
assert heading_outline_ok([]) is True
```
model:
```python
def heading_outline_ok(levels):
    previous = 0
    for level in levels:
        if level > previous + 1:
            return False
        previous = level
    return True
```
hint: Treat the "heading before the first one" as level 0, so the first heading may be at most level 1.
hint: Remember the previous level and fail as soon as `level > previous + 1`.
solution: Start with `previous = 0`; for each heading, `level > previous + 1` means a skipped level (this also rejects a first heading deeper than 1). Otherwise update `previous` and continue; if the loop finishes, the outline is fine.
