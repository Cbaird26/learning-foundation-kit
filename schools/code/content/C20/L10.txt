@article
A web application must remember things between requests and after restarts. That requires **persistent storage**, almost always a relational database (SQLite for small apps, PostgreSQL or MySQL for larger ones). The server turns the data into HTML (or JSON) with **templates**, and accepts new data through **forms**.

### SQL and sqlite3

A relational database stores data in **tables** of rows and columns; a **primary key** identifies each row and a **foreign key** refers to a row of another table. SQLite is a database in a single file, accessed from Python through the standard `sqlite3` module:

```python
import sqlite3

db = sqlite3.connect("books.db")
db.row_factory = sqlite3.Row            # rows behave like dictionaries
db.execute(
    "CREATE TABLE IF NOT EXISTS books ("
    " id INTEGER PRIMARY KEY,"
    " title TEXT NOT NULL,"
    " author TEXT NOT NULL DEFAULT '')"
)
db.execute("INSERT INTO books (title, author) VALUES (?, ?)", ("Dune", "Herbert"))
db.commit()                             # make the change permanent
rows = db.execute("SELECT id, title FROM books ORDER BY title").fetchall()
db.close()
```

Changes are made permanent by `commit()`. In SQLite, foreign keys are enforced only if each connection runs `PRAGMA foreign_keys = ON`.

### SQL injection and parameters

**Vulnerable** (do not write this):

```python
# VULNERABLE: user input is pasted into the SQL text
db.execute("SELECT * FROM books WHERE author = '" + author + "'")
```

If `author` contains a quote character, it ends the string literal early and the remainder is parsed as SQL: the user's data has become part of the program. **Fixed**: pass values separately, so the database never parses them as SQL:

```python
db.execute("SELECT * FROM books WHERE author = ?", (author,))
```

Use placeholders (`?` in `sqlite3`; `%s` or `:name` styles in other drivers) for *every* value. Placeholders cannot stand for table or column names; if those vary, choose them from a fixed allow-list. Injection is item A05 of the OWASP Top 10:2025.

### Templates

Building HTML by string concatenation is error-prone and unsafe. Flask uses the **Jinja2** template engine. Templates live in the `templates` folder and are rendered with `render_template`:

```html
{% extends "base.html" %}
{% block content %}
  <h1>Books</h1>
  <ul>
    {% for book in books %}
      <li>{{ book["title"] }} by {{ book["author"] }}</li>
    {% else %}
      <li>No books yet.</li>
    {% endfor %}
  </ul>
{% endblock %}
```

`{{ ... }}` prints a value, `{% ... %}` is a statement (`for`, `if`), and `{% extends %}` with `{% block %}` lets pages share a layout defined once in `base.html`. In Flask, **autoescaping is on** for templates ending in `.html`: `{{ value }}` converts `<`, `>`, `&` and quotes to entities, so `<script>` in data is displayed as text. The `|safe` filter turns escaping off; use it only for HTML you wrote yourself, never for user data.

### Forms

```html
<form method="post" action="/books">
  <label for="title">Title</label>
  <input id="title" name="title" required>
  <button>Add book</button>
</form>
```

The browser sends the fields that have a `name` as `title=Dune&author=...`, URL-encoded, with `Content-Type: application/x-www-form-urlencoded` (or `multipart/form-data` when files are included). In Flask they appear in `request.form`. Use `GET` for forms that only read (a search box: the URL is shareable) and `POST` for forms that change data.

**Validate on the server.** Attributes such as `required`, `type="email"` and `maxlength` give quick feedback, but anyone can send a request without a browser, so they are never a security measure. When data is invalid, re-render the form with status `400` or `422`, show specific error messages next to the fields and keep what the user typed. When it is valid, perform the change and **redirect** to a page that displays the result: **Post/Redirect/Get**. Otherwise, pressing Reload re-submits the form and creates a duplicate.

@example
title: Why parameters matter
problem: Explain what goes wrong with `"SELECT * FROM books WHERE title = '" + title + "'"` for the title `It's`, and fix it.
step: The text becomes `... WHERE title = 'It's'`. The apostrophe in the data closes the string literal, leaving `s'` as invalid SQL, so the query raises an error.
step: A deliberately crafted value can do worse than raise an error: it can change the meaning of the query, which is why this is a security flaw as well as a bug.
step: Replace the concatenation by a placeholder and pass the value separately:

```python
db.execute("SELECT * FROM books WHERE title = ?", (title,))
```
step: Now the SQL text is fixed, `It's` is treated as a value, and the query finds the book titled `It's`.

@example
title: The life of a form submission
problem: A user submits the "Add book" form with the title `Dune`. List what the server and browser do.
step: The browser sends `POST /books` with the body `title=Dune`.
step: The view reads `request.form.get("title", "").strip()`, finds it non-empty and runs `INSERT ... VALUES (?, ?)`, then `db.commit()`.
step: The view returns `redirect(url_for("index"), code=303)`, so the browser requests `GET /` and shows the list including the new book.
step: Reloading now repeats the harmless `GET`, not the `POST`.

@mistakes
- Building SQL with string concatenation or f-strings instead of placeholders.
- Forgetting `commit()`, so an insert disappears when the connection closes.
- Disabling escaping with `|safe` for user-supplied text, which creates a cross-site scripting hole.
- Relying on browser-side validation only, or answering a successful `POST` with a rendered page, so Reload re-submits the form.

tests:
```python
assert render("<p>{{ name }}</p>", {"name": "Ada"}) == "<p>Ada</p>"
assert render("<p>{{ name }}</p>", {"name": "<b>Ada</b>"}) == (
    "<p>&lt;b&gt;Ada&lt;/b&gt;</p>")
assert render("{{ markup|safe }}", {"markup": "<b>x</b>"}) == "<b>x</b>"
assert render("{{ markup | safe }}!", {"markup": "<i>"}) == "<i>!"

assert render("{{a}}-{{ b }}-{{ n }}", {"a": "x", "b": "y", "n": 5}) == "x-y-5"
assert render("{{ a }}", {"a": "{{ b }}", "b": "X"}) == "{{ b }}"

```
model:
```python
import html
import re

PLACEHOLDER = re.compile(r"\{\{\s*(\w+)\s*(\|\s*safe\s*)?\}\}")


def render(template, context):
    def replace(match):
        text = str(context.get(match.group(1), ""))
        if match.group(2):
            return text
        return html.escape(text)
    return PLACEHOLDER.sub(replace, template)
```
hint: `re.sub` with a function computes each replacement from its match, and scans the template only once.
hint: A regular expression with an optional group for `|safe` tells you which placeholders to leave unescaped.
solution: One pass of `re.sub` replaces each placeholder with the (escaped unless `|safe`) value; because the substitution scans only the original template, a value that looks like a placeholder is inserted as plain text. Escaping by default is the same safe-by-default design that Jinja2 uses.

@practice self
prompt: Write a Flask application (`app.py` and the template `index.html`) for a book list stored in SQLite. `GET /` lists all books ordered by title; `POST /books` adds a book from the form fields `title` (required) and `author`. Use a helper that opens one connection per request, parameterized queries, template autoescaping, an error message with status `400` when the title is empty, and Post/Redirect/Get on success. The table is created by an `init_db()` function.
hint: Start with `get_db()` using Flask's `g` object and a teardown function that closes the connection; then write `index()` and `add_book()`, with `add_book()` validating first.
solution: A model answer:

```python
import sqlite3

from flask import Flask, g, redirect, render_template, request, url_for

app = Flask(__name__)
DATABASE = "books.db"


def get_db():
    if "db" not in g:
        g.db = sqlite3.connect(DATABASE)
        g.db.row_factory = sqlite3.Row
    return g.db


@app.teardown_appcontext
def close_db(error):
    db = g.pop("db", None)
    if db is not None:
        db.close()


def init_db():
    db = sqlite3.connect(DATABASE)
    db.execute(
        "CREATE TABLE IF NOT EXISTS books ("
        " id INTEGER PRIMARY KEY,"
        " title TEXT NOT NULL,"
        " author TEXT NOT NULL DEFAULT '')"
    )
    db.commit()
    db.close()


def all_books():
    return get_db().execute(
        "SELECT id, title, author FROM books ORDER BY title"
    ).fetchall()


@app.get("/")
def index():
    return render_template("index.html", books=all_books(), error=None)


@app.post("/books")
def add_book():
    title = request.form.get("title", "").strip()
    author = request.form.get("author", "").strip()
    if not title:
        page = render_template(
            "index.html", books=all_books(), error="Title is required")
        return page, 400
    db = get_db()
    db.execute(
        "INSERT INTO books (title, author) VALUES (?, ?)", (title, author))
    db.commit()
    return redirect(url_for("index"), code=303)
```

model:
```python
import re


def validate_signup(form):
    errors = {}
    username = form.get("username", "")
    if not re.fullmatch(r"[A-Za-z0-9_]{3,20}", username):
        errors["username"] = "Use 3-20 letters, digits or underscores."
    email = form.get("email", "")
    if not re.fullmatch(r"[^@\s]+@[^@\s]+\.[^@\s]+", email):
        errors["email"] = "Enter an address like name@example.com."
    quantity = form.get("quantity", "").strip()
    if not (re.fullmatch(r"[0-9]+", quantity) and 1 <= int(quantity) <= 10):
        errors["quantity"] = "Enter a whole number from 1 to 10."
    return errors
```
hint: `re.fullmatch` requires the whole string to match, so the length and character rules can be one pattern each.
hint: For `quantity`, check that it is all digits before converting with `int`, then check the range.
solution: Validate each field independently and collect messages in a dictionary. Use `fullmatch` with explicit character classes, and for the quantity test the digits first so that `int()` never sees a sign, a decimal point or text. An empty dictionary means the form is valid.
