@article
**CSS** (Cascading Style Sheets) is a list of rules. Each rule has a **selector**, which says which elements it applies to, and a **declaration block** of `property: value;` pairs:

```css
.card {
  padding: 1rem;
  border: 1px solid #ccc;
}
```

Attach CSS with `<link rel="stylesheet" href="styles.css">` in the `head` (the usual way, so the browser can cache it), a `style` element, or a `style` attribute on one element (avoid: it is hard to override and cannot use selectors).

### Selectors

| Selector | Matches |
|---|---|
| `p` | every `p` element (type selector) |
| `.note` | elements with `class="note"` |
| `#menu` | the element with `id="menu"` (IDs are unique) |
| `a[href^="https"]` | `a` elements whose `href` starts with `https` |
| `nav a` | any `a` inside a `nav` (descendant) |
| `ul > li` | `li` that are direct children of `ul` |
| `h2 + p` | a `p` immediately after an `h2` |
| `h2 ~ p` | any later `p` sibling of an `h2` |
| `a:hover`, `input:focus-visible` | pseudo-classes: an element in a state |
| `li:nth-child(2n)` | every second child |
| `p::first-line` | a pseudo-element: a part of an element |

Modern selectors include `:is()`, `:where()`, `:not()` and `:has()` (the parent selector, for example `li:has(> a)`), and CSS now supports **nesting**, where a rule can contain other rules written with `&`.

### The cascade

Several rules may set the same property on one element. The browser chooses the winner by these criteria, in order: **origin and importance** (a declaration marked `!important` beats a normal one; avoid it), **cascade layers** (`@layer`), **specificity**, and finally **order of appearance** (the later rule wins a tie).

**Specificity** is a triple $(a, b, c)$ compared left to right: $a$ counts ID selectors, $b$ counts class selectors, attribute selectors and pseudo-classes, and $c$ counts type selectors and pseudo-elements. The universal selector `*` and combinators count nothing. So `#menu a` is $(1,0,1)$, `nav .link` is $(0,1,1)$ and `a` is $(0,0,1)$; the first wins regardless of order, because $a=1$ beats $a=0$. `:where()` always contributes zero, which makes it useful for low-specificity defaults. An inline `style` attribute outranks any selector.

### Inheritance

Some properties are **inherited** by descendants when no rule sets them: text-related ones such as `color`, `font-family`, `line-height`. Layout ones such as `margin`, `padding` and `border` are not. `inherit`, `initial` and `unset` force the choice.

### The box model

Every element generates a **box** with four layers from the inside out: **content**, **padding**, **border** and **margin**. With the default `box-sizing: content-box`, the `width` property sets the *content* width, so the space used on a line is

$$\text{width} + 2\cdot\text{padding} + 2\cdot\text{border} + 2\cdot\text{margin}$$

(for equal left and right values). With `box-sizing: border-box`, `width` covers content, padding and border, so margin is the only addition. Most stylesheets begin with:

```css
*, *::before, *::after {
  box-sizing: border-box;
}
```

because widths such as `width: 50%` then include padding and borders and stop overflowing. In `border-box` the content width cannot go below 0, so the box is never smaller than its padding plus border. **Vertical margins of adjacent block boxes collapse**: the gap between them is the larger of the two margins, not the sum. Margins of flex and grid items do not collapse.

### Units and custom properties

`px` is a CSS pixel; `rem` is relative to the root element's font size (16px by default in browsers); `em` is relative to the element's own font size (or, for the `font-size` property itself, the parent's); `%`, `vw`, `vh` and `ch` are relative to other things. Prefer `rem` for text and spacing so that the page respects the user's font-size setting. **Custom properties** store reusable values: declare `--accent: #0b5fff;` on `:root` and use `color: var(--accent);`.

@example
title: Which rule wins?
problem: With the markup `<nav id="menu"><a class="link" href="/">Home</a></nav>` and these rules, what color is the link?

```css
nav .link { color: blue; }
a         { color: green; }
#menu a   { color: red; }
```
step: Compute the specificity of each selector. `nav .link` has one class and one type: $(0,1,1)$. `a` is $(0,0,1)$. `#menu a` has one ID and one type: $(1,0,1)$.
step: Compare left to right. The ID count decides first, so `#menu a` wins over the other two, regardless of the order in which the rules are written.
step: All three rules match the same element and the same property, so only the highest specificity applies.
answer: The link is red.

@example
title: Sizing a box
problem: A box has `width: 300px; padding: 20px; border: 5px solid; margin: 10px;`. How much horizontal space does it occupy with `content-box`, and with `border-box`?
step: With `content-box`, 300px is only the content. Add padding on both sides (40px) and border on both sides (10px): the border box is 350px wide.
step: Margins add 20px: the box occupies 370px.
step: With `border-box`, the 300px already includes padding and border, so the content is $300 - 40 - 10 = 250$px and the border box stays 300px.
step: Margins still add 20px, so the box occupies 320px.
answer: 370px with `content-box` and 320px with `border-box`.

@mistakes
- Assuming the later rule always wins; specificity is compared first, and order only breaks ties.
- Forgetting that `content-box` makes padding and borders extra, so `width: 100%` with padding overflows its container.
- Using `!important` to win a specificity fight, which makes later overrides harder; reduce specificity instead.
- Expecting `border` or `padding` to be inherited by children, or adding vertical margins together when they collapse.

```python
assert specificity("ul li:first-child") == (0, 1, 2)
```

model:
```python
import re


def specificity(selector):
    attrs = re.findall(r"\[[^\]]*\]", selector)
    rest = re.sub(r"\[[^\]]*\]", " ", selector)
    elements = re.findall(r"::[\w-]+", rest)
    rest = re.sub(r"::[\w-]+", " ", rest)
    pseudo = re.findall(r":[\w-]+", rest)
    rest = re.sub(r":[\w-]+", " ", rest)
    ids = re.findall(r"#[\w-]+", rest)
    rest = re.sub(r"#[\w-]+", " ", rest)
    classes = re.findall(r"\.[\w-]+", rest)
    rest = re.sub(r"\.[\w-]+", " ", rest)
    types = re.findall(r"[A-Za-z][\w-]*", rest)
    return (len(ids), len(classes) + len(attrs) + len(pseudo),
            len(types) + len(elements))
```
hint: Remove each kind of token from the string after counting it, so later patterns do not match pieces of earlier ones (for instance the `a` in `[href]`).
hint: Handle attribute selectors first, then `::pseudo-elements` before `:pseudo-classes`, then `#ids`, `.classes`, and what is left are the type selectors.
solution: Count and blank out attribute selectors first (their contents could look like other tokens), then pseudo-elements (so `::before` is not also counted as `:before`), then pseudo-classes, IDs and classes. Words left over are type selectors.

```python
def content_width(width, padding, border, box_sizing="content-box"):

```
tests:
```python
assert content_width(300, 20, 5) == 300
assert content_width(300, 20, 5, "border-box") == 250
assert content_width(30, 20, 5, "border-box") == 0
assert content_width(100, 0, 0, "border-box") == 100
```

model:
```python
def content_width(width, padding, border, box_sizing="content-box"):
    if box_sizing == "content-box":
        return width
    if box_sizing == "border-box":
        return max(0, width - 2 * padding - 2 * border)
    raise ValueError(f"unknown box-sizing: {box_sizing}")
```
hint: There are three cases: `content-box`, `border-box` and anything else.
hint: Use `max(0, ...)` to keep a `border-box` content width from going negative.
solution: In `content-box` the declared width is already the content width. In `border-box`, subtract the padding and border on both sides and clamp at 0, because a box cannot have a negative content width.

tests:
```python
assert occupied_width(150, 10, 2, 4) == 182
assert occupied_width(150, 10, 2, 4, "border-box") == 158
assert occupied_width(30, 20, 5, 10, "border-box") == 70
assert occupied_width(0, 0, 0, 0) == 0
```

model:
```python
def occupied_width(width, padding, border, margin, box_sizing="content-box"):
    extra = 2 * padding + 2 * border
    if box_sizing == "content-box":
        box = width + extra
    elif box_sizing == "border-box":
        box = max(width, extra)
    else:
        raise ValueError(f"unknown box-sizing: {box_sizing}")
    return box + 2 * margin
```
hint: Compute the width of the border box first, then add the margins.
hint: In `border-box`, the border box is `max(width, 2 * padding + 2 * border)`.
solution: The border box is `width + extra` in `content-box` and `max(width, extra)` in `border-box`, where `extra` is padding plus border on both sides. Add `2 * margin` to either. The test with width 30 checks the clamp: padding and border alone need 50px.
