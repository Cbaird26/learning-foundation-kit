@article
So far the browser has done the work. A **server-side** application runs on a server, receives HTTP requests and produces responses: HTML pages, JSON or files. **Flask** is a small Python web framework: it handles routing, request parsing and responses, and leaves the choice of database, forms and authentication libraries to you. Install it into a virtual environment with `python -m venv .venv`, activate it, then `pip install flask`.

### A first application

```python
from flask import Flask, abort, request

app = Flask(__name__)


@app.get("/")
def home():
    return "Hello, web!"


@app.get("/api/greet/<name>")
def greet(name):
    return {"message": f"Hello, {name}!"}


@app.post("/api/echo")
def echo():
    data = request.get_json()
    return data, 201


@app.get("/api/items/<int:item_id>")
def item(item_id):
    if item_id > 100:
        abort(404)
    return {"id": item_id}
```

Save it as `app.py` and run the development server with `flask --app app run --debug`. It listens on `http://127.0.0.1:5000` by default and, in debug mode, reloads on code changes and shows an interactive debugger, so **never enable debug mode on a public server**.

### Routing

`@app.get`, `@app.post` and so on (Flask 2.0 and later) are shortcuts for `@app.route(path, methods=[...])`; a bare `@app.route("/")` allows `GET` (plus `HEAD` and `OPTIONS`). A decorator **registers** the function in the app's URL map. The parts in angle brackets are **converters**: `<name>` matches a string without slashes, `<int:item_id>` matches digits and passes the function an `int`, and there are also `float`, `path` and `uuid`. A request whose path matches no route gets `404 Not Found`; a path that matches but with an unsupported method gets `405 Method Not Allowed`. Defining `/about/` (with a trailing slash) makes `/about` redirect to it, whereas defining `/about` makes `/about/` a 404.

### The request object

Inside a view, the global-looking `request` describes the current request: `request.method`, `request.path`, `request.args` (the query string, so `request.args.get("q", "")` for `?q=flask`), `request.form` (an HTML form body), `request.headers`, `request.cookies` and `request.get_json()`. For `get_json()`, Flask answers `415` if the request is not declared as JSON, and `400` if the JSON is invalid; `request.get_json(silent=True)` returns `None` instead. **Validate everything from the client**: its values are untrusted input (week 11).

### Responses

A view may return a string (an HTML `200` response), a `dict` or `list` (converted to JSON with `Content-Type: application/json`), or a tuple `(body, status)` or `(body, status, headers)`. `abort(404)` raises an HTTP error immediately. `redirect(url)` returns a `302` redirect (a `303` after a `POST` is the usual choice), and `url_for("home")` builds a URL from a view's function name, so URLs are not scattered through your code. Customize errors with a handler:

```python
@app.errorhandler(404)
def not_found(error):
    return {"error": "not found"}, 404
```

Files placed in the `static` folder are served under `/static/...`, and HTML templates live in `templates` (week 10).

### How a request reaches your code

A Python web server speaks HTTP to the browser and calls the application through a standard interface: **WSGI** (Web Server Gateway Interface), a function-call protocol that Flask implements; ASGI is the asynchronous counterpart used by other frameworks. Flask's built-in server is for development only. In production, run a WSGI server such as **Gunicorn** (`gunicorn app:app` means module `app`, variable `app`), usually behind a reverse proxy that terminates TLS and serves static files. The flow: browser sends a request, the proxy forwards it to Gunicorn, Gunicorn builds a WSGI call, Flask matches the URL to a view, calls it with the converted parameters, and turns the return value into an HTTP response.

### Structuring and configuring

Keep configuration (secret keys, database paths) out of source code: read it from environment variables into `app.config`. As an application grows, use an **application factory** (`create_app()`) and **blueprints** to group related routes. Because each request is independent (HTTP is stateless), do not keep per-user data in module-level variables: a server runs several worker processes, and the data would differ between them and vanish on restart.

@example
title: Reading a Flask route
problem: Given `@app.get("/users/<int:uid>")`, what happens for `GET /users/42`, `GET /users/abc` and `POST /users/42`?
step: `/users/42` matches: `42` is digits, so Flask calls the view with `uid=42` (an `int`) and sends its return value as the response.
step: `/users/abc` does not match, because the `int` converter requires digits; no other route matches, so the response is `404 Not Found`.
step: `/users/42` with `POST` matches the URL, but the route allows only `GET` (and `HEAD`, `OPTIONS`), so the response is `405 Method Not Allowed`.
step: The view function never runs in the last two cases, so your code does not need to check for them.

@example
title: A route that reads the query string
problem: Write `GET /search?q=flask` so it returns the JSON `{"query": "flask", "length": 5}`, and returns an error for a missing `q`.
step: Read the parameter with `request.args.get("q", "").strip()`; the default avoids `None`.
step: If it is empty, call `abort(400)`: the client sent a bad request.
step: Otherwise return a dictionary, which Flask converts to JSON:

```python
@app.get("/search")
def search():
    query = request.args.get("q", "").strip()
    if not query:
        abort(400)
    return {"query": query, "length": len(query)}
```
step: For `/search?q=flask` the response is `200` with `{"query": "flask", "length": 5}`; for `/search` it is `400`.

@mistakes
- Running with `debug=True` or `--debug` on a public server, which exposes an interactive debugger.
- Using the development server in production instead of Gunicorn or another WSGI server.
- Trusting `request.args`, `request.form` or JSON values without validating type and range.
- Storing user data in a global variable, which breaks with multiple worker processes and restarts.

model:
```python
def parse_segment(segment):
    if segment.startswith("<") and segment.endswith(">"):
        inner = segment[1:-1]
        if ":" in inner:
            kind, name = inner.split(":", 1)
        else:
            kind, name = "string", inner
        return kind, name
    return None


def match_route(pattern, path):
    pattern_parts = pattern.split("/")
    path_parts = path.split("/")
    if len(pattern_parts) != len(path_parts):
        return None
    params = {}
    for expected, actual in zip(pattern_parts, path_parts):
        parsed = parse_segment(expected)
        if parsed is None:
            if expected != actual:
                return None
            continue
        kind, name = parsed
        if actual == "":
            return None
        if kind == "int":
            if not (actual.isascii() and actual.isdigit()):
                return None
            params[name] = int(actual)
        else:
            params[name] = actual
    return params
```
hint: Split both strings on `/` and compare segment by segment; different counts mean no match.
hint: A parameter segment starts with `<` and ends with `>`; if the text inside contains a colon, the part before it is the converter and the part after it is the name.
solution: Split pattern and path into segments, require equal lengths, and compare each pair: literal segments must be equal; a parameter segment must be non-empty, and an `int` segment must be all digits, which excludes `-5` and `abc`. Collect the converted values in a dictionary.

@practice code
prompt: Write `dispatch(routes, method, path)` for a tiny router. `routes` is a list of `(pattern, methods, handler)` tuples, where `methods` is a set of upper-case method names and `handler` is a function taking the URL parameters as keyword arguments. Patterns have `/`-separated segments; a segment `<name>` matches any non-empty text without `/` and becomes a keyword argument (a string); other segments must match exactly.

model:
```python
def _match(pattern, path):
    pattern_parts = pattern.split("/")
    path_parts = path.split("/")
    if len(pattern_parts) != len(path_parts):
        return None
    params = {}
    for expected, actual in zip(pattern_parts, path_parts):
        if expected.startswith("<") and expected.endswith(">"):
            if actual == "":
                return None
            params[expected[1:-1]] = actual
        elif expected != actual:
            return None
    return params


def dispatch(routes, method, path):
    path_matched = False
    for pattern, methods, handler in routes:
        params = _match(pattern, path)
        if params is None:
            continue
        path_matched = True
        if method in methods:
            return 200, handler(**params)
    if path_matched:
        return 405, "Method Not Allowed"
    return 404, "Not Found"
```
hint: Remember whether any pattern matched the path, even if the method did not, to tell `405` from `404`.
hint: Do not stop at the first matching pattern: the same URL may have separate routes for `GET` and `POST`.
solution: Loop over the routes; for each one whose pattern matches, note that the path exists, and call the handler if the method is allowed. After the loop, `405` means the path exists but not for this method, and `404` means nothing matched. The `/users` path has two routes, which is why the loop must continue after a pattern match with the wrong method.

model:
```python
from urllib.parse import quote


def build_url(pattern, **params):
    parts = []
    for segment in pattern.split("/"):
        if segment.startswith("<") and segment.endswith(">"):
            inner = segment[1:-1]
            if ":" in inner:
                kind, name = inner.split(":", 1)
            else:
                kind, name = "string", inner
            value = params[name]
            if kind == "int":
                if (not isinstance(value, int) or isinstance(value, bool)
                        or value < 0):
                    raise ValueError(f"{name} must be a non-negative int")
                segment = str(value)
            else:
                segment = quote(str(value), safe="")
        parts.append(segment)
    return "/".join(parts)
```
hint: Split the pattern on `/`, replace each parameter segment, and join the segments again with `/`.
hint: Look up `params[name]` first (this raises `KeyError` if it is missing), then check the type for the `int` converter.
solution: Replace every parameter segment: look up the value (a missing name raises `KeyError`), validate and format integers, and percent-encode strings with `quote(..., safe="")`, which also encodes `/`. Building URLs from one function instead of by string concatenation keeps them consistent and correctly encoded.
