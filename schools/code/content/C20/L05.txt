@article
**JavaScript** is the language of the browser (and, through runtimes such as Node.js, of servers). It is dynamically typed, has first-class functions and is standardized as **ECMAScript**, with a new edition every year. Load a script with `<script src="app.js" defer></script>` (it runs after the HTML is parsed) or `type="module"`, which is deferred automatically and enables `import` and `export`. Output for debugging goes to the browser console with `console.log(...)`.

### Values and types

The primitive types are `number` (one 64-bit floating-point type, so `0.1 + 0.2` is `0.30000000000000004`), `string`, `boolean`, `undefined`, `null`, `bigint` and `symbol`. Everything else is an **object** (arrays, functions, dates). `typeof` reports the type as a string; note the historical quirk `typeof null === "object"`, and use `Array.isArray(x)` for arrays.

### Variables

Declare with `const` for bindings that are never reassigned and `let` for those that are. Both are **block-scoped**. Avoid `var`: it is function-scoped and hoisted, which causes surprises. `const` fixes the *binding*, not the contents: a `const` array can still be modified with `push`.

### Equality and truthiness

`===` compares without conversion: `5 === "5"` is `false`. `==` converts types first, with rules that surprise people (`0 == ""` is `true`), so use `===` and `!==`. `NaN` is not equal to anything, even itself; test with `Number.isNaN(x)`. In a condition, **falsy** values are `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined` and `NaN`; everything else is truthy, including `"0"`, `"false"`, `[]` and `{}`. The operators `??` (use the right side only if the left is `null` or `undefined`) and `?.` (stop if the value is `null` or `undefined`) are the modern way to handle missing values.

### Strings and template literals

```javascript
const name = "Ada";
const items = 3;
console.log(`Hello, ${name}: ${items * 2} points`);
```

Backtick strings interpolate any expression inside `${...}` and can span lines. Without them, `"5" + 3` is `"53"` (concatenation) but `"5" - 3` is `2`, because `-` converts to numbers.

### Functions and closures

```javascript
function add(a, b) { return a + b; }
const double = (n) => n * 2;          // arrow function

function makeCounter() {
  let count = 0;
  return () => { count += 1; return count; };
}
const next = makeCounter();
next(); next();                        // 1, then 2
```

`makeCounter` returns a function that still uses `count` after `makeCounter` has finished. This is a **closure**: a function together with the variables of the scope where it was created. Each call to `makeCounter` creates a separate `count`. Arrow functions have no `this` of their own; they use the `this` of the surrounding code.

### Arrays and objects

```javascript
const nums = [1, 2, 3, 4];
const total = nums
  .filter((n) => n % 2 === 0)        // [2, 4]
  .map((n) => n * n)                 // [4, 16]
  .reduce((acc, n) => acc + n, 0);   // 20

const user = { name: "Ada", langs: ["JS", "Python"] };
const { name, langs } = user;        // destructuring
const copy = { ...user, name: "Bo" };// spread: shallow copy with a change
```

`map` returns a new array of the same length, `filter` keeps the elements for which the callback returns a truthy value, and `reduce` folds an array into one value, with the second argument as the starting value. These do not modify the original array. **Beware**: `sort()` sorts in place and, by default, compares elements as *strings*, so `[10, 9, 1].sort()` gives `[1, 10, 9]`; pass a comparison function, `sort((a, b) => a - b)`. `for (const x of array)` loops over values; `for...in` loops over property names, which is rarely what you want for arrays.

### Errors

```javascript
try {
  JSON.parse("{bad json");
} catch (err) {
  console.log(err.name);   // "SyntaxError"
}
```

@example
title: Tracing filter, map and reduce
problem: What does this code print?

```javascript
const words = ["sun", "moon", "star", "sky"];
const n = words
  .filter((w) => w.length === 3)
  .map((w) => w.toUpperCase())
  .join("-");
console.log(n);
```
step: `filter` keeps the words of length 3: `["sun", "sky"]` (`moon` and `star` have 4 letters).
step: `map` upper-cases each: `["SUN", "SKY"]`.
step: `join("-")` glues the elements with hyphens into the string `"SUN-SKY"`.
step: `console.log` prints the string without quotation marks.
answer: `SUN-SKY`

@example
title: Closures keep their own variable
problem: What do the two counters print?

```javascript
function makeCounter() {
  let count = 0;
  return () => ++count;
}
const a = makeCounter();
const b = makeCounter();
console.log(a(), a(), b());
```
step: Each call to `makeCounter()` creates a new `count` starting at 0, so `a` and `b` have separate variables.
step: `a()` increments `a`'s count to 1, and the second `a()` makes it 2.
step: `b()` increments `b`'s own count, which was 0, to 1.
step: `console.log(a(), a(), b())` prints the three values separated by spaces.
answer: `1 2 1`

@mistakes
- Using `==` and being surprised by conversions (`0 == ""`, `"1" == 1`); use `===`.
- Calling `sort()` on numbers without a comparison function, which sorts them as text.
- Thinking `const` makes an object or array immutable; it only prevents rebinding the name.
- Treating `[]` or `"0"` as falsy, or testing `x === NaN` (always `false`).

```python
def js_truthy(value):
    if value is None or isinstance(value, bool):
        return bool(value)
    if isinstance(value, (int, float)):

    if isinstance(value, str):
        return value != ""
    return True
```

@practice code
prompt: Write `my_reduce(items, fn, initial=MISSING)` that behaves like JavaScript's `Array.prototype.reduce`. `fn(acc, item)` is called for each item in order, and the result becomes the next `acc`. If `initial` is given, it is the first `acc`; if not, the first item is the first `acc` and the loop starts at the second item. Reducing an empty list without `initial` raises `TypeError`; with `initial` it returns `initial`. `MISSING` is already defined in the starter code.
starter:
```python
MISSING = object()


def my_reduce(items, fn, initial=MISSING):
    pass
```
tests:
```python
assert my_reduce([1, 2, 3, 4], lambda a, b: a + b) == 10
assert my_reduce([1, 2, 3, 4], lambda a, b: a * b, 10) == 240
assert my_reduce(["a", "b", "c"], lambda a, b: a + b, "") == "abc"
assert my_reduce([], lambda a, b: a + b, 7) == 7
assert my_reduce([5], lambda a, b: a + b) == 5
assert raises(TypeError, my_reduce, [], lambda a, b: a + b)
assert my_reduce([3, 1, 2], lambda a, b: a if a > b else b) == 3
```
model:
```python
MISSING = object()


def my_reduce(items, fn, initial=MISSING):
    items = list(items)
    if initial is MISSING:
        if not items:
            raise TypeError("reduce of empty list with no initial value")
        acc, rest = items[0], items[1:]
    else:
        acc, rest = initial, items
    for item in rest:
        acc = fn(acc, item)
    return acc
```
hint: A sentinel object lets you tell "no initial value" apart from an initial value of `None` or `0`.
hint: Decide `acc` and the list of items still to process before the loop.
solution: If no initial value was passed, the first item becomes the accumulator (an empty list is an error); otherwise the initial value is the accumulator. Then fold the remaining items with `acc = fn(acc, item)`.

@quiz code
prompt: Write `group_by(items, key_fn)` that returns a dictionary mapping each key `key_fn(item)` to the list of items with that key, with the items in their original order within each list and keys in order of first appearance (like JavaScript's `Object.groupBy`). An empty input gives `{}`.
starter:
```python
def group_by(items, key_fn):
    pass
```
tests:
```python
words = ["apple", "bob", "cat", "avocado", "bee"]
assert group_by(words, lambda w: w[0]) == {
    "a": ["apple", "avocado"], "b": ["bob", "bee"], "c": ["cat"]}
assert group_by([1, 2, 3, 4, 5], lambda n: n % 2 == 0) == {
    False: [1, 3, 5], True: [2, 4]}
assert group_by([], len) == {}
assert list(group_by(["bb", "a", "cc"], len)) == [2, 1]
assert group_by(["x"], lambda w: w) == {"x": ["x"]}
```
model:
```python
def group_by(items, key_fn):
    groups = {}
    for item in items:
        groups.setdefault(key_fn(item), []).append(item)
    return groups
```
hint: Create an empty dictionary and add each item to the list stored under its key.
hint: `dict.setdefault(key, [])` returns the existing list or inserts an empty one.
solution: For each item compute its key, fetch (or create) the list for that key with `setdefault`, and append. Dictionaries remember insertion order, so keys come out in order of first appearance.

@quiz mc
prompt: What does this JavaScript print?

```javascript
var fns = [];
for (var i = 0; i < 3; i++) {
  fns.push(() => i);
}
console.log(fns.map((f) => f()).join(","));
```
choice: `0,1,2`
choice*: `3,3,3`
choice: `0,0,0`
choice: `2,2,2`
hint: `var` creates one variable for the whole function, not one per loop pass.
solution: With `var`, all three arrow functions share one `i`, which is 3 when the loop ends and the functions are finally called. Declaring the loop variable with `let` creates a new `i` for each pass, and the output would be `0,1,2`.
