@article
Before flexbox and grid, pages were laid out with floats and tables. Today there are two purpose-built layout systems, and **responsive design** (one page that adapts to any screen) is the default expectation.

### Flexbox: one dimension

Set `display: flex` on a **container** and its children become **flex items** laid out along the **main axis** (horizontal for the default `flex-direction: row`, vertical for `column`); the perpendicular direction is the **cross axis**.

```css
.toolbar {
  display: flex;
  justify-content: space-between; /* main axis */
  align-items: center;            /* cross axis */
  gap: 1rem;
  flex-wrap: wrap;
}
.toolbar .search { flex: 1; }
```

`justify-content` distributes items along the main axis; `align-items` aligns them on the cross axis. `gap` adds space between items. By default items stay on one line; `flex-wrap: wrap` lets them wrap.

Each item has three sizing properties, written together as `flex: grow shrink basis`. The **basis** is the starting size (default `auto`, meaning the item's `width` or content size). If the items together are smaller than the container, the free space is shared in proportion to the **grow** factors (default 0, so no growth). If they are larger, the overflow is taken away in proportion to the **shrink** factors (default 1). The shorthand `flex: 1` means `1 1 0%`. With basis 0, each item's whole width is distributed by grow factors, so `flex: 1` items end up equal.

### Grid: two dimensions

`display: grid` defines rows and columns on the container.

```css
.gallery {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(12rem, 1fr));
  gap: 1rem;
}
```

The `fr` unit is a share of the free space left after fixed tracks and gaps. `repeat(auto-fill, minmax(12rem, 1fr))` creates as many columns of at least `12rem` as fit and stretches them to fill the row, a responsive gallery with no media query. (`auto-fit` does the same but collapses empty tracks, so a short row's items stretch.) `grid-template-areas` names regions of a page layout, and items can span tracks with `grid-column: 1 / -1`. Rule of thumb: use flexbox to lay out items *along a line* (a nav bar, a card's footer) and grid to lay out a *page or a grid of items*.

### Responsive design

1. **Viewport meta tag**: `<meta name="viewport" content="width=device-width, initial-scale=1">`. Without it, phones pretend to be wide and shrink the page.
2. **Fluid sizes**: use `%`, `rem`, `fr` and `max-width` instead of fixed pixel widths. Make images fit with `img { max-width: 100%; height: auto; }`. `clamp(1rem, 2.5vw, 2rem)` gives a size that scales between a minimum and a maximum.
3. **Media queries** apply rules only when a condition holds. Work **mobile-first**: write the base styles for narrow screens, then add `min-width` queries that enhance the layout for larger ones.

```css
.page { display: grid; gap: 1rem; }

@media (min-width: 48em) {
  .page { grid-template-columns: 14rem 1fr; }
}
```

4. **Choose breakpoints by content**: add one where the layout starts to look bad, not at the sizes of particular devices. Media queries also test preferences, such as `(prefers-color-scheme: dark)` and `(prefers-reduced-motion: reduce)`. **Container queries** (`@container`) style a component by the size of its container rather than the viewport.

Test by resizing the window, zooming to 200%, and using the browser's device emulation: a responsive page must not need horizontal scrolling at a width of 320 CSS pixels (WCAG 2.2 reflow, criterion 1.4.10).

@example
title: Centering with flexbox
problem: Center a box of unknown size horizontally and vertically inside a container 300px tall.
step: Make the container a flex container: `display: flex`.
step: Center along the main axis (horizontal in a row) with `justify-content: center`.
step: Center along the cross axis (vertical) with `align-items: center`:

```css
.stage {
  display: flex;
  justify-content: center;
  align-items: center;
  height: 300px;
}
```
step: The child is centered in both directions without knowing its size.

@example
title: How flex-grow shares free space
problem: A 500px flex container (no gap) holds two items with `flex-basis: 100px`, and `flex-grow` of 1 and 3. How wide is each item?
step: The bases total 200px, so the free space is $500 - 200 = 300$px.
step: The grow factors total 4, so one share is $300 / 4 = 75$px.
step: The first item grows by $1 \times 75 = 75$px and the second by $3 \times 75 = 225$px.
step: The widths are $100 + 75 = 175$px and $100 + 225 = 325$px, which add up to 500px.
answer: 175px and 325px.

@mistakes
- Using flexbox's `justify-content` to center vertically in a row layout; it acts on the main axis, so use `align-items` for the cross axis.
- Forgetting the viewport meta tag, so phones render a zoomed-out desktop layout and media queries seem not to work.
- Writing desktop-first CSS with `max-width` queries that undo styles, instead of mobile-first `min-width` queries.
- Assuming `flex: 1` and `flex-grow: 1` are the same: `flex: 1` also sets the basis to `0%`, which changes how space is shared.

@practice code
prompt: Write `flex_widths(container, items, gap)` that simulates how a flex row sizes its items when there is free space. `items` is a list of `(basis, grow)` pairs of numbers. The free space is `container - sum(bases) - gap * (len(items) - 1)`. If the free space is positive and the grow factors have a positive total, each item's width is its basis plus `free * grow / total_grow`; otherwise each width is just its basis (ignore shrinking). Return the list of widths.
starter:
```python
def flex_widths(container, items, gap):
    pass
```
tests:
```python
assert flex_widths(500, [(100, 1), (100, 3)], 0) == [175, 325]
assert flex_widths(500, [(100, 1), (100, 3)], 20) == [170, 310]
assert flex_widths(500, [(100, 0), (100, 0)], 0) == [100, 100]
assert flex_widths(150, [(100, 1), (100, 1)], 0) == [100, 100]
assert flex_widths(300, [(100, 1)], 10) == [300]
assert flex_widths(300, [], 10) == []
```
model:
```python
def flex_widths(container, items, gap):
    if not items:
        return []
    bases = sum(basis for basis, _ in items)
    free = container - bases - gap * (len(items) - 1)
    total_grow = sum(grow for _, grow in items)
    if free <= 0 or total_grow <= 0:
        return [basis for basis, _ in items]
    return [basis + free * grow / total_grow for basis, grow in items]
```
hint: Compute the free space first, then decide whether anything can grow.
hint: Handle the empty list, the case of no free space, and a total grow of 0 before dividing.
solution: Free space is the container minus the bases and the gaps between items. If it is not positive, or nothing can grow, return the bases; otherwise give each item its share `free * grow / total_grow` on top of its basis. With a 20px gap in the second test, the free space is 280, so the shares are 70 and 210.

@quiz code
prompt: Write `fr_tracks(container, gap, tracks)` that computes the pixel size of each grid column track. `tracks` is a list of strings, each either a fixed size such as `"200px"` or a fraction such as `"2fr"`. The free space is `container - total fixed pixels - gap * (len(tracks) - 1)`, never below 0. Each fraction track gets `free * n / total_fr` pixels, where `n` is its number of `fr` and `total_fr` is the sum over all fraction tracks. Return a list of numbers in track order (use 0 for fraction tracks if there are no fractions to share, which cannot happen in the tests).
starter:
```python
def fr_tracks(container, gap, tracks):
    pass
```
tests:
```python
assert fr_tracks(780, 20, ["200px", "1fr", "2fr"]) == [200, 180, 360]
assert fr_tracks(600, 0, ["1fr", "1fr", "1fr"]) == [200, 200, 200]
assert fr_tracks(600, 0, ["300px", "300px"]) == [300, 300]
assert fr_tracks(100, 10, ["80px", "1fr"]) == [80, 10]
assert fr_tracks(100, 10, ["120px", "1fr"]) == [120, 0]
assert fr_tracks(500, 0, ["2fr", "3fr"]) == [200, 300]
```
model:
```python
def fr_tracks(container, gap, tracks):
    fixed = sum(int(t[:-2]) for t in tracks if t.endswith("px"))
    total_fr = sum(int(t[:-2]) for t in tracks if t.endswith("fr"))
    free = max(0, container - fixed - gap * (len(tracks) - 1))
    sizes = []
    for t in tracks:
        if t.endswith("px"):
            sizes.append(int(t[:-2]))
        else:
            sizes.append(free * int(t[:-2]) / total_fr)
    return sizes
```
hint: Strip the two-letter unit (`t[:-2]`) and convert the number with `int`.
hint: Clamp the free space with `max(0, ...)` before sharing it.
solution: Sum the fixed tracks and the `fr` counts, compute the free space after fixed tracks and gaps, clamp it at 0, then give each `fr` track its proportional share. In the first test the free space is $780 - 200 - 40 = 540$, so the `fr` tracks get 180 and 360.
