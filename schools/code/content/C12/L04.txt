@article
A tree is just data until something gives it **meaning**. An **interpreter** gives meaning to a program by *executing* it directly. For expressions, the simplest design is a **tree-walking interpreter**: a function that looks at the kind of a node and computes its value, recursing into the children first.

### The evaluator

The value of a node depends only on the values of its children, which is the defining property of **structural recursion** on a tree:

```python
import operator

OPS = {
    "+": operator.add,
    "-": operator.sub,
    "*": operator.mul,
    "/": operator.truediv,
}


def evaluate(node):
    kind = node[0]
    if kind == "num":
        return node[1]
    if kind == "neg":
        return -evaluate(node[1])
    if kind == "bin":
        left = evaluate(node[2])
        right = evaluate(node[3])
        return OPS[node[1]](left, right)
    raise ValueError(f"unknown node kind {kind!r}")
```

The evaluator is a **post-order traversal**: it needs both operand values before it can apply the operator. With $n$ nodes, evaluation takes $O(n)$ time, since each node is visited once, and uses stack space proportional to the height of the tree.

Notice that the evaluator never looks at tokens, precedence or parentheses. The parser already encoded all of that in the shape of the tree. This **separation of concerns** is the reason compilers are built in stages: the evaluator can be tested with hand-built trees, and the parser without any evaluator.

### Putting it together

A complete calculator chains the three stages:

```python
def calc(source):
    return evaluate(parse(tokenize(source)))
```

`calc("2 * (3 + 4)")` gives `14`. Each stage reports its own kind of error: `tokenize` raises `ValueError` for a bad character, `parse` raises `SyntaxError` for a malformed expression, and `evaluate` can fail at run time: `calc("1 / 0")` raises `ZeroDivisionError`. A good interpreter distinguishes *when* an error is found (lexical, syntax, runtime) and explains it to the user.

Language design decisions hide in the evaluator. Does `/` on two integers give a float (`7 / 2` is `3.5`) or an integer (`3`)? What is `-7 / 2` under integer division? Python's `//` rounds toward negative infinity and gives `-4`, while C rounds toward zero. A language reference must state the choice, because it is part of the **semantics**.

Never implement a calculator by passing user text to Python's built-in `eval`. That executes arbitrary Python code, not just arithmetic. Parsing and evaluating the input yourself restricts it to exactly the language you defined.

### A stack machine

Postfix notation needs no parser, only a stack. Scan the tokens left to right. A number is pushed. An operator pops two values (the right operand first, then the left), applies the operation and pushes the result. At the end the stack holds exactly one value. For `3 4 + 2 *` the stack goes `[3]`, `[3, 4]`, `[7]`, `[7, 2]`, `[14]`.

This is the idea behind **bytecode virtual machines**: a compiler walks the tree once and emits a linear list of instructions such as `PUSH 3`, `PUSH 4`, `ADD`, and a small loop executes them quickly. Tree walking and stack machines compute the same values; they differ in speed and in how easy they are to build.

@example
title: Evaluating a tree
problem: Evaluate `("bin", "-", ("bin", "*", ("num", 6), ("num", 2)), ("neg", ("num", 3)))`.
step: The root is a `bin` node with operator `-`. Evaluate its left child first.
step: The left child is `6 * 2`. Both operands are numbers, so it evaluates to `12`.
step: The right child is `("neg", ("num", 3))`, which evaluates to `-3`.
step: Apply the root operator: `12 - (-3) = 15`.
answer: `15`

@example
title: A stack machine trace
problem: Evaluate the postfix tokens `["8", "3", "-", "2", "-"]`.
step: Push 8 and 3: the stack is `[8, 3]`.
step: `-` pops `b = 3` then `a = 8`, computes `a - b = 5` and pushes it: `[5]`.
step: Push 2: `[5, 2]`. The second `-` pops `b = 2` and `a = 5` and pushes `3`.
step: One value remains, so the result is `3`. The order of the pops matters: the right operand comes off first.
answer: `3`

@mistakes
- Applying the operator to the operands in the wrong order in a stack machine (`b - a` instead of `a - b`).
- Using Python's `eval` for the calculator, which runs arbitrary code from the user's input.
- Evaluating a node without recursing into its children, or recursing with the wrong child indexes.
- Not stating division semantics, so integer and float results are mixed unpredictably.

model:
```python
def rpn_eval(tokens):
    stack = []
    for t in tokens:
        if t in ("+", "-", "*", "/"):
            if len(stack) < 2:
                raise ValueError("missing operand")
            b = stack.pop()
            a = stack.pop()
            if t == "+":
                stack.append(a + b)
            elif t == "-":
                stack.append(a - b)
            elif t == "*":
                stack.append(a * b)
            else:
                stack.append(a / b)
        else:
            stack.append(int(t))
    if len(stack) != 1:
        raise ValueError("malformed expression")
    return stack[0]
```
hint: Use a Python list as the stack, with `append` to push and `pop()` to pop.
hint: Pop `b` first and then `a`, and apply the operator as `a op b`; check the stack size before popping and after the loop.
solution: Push each number; for an operator pop `b` then `a` and push `a op b`. Check for too few operands during the scan and for a final stack size other than 1, and raise `ValueError` in both cases.

model:
```python
def simplify(node):
    kind = node[0]
    if kind in ("num", "var"):
        return node
    if kind == "neg":
        child = simplify(node[1])
        if child[0] == "num":
            return ("num", -child[1])
        return ("neg", child)
    op = node[1]
    left = simplify(node[2])
    right = simplify(node[3])
    if op != "/" and left[0] == "num" and right[0] == "num":
        a, b = left[1], right[1]
        if op == "+":
            return ("num", a + b)
        if op == "-":
            return ("num", a - b)
        return ("num", a * b)
    return ("bin", op, left, right)
```
hint: Simplify the children first (post-order), then look at what they became.
hint: A node can be folded only when its simplified children are both `("num", ...)` nodes and its operator is not `/`.
solution: Recurse into the children, then fold when the simplified children are numbers. Because folding happens bottom-up, `10 - (4 - 3)` first becomes `10 - 1` and then `9`.
