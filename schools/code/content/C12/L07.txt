@article
The functional style builds results by applying functions to data instead of updating variables in loops. Three higher-order functions cover most loops.

### Map, filter, reduce

- **map** applies a function to every element: `map(f, xs)` gives `f(x)` for each `x`.
- **filter** keeps the elements for which a predicate is true: `filter(p, xs)`.
- **reduce** (also called *fold*) combines all elements into one value with a two-argument function and a starting value: `reduce(f, xs, init)` computes `f(f(f(init, x1), x2), x3)` and so on.

In Python, `map` and `filter` return lazy iterators, and `reduce` lives in `functools`:

```python
from functools import reduce

nums = [1, 2, 3, 4, 5]
squares = list(map(lambda n: n * n, nums))        # [1, 4, 9, 16, 25]
odds = list(filter(lambda n: n % 2 == 1, nums))   # [1, 3, 5]
total = reduce(lambda acc, n: acc + n, nums, 0)   # 15
```

Python's idiomatic spelling of map and filter is the **comprehension**: `[n * n for n in nums]` and `[n for n in nums if n % 2 == 1]`. A loop with an accumulator is exactly a reduce: the accumulator is the first argument of `f`, and the loop body is `f`. Each of these runs in $O(n)$ time.

### Recursion

A **recursive** function is defined in terms of itself. Every correct recursive function has a **base case** that needs no recursive call, and a **recursive case** that calls itself on a *smaller* problem, so the base case is eventually reached. Lists have a natural recursive shape: either empty, or a first element followed by a shorter list.

```python
def total(xs):
    if not xs:
        return 0
    return xs[0] + total(xs[1:])
```

This works, but `xs[1:]` copies the list, so the function takes $O(n^2)$ time; passing an index instead avoids the copying and brings it to $O(n)$. Recursion shines on nested data, where loops are awkward:

```python
def flatten(x):
    if not isinstance(x, list):
        return [x]
    result = []
    for item in x:
        result.extend(flatten(item))
    return result
```

`flatten([1, [2, [3]], 4])` returns `[1, 2, 3, 4]`. Here the recursion follows the shape of the data, which is the same idea as the recursive evaluator for trees.

### The cost of recursion

Each call occupies a **stack frame**. A recursion of depth $n$ uses $O(n)$ stack space, and CPython limits the depth (the default limit is 1000 frames, readable with `sys.getrecursionlimit()`); exceeding it raises `RecursionError`.

A call is a **tail call** when it is the very last thing a function does, so nothing remains to be done after it returns. Writing the accumulator as a parameter turns `total` into a tail-recursive function:

```python
def total_tail(xs, i=0, acc=0):
    if i == len(xs):
        return acc
    return total_tail(xs, i + 1, acc + xs[i])
```

Languages such as Scheme require the implementation to reuse the frame for a tail call (**tail-call elimination**), making this as cheap as a loop. **CPython does not do this**, so `total_tail` still builds one frame per element and fails for long lists. In Python, convert deep tail recursion to a `while` loop; the accumulator parameters become loop variables.

### Choosing a style

Recursion is the right tool when the data is recursive (trees, nested lists, expression ASTs) or the problem splits naturally (divide and conquer). A comprehension or reduce is clearer for flat transformations. A plain loop is often the most readable and efficient choice in Python. The functional habits worth keeping everywhere: small functions, results returned rather than printed, and no hidden state.

@example
title: Folding by hand
problem: Compute `reduce(lambda acc, n: acc * 10 + n, [4, 2, 7], 0)`.
step: Start with `acc = 0`.
step: Combine with `4`: `0 * 10 + 4 = 4`.
step: Combine with `2`: `4 * 10 + 2 = 42`.
step: Combine with `7`: `42 * 10 + 7 = 427`. This fold turns a list of digits into the number they spell.
answer: `427`

@example
title: Designing a recursive function
problem: Write `count_leaves(x)` that counts the non-list items in a nested list such as `[1, [2, 3], [[4]]]`.
step: Base case: if `x` is not a list, it is a single leaf, so the count is `1`.
step: Recursive case: if `x` is a list, the count is the sum of the counts of its items.
step: Combine the cases:

```python
def count_leaves(x):
    if not isinstance(x, list):
        return 1
    return sum(count_leaves(item) for item in x)
```
step: For `[1, [2, 3], [[4]]]` the items give `1 + 2 + 1 = 4`. An empty list gives `sum` of nothing, which is `0`, so `[]` has no leaves.
answer: `count_leaves([1, [2, 3], [[4]]])` is `4`.

@mistakes
- Forgetting the base case, or writing a recursive call on a problem that is not smaller, which ends in `RecursionError`.
- Expecting `map` and `filter` to return lists in Python 3; they return lazy iterators, so wrap them in `list(...)` when you need the elements.
- Passing arguments to the reducing function in the wrong order, or omitting the initial value so that an empty input raises `TypeError`.
- Assuming Python removes tail calls; a long tail-recursive function still overflows the stack.
