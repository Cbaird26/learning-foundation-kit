@article
In a language with **first-class functions**, functions are values like numbers: you can store them in variables, pass them to other functions and return them from functions. A function that takes or returns a function is called **higher-order**. Python, JavaScript and Rust work this way. Java comes close: since Java 8, a lambda is an object that implements a functional interface, so it can be stored, passed and returned like other values.

### Function values and calls

We add two AST nodes: `("fun", params, body)` creates a function value from a list of parameter names and a body expression, and `("call", fn, args)` evaluates the expression `fn` to a function, evaluates the argument expressions and runs the body. A call creates a **new environment** in which the parameters are bound to the argument values, then evaluates the body in it.

The crucial question is the *parent* of that new environment. It must be the environment where the function was **created**, not where it is called (lexical scope, as in week 5). So a function value must carry that environment with it. The pair (parameters, body, creation environment) is a **closure**:

```python
class Closure:
    def __init__(self, params, body, env):
        self.params = params
        self.body = body
        self.env = env
```

Evaluating a `fun` node builds a closure that remembers the current `env`. Evaluating a `call` node does this:

```python
    if kind == "call":
        f = evaluate(node[1], env)
        args = [evaluate(a, env) for a in node[2]]
        inner = dict(f.env)
        inner.update(zip(f.params, args))
        return evaluate(f.body, inner)
```

(A full version also checks that `f` is a closure and that the argument count is right.) Because `inner` starts from the closure's environment, the body sees the variables that existed where the function was written, even after the code that created it has finished.

### Closures in Python

A **closure** is a function that keeps access to variables from its enclosing scope:

```python
def make_adder(n):
    def add(x):
        return x + n
    return add

add5 = make_adder(5)
print(add5(10))   # 15
```

After `make_adder` returns, its local `n` would normally vanish, but `add` still refers to it, so it stays alive. Each call to `make_adder` makes a fresh `n`, so `make_adder(1)` and `make_adder(2)` are independent.

A closure captures the **variable**, not a copy of its value at the moment of creation. That has two consequences. First, a closure can *change* the variable with `nonlocal`, which gives functions private mutable state without a class:

```python
def make_counter():
    count = 0
    def step():
        nonlocal count
        count += 1
        return count
    return step
```

Second, several closures created in a loop can share a single variable. This is the classic **late-binding** surprise:

```python
fs = [lambda: i for i in range(3)]
print([f() for f in fs])   # [2, 2, 2]
```

Every lambda reads the same `i`, which is `2` when the loop finishes. Giving each lambda its own binding fixes it: `lambda i=i: i` copies the current value into a default parameter at creation time.

### Recursion needs a name

A function body can call itself only if its own name is visible in the environment it closes over. With `let f = fun ... in ...`, the closure is created *before* `f` is bound, so `f` is not in its captured environment. Languages solve this with a recursive binding form (often `let rec` or `letrec`): create the closure, then add the name to the environment it captured. In Python this is automatic because a `def` binds the name in an enclosing scope that the function can see.

### Why it matters

Closures are the basis of callbacks, decorators, iterators, partial application and **currying** (turning a function of two arguments into a function that returns a function). They also link back to memory: a closure keeps its environment alive as long as the closure itself is reachable, which we will study in week 12.

@example
title: Tracing a closure
problem: What does this program print?

```python
def make_adder(n):
    def add(x):
        return x + n
    return add

a = make_adder(1)
b = make_adder(10)
print(a(5), b(5))
```
step: `make_adder(1)` creates a fresh environment with `n = 1` and returns `add`, which remembers that environment. That function is stored in `a`.
step: `make_adder(10)` creates another, separate environment with `n = 10`; `b` holds the second closure.
step: `a(5)` evaluates `x + n` with `x = 5` and the `n` from the first environment: `5 + 1 = 6`.
step: `b(5)` uses the second environment: `5 + 10 = 15`.
answer: `6 15`

@example
title: The late-binding pitfall
problem: Why does `[f() for f in [lambda: i for i in range(3)]]` give `[2, 2, 2]`, and how do you get `[0, 1, 2]`?
step: All three lambdas close over the same variable `i`, the loop variable, not over its value at the time each lambda was created.
step: The lambdas are called only after the loop has finished, when `i` is `2`.
step: To capture the value, give each lambda its own parameter with a default: `lambda i=i: i`. The default value is computed when the lambda is created.
step: Now the three functions have defaults `0`, `1` and `2`, so calling them with no arguments gives `[0, 1, 2]`.
answer: Closures capture variables, not values. Use `lambda i=i: i` to capture the current value.

@mistakes
- Making the call environment a child of the caller's environment instead of the closure's (that is dynamic scope).
- Believing a closure stores the value a variable had when the closure was created, rather than the variable itself.
- Forgetting `nonlocal` when a nested function assigns to an enclosing variable; the assignment then creates a new local variable.
- Defining a function with `let f = ...` and expecting it to call itself without a recursive binding.

        if node[1] == "-":

```

assert raises(TypeError, evaluate, ("call", num(3), []), {})
assert raises(TypeError, evaluate, ("call", inc, []), {})
```
model:
```python
class Closure:
    def __init__(self, params, body, env):
        self.params = params
        self.body = body
        self.env = env


def evaluate(node, env):
    kind = node[0]
    if kind == "num":
        return node[1]
    if kind == "var":
        return env[node[1]]
    if kind == "bin":
        left = evaluate(node[2], env)
        right = evaluate(node[3], env)
        if node[1] == "+":
            return left + right
        if node[1] == "-":
            return left - right
        return left * right
    if kind == "let":
        value = evaluate(node[2], env)
        inner = dict(env)
        inner[node[1]] = value
        return evaluate(node[3], inner)
    if kind == "fun":
        return Closure(node[1], node[2], env)
    if kind == "call":
        f = evaluate(node[1], env)
        if not isinstance(f, Closure):
            raise TypeError("not a function")
        args = [evaluate(a, env) for a in node[2]]
        if len(args) != len(f.params):
            raise TypeError("wrong number of arguments")
        inner = dict(f.env)
        inner.update(zip(f.params, args))
        return evaluate(f.body, inner)
    raise ValueError(f"unknown node {kind!r}")
```
hint: A `fun` node produces a closure object holding `params`, `body` and the current `env`.
hint: In a call, build the body's environment from `f.env`, not from the caller's `env`; that is what makes scope lexical.
solution: Return `Closure(params, body, env)` for `fun`. For `call`, evaluate the function and arguments, check them, copy the closure's environment, bind the parameters and evaluate the body. The test with `make` and an outer `n = 100` yields `2` only if the call uses the closure's environment.
