material: ### The Mini language specification

A Mini program is one expression. Its value is an integer, a boolean or a function.

```text
expr     -> "let" ["rec"] IDENT "=" expr "in" expr
          | "if" expr "then" expr "else" expr
          | "fun" "(" [IDENT ("," IDENT)*] ")" "->" expr
          | or_expr
or_expr  -> and_expr ("or" and_expr)*
and_expr -> cmp ("and" cmp)*
cmp      -> sum [("<" | "<=" | ">" | ">=" | "==" | "!=") sum]
sum      -> product (("+" | "-") product)*
product  -> unary (("*" | "/" | "%") unary)*
unary    -> ("-" | "not") unary | call
call     -> atom ("(" [expr ("," expr)*] ")")*
atom     -> NUMBER | "true" | "false" | IDENT | "(" expr ")"
```

Lexical rules: a NUMBER is one or more decimal digits; an IDENT starts with a letter or `_` and continues with letters, digits and `_`; the keywords are `let rec in if then else fun and or not true false`; `#` starts a comment that runs to the end of the line; whitespace separates tokens.

Semantics:
- `/` is floor division on integers and `%` is the matching remainder (as in Python's `//` and `%`); dividing or taking a remainder by zero is an error.
- `and` and `or` evaluate their right operand only if needed and require booleans; `not` requires a boolean. Because `not` is a unary operator in this grammar, it binds more tightly than comparisons (unlike Python): `not 1 < 2` means `(not 1) < 2`, which is an error, so write `not (1 < 2)`.
- `if` requires a boolean condition and evaluates only the chosen branch.
- `let x = e1 in e2` evaluates `e1` in the current environment and `e2` in a new environment that also binds `x`. `let rec f = fun ... in e2` makes `f` visible inside the function body as well.
- A `fun` expression creates a closure over the current environment. Scope is lexical. Calling a closure with the wrong number of arguments is an error.
- The result is printed as a decimal integer, `true`, `false`, or `<function>`.
- Every error (bad character, syntax error, unbound variable, type error, wrong arity, division by zero) is reported as a `LangError` with a message.

```python
from interp import run, LangError

# (source, expected). An expected value of "ERROR" means a LangError.
PROGRAMS = [
    ("1 + 2 * 3", 7),
    ("10 - 4 - 3", 3),
    ("1 + true", "ERROR"),
    ("let x = 5 in x * x", 25),
    # ... at least 30 in total ...
]


def check(source, expected):
    try:
        result = run(source)
    except LangError:
        return expected == "ERROR"
    return type(result) is type(expected) and result == expected


if __name__ == "__main__":
    failures = [s for s, e in PROGRAMS if not check(s, e)]
    for s in failures:
        print("FAILED:", s)
    print(f"{len(PROGRAMS) - len(failures)} of {len(PROGRAMS)} passed")
```

## Week-by-week review

**Week 1: language design and paradigms.** A language is syntax, semantics and an implementation. Paradigms (imperative, object-oriented, functional, declarative) are styles, and most languages are multi-paradigm. The pipeline is source, tokens, AST, analysis, execution.

**Week 2: tokens and grammars.** A scanner groups characters into tokens using maximal munch; a context-free grammar in BNF describes how tokens combine and encodes precedence by layering.

**Week 3: ASTs and recursive descent.** One function per grammar rule, loops for left-associative operators, recursion for parentheses and unary operators. Left-recursive rules must be rewritten as loops.

**Week 4: evaluation.** A tree-walking evaluator is structural recursion; it runs in $O(n)$ time for $n$ nodes. A stack machine evaluates postfix. Never use `eval` on untrusted input.

**Week 5: environments and scope.** An environment is a chain of dictionaries. Lexical scope looks names up where the code was written; shadowing hides outer bindings; `let` evaluates its value in the outer environment.

**Week 6: closures.** A closure is code plus its creation environment. A call's environment is a child of the closure's environment. Closures capture variables, not values (late binding).

**Week 7: functional style.** `map`, `filter` and `reduce` replace loops; recursion needs a base case; CPython does not eliminate tail calls and limits the recursion depth.

**Week 8: purity and immutability.** Pure functions depend only on their arguments and have no side effects, so they can be memoized. Immutability is shallow; update by copying.

**Week 9: types.** Static versus dynamic is when types are checked; strong versus weak is how strictly. Python is dynamic and strong; type hints are not enforced at run time.

**Week 10: type checking and inference.** Typing rules become a recursive function over the AST with a type environment. Inference uses type variables and unification with an occurs check.

**Week 11: objects.** Dynamic dispatch picks the method from the receiver's actual class; method lookup follows the class chain or the MRO; `super()` means the next class in the MRO.

**Week 12: memory.** Manual management, reference counting (cycles leak), and tracing collection (mark reachable objects from the roots, sweep the rest).

## Common errors

- Making `+` and `*` the same precedence, or recursing on the right and getting right-associative subtraction.
- Evaluating a `let` value in the new environment, or making a call's environment a child of the caller's.
- Forgetting `nonlocal`, or expecting a closure to copy a variable's value.
- Mixing up static/dynamic with strong/weak.
- Forgetting the occurs check, or the visited set in a graph traversal over cyclic references.

model:
```python
class Closure:
    def __init__(self, params, body, env):
        self.params = params
        self.body = body
        self.env = env


def evaluate(node, env):
    kind = node[0]
    if kind in ("num", "bool"):
        return node[1]
    if kind == "var":
        if node[1] not in env:
            raise NameError(f"unbound variable {node[1]!r}")
        return env[node[1]]
    if kind == "fun":
        return Closure(node[1], node[2], env)
    if kind == "let":
        value = evaluate(node[2], env)
        inner = dict(env)
        inner[node[1]] = value
        return evaluate(node[3], inner)
    if kind == "letrec":
        inner = dict(env)
        fun = node[2]
        inner[node[1]] = Closure(fun[1], fun[2], inner)
        return evaluate(node[3], inner)
    if kind == "if":
        cond = evaluate(node[1], env)
        if type(cond) is not bool:
            raise TypeError("condition must be a boolean")
        return evaluate(node[2] if cond else node[3], env)
    if kind == "call":
        f = evaluate(node[1], env)
        if not isinstance(f, Closure):
            raise TypeError("not a function")
        args = [evaluate(a, env) for a in node[2]]
        if len(args) != len(f.params):
            raise TypeError("wrong number of arguments")
        inner = dict(f.env)
        inner.update(zip(f.params, args))
        return evaluate(f.body, inner)
    if kind == "bin":
        op = node[1]
        left = evaluate(node[2], env)
        right = evaluate(node[3], env)
        if op == "==":
            if type(left) is not type(right) or type(left) not in (int, bool):
                raise TypeError("== needs two ints or two bools")
            return left == right
        if type(left) is not int or type(right) is not int:
            raise TypeError(f"{op} needs integers")
        if op == "+":
            return left + right
        if op == "-":
            return left - right
        if op == "*":
            return left * right
        if op == "<":
            return left < right
    raise ValueError(f"unknown node {node!r}")
```
