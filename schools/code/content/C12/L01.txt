@article
A **programming language** is a precise notation for describing computation. Three things define it, and keeping them apart will save you from many confusions.

- **Syntax** is which strings of characters are valid programs, and how they are structured. `x = 1 + 2` is valid Python; `x = + * 2` is not.
- **Semantics** is what a valid program means: which value an expression has, which effects a statement causes. In Python `1 + 2` means the integer `3`; in JavaScript `"1" + 2` means the string `"12"`.
- **Implementation** is the software (or hardware) that actually runs programs. One language can have several implementations. CPython and PyPy both implement Python.

"Is Python interpreted or compiled?" is therefore a question about an implementation, not about the language. CPython first **compiles** your source to bytecode, and then a **virtual machine** executes that bytecode instruction by instruction.

### The pipeline

Nearly every implementation starts the same way, and this course builds each stage:

1. **Scanning (tokenizing)** turns characters into tokens: `12`, `+`, `(`.
2. **Parsing** turns tokens into a tree that records structure, the **abstract syntax tree** (AST).
3. **Analysis** resolves names and checks types.
4. **Execution** either walks the tree (a *tree-walking interpreter*), translates it to bytecode for a virtual machine, or generates machine code (a *compiler*).

A tree-walking interpreter is the simplest to write and the slowest to run. Bytecode machines trade extra work up front for faster execution, and native compilers produce the fastest programs but need the most machinery.

### Paradigms

A **paradigm** is a style of organizing programs. The same task, "sum the squares of the even numbers", looks different in each:

```python
nums = [1, 2, 3, 4]

# Imperative: a sequence of commands that change variables.
total = 0
for n in nums:
    if n % 2 == 0:
        total += n * n

# Functional: an expression built from functions, with no updates.
total = sum(n * n for n in nums if n % 2 == 0)
```

- **Imperative** (procedural) programs are sequences of statements that change state. C is the standard example.
- **Object-oriented** programs bundle state with the operations on it in objects, and objects interact by sending messages (method calls). Java and Smalltalk are class-based examples.
- **Functional** programs compute by applying and composing functions, preferring values to mutation. Haskell is the standard example.
- **Declarative** programs state *what* is wanted and leave the *how* to the system: a SQL query, a regular expression, an HTML page.

Most modern languages, including Python, JavaScript, Rust and C++, are **multi-paradigm**: they let you pick the style that fits the problem.

### Design tradeoffs

Every language balances competing goals: expressiveness against safety, convenience against performance, flexibility against predictability. Garbage collection removes a class of memory bugs but costs run time. Static types catch mistakes early but add notation. There is no best language, only fit for a purpose.

### Expressions and statements

An **expression** produces a value (`n * n`, `f(3)`). A **statement** performs an action (`x = 5`, `for ...`). Functional languages lean on expressions; imperative languages lean on statements. Python's conditional expression `a if c else b` is an expression, while an `if` statement is not.

@example
title: One task, three paradigms
problem: Classify each fragment as imperative, functional or declarative: (1) `SELECT name FROM users WHERE age > 30` (2) `total = 0` followed by a loop doing `total += x` (3) `sum(map(abs, xs))`.
step: Fragment (1) says which rows are wanted and nothing about how to scan or index the table, so it is **declarative**.
step: Fragment (2) changes a variable step by step. A named location is updated repeatedly, which is the mark of the **imperative** style.
step: Fragment (3) builds the result by applying functions to values: `abs` to each item, then `sum` to the results. No variable is updated, so it is **functional** in style.
step: Notice that fragments (2) and (3) can be written in the same language. The paradigm is a property of how the program is written, not only of the language.
answer: (1) declarative, (2) imperative, (3) functional.

@example
title: Expressions versus statements
problem: Which of `x = 4`, `x + 4`, `4 if x else 0` and `print(x)` can appear as the right-hand side of an assignment `y = ...`?
step: The right-hand side of `y = ...` must be an expression, since an assignment needs a value to store.
step: `x = 4` is an assignment statement and produces no value, so `y = x = 4` is a chained assignment, not an assignment of a value from a statement.
step: `x + 4` is an expression. `4 if x else 0` is a conditional expression, so it is allowed.
step: `print(x)` is a call expression. It is allowed, but its value is `None`, so `y` would be `None`.
answer: `x + 4`, `4 if x else 0` and `print(x)` (the last stores `None`).

@mistakes
- Saying "Python is an interpreted language" as if it were a property of the language; interpretation or compilation belongs to an implementation.
- Confusing syntax with semantics: a program can be syntactically valid and still fail at run time or mean something other than you intended.
- Believing each language belongs to exactly one paradigm. Style is a choice made in each program, and most languages support several.
- Treating "functional" as meaning "uses functions". Every language has functions; the functional style avoids mutation and builds results from expressions.
