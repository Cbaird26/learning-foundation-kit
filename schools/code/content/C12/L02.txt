@article
Before a program can be run it has to be read. Reading happens in two layers, and each uses a different tool.

### Tokens: the lexical layer

The **scanner** (or *lexer*, or *tokenizer*) groups characters into **tokens**, the smallest meaningful units: numbers, identifiers, keywords, operators, punctuation. Whitespace and comments usually separate tokens and then vanish. A token has a **kind** and its text (its **lexeme**):

```text
source:  (12 + 3) * 4
tokens:  LPAREN "("   NUM "12"   OP "+"   NUM "3"   RPAREN ")"   OP "*"   NUM "4"
```

The set of valid lexemes for each kind is simple: a number is one or more digits, an identifier is a letter followed by letters and digits. Such patterns are **regular**, which is why regular expressions and finite automata are the classic tools for scanning.

Two rules appear in almost every scanner. **Maximal munch**: take the longest lexeme that matches, so `<=` is one token rather than `<` followed by `=`, and `123` is one number rather than three. **Keywords versus identifiers**: scan an identifier first, then check whether its text is reserved (`if`, `let`).

### Grammars: the phrase layer

Tokens alone do not say how they combine. A **context-free grammar** does. It is a set of **productions**, each rewriting a **nonterminal** (a syntactic category) into a sequence of terminals (tokens) and nonterminals. We write them in **Backus-Naur form (BNF)**. Here is a grammar for sums and products:

```text
expr   -> term  ( "+" term )*
term   -> factor ( "*" factor )*
factor -> NUM | "(" expr ")"
```

The `( ... )*` means "zero or more repetitions" (extended BNF). To **derive** a string, start from the start symbol `expr` and keep replacing a nonterminal using one of its productions until only tokens remain. A string is in the language exactly when some derivation produces it.

The grammar encodes **precedence**. Because `*` is handled lower in the grammar (in `term`) than `+` (in `expr`), a product always groups tighter than a sum: `1 + 2 * 3` has the product `2 * 3` as one operand of the `+`. Repetition in a production also lets the parser fix **associativity**: if the grammar had a `-` operator, a parser that folds the repeated operands from the left would group `10 - 4 - 3` as `(10 - 4) - 3`.

A grammar is **ambiguous** if some string has two different parse trees. The rule `expr -> expr "+" expr | expr "*" expr | NUM` is ambiguous for `1 + 2 * 3`. Layering the grammar (`expr`, `term`, `factor`) removes the ambiguity.

### Writing a tokenizer

A hand-written scanner is a loop over the characters with an index `i`. At each position it looks at the current character and decides which kind of token starts there:

```python
def tokenize(src):
    tokens = []
    i = 0
    while i < len(src):
        ch = src[i]
        if ch.isspace():
            i += 1
        elif ch in "0123456789":
            j = i
            while j < len(src) and src[j] in "0123456789":
                j += 1
            tokens.append(("NUM", src[i:j]))
            i = j
        elif ch in "+-*/":
            tokens.append(("OP", ch))
            i += 1
        else:
            raise ValueError(f"unexpected character {ch!r}")
    return tokens
```

The inner loop implements maximal munch: it extends `j` while digits continue. The scan is linear, $O(n)$ in the length of the source, because each character is examined a constant number of times. An unrecognized character is reported as an error with a clear message, rather than silently skipped.

@example
title: Tokenizing step by step
problem: Trace the tokenizer on `"12+3"`.
step: `i = 0`, `ch = "1"` is a digit. The inner loop advances `j` past `1` and `2` and stops at `+` (`j = 2`). Append `("NUM", "12")` and set `i = 2`.
step: `i = 2`, `ch = "+"` is in `"+-*/"`. Append `("OP", "+")` and set `i = 3`.
step: `i = 3`, `ch = "3"` is a digit. The inner loop stops at `j = 4` because `j == len(src)`. Append `("NUM", "3")` and set `i = 4`.
step: `i = 4` is no longer less than `len(src)`, so the loop ends.
answer: `[("NUM", "12"), ("OP", "+"), ("NUM", "3")]`

@example
title: Deriving a string from a grammar
problem: Using `expr -> term ("+" term)*`, `term -> factor ("*" factor)*` and `factor -> NUM | "(" expr ")"`, show that `1 + 2 * 3` is in the language.
step: Start with `expr` and use one repetition of the `+` part: `expr => term "+" term`.
step: Expand the left `term` as a single factor: `term => factor => NUM`, giving `NUM "+" term`.
step: Expand the right `term` with one `*`: `term => factor "*" factor`, so we now have `NUM "+" factor "*" factor`.
step: Replace each remaining `factor` by `NUM`, giving `NUM "+" NUM "*" NUM`, which matches `1 + 2 * 3`. The `*` was produced inside a `term`, so the product groups first.
answer: The string is derivable, and `2 * 3` forms one operand of `+`.

@mistakes
- Splitting the source on spaces instead of scanning characters; `12+3` has no spaces but still contains three tokens.
- Forgetting maximal munch, so `123` becomes three number tokens or `<=` becomes two tokens.
- Reading past the end of the string in the inner digit loop because the `j < len(src)` check is missing or comes after `src[j]`.
- Mixing up the layers: whether `1 + * 2` is valid is a grammar question, while whether `?` is a legal character is a lexical question.

def tokenize(src):

        ch = src[i]
        if ch.isspace():

        elif ch in "0123456789":

model:
```python
def strip_comments(src):
    out = []
    i = 0
    while i < len(src):
        if src[i] == "#":
            while i < len(src) and src[i] != "\n":
                i += 1
        else:
            out.append(src[i])
            i += 1
    return "".join(out)
```
hint: Scan one character at a time, like a tokenizer, and keep a list of the characters you keep.
hint: When you see `#`, advance the index until you reach a newline or the end, without appending anything, and leave the newline for the next pass.
solution: Scan with an index. On `#`, skip characters until the newline (which is not consumed), otherwise copy the character. The second `#` in `x # a # b` is inside the comment and disappears with it.
