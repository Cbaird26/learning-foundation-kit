@article
A **shell** is a program that reads a line you type, runs the command it names, and shows the result. The most common one on Linux and in older macOS versions is **bash**; recent macOS uses **zsh**, which behaves almost identically for everything in this course. On Windows you can use the Windows Subsystem for Linux or Git Bash. Using the shell is faster than clicking once you can **repeat, combine and script** your actions, which is the theme of the next three weeks.

### The filesystem is a tree

Everything lives in one tree whose top is the **root directory** `/`. A **path** names a place in the tree. An **absolute path** starts with `/` (for example `/home/ana/docs`). A **relative path** does not, and is read starting from the **current working directory**. Three shortcuts matter: `.` is the current directory, `..` is its parent, and `~` expands to your home directory.

| command | what it does |
|---|---|
| `pwd` | print the working directory |
| `cd dir` | change directory (`cd` alone or `cd ~` goes home, `cd -` returns to the previous directory) |
| `ls`, `ls -l`, `ls -a` | list names; long format with sizes and times; include hidden names that start with `.` |
| `mkdir -p a/b/c` | make a directory, creating missing parents |
| `touch f` | create an empty file, or update its modification time |
| `cp f g`, `cp -r d e` | copy a file; copy a directory recursively |
| `mv f g` | rename `f` to `g`, or move it into `g` if `g` is a directory |
| `rm f`, `rm -r d` | delete a file; delete a directory and everything in it |
| `cat f`, `less f` | print a file; page through it (`q` quits) |
| `head -n 5 f`, `tail -n 5 f`, `wc -l f` | first lines, last lines, count of lines |

**There is no recycle bin.** `rm` removes the name immediately, and `rm -rf` (recursive, no questions) is the classic way to destroy work. Run `ls` with the same pattern first to see what a command will touch, and prefer `rm -i` when unsure.

### Globs and quoting

Before running a command, the shell expands **glob patterns** into matching names: `*` matches any run of characters (including none), `?` matches exactly one character, and `[ab]` matches one of the listed characters. So `mv *.txt archive/` becomes `mv a.txt b.txt archive/` before `mv` ever starts: the program never sees the `*`. By default a leading `.` is not matched by `*`, which is why `*` skips hidden files.

The shell splits a line into words at spaces. A file named `my notes.txt` therefore needs quotes: `cat "my notes.txt"` or `cat my\ notes.txt`. Double quotes still allow variable expansion; single quotes are fully literal. Quote a variable such as `"$HOME"` whenever its value could contain spaces.

### Getting help

`man ls` opens the manual page for `ls` (`q` to leave, `/word` to search), and most commands accept `--help`. Press Tab to complete names and the Up arrow to recall earlier lines. These habits save more time than any single command.

@example
title: Tracing `cd` through relative paths
problem: You start in `/home/ana`. You run `cd projects/web`, then `cd ../data`, then `cd ../../..`. What does `pwd` print?
step: `cd projects/web` is relative, so the directory becomes `/home/ana/projects/web`.
step: `cd ../data` first goes up to `/home/ana/projects`, then down into `data`: `/home/ana/projects/data`. The directory `data` must already exist, or `cd` reports an error and stays where it was.
step: `cd ../../..` climbs three levels from `/home/ana/projects/data`: to `projects`, then `ana`, then `home`.
step: The result is `/home`, which `pwd` prints.
answer: `/home`

@mistakes
- Forgetting that `rm` is permanent, and running `rm -rf` with a wrong or unquoted path (a stray space in `rm -rf ~/work /tmp` deletes two trees).
- Leaving a space unquoted so `cat my notes.txt` looks for two files, `my` and `notes.txt`.
- Using `mv` or `cp` onto an existing name without noticing: both silently overwrite unless you add `-i`.
- Thinking `cd ..` from `/` is an error: the parent of the root is the root itself.

def normalize_path(path):
    parts = []
    for piece in path.split("/"):
        if piece in ("", "."):
            continue
        if piece == "..":
            if parts:
                parts.pop()
        else:
            parts.append(piece)
    return "/" + "/".join(parts)
```

Ignore bracket expressions and the rule about leading dots. Example: `glob_match("*.txt", "notes.txt")` is `True`.

```
tests:
```python
assert glob_match("*.txt", "notes.txt") is True
assert glob_match("*.txt", "notes.txt.bak") is False
assert glob_match("file?.c", "file1.c") is True
assert glob_match("file?.c", "file10.c") is False
assert glob_match("*", "") is True
assert glob_match("a*b*c", "aXXbYYc") is True
assert glob_match("?", "") is False
```
model:
```python
def glob_match(pattern, name):
    if not pattern:
        return not name
    if pattern[0] == "*":
        if glob_match(pattern[1:], name):
            return True
        return bool(name) and glob_match(pattern, name[1:])
    if name and (pattern[0] == "?" or pattern[0] == name[0]):
        return glob_match(pattern[1:], name[1:])
    return False
```
hint: Use recursion on the first character of the pattern.
hint: For `*`, either it matches nothing (drop the `*`) or it swallows one more character of `name` (keep the `*`, drop one character).
solution: An empty pattern matches only an empty name. A leading `*` tries matching zero characters, then one more character at a time. `?` and literal characters consume one character of each string, and anything else fails.
