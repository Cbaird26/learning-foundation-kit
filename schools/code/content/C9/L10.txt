@article
The internet has hundreds of thousands of networks and a global table of about a million IPv4 prefixes. One routing algorithm for all of it would not scale, and organizations want to control their own routing. So the internet is divided into **autonomous systems (ASes)**: collections of routers under one administration, each with an **AS number**. Routing is **hierarchical**: an **intra-AS** (interior gateway) protocol runs inside each AS and the **inter-AS** protocol, BGP, connects the ASes.

### Intra-AS routing: OSPF

**OSPF** (Open Shortest Path First, OSPFv2 is RFC 2328) is a **link-state** protocol. Each router floods link-state advertisements to all routers in its area, builds the same topology database and runs Dijkstra's algorithm. Link costs are set by the administrator (often inversely related to bandwidth). OSPF messages are carried directly in IP datagrams (protocol number 89), not in TCP or UDP. A large AS is split into **areas**, joined through a backbone area (area 0), which limits flooding. IS-IS is a similar link-state protocol. **RIP** is an older distance-vector protocol with a hop-count metric and a maximum of 15 hops.

### Inter-AS routing: BGP

**BGP** (Border Gateway Protocol, BGP-4 is RFC 4271) is the protocol that holds the internet together. Neighboring routers set up a TCP connection (port 179) and exchange **route announcements** for prefixes: "I can reach 203.0.113.0/24 via this AS path". A route carries attributes, notably:

- **AS-PATH**: the list of ASes the announcement has passed through. A router **prepends its own AS number** when it announces a route to a neighbor in another AS, and **discards any route that already contains its own AS number**, which prevents loops. BGP is therefore called a **path-vector** protocol.
- **NEXT-HOP**: the router interface to send packets to.
- **LOCAL-PREF**: a local preference set by policy inside an AS.

**eBGP** runs between ASes and **iBGP** distributes routes learned from outside to the routers inside an AS.

A router often hears several routes to the same prefix and picks one with a **decision process**. The first rules are, in order: (1) highest LOCAL-PREF; (2) shortest AS-PATH; (3) closest NEXT-HOP according to the intra-AS routing cost (**hot-potato routing**: get the packet out of my AS as soon as possible); then further tie-breakers, ending with the lowest router ID. (Real routers also apply the MED attribute and eBGP-over-iBGP preference between these steps.) The first rule shows that BGP routes by **policy**, not by cost.

### Business relationships and policy

An AS usually pays its **provider** for transit, is paid by its **customers**, and exchanges traffic free with **peers**. The export rules follow the money: an AS announces its customers' routes to everyone, but announces routes learned from a provider or peer only to its customers (otherwise it would carry transit traffic for free). Customers get a higher LOCAL-PREF than peers and providers.

BGP trusts what neighbors announce. A mistaken or malicious announcement of someone else's prefix (a **prefix hijack**) or a **route leak** can redirect or black-hole traffic. **RPKI** lets prefix owners publish signed records authorizing which AS may originate a prefix, so routers can reject invalid origins; it is being deployed widely.

### Network address translation (NAT)

IPv4 addresses are scarce, so a home or company network often uses private addresses behind one public address. A **NAT** router rewrites packets: for an outgoing packet from private `(192.168.0.2, 5000)` it picks an unused public port, say 50000, rewrites the source to `(203.0.113.1, 50000)` and records the mapping in its **NAT translation table**. A reply addressed to port 50000 is looked up and rewritten back to `(192.168.0.2, 5000)`. A packet that arrives with no mapping is normally dropped. With about 64 000 usable ports, one public address supports tens of thousands of simultaneous flows. NAT works, but it violates the end-to-end principle: outside hosts cannot start a connection to an inside host without **port forwarding** or traversal techniques, and it modifies packets (and port numbers inside application data can break). IPv6 removes the shortage that motivated NAT; carrier-grade NAT (`100.64.0.0/10`) is NAT applied by the provider.

@example
title: Choosing a BGP route
problem: A router has heard three routes to 198.51.100.0/24: route 1 with LOCAL-PREF 100 and AS-PATH [20, 30], route 2 with LOCAL-PREF 100 and AS-PATH [40], route 3 with LOCAL-PREF 80 and AS-PATH [50]. Which does it choose? Would it accept a route with AS-PATH [60, 10, 70] if its own AS number is 10?
step: LOCAL-PREF first: routes 1 and 2 have 100, route 3 only 80, so route 3 is eliminated even though it is also short.
step: Tie between routes 1 and 2: the shorter AS-PATH wins. Route 2 has length 1, route 1 has length 2.
step: The router chooses route 2.
step: A path containing the router's own AS number (10) means the announcement went through this AS before, so accepting it would create a loop: the router discards it.
answer: Route 2; the route containing AS 10 is discarded.

@example
title: A NAT translation
problem: A NAT router has public address 203.0.113.1 and assigns public ports from 50000 upward. Host 192.168.0.2 sends from port 5000, then host 192.168.0.3 sends from port 5000. What happens to the first host's replies?
step: First packet: source `(192.168.0.2, 5000)`; the NAT assigns port 50000, rewrites the source to `(203.0.113.1, 50000)` and stores the mapping.
step: Second host: its source port 5000 is the same number but a different private address, so it gets a different mapping: `(192.168.0.3, 5000)` becomes `(203.0.113.1, 50001)`.
step: A reply to `(203.0.113.1, 50000)` matches the first mapping and is rewritten to destination `(192.168.0.2, 5000)`; one to port 50001 goes to the second host.
step: Further packets from `(192.168.0.2, 5000)` reuse port 50000: the mapping is per flow, not per packet.
answer: Replies to port 50000 go to 192.168.0.2:5000; replies to port 50001 go to 192.168.0.3:5000.

@mistakes
- Believing BGP chooses the lowest-cost path. Policy (LOCAL-PREF) comes first, then the shortest AS path.
- Confusing the AS-PATH check with TTL. The AS-PATH check is what stops BGP routing loops between ASes.
- Saying that OSPF runs over TCP or UDP. It runs directly over IP.
- Thinking NAT provides security by design. It blocks unsolicited inbound traffic only as a side effect of having no mapping; it is not a substitute for a firewall.

model:
```python
class NatTable:
    def __init__(self, public_ip, first_port=50000):
        self.public_ip = public_ip
        self.next_port = first_port
        self.out_map = {}
        self.in_map = {}

    def outbound(self, src_ip, src_port):
        key = (src_ip, src_port)
        if key not in self.out_map:
            self.out_map[key] = self.next_port
            self.in_map[self.next_port] = key
            self.next_port += 1
        return (self.public_ip, self.out_map[key])

    def inbound(self, public_port):
        return self.in_map.get(public_port)
```
hint: Keep two dictionaries: one from internal endpoint to public port and one back.
hint: Only allocate a new port when the internal endpoint is not already in the first dictionary.
solution: `outbound` looks up the internal endpoint, allocates `next_port` if it is new (recording the mapping in both directions) and returns the public address with the port. `inbound` is a lookup in the reverse dictionary.

```python
def best_route(routes):
    if not routes:
        return None
    return min(routes, key=lambda r: (-r["local_pref"], len(r["as_path"]), r["router_id"]))
```

(b) Run the distance-vector (Bellman-Ford) computation from the point of view of the destination S: in synchronous rounds, each node sets its estimate to the minimum over its neighbors of the neighbor's previous-round estimate plus the link cost (S stays 0, the others start at infinity, and estimates never increase). solution: (a) Start S 0. Finalize S: U = 3, T = 9. Finalize U (3): T = min(9, 3 + 4) = 7, W = 3 + 6 = 9. Finalize T (7): V = 7 + 2 = 9.
