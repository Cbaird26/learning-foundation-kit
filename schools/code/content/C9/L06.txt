@article
IP is best effort: packets can be lost, duplicated, delayed or reordered. A **reliable transport protocol** hides this from the application. The tools are **acknowledgments** (ACKs) from the receiver, **sequence numbers** to detect loss and duplication, **timeouts** and **retransmissions**, and, for speed, a **window** of unacknowledged data.

### Stop-and-wait

The sender transmits one packet, waits for its ACK, and retransmits if a timer expires. It is correct but slow. If a packet has $L$ bits, the link has rate $R$ and the round-trip time is RTT, the sender is busy for $L/R$ seconds out of every $\text{RTT} + L/R$, so the **utilization** is

$$U_{\text{sender}} = \frac{L/R}{\text{RTT} + L/R}.$$

On a 1 Gb/s link with a 30 ms RTT, a 1000-byte packet gives $U \approx 0.00027$: the link is idle almost all the time. The cure is **pipelining**: keep $W$ packets in flight, so utilization is about $W \cdot (L/R)/(\text{RTT} + L/R)$ until it reaches 1.

### Sliding-window protocols

- **Go-Back-N (GBN):** the sender may have up to $N$ unacknowledged packets. The receiver accepts only the next expected packet and sends a **cumulative ACK** for the highest in-order packet. On a timeout the sender retransmits the oldest unacknowledged packet **and all later ones**.
- **Selective repeat (SR):** the receiver buffers out-of-order packets and acknowledges each one individually; the sender keeps a timer per packet and retransmits only the lost ones. Selective repeat needs a window size of at most half the sequence-number space to avoid confusing old and new packets.

### TCP

**TCP** (RFC 9293) provides a reliable, ordered, full-duplex **byte stream** between two processes, after a connection is established. It is a hybrid of these ideas.

- **Sequence numbers count bytes**, not segments. The header's 32-bit sequence number is the stream position of the first data byte of the segment. The **acknowledgment number** is the sequence number of the **next byte expected**, and it is cumulative: `ack = 1301` means "all bytes before 1301 arrived".
- The header has source and destination ports, sequence and acknowledgment numbers, flag bits (**SYN**, **ACK**, **FIN**, **RST**, **PSH**), a 16-bit receive window (week 7), a checksum and options (such as the MSS); the minimum size is 20 bytes.
- **Three-way handshake:** the client sends SYN with its **initial sequence number** (ISN) $x$; the server replies SYN-ACK with its ISN $y$ and ack $x+1$; the client sends ACK with ack $y+1$ (and may carry data). A SYN consumes one sequence number, as does a FIN. The ISNs are chosen unpredictably to avoid old segments being accepted and to make off-path spoofing harder.
- **Teardown:** each side sends FIN when it is done sending and the other acknowledges it, so a normal close takes four segments (the middle two can be combined). The side that closes first waits in **TIME-WAIT** for twice the maximum segment lifetime before the connection is fully forgotten. A **RST** aborts a connection.
- **Duplicate ACKs and fast retransmit:** if a segment is lost, later segments cause the receiver to repeat the same ACK. After **three duplicate ACKs** the sender retransmits the missing segment without waiting for the timer.

### Setting the timeout

The timeout must exceed the RTT but not by much. TCP measures RTT samples and keeps a smoothed average and a variance (RFC 6298). For the first sample $R$: $\text{SRTT} = R$, $\text{RTTVAR} = R/2$. For each later sample $R$ (using the old SRTT):

$$\text{RTTVAR} \leftarrow (1-\beta)\,\text{RTTVAR} + \beta\,|\text{SRTT} - R|,\qquad \text{SRTT} \leftarrow (1-\alpha)\,\text{SRTT} + \alpha R,$$

with $\alpha = 1/8$ and $\beta = 1/4$, and $\text{RTO} = \text{SRTT} + 4\,\text{RTTVAR}$ (real implementations also enforce a minimum, and back off the timer exponentially after each timeout). Samples are never taken from retransmitted segments, because it is ambiguous which transmission an ACK refers to (Karn's algorithm).

@example
title: Stop-and-wait utilization
problem: A sender uses stop-and-wait with 8000-bit packets on a 1 Gb/s link; RTT is 30 ms. Find the utilization, and the window needed to keep the link busy.
step: Transmission time $L/R = 8000/10^9 = 8\ \mu\text{s}$.
step: $U = 8\ \mu\text{s} / (30\,000\ \mu\text{s} + 8\ \mu\text{s}) \approx 0.000267$, about 0.027 percent.
step: To fill the pipe the sender needs about $(\text{RTT} + L/R)/(L/R) = 30\,008/8 = 3751$ packets in flight.
answer: utilization about 0.027 percent; a window of about 3751 packets

@example
title: A short TCP conversation
problem: A client with ISN 4000 connects to a server with ISN 9000, sends 100 bytes, receives 200 bytes, and the client acknowledges. Give the segments.
step: Client SYN: `seq=4000`. Server SYN-ACK: `seq=9000, ack=4001` (the SYN used up number 4000). Client ACK: `seq=4001, ack=9001`.
step: Client sends 100 bytes: `seq=4001`, bytes 4001 to 4100. Server ACK: `seq=9001, ack=4101`.
step: Server sends 200 bytes: `seq=9001`, bytes 9001 to 9200 (it may carry `ack=4101` in the same segment).
step: Client ACK: `seq=4101, ack=9201`: it expects byte 9201 next.
answer: The acknowledgment number is always the next byte expected: 4101 for the client's data and 9201 for the server's.

@mistakes
- Treating TCP sequence numbers as segment counts. They count bytes, and a SYN or FIN counts as one byte.
- Reading `ack = n` as "I received segment n". It means that every byte before `n` was received and `n` is expected next.
- Forgetting that stop-and-wait utilization uses RTT plus the transmission time in the denominator.
- Mixing up GBN and selective repeat: GBN retransmits everything after the loss, SR only the lost packet.

```python
def estimate_rtt(samples):
```

```python
    rttvar = samples[0] / 2
```

```python
def tcp_acks(arrivals):
    received = set()
    expected = 0
    acks = []
    for seg in arrivals:
        received.add(seg)
        while expected in received:
            expected += 1
        acks.append(expected)
    return acks
```

```python
def seq_numbers(isn, sizes):

```
tests:
```python
assert seq_numbers(1000, [300, 500]) == [(1000, 1300), (1300, 1800)]
assert seq_numbers(2**32 - 100, [300]) == [(4294967196, 200)]
assert seq_numbers(0, []) == []
assert seq_numbers(2**32 - 1, [1, 1]) == [(4294967295, 0), (0, 1)]
```
model:
```python
def seq_numbers(isn, sizes):
    result = []
    seq = isn % 2**32
    for size in sizes:
        nxt = (seq + size) % 2**32
        result.append((seq, nxt))
        seq = nxt
    return result
```
hint: Each segment starts where the previous one ended.
hint: Take every sum modulo `2**32`, so values wrap around to 0.
solution: Keep the current sequence number, add the segment size modulo $2^{32}$ to get the next one, record the pair, and continue from the next number.
