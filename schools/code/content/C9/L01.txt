@article
The internet is a network of networks that moves data in small pieces called **packets**. Each packet travels from its source through a series of **links** (copper, fibre, radio) and **routers** or **switches**, which forward it toward its destination. This is **packet switching**: all traffic shares the links and the capacity is used on demand. The alternative, **circuit switching** (the old telephone network), reserves a fixed share of each link for the whole call, which wastes capacity when a source is silent but guarantees a rate.

### The four delays at each hop

When a packet arrives at a router and leaves on the next link, it suffers four delays:

- **Processing delay** $d_{\text{proc}}$: examining the header, checking for bit errors, choosing the output link. Typically microseconds or less.
- **Queuing delay** $d_{\text{queue}}$: waiting in the output buffer while earlier packets are sent. It varies from packet to packet, from zero to very large.
- **Transmission delay** $d_{\text{trans}} = L/R$: the time to push all $L$ bits of the packet onto a link of rate $R$ bits per second. It depends on packet size and link **rate**, not on link length.
- **Propagation delay** $d_{\text{prop}} = d/s$: the time for one bit to travel a link of length $d$ metres at propagation speed $s$. In fibre and copper $s$ is about $2 \times 10^8$ m/s. It depends on link **length**, not on the rate.

The nodal delay is the sum $d_{\text{nodal}} = d_{\text{proc}} + d_{\text{queue}} + d_{\text{trans}} + d_{\text{prop}}$. Do not confuse the last two terms: a 1 Gb/s link is not "faster" in the sense of propagation, since a bit still needs 5 ms to cross 1000 km of fibre. A rate of $R$ bits per second is called the **bandwidth** (or link rate) of the link; the unit is bits, so a 1500-byte packet is $12\,000$ bits.

### Store-and-forward

Routers use **store-and-forward**: the whole packet must arrive before the first bit is sent onward. A single packet of $L$ bits across $N$ links of equal rate $R$ (ignoring propagation, processing and queuing) takes $N \cdot L/R$. If $P$ packets are sent back to back, the links work like a pipeline: the first packet arrives after $N \cdot L/R$, and each later packet arrives $L/R$ after the previous one, so the last arrives at

$$T = (N + P - 1)\,\frac{L}{R}.$$

### Queues and loss

Let $a$ be the average packet arrival rate (packets per second). The **traffic intensity** is $La/R$, the average bits arriving per second divided by the bits the link can send per second. If $La/R$ is close to 0 queues are nearly empty. As it approaches 1 the average queuing delay grows sharply, and if $La/R > 1$ the backlog grows without bound. Router buffers are finite, so when the buffer is full an arriving packet is **dropped**: this is **packet loss**. A lost packet may be retransmitted by a higher layer, which is one reason loss and delay are both visible to users.

### Throughput

**Throughput** is the rate at which bits actually arrive at the receiver. For a path of links with rates $R_1, \dots, R_k$ carrying one flow, the throughput is limited by the **bottleneck link**: $\min(R_1,\dots,R_k)$. Transferring $F$ bits then takes about $F/\min(R_i)$ seconds, plus the delays above. When many flows share the bottleneck, each gets roughly its share of that rate.

The **bandwidth-delay product** $R \times \text{RTT}$ is the number of bits "in flight" on a path when the sender keeps the link full; we use it again in the transport weeks.

@example
title: End-to-end delay of one packet
problem: A host sends one 1500-byte packet through one router to a server. Link 1 is 100 km long with rate 10 Mb/s; link 2 is 500 km long with rate 5 Mb/s. Propagation speed is $2 \times 10^8$ m/s. Ignore processing and queuing. How long until the last bit reaches the server?
step: The packet has $L = 1500 \times 8 = 12\,000$ bits.
step: Link 1: $d_{\text{trans}} = 12\,000 / (10 \times 10^6) = 1.2$ ms and $d_{\text{prop}} = 10^5 / (2 \times 10^8) = 0.5$ ms, so 1.7 ms.
step: Store-and-forward: the router waits for the whole packet, so link 2 starts after 1.7 ms. Link 2: $d_{\text{trans}} = 12\,000 / (5 \times 10^6) = 2.4$ ms and $d_{\text{prop}} = 5 \times 10^5 / (2 \times 10^8) = 2.5$ ms, so 4.9 ms.
step: Add the hops: $1.7 + 4.9 = 6.6$ ms.
answer: 6.6 ms

@example
title: A stream of packets through a pipeline
problem: Four packets of 12 000 bits are sent back to back over three store-and-forward links, each 12 Mb/s. Ignoring propagation, when does the last packet arrive?
step: One transmission takes $L/R = 12\,000 / (12 \times 10^6) = 1$ ms.
step: The first packet needs 3 transmissions, one per link, so it arrives at 3 ms.
step: The remaining 3 packets each arrive 1 ms after the one before, because the bottleneck sends one packet per millisecond.
step: The last packet arrives at $3 + 3 = 6$ ms, which matches $(N + P - 1)L/R = (3 + 4 - 1)(1\text{ ms})$.
answer: 6 ms

@mistakes
- Using the link length in the transmission delay or the link rate in the propagation delay. Transmission delay is size over rate; propagation delay is distance over speed.
- Mixing bytes and bits: packet sizes are usually quoted in bytes and link rates in bits per second, so multiply bytes by 8.
- Forgetting store-and-forward, and charging only one transmission delay for a multi-hop path.
- Believing that a faster link always shortens propagation delay: it shortens transmission delay only.
