@article
A network is too complex to design as one piece, so it is built in **layers**. Each layer provides a **service** to the layer above, using only the services of the layer below, and the details of how it works are hidden behind that interface. A layer can change (Wi-Fi replaces Ethernet, QUIC replaces TCP for some traffic) without rewriting the layers around it. The rules for how two peers at the same layer talk to each other form a **protocol**; the protocols are written down in documents called **RFCs** (published by the IETF) and, for Ethernet and Wi-Fi, in IEEE standards.

### The five-layer internet model

| Layer | Job | Examples | PDU name |
|---|---|---|---|
| Application | network applications | HTTP, DNS, SMTP | message |
| Transport | process-to-process delivery | TCP, UDP | segment (TCP), datagram (UDP) |
| Network | host-to-host delivery across networks | IP, routing protocols | packet or datagram |
| Link | delivery across one link | Ethernet, Wi-Fi | frame |
| Physical | bits on the medium | copper, fibre, radio | bits |

The **OSI model** has seven layers: it splits the application layer into application, presentation and session. The internet protocols do not have separate presentation and session layers; applications handle formatting and sessions themselves. IP is called the **narrow waist** of the internet: many applications and many link technologies, but one network-layer protocol in the middle.

### Encapsulation

A sender's application hands a message to the transport layer, which prepends a **header** to make a segment. The network layer prepends its header to make a packet, and the link layer adds a header (and often a trailer) to make a frame. This wrapping is **encapsulation**; the receiver reverses it, **decapsulating** layer by layer. Minimum header sizes you should know:

- TCP header: 20 bytes (more with options). UDP header: 8 bytes.
- IPv4 header: 20 bytes (more with options). IPv6 header: 40 bytes.
- Ethernet: 14-byte header (destination MAC 6, source MAC 6, EtherType 2) and a 4-byte trailer, the frame check sequence (FCS). The preamble is not counted in the frame size.

The largest payload an Ethernet frame carries is the **MTU** (maximum transmission unit), 1500 bytes. With TCP and IPv4, the **MSS** (maximum segment size, the largest TCP payload) is therefore $1500 - 20 - 20 = 1460$ bytes. A message larger than the MSS is split across several segments, and every one of them pays the header overhead. Ethernet also requires a payload of at least 46 bytes; shorter payloads are padded.

### Who looks at which header

A **switch** forwards frames using only the link-layer header. A **router** removes the incoming frame's link header, reads the network-layer header to choose an output link, decrements the **TTL** (time to live, which stops packets looping forever), recomputes the header checksum in IPv4, and wraps the packet in a new frame for the next link. The source and destination IP addresses stay the same end to end (unless NAT rewrites them, week 10), but the MAC addresses change at every hop. Transport headers are examined only by the end hosts, which is the **end-to-end principle**: functions such as reliability are best implemented at the ends, because only the ends know whether the data really arrived.

### Costs of layering

Layers hide detail, but they add header overhead and can hide information that a layer would like to use (for example, a transport protocol cannot see that a link is wireless). The benefit is modularity and the ability to evolve one layer at a time.

@example
title: Bytes on the wire for a message
problem: An application sends a 3000-byte message with TCP over IPv4 over Ethernet, with no options and an MTU of 1500. How many segments are sent, and how many bytes cross the link in total (count Ethernet header and FCS, not the preamble)? How long does that take at 100 Mb/s?
step: The MSS is $1500 - 20 - 20 = 1460$ bytes, so the payloads are 1460, 1460 and $3000 - 2920 = 80$ bytes: 3 segments.
step: Every frame adds $20 + 20 + 14 + 4 = 58$ bytes of headers and trailer, so the frames are 1518, 1518 and 138 bytes.
step: Total on the wire: $1518 + 1518 + 138 = 3174$ bytes, which equals $3000 + 3 \times 58$.
step: Transmission time: $3174 \times 8 = 25\,392$ bits at $10^8$ bits per second is $253.92\ \mu\text{s}$.
answer: 3 segments, 3174 bytes, 253.92 microseconds

@example
title: Following headers through a router
problem: Host A (IP 10.0.1.5) sends a packet to server S (IP 203.0.113.9) through one router. Which header fields differ in the frame on the A-to-router link and in the frame on the router-to-S link?
step: On both links the IP source is 10.0.1.5 and the IP destination is 203.0.113.9: the IP addresses name the end hosts and do not change.
step: The Ethernet destination of the first frame is the router's interface MAC; the source is A's MAC. The router strips this header.
step: For the second link the router builds a new Ethernet header: source is the router's other interface, destination is S's MAC (or the next hop's).
step: The IP TTL is one smaller in the second packet and its header checksum is recomputed. The TCP header and payload are unchanged.
answer: The Ethernet addresses, FCS, IP TTL and IP header checksum differ; everything else is the same.

@mistakes
- Saying that a router changes the IP addresses of a packet. It changes the link-layer addresses; only a NAT rewrites IP addresses.
- Forgetting that every frame, not every message, pays the header overhead, so small segments waste more bandwidth.
- Counting the 1500-byte MTU as the amount of application data. The MTU includes the IP and TCP headers.
- Thinking that a switch reads IP addresses or TCP ports. An ordinary switch uses only the Ethernet header.

```python
def wire_bytes(message, mss=1460, overhead=58):

```
tests:
```python
assert wire_bytes(3000) == 3174
assert wire_bytes(1460) == 1518
assert wire_bytes(1461) == 1577
assert wire_bytes(0) == 0
assert wire_bytes(100, mss=500, overhead=40) == 140
```
model:
```python
def wire_bytes(message, mss=1460, overhead=58):
    segments = -(-message // mss)
    return message + segments * overhead
```
hint: First find how many segments are needed: a division that rounds up.
hint: `-(-message // mss)` is ceiling division for positive integers; the result is `message + segments * overhead`.
solution: The number of segments is the ceiling of `message / mss`. Each adds `overhead` bytes, so the total is `message + segments * overhead`. For 1461 bytes there are 2 segments, so 1461 plus 2 times 58 is 1577.

@quiz code
prompt: Write `segment_sizes(message, mss)` that returns the list of payload sizes, in order, into which a message of `message` bytes is split when each segment carries at most `mss` bytes. For example `segment_sizes(3000, 1460)` is `[1460, 1460, 80]`. A message of 0 bytes gives the empty list.
starter:
```python
def segment_sizes(message, mss):
    pass
```
tests:
```python
assert segment_sizes(3000, 1460) == [1460, 1460, 80]
assert segment_sizes(1460, 1460) == [1460]
assert segment_sizes(1, 1460) == [1]
assert segment_sizes(0, 1460) == []
assert segment_sizes(10, 4) == [4, 4, 2]
```
model:
```python
def segment_sizes(message, mss):
    sizes = []
    remaining = message
    while remaining > 0:
        size = min(mss, remaining)
        sizes.append(size)
        remaining -= size
    return sizes
```
hint: Keep track of how many bytes remain and take at most `mss` of them each time.
hint: Use a `while remaining > 0:` loop with `min(mss, remaining)`.
solution: Repeatedly take `min(mss, remaining)` bytes until nothing remains. Full segments come first and the last one holds the leftover, which is why the sizes for 3000 bytes are 1460, 1460 and 80.
