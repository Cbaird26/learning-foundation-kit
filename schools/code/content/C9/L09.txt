@article
Routing is the network-wide process that fills the forwarding tables. We model the network as a graph: nodes are routers, edges are links, and each edge has a **cost** (a hop count, a delay, or a value set by an administrator). A routing algorithm finds a **least-cost path** from each router to each destination. Two families are used.

### Link-state routing and Dijkstra's algorithm

In **link-state** routing every router learns the **whole topology**: each router measures the cost to its neighbors and **floods** this information in link-state advertisements to all other routers. Each router then runs **Dijkstra's algorithm** locally on the same graph. Dijkstra's algorithm needs all link costs to be non-negative. Let $D(v)$ be the current best known cost from the source $s$ to $v$.

1. Set $D(s) = 0$ and $D(v) = \infty$ for all other $v$; let $N'$ (the finished set) be empty.
2. Pick the node $u$ not in $N'$ with the smallest $D(u)$ and add it to $N'$; its cost is now final.
3. For each neighbor $v$ of $u$ not in $N'$, set $D(v) \leftarrow \min(D(v),\, D(u) + c(u,v))$.
4. Repeat from step 2 until all reachable nodes are in $N'$.

With a simple array the running time is $O(V^2)$; with a binary heap (priority queue) it is $O((V + E)\log V)$. To build the **forwarding table**, a router records for each destination the **first hop** of its least-cost path. Link-state protocols (OSPF, IS-IS) converge quickly and react to changes by flooding, but cost memory (the full topology) and flooding messages. If link costs depend on traffic, route oscillations can occur.

### Distance-vector routing and Bellman-Ford

In **distance-vector** routing each router knows only its neighbors and the link costs to them, and keeps a **vector** of its current cost estimates to every destination. The algorithm rests on the Bellman-Ford equation

$$d_x(y) = \min_{v \in \text{neighbors}(x)} \{\, c(x,v) + d_v(y) \,\}.$$

Each router sends its vector to its neighbors whenever it changes, and recomputes with the equation when it receives a neighbor's vector. The process is **iterative, asynchronous and distributed**, and, if no link cost changes, it converges to the true least costs. The centralized **Bellman-Ford algorithm** relaxes every edge $V - 1$ times and takes $O(VE)$ time; it handles negative edge weights and can detect a negative cycle (a further relaxation still improves a distance).

**Good news travels fast, bad news slowly.** If a link cost falls, neighbors learn it within a few exchanges. If a link cost rises or a link fails, routers may route through each other in a loop and raise their estimates a little at a time: **count to infinity**. For example, if $z$ reaches $x$ only through $y$, and $y$'s link to $x$ fails, $y$ may believe $z$ still has a path to $x$ and adopt it through $z$ itself. Remedies: define a small value as "infinity" (RIP uses 16 hops, so its maximum usable path is 15 hops) and **poison reverse**: if $z$ routes to $x$ through $y$, then $z$ tells $y$ that its distance to $x$ is infinite, so $y$ never routes back through $z$. Poison reverse removes two-node loops but not all longer loops.

### Comparison

| | Link state | Distance vector |
|---|---|---|
| Knowledge | full topology | neighbors' vectors |
| Messages | flooding to all routers | to neighbors only |
| Computation | Dijkstra at each router | Bellman-Ford equation, shared work |
| Convergence | fast | can be slow (count to infinity) |
| A faulty router | advertises only its own links wrongly | can advertise wrong paths to everyone |

@example
title: Running Dijkstra's algorithm
problem: Graph (undirected): A-B 2, A-C 5, B-C 1, B-D 4, C-D 1, C-E 7, D-E 3. Find least costs from A.
step: Start: $D(A) = 0$, everything else $\infty$. Finish A: $D(B) = 2$, $D(C) = 5$.
step: Smallest unfinished is B (2). Update C: $\min(5, 2+1) = 3$; D: $2 + 4 = 6$.
step: Next C (3). Update D: $\min(6, 3+1) = 4$; E: $3 + 7 = 10$.
step: Next D (4). Update E: $\min(10, 4+3) = 7$. Finally E (7) is finished.
step: Result: A 0, B 2, C 3, D 4, E 7; the path to E is A-B-C-D-E, so A's first hop to every destination is B.
answer: A 0, B 2, C 3, D 4, E 7

@example
title: A distance-vector update
problem: Router x has neighbors y (link cost 2) and z (link cost 7). It receives $d_y = \{x{:}2,\ y{:}0,\ z{:}1\}$ and $d_z = \{x{:}7,\ y{:}1,\ z{:}0\}$. Compute x's new vector.
step: For destination y: via y it costs $2 + 0 = 2$; via z it costs $7 + 1 = 8$. The minimum is 2.
step: For destination z: via y it costs $2 + 1 = 3$; via z it costs $7 + 0 = 7$. The minimum is 3.
step: Destination x itself costs 0.
step: x's vector is $\{x{:}0,\ y{:}2,\ z{:}3\}$ and its path to z goes through y, so it improved from 7 to 3.
answer: x: 0, y: 2, z: 3

@mistakes
- Using Dijkstra's algorithm on a graph with negative edge weights. It can finalize a node too early; use Bellman-Ford.
- Forgetting that the forwarding table stores the first hop, not the whole path or only the distance.
- Believing that distance-vector routers know the topology. They know only distances and neighbors.
- Thinking poison reverse eliminates all routing loops. It handles only loops between two neighbors.

model:
```python
import heapq


def dijkstra(graph, source):
    dist = {}
    heap = [(0, source)]
    while heap:
        d, u = heapq.heappop(heap)
        if u in dist:
            continue
        dist[u] = d
        for v, cost in graph.get(u, {}).items():
            if v not in dist:
                heapq.heappush(heap, (d + cost, v))
    return dist
```
hint: Use `heapq` as a priority queue of `(distance, node)` pairs.
hint: The first time a node is popped its distance is final; skip nodes already finished.
solution: Pop the smallest `(d, u)`; if `u` is already finished skip it, otherwise record `d` as its final cost and push each unfinished neighbor with `d + cost`. Stale heap entries are ignored when popped, so every node is finalized once.

def next_hops(graph, source):

    first = {}

model:
```python
def bellman_ford(nodes, edges, source):
    inf = float("inf")
    dist = {n: inf for n in nodes}
    dist[source] = 0
    for _ in range(len(nodes) - 1):
        for u, v, w in edges:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
    for u, v, w in edges:
        if dist[u] + w < dist[v]:
            raise ValueError("negative cycle")
    return dist
```
hint: Relax every edge `len(nodes) - 1` times: `if dist[u] + w < dist[v]` then update.
hint: After those passes, one more pass that still finds an improvement proves a negative cycle is reachable.
solution: Start with infinity everywhere except the source, relax all edges $V - 1$ times, then do one more pass: if any edge can still be relaxed there is a reachable negative cycle. Because `inf + w` is `inf`, edges out of unreachable nodes never change anything.

model:
```python
def dv_update(me, costs, vectors):
    result = {me: 0}
    for neighbor, cost in costs.items():
        for dest, dist in vectors[neighbor].items():
            if dest == me:
                continue
            candidate = cost + dist
            if dest not in result or candidate < result[dest]:
                result[dest] = candidate
    return result
```
hint: This is the Bellman-Ford equation: take the minimum, over neighbors, of link cost plus the neighbor's distance.
hint: Skip the entry for `me` in the neighbors' vectors, because the distance to yourself is 0.
solution: Loop over neighbors and over the destinations in their vectors, compute `cost + dist`, and keep the smallest candidate for each destination; `me` stays at 0.
