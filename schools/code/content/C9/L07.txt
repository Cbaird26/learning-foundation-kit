@article
A TCP sender must respect two different limits. **Flow control** protects the **receiver**: the sender must not send faster than the receiving application can read. **Congestion control** protects the **network**: the sender must not send faster than the routers on the path can forward. Both are enforced by limiting the amount of unacknowledged data in flight.

### Flow control

The receiver has a buffer of size `RcvBuffer`. It advertises the free space in the **receive window** field of every segment it sends:

$$\text{rwnd} = \text{RcvBuffer} - (\text{LastByteRcvd} - \text{LastByteRead}).$$

The sender keeps $\text{LastByteSent} - \text{LastByteAcked} \le \text{rwnd}$. If the application stops reading, rwnd shrinks to 0 and the sender stops, probing occasionally with tiny segments (**window probes**) so that it learns when space reappears. The 16-bit field limits the window to 65 535 bytes unless both sides use the **window scale** option (RFC 7323), which allows windows up to about 1 GiB.

### Congestion control

There is no explicit message from the network saying "slow down" in classic TCP (the **end-to-end** approach); the sender infers congestion from **loss**: a timeout or three duplicate ACKs. It keeps a **congestion window** `cwnd` (in bytes, often counted in MSS) and may have at most

$$\min(\text{cwnd},\ \text{rwnd})$$

bytes unacknowledged, the **effective window**. Roughly, the sending rate is $\text{cwnd}/\text{RTT}$. The classic algorithm, **TCP Reno** (RFC 5681), works in phases:

- **Slow start:** `cwnd` starts at a small value (in modern TCP 10 MSS, but in this lesson 1 MSS) and grows by 1 MSS for every ACK, which **doubles `cwnd` every RTT**. It is "slow" only compared to sending a full window at once. It continues until `cwnd` reaches the slow-start threshold `ssthresh`.
- **Congestion avoidance:** above `ssthresh`, `cwnd` grows by about 1 MSS per RTT: **additive increase**.
- **Triple duplicate ACK:** a mild sign of congestion (later packets are still getting through). Set `ssthresh = cwnd / 2` and `cwnd = ssthresh` after fast retransmit and fast recovery: **multiplicative decrease**.
- **Timeout:** a stronger sign. Set `ssthresh = cwnd / 2` and `cwnd = 1 MSS`, and restart slow start.

The pattern of additive increase and multiplicative decrease, **AIMD**, makes `cwnd` follow a sawtooth. AIMD is stable and converges to a **fair** share when flows compete for a bottleneck link: if the window oscillates between $W/2$ and $W$, the average window is $0.75\,W$ and the average throughput is about $0.75\,W \cdot \text{MSS}/\text{RTT}$.

For a long flow with loss probability $p$ per packet, a well-known approximation (the Mathis formula) is

$$\text{throughput} \approx \frac{\text{MSS}}{\text{RTT}} \cdot \frac{1.22}{\sqrt{p}}.$$

Halving the loss rate does not double the throughput; throughput scales with $1/\sqrt{p}$ and falls as RTT grows.

### Modern variants

Linux uses **CUBIC** by default: it grows the window as a cubic function of time since the last loss, which suits high-bandwidth, long-delay paths. **BBR** estimates the bottleneck bandwidth and minimum RTT instead of treating loss as the signal. Routers can also mark packets with **ECN** (explicit congestion notification, RFC 3168) so that the sender can slow down without losses. QUIC implements the same ideas in user space.

In this lesson's simulations we use a simplified Reno model counted once per RTT in whole MSS: slow start doubles `cwnd` (but never beyond `ssthresh`), congestion avoidance adds 1, a triple duplicate ACK sets `ssthresh = max(cwnd // 2, 2)` and `cwnd = ssthresh`, and a timeout sets `ssthresh = max(cwnd // 2, 2)` and `cwnd = 1`.

@example
title: The effective window
problem: The receiver advertises `rwnd = 12 000` bytes. The sender has `cwnd = 9000` bytes, `LastByteSent = 30 000` and `LastByteAcked = 26 000`. How many more bytes may it send now?
step: The window limit is $\min(\text{cwnd}, \text{rwnd}) = \min(9000, 12\,000) = 9000$ bytes.
step: Bytes in flight: $30\,000 - 26\,000 = 4000$.
step: Usable: $9000 - 4000 = 5000$ bytes. Here congestion control, not flow control, is the limit.
answer: 5000 bytes

@example
title: A congestion window trace
problem: Start with `cwnd = 1`, `ssthresh = 16`. Five RTTs succeed, then one RTT ends with a triple duplicate ACK, then one succeeds, then a timeout occurs. Give `cwnd` after each RTT.
step: Slow start: 1 becomes 2, 4, 8, 16 after four RTTs. At 16 it equals `ssthresh`, so growth is now additive.
step: Fifth RTT: `cwnd` becomes 17.
step: Triple duplicate ACK: `ssthresh = 17 // 2 = 8` and `cwnd = 8`.
step: Next RTT succeeds: `cwnd = 9` (additive, since 8 is not below `ssthresh = 8`).
step: Timeout: `ssthresh = 9 // 2 = 4` and `cwnd = 1`.
answer: 2, 4, 8, 16, 17, 8, 9, 1

@mistakes
- Confusing the two windows: rwnd comes from the receiver and protects its buffer, cwnd is computed by the sender to protect the network.
- Thinking that slow start is slow in the long run. It is exponential; "slow" refers to the small starting window.
- Applying the timeout reaction (cwnd to 1) to a triple duplicate ACK. A duplicate-ACK loss is treated more mildly.
- Expecting throughput to double when the loss rate is halved. Throughput varies as $1/\sqrt{p}$.

```python
def effective_window(cwnd, rwnd, last_sent, last_acked):
    in_flight = last_sent - last_acked

```

For `"timeout"`: `ssthresh = max(cwnd // 2, 2)` then `cwnd = 1`. Return the list of `cwnd` values after each RTT.
starter:
```python
def reno_cwnd(events, ssthresh):

```
tests:
```python
assert reno_cwnd(["ok"] * 5, 8) == [2, 4, 8, 9, 10]
assert reno_cwnd(["ok"] * 5 + ["dup", "ok"], 8) == [2, 4, 8, 9, 10, 5, 6]
assert reno_cwnd(["ok"] * 5 + ["dup", "ok", "timeout", "ok", "ok", "ok"], 8) == [
    2, 4, 8, 9, 10, 5, 6, 1, 2, 3, 4]

assert reno_cwnd([], 8) == []
```
model:
```python
def reno_cwnd(events, ssthresh):
    cwnd = 1
    history = []
    for event in events:
        if event == "ok":
            if cwnd < ssthresh:
                cwnd = min(2 * cwnd, ssthresh)
            else:
                cwnd += 1
        elif event == "dup":
            ssthresh = max(cwnd // 2, 2)
            cwnd = ssthresh
        elif event == "timeout":
            ssthresh = max(cwnd // 2, 2)
            cwnd = 1
        history.append(cwnd)
    return history
```
hint: Keep `cwnd` and `ssthresh` as variables that persist across the loop.
hint: Handle the three event kinds in an `if`/`elif` chain and append `cwnd` after each one.
solution: Loop over the events, updating `cwnd` and `ssthresh` by the rules and appending `cwnd` after each RTT. In the second test `cwnd` is 10 when the duplicate-ACK event happens, so `ssthresh` and `cwnd` both become 5, and the next good RTT gives 6.

```python
def slow_start_rtts(target):
    cwnd = 1
    rtts = 0
    while cwnd < target:
        cwnd *= 2
        rtts += 1

```
hint: Double the window and count each doubling until it reaches the target.
