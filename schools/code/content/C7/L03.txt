@article
Memory is a long row of bytes, each with a numeric **address**. A variable occupies some bytes, and a **pointer** is a variable whose value is the address of another object. Pointers are how C code shares data, modifies its caller's variables, builds linked structures and talks to the operating system.

### The two operators

```c
int a = 10;
int *p = &a;     /* p holds the address of a */
*p = 25;         /* write through p: a is now 25 */
printf("%d\n", *p);
```

`&a` is the **address of** `a`. In a declaration, `int *p` says "`p` is a pointer to `int`". In an expression, `*p` **dereferences** the pointer: it names the object `p` points to, and it can be read or assigned. The declaration `int *p = &a;` initializes `p` itself, not `*p`. The type matters: `*p` reads `sizeof(int)` bytes starting at the address, and the compiler warns if you assign an `int *` to a `double *`.

Pointers have their own storage. On a typical 64-bit system a pointer takes 8 bytes. To print one, cast to `void *` and use `%p`: `printf("%p\n", (void *)&a);`. The actual number differs from run to run, so never depend on it.

### Memory diagrams

Draw each variable as a box with its name, its current value and, for pointers, an arrow to the target:

```text
a [ 25 ] <----- p [ * ]
```

Whenever a line of code runs, update the boxes. The rule `*p = v` changes the box at the end of the arrow; `p = &b` moves the arrow and changes no data. Tracing pointer programs on paper this way is the fastest way to find bugs.

### Null, uninitialized and dangling pointers

A pointer holding `NULL` (from `<stddef.h>` and other headers; a keyword `nullptr` in C23) points at no object, and dereferencing it is undefined behavior; in practice it usually crashes with a segmentation fault. An **uninitialized** pointer holds garbage: always initialize pointers, to a real address or to `NULL`. A **dangling** pointer holds the address of an object whose lifetime has ended, most commonly a local variable of a function that has returned:

```c
int *bad(void) {
    int local = 7;
    return &local;      /* BUG: local ceases to exist on return */
}
```

Using the returned pointer is undefined behavior. Compilers usually warn about this particular case, but not about all of them.

### Pointers as parameters

Because arguments are passed by value, a function that must change the caller's variable receives its address:

```c
void swap(int *x, int *y) {
    int t = *x;
    *x = *y;
    *y = t;
}
/* call: swap(&a, &b); */
```

The pointers are copies, but they point at the caller's objects, so writing through them changes the caller's data. A function can also return several results by writing to pointer parameters, as `scanf` does.

### Pointers to pointers and `void *`

A pointer can point at another pointer: `int **pp = &p;` then `*pp` is `p` and `**pp` is the `int`. A function needs an `int **` parameter when it must change which object the caller's pointer points at. A `void *` is a pointer to an unspecified type: it converts to and from any object pointer type in C without a cast and cannot be dereferenced directly. `const int *p` means "pointer to an `int` that cannot be modified through `p`".

@example
title: Tracing pointer assignments
problem: What does this program print?

```c
#include <stdio.h>

int main(void) {
    int a = 10, b = 20;
    int *p = &a;
    *p = *p + 5;
    p = &b;
    *p = a;
    printf("%d %d\n", a, b);
    return 0;
}
```
step: After the declarations: `a` is `10`, `b` is `20`, and `p` points at `a`.
step: `*p = *p + 5` reads `10` through `p` and writes `15` into `a`. Now `a` is `15`.
step: `p = &b` changes the arrow, not any data: `p` now points at `b`.
step: `*p = a` writes the value of `a` (`15`) into the object `p` points at, which is `b`. Now `b` is `15`.
step: The program prints `15 15`.
answer: `15 15`

@example
title: A function that modifies two variables
problem: Write `min_max(int x, int y, int *lo, int *hi)` that stores the smaller of `x` and `y` in `*lo` and the larger in `*hi`, and show a call.
step: The function must return two results, so it writes through two pointer parameters.
step: Compare once: if `x < y` the smaller is `x`, otherwise `y`.
step: Write the results with dereferenced assignments:

```c
void min_max(int x, int y, int *lo, int *hi) {
    if (x < y) {
        *lo = x;
        *hi = y;
    } else {
        *lo = y;
        *hi = x;
    }
}
```
step: The caller passes addresses of its own variables: `int small, big; min_max(7, 3, &small, &big);` leaves `small` equal to `3` and `big` equal to `7`.

@mistakes
- Dereferencing a pointer that is `NULL`, uninitialized or dangling: undefined behavior, often a crash but sometimes silent corruption.
- Returning the address of a local variable.
- Writing `p = 5` when you mean `*p = 5`: the first changes where `p` points (and the compiler warns), the second changes the target.
- Passing `a` instead of `&a` to a function with an `int *` parameter, or the reverse.
- Thinking `int *a, b;` declares two pointers: only `a` is a pointer; `b` is a plain `int`.

@practice code
prompt: Model memory as a Python list `mem` whose indices are addresses and whose items are the values stored there. Write `swap(mem, p, q)` that exchanges the values stored at addresses `p` and `q` (like the C function `swap(int *p, int *q)`). It modifies `mem` in place and returns `None`. The two addresses may be equal.
starter:
```python
def swap(mem, p, q):
    pass
```
tests:
```python
mem = [10, 20, 30]
assert swap(mem, 0, 2) is None
assert mem == [30, 20, 10]
swap(mem, 1, 1)
assert mem == [30, 20, 10]
mem2 = [1, 2]
swap(mem2, 1, 0)
assert mem2 == [2, 1]
mem3 = [5]
swap(mem3, 0, 0)
assert mem3 == [5]
```
model:
```python
def swap(mem, p, q):
    t = mem[p]
    mem[p] = mem[q]
    mem[q] = t
```
hint: Use a temporary variable, exactly as the C version does.
hint: Read `mem[p]` into the temporary before overwriting it.
solution: Save `mem[p]` in `t`, copy `mem[q]` into `mem[p]`, then store `t` in `mem[q]`. When `p == q` the three steps leave the value unchanged, just like the C function.

@practice mc
prompt: Which statement about this function is correct?

```c
int *make_counter(void) {
    int count = 0;
    return &count;
}
```
choice: It is correct: the returned pointer stays valid as long as the caller keeps it.
choice*: It returns a dangling pointer, because `count` ceases to exist when the function returns, so using the result is undefined behavior.
choice: It always returns `NULL`, because `count` is local.
choice: It does not compile, because a function cannot return a pointer.
hint: How long does a local variable live?
solution: Local variables belong to the function's stack frame, which is reused after the call returns. The pointer then refers to dead storage. To keep the counter alive the caller can pass in its own `int` (or a pointer to one), or the function can use `static` or `malloc`.

@practice code
prompt: With memory modeled as a Python list `mem` (indices are addresses), a value that is a pointer is simply an address stored in a cell. Write `deref(mem, addr, depth)` that starts at the address `addr` and follows `depth` dereferences: `depth` 0 returns `addr` itself, depth 1 returns `mem[addr]`, depth 2 returns `mem[mem[addr]]`, and so on.
starter:
```python
def deref(mem, addr, depth):
    pass
```
tests:
```python
mem = [3, 0, 1, 5, 2]
assert deref(mem, 4, 0) == 4
assert deref(mem, 4, 1) == 2
assert deref(mem, 4, 2) == 1
assert deref(mem, 4, 3) == 0
assert deref(mem, 4, 4) == 3
assert deref(mem, 3, 1) == 5
```
model:
```python
def deref(mem, addr, depth):
    for _ in range(depth):
        addr = mem[addr]
    return addr
```
hint: Each dereference replaces the current address by the value stored at that address.
hint: Repeat that replacement `depth` times in a loop and return what you have.
solution: Loop `depth` times doing `addr = mem[addr]`. This is exactly what `*p`, `**pp` and `***ppp` do to a chain of pointers. With `depth` 0 the loop never runs and `addr` is returned unchanged.

@quiz code
prompt: With memory modeled as a Python list `mem` (indices are addresses), write `sort3(mem, a, b, c)` that rearranges the values at the three distinct addresses `a`, `b` and `c` so that `mem[a] <= mem[b] <= mem[c]`, using only reads and writes of those three cells. It modifies `mem` in place and returns `None`; other cells are untouched.
starter:
```python
def sort3(mem, a, b, c):
    pass
```
tests:
```python
mem = [9, 1, 5, 0]
sort3(mem, 0, 1, 2)
assert mem == [1, 5, 9, 0]
mem = [3, 2, 1, 8]
sort3(mem, 2, 0, 1)
assert mem == [2, 3, 1, 8]
mem = [4, 4, 4]
sort3(mem, 0, 1, 2)
assert mem == [4, 4, 4]
mem = [1, 2, 3]
sort3(mem, 0, 1, 2)
assert mem == [1, 2, 3]
mem = [7, 0, 9, 3]
sort3(mem, 3, 1, 0)
assert mem == [7, 3, 9, 0]
```
model:
```python
def sort3(mem, a, b, c):
    if mem[a] > mem[b]:
        mem[a], mem[b] = mem[b], mem[a]
    if mem[b] > mem[c]:
        mem[b], mem[c] = mem[c], mem[b]
    if mem[a] > mem[b]:
        mem[a], mem[b] = mem[b], mem[a]
```
hint: Compare and swap neighbours: first the cells at `a` and `b`, then `b` and `c`.
hint: After those two compare-and-swap steps the largest value is at `c`; one more compare-and-swap of `a` and `b` finishes the job.
solution: Three compare-and-swap steps (a,b), (b,c), (a,b) sort any three values, like a tiny sorting network. The addresses need not be in increasing order: the sorted values are placed in the cells at `a`, `b` and `c` in that order.

@quiz text
prompt: What does this program print? Type the output exactly (two numbers separated by one space).

```c
#include <stdio.h>

static void ensure(int **pp, int *fallback) {
    if (*pp == NULL) {
        *pp = fallback;
    }
}

int main(void) {
    int d = 5, e = 8;
    int *p = NULL;
    int *q = &e;
    ensure(&p, &d);
    ensure(&q, &d);
    printf("%d %d\n", *p, *q);
    return 0;
}
```
answer: 5 8
check: run_c('#include <stdio.h>\n\nstatic void ensure(int **pp, int *fallback) {\n    if (*pp == NULL) {\n        *pp = fallback;\n    }\n}\n\nint main(void) {\n    int d = 5, e = 8;\n    int *p = NULL;\n    int *q = &e;\n    ensure(&p, &d);\n    ensure(&q, &d);\n    printf("%d %d\\n", *p, *q);\n    return 0;\n}\n')
