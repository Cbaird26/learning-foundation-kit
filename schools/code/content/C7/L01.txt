@article
C is a small language that sits close to the hardware. There is no runtime that checks your work: the compiler turns your source into machine code, and the program does exactly what you wrote, including the mistakes. In this course we use the C17 standard (ISO/IEC 9899:2018) and note where C23 (ISO/IEC 9899:2024) changed something. A first program:

```c
#include <stdio.h>

int main(void) {
    printf("Hello, %d\n", 42);
    return 0;
}
```

Compile and run it on Linux or macOS with `gcc -std=c17 -Wall -Wextra -o hello hello.c` and then `./hello`. The flags ask for the C17 language and for most useful warnings; read every warning, because many of them point at real bugs. `main` returns an `int`, the exit status that the shell sees (`0` means success).

### Types

Every variable has a fixed type chosen at compile time. The integer types are `char`, `short`, `int`, `long` and `long long`, each with a `signed` and an `unsigned` form. The standard guarantees only minimum ranges: `int` has at least 16 bits, and `sizeof(char)` is always 1 by definition. On a typical 64-bit Linux system `int` has 32 bits and `long` has 64, but on 64-bit Windows `long` has 32. When you need an exact width, include `<stdint.h>` and use `int32_t`, `uint8_t`, `uint64_t` and friends. The floating types are `float`, `double` and `long double`; `double` is the default choice. Since C23, `bool`, `true` and `false` are keywords; in C17 you include `<stdbool.h>`.

A `char` holds one byte and is an integer: `'a'` is the integer 97 in ASCII, so `'a' + 1` is 98. Whether plain `char` is signed is implementation-defined.

### What happens when a value does not fit

Unsigned arithmetic wraps around **modulo $2^N$** for an $N$-bit type, and this is well defined: `(unsigned char)300` is `300 mod 256 = 44`. **Signed** overflow, such as `INT_MAX + 1`, is *undefined behavior*: the standard places no requirements on the program, and optimizing compilers assume it never happens. Never rely on signed wraparound. We return to undefined behavior in week 12.

### Operators

- Arithmetic: `+ - * / %`. If both operands are integers, `/` is **integer division** that truncates toward zero (`7 / 2` is `3`, `-7 / 2` is `-3`), and `%` satisfies `(a / b) * b + a % b == a`, so `-7 % 2` is `-1`. `7 / 2.0` is `3.5` because one operand is `double`.
- Comparison and logic: `== != < <= > >=`, `&&`, `||`, `!`. They yield `int` `1` or `0`. `&&` and `||` **short-circuit**: the right side is evaluated only if needed. Any nonzero value is true.
- Bitwise: `& | ^ ~ << >>`. `n & 1` is the lowest bit of `n`; `n >> 1` halves a non-negative number. Do not confuse `&` with `&&`.
- Assignment is an expression: `x = 5` has the value `5`. So `if (x = 5)` assigns instead of comparing, a classic bug that `-Wall` warns about.

### Control flow

`if`/`else`, `while`, `do`/`while` and `for` behave as in other languages; `break` leaves a loop and `continue` skips to the next iteration. `for (int i = 0; i < n; i++)` declares the counter in the loop header (allowed since C99). A `switch` jumps to the matching `case` label and then **keeps running** into the following cases until a `break`; this fall-through is occasionally useful but often a bug.

### Printing

`printf` takes a format string: `%d` for `int`, `%u` for `unsigned int`, `%ld` for `long`, `%zu` for `size_t`, `%f` for `double`, `%c` for a character, `%s` for a string and `%x` for hexadecimal. A mismatch between the conversion and the argument's type is undefined behavior.

@example
title: Tracing a loop with continue
problem: What does this program print?

```c
#include <stdio.h>

int main(void) {
    int total = 0;
    for (int i = 1; i <= 10; i++) {
        if (i % 3 == 0) {
            continue;
        }
        total += i;
    }
    printf("%d\n", total);
    return 0;
}
```
step: `total` starts at `0`, and `i` runs from `1` to `10` inclusive.
step: When `i % 3 == 0` (that is, `i` is `3`, `6` or `9`), `continue` skips the addition.
step: All other values are added: `1 + 2 + 4 + 5 + 7 + 8 + 10 = 37`.
step: `printf` runs once, after the loop, and prints `37`.
answer: `37`

@example
title: Integer division and remainder with negatives
problem: What does `printf("%d %d %.2f\n", -7 / 2, -7 % 2, 7 / 2.0);` print?
step: Both operands of `-7 / 2` are `int`, so the quotient is truncated toward zero: `-3`, not `-4`.
step: The remainder must satisfy `(a / b) * b + a % b == a`, so `-7 % 2` is `-7 - (-3 * 2) = -1`.
step: In `7 / 2.0` the integer `7` is converted to `double`, so the result is `3.5`, and `%.2f` prints two decimals: `3.50`.
step: The line printed is `-3 -1 3.50`.
answer: `-3 -1 3.50`

@mistakes
- Writing `if (x = 5)` instead of `if (x == 5)`: the assignment is always true and changes `x`.
- Expecting `7 / 2` to be `3.5`: integer operands give integer division, so convert one operand (`7 / 2.0`) when you want a fraction.
- Relying on signed overflow to wrap around: it is undefined behavior; only unsigned types wrap, modulo $2^N$.
- Forgetting `break` at the end of a `switch` case, so execution falls through into the next case.
- Passing the wrong type to `printf` (for example `%d` with a `double`), which is undefined behavior.

prompt: Write `popcount(n)` that returns the number of 1 bits in the binary representation of the non-negative integer `n`. Work like a C programmer: use a loop with the bitwise operators `&` and `>>`, and do not use `bin`, `str.count` or `int.bit_count`. Example: `popcount(7)` is `3`.
starter:
```python
def popcount(n):
    pass
```
tests:
```python
assert popcount(0) == 0
assert popcount(7) == 3
assert popcount(255) == 8
assert popcount(1024) == 1
assert popcount(0b101101) == 4
```
model:
```python
def popcount(n):
    count = 0
    while n > 0:
        count += n & 1
        n >>= 1
    return count
```
hint: `n & 1` is `1` exactly when the lowest bit of `n` is set.
hint: After examining the lowest bit, shift `n` right by one with `n >>= 1` and repeat until `n` is `0`.
solution: Loop while `n > 0`, add `n & 1` to a counter, and shift right. The loop runs once per bit of `n`, so the time is $O(\log n)$.

@quiz code
prompt: Write `to_int8(n)` that returns the value a two's-complement 8-bit `int8_t` holds after the integer `n` (any size, possibly negative) is reduced modulo 256: results are in the range -128 to 127. Examples: `to_int8(255)` is `-1` and `to_int8(128)` is `-128`.
starter:
```python
def to_int8(n):
    pass
```
tests:
```python
assert to_int8(127) == 127
assert to_int8(128) == -128
assert to_int8(255) == -1
assert to_int8(256) == 0
assert to_int8(-129) == 127
assert to_int8(-128) == -128
```
model:
```python
def to_int8(n):
    n = n % 256
    if n >= 128:
        n -= 256
    return n
```
hint: First reduce `n` to the range 0 to 255.
hint: Bit patterns from 128 to 255 have the top bit set and represent negative numbers: subtract 256 from them.
solution: Reduce with `n % 256`, then subtract 256 when the result is at least 128. In two's complement the top bit of an $N$-bit pattern has weight $-2^{N-1}$, which is why 255 means `-1`. (In C, converting an out-of-range value to a signed type is implementation-defined; GCC does exactly this reduction.)
