@article
A **linked list** stores each element in its own heap-allocated **node** holding a value and a pointer to the next node. The list itself is just a pointer to the first node, the **head**; the last node's `next` is `NULL`.

```c
typedef struct node {
    int value;
    struct node *next;
} node;
```

The tag `struct node` is needed inside the definition, because the typedef name does not exist yet at that point. An empty list is `head == NULL`.

### Basic operations

Pushing at the front takes $O(1)$ time. Because the head pointer must change, the function takes a pointer to it:

```c
int push_front(node **head, int value) {
    node *n = malloc(sizeof *n);
    if (n == NULL) {
        return -1;
    }
    n->value = value;
    n->next = *head;
    *head = n;
    return 0;
}
```

Walking the list uses a loop on the pointer: `for (node *p = head; p != NULL; p = p->next)`. Finding a value is $O(n)$; reaching the $k$-th node is $O(k)$ (no random access). Appending at the end is $O(n)$ unless you also keep a tail pointer. Inserting or removing a node you already have a pointer to (and its predecessor) is $O(1)$, because no elements move.

### Freeing a list

Read `next` **before** freeing the node:

```c
void free_list(node *head) {
    while (head != NULL) {
        node *next = head->next;
        free(head);
        head = next;
    }
}
```

Writing `free(head); head = head->next;` is a use after free. The code that calls `malloc` for a node owns it until the node is unlinked and freed; document who owns the list as a whole.

### Removing with a pointer to a pointer

The tricky part of removal is the head: the first node has no predecessor node. A pointer to the **link that points at the current node** removes the special case. `pp` starts as `&head` and later becomes the address of some node's `next` field:

```c
int remove_first(node **head, int value) {
    for (node **pp = head; *pp != NULL; pp = &(*pp)->next) {
        if ((*pp)->value == value) {
            node *dead = *pp;
            *pp = dead->next;      /* unlink: bypass the node */
            free(dead);
            return 1;
        }
    }
    return 0;
}
```

`*pp` is the node under inspection; assigning to `*pp` rewrites whichever link led to it, whether that is the head variable or a `next` field. Draw this on paper: `pp` is an arrow pointing at an arrow.

### Reversing in place

```c
node *reverse(node *head) {
    node *prev = NULL;
    while (head != NULL) {
        node *next = head->next;   /* remember the rest */
        head->next = prev;         /* flip this link */
        prev = head;
        head = next;
    }
    return prev;
}
```

It runs in $O(n)$ time and $O(1)$ extra space, and returns the new head.

### Other linked structures

A **doubly linked list** adds a `prev` pointer, which makes removal of a known node $O(1)$ at the cost of more pointer updates. A **stack** is a list used through `push_front` and a pop of the head; a **queue** keeps head and tail pointers. A **binary tree** node has two child pointers, `left` and `right`, and is usually processed with recursion; freeing it is a post-order traversal (free both children, then the node). A **cycle** (a `next` pointer leading back into the list) makes a traversal loop forever; two pointers that move at different speeds can detect one.

Linked lists have poor locality: nodes are scattered in memory and each step is a pointer chase, so arrays are usually faster in practice unless you need cheap insertion in the middle. Choose a list when the operations you need are constant-time splices.

@example
title: Tracing a list reversal
problem: Trace `reverse` on the list `1 -> 2 -> 3`, drawing the pointers after each iteration.
step: Start: `prev = NULL`, `head` at node 1. The list is `1 -> 2 -> 3 -> NULL`.
step: Iteration 1: `next` is node 2; node 1's link is set to `prev` (`NULL`); `prev` becomes node 1 and `head` becomes node 2. Now `1 -> NULL` is finished and `2 -> 3` is left.
step: Iteration 2: `next` is node 3; node 2 now points to node 1; `prev` is node 2 and `head` is node 3. The finished part is `2 -> 1 -> NULL`.
step: Iteration 3: `next` is `NULL`; node 3 points to node 2; `prev` is node 3 and `head` is `NULL`, so the loop ends. The function returns node 3: `3 -> 2 -> 1 -> NULL`.

@example
title: Removing the head with node **
problem: Show why `remove_first(&head, 3)` needs no special case when the list is `3 -> 1`.
step: `pp` starts as `&head`, so `*pp` is the head variable, which points at node 3.
step: `(*pp)->value == 3`, so `dead` is node 3 and `*pp = dead->next` assigns node 1 to the **head variable itself**.
step: `free(dead)` releases node 3, and the list is now `1`.
step: For a match in the middle, `pp` would be `&prev_node->next`, and the same two lines would rewrite that `next` field. One code path serves both cases.

@mistakes
- Freeing a node and then reading `head->next`: save `next` first.
- Losing the rest of the list by overwriting the only pointer to it before saving it.
- Forgetting that adding or removing the first node changes the caller's head pointer, so the function needs `node **` or must return the new head.
- Not setting the last node's `next` to `NULL` (malloc does not zero memory), so traversals run into garbage.
- Leaking nodes by overwriting a head pointer or never calling `free_list`.

@quiz code
prompt: Using the array model of a list (`val[i]`, `nxt[i]` is the next node's index or `-1`), write `has_cycle(nxt, head)` that returns `True` if following `nxt` from `head` never reaches `-1` (the list contains a cycle) and `False` otherwise. Use **Floyd's tortoise and hare** (a slow pointer moving one step, a fast pointer moving two) and no set or other extra collection, so the extra space is $O(1)$. `head == -1` is the empty list.
starter:
```python
def has_cycle(nxt, head):
    pass
```
tests:
```python
assert has_cycle([1, 2, -1], 0) is False
assert has_cycle([], -1) is False
assert has_cycle([0], 0) is True
assert has_cycle([1, 2, 3, 1], 0) is True
assert has_cycle([1, -1], 0) is False
assert has_cycle([1, 2, 0], 1) is True
```
model:
```python
def has_cycle(nxt, head):
    slow = head
    fast = head
    while fast != -1 and nxt[fast] != -1:
        slow = nxt[slow]
        fast = nxt[nxt[fast]]
        if slow == fast:
            return True
    return False
```
hint: Move `slow` one node and `fast` two nodes per round; if `fast` falls off the end (reaches `-1`) there is no cycle.
hint: Check that `fast` and `nxt[fast]` are both valid before moving two steps, and report a cycle when the two pointers become equal.
solution: In a cycle the fast pointer gains one node on the slow pointer each round, so they must meet; in a list that ends, the fast pointer reaches `-1` first. The loop makes $O(n)$ steps in total, with $O(1)$ extra space.
