@article
Three ADTs restrict where you may insert and remove, and in exchange give constant-time operations and clear meaning.

- A **stack** is last in, first out (LIFO): `push`, `pop`, `peek`.
- A **queue** is first in, first out (FIFO): `enqueue` at the back, `dequeue` from the front.
- A **deque** (double-ended queue, pronounced "deck") allows adding and removing at both ends.

### Stacks

A stack is the structure behind the call stack, undo history, backtracking and expression parsing. A Python `list` is a fine stack: `append` and `pop()` at the end are $O(1)$ (amortized for `append`).

**Matching brackets.** To check that `"([]{})"` is balanced, push each opening bracket; for each closing bracket, the top of the stack must be its matching opener, which you pop. The string is balanced exactly when no mismatch occurs and the stack is empty at the end. The stack's LIFO order matches how brackets nest: the most recently opened bracket must close first.

**Postfix evaluation.** In postfix (reverse Polish) notation the operator follows its operands: `3 4 + 2 *` means $(3 + 4) \times 2$. Scan the tokens; push numbers; on an operator, pop the right operand, then the left operand, apply the operator and push the result. A valid expression leaves exactly one value.

### Queues

Queues model waiting lines, breadth-first search (week 11) and buffers. `list.pop(0)` is a poor dequeue, since it shifts every remaining element in $O(n)$. Two good implementations:

**Linked nodes**: keep `head` and `tail`; enqueue links a node after `tail`, dequeue unlinks `head`. Both are $O(1)$ worst case.

**Circular array** (ring buffer): keep a fixed array, an index `front` and a count `size`. The back position is `(front + size) % capacity`. Enqueue writes there and increments `size`; dequeue reads at `front`, then sets `front = (front + 1) % capacity` and decrements `size`. Indexes wrap around, so no element is ever shifted. When the array is full, a resizing queue allocates a larger array and copies the elements in order starting from `front`, giving $O(1)$ amortized operations like a dynamic array.

```python
class RingQueue:
    def __init__(self, capacity=4):
        self._data = [None] * capacity
        self._front = 0
        self._size = 0

    def enqueue(self, x):
        if self._size == len(self._data):
            raise OverflowError("queue is full")
        back = (self._front + self._size) % len(self._data)
        self._data[back] = x
        self._size += 1
```

### Deques and `collections.deque`

A deque supports `append`, `appendleft`, `pop` and `popleft`. Python's `collections.deque` implements these in $O(1)$ at both ends (using a linked structure of blocks), but indexing in the middle is $O(n)$. Use it whenever you need a queue:

```python
from collections import deque

q = deque()
q.append("a")        # enqueue at the back
q.append("b")
first = q.popleft()  # dequeue from the front: "a"
```

A deque can also be a stack (use `append` and `pop`) and is the right tool for sliding-window algorithms, which pop from both ends.

### A queue from two stacks

Keep an `inbox` stack and an `outbox` stack. Enqueue pushes onto `inbox`. To dequeue, if `outbox` is empty, pop everything from `inbox` and push it onto `outbox` (reversing the order), then pop from `outbox`. A single dequeue may cost $O(n)$, but each element is moved at most once, so any sequence of $n$ operations costs $O(n)$: $O(1)$ amortized per operation.

### Summary

| ADT | Insert | Remove | Typical implementations |
|---|---|---|---|
| stack | top | top | list, linked nodes |
| queue | back | front | `deque`, ring buffer, linked nodes |
| deque | either end | either end | `deque`, ring buffer, doubly linked list |

@example
title: Matching brackets with a stack
problem: Is the string `"{[()]}("` balanced? Trace the stack.
step: Scan left to right. `{` is an opener: stack is `{`. Then `[`: stack `{ [`. Then `(`: stack `{ [ (`.
step: `)` is a closer. The top is `(`, which matches, so pop it: stack `{ [`.
step: `]` matches the top `[`; pop. `}` matches the top `{`; pop. The stack is now empty.
step: The final `(` is an opener: push it. The stack is `(`.
step: The string ended with a non-empty stack, so an opener was never closed.
answer: Not balanced: one `(` remains on the stack at the end.

@example
title: Evaluating a postfix expression
problem: Evaluate the postfix expression `5 1 2 + 4 * + 3 -`.
step: Push 5, push 1, push 2. Stack: `5 1 2`.
step: `+`: pop 2 and 1, push `1 + 2 = 3`. Stack: `5 3`. Push 4: `5 3 4`.
step: `*`: pop 4 and 3, push `3 * 4 = 12`. Stack: `5 12`.
step: `+`: pop 12 and 5, push `5 + 12 = 17`. Stack: `17`. Push 3: `17 3`.
step: `-`: pop the right operand 3, then the left operand 17, and push `17 - 3 = 14`. The stack holds the single value 14.
answer: 14

@mistakes
- Using `list.pop(0)` or `list.insert(0, x)` as the queue operations, which are $O(n)$ each; use `collections.deque`.
- Popping the operands of a postfix operator in the wrong order, which gives `3 - 17` instead of `17 - 3` for non-commutative operators.
- Declaring brackets balanced when the scan ends but the stack is not empty, or popping from an empty stack on an extra closer.
- In a ring buffer, forgetting `% capacity` when advancing the indexes, or confusing a full buffer with an empty one when only `front` and `back` are stored (store `size`).

model:
```python
def is_balanced(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)
        elif ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
    return not stack
```
hint: Push every opener; for a closer, compare it with the opener on top of the stack.
hint: Return `False` immediately for a closer when the stack is empty or its top is the wrong opener. At the end the stack must be empty.
solution: A stack records the openers that are still unclosed, most recent on top. Each closer must match the top. `"([)]"` fails because `)` meets `[` on top, and `"(("` fails because the stack is non-empty at the end.

```python
def eval_postfix(tokens):
    stack = []
    for tok in tokens:
        if tok in ("+", "-", "*"):
            right = stack.pop()
            left = stack.pop()
            if tok == "+":
                stack.append(left + right)
            elif tok == "-":
                stack.append(left - right)
            else:
                stack.append(left * right)
        else:
            stack.append(int(tok))
    return stack.pop()
```
hint: Push each number as an `int`.
hint: For an operator, `right = stack.pop()` comes first, then `left = stack.pop()`; push the result of `left op right`.
solution: Numbers go on the stack; an operator replaces its two top values by the result. Taking `right` first matters for `-`: `["10", "4", "-"]` is `10 - 4 = 6`. The one remaining value is the answer.

model:
```python
class RingQueue:
    def __init__(self, capacity):
        self._data = [None] * capacity
        self._front = 0
        self._size = 0

    def __len__(self):
        return self._size

    def enqueue(self, x):
        if self._size == len(self._data):
            raise OverflowError("queue is full")
        back = (self._front + self._size) % len(self._data)
        self._data[back] = x
        self._size += 1

    def dequeue(self):
        if self._size == 0:
            raise IndexError("dequeue from empty queue")
        x = self._data[self._front]
        self._data[self._front] = None
        self._front = (self._front + 1) % len(self._data)
        self._size -= 1
        return x
```
hint: Store the array, the index `_front` of the oldest item and the item count `_size`.
hint: The next free position is `(front + size) % capacity`. After a dequeue, advance `front` the same way and decrease `size`.
solution: The array is treated as a circle. The back index is computed from `front` and `size`, so storing `size` also tells empty from full. The final loop wraps the indexes around many times without ever shifting an element; every operation is $O(1)$.

model:
```python
class TwoStackQueue:
    def __init__(self):
        self._inbox = []
        self._outbox = []

    def __len__(self):
        return len(self._inbox) + len(self._outbox)

    def enqueue(self, x):
        self._inbox.append(x)

    def dequeue(self):
        if not self._outbox:
            while self._inbox:
                self._outbox.append(self._inbox.pop())
        if not self._outbox:
            raise IndexError("dequeue from empty queue")
        return self._outbox.pop()
```
hint: Moving items from one stack to another reverses their order, which turns LIFO into FIFO.
hint: Refill `outbox` only when it is empty; otherwise older items would be overtaken by newer ones.
solution: `inbox` receives new items. When `outbox` runs dry, popping `inbox` onto `outbox` reverses the order so the oldest item is on top. Each item moves at most once, so the amortized cost per operation is $O(1)$. The test enqueues `4` between dequeues to check that `4` does not jump ahead of `3`.
