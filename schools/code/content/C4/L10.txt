@article
A **priority queue** is an ADT that stores items with priorities and supports `push(item)`, `pop()` which removes and returns the item with the **smallest** priority (or the largest, in a max-priority queue), and `peek()`. Operating systems schedule jobs this way, graph algorithms such as Dijkstra's algorithm repeatedly need the closest unvisited vertex, and "top-$k$" problems keep the best few items seen so far. A sorted list makes `pop` cheap but `push` $O(n)$; an unsorted list reverses that. A **binary heap** gives $O(\log n)$ for both and $O(1)$ for `peek`.

### Heap structure

A binary heap is a **complete binary tree** (all levels full except possibly the last, which fills from the left) satisfying the **min-heap property**: every node's key is less than or equal to its children's keys. The root is therefore the minimum. (A max-heap reverses the inequality.) Unlike a BST, a heap says nothing about left versus right, only about parent versus child.

Because the tree is complete, it needs no node objects. Store it in an array level by level. With 0-based indices, for the item at index $i$:
$$\text{parent}(i) = \left\lfloor \frac{i - 1}{2} \right\rfloor, \qquad \text{left}(i) = 2i + 1, \qquad \text{right}(i) = 2i + 2.$$
A heap with $n$ items has height $\lfloor \log_2 n \rfloor$.

### Push: sift up

Append the new item at the end (the next free leaf position), then **sift up**: while it is smaller than its parent, swap them. Each swap moves one level up, so push is $O(\log n)$ worst case.

### Pop: sift down

The minimum is at index 0. Remove it by moving the **last** item to the root (the array shrinks by one and stays complete), then **sift down**: while the item is larger than its smaller child, swap with that child. Always choose the smaller child so the swapped-up value is smaller than its new sibling. Pop is $O(\log n)$.

```python
def sift_down(a, i, n):
    while True:
        left, right, smallest = 2 * i + 1, 2 * i + 2, i
        if left < n and a[left] < a[smallest]:
            smallest = left
        if right < n and a[right] < a[smallest]:
            smallest = right
        if smallest == i:
            return
        a[i], a[smallest] = a[smallest], a[i]
        i = smallest
```

### Building a heap in $O(n)$

Pushing $n$ items one at a time costs $O(n \log n)$. **Bottom-up heapify** does better: treat the array as a tree, and for $i$ from the last internal node ($\lfloor n/2 \rfloor - 1$) down to 0, call `sift_down(a, i, n)`. Leaves are already heaps. A node at height $j$ sifts down at most $j$ levels, and at most about $n / 2^{j+1}$ nodes have height $j$, so the total work is at most
$$\sum_{j \ge 0} \frac{n}{2^{j+1}}\, j = O(n),$$
since $\sum_j j/2^{j+1} = 1$. Most nodes are near the bottom, where sifting is cheap.

### Heapsort

Heapify the array into a **max**-heap, then repeatedly swap the root (the maximum) with the last unsorted position, shrink the heap by one and sift down. After $n$ rounds the array is sorted ascending. Heapsort is $O(n \log n)$ in the worst case, in place, but not stable.

### Python's `heapq`

The `heapq` module treats a plain list as a **min**-heap: `heappush(h, x)`, `heappop(h)`, `heapify(h)` (in place, $O(n)$), `h[0]` for the minimum, `heapreplace(h, x)` (pop then push) and `nlargest(k, it)` / `nsmallest(k, it)`. For a max-heap, push negated priorities. For prioritized objects, push tuples `(priority, tiebreaker, item)`: tuples compare element by element, and a unique tiebreaker such as a counter prevents Python from comparing the items themselves. A **top-$k$** pass keeps a min-heap of the $k$ largest items so far: for each new item larger than the heap's minimum, replace the minimum, for $O(n \log k)$ time and $O(k)$ space.

### Costs

| Operation | Binary heap |
|---|---|
| `peek` | $O(1)$ |
| `push` | $O(\log n)$ worst case |
| `pop` | $O(\log n)$ worst case |
| build from $n$ items | $O(n)$ |
| search for an arbitrary item | $O(n)$ |

The heap is not good at searching or sorted iteration; it is good at one thing, finding the extreme.

@example
title: Pushing into a min-heap
problem: Push 5, 3, 8, 1 into an empty min-heap. Show the array after each push.
step: Push 5: the array is `[5]`. Push 3: append at index 1, so `[5, 3]`. Its parent is index 0 (value 5); $3 < 5$, so swap: `[3, 5]`.
step: Push 8: append at index 2: `[3, 5, 8]`. Its parent is index 0 (value 3); $8 > 3$, no swap.
step: Push 1: append at index 3: `[3, 5, 8, 1]`. Its parent is index $\lfloor (3-1)/2 \rfloor = 1$ (value 5); $1 < 5$, swap: `[3, 1, 8, 5]`.
step: Now 1 is at index 1 with parent index 0 (value 3); $1 < 3$, swap: `[1, 3, 8, 5]`. At index 0 it has no parent, so stop.
answer: `[1, 3, 8, 5]`, with the minimum 1 at the root.

@example
title: Popping from a min-heap
problem: Pop the minimum from the heap `[2, 4, 3, 9, 6, 5]`. Show the array and the returned value.
step: The minimum is the root, 2. Save it to return. Remove the last item (5) and put it at the root: `[5, 4, 3, 9, 6]`.
step: Sift down from index 0. Its children are 4 (index 1) and 3 (index 2). The smaller child is 3, and $5 > 3$, so swap with index 2: `[3, 4, 5, 9, 6]`.
step: Index 2 would have children at indices 5 and 6, which do not exist (the array has 5 items), so stop.
step: Check the heap property: 3 has children 4 and 5; 4 has children 9 and 6. All parents are at most their children.
answer: It returns 2, and the heap becomes `[3, 4, 5, 9, 6]`.

@mistakes
- Swapping with the larger child, or with the left child regardless of size, when sifting down; the result violates the heap property.
- Believing that a heap's array is sorted, or that the second smallest item must be at index 1: it is at index 1 or 2.
- Using `heapq` as a max-heap directly. It is a min-heap; negate the priorities, or push `(-priority, item)`.
- Forgetting that building with $n$ pushes is $O(n \log n)$ whereas `heapify` is $O(n)$, and that searching for an arbitrary item in a heap is still $O(n)$.

model:
```python
class MinHeap:
    def __init__(self):
        self._a = []

    def __len__(self):
        return len(self._a)

    def to_list(self):
        return list(self._a)

    def peek(self):
        if not self._a:
            raise IndexError("peek at empty heap")
        return self._a[0]

    def push(self, x):
        a = self._a
        a.append(x)
        i = len(a) - 1
        while i > 0:
            parent = (i - 1) // 2
            if a[parent] <= a[i]:
                break
            a[parent], a[i] = a[i], a[parent]
            i = parent

    def pop(self):
        a = self._a
        if not a:
            raise IndexError("pop from empty heap")
        top = a[0]
        last = a.pop()
        if a:
            a[0] = last
            self._sift_down(0)
        return top

    def _sift_down(self, i):
        a = self._a
        n = len(a)
        while True:
            left = 2 * i + 1
            right = left + 1
            smallest = i
            if left < n and a[left] < a[smallest]:
                smallest = left
            if right < n and a[right] < a[smallest]:
                smallest = right
            if smallest == i:
                return
            a[i], a[smallest] = a[smallest], a[i]
            i = smallest
```
hint: `push` appends and then swaps with the parent while the item is smaller than the parent.
hint: For `pop`, save `a[0]`, remove the last item with `a.pop()`, and if the list is not empty put that item at index 0 and sift it down by swapping with the smaller child.
solution: Push appends to the end and sifts up through at most $\log_2 n$ levels. Pop saves the root, moves the last item to the root and sifts it down, choosing the smaller child at each level. Popping everything returns the items in sorted order, which the test with the 30 numbers checks.

model:
```python
def heapify(a):
    n = len(a)
    for start in range(n // 2 - 1, -1, -1):
        i = start
        while True:
            left = 2 * i + 1
            right = left + 1
            smallest = i
            if left < n and a[left] < a[smallest]:
                smallest = left
            if right < n and a[right] < a[smallest]:
                smallest = right
            if smallest == i:
                break
            a[i], a[smallest] = a[smallest], a[i]
            i = smallest
```
hint: Leaves are already valid heaps, so start at the last internal node, index `n // 2 - 1`.
hint: Loop `i` from `n // 2 - 1` down to 0, and for each run a sift-down that swaps with the smaller child while the item is larger than it.
solution: Sifting down from each internal node, children before parents, makes every subtree a heap by the time its root is processed. Most nodes sit near the leaves and sift down only a short way, so the total is $O(n)$, not $O(n \log n)$. The function mutates `a` and returns nothing.

model:
```python
import heapq


def k_largest(nums, k):
    if k <= 0:
        return []
    heap = []
    for x in nums:
        if len(heap) < k:
            heapq.heappush(heap, x)
        elif x > heap[0]:
            heapq.heapreplace(heap, x)
    return sorted(heap, reverse=True)
```
hint: Keep a min-heap of the best `k` values so far; its root is the smallest of them.
hint: While the heap holds fewer than `k` items, push. After that, a new value matters only if it is larger than `heap[0]`; then `heapq.heapreplace` swaps it in. Sort the `k` survivors at the end.
solution: The heap's root is the weakest of the current top `k`, so a new value either beats it (replace it) or is discarded. Each of the $n$ items costs $O(\log k)$, and the final sort of $k$ items is $O(k \log k)$. Using a max-heap of all items would cost $O(n)$ memory.
