import time


def best_time(setup, work, repeats=3):
    """Build fresh input with setup(), time work(input); keep the best."""
    best = float("inf")
    for _ in range(repeats):
        data = setup()
        start = time.perf_counter()
        work(data)
        best = min(best, time.perf_counter() - start)
    return best


def report(name, setup_for, work, sizes):
    previous = None
    for n in sizes:
        t = best_time(lambda: setup_for(n), work)
        ratio = "" if previous is None else f"{t / previous:5.2f}x"
        print(f"{name:24} n={n:>8} {t * 1000:10.3f} ms  {ratio}")
        previous = t

### Week by week

- **Week 1, abstract data types and big-O.** An ADT is behavior; a data structure is an implementation. Count operations, drop constants, name the case. Hidden loops: `in` on a list, `insert(0, x)`, `pop(0)`, slicing.
- **Week 2, dynamic arrays.** Size versus capacity. Doubling gives $O(1)$ amortized append because the copies sum to less than $2n$; constant-size growth gives $O(n)$ amortized.
- **Week 3, linked lists.** Nodes and references; $O(1)$ at the head, $O(n)$ to reach an index; reverse with `prev`, `node`, `nxt`; sentinels and `tail` handle special cases.
- **Week 4, stacks, queues, deques.** LIFO and FIFO; brackets and postfix with a stack; ring buffers with `% capacity`; `collections.deque` for $O(1)$ at both ends; two stacks make a queue.
- **Weeks 5 and 6, hash tables.** Hash, then reduce modulo $m$; equal keys must have equal hashes; chaining versus open addressing and tombstones; load factor $\alpha = n/m$; resize by doubling and recompute every index; expected $O(1)$, worst case $O(n)$.
- **Weeks 7 and 8, trees and BSTs.** Height in edges (empty is $-1$); preorder, inorder, postorder, level order; BST search, insert, delete (successor); inorder is sorted; cost $O(h)$, up to $n - 1$.
- **Week 9, balanced trees.** Rotations preserve order; AVL balance factor in $\{-1, 0, 1\}$ and the four cases; red-black properties and height at most $2\log_2(n+1)$.
- **Week 10, heaps.** Complete tree in an array; parent $\lfloor (i-1)/2 \rfloor$; sift up and sift down in $O(\log n)$; heapify in $O(n)$; `heapq` is a min-heap.
- **Weeks 11 and 12, graphs, tries, union-find.** Adjacency lists use $O(V + E)$ space; BFS (queue) gives fewest edges; DFS (stack) for components, cycles; tries give $O(L)$ prefix queries; union-find with compression and union by size is nearly constant per operation.

### Common errors

- Quoting a cost without the case: "hash lookup is $O(1)$" means expected, not worst case.
- Off-by-one in heap indices, ring buffer wrap-around and tree height conventions.
- Not updating `tail`, `size` or heights after a deletion or rotation.
- Marking graph vertices visited too late, which repeats work or loops forever.
- Using a list as a queue (`pop(0)`) or `x in some_list` inside a loop and accidentally writing $O(n^2)$ code.

model:
```python
class _Node:
    def __init__(self, key, value):
        self.key = key
        self.value = value
        self.prev = None
        self.next = None


class LRUCache:
    def __init__(self, capacity):
        self._capacity = capacity
        self._map = {}
        self._head = _Node(None, None)
        self._tail = _Node(None, None)
        self._head.next = self._tail
        self._tail.prev = self._head

    def __len__(self):
        return len(self._map)

    def _unlink(self, node):
        node.prev.next = node.next
        node.next.prev = node.prev

    def _push_front(self, node):
        node.prev = self._head
        node.next = self._head.next
        self._head.next.prev = node
        self._head.next = node

    def get(self, key):
        node = self._map.get(key)
        if node is None:
            return None
        self._unlink(node)
        self._push_front(node)
        return node.value

    def put(self, key, value):
        node = self._map.get(key)
        if node is not None:
            node.value = value
            self._unlink(node)
            self._push_front(node)
            return
        if len(self._map) == self._capacity:
            oldest = self._tail.prev
            self._unlink(oldest)
            del self._map[oldest.key]
        node = _Node(key, value)
        self._map[key] = node
        self._push_front(node)

    def keys_by_recency(self):
        keys = []
        node = self._head.next
        while node is not self._tail:
            keys.append(node.key)
            node = node.next
        return keys
```
hint: The dictionary maps each key to its list node, giving $O(1)$ lookup; the doubly linked list keeps the keys in recency order with the most recent next to the head.
hint: Use two sentinel nodes (head and tail) so that unlinking and inserting at the front never need special cases. `get` and `put` of an existing key both unlink the node and push it to the front.
solution: The hash map finds a node in expected $O(1)$ time and the doubly linked list can unlink a node it holds in $O(1)$ time and move it to the front. On a full insertion, the node before the tail sentinel is the least recently used; unlink it and delete its key from the dictionary. Sentinels remove the empty-list and single-node cases.

model:
```python
import heapq


class RunningMedian:
    def __init__(self):
        self._low = []    # max-heap of the smaller half, stored negated
        self._high = []   # min-heap of the larger half

    def add(self, x):
        if self._low and x > -self._low[0]:
            heapq.heappush(self._high, x)
        else:
            heapq.heappush(self._low, -x)
        if len(self._low) > len(self._high) + 1:
            heapq.heappush(self._high, -heapq.heappop(self._low))
        elif len(self._high) > len(self._low):
            heapq.heappush(self._low, -heapq.heappop(self._high))

    def median(self):
        if not self._low:
            raise IndexError("median of no data")
        if len(self._low) > len(self._high):
            return -self._low[0]
        return (-self._low[0] + self._high[0]) / 2
```
hint: Keep the two halves balanced so that the lower half has the same size as the upper half or one more element; the median is then at the top of one heap or between the two tops.
hint: Insert each new number into the correct half by comparing it with the top of the lower half, then rebalance by moving one element from the larger heap to the smaller if their sizes differ by more than allowed.
solution: Every element of the lower half is at most every element of the upper half, and the lower half has the same size as the upper half or one more. The median is then the top of the lower half (odd count) or the mean of the two tops (even count). An insertion pushes into one heap and moves at most one element across, costing $O(\log n)$.

@exam num
prompt: A chaining hash map starts with 4 buckets. After inserting a new key, if the number of keys divided by the number of buckets exceeds 0.75, the bucket count doubles and every stored pair is reinserted into the new table. Starting from an empty map, 50 distinct keys are inserted. How many pair reinsertions do the resizes perform in total (not counting the 50 ordinary insertions)?
answer: 98
check: int(run("m = 4\nn = 0\ntotal = 0\nfor _ in range(50):\n    n += 1\n    if n / m > 0.75:\n        total += n\n        m *= 2\nprint(total)\n"))
hint: Find the key counts at which the table resizes: the first resize happens when the 4th key makes the load factor exceed 0.75.
hint: The resizes occur after the 4th, 7th, 13th, 25th and 49th insertions; each reinserts as many pairs as the map held at that moment.
solution: With 4 buckets the 4th key gives load $4/4 > 0.75$ (4 pairs reinserted, 8 buckets). The 7th key gives $7/8$ (7 pairs, 16 buckets), the 13th gives $13/16$ (13 pairs, 32 buckets), the 25th gives $25/32$ (25 pairs, 64 buckets) and the 49th gives $49/64$ (49 pairs, 128 buckets). The total is $4 + 7 + 13 + 25 + 49 = 98$, less than twice the 50 insertions, which illustrates amortized $O(1)$ cost.
