@article
Is the Turing machine too weak or too simple a model? We answer by trying to make it stronger. Every reasonable enhancement turns out to recognize exactly the same languages, which is why the model is considered robust.

### Equivalent variants

**Multitape machines.** A $k$-tape TM has $k$ tapes with independent heads, and its transitions read all $k$ symbols at once.

*Theorem.* Every multitape TM has an equivalent single-tape TM.

The single-tape machine stores all $k$ tapes on one tape, separated by a marker `#`, and marks each head position by a dotted copy of the symbol under it. To simulate one step it scans the whole tape to find the $k$ symbols under the heads, then scans again to update them. If the multitape machine runs $t$ steps, the tape holds $O(t)$ cells, so the simulation takes $O(t^2)$ steps: **a quadratic slowdown, not a gain in power**.

**Nondeterministic machines.** A nondeterministic TM (NTM) has $\delta : Q \times \Gamma \to \mathcal{P}(Q \times \Gamma \times \{L,R\})$. It accepts if *some* branch of its computation tree reaches $q_{\text{accept}}$.

*Theorem.* Every NTM has an equivalent deterministic TM.

The deterministic machine explores the computation tree **breadth first**, trying all computations of length 1, then length 2, and so on, and accepts if it finds an accepting configuration. Depth-first search would be wrong, since it could follow an infinite branch forever and never reach an accepting branch elsewhere. The cost is exponential: an NTM running in time $t(n)$ is simulated in time $2^{O(t(n))}$. Whether this blowup is unavoidable is the P versus NP question next week.

**Enumerators.** An **enumerator** is a TM with a printer that outputs strings, in any order and possibly with repeats. *A language is Turing-recognizable if and only if some enumerator prints exactly its strings.* One direction runs a recognizer on the strings $s_1, s_2, \dots$ in **shortlex order** (by length, then alphabetically) using **dovetailing**: in stage $k$, run the recognizer on each of $s_1, \dots, s_k$ for $k$ steps, printing any string that has accepted. Dovetailing avoids getting stuck on a string on which the recognizer loops.

### Other models

Random-access machines, Python programs, and the **$\lambda$-calculus** (a formalism for functions) all compute exactly the functions Turing machines compute, given unbounded memory.

### The Church–Turing thesis

> Every effective procedure, that is, every process that a human could carry out by following precise mechanical rules, can be carried out by a Turing machine.

This is a **thesis**, not a theorem: it connects an informal idea ("algorithm") with a formal one, so it cannot be proved. The evidence is the convergence of independent definitions, and no counterexample. In practice it lets us describe algorithms in pseudocode or Python and know a Turing machine exists. It also lets us talk about objects given to an algorithm through an **encoding** such as $\langle G \rangle$ for a graph $G$ or $\langle M, w \rangle$ for a machine and its input.

The **extended Church–Turing thesis** claims that any reasonable computer can be simulated by a TM with only a polynomial slowdown. It is not established, and quantum computing is a standing challenge to it, since some problems (such as integer factoring) have efficient quantum algorithms but no known efficient classical algorithm.

### Levels of description

TM algorithms can be given at three levels: a **formal** description (the full tuple), an **implementation** description (how the head and tape are used), and a **high-level** description (an algorithm in prose). From now on we mainly use high-level descriptions.

@example
title: Dovetailing a recognizer
problem: A TM $R$ recognizes $L$, but may loop on strings not in $L$. Describe an enumerator for $L$.
step: List all strings in shortlex order: $s_1 = \varepsilon$, and so on. The enumerator works in stages $k = 1, 2, 3, \dots$.
step: In stage $k$, for each $i \le k$ run $R$ on $s_i$ for exactly $k$ steps. If $R$ has accepted $s_i$ by then, print $s_i$.
step: If $s \in L$, then $R$ accepts $s = s_i$ in some finite number $t$ of steps, so in every stage $k \ge \max(i, t)$ the enumerator prints $s$ (possibly again). Every string of $L$ is printed.
step: If $s \notin L$, then $R$ never accepts it, so it is never printed. A looping $R$ cannot block the enumerator, because every run is cut off after $k$ steps.
answer: The dovetailing enumerator prints exactly the strings of $L$.

@example
title: Position in shortlex order
problem: In shortlex order over $\{0,1\}$ (the empty string first, then by length, then alphabetically), what is the position, counting from 1, of the string $101$?
step: Strings shorter than length $3$ come first: $1 + 2 + 4 = 7$ of them ($\varepsilon$, then $0$ and $1$, then the four of length $2$).
step: Among strings of length $3$, alphabetical order is the same as the order of the numbers $000, 001, \dots$ read in binary. The string $101$ is binary $5$, so it is the $6$th of length $3$ counting from $000$.
step: The position is $7 + 6 = 13$.
answer: $13$

@mistakes
- Believing the Church–Turing thesis has been proved. It is a thesis relating an informal notion to a formal one.
- Simulating a nondeterministic machine depth first. A single infinite branch would prevent the simulation from finding an accepting branch elsewhere.
- Running a recognizer to completion on one string at a time when enumerating: a looping run would block everything after it. Dovetail instead.
- Assuming that equal computability means equal speed. Variants differ in efficiency (multitape machines are polynomially faster) but not in what they can compute.

model:
```python
from itertools import product


def shortlex(alphabet, n):
    result = []
    length = 0
    while len(result) < n:
        for symbols in product(alphabet, repeat=length):
            if len(result) == n:
                break
            result.append("".join(symbols))
        length += 1
    return result
```
hint: Produce all strings of length 0, then all of length 1, and so on, stopping as soon as you have `n`.
hint: `itertools.product(alphabet, repeat=length)` gives the strings of one length in alphabetical order.
solution: Generate the strings length by length with `product`, which yields them in alphabetical order for a given length, and stop when the result has `n` items. Because every length is exhausted before the next begins, the output is in shortlex order.

model:
```python
def first_to_halt(gens, limit):
    for _ in range(limit):
        for i, g in enumerate(gens):
            try:
                next(g)
            except StopIteration:
                return i
    return None
```
hint: Use two nested loops: rounds on the outside, generators on the inside.
hint: Catch `StopIteration` around `next(g)`. The generator that raises it has halted.
solution: This is dovetailing: every machine advances one step per round, so a machine that loops forever (like `forever`) cannot prevent another one from being noticed. A generator `counter(n)` halts on its $(n+1)$th call to `next`, which is why `counter(10)` needs `limit` of at least 11.

@practice self
prompt: Give a high-level description of a Turing machine that decides $\{w\#w : w \in \{0,1\}^*\}$, and trace its first two passes on $01\#01$.
solution: Machine: on input $x$: (1) Check that $x$ contains exactly one $\#$; if not, reject. (2) Zigzag: repeatedly take the first unmarked symbol to the left of $\#$, remember it (in the state), mark it (for example, replace it by a crossed-off version), move right past $\#$ to the first unmarked symbol there, and compare. If it is a different symbol, or there is none, reject; otherwise mark it. Then return to the left end. (3) When no unmarked symbol is left on the left of $\#$, check that no unmarked symbol remains on the right; if none remains, accept, otherwise reject. Trace on $01\#01$: pass 1 marks the left $0$ and the first $0$ after $\#$, giving $\hat{0}1\#\hat{0}1$; pass 2 marks the $1$ on the left and the $1$ on the right, giving $\hat{0}\hat{1}\#\hat{0}\hat{1}$; now no unmarked symbol is left on either side, so the machine accepts.
hint: Compare one position at a time: cross off a symbol on the left, then the matching symbol on the right of the $\#$.
hint: The state can remember the one symbol being carried across the $\#$.
rubric: Cross-off comparison of corresponding positions, with the carried symbol remembered in the state.
rubric: Handles the end cases: unequal lengths, a missing or repeated $\#$.
rubric: The trace shows both passes with the marked symbols.

model:
```python
def count_halting(gens, rounds):
    alive = list(gens)
    halted = 0
    for _ in range(rounds):
        still = []
        for g in alive:
            try:
                next(g)
                still.append(g)
            except StopIteration:
                halted += 1
        alive = still
    return halted
```
hint: Keep a list of generators that are still running and drop each one when it raises `StopIteration`.
hint: `counter(n)` halts on its $(n+1)$th call to `next`, so it halts within `rounds` rounds only if `rounds >= n + 1`.
solution: In each round, step every live generator; those that raise `StopIteration` are counted and removed. A generator that never halts, such as `forever()`, stays alive for all rounds and is never counted, which shows that "has not halted yet" never tells you it will not halt later.
