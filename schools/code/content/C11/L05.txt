@article
Regular languages cannot match nested structure such as balanced parentheses or $\{0^n 1^n\}$. **Context-free grammars (CFGs)** can, and they are the formalism behind the syntax of programming languages and the parsers in compilers.

### Definition

A CFG is a 4-tuple $G = (V, \Sigma, R, S)$:

- $V$ is a finite set of **variables** (nonterminals);
- $\Sigma$ is a finite set of **terminals**, disjoint from $V$;
- $R$ is a finite set of **rules** $A \to w$ with $A \in V$ and $w \in (V \cup \Sigma)^*$;
- $S \in V$ is the **start variable**.

Write $A \to w_1 | w_2$ as a shorthand for two rules. A **derivation** starts with $S$ and repeatedly replaces one variable by the right-hand side of one of its rules. If $u \Rightarrow v$ means "$v$ results from $u$ by one rule application" and $S \Rightarrow^* w$ with $w \in \Sigma^*$, then $w$ is **generated** by $G$. The language $L(G)$ is the set of generated strings. A language is **context-free** if some CFG generates it.

"Context-free" means that a rule $A \to w$ may be applied wherever $A$ occurs, regardless of the surrounding symbols.

### First grammars

- $S \to 0S1 | \varepsilon$ generates $\{0^n1^n : n \ge 0\}$. Each use of the first rule wraps a matched pair around the middle.
- $S \to (S)S | \varepsilon$ generates the balanced strings of parentheses.
- $S \to aSa | bSb | a | b | \varepsilon$ generates the palindromes over $\{a,b\}$.

Every regular language is context-free (translate a DFA: one variable per state, $q \to a\,r$ for each transition, $q \to \varepsilon$ for each accepting state), but not conversely.

### Parse trees and ambiguity

A **parse tree** shows how a string was derived: the root is $S$, each internal node is a variable whose children are the symbols of the right-hand side used, and the leaves read left to right give the string. Different derivation *orders* can give the same tree. A **leftmost derivation** always expands the leftmost variable and corresponds to exactly one parse tree.

A grammar is **ambiguous** if some string has two or more parse trees (equivalently, two leftmost derivations). For $E \to E+E \,|\, E*E \,|\, a$, the string $a+a*a$ has two trees: one groups it as $(a+a)*a$ and the other as $a+(a*a)$. A compiler needs one meaning, so we rewrite the grammar to build precedence into it:

$$E \to E+T \,|\, T, \qquad T \to T*F \,|\, F, \qquad F \to (E) \,|\, a.$$

Now $*$ binds tighter than $+$ and each operator is left-associative. Ambiguity belongs to a grammar, not always to a language, but some context-free languages are **inherently ambiguous**: every grammar for them is ambiguous.

### Normal form and closure

Every CFG can be converted to **Chomsky normal form**, in which every rule has the form $A \to BC$ or $A \to a$ (plus $S \to \varepsilon$ if needed). A string of length $n \ge 1$ then has a derivation with exactly $2n - 1$ steps, and this gives a decision procedure for membership. Context-free languages are closed under union, concatenation and star, but not under intersection or complement.

@example
title: Deriving and drawing 0011
problem: Using $S \to 0S1 | \varepsilon$, derive $0011$ and describe its parse tree.
step: Start with $S$. Apply $S \to 0S1$: $S \Rightarrow 0S1$.
step: Apply $S \to 0S1$ to the remaining $S$: $0S1 \Rightarrow 00S11$.
step: Apply $S \to \varepsilon$: $00S11 \Rightarrow 0011$. There are three rule applications, and only one choice of rule is possible at each point, so there is only one parse tree.
step: The tree has the root $S$ with children $0$, $S$, $1$. That inner $S$ again has children $0$, $S$, $1$, and the innermost $S$ has the single child $\varepsilon$. Reading the leaves left to right gives $0011$.
answer: $S \Rightarrow 0S1 \Rightarrow 00S11 \Rightarrow 0011$.

@example
title: A grammar for an "or" language
problem: Write a grammar for $L = \{a^i b^j c^k : i = j \text{ or } j = k\}$.
step: $L$ is the union of $L_1 = \{a^ib^ic^k\}$ and $L_2 = \{a^ib^jc^j\}$. Union of grammars is easy: a new start variable with a rule to each part.
step: For $L_1$: a part that matches $a$s with $b$s, followed by free $c$s. Use $X \to aXb | \varepsilon$ for the matched part and $C \to cC | \varepsilon$ for any number of $c$s.
step: For $L_2$: free $a$s followed by a part that matches $b$s with $c$s: $A \to aA | \varepsilon$ and $Y \to bYc | \varepsilon$.
step: Combine them: $S \to XC \,|\, AY$.
step: Check $abcc$ (here $i = j = 1$ and $k = 2$) with $S \Rightarrow XC$: $X \Rightarrow aXb \Rightarrow ab$ and $C \Rightarrow cC \Rightarrow ccC \Rightarrow cc$, so $S \Rightarrow XC \Rightarrow^* abcc$.
answer: $S \to XC | AY$, $X \to aXb | \varepsilon$, $C \to cC | \varepsilon$, $A \to aA | \varepsilon$, $Y \to bYc | \varepsilon$. (A string with $i = j = k$ has two parse trees, so this grammar is ambiguous; in fact $L$ is inherently ambiguous.)

@mistakes
- Confusing variables with terminals: a derivation is finished only when no variable remains.
- Using a rule such as $S \to 0S1S$ when you want a *matched* pair: counts are matched only when a single rule grows both sides at once.
- Believing a grammar and its language are the same thing. Two different grammars can generate the same language, and one may be ambiguous while the other is not.
- Assuming that a string with two different *derivations* is ambiguous. Ambiguity needs two different *parse trees* (equivalently, two leftmost derivations).

model:
```python
def generate(rules, start, max_len):
    seen = {start}
    todo = [start]
    out = set()
    while todo:
        form = todo.pop()
        pos = None
        for i, ch in enumerate(form):
            if ch.isupper():
                pos = i
                break
        if pos is None:
            out.add(form)
            continue
        for rhs in rules[form[pos]]:
            new = form[:pos] + rhs + form[pos + 1:]
            if len(new) <= max_len and new not in seen:
                seen.add(new)
                todo.append(new)
    return sorted(out, key=lambda s: (len(s), s))
```
hint: Search over sentential forms, always expanding the leftmost variable.
hint: A form with no uppercase letters is a generated string. Skip forms longer than `max_len` and forms you have already seen.
solution: Do a graph search whose nodes are sentential forms. Expand the leftmost uppercase letter with each of its right-hand sides, drop results longer than `max_len` (they can never shrink), and collect the forms without variables. Sort by `(len(s), s)`. Leftmost expansion reaches every generated string, because every derivation can be rearranged into a leftmost one.

model:
```python
def evaluate(s):
    pos = 0

    def peek():
        return s[pos] if pos < len(s) else ""

    def expr():
        nonlocal pos
        value = term()
        while peek() == "+":
            pos += 1
            value += term()
        return value

    def term():
        nonlocal pos
        value = factor()
        while peek() == "*":
            pos += 1
            value *= factor()
        return value

    def factor():
        nonlocal pos
        if peek() == "(":
            pos += 1
            value = expr()
            pos += 1  # skip the closing parenthesis
            return value
        value = int(s[pos])
        pos += 1
        return value

    return expr()
```
hint: Write one function for each variable: `expr`, `term` and `factor`, each calling the one below it.
hint: The left-recursive rules $E \to E+T$ and $T \to T*F$ become loops: parse a `term` (or `factor`), then keep reading `+` (or `*`) and another operand while you see that operator.
solution: This is recursive-descent parsing. `factor` handles a digit or a parenthesized `expr`; `term` multiplies factors; `expr` adds terms. Because `expr` calls `term` and `term` calls `factor`, products are computed before sums, which is exactly the precedence the grammar encodes.

Each use of $S \to aSc$ adds one $a$ on the left and one $c$ on the right, so after $n$ such steps and then $S \to T$ we get $a^n b^m c^m c^n = a^n b^m c^{n+m}$. Derivation of $abcc$: $S \Rightarrow aSc \Rightarrow aTc \Rightarrow abTcc \Rightarrow abcc$. Conversely, the $c$s are always generated in matched pairs with an $a$ or a $b$, nested outside to inside, so the number of $c$s is the number of $a$s plus the number of $b$s.

@quiz num
prompt: With the ambiguous grammar $E \to E+E \,|\, a$, how many different parse trees does the string $a+a+a$ have?
answer: 2
check: comb(4, 2) // 3
hint: The string has two $+$ signs. Either the left or the right $+$ is the root of the tree.
solution: The root can be the first $+$, giving $a+(a+a)$, or the second $+$, giving $(a+a)+a$. Each choice is then unique, so there are $2$ parse trees. This count is the Catalan number $C_2 = \binom{4}{2}/3 = 2$.
