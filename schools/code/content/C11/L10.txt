@article
Last week we proved that $A_{\mathrm{TM}}$ is undecidable. This week we use it as a starting point, and **reductions** carry the result to other problems.

### The halting problem

$$\mathrm{HALT}_{\mathrm{TM}} = \{\langle M, w \rangle : M \text{ is a TM that halts on input } w\}.$$

**Theorem.** $\mathrm{HALT}_{\mathrm{TM}}$ is undecidable.

The same diagonal idea works for programs. Suppose a function `halts(program, data)` always correctly says whether `program(data)` finishes. Define a program that does the opposite of what the checker predicts about it. Run on itself, if the checker says it halts, it loops; if the checker says it loops, it halts. Either way the checker is wrong, so no correct `halts` exists.

### Mapping reductions

A function $f : \Sigma^* \to \Sigma^*$ is **computable** if some TM halts on every input $w$ with just $f(w)$ on its tape. Language $A$ is **mapping reducible** to $B$, written $A \le_m B$, if there is a computable $f$ such that for every string $w$,

$$w \in A \iff f(w) \in B.$$

The function $f$ is the *reduction*. It converts questions about $A$ into questions about $B$.

**Theorem.** If $A \le_m B$ and $B$ is decidable, then $A$ is decidable. (Decide $A$ by computing $f(w)$ and running the decider for $B$.) The same holds for recognizable.

**Corollary.** If $A \le_m B$ and $A$ is undecidable, then $B$ is undecidable.

The corollary is the working tool. **To prove a new problem $B$ undecidable, reduce a known undecidable problem $A$ to $B$.** The direction matters: you map the known-hard problem *into* the new problem.

### Example reductions

**$A_{\mathrm{TM}} \le_m \mathrm{HALT}_{\mathrm{TM}}$.** Given $\langle M, w \rangle$, build $M'$ that runs $M$ on its input; if $M$ accepts, $M'$ accepts; if $M$ rejects, $M'$ loops forever. Then $M$ accepts $w$ if and only if $M'$ halts on $w$.

**$E_{\mathrm{TM}} = \{\langle M \rangle : L(M) = \emptyset\}$ is undecidable.** Given $\langle M, w \rangle$, build $M_w$: *on any input $x$, ignore $x$, run $M$ on $w$, and accept if $M$ accepts.* If $M$ accepts $w$ then $L(M_w) = \Sigma^*$; otherwise $L(M_w) = \emptyset$. So $M$ accepts $w$ if and only if $\langle M_w \rangle \notin E_{\mathrm{TM}}$. This maps $A_{\mathrm{TM}}$ to the *complement* of $E_{\mathrm{TM}}$; as a decider for $E_{\mathrm{TM}}$ would give one for its complement, $E_{\mathrm{TM}}$ is undecidable.

### Rice's theorem

A property of languages is **non-trivial** if some Turing-recognizable language has it and some does not.

**Rice's theorem.** If $P$ is a non-trivial property of languages, then $\{\langle M \rangle : L(M) \text{ has property } P\}$ is undecidable.

So it is undecidable whether $L(M)$ is empty, is regular, is finite, contains a particular string, or equals a given language. Rice's theorem applies only to properties of the **language** $L(M)$, not of the machine's description: "does $M$ have more than $10$ states?" is decidable by reading the description.

### Recognizable and co-recognizable

A language is **co-recognizable** if its complement is recognizable. *A language is decidable if and only if it is both recognizable and co-recognizable.* (Run both recognizers in parallel; exactly one accepts.) Since $A_{\mathrm{TM}}$ is recognizable but not decidable, its complement is **not** recognizable.

@example
title: The halting problem in code
problem: Show that no correct Python function `halts(program, data)` can exist.
step: Suppose `halts(program, data)` always returns `True` if `program(data)` finishes and `False` if it runs forever. Write a program that uses it:

```python
def paradox(program):
    if halts(program, program):
        while True:       # loop forever
            pass
    return "done"         # halt
```
step: Call `paradox(paradox)`. If `halts(paradox, paradox)` returns `True`, then `paradox(paradox)` enters the infinite loop, so it does not halt.
step: If `halts(paradox, paradox)` returns `False`, then `paradox(paradox)` returns `"done"`, so it does halt.
step: In both cases the checker was wrong about this one input, so `halts` is not correct. The assumption that it exists must be false.
answer: A correct halting checker cannot exist; this is the halting problem.

@example
title: Reducing A_TM to the complement of E_TM
problem: Prove that $E_{\mathrm{TM}}$ is undecidable by a reduction from $A_{\mathrm{TM}}$.
step: Suppose a decider $R$ for $E_{\mathrm{TM}}$ exists. We will build a decider for $A_{\mathrm{TM}}$, which cannot exist.
step: On input $\langle M, w \rangle$, build the description of the machine $M_w$ that ignores its input, runs $M$ on $w$, and accepts if $M$ accepts. Constructing $\langle M_w \rangle$ only rewrites a description, so it is computable.
step: If $M$ accepts $w$, then $M_w$ accepts every string and $L(M_w) \ne \emptyset$. If $M$ does not accept $w$, then $L(M_w) = \emptyset$.
step: Run $R$ on $\langle M_w \rangle$. If $R$ accepts (the language is empty), reject $\langle M, w \rangle$; if $R$ rejects, accept it.
step: This decides $A_{\mathrm{TM}}$, a contradiction. So $R$ does not exist and $E_{\mathrm{TM}}$ is undecidable.
answer: $E_{\mathrm{TM}}$ is undecidable.

@mistakes
- Reducing in the wrong direction. To show $B$ is undecidable, reduce a *known undecidable* problem $A$ to $B$, not the other way around.
- Having the reduction *run* $M$ on $w$ to decide something. A reduction only constructs $\langle M_w \rangle$; it must not simulate unboundedly, because it has to halt.
- Applying Rice's theorem to properties of the machine's code (number of states, whether it uses a symbol), which are decidable.
- Forgetting that decidable languages are closed under complement, which is why reducing to the complement of a language is enough.

@practice code
prompt: Model a machine as a Python function `make_gen()` that returns a generator which yields once per step and, when it halts, returns `True` (accept) or `False` (reject); a machine that never halts simply never finishes. Write `loop_on_reject(make_gen)` that returns a new function `new_make_gen` of the same kind. The new machine runs the original step by step; if the original accepts, it accepts; if the original rejects, it **loops forever** (yielding forever). This is the reduction from $A_{\mathrm{TM}}$ to the halting problem: the new machine halts exactly when the original accepts.
starter:
```python
def loop_on_reject(make_gen):
    pass
```
tests:
```python
def acc():
    yield
    yield
    return True


def rej():
    yield
    return False


def spin():
    while True:
        yield


def run_steps(g, k):
    for _ in range(k):
        try:
            next(g)
        except StopIteration as e:
            return ("halt", e.value)
    return ("running", None)


assert run_steps(rej(), 50) == ("halt", False)
assert run_steps(loop_on_reject(acc)(), 50) == ("halt", True)
assert run_steps(loop_on_reject(rej)(), 50) == ("running", None)
assert run_steps(loop_on_reject(spin)(), 50) == ("running", None)
```
model:
```python
def loop_on_reject(make_gen):
    def new_make_gen():
        g = make_gen()
        while True:
            try:
                next(g)
            except StopIteration as e:
                result = e.value
                break
            yield
        if result:
            return True
        while True:
            yield
    return new_make_gen
```
hint: Run the original generator one `next` at a time inside your own generator, yielding once for every step it takes.
hint: When the original raises `StopIteration`, its `.value` is the answer. If it is `True`, return `True`; otherwise enter an endless `while True: yield` loop.
solution: The new machine simulates the old one step by step, so it halts only if the old one does. On acceptance it returns `True`; on rejection it spins forever. Hence the new machine halts if and only if the old one accepts, which is how $\langle M, w \rangle \in A_{\mathrm{TM}}$ is turned into $\langle M', w \rangle \in \mathrm{HALT}_{\mathrm{TM}}$.

@practice self
prompt: Let $\mathrm{ACCEPTS}_\varepsilon = \{\langle M \rangle : M \text{ is a TM that accepts the empty string}\}$. Prove it is undecidable by a reduction from $A_{\mathrm{TM}}$.
solution: Suppose a decider $R$ for $\mathrm{ACCEPTS}_\varepsilon$ exists. We build a decider $S$ for $A_{\mathrm{TM}}$. On input $\langle M, w \rangle$, $S$ constructs the description of a machine $M'$: on any input $x$, $M'$ ignores $x$, runs $M$ on $w$, and accepts if $M$ accepts (and rejects if $M$ rejects, looping if $M$ loops). The construction only rewrites a description, so $S$ always finishes it. Then $M'$ accepts the empty string if and only if $M$ accepts $w$. $S$ runs $R$ on $\langle M' \rangle$ and gives the same answer. Since $R$ always halts, so does $S$, and $S$ accepts $\langle M, w \rangle$ exactly when $M$ accepts $w$. This decides $A_{\mathrm{TM}}$, which is impossible, so $R$ does not exist.
hint: Build a machine $M'$ whose behavior on the empty string encodes whether $M$ accepts $w$.
hint: Let $M'$ ignore its input and simulate $M$ on $w$. The reduction constructs $M'$ but never runs it.

rubric: The constructed machine $M'$ ignores its input and simulates $M$ on $w$.

```python
def simulate_bounded(make_gen, k):
    g = make_gen()
    for _ in range(k):
        try:
            next(g)
        except StopIteration as e:
            return "accept" if e.value is True else "reject"
    return "unknown"
```
hint: The answer of a halting generator is the `value` attribute of the `StopIteration` exception.
hint: `acc` yields twice and then returns, so its third call to `next` raises `StopIteration`.
solution: Call `next` up to `k` times. A `StopIteration` means the machine halted, and `e.value` tells whether it accepted. If the loop ends without a halt, the answer is genuinely unknown, which is why a bounded simulation can never replace a decider.
