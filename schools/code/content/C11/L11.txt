@article
So far we asked whether a problem can be solved at all. Now we ask how much **time** it takes, measured as the number of TM steps as a function of the input length $n$.

### Time complexity classes

For a function $t : \mathbb{N} \to \mathbb{N}$, $\mathrm{TIME}(t(n))$ is the set of languages decided by some deterministic TM that runs in $O(t(n))$ steps on inputs of length $n$. The class

$$\mathrm{P} = \bigcup_{k \ge 1} \mathrm{TIME}(n^k)$$

is the set of languages decidable in **polynomial time**. P is the standard formalization of "efficiently solvable". It is robust: all the reasonable deterministic models (multitape TMs, random-access machines) simulate one another with polynomial overhead, so P does not depend on the model. Examples in P:

- **PATH**: is there a directed path from $s$ to $t$ in a graph? Breadth-first search takes $O(V + E)$ time.
- **Relative primality** of two numbers, by Euclid's algorithm, in time polynomial in the number of digits.
- Every context-free language, by dynamic programming in $O(n^3)$ time.
- **PRIMES**: whether a number is prime is in P, as proved by a polynomial-time algorithm.

Be careful about what $n$ means: the length of the input *in symbols*. Testing a number $N$ for primality by trial division takes about $\sqrt{N}$ divisions, but $N$ has only $\log_2 N$ bits, so this is exponential in the input length.

### Exponential growth

| $n$ | $n^2$ | $2^n$ |
|---|---|---|
| 10 | 100 | 1,024 |
| 20 | 400 | 1,048,576 |
| 50 | 2,500 | about $1.1 \times 10^{15}$ |

A brute-force search over all subsets of $n$ items examines $2^n$ candidates, which is hopeless for $n = 50$.

### Verifiers and the class NP

Some problems have a hard-looking search but an easy check. A **verifier** for a language $A$ is an algorithm $V$ such that

$$w \in A \iff \text{there is a string } c \text{ such that } V \text{ accepts } \langle w, c \rangle.$$

The string $c$ is a **certificate** (or witness). A **polynomial-time verifier** runs in time polynomial in $|w|$; this forces the certificate to be of polynomial length too. **NP** is the class of languages with polynomial-time verifiers. Equivalently, NP is the class of languages decided by *nondeterministic* TMs in polynomial time: the NTM guesses the certificate and then runs the verifier. The name stands for "nondeterministic polynomial time", not "non-polynomial".

Examples in NP:

- **HAMPATH**: given a directed graph and two vertices $s$ and $t$, is there a path from $s$ to $t$ that visits every vertex exactly once? Certificate: the path.
- **CLIQUE**: does an undirected graph have $k$ vertices that are pairwise adjacent? Certificate: the $k$ vertices.
- **SUBSET-SUM**: do some of the numbers $x_1, \dots, x_m$ sum to a target $t$? Certificate: the chosen numbers.
- **COMPOSITES**: is $N$ composite? Certificate: a divisor $d$ with $1 < d < N$.
- **SAT**: does a Boolean formula have a satisfying assignment? Certificate: the assignment.

### What is known

$\mathrm{P} \subseteq \mathrm{NP}$: a polynomial-time decider is a verifier that ignores its certificate. Also $\mathrm{NP} \subseteq \mathrm{EXPTIME}$, since trying all certificates of polynomial length takes exponential time. Whether $\mathrm{P} = \mathrm{NP}$ is a famous open problem, and one of the Clay Mathematics Institute's Millennium Prize Problems. Most researchers believe $\mathrm{P} \ne \mathrm{NP}$, but there is no proof either way.

@example
title: Showing a language is in NP
problem: Show that SUBSET-SUM $= \{\langle x_1, \dots, x_m, t \rangle : \text{some subset of the } x_i \text{ sums to } t\}$ is in NP.
step: A certificate is the list of indices $i_1 < \dots < i_r$ of the chosen numbers. It has at most $m$ entries, so its length is polynomial in the input.
step: The verifier $V$ on $\langle \langle x_1, \dots, x_m, t \rangle, c \rangle$ checks that the indices in $c$ are distinct and in the range $1..m$, adds up the corresponding numbers and accepts if the sum equals $t$.
step: This takes $O(m)$ additions of numbers whose lengths are bounded by the input length, so the verifier runs in polynomial time.
step: If a subset with sum $t$ exists, its indices make $V$ accept; if none exists, no certificate makes $V$ accept. So SUBSET-SUM $\in$ NP.
answer: SUBSET-SUM is in NP, with the chosen indices as the certificate.

@example
title: Brute-force cost
problem: A brute-force algorithm checks every subset of $n = 30$ numbers against a target, doing $30$ additions per subset at most. How many subsets are there, and why is this not a polynomial-time algorithm?
step: A set of $30$ elements has $2^{30}$ subsets, and $2^{30} = 1{,}073{,}741{,}824$.
step: Doing up to $30$ additions each gives at most about $3.2 \times 10^{10}$ additions, and each extra number in the input doubles the work.
step: The running time $2^n \cdot n$ grows exponentially in $n$, faster than any polynomial $n^k$, so this is not polynomial time. A polynomial-time algorithm for SUBSET-SUM would show $\mathrm{P} = \mathrm{NP}$, since the problem is NP-complete.
answer: There are $2^{30} = 1{,}073{,}741{,}824$ subsets; the running time is exponential in the number of items.

@mistakes
- Reading NP as "not polynomial". NP stands for nondeterministic polynomial time, and $\mathrm{P} \subseteq \mathrm{NP}$.
- Forgetting that the verifier itself must run in polynomial time and the certificate must be short; "the whole answer" is not a certificate if it is exponentially long.
- Measuring time by the *value* of a number rather than the number of its digits (for example in trial division).
- Concluding that a problem in NP is hard. Many NP problems, including every problem in P, are easy.

model:
```python
def verify_subset_sum(nums, target, indices):
    if len(set(indices)) != len(indices):
        return False
    for i in indices:
        if i < 0 or i >= len(nums):
            return False
    return sum(nums[i] for i in indices) == target
```
hint: A verifier checks a certificate; it never searches. Check the certificate's validity first, then its sum.
hint: Distinct indices means the set of indices has the same length as the list. Reject negative and out-of-range positions before using them.
solution: Reject a certificate with repeated or out-of-range indices (a negative index would wrongly wrap around in Python), then compare the sum of the chosen numbers with the target. This runs in time linear in the certificate length.

assert verify_clique(edges, 3, [0, 1, 2]) is True
assert verify_clique(edges, 3, [1, 2, 3]) is False

model:
```python
def verify_clique(edges, k, vertices):
    if len(vertices) != k or len(set(vertices)) != k:
        return False
    adjacent = set()
    for u, v in edges:
        adjacent.add((u, v))
        adjacent.add((v, u))
    for i in range(k):
        for j in range(i + 1, k):
            if (vertices[i], vertices[j]) not in adjacent:
                return False
    return True
```
hint: Store the edges in both directions in a set so that adjacency checks are quick.
hint: Check the length and distinctness first, then every pair of positions `i < j`.
solution: First check that the certificate has exactly `k` distinct vertices; then check that all $\binom{k}{2}$ pairs are adjacent. The work is polynomial in the size of the graph, so CLIQUE has a polynomial-time verifier.

@practice self
prompt: Show that COMPOSITES $= \{N : N \text{ is a composite number}\}$ is in NP, where $N$ is given in binary. State the certificate, the verifier, and why it runs in polynomial time in the length of the input.
solution: A number $N > 1$ is composite if and only if it has a divisor $d$ with $1 < d < N$. Let the certificate be such a divisor $d$, written in binary. It has at most as many bits as $N$, so it is short. The verifier on $\langle N, d \rangle$ checks that $1 < d < N$ and that $d$ divides $N$ (one division with remainder), and accepts if both hold. Long division on numbers with $b$ bits takes time polynomial in $b$ (for example $O(b^2)$). If $N$ is composite, its divisor makes the verifier accept; if $N$ is prime (or $N \le 1$), no $d$ works. So COMPOSITES is in NP.
hint: Which short piece of information proves that $N$ is composite?
hint: A verifier only has to check that the divisor works: one range check and one division.
rubric: The certificate is a divisor $d$ of $N$ with $1 < d < N$, and its length is bounded by that of $N$.
rubric: The verifier checks the range and divisibility, and accepts correctly in both directions (composite and not).
rubric: The running time is measured in the number of bits of $N$, not in its value.

model:
```python
from itertools import permutations


def has_hamiltonian_path(n, edges):
    adjacent = set()
    for u, v in edges:
        adjacent.add((u, v))
        adjacent.add((v, u))
    for order in permutations(range(n)):
        if all((order[i], order[i + 1]) in adjacent for i in range(n - 1)):
            return True
    return False
```
hint: Try every ordering of the vertices with `itertools.permutations`.
hint: An ordering works when every consecutive pair is an edge; a one-vertex ordering has no pairs to check.
solution: Enumerate all $n!$ orderings and test whether each consecutive pair is an edge, in either direction. This is exponential time, in contrast with the polynomial-time verifier that checks one given ordering.
