@article
**Relational algebra** is a small set of operators that take relations as input and produce a relation as output. Because the output is again a relation, operators compose into **expressions**. SQL is built on this algebra, and a database's query optimizer rewrites queries internally as algebra trees (week 10), so learning the algebra now explains much of SQL later. In this lesson relations are **sets**: results never contain duplicates.

### The basic operators

- **Selection** $\sigma_{p}(R)$ keeps the tuples of $R$ for which predicate $p$ is true. Example: $\sigma_{major='CS'}(Student)$.
- **Projection** $\pi_{A_1,\dots,A_k}(R)$ keeps only the listed attributes and removes duplicate tuples that result. Example: $\pi_{major}(Student)$ lists each major once.
- **Union** $R \cup S$, **difference** $R - S$ and **intersection** $R \cap S$ combine two relations that are **union-compatible**: same number of attributes with matching domains.
- **Cartesian product** $R \times S$ pairs every tuple of $R$ with every tuple of $S$. Its cardinality is $|R| \cdot |S|$ and its degree is the sum of the degrees.
- **Rename** $\rho_{T(B_1,\dots,B_k)}(R)$ gives a relation, and optionally its attributes, new names. It is needed to join a relation with itself and to avoid name clashes.

The five operators selection, projection, union, difference and product (with rename) are enough to express every other operator below. A query language that can express everything these can is called **relationally complete**.

### Joins

A **theta join** $R \bowtie_{\theta} S$ is defined as $\sigma_{\theta}(R \times S)$. An **equijoin** uses only equality conditions. The **natural join** $R \bowtie S$ equates all attributes with the same name in both relations and keeps one copy of each. If there are no common attributes, the natural join equals the product.

Suppose `Student(sid, name, major)` and `Took(sid, cid, grade)`. Then $Student \bowtie Took$ pairs each student with their course rows. A student who took nothing disappears from the result, which is why the outer joins of week 4 exist.

### Division

Division answers "for all" questions. For $R(A, B)$ and $S(B)$, the quotient $R \div S$ contains the values $a$ such that for **every** $b \in S$ the tuple $(a, b)$ is in $R$. Using the basic operators:

$$R \div S = \pi_A(R) - \pi_A\big((\pi_A(R) \times S) - R\big)$$

Read it as: take all candidate $a$ values, build every pair they would need, subtract the pairs that really exist, and remove the candidates that have a missing pair.

### Useful equivalences

Selections can be cascaded and reordered: $\sigma_{p \wedge q}(R) = \sigma_p(\sigma_q(R))$. A selection that mentions only attributes of $R$ can be pushed below a join: $\sigma_p(R \bowtie S) = \sigma_p(R) \bowtie S$. Joins are commutative and associative. These identities let an optimizer choose a cheaper order without changing the answer.

### Operators in code

Representing a relation instance as a list of dictionaries, projection is a loop that builds tuples and removes repeats:

```python
def project(rows, attrs):
    seen, out = set(), []
    for row in rows:
        values = tuple(row[a] for a in attrs)
        if values not in seen:
            seen.add(values)
            out.append(dict(zip(attrs, values)))
    return out
```

Selection is a list comprehension, `[r for r in rows if predicate(r)]`. This costs one pass over the input, $O(|R|)$, whereas a naive join is a nested loop over both inputs, $O(|R| \cdot |S|)$.

@example
title: Evaluating an expression
problem: Let Student be the relation below. Evaluate $\pi_{name}(\sigma_{major='CS' \wedge year>1}(Student))$.

| sid | name | major | year |
|---|---|---|---|
| 1 | Ana | CS | 1 |
| 2 | Ben | CS | 3 |
| 3 | Cy | Math | 2 |
| 4 | Di | CS | 2 |
step: Work from the inside out. First evaluate the selection with condition `major = 'CS'` and `year > 1`.
step: Ana is CS but year 1, so she fails. Ben (CS, 3) and Di (CS, 2) pass. Cy is not CS.
step: The selection leaves the tuples for Ben and Di.
step: Projection onto `name` keeps just the names and removes duplicates, of which there are none.
answer: The result has two tuples, `Ben` and `Di`.

@example
title: Students who took no course
problem: With `Student(sid, name)` and `Took(sid, cid)`, write an expression for the ids of students who took no course.
step: "Took no course" is a "not in" question, so use difference.
step: All student ids: $\pi_{sid}(Student)$.
step: Ids of students who took at least one course: $\pi_{sid}(Took)$.
step: The two relations are union-compatible (one attribute `sid`), so subtract.
answer: $\pi_{sid}(Student) - \pi_{sid}(Took)$

@mistakes
- Forgetting that projection removes duplicates in the set algebra, so counting results from a projection gives fewer tuples than rows.
- Applying union, difference or intersection to relations that are not union-compatible.
- Confusing $\sigma$ (chooses rows by a condition) with $\pi$ (chooses columns).
- Using join where division is needed: "took at least one CS course" is a join, "took every CS course" is a division.

model:
```python
def natural_join(r, s):
    if not r or not s:
        return []
    shared = [a for a in r[0] if a in s[0]]
    out = []
    for x in r:
        for y in s:
            if all(x[a] == y[a] for a in shared):
                out.append({**x, **y})
    return out
```
hint: Compute the list of shared attribute names once, from the first row of each relation.
hint: Use a nested loop; `all(...)` over an empty list is `True`, which gives the product case for free.
solution: Find `shared`, then test every pair with `all(x[a] == y[a] for a in shared)` and merge matching pairs with `{**x, **y}`. This is a nested-loop join, $O(|R| \cdot |S|)$ comparisons.

model:
```python
def difference(r, s):
    out = []
    for row in r:
        if row not in s and row not in out:
            out.append(row)
    return out
```
hint: Dictionaries compare equal when they have the same keys and values, so `row in s` works.
hint: Also check that `row` is not already in the output, to remove duplicates.
solution: Scan `r`; keep a row only if it is absent from `s` and not already kept. Whole-dictionary equality is exactly tuple equality for a relation.

@quiz num
prompt: Relation `R(A)` has 6 tuples, `S(A)` has 4 tuples, and 3 tuples appear in both. How many tuples does $R \cup S$ have?
answer: 7
check: 6 + 4 - 3
hint: Tuples in both relations should be counted once.
solution: By inclusion and exclusion, $|R \cup S| = |R| + |S| - |R \cap S| = 6 + 4 - 3 = 7$.
