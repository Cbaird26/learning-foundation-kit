@article
**SQL** (Structured Query Language) is the standard language of relational databases. It is **declarative**: you describe the result you want, and the database decides how to compute it. A basic query has the shape below. The examples run unchanged in SQLite, which ships with Python as the `sqlite3` module.

```sql
SELECT name, price * 1.2 AS price_with_tax
FROM product
WHERE category = 'tool' AND price BETWEEN 5 AND 50
ORDER BY price DESC, name
LIMIT 10;
```

### The clauses

- `SELECT` lists the output columns. Each item may be a column, an expression, or `*` for all columns. `AS` gives an output column an **alias**.
- `FROM` names the table the rows come from.
- `WHERE` keeps only rows for which the predicate is **true**. Rows where it is false or unknown are dropped.
- `ORDER BY` sorts the result; `ASC` (ascending) is the default and `DESC` reverses it. Later keys break ties of earlier ones.
- `LIMIT n OFFSET m` skips `m` rows and returns at most `n`. This is a widely supported extension. The SQL standard spells it `OFFSET m ROWS FETCH FIRST n ROWS ONLY`. Without `ORDER BY`, which rows you get is unspecified.

`SELECT DISTINCT` removes duplicate output rows. Unlike the set algebra of week 2, SQL keeps duplicates unless you ask for `DISTINCT`.

### Predicates

| Predicate | Meaning |
|---|---|
| `a = b`, `a <> b`, `<`, `<=`, `>`, `>=` | comparison (`<>` means not equal) |
| `x BETWEEN lo AND hi` | `x >= lo AND x <= hi`, both ends included |
| `x IN (1, 2, 3)` | `x = 1 OR x = 2 OR x = 3` |
| `s LIKE 'ab%'` | pattern match: `%` is any sequence of characters (even none), `_` exactly one character |
| `x IS NULL` | true when `x` is missing |

`LIKE` is case-sensitive in the SQL standard, but SQLite compares ASCII letters case-insensitively by default, so check your system's rule.

### Boolean logic and precedence

Predicates combine with `NOT`, then `AND`, then `OR`, in that precedence (highest first). So `a OR b AND c` means `a OR (b AND c)`. Use parentheses whenever a condition mixes `AND` and `OR`; they cost nothing and prevent the commonest mistake. Because of three-valued logic (lesson 1), a row where a column is NULL fails both `x > 3` and `NOT (x > 3)`. To include such rows write `x > 3 OR x IS NULL`.

### Logical evaluation order

You write `SELECT` first, but conceptually it runs late. The logical order is: `FROM`, then `WHERE`, then (next week) `GROUP BY` and `HAVING`, then `SELECT` (computing expressions and aliases), then `DISTINCT`, then `ORDER BY`, then `LIMIT`. Two consequences: a column alias defined in `SELECT` cannot be used in `WHERE` in standard SQL (the alias does not exist yet; SQLite and a few other systems accept it as an extension, so do not rely on it), but it can be used in `ORDER BY`. Database engines may execute differently, but the result always matches this order.

### NULL in sorting

The standard leaves the position of NULLs in `ORDER BY` to the implementation, and offers `NULLS FIRST` or `NULLS LAST` to choose. SQLite treats NULL as smaller than every other value, so NULLs come first in ascending order and last in descending order.

@example
title: Reading a query with sorting and limits
problem: Table `p(name, score)` holds (Ann, 70), (Bo, 95), (Cy, 80), (Di, 60). What does `SELECT name FROM p WHERE score >= 70 ORDER BY score DESC LIMIT 2` return?
step: `WHERE score >= 70` keeps Ann (70), Bo (95) and Cy (80); Di (60) is removed.
step: `ORDER BY score DESC` sorts the survivors from largest: Bo (95), Cy (80), Ann (70).
step: `LIMIT 2` keeps the first two rows of the sorted result.
step: `SELECT name` outputs only the name column.
answer: Bo, then Cy.

@example
title: Precedence of AND and OR
problem: A table has rows (id, color, size): (1, red, 1), (2, blue, 9), (3, blue, 2). Which ids does `WHERE color = 'red' OR color = 'blue' AND size > 5` return, and how would you write "red or blue, and size over 5"?
step: `AND` binds tighter, so the condition is `color = 'red' OR (color = 'blue' AND size > 5)`.
step: Row 1 is red, so it passes. Row 2 is blue with size 9, so it passes. Row 3 is blue with size 2, so it fails.
step: To apply the size test to both colors, add parentheses: `WHERE (color = 'red' OR color = 'blue') AND size > 5`, or `color IN ('red', 'blue') AND size > 5`.
answer: Ids 1 and 2; the parenthesized version returns only id 2.

@mistakes
- Writing `WHERE x = NULL` or `x <> NULL`; both are always unknown. Use `IS NULL` and `IS NOT NULL`.
- Mixing `AND` and `OR` without parentheses and getting a different condition from the one intended.
- Using a `SELECT` alias in `WHERE`; in standard SQL the clause runs before the alias exists (it works in `ORDER BY`), and the few systems that accept it are not portable.
- Using `LIMIT` without `ORDER BY` and expecting the same rows every time.

tests:
```python
assert tv_not(True) is False
assert tv_not(False) is True
assert tv_not(None) is None
assert tv_and(False, None) is False
assert tv_and(None, False) is False
```

model:
```python
def tv_not(a):
    return None if a is None else not a


def tv_and(a, b):
    if a is False or b is False:
        return False
    if a is None or b is None:
        return None
    return True


def tv_or(a, b):
    if a is True or b is True:
        return True
    if a is None or b is None:
        return None
    return False
```
hint: Check the dominating value first: `False` for AND, `True` for OR.
hint: Use `is None` to test for unknown, never `== False`, because `0 == False` in Python.
solution: Each function first checks the value that decides the result regardless of the other input (`False` for AND, `True` for OR), then returns unknown if either input is unknown, and otherwise the ordinary result.

@practice code
prompt: Write `like_match(text, pattern)` that returns `True` when the whole string `text` matches the SQL `LIKE` pattern `pattern`, using these rules: `%` matches any sequence of characters, including none; `_` matches exactly one character; every other character matches itself, case-sensitively. There is no escape character.
starter:
```python
def like_match(text, pattern):
    pass
```
tests:
```python
assert like_match("Max", "_a%") == True
assert like_match("a", "_a%") == False
assert like_match("", "%") == True
assert like_match("abc", "a%c") == True
assert like_match("ac", "a%c") == True
assert like_match("abc", "a_") == False
assert like_match("abc", "%b%") == True
assert like_match("ABC", "abc") == False
assert like_match("abc", "abc") == True
```
model:
```python
def like_match(text, pattern):
    positions = {0}
    for ch in pattern:
        nxt = set()
        for i in positions:
            if ch == "%":
                nxt.update(range(i, len(text) + 1))
            elif i < len(text) and (ch == "_" or text[i] == ch):
                nxt.add(i + 1)
        positions = nxt
    return len(text) in positions
```
hint: Track the set of positions in `text` that the pattern read so far could have consumed up to.
hint: A `%` extends every current position to all positions at or after it; a literal or `_` advances by one if it fits.
solution: Start with position 0 reached. For each pattern character, build the next set of reachable positions: `%` reaches every later position, `_` or a matching literal moves one step right. The pattern matches if the end of the text is reachable after the last pattern character.

@quiz code
prompt: Write `tv_all(values)` that combines a list of truth values (`True`, `False` or `None` for unknown) with SQL's AND: the result is `False` if any value is `False`; otherwise `None` if any value is `None`; otherwise `True`. An empty list gives `True`.
starter:
```python
def tv_all(values):
    pass
```
tests:
```python
assert tv_all([]) is True
assert tv_all([True, True]) is True
assert tv_all([True, None, True]) is None
assert tv_all([None, False, None]) is False
assert tv_all([False]) is False
```
model:
```python
def tv_all(values):
    if any(v is False for v in values):
        return False
    if any(v is None for v in values):
        return None
    return True
```
hint: Check for `False` before checking for `None`.
hint: Use `v is False`, not `not v`, because `not None` is `True`.
solution: A single `False` decides the AND, so test for it first; then a single unknown makes the result unknown; otherwise every value is `True` (and the empty AND is `True`).
