material: **Problem 1: Scheduling unit jobs with deadlines and profits (greedy).** Each job takes exactly one time unit. The input `jobs` is a list of `(deadline, profit)` pairs with integer `deadline >= 1` and `profit >= 0`. Time slots are numbered `1, 2, 3, ...`, only one job can use a slot, and a job placed in slot `t` earns its profit only if `t <= deadline`. Write `max_profit_schedule(jobs)` returning the maximum total profit. Example: `[(2, 100), (1, 19), (2, 27), (1, 25), (3, 15)]` gives `142` (jobs with profits 27, 100 and 15 in slots 1, 2 and 3). Target: $O(n \log n)$ or better in practice; consider sorting by profit and a union–find structure to find the latest free slot.
material: **Problem 2: Significant inversions (divide and conquer).** Given a list of integers `a`, count the pairs of positions `i < j` with `a[i] > 2 * a[j]`. Write `count_big_inversions(a)`. Example: `[1, 3, 2, 3, 1]` gives `2` (the pairs of positions `(1, 4)` and `(3, 4)`, values `3 > 2 * 1`). Note that `2 * a[j]` may be negative, so do not assume positive values. Target: $\Theta(n \log n)$ by counting these pairs across the two halves before the merge step of a merge sort, which is possible because both halves are sorted at that point.
material: **Problem 3: Splitting numbers evenly (dynamic programming).** Given a list `nums` of positive integers, split it into two groups (either may be empty) so that the absolute difference between the two group sums is as small as possible, and return that minimum difference. Write `min_partition_difference(nums)`. Example: `[3, 1, 4, 2, 2]` gives `0` (sums 6 and 6), and `[8, 3, 3]` gives `2`. Target: time $O(n \cdot S)$ where $S$ is the total sum; explain why this is pseudo-polynomial and what that means for large sums.
material: **Problem 4: Cheapest route with an edge budget (shortest paths).** A directed graph has vertices `0..n-1` and edges `(u, v, w)` where the weight `w` may be negative. Write `cheapest_with_edges(n, edges, s, t, k)` that returns the minimum total weight of a walk from `s` to `t` that uses **at most** `k` edges (`k >= 0`), or `None` if there is no such walk. A walk may repeat vertices. If `s == t`, the empty walk has weight 0. Example: with `n = 4`, `edges = [(0, 1, 1), (1, 2, 1), (2, 3, 1), (0, 3, 10)]`, `s = 0`, `t = 3`: `k = 2` gives `10` and `k = 3` gives `3`. Target: $O(k \cdot E)$ time. Be careful: relaxing edges in place during a round lets a round use more than one new edge; each round must read distances from the previous round only.
material: **Problem 5: Course enrollment (network flow).** There are courses `0..m-1` with seat limits `capacities[c]` and students, where `preferences[i]` is the list of course numbers acceptable to student `i`. Each student can be placed in at most one acceptable course, and course `c` can hold at most `capacities[c]` students. Write `max_assignments(capacities, preferences)` returning the largest number of students that can be placed. Example: `capacities = [1, 2]`, `preferences = [[0, 1], [0], [1], [1]]` gives `3`. Target: model the problem as a maximum flow in a network with a source, the students, the courses and a sink, and use augmenting paths. State the network you build and why an integral maximum flow gives a valid placement.

@review
This review walks through the course week by week. Re-derive each idea from scratch before checking your notes.

**Weeks 1-2: analysis.** $f = O(g)$ means $f \le c\,g$ beyond some $n_0$; $\Omega$ is the matching lower bound and $\Theta$ is both. Correctness of loops is shown with an invariant (initialization, maintenance, termination); recursion is shown by induction. Recurrences are solved by recursion trees, substitution and the master theorem: compare $d$ with $\log_b a$ and decide whether the leaves, every level or the root dominates. It fails when the gap is not polynomial (such as $n\log n$ against $n$) and for $T(n-1)$ forms.

**Weeks 3-4: divide and conquer and sorting.** Divide, conquer, combine. Fast exponentiation is $\Theta(\log n)$ because there is one recursive call. Merge sort is $\Theta(n\log n)$ and stable; quicksort is $\Theta(n^2)$ worst case but $\Theta(n\log n)$ expected with a random pivot. Comparison sorting needs $\Omega(n\log n)$ comparisons because a decision tree needs $n!$ leaves. Counting sort avoids comparisons.

**Weeks 5-6: greedy and DP.** Greedy algorithms need a proof: an exchange argument or "stays ahead". Interval scheduling (earliest finish), earliest deadline first, Huffman coding and fractional knapsack are correct; greedy coin change and 0/1 knapsack are not. DP needs overlapping subproblems and optimal substructure: define the state, write the recurrence and base cases, choose the order, and count subproblems times work per subproblem.

**Weeks 7-8: sequences, knapsack and graph search.** LCS, edit distance and knapsack tables are $\Theta(mn)$ or $\Theta(nW)$; knapsack is pseudo-polynomial. BFS gives unweighted distances, DFS gives edge types and topological orders, both in $\Theta(V+E)$. A directed graph has a topological order exactly when it has no cycle.

**Weeks 9-10: shortest paths and spanning trees.** Dijkstra needs non-negative weights and runs in $O((V+E)\log V)$ with a heap; Bellman-Ford handles negative edges in $\Theta(VE)$ and detects negative cycles. The cut property justifies Kruskal and Prim; union-find with union by size and path compression is nearly constant per operation.

**Weeks 11-12: flow and complexity.** Max flow equals min cut; augment along paths in the residual graph, including backward edges; Edmonds-Karp is $O(VE^2)$. P is polynomial-time solvable, NP is polynomial-time verifiable; reductions go from a known hard problem to the new one; NP-complete problems are the hardest in NP.

**Self-check.** Can you (1) prove a bound with explicit constants, (2) solve $T(n) = 3T(n/2) + n$, (3) prove interval scheduling optimal, (4) write and run a DP table by hand, (5) explain why Dijkstra fails on negative edges, (6) state the cut property and prove it, (7) find a min cut from a max flow, (8) carry out a reduction in both directions?

**Common errors.** Calling $O$ "worst case"; using the master theorem outside its conditions; trusting a greedy rule without a proof; forgetting base cases or the order of a DP table; marking BFS vertices visited when popped; ignoring backward residual edges; reducing in the wrong direction.

model:
```python
import heapq


def min_cost_grid(grid):
    rows, cols = len(grid), len(grid[0])
    best = {(0, 0): grid[0][0]}
    heap = [(grid[0][0], 0, 0)]
    while heap:
        d, r, c = heapq.heappop(heap)
        if d > best[(r, c)]:
            continue
        if (r, c) == (rows - 1, cols - 1):
            return d
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < rows and 0 <= nc < cols:
                nd = d + grid[nr][nc]
                if (nr, nc) not in best or nd < best[(nr, nc)]:
                    best[(nr, nc)] = nd
                    heapq.heappush(heap, (nd, nr, nc))
    return best[(rows - 1, cols - 1)]
```
hint: Each cell is a vertex and entering a neighbor costs that neighbor's value, so this is a shortest-path problem with non-negative weights.
hint: A route may need to move up or left, so a simple DP over right and down moves is not enough; use Dijkstra's algorithm with a heap.
solution: Treat the grid as a graph whose edge into a cell has that cell's cost, start with the start cell's own cost, and run Dijkstra with a heap. The first time the bottom-right cell is popped, its distance is the minimum. Time $O(rc \log(rc))$.

@exam self
prompt: Let $G$ be a connected undirected graph with distinct positive edge weights, and let $G'$ be the graph obtained by adding the same constant $c > 0$ to every edge weight. (a) Prove that $G$ and $G'$ have the same minimum spanning tree. (b) Show by a small example that the shortest path between two vertices can differ in $G$ and $G'$. (c) Explain why this does not contradict the fact that Prim's and Dijkstra's algorithms look similar.
solution: (a) Every spanning tree has exactly $V - 1$ edges, so its weight in $G'$ equals its weight in $G$ plus $(V-1)c$. The added amount is the same for all spanning trees, so the ordering of spanning trees by weight is unchanged, and the tree of minimum weight in $G$ is the tree of minimum weight in $G'$. (Alternatively, Kruskal only uses the order of the edge weights, and adding $c$ to all weights preserves their order.) (b) Take vertices $s, a, t$ with edges $s$–$a$ of weight 1, $a$–$t$ of weight 2 and $s$–$t$ of weight 4 (distinct, as required). The shortest $s$–$t$ path is $s, a, t$ with weight 3. Adding $c = 2$ gives weights 3, 4 and 6: the path through $a$ now has weight 7 and the direct edge has weight 6, so the shortest path changes. Paths have different numbers of edges, so a constant added to each edge penalizes longer paths. (c) Prim chooses, at each step, the lightest single edge that connects a new vertex to the tree, so only the order of weights matters. Dijkstra chooses the vertex minimizing the **sum** of weights along a path from the source, which depends on the actual values and on the number of edges. The two algorithms share a heap-based structure and the same running time but optimize different quantities.
rubric: Proves (a) by noting that every spanning tree has exactly $V-1$ edges (or by Kruskal's dependence on order only).
rubric: Gives a correct counterexample for (b) in which the path with more edges is shorter in $G$ but longer in $G'$.
rubric: Explains in (c) that Prim compares single edge weights while Dijkstra compares path sums.
hint: Count how many edges every spanning tree has.
hint: For (b), choose a graph where a two-edge path beats a one-edge path before the shift but not after.
