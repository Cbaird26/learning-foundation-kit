@article
A graph $G = (V, E)$ has vertices and edges (pairs of vertices; ordered pairs when the graph is **directed**). Let $V$ and $E$ also denote the counts, so $E \le V^2$.

### Representations

An **adjacency list** stores for each vertex the list of its neighbors: space $\Theta(V + E)$, and iterating over the neighbors of $u$ costs $\Theta(\deg u)$. An **adjacency matrix** is a $V \times V$ table of booleans: space $\Theta(V^2)$, but testing whether an edge exists is $O(1)$. For sparse graphs ($E \ll V^2$), which are most graphs, use lists. In Python, a dictionary mapping each vertex to a list of neighbors is the standard choice, and for an undirected graph each edge appears in both lists.

### Breadth-first search

BFS explores in rings: first the start $s$, then everything one edge from $s$, then two edges, and so on, using a **queue**.

```python
from collections import deque

def bfs(graph, s):
    dist = {s: 0}
    queue = deque([s])
    while queue:
        u = queue.popleft()
        for v in graph[u]:
            if v not in dist:
                dist[v] = dist[u] + 1
                queue.append(v)
    return dist
```

Each vertex enters the queue at most once and each edge is examined once (twice if undirected), so the time is $\Theta(V + E)$. The key property: **`dist[v]` equals the number of edges on a shortest path from $s$ to $v$** in an unweighted graph, and vertices leave the queue in non-decreasing order of distance. Recording the vertex `u` from which each `v` was discovered gives a shortest-path tree. BFS also finds the connected components of an undirected graph: start a search from every unvisited vertex.

### Depth-first search

DFS follows one path as deep as it can, then backtracks; it is naturally recursive (or uses an explicit stack). With a `visited` set it also runs in $\Theta(V + E)$ time. Record a **discovery time** when a vertex is first reached and a **finish time** when all its neighbors have been explored. In a directed graph DFS classifies each edge $(u, v)$ as a **tree edge** (it discovered $v$), a **back edge** (to an ancestor still being explored), a **forward edge** (to a descendant already finished) or a **cross edge** (to a vertex in a finished, unrelated subtree). The important fact: **a directed graph has a cycle if and only if DFS finds a back edge.** (Python's default recursion limit is about 1000 frames, so a deep DFS on a large graph needs an explicit stack or a raised limit.)

### Topological sort

A **topological order** of a directed graph lists the vertices so that every edge goes from earlier to later. One exists **if and only if the graph is acyclic** (a DAG): a cycle forces each of its vertices to precede the next one. Two linear-time methods:

- **DFS:** list vertices in decreasing finish time (reverse postorder). A vertex finishes after everything reachable from it, and in a DAG there are no back edges, so that order is valid.
- **Kahn's algorithm:** repeatedly remove a vertex with in-degree 0 (appending it to the order) and decrease the in-degree of its out-neighbors. If vertices remain but none has in-degree 0, the graph has a cycle.

Topological orders are rarely unique. The order is the natural evaluation order for **dynamic programming on a DAG**: the number of paths from $s$ to each vertex, or the longest path, is computed by processing vertices in topological order, since each vertex's value depends only on earlier ones.

@example
title: BFS distances
problem: Run BFS from $A$ in the undirected graph with adjacency lists $A: [B, C]$, $B: [A, D]$, $C: [A, D]$, $D: [B, C, E]$, $E: [D]$.
step: Start: `dist = {A: 0}`, queue $[A]$.
step: Pop $A$: discover $B$ and $C$ with distance 1. Queue $[B, C]$.
step: Pop $B$: $A$ is known, discover $D$ with distance 2. Pop $C$: $A$ and $D$ are known. Queue $[D]$.
step: Pop $D$: discover $E$ with distance 3. Pop $E$: nothing new.
answer: distances $A = 0$, $B = 1$, $C = 1$, $D = 2$, $E = 3$.

@example
title: Kahn's algorithm
problem: Find a topological order of the graph with edges $1 \to 3$, $2 \to 3$, $3 \to 5$, $2 \to 4$, $4 \to 5$.
step: In-degrees: vertex 1 has 0, vertex 2 has 0, vertex 3 has 2, vertex 4 has 1, vertex 5 has 2. The queue starts with $[1, 2]$.
step: Remove 1: the in-degree of 3 drops to 1. Remove 2: 3 drops to 0 and 4 drops to 0, so both join the queue: $[3, 4]$.
step: Remove 3: 5 drops to 1. Remove 4: 5 drops to 0 and joins the queue. Remove 5.
step: The order is $1, 2, 3, 4, 5$. All five vertices were removed, so the graph is acyclic. Another valid order is $2, 4, 1, 3, 5$.
answer: $1, 2, 3, 4, 5$ is a valid topological order.

@mistakes
- Marking a vertex visited when it is **popped** instead of when it is **pushed** in BFS, which lets it enter the queue many times.
- Using BFS distances on weighted graphs. BFS counts edges, not total weight; use Dijkstra next week.
- Treating any DFS visit of an already seen vertex as a cycle in a directed graph; only an edge to a vertex still on the current recursion path is a back edge. (In an undirected graph the edge back to the parent is not a cycle either.)
- Building the adjacency list of an undirected graph with each edge in only one direction.

```python
from collections import deque


def maze_steps(maze):
    rows, cols = len(maze), len(maze[0])
    if maze[0][0] == "#" or maze[rows - 1][cols - 1] == "#":
        return -1
    dist = {(0, 0): 0}
    queue = deque([(0, 0)])
    while queue:
        r, c = queue.popleft()
        if (r, c) == (rows - 1, cols - 1):
            return dist[(r, c)]
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if (0 <= nr < rows and 0 <= nc < cols
                    and maze[nr][nc] == "." and (nr, nc) not in dist):
                dist[(nr, nc)] = dist[(r, c)] + 1
                queue.append((nr, nc))
    return -1
```
hint: The cells are the vertices, and each move is an edge of length 1, so BFS finds the shortest route.
hint: Store the distance of a cell when you push it, and check the four neighbors for the grid bounds, an open cell and not yet visited.
solution: BFS from the top-left cell, marking a cell visited (by giving it a distance) when it is first pushed. The first time the bottom-right cell is reached, its distance is the minimum. If the queue empties first, there is no route. Time $\Theta(rc)$.

model:
```python
from collections import deque


def topo_sort(graph):
    indegree = {v: 0 for v in graph}
    for u in graph:
        for v in graph[u]:
            indegree[v] += 1
    queue = deque(v for v in graph if indegree[v] == 0)
    order = []
    while queue:
        u = queue.popleft()
        order.append(u)
        for v in graph[u]:
            indegree[v] -= 1
            if indegree[v] == 0:
                queue.append(v)
    return order if len(order) == len(graph) else None
```
hint: Compute the in-degree of every vertex, and keep a queue of the vertices whose in-degree is 0.
hint: When you remove a vertex, decrease the in-degree of each out-neighbor. If you finish with fewer vertices than the graph has, a cycle remains.
solution: Kahn's algorithm: repeatedly remove an in-degree-0 vertex and update its neighbors. Vertices on a cycle never reach in-degree 0, so if the order is shorter than the vertex set, the graph is cyclic and the function returns `None`. A self-loop makes in-degree at least 1 forever, so it is handled too. Time $\Theta(V + E)$.

```python
def count_paths_dag(graph, s, t):
    memo = {}

    def paths(u):
        if u == t:
            return 1
        if u not in memo:
            memo[u] = sum(paths(v) for v in graph[u])
        return memo[u]

    return paths(s)
```
hint: The number of paths from `u` to `t` is the sum over the out-neighbors `v` of `u` of the number of paths from `v` to `t`.
hint: Memoize that count per vertex, with value `1` at `t` itself. Without memoization, paths are recounted exponentially often.
solution: Let `paths(u)` be the number of paths from `u` to `t`: it is 1 at `t` and otherwise the sum of `paths(v)` over out-neighbors. Because the graph is acyclic, the recursion terminates, and memoization makes each vertex's value computed once, for $\Theta(V + E)$ time. This is dynamic programming along a topological order.

@practice self
prompt: Prove that BFS computes shortest-path distances in an unweighted graph: for every vertex $v$ reachable from $s$, the value `dist[v]` set by BFS equals $\delta(s, v)$, the minimum number of edges on a path from $s$ to $v$.
solution: Each `dist[v]` is assigned once, when $v$ is enqueued, as `dist[u] + 1` for the vertex $u$ being dequeued with an edge $u \to v$. Lemma 1: every assigned value is at least $\delta(s, v)$, because by induction on assignments it is the length of an actual path from $s$ to $v$. Lemma 2: at every moment the queue, front to back, has non-decreasing `dist` values with the last at most the first plus 1. This holds initially (the queue is $[s]$); dequeuing a vertex with value $d$ leaves values that are at least $d$, and the vertices appended get $d + 1$, which is at least every value in the queue and at most (new front) $+ 1$. Consequently the values of dequeued vertices are non-decreasing. Main claim: `dist[v]` equals $\delta(s, v)$ for every reachable $v$, by induction on $k = \delta(s, v)$. For $k = 0$, $v = s$ and `dist[s] = 0`. For $k \ge 1$ take a shortest path whose last edge is $u \to v$; then $\delta(s, u) = k - 1$ (a shorter path to $u$ would give $v$ a shorter path), so `dist[u] = k - 1` by the induction hypothesis, and $u$ is dequeued at some time because every enqueued vertex is eventually dequeued. If $v$ is unassigned at that moment, BFS sets `dist[v] = k`. If $v$ was assigned earlier, it was set to `dist[w] + 1` by a vertex $w$ dequeued before $u$, and by Lemma 2 `dist[w]` $\le$ `dist[u]` $= k - 1$, so `dist[v]` $\le k$. With Lemma 1, `dist[v]` $\ge k$, so `dist[v] = k`.
rubric: Sets up an induction on the true distance $k$ and uses a shortest path to a predecessor $u$ with $\delta(s,u) = k-1$.
rubric: Argues that the assigned value is neither too large (it is assigned when $u$ is dequeued) nor too small (it corresponds to a real path).
rubric: Notes that the queue is ordered by distance, so vertices are processed in non-decreasing order of distance.
hint: Induct on the true distance of the vertex, and look at the predecessor of $v$ on a shortest path.
hint: Show the BFS value is both an upper bound (when the predecessor is dequeued) and a lower bound (it comes from a real path).

model:
```python
def count_components(graph):
    seen = set()
    count = 0
    for start in graph:
        if start in seen:
            continue
        count += 1
        seen.add(start)
        stack = [start]
        while stack:
            u = stack.pop()
            for v in graph[u]:
                if v not in seen:
                    seen.add(v)
                    stack.append(v)
    return count
```
hint: Start a search from each vertex you have not seen yet; each search covers exactly one component.
hint: Use an explicit stack or queue and a `seen` set, and count how many searches you start.
solution: Every search started from an unseen vertex visits its whole component, so the number of searches equals the number of components. The total time is $\Theta(V + E)$ since each vertex and edge is processed a constant number of times.

prompt: A directed graph has vertices $A, B, C, D, E$ and edges $A \to C$, $B \to C$, $C \to D$ and $B \to E$. How many different topological orders does it have?
answer: 7
check: int(run("from itertools import permutations\nE = [('A', 'C'), ('B', 'C'), ('C', 'D'), ('B', 'E')]\nn = 0\nfor p in permutations('ABCDE'):\n    pos = {v: i for i, v in enumerate(p)}\n    if all(pos[u] < pos[v] for u, v in E):\n        n += 1\nprint(n)\n"))
hint: $A$ and $B$ must precede $C$, $C$ must precede $D$, and $B$ must precede $E$. Place $E$ relative to the chain.
solution: The vertices $A, B, C, D$ must form an order in which $A$ and $B$ come before $C$ and $C$ before $D$: $A, B, C, D$ or $B, A, C, D$. In each such order, $E$ can be inserted anywhere after $B$. For $A, B, C, D$, $B$ is in position 2 and $E$ can go in 3 places (after $B$, after $C$, after $D$): 3 orders. For $B, A, C, D$, $E$ can go in 4 places: 4 orders. Total $3 + 4 = 7$.
