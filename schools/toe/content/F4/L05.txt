@article
Science deals in collections of numbers: a series of measurements, positions at successive times, the components of a vector. Python has two tools for them: the built-in **list** and the **NumPy array**.

### Lists

```python
v = [3.0, 1.5, 4.0, 1.0]
v[0]       # 3.0           indexing starts at 0
v[-1]      # 1.0           negative indices count from the end
v[1:3]     # [1.5, 4.0]    slice: start included, stop excluded
v[::2]     # [3.0, 4.0]    every second item
len(v)     # 4
v.append(2.5)              # v now has five items
```

A slice is written `v[start:stop:step]`, and any part may be left out. A list can grow and shrink, and it is **mutable**: `v[0] = 9.9` changes the list itself. That has a consequence called **aliasing**:

```python
a = [1, 2, 3]
b = a            # a second name for the SAME list
b[0] = 99
print(a)         # [99, 2, 3]
c = a.copy()     # an independent copy; a[:] and list(a) also work
```

Loop over a list directly with `for x in v:` instead of counting indices.

### NumPy arrays

```python
import numpy as np
t = np.linspace(0.0, 1.0, 5)   # 0.0, 0.25, 0.5, 0.75, 1.0
y = 3.0 * t ** 2               # applied to every element
print(y.sum(), y.mean())       # 5.625 1.125
```

An array stores numbers of one type, and arithmetic acts **element by element** with no loop. This is called *vectorised* code, and it is both shorter and much faster. Compare `[1, 2] + [3, 4]`, which is the list `[1, 2, 3, 4]`, with `np.array([1, 2]) + np.array([3, 4])`, which is `[4, 6]`.

Useful constructors: `np.linspace(a, b, n)` gives `n` points *including both ends*, so the spacing is $(b - a)/(n - 1)$. `np.arange(a, b, h)` excludes `b` and can surprise you with float steps. `np.zeros(n)` gives `n` zeros. Useful methods are `.sum()`, `.mean()`, `.max()`, `.min()`, and functions such as `np.sqrt`, `np.sin` and `np.exp`. The call `np.argmax(y)` returns the index of the largest entry.

### Boolean masks

Comparing an array gives an array of booleans, and that can select elements:

```python
y = np.array([2.0, 7.5, 4.1, 9.3])
big = y[y > 4]      # the entries 7.5, 4.1, 9.3
```

### Views, not copies

Slicing a NumPy array does **not** copy: `b = a[1:3]` is a window onto the same data, so changing `b` changes `a`. Use `a[1:3].copy()` when you need independence. (Slicing a list does make a copy.)

@example
title: Indexing and slicing a list
problem: Let `v = [10, 20, 30, 40, 50]`. Find `v[1]`, `v[-2]`, `v[1:4]` and `v[::2]`.
step: Indexing starts at 0, so `v[1]` is the second item: `20`.
step: Negative indices count from the end: `v[-1]` is `50`, so `v[-2]` is `40`.
step: The slice `v[1:4]` starts at position 1 and stops before position 4, so it holds positions 1, 2, 3: `[20, 30, 40]`. It has $4 - 1 = 3$ items.
step: The slice `v[::2]` takes every second item from the start: positions 0, 2, 4, giving `[10, 30, 50]`.

@example
title: A function on a grid with NumPy
problem: Use NumPy to tabulate $y = x^2$ at five equally spaced points from $0$ to $2$ and find the sum and mean of the values.
step: `x = np.linspace(0, 2, 5)` gives 5 points including both ends. The spacing is $(2 - 0)/(5 - 1) = 0.5$, so `x` holds 0, 0.5, 1.0, 1.5, 2.0.
step: `y = x ** 2` squares every element: 0, 0.25, 1.0, 2.25, 4.0.
step: `y.sum()` is $0 + 0.25 + 1 + 2.25 + 4 = 7.5$.
step: `y.mean()` is $7.5 / 5 = 1.5$. This is the average of $x^2$ at five sample points. The exact average of $x^2$ over $[0, 2]$ is $4/3$, so a finer grid would be needed for better agreement.

@mistakes
- Off-by-one slicing: `v[1:3]` has two items, not three, because the stop is excluded.
- Believing `b = a` copies a list. It creates a second name for the same list, so changes through `b` show up in `a`.
- Adding lists to add numbers: `[1, 2] + [3, 4]` joins them. Use arrays for element-wise arithmetic.
- Forgetting that `np.linspace(a, b, n)` has `n - 1` gaps, so the spacing is $(b - a)/(n - 1)$, not $(b - a)/n$.
- Modifying a NumPy slice and not realising it is a view of the original array.

@practice self
prompt: Using NumPy and no `for` loop, write code that creates 101 equally spaced values of $x$ from $0$ to $2\pi$, computes $y = \sin x$ at those values, and prints the largest value of $y$ together with the $x$ at which it occurs. State the two values you expect.
hint: `np.linspace(0, 2 * np.pi, 101)` gives the grid, and `np.sin` acts on the whole array.
hint: `np.argmax(y)` gives the position of the largest entry. Use it to index into `x`.
solution: One possible program:
```python
import numpy as np
x = np.linspace(0, 2 * np.pi, 101)   # 101 points, spacing 2*pi/100
y = np.sin(x)                        # element by element
i = np.argmax(y)                     # position of the largest value
print(y[i], x[i])                    # 1.0 and about 1.5708
```
The maximum of $\sin x$ is $1$, reached at $x = \pi/2 \approx 1.5708$, which is grid point number 25.
rubric: The grid has 101 points, created with linspace so that both end points are included.
rubric: The sine is computed on the whole array in one expression, with no for loop.
rubric: The code finds the position of the maximum (for example with argmax) and uses it to look up the matching x.
rubric: The expected output is stated as about 1.0 at about 1.5708.

```python
import numpy as np
a = np.array([1, 2, 3, 4])
b = a[1:3]

```
choice*: `[1, 99, 3, 4]`

choice: `[1, 99, 99, 4]`
hint: Is `b` a separate copy of those two entries, or a window onto the same data?
