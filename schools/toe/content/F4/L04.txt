@article
A **function** gives a name to a computation so you can reuse it, test it on its own, and read a program as a sequence of ideas rather than a wall of arithmetic.

### Defining and calling

```python
def kinetic_energy(m, v):
    """Return kinetic energy in joules for mass m (kg) and speed v (m/s)."""
    return 0.5 * m * v ** 2

e = kinetic_energy(2.0, 3.0)    # 9.0
```

The header `def name(parameters):` introduces the function. The indented body runs only when the function is **called**. The values you pass are **arguments**; they are matched to parameters by position, or by name: `kinetic_energy(v=3.0, m=2.0)`. The string right after the header is a **docstring**: it says what the function does and in which units.

### return is not print

`return` hands a value back to the caller and ends the function. `print` only displays text. A function with no `return` gives back `None`, so after `y = f(x)` the variable `y` is useless if `f` merely printed. In scientific code, return values, so that other functions can use the result.

### Default arguments

A parameter may have a default: `def drag_force(v, c=0.47):` can be called as `drag_force(10)` or `drag_force(10, c=1.0)`. Parameters with defaults must come after those without.

### Scope

Names assigned inside a function are **local**: they exist only during the call, and every call gets a fresh set.

```python
x = 10
def f(y):
    x = y * 2        # a new local x; the global x is untouched
    return x
print(f(3), x)       # 6 10
```

A function may *read* a global name, but assigning to a name anywhere inside a function makes it local throughout that function. So `count = count + 1` inside a function fails with `UnboundLocalError`: the local `count` is read before it has a value. The clean fix is to pass values in as arguments and return results.

### A sequence generator

Many models are recurrences, where each term is computed from the previous ones. A function with a loop produces them:

```python
def fibonacci(n):
    """Return the n-th Fibonacci number, with F(1) = F(2) = 1."""
    a, b = 1, 1
    for _ in range(n - 2):
        a, b = b, a + b
    return b
```

The line `a, b = b, a + b` evaluates the whole right side with the old values and only then assigns both names. The underscore `_` is the usual name for a loop variable you never use. To explain every line of such a function, say what each line does, what the variables mean after it, and why the loop runs `n - 2` times: the first two terms are already in place.

@example
title: Defaults, arguments and scope together
problem: What does this program print?
```python
k = 2
def scale(x, k=10):
    y = x * k
    return y
print(scale(3), scale(3, k), k)
```
step: In `scale(3)` no second argument is given, so the parameter `k` takes its default 10. The call returns $3 \times 10 = 30$.
step: In `scale(3, k)` the argument is the global `k`, whose value is 2. Inside the function the parameter `k` is a separate local name holding 2, so the call returns $3 \times 2 = 6$.
step: The local `y` disappears when the call ends. The global `k` was never changed, so the last item printed is `2`.
step: The program prints `30 6 2`.

@example
title: Tracing a sequence generator
problem: Trace `fibonacci(6)` using the function from the article, and say what it returns.
step: Before the loop, `a = 1` and `b = 1`. Since $n - 2 = 4$, the loop body runs four times.
step: Pass 1: `a, b = b, a + b` gives `a = 1, b = 2`. Pass 2: `a = 2, b = 3`. Pass 3: `a = 3, b = 5`. Pass 4: `a = 5, b = 8`.
step: The function returns `b`, which is 8.
step: Check against the sequence 1, 1, 2, 3, 5, 8: the sixth term is 8.

@mistakes
- Using `print` where `return` is needed: the caller receives `None` and later arithmetic fails.
- Expecting `x = ...` inside a function to change a global `x`. It creates a local `x` and leaves the global alone.
- Forgetting the parentheses when calling: `kinetic_energy` is the function object, while `kinetic_energy(2.0, 3.0)` is a call.
- Writing the loop count wrongly in a generator, so the sequence has one term too many or too few. Trace a small case by hand.

@practice self
prompt: Write a function `recurrence(x0, a, b, n)` that returns a list of the first `n` terms of the sequence $x_{k+1} = a\,x_k + b$, starting with $x_0$ = `x0`. Put a comment on every line saying what it does, and state what `recurrence(1, 2, 1, 5)` should return.
hint: Start a list with the first term, then loop, computing each new term from the previous one.
hint: A list is built with `terms = []` and grown with `terms.append(value)`. Be careful that the list ends up with exactly `n` terms.
solution: One possible answer:
```python
def recurrence(x0, a, b, n):
    terms = []               # will hold the sequence
    x = x0                   # current term, starts at x_0
    for _ in range(n):       # repeat n times, one term per pass
        terms.append(x)      # store the current term
        x = a * x + b        # compute the next term from this one
    return terms             # hand the whole list back
```
`recurrence(1, 2, 1, 5)` returns `[1, 3, 7, 15, 31]`.
rubric: The function returns a list with exactly n terms, and the first term is x0.
rubric: Each new term is computed from the previous one using a * x + b, with the update after the append.
rubric: Every line has a comment that says what it does and what the variables mean at that point.
rubric: The stated test result is [1, 3, 7, 15, 31].

@quiz num
prompt: What does this program print?
```python
def update(x):
    x = x + 1
    return x * 2
x = 3
y = update(x)
print(x + y)
```
answer: 11
check: 3 + (lambda x: (x + 1) * 2)(3)
hint: Does the assignment inside `update` change the global `x`?
hint: The global `x` stays 3. Compute `y` from the local value 4.
solution: Inside `update`, the local `x` becomes 4, and the function returns $4 \times 2 = 8$. The global `x` is still 3, so `x + y` is $3 + 8 = 11$.

@quiz mc
prompt: What happens when this program runs?
```python
count = 0
def add_one():
    count = count + 1
    return count
print(add_one())
```
choice*: It raises an error, because `count` is local inside `add_one` and is read before it is assigned.
choice: It prints `1`.
choice: It prints `0`.
choice: It prints `None`.
hint: An assignment anywhere in a function body makes that name local to the whole function.
solution: Because `count` is assigned inside `add_one`, Python treats it as local for the entire function. The right-hand side `count + 1` reads the local `count` before it has any value, which raises `UnboundLocalError`. The global `count` is never consulted.
