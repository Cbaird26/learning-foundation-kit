@article
A **loop** repeats a block of code. Scientific programs are mostly loops: step through time, sum a series, refine an estimate until it is good enough.

### for loops

A `for` loop runs its indented body once for each item of a sequence. The sequence is often `range(...)`:

| call | values produced |
|---|---|
| `range(5)` | 0, 1, 2, 3, 4 |
| `range(2, 6)` | 2, 3, 4, 5 |
| `range(0, 10, 3)` | 0, 3, 6, 9 |

The stop value is **never included**. To run $k = 1, \dots, n$ write `range(1, n + 1)`.

### The accumulator pattern

To add up many terms, start a running total **before** the loop and update it inside:

```python
total = 0
for k in range(1, 101):      # k = 1, 2, ..., 100
    total += k               # same as total = total + k
print(total)                 # 5050
```

This agrees with the formula $\sum_{k=1}^{n} k = \frac{n(n+1)}{2} = 5050$. Checking a loop against a formula you trust is a habit worth keeping. The same pattern builds products (start at `1`, use `*=`) and partial sums of series:

```python
s = 0.0
for k in range(1, 1001):
    s += 1 / k ** 2
print(s)    # about 1.6439; the infinite sum is pi**2/6 = 1.6449
```

### while loops

Use `while` when you do not know in advance how many repetitions you need. The body repeats **as long as** the condition is true:

```python
step = 1.0
count = 0
while step > 1e-3:
    step = step / 2
    count += 1
print(count)     # 10
```

Two rules keep a `while` loop honest. First, the condition must be able to become false, so the body must change the variables it tests. Second, when floats are involved, test with `<` or `>` rather than `==` or `!=`, because floats rarely hit a target exactly.

### Tracing a loop

When a loop surprises you, write a table with one row per pass: the loop variable and every variable that changes. Do this by hand before you run the code, then compare.

### Stopping early

`break` leaves the loop immediately; `continue` skips to the next pass. Use them sparingly. A clear loop condition is usually easier to read.

@example
title: How long until half remains?
problem: A sample loses 10% of its mass every hour. Use a loop to find how many whole hours pass until less than half of the original mass remains.
```python
mass = 1.0      # fraction of the original mass
hours = 0
while mass >= 0.5:
    mass = mass * 0.9
    hours += 1
print(hours)
```
step: Before the loop, `mass` is 1.0 and `hours` is 0. The test `mass >= 0.5` means "at least half is still left", so the loop keeps going while that is true.
step: Each pass multiplies the mass by 0.9 and counts one hour. After 6 passes the mass is $0.9^6 \approx 0.531$, which is still at least 0.5, so the loop runs again.
step: After pass 7 the mass is $0.9^7 \approx 0.478 < 0.5$. The condition is now false, the loop stops, and `hours` is 7.
step: Check with algebra: we need $0.9^n < 0.5$, so $n > \ln 0.5 / \ln 0.9 \approx 6.58$. The smallest whole number is 7, which agrees.

@example
title: Tracing a for loop
problem: Trace this loop with a table and say what it prints.
```python
total = 0
for k in range(1, 5):
    total += 2 * k
print(total)
```
step: `range(1, 5)` gives $k = 1, 2, 3, 4$. The value 5 is excluded.
step: Pass 1 ($k=1$): `total` becomes $0 + 2 = 2$. Pass 2 ($k=2$): $2 + 4 = 6$. Pass 3 ($k=3$): $6 + 6 = 12$. Pass 4 ($k=4$): $12 + 8 = 20$.
step: The loop ends, and the program prints `20`.
step: Check with algebra: $2(1 + 2 + 3 + 4) = 2 \cdot 10 = 20$.

@mistakes
- Off-by-one errors: `range(5)` gives 0 to 4 and `range(1, 5)` stops at 4. To include `n`, write `range(1, n + 1)`.
- Forgetting to change the tested variable inside a `while` loop, which makes it run forever.
- Resetting the accumulator inside the loop body (`total = 0` on every pass), so only the last term survives.
- Using `while x != target` with floats. Rounding error means `x` may skip past the target and never equal it.

@practice self
prompt: Write a `while` loop that finds the smallest whole number $n$ for which the harmonic sum $1 + \tfrac{1}{2} + \tfrac{1}{3} + \dots + \tfrac{1}{n}$ exceeds $3$, and prints that $n$. Say what value it should print.
hint: You need two variables before the loop: a running total and a counter.
hint: Inside the loop, increase the counter first, then add $1/n$ to the total. Keep looping while the total has not yet exceeded 3.
solution: One possible program:
```python
total = 0.0
n = 0
while total <= 3:
    n += 1
    total += 1 / n
print(n)     # 11
```
The partial sums are about 2.929 for $n = 10$ and about 3.020 for $n = 11$, so the program prints 11.
rubric: Both `total` and `n` are initialised before the loop.
rubric: The loop condition keeps looping while the total is at most 3, and both variables change inside the body.
rubric: The loop terminates and prints a single integer, 11.
rubric: The learner can explain why `n` is incremented before `1 / n` is used (no division by zero).

@quiz ms
prompt: Four loops are shown below. Which of them never terminate? Select all that apply.
```python
# Loop A
i = 0
while i < 5:
    print(i)
# Loop B
x = 1.0
while x != 0:
    x = x - 0.1
# Loop C
n = 10
while n > 0:
    n = n - 3
# Loop D
k = 1
while k < 100:
    k = k * 2
```
choice*: Loop A
choice*: Loop B
choice: Loop C
choice: Loop D
hint: For each loop, ask whether the variable in the condition changes and whether it can ever make the condition false.
hint: Loop B subtracts 0.1 repeatedly. Does `x` land on exactly 0 in floating point?
solution: Loop A never changes `i`, so `i < 5` stays true forever. In Loop B, `x` reaches about $1.4 \times 10^{-16}$ rather than exactly 0 because 0.1 is not exactly representable, then goes negative, so `x != 0` stays true. Loop C gives 10, 7, 4, 1, -2 and stops. Loop D doubles `k` up to 128 and stops.
