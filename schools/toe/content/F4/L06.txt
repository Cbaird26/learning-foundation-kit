@article
Real data lives in files. A program that reads a file, summarizes it and saves the answer can be re-run whenever the data change, and that is the first step toward reproducible science.

### Opening files

```python
with open("readings.txt") as f:
    text = f.read()
```

The `with` block closes the file for you, even if an error occurs. The second argument of `open` is the **mode**: `"r"` reads (the default), `"w"` writes and **erases any existing content**, and `"a"` appends to the end. A relative name such as `"readings.txt"` is looked up in the folder you run Python from; if it is not there you get `FileNotFoundError`.

### Text in, numbers out

Everything read from a file is a **string**. Convert it explicitly: `float("2.5")` is the number `2.5`, but `"2.5" + "1.5"` is the text `"2.51.5"`. Two string methods do most of the work: `line.strip()` removes the newline and spaces at the ends, and `line.split(",")` cuts a line into a list of pieces.

Suppose `trial.csv` contains

```
# time_s, position_m
0.0, 0.00
0.5, 1.23

1.0, 4.90
```

A loader that skips comment and blank lines:

```python
times, positions = [], []
with open("trial.csv") as f:
    for line in f:
        line = line.strip()
        if line == "" or line.startswith("#"):
            continue
        t, x = line.split(",")
        times.append(float(t))
        positions.append(float(x))
```

### The NumPy shortcut

For a clean numeric table, one call is enough. Lines starting with `#` are treated as comments and skipped:

```python
import numpy as np
data = np.loadtxt("trial.csv", delimiter=",")
t = data[:, 0]        # first column
x = data[:, 1]        # second column
```

### Writing results

```python
with open("summary.txt", "w") as out:
    out.write(f"mean position: {x.mean():.3f} m\n")
```

In an f-string, `{value:.3f}` prints a number with three digits after the decimal point, and `\n` ends the line.

### Never edit raw data by hand

If the program fails on a strange line, fix the **program** so that it skips or converts that line, and leave the raw file untouched. Write outputs to new files. A script that goes from the raw file to the summary is a complete, repeatable record of what you did. A hand-edited file is not.

@example
title: Parsing one line of a file
problem: A line read from a file is the string `"0.5, 1.23\n"`. Turn it into two numbers.
step: Remove the newline and surrounding spaces: `line.strip()` gives `"0.5, 1.23"`.
step: Cut at the comma: `"0.5, 1.23".split(",")` gives the list `["0.5", " 1.23"]`. Both pieces are still strings.
step: Convert each piece with `float`. The conversion ignores the space in `" 1.23"`, so `t = float("0.5")` is `0.5` and `x = float(" 1.23")` is `1.23`.
step: All together: `t, x = [float(s) for s in line.strip().split(",")]`.

@example
title: Summarizing a small file
problem: A file `g.txt` contains the lines `# g measurements (m/s^2)`, `9.78`, `9.84`, `9.81` and `9.77`. Describe a script that writes the mean to `g_summary.txt`, and find the mean.
step: Read the lines inside a `with open("g.txt") as f:` block and skip any line that starts with `#`.
step: Convert the remaining lines with `float` and collect them in a list `g`. There are four values.
step: The sum is $9.78 + 9.84 + 9.81 + 9.77 = 39.20$, so the mean is $39.20 / 4 = 9.80$.
step: Write the result with `out.write(f"mean g: {mean:.2f} m/s^2\n")` inside `with open("g_summary.txt", "w") as out:`. Re-running the script on a new `g.txt` updates the summary with no hand editing.

@mistakes
- Forgetting that file contents are strings: `"2.5" + "1.5"` joins text instead of adding numbers.
- Opening a file you want to keep with mode `"w"`. It is emptied immediately; use `"a"` to add or choose a new file name.
- Editing the raw data "just this once" to make a program run. Fix the code, not the data.
- Assuming the file is in the right place. Relative paths are looked up in the current working directory.

@practice self
prompt: A data file `measurements.csv` must not be edited by hand. It contains
```
# sample mass measurements
# columns: id, mass_g
1, 12.1
2, 11.8
3, nan
4, 12.4
```
Write a script that loads it, ignores the row whose mass is missing (`nan`), and writes a file `summary.txt` giving the count, the mean and the maximum of the remaining masses. State what the summary should say.
hint: `np.loadtxt(..., delimiter=",")` skips the lines that start with `#`, and it reads `nan` as a missing number.
hint: `np.isnan(mass)` is an array of booleans, and `~` flips it, so `mass[~np.isnan(mass)]` keeps only valid entries.
solution: One possible script:
```python
import numpy as np

data = np.loadtxt("measurements.csv", delimiter=",")   # '#' lines are skipped
mass = data[:, 1]                                      # second column
mass = mass[~np.isnan(mass)]                           # drop missing values

with open("summary.txt", "w") as out:
    out.write(f"count: {len(mass)}\n")
    out.write(f"mean: {mass.mean():.2f} g\n")
    out.write(f"max: {mass.max():.2f} g\n")
```
The summary should say count 3, mean 12.10 g (since $(12.1 + 11.8 + 12.4)/3 = 12.1$) and max 12.40 g.
rubric: The script reads measurements.csv directly, with no manual change to the file.
rubric: The missing value is removed in code, for example by a mask on np.isnan, before any statistic is computed.
rubric: The results are written to a new file opened with mode "w", not printed only.
rubric: The summary reports count 3, mean 12.1 and max 12.4.
