@article
A program that only follows a straight line is a calculator. A **conditional** lets it choose. The choice is made by a **boolean** expression, one whose value is `True` or `False`.

### Comparisons and logic

Comparison operators produce booleans: `==` (equal), `!=` (not equal), `<`, `<=`, `>`, `>=`. Note the double sign: `x = 3` assigns, while `x == 3` asks a question. Booleans combine with `and`, `or` and `not`. Python even lets you chain: `0 <= x < 10` means $0 \le x < 10$.

```python
temp_c = -300.0
print(temp_c < -273.15)        # True
print(0 <= 5 < 10, 0 <= 12 < 10)   # True False
```

### The if statement

The `def` line below defines a small **function**: a named recipe that takes an input and `return`s an answer. Week 4 treats functions fully; for now read it as "given `speed`, the answer is whatever the chosen branch returns."

```python
def classify(speed):
    if speed < 0:
        return "invalid"
    elif speed < 340.0:
        return "subsonic"
    else:
        return "supersonic"
```

Python checks the conditions **in order** and runs only the first branch whose condition is true. The indentation is the syntax: it marks what belongs to each branch. Use four spaces per level, the standard convention, and keep it consistent. The colon at the end of each header line is required.

### Boundary checks for physical quantities

Many quantities have limits: a temperature cannot be below absolute zero ($-273.15\ ^\circ\text{C}$), a mass cannot be negative, a probability lies in $[0, 1]$. A function that converts units should check its input first and refuse nonsense, using `raise ValueError("message")`:

```python
def celsius_to_kelvin(temp_c):
    if temp_c < -273.15:
        raise ValueError("below absolute zero")
    return temp_c + 273.15
```

Raising an error stops the program with a clear message, which is far better than quietly returning a meaningless number. Always test the **boundaries**: exactly at the limit, just inside and just outside. Here `-273.15` must be accepted and `-273.16` rejected.

### Floats and equality

Avoid `==` on computed floats. Compare with a tolerance instead: `abs(a - b) < 1e-9`. Week 8 explains why.

@example
title: Which branch runs?
problem: A function sorts a mass reading into a category.
```python
def size_class(m):
    if m < 0:
        return "invalid"
    elif m < 1.0:
        return "small"
    elif m < 10.0:
        return "medium"
    else:
        return "large"
```
Find `size_class(m)` for $m = 1.0$, $m = 0.999$ and $m = -2$.
step: For `m = 1.0`: the test `m < 0` is false and `m < 1.0` is false (the value equals 1.0, it is not below it). The test `m < 10.0` is true, so the result is `"medium"`.
step: For `m = 0.999`: `m < 0` is false, but `m < 1.0` is true, so the result is `"small"`.
step: For `m = -2`: the first test is true, so the result is `"invalid"`, and the later tests are never evaluated.
step: The lesson: which branch a boundary value such as `1.0` lands in is decided by the operator (`<` versus `<=`). Always write down which side of each boundary a value belongs to.

@mistakes
- Using `=` where `==` is meant in a condition (Python reports a syntax error).
- Writing `if x == 1 or 2:`. The `2` is always true by itself; write `if x == 1 or x == 2:`.
- Ordering `elif` branches badly. Because the first true test wins, checking `x < 10` before `x < 1` makes the second branch unreachable.
- Testing computed floats with `==`, for example `0.1 + 0.2 == 0.3`, which is `False`.

@practice num
prompt: A function is defined by
```python
def shipping(mass_kg):
    if mass_kg <= 1:
        return 5
    elif mass_kg <= 5:
        return 8
    else:
        return 8 + 2 * (mass_kg - 5)
```
What does `shipping(7.5)` return?
answer: 13
check: (lambda f: f(7.5))(lambda m: 5 if m <= 1 else (8 if m <= 5 else 8 + 2 * (m - 5)))
hint: Which branch matches $7.5$? Both earlier tests fail.
hint: In the `else` branch, compute `8 + 2 * (7.5 - 5)`.
solution: Neither `7.5 <= 1` nor `7.5 <= 5` is true, so the `else` branch runs: $8 + 2(7.5 - 5) = 8 + 5 = 13$.

@practice self
prompt: Write two functions, `km_to_miles(d_km)` and `miles_to_km(d_mi)`, using $1\ \text{mile} = 1.609344\ \text{km}$. Each must raise `ValueError` for a negative distance and otherwise return the converted distance. Then list three test inputs (including one at the boundary) with the output you expect.
hint: Define the conversion factor once, as a named constant, and use it in both functions.
hint: A distance of exactly $0$ is allowed. Test $0$, a typical positive value, and a negative value.
solution: One possible answer:
```python
KM_PER_MILE = 1.609344

def km_to_miles(d_km):
    if d_km < 0:
        raise ValueError("distance cannot be negative")
    return d_km / KM_PER_MILE

def miles_to_km(d_mi):
    if d_mi < 0:
        raise ValueError("distance cannot be negative")
    return d_mi * KM_PER_MILE
```
Tests: `miles_to_km(0)` returns `0.0` (the boundary, accepted). `miles_to_km(1)` returns `1.609344`. `km_to_miles(-1)` raises `ValueError`. Also `km_to_miles(miles_to_km(5))` should be very close to `5`.
rubric: The conversion factor is a single named constant, and the two functions use it consistently (multiply for miles to km, divide for km to miles).
rubric: Both functions raise ValueError for negative input and accept zero.
rubric: The tests include the boundary value 0, a normal value, and an invalid value, each with a stated expected result.
rubric: The round-trip or another independent check confirms the two functions are inverses.

@quiz num
prompt: A function returns a value depending on `x`:
```python
def f(x):
    if x < 0:
        return -x
    elif x < 4:
        return x * x
    else:
        return 16
```
What is `f(-3) + f(2) + f(9)`?
answer: 23
check: (lambda f: f(-3) + f(2) + f(9))(lambda x: -x if x < 0 else (x * x if x < 4 else 16))
hint: Evaluate the three calls separately and decide the branch for each.
hint: `f(-3)` is `3`, and `f(2)` is `4`.
solution: `f(-3)` takes the first branch and gives `3`. `f(2)` takes the second branch and gives `4`. `f(9)` takes the `else` branch and gives `16`. The sum is `3 + 4 + 16 = 23`.
