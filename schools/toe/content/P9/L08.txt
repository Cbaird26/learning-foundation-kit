@article
A method can be accurate for small steps and useless for large ones. **Stability** asks whether numerical errors stay bounded as the steps accumulate.

### The test problem

Take the decay equation $y' = -\lambda y$ with $\lambda > 0$; the exact solution $e^{-\lambda t}$ decays. Forward Euler gives

$$y_n = (1 - h\lambda)^n\,y_0 .$$

The numerical solution decays only if $|1 - h\lambda| < 1$, that is

$$h < \frac{2}{\lambda}.$$

Beyond this limit the iterates alternate in sign and grow. For $1 < h\lambda < 2$ they decay but oscillate, which is already wrong. A large $\lambda$ (a fast time scale) therefore forces tiny steps even when you care only about slow behavior; such a system is called **stiff**.

**Backward (implicit) Euler**, $y_{n+1} = y_n + h f(t_{n+1}, y_{n+1})$, gives $y_{n+1} = y_n/(1 + h\lambda)$, which decays for every $h > 0$. It is only first-order accurate and needs an equation solved at each step, but it removes the stability limit. Midpoint and RK4 also have finite limits on the decay equation ($h\lambda \le 2$ and about $2.78$).

### Step size study

Stable does not mean accurate. A **step size study** runs with $h, h/2, h/4, \dots$ and compares with an exact or reference value:

1. Errors fall by about $2^p$ at each halving for a method of order $p$, so $p \approx \log_2\big(e(h)/e(h/2)\big)$.
2. On a log-log plot of error against $h$ the points lie on a line of slope $p$.
3. With no exact answer, use three step sizes: $p \approx \log_2\dfrac{y_h - y_{h/2}}{y_{h/2} - y_{h/4}}$.

If the observed order differs from the theoretical order, suspect a bug, a non-smooth input, or steps that are still too large.

### Richardson extrapolation

For a method of order $p$,

$$y_{\text{exact}} \approx y_{h/2} + \frac{y_{h/2} - y_h}{2^p - 1},$$

which gives a better value and an error estimate without knowing the exact answer.

### The round-off floor

Truncation error falls like $h^p$, but round-off accumulates roughly like $\epsilon N$ over $N = (t_1 - t_0)/h$ steps, with $\epsilon \approx 10^{-16}$ in double precision. For very small $h$ the total error stops falling and then rises. Work on the falling part of the curve.

```python
import numpy as np

def rk2(lam, y0, T, h):
    n = round(T / h)
    r = 1 - h * lam + (h * lam)**2 / 2     # midpoint step on y' = -lam*y
    return y0 * r**n

exact = np.exp(-1.0)
hs = np.array([0.2, 0.1, 0.05, 0.025])
errs = np.array([abs(rk2(1.0, 1.0, 1.0, h) - exact) for h in hs])
print(errs, np.polyfit(np.log(hs), np.log(errs), 1)[0])   # slope near 2
```

@example
title: The Euler stability limit
problem: Forward Euler is applied to $y' = -50y$ with $y(0) = 1$. Find the largest stable step, then compare $h = 0.05$ and $h = 0.01$.
step: The limit is $h < 2/\lambda = 2/50 = 0.04$.
step: For $h = 0.05$ we have $h\lambda = 2.5$ and the factor $1 - 2.5 = -1.5$, which has magnitude above $1$, so the method is unstable.
step: After ten steps ($t = 0.5$) the numerical value is $(-1.5)^{10} = 57.7$, while the true solution has decayed to $e^{-25} \approx 10^{-11}$.
step: For $h = 0.01$, $h\lambda = 0.5$ and the factor is $0.5$, so the numerical solution decays smoothly.
step: Being below the limit guarantees stability, not accuracy; the factor $0.5$ per step differs from the true factor $e^{-0.5} = 0.607$, so a smaller step is still needed for accuracy.

@example
title: A step size study for Euler
problem: Forward Euler is applied to $y' = -y$ with $y(0) = 1$ and the value at $t = 1$ is recorded. With $h = 0.1$ it gives $0.34868$ and with $h = 0.05$ it gives $0.35849$. Estimate the observed order and extrapolate.
step: The exact value is $e^{-1} = 0.36788$, so the errors are $0.01920$ (for $h = 0.1$) and $0.00939$ (for $h = 0.05$).
step: The ratio is $0.01920/0.00939 = 2.04$, so $p = \log_2 2.04 = 1.03$, consistent with first order.
step: Richardson extrapolation with $p = 1$: $y \approx 0.35849 + (0.35849 - 0.34868)/(2^1 - 1) = 0.36830$.
step: The extrapolated error is $0.0004$, more than twenty times smaller than the raw error of $0.0094$, obtained without any additional runs.

@mistakes
- Concluding that a method is accurate because it did not blow up; stable does not mean accurate.
- Estimating the order from step sizes that are all too large to be in the asymptotic regime.
- Shrinking $h$ without limit and ignoring the round-off floor.
- Comparing runs whose final time is not an integer multiple of $h$, so that they stop at different times.

@practice self
prompt: Write a Python script that performs a step size study for forward Euler on $y' = -y$, $y(0) = 1$, up to $t = 1$, with $h = 0.1, 0.05, 0.025, 0.0125$. It should compute the error against $e^{-1}$ at each step size and estimate the order from a log-log fit. State the value you expect, and what you would conclude if the fit gave $0.5$.
hint: Loop over the step sizes, compute the number of steps with `round(1/h)`, and store the absolute error.
hint: The slope of `np.polyfit(np.log(hs), np.log(errs), 1)` is the observed order.
solution: ```python
import numpy as np

def euler_decay(h):
    y = 1.0
    for _ in range(round(1.0 / h)):
        y = y + h * (-y)
    return y

hs = np.array([0.1, 0.05, 0.025, 0.0125])
errs = np.array([abs(euler_decay(h) - np.exp(-1.0)) for h in hs])
p = np.polyfit(np.log(hs), np.log(errs), 1)[0]
print(errs, p)
```
I expect $p \approx 1$ because forward Euler is first order. A value near $0.5$ would signal a bug (for example a final time that does not match, or comparing at the wrong time) or an error that is dominated by something other than truncation, so I would check the code before trusting the method.
