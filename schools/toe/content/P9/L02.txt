@article
Every number you compute from measurements inherits uncertainty from its inputs. **Propagation** tells you how much. The idea is simple: a small error $\delta x$ in an input changes a result $f$ by about $\frac{\partial f}{\partial x}\,\delta x$. When errors in different inputs are random and independent they sometimes cancel and sometimes add, so they combine like the perpendicular sides of a right triangle: **in quadrature**.

### The general rule

For a result $f(x_1,\dots,x_n)$ with independent standard uncertainties $u_i$ on the inputs,

$$u_f^2 = \sum_{i=1}^{n}\left(\frac{\partial f}{\partial x_i}\right)^2 u_i^2 .$$

The partial derivatives are evaluated at the measured values. This is a first-order (linear) approximation, good when each $u_i$ is small compared with $x_i$.

### Rules you will use constantly

| Result | Uncertainty |
|---|---|
| $f = x \pm y$ | $u_f = \sqrt{u_x^2 + u_y^2}$ |
| $f = xy$ or $f = x/y$ | $\dfrac{u_f}{\lvert f\rvert} = \sqrt{\left(\dfrac{u_x}{x}\right)^2 + \left(\dfrac{u_y}{y}\right)^2}$ |
| $f = x^n$ | $\dfrac{u_f}{\lvert f\rvert} = \lvert n\rvert\,\dfrac{u_x}{\lvert x\rvert}$ |

Sums and differences combine **absolute** uncertainties; products, quotients and powers combine **relative** ones. A squared input counts twice, a cubed one three times.

### Which input matters?

Because of the squares, the largest term dominates. If one contribution is three times another, the smaller one raises the total by only about 5%. List each term's contribution (an **uncertainty budget**) and improve the largest one first; polishing a small term is wasted effort.

### When the rule fails

Independence is essential. Two readings taken from a ruler with the same unknown zero offset share that error: in a difference the shared part cancels, in a sum it doubles. Add covariance terms in that case, or remeasure so the errors are separate. Adding uncertainties linearly, $u_x + u_y$, gives a cautious upper bound, not the usual answer.

### Doing it in code

For a formula that is awkward to differentiate by hand, estimate each derivative with a central difference:

```python
import numpy as np

def propagate(f, x, u, h=1e-6):
    """First-order uncertainty of f(*x) for independent inputs."""
    x = np.asarray(x, dtype=float)
    total = 0.0
    for i in range(len(x)):
        step = h * (abs(x[i]) if x[i] != 0 else 1.0)
        hi, lo = x.copy(), x.copy()
        hi[i] += step
        lo[i] -= step
        dfdx = (f(*hi) - f(*lo)) / (2 * step)
        total += (dfdx * u[i]) ** 2
    return np.sqrt(total)

g = lambda L, T: 4 * np.pi**2 * L / T**2
print(propagate(g, [0.500, 1.420], [0.002, 0.006]))   # about 0.092
```

Always check a code result against the hand rule on one easy case before you trust it.

@example
title: Uncertainty in g from a pendulum
problem: A simple pendulum has length $L = 0.500 \pm 0.002$ m and period $T = 1.420 \pm 0.006$ s (supplied, illustrative values). Use $g = 4\pi^2 L/T^2$ to find $g$ and its standard uncertainty.
step: Compute the value: $g = 4\pi^2(0.500)/(1.420)^2 = 9.789\ \text{m/s}^2$.
step: The formula is a product and quotient, so work with relative uncertainties: $u_L/L = 0.002/0.500 = 0.40\%$ and $u_T/T = 0.006/1.420 = 0.42\%$.
step: $T$ appears squared, so its contribution doubles: $2 \times 0.42\% = 0.85\%$. The length contributes $0.40\%$.
step: Combine in quadrature: $\sqrt{0.40^2 + 0.85^2}\,\% = 0.94\%$.
step: Convert back to an absolute uncertainty: $u_g = 0.0094 \times 9.789 = 0.092\ \text{m/s}^2$. Report $g = 9.79 \pm 0.09\ \text{m/s}^2$. The period dominates, so timing more swings is the best improvement.

@mistakes
- Adding absolute uncertainties for a product instead of relative ones, or mixing the two in one sum.
- Forgetting the exponent: an input that is squared contributes twice its relative uncertainty.
- Using quadrature when two errors are really the same error, such as a shared zero offset.
- Spending effort on an input whose contribution is already a few times smaller than the largest term.
