Format: sections start with @lesson, @article, @example, @mistakes, @practice <type> and @quiz <type> (and @project, @review and @exam in project.txt). Text inside ``` fences is verbatim code. Items have prompt, answer, check, hint and solution fields; num items may have tol and unit; expr items have vars; code items also have starter, tests, stdout, stdin and model blocks. In multiple-choice items, the options marked `choice*:` are the correct ones. The validator already guarantees that each `check:` agrees with its `answer:` and that each code item's model solution passes its tests (in CPython and in the browser) while the starter fails them; but a check or a test can share an item's mistake, so confirm independently that the prompt, the method, the answer and the solution agree.

Work file by file. Read each file once, then check: every definition and every statement in the article; every mechanism and every claim about what an experiment found; every derivation, line by line; every result's conditions (the Nernst equation applies to one permeant ion; a double dissociation needs two patients or groups with opposite deficits; a test's assumptions); every number and unit, recomputed with Python; every table of values; every code sample (run it, and confirm it is correct, idiomatic, plain Python and does what the text says, including any output shown); every attribution and year (against the BRIEF's list; remove a name or a year you cannot confirm rather than guess); every claim about what a paper, a law, a guideline or a classification says (against the BRIEF's current facts; laws must be described as of their stated dates, with a reminder to check the current text); every hint and solution step; the choices marked correct and the others marked wrong (each mc item must have exactly one best answer, and its answer must be correct whatever view the learner holds); tolerances and units (a rounded answer needs a `tol:` of about one unit in the last place asked for; a percent answer has `unit: %`); and the rubric lines (they must reward the quality of reasoning, never agreement with one side of a contested question). For each code item, also check that the prompt states everything the tests check (names, parameters, data representation, units, return values, ties and edge cases), that float results are compared with a tolerance, that no test depends on random values or set order, that the work is small enough to run quickly in the browser, and that the tests would catch the typical wrong solutions (dividing by n instead of n − 1 or the reverse, a sign error in a leak or an update, mixing milliseconds and seconds, an off-by-one bin, in-place updates where a copy is needed) — add an assert where one is clearly missing. In project.txt, also check the review guide, the materials (small, typed-out data) and the exam items, and that any project with people uses only low-risk tasks with volunteers who agree and anonymous data, and that no project involves animals. Also fix: any item that needs data from another item or from the article ("the previous problem", "as above") — restate it; any practice or quiz item that reuses a worked example's data — change the data; any code item that asks for a function the article already gives in full — make it a variant that requires applying the idea; any prompt that is ambiguous in a way that would mark a correct alternative answer wrong — state what is wanted; any passage or item that takes sides on a contested question (the mind–body problem, theories of consciousness, free will, nature and nurture, animal and machine consciousness, psychiatric categories, animal research, enhancement, neuroscience in court) instead of presenting the views fairly — make it balanced; any description, comparison or ranking of current commercial neurotechnology products or companies — make it generic or historical; any drug dose, stimulation setting or treatment instruction a reader could follow — reduce it to the textbook level; any statement about group differences in intelligence or brain function between racial or ethnic groups — remove it; British spellings — make them American; and any statement unsuitable for the course's audience.
