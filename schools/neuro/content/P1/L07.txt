@article
A neuron's spike count varies from trial to trial even for the same stimulus. How much does the count tell an observer about the stimulus? Shannon's **mutual information** answers in bits, and it is the common currency for comparing codes. Applied to neurons since the 1950s and put on a firm experimental footing by methods such as those of Strong and colleagues (1998), it measures what a response *could* tell an ideal observer, not what the brain does read out.

### Entropy and mutual information

For a discrete variable with probabilities $p_k$ the **entropy** is $H = -\sum_k p_k\log_2 p_k$ bits (with $0\log 0 = 0$): the average number of yes/no questions needed to identify the value, or the uncertainty before seeing it. For a stimulus $S$ and a response $R$,

$$I(S;R) = H(R) - H(R\mid S) = \sum_{s,r}p(s,r)\log_2\frac{p(s,r)}{p(s)\,p(r)} \ge 0,$$

the reduction in uncertainty about the response when the stimulus is known (equivalently, about the stimulus when the response is known). It is zero if and only if $S$ and $R$ are independent, and it is symmetric. It is a **nonlinear** measure of dependence: it captures any relation, not only correlation.

**Example.** Two equally likely stimuli, $P(S{=}0) = P(S{=}1) = 0.5$, and a spike count $R\in\{0,1,2\}$ with $P(R\mid S{=}0) = (0.6, 0.3, 0.1)$ and $P(R\mid S{=}1) = (0.1, 0.3, 0.6)$. Then $p(R) = (0.35, 0.30, 0.35)$, $H(R) = 1.5813$ bits, and each conditional distribution has entropy $1.2955$ bits, so $I = 1.5813 - 1.2955 = 0.2858$ bits: one count tells you about 0.29 of the 1 bit needed to identify the stimulus.

The **data processing inequality** says that processing cannot add information: if $S\to R\to Z$ forms a Markov chain ($Z$ depends on $S$ only through $R$), then $I(S;Z)\le I(S;R)$. It is why any downstream readout, however clever, is bounded by the information in its input.

### The Gaussian channel

If $R = S + N$ with $S$ Gaussian of variance $\sigma_S^2$ and independent Gaussian noise of variance $\sigma_N^2$, then
$$I(S;R) = \tfrac12\log_2\big(1 + \sigma_S^2/\sigma_N^2\big)\ \text{bits}.$$
Signal-to-noise ratio 3 gives exactly 1 bit; ratio 15 gives 2 bits. Each doubling of the information requires a much larger SNR (information grows logarithmically with it).

### Fisher information and the Cramér–Rao bound

Mutual information is global. For fine discrimination, the local quantity is **Fisher information** $J(s) = \mathbb E\big[(\partial_s\log p(r\mid s))^2\big]$, and the **Cramér–Rao bound** says any unbiased estimator has $\mathrm{Var}(\hat s) \ge 1/J(s)$. For independent Poisson neurons with tuning curves $f_i(s)$ (Hz) counted over a window $T$, $J(s) = T\sum_i f_i'(s)^2/f_i(s)$. For Gaussian tuning curves $f_i = r_{\max}\exp(-(s - s_i)^2/2w^2)$ with preferred stimuli spread at density $\rho$, replacing the sum by an integral gives
$$J = T\,\rho\,r_{\max}\sqrt{2\pi}/w,$$
independent of $s$. With $T = 0.1$ s, $\rho = 2$ neurons per degree, $r_{\max} = 40$ Hz, $w = 10^\circ$: $J = 2.005$ deg$^{-2}$, a minimum standard deviation of $0.706^\circ$. In this one-dimensional case narrower tuning gives *more* information. Results depend on dimension and on noise correlations: with correlations that are not removable by averaging, information saturates as the population grows (Moreno-Bote and colleagues, 2014, called these information-limiting correlations).

### Limited sampling bias

Estimating $H$ or $I$ from $N$ samples with the observed frequencies (the **plug-in** estimator) is biased: entropy is underestimated, and mutual information overestimated, because sampling noise makes the data look more structured than the source. To leading order, the plug-in entropy of a distribution with $K$ occupied bins is low by $(K-1)/(2N\ln 2)$ bits, and the **Miller–Madow correction** adds this. With $N = 20$ and $K = 4$ the correction is $0.108$ bits. For the mutual information, the leading-order bias of the plug-in estimate is $(K_S - 1)(K_R - 1)/(2N\ln 2)$ bits (Treves and Panzeri, 1995). This is a first-order fix valid when each bin has at least a few samples; more sophisticated estimators and shuffle controls are standard.

### What information does and does not say

Information bounds what a response could convey; it does not say which feature of the response the brain uses, whether the code is easy to read out, or whether the stimulus ensemble matches natural input. Always report the stimulus ensemble, window and estimator.

### In code

```python
import math


def entropy(p):
    """Entropy in bits of a list of probabilities (0 log 0 = 0)."""
    return -sum(x * math.log2(x) for x in p if x > 0)
```

For a joint table, `entropy` applied to the marginals and to the flattened joint gives $I = H(S) + H(R) - H(S,R)$.

title: Mutual information from a joint table
problem: A neuron's response $R \in \{0, 1\}$ (spike or no spike) for stimulus $S \in \{0, 1\}$ has joint probabilities $P(0,0) = 0.4$, $P(0,1) = 0.1$, $P(1,0) = 0.1$, $P(1,1) = 0.4$. Compute $I(S;R)$.
step: The marginals are $p(S) = (0.5, 0.5)$ and $p(R) = (0.5, 0.5)$, so $H(S) = H(R) = 1$ bit.
step: The joint entropy is $H(S,R) = -(2\times0.4\log_2 0.4 + 2\times0.1\log_2 0.1) = 0.8\times1.3219 + 0.2\times3.3219 = 1.0575 + 0.6644 = 1.7219$ bits.
step: $I = H(S) + H(R) - H(S,R) = 2 - 1.7219 = 0.2781$ bits.
step: Check with $I = H(R) - H(R\mid S)$: given $S$, $R$ has probabilities $(0.8, 0.2)$ with entropy $0.7219$, and $1 - 0.7219 = 0.2781$.
answer: $I = 0.278$ bits.

@mistakes
- Using the natural logarithm and calling the answer bits: $\ln$ gives nats; divide by $\ln 2$ to convert to bits.
- Treating plug-in mutual information from a few trials as unbiased: with a 5-by-5 table and 50 trials, the leading-order bias is $16/(100\ln 2) = 0.23$ bits, which can exceed the true information.
- Reading mutual information as a measure of what the brain decodes: it is an upper bound on what any readout can extract.
- Assuming more spikes means more information: information depends on how the response distribution varies with the stimulus, relative to the noise.

```python
import math


def mutual_information(counts):
    """Plug-in mutual information (bits) of a stimulus-by-response count table."""
    total = sum(sum(row) for row in counts)
    ps = [sum(row) / total for row in counts]
    pr = [sum(col) / total for col in zip(*counts)]
    info = 0.0
    for i, row in enumerate(counts):
        for j, c in enumerate(row):
            if c > 0:
                p = c / total
                info += p * math.log2(p / (ps[i] * pr[j]))
    return info
```
hint: Use `zip(*counts)` to get the column sums, and skip empty cells because $0\log 0 = 0$.
solution: The marginals come from row and column sums; empty cells contribute nothing. The diagonal table has three equally likely stimuli perfectly identified by the response, so the information is $\log_2 3$ bits. The first test is the independent case, with zero information.

```python
import math


def miller_madow_entropy(counts):
    """Plug-in entropy (bits) plus the Miller-Madow bias correction."""
    n = sum(counts)
    if n == 0:
        return 0.0
    occupied = [c for c in counts if c > 0]
    h = -sum(c / n * math.log2(c / n) for c in occupied)
    return h + (len(occupied) - 1) / (2 * n * math.log(2))
```
hint: Count only occupied bins for both the entropy sum and $K$; convert the correction from nats to bits by dividing by $\ln 2$.
solution: With all the mass in one bin, $K = 1$ and the correction is zero, so the entropy is 0. For `[5, 0, 5]` the plug-in entropy is 1 bit and $K = 2$ gives a correction of $1/(20\ln2) = 0.0721$ bits; counting the empty bin would give a wrong value.
