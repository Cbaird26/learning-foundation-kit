@article
Randomness is everywhere in computing: hash functions spread keys over slots, randomized algorithms flip coins, and networks drop packets. To reason about it, we first need a precise model of a random experiment.

### Probability spaces

A **probability space** has three parts. The **sample space** $\Omega$ is the set of all possible outcomes of the experiment. An **event** is a subset $A \subseteq \Omega$ (a set of outcomes we care about). A **probability function** $P$ assigns each event a number so that

1. $P(A) \ge 0$ for every event $A$,
2. $P(\Omega) = 1$,
3. if $A_1, A_2, \dots$ are pairwise **disjoint** events (no shared outcomes), then $P(A_1 \cup A_2 \cup \cdots) = P(A_1) + P(A_2) + \cdots$.

Everything else follows from these axioms. For instance, since $A$ and its complement $A^c$ are disjoint with union $\Omega$, we get $P(A^c) = 1 - P(A)$. For any two events,

$$P(A \cup B) = P(A) + P(B) - P(A \cap B),$$

because adding $P(A)$ and $P(B)$ counts the outcomes of $A \cap B$ twice. This is the two-event case of **inclusion-exclusion**; for three events you add the three single probabilities, subtract the three pairwise intersections and add back the triple intersection.

### Uniform spaces and counting

When $\Omega$ is finite and all outcomes are equally likely (a **uniform** or **naive** sample space), the axioms give

$$P(A) = \frac{|A|}{|\Omega|}.$$

The whole problem becomes counting, and you must be sure the outcomes you count really are equally likely. Two dice should be modeled as 36 ordered pairs, not 11 possible sums: the sum 7 is far more likely than the sum 2.

### Counting tools

- **Multiplication rule.** If a task has $k$ stages with $n_1, n_2, \dots, n_k$ choices (each count independent of earlier choices), there are $n_1 n_2 \cdots n_k$ ways to do it. A string of $n$ characters from an alphabet of size $m$ has $m^n$ possibilities.
- **Permutations.** The number of ordered arrangements of $k$ distinct items chosen from $n$ is $n(n-1)\cdots(n-k+1) = \frac{n!}{(n-k)!}$.
- **Combinations.** The number of unordered subsets of size $k$ from $n$ items is $\binom{n}{k} = \frac{n!}{k!\,(n-k)!}$. Each subset corresponds to $k!$ orderings, which is why you divide.

In Python, `math.comb(n, k)` and `math.perm(n, k)` compute these exactly with integers.

### The birthday problem and hashing

If $k$ keys are hashed independently and uniformly into $m$ slots, there are $m^k$ equally likely assignments, and $m(m-1)\cdots(m-k+1)$ of them put every key in a different slot. So

$$P(\text{some collision}) = 1 - \frac{m(m-1)\cdots(m-k+1)}{m^k}.$$

With $m = 365$ and $k = 23$ this is about $0.507$: collisions appear far sooner than intuition suggests, which is why hash tables must handle them.

@example
title: Two dice
problem: Two fair six-sided dice are rolled. What is the probability that the sum is 8?
step: Model the experiment with ordered pairs $(a, b)$ where $a$ and $b$ are the two faces. By the multiplication rule $|\Omega| = 6 \cdot 6 = 36$, and the pairs are equally likely.
step: List the pairs with $a + b = 8$: $(2,6), (3,5), (4,4), (5,3), (6,2)$. Note that $(2,6)$ and $(6,2)$ are different outcomes.
step: So $|A| = 5$ and $P(A) = |A| / |\Omega| = 5/36$.
answer: $5/36$

@example
title: A collision in a small hash table
problem: Three keys are hashed independently and uniformly into 10 slots. What is the probability that at least two keys land in the same slot?
step: Count all assignments: each key has 10 choices, so $|\Omega| = 10^3 = 1000$, all equally likely.
step: Count assignments with all slots distinct: $10 \cdot 9 \cdot 8 = 720$ (any slot for the first key, then a different one for the second, then a third different slot).
step: The complement of "some collision" is "no collision", so $P(\text{collision}) = 1 - 720/1000$.
step: This equals $280/1000 = 7/25$.
answer: $7/25$

@mistakes
- Treating outcomes as equally likely when they are not, such as using the 11 sums of two dice instead of the 36 ordered pairs.
- Using combinations when order matters (or permutations when it does not), which changes the count by a factor of $k!$.
- Adding $P(A) + P(B)$ for events that overlap, forgetting to subtract $P(A \cap B)$.
- Counting "at least one" directly instead of using the complement, which usually leads to double counting.

@practice num
prompt: A fair coin is tossed 4 times. What is the probability of exactly two heads? Give an exact fraction.
answer: 3/8
check: Fraction(comb(4, 2), 2**4)
hint: There are $2^4$ equally likely sequences of heads and tails.
hint: A sequence with exactly two heads is determined by which 2 of the 4 positions hold heads.
solution: There are $\binom{4}{2} = 6$ favorable sequences out of $2^4 = 16$, so the probability is $6/16 = 3/8$.

```python
from fractions import Fraction
from math import comb


def prob_at_least_k_heads(n, k):
    favorable = sum(comb(n, j) for j in range(k, n + 1))
    return Fraction(favorable, 2 ** n)
```

solution: Sum `comb(n, j)` over `j = k, ..., n` to count favorable sequences, and divide by `2 ** n` using `Fraction` to keep the result exact. If `k > n` the sum is over an empty range and gives `0`.

model:
```python
def birthday_collision(n, days=365):
    if n <= 1:
        return 0.0
    if n > days:
        return 1.0
    all_different = 1.0
    for i in range(n):
        all_different *= (days - i) / days
    return 1.0 - all_different
```
hint: Compute the probability that all birthdays are different, then subtract from 1.
hint: Person $i$ (counting from 0) must avoid the $i$ earlier birthdays, which has probability `(days - i) / days`; multiply these factors.
solution: Multiply `(days - i) / days` for `i = 0, ..., n - 1` to get the probability that all birthdays differ, and return one minus that. Handling `n <= 1` and `n > days` separately matches the specification (for `n > days` the product would contain a zero factor anyway).

@quiz code
prompt: Write `prob_sum(target, sides=6)` that returns, as a `Fraction`, the probability that two fair dice with `sides` faces each (faces numbered 1 to `sides`) have a sum equal to `target`. Enumerate the equally likely ordered pairs. Impossible sums have probability `Fraction(0)`.
starter:
```python
from fractions import Fraction


def prob_sum(target, sides=6):
    pass
```
tests:
```python
from fractions import Fraction

assert prob_sum(7) == Fraction(1, 6)
assert prob_sum(2) == Fraction(1, 36)
assert prob_sum(13) == 0
assert prob_sum(8, 4) == Fraction(1, 16)
assert prob_sum(5, 4) == Fraction(1, 4)
```
model:
```python
from fractions import Fraction


def prob_sum(target, sides=6):
    favorable = 0
    for a in range(1, sides + 1):
        for b in range(1, sides + 1):
            if a + b == target:
                favorable += 1
    return Fraction(favorable, sides * sides)
```
hint: The sample space is all ordered pairs `(a, b)`, so it has `sides * sides` equally likely outcomes.
hint: Use two nested loops and count the pairs whose sum equals `target`.
solution: Count the ordered pairs with `a + b == target` with two nested loops and divide by `sides * sides`. For two four-sided dice and target 5 the pairs are (1,4), (2,3), (3,2), (4,1), so the answer is $4/16 = 1/4$.

@quiz num
prompt: A committee of 3 people is chosen uniformly at random from a group of 10 people that includes Ann and Bob. What is the probability that both Ann and Bob are on the committee? Give an exact fraction.
answer: 1/15
check: Fraction(comb(8, 1), comb(10, 3))
hint: There are $\binom{10}{3}$ equally likely committees.
hint: If Ann and Bob are both in, only the third member is still to be chosen from the other 8 people.
solution: There are $\binom{10}{3} = 120$ committees. Those containing both Ann and Bob are determined by the third member, so there are $8$ of them. The probability is $8/120 = 1/15$.
