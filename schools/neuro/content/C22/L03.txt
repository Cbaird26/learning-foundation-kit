@article
The normal equations solve linear regression in one shot, but most models have no closed-form solution, and for very large $d$ even $O(d^3)$ is too slow. **Gradient descent** is the general-purpose alternative: start somewhere and repeatedly walk downhill.

### The update rule

For a loss $L(w)$ the **gradient** $\nabla L(w)$ is the vector of partial derivatives; it points in the direction of steepest increase. Gradient descent moves the opposite way:
$$w \leftarrow w - \eta\, \nabla L(w).$$
The positive number $\eta$ is the **learning rate** (step size). Each step is cheap, and the method works for any differentiable loss.

### The learning rate

Take $L(w) = (w - 3)^2$, so $L'(w) = 2(w - 3)$. The update is $w - 3 \leftarrow (1 - 2\eta)(w - 3)$: the distance to the minimum is multiplied by $1 - 2\eta$ at every step. If $0 < \eta < 1$ the factor has absolute value below 1 and the iterates converge to 3; for $\eta > 1$ its absolute value exceeds 1 and they **diverge**, jumping farther away each time. Too small an $\eta$ converges slowly; too large an $\eta$ oscillates or blows up. For a general quadratic loss with largest curvature $\lambda_{\max}$ (the largest eigenvalue of the Hessian), descent converges when $\eta < 2/\lambda_{\max}$.

### Gradient of the mean squared error

For the linear model $\hat{y}_i = x_i^\top w$ (intercept included as a column of ones) and $L(w) = \frac{1}{n}\sum_i (\hat{y}_i - y_i)^2$, the chain rule gives
$$\nabla L(w) = \frac{2}{n} X^\top (Xw - y).$$
For one feature plus an intercept, $\hat{y} = wx + b$: $\partial L/\partial w = \frac{2}{n}\sum_i e_i x_i$ and $\partial L/\partial b = \frac{2}{n}\sum_i e_i$, where $e_i = \hat{y}_i - y_i$. Both are computed from the **old** parameters before either is updated.

```python
def step(w, b, xs, ys, lr):
    n = len(xs)
    errs = [w * x + b - y for x, y in zip(xs, ys)]
    gw = 2 / n * sum(e * x for e, x in zip(errs, xs))
    gb = 2 / n * sum(errs)
    return w - lr * gw, b - lr * gb
```

The MSE of a linear model is **convex**, so every local minimum is global and gradient descent with a small enough $\eta$ reaches it. For neural networks the loss is not convex, and descent finds a good (not necessarily global) minimum.

### Batch, stochastic and mini-batch

The loss is an average over examples, so its gradient is too. **Batch** gradient descent uses all $n$ examples per step: cost $O(nd)$. **Stochastic gradient descent (SGD)** uses one random example per step, an unbiased but noisy estimate of the gradient, at cost $O(d)$. **Mini-batch** descent uses a small random batch (for example 32 examples), trading noise against cost and exploiting vectorized hardware. One pass over the data is an **epoch**.

### Practical advice

Features on very different scales make the loss surface a long narrow valley: a step size small enough for the steep direction crawls along the flat one. **Standardize the features** (week 1) before using gradient descent. Stop after a fixed number of steps, when the gradient norm is small, or when the loss on held-out data stops improving. To catch mistakes in a hand-derived gradient, compare it with the **numerical gradient** $\bigl(L(w + h e_i) - L(w - h e_i)\bigr)/(2h)$ for a small $h$ such as $10^{-5}$.

@example
title: Gradient descent on a parabola
problem: Minimize $L(w) = (w - 3)^2$ with $\eta = 0.1$ starting from $w_0 = 0$. Compute $w_1$ and $w_2$.
step: The gradient is $L'(w) = 2(w - 3)$.
step: At $w_0 = 0$, $L'(0) = -6$, so $w_1 = 0 - 0.1(-6) = 0.6$.
step: At $w_1 = 0.6$, $L'(0.6) = 2(-2.4) = -4.8$, so $w_2 = 0.6 + 0.48 = 1.08$.
step: Check with the factor $1 - 2\eta = 0.8$: the distance to 3 shrinks from 3 to $2.4$ to $1.92$, and $3 - 1.92 = 1.08$.
answer: $w_1 = 0.6$ and $w_2 = 1.08$.

@example
title: One step of descent for a linear model
problem: Fit $\hat{y} = wx$ (no intercept) with MSE loss to the data $x = (1, 2)$, $y = (2, 4)$. Starting from $w = 0$ with $\eta = 0.05$, compute the gradient and the new $w$.
step: The errors at $w = 0$ are $e_i = wx_i - y_i = (-2, -4)$.
step: The gradient is $\frac{2}{n}\sum e_i x_i = \frac{2}{2}\bigl((-2)(1) + (-4)(2)\bigr) = -10$.
step: The update is $w \leftarrow 0 - 0.05(-10) = 0.5$.
step: The true slope is 2, and the step moved $w$ from 0 toward it. The next gradient is smaller in size because the errors are smaller.
answer: The gradient is $-10$ and the new weight is $0.5$.

@mistakes
- Adding the gradient instead of subtracting it, which climbs the loss (gradient ascent).
- Updating $w$ before computing the gradient for $b$, so $b$'s gradient uses a mixture of old and new parameters.
- Using one learning rate for unscaled features and being surprised that the loss diverges or crawls.
- Believing a smaller loss on the training data after every step is guaranteed: with SGD or a too-large learning rate the loss can go up.

model:
```python
def fit_linear_gd(xs, ys, lr, steps):
    n = len(xs)
    w = 0.0
    b = 0.0
    for _ in range(steps):
        errs = [w * x + b - y for x, y in zip(xs, ys)]
        gw = 2 / n * sum(e * x for e, x in zip(errs, xs))
        gb = 2 / n * sum(errs)
        w, b = w - lr * gw, b - lr * gb
    return (w, b)
```
hint: In each step compute the list of errors once from the current `w` and `b`.
hint: $\partial L/\partial w = \frac{2}{n}\sum e_i x_i$ and $\partial L/\partial b = \frac{2}{n}\sum e_i$. Assign both new values in one statement.
solution: Compute errors from the old parameters, then both gradients, then update `w` and `b` together. If `b` were updated using errors recomputed after changing `w`, the first-step test would fail.

model:
```python
def numeric_gradient(f, point, h=1e-5):
    grad = []
    for i in range(len(point)):
        up = list(point)
        down = list(point)
        up[i] += h
        down[i] -= h
        grad.append((f(up) - f(down)) / (2 * h))
    return grad
```
hint: For each coordinate make two copies of the point, one nudged up by `h` and one down by `h`.
solution: Copy the point for every coordinate, add `h` to that coordinate in one copy and subtract it in the other, and divide the difference of the function values by `2 * h`. Copying keeps the caller's list unchanged. Gradient checking like this is the standard test for a hand-derived gradient.
