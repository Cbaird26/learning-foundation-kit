@review
## Week 13 review: Programming in Python II

**Weeks 1-2, functions and tests.** A function takes parameters and *returns* a value; `print` only shows text, and a function without `return` gives `None`. Split big tasks into small helpers with one job each. `assert` states what must be true; test typical, edge and likely-wrong cases, and compare decimals with a tolerance.

**Weeks 3-4, lists and strings.** Slices `xs[a:b:c]` make new lists, with the stop index excluded. `sort`, `append` and `random.shuffle` change a list in place and return `None`. `b = a` makes an alias, not a copy. Comprehensions `[expr for x in xs if cond]` transform and filter. Strings are immutable; use `strip`, `lower`, `split` and `join` to clean text into words.

**Weeks 5-6, dictionaries, sets and files.** A dictionary maps keys to values; `get(key, default)` avoids `KeyError`; the counting and grouping patterns summarize data. Sets remove duplicates and support `&`, `|` and `-`. Open files with `with`; mode `"w"` erases, `"a"` appends. Everything read is text: convert with `int` or `float`, and skip bad lines with `try`/`except ValueError`.

**Weeks 7-8, searching and sorting.** Linear search checks items one by one and works on any list. Binary search needs a sorted list and halves the range with `lo`, `hi` and `mid`. Selection sort and insertion sort take about $n^2/2$ steps; `sorted` and `list.sort` are much faster, accept `key` and `reverse`, and are stable.

**Weeks 9-10, efficiency and simulation.** Count steps as a function of the input size $n$. Doubling $n$ doubles a linear algorithm's work, quadruples a quadratic one's, and adds one probe to binary search. A set lookup beats a list scan. `random.randint(a, b)` includes both ends; estimates from simulations improve with more trials; pass the random part in as a function so the rules can be tested.

**Weeks 11-12, impact and design.** Removing names does not make data anonymous; the smallest group size (k-anonymity), generalization and data minimization help judge and reduce the risk. Consider benefits, harms and bias from several viewpoints. Plan large programs: requirements and examples, data, function list, tests, then build one tested function at a time.

### Common errors

- Returning inside the loop instead of after it, or printing instead of returning.
- `xs = xs.sort()` and `xs = random.shuffle(xs)`, which store `None`.
- Off-by-one mistakes in slices, `range` and binary search bounds.
- Forgetting to convert text from a file to numbers, or crashing on a blank line.
- Using binary search on unsorted data.
- Trusting a simulation with too few trials, or testing random output directly.

text = "The cat and the hat and the bat."
assert top_words(text, 3) == [("the", 3), ("and", 2), ("bat", 1)]
assert top_words("A a. B b! c", 2) == [("a", 2), ("b", 2)]

model:
```python
import string


def count_key(pair):
    word, count = pair
    return (-count, word)


def top_words(text, n):
    counts = {}
    for raw in text.lower().split():
        word = raw.strip(string.punctuation)
        if word:
            counts[word] = counts.get(word, 0) + 1
    ordered = sorted(counts.items(), key=count_key)
    return ordered[:n]
```
hint: First clean the words and count them in a dictionary, as in the word-frequency counter.
hint: `counts.items()` gives `(word, count)` pairs; sort them with a key function that returns `(-count, word)`, then take the first `n` with a slice.
solution: Count the cleaned words with the counting pattern. Sorting the `(word, count)` pairs with the key `(-count, word)` puts higher counts first and breaks ties alphabetically, and the slice `[:n]` keeps at most `n` pairs (and gives `[]` for `n = 0`). This connects string cleaning (week 4), dictionaries (week 5) and sorting with keys (week 8).

model:
```python
def search_scores(filename, minimum):
    with open(filename) as f:
        text = f.read()
    records = []
    for line in text.splitlines():
        parts = line.split(",")
        if len(parts) != 2:
            continue
        try:
            score = int(parts[1])
        except ValueError:
            continue
        if score >= minimum:
            records.append((-score, parts[0].strip()))
    records.sort()
    return [name for _, name in records]
```
hint: Read the file, split each line at the comma, and skip the lines that do not have two fields or whose score is not a whole number.
hint: Store `(-score, name)` for the lines that qualify; sorting these tuples gives highest scores first and alphabetical names for ties.
solution: Parse each line defensively (blank lines have one field and are skipped by the length check), keep the records with `score >= minimum` as `(-score, name)` tuples, sort them, and return the names. Negating the score makes the ascending sort of tuples put the highest scores first. This combines files (week 6), error handling, and sorting by several criteria (week 8).

@exam num
prompt: A sorted list has 1,000,000 items. Using binary search with the `lo`/`hi` method, what is the largest number of probes (items examined) that any search can need? Give the number.
answer: 20
check: floor(log2(10**6)) + 1
hint: Each probe halves the range, so the worst case is $\lfloor \log_2 n \rfloor + 1$. Estimate $\log_2 1{,}000{,}000$ from $2^{10} = 1024$.
solution: Since $2^{10} \approx 1000$, we get $2^{20} \approx 10^6$. More precisely $2^{19} = 524{,}288 < 10^6 < 2^{20} = 1{,}048{,}576$, so $\lfloor \log_2 10^6 \rfloor = 19$ and the worst case is $19 + 1 = 20$ probes, compared with up to 1,000,000 comparisons for linear search.
