@article
Last week we differentiated a graph by hand. This week a program does it. **Backpropagation** (popularized for neural networks by Rumelhart, Hinton and Williams, 1986) is the special case of **reverse-mode automatic differentiation** (autodiff) applied to a network's loss. It is not symbolic differentiation (no formula for the derivative is built) and it is not finite differences (no approximation): it applies the exact chain rule to the numbers that the forward pass actually produced.

### Why reverse mode

Automatic differentiation has two modes. **Forward mode** carries a derivative along with each value, so one sweep gives the derivative of every output with respect to *one* input. **Reverse mode** first runs the function forward and records the graph, then sweeps backward from the output, so one sweep gives the derivative of *one* output with respect to *every* input. A training loss is a single scalar and a network has millions of parameters, so reverse mode wins: its cost is a small constant multiple of one forward pass, regardless of the number of parameters. Its price is memory, because the intermediate values of the forward pass must be stored.

### The design of a scalar engine

Each number is wrapped in a `Value` object holding its `data`, its `grad` (initially 0), the `parents` that produced it, and a small function `_backward` that pushes the node's gradient to its parents using the local derivative. Operations build new `Value` objects, so ordinary Python expressions record the graph as they run.

```python
class Value:
    def __init__(self, data, parents=()):
        self.data = data
        self.grad = 0.0
        self.parents = parents
        self._backward = lambda: None

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other))
        def _backward():
            self.grad += out.grad
            other.grad += out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other))
        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward
        return out
```

Every `_backward` uses `+=` because a node can be used many times. A `tanh` is added the same way: with $t = \tanh(\text{data})$, the local derivative is $1 - t^2$.

### The backward pass

A node's gradient is complete only when *every* node that uses it has already sent its contribution. That is guaranteed by processing nodes in **reverse topological order**: a topological order lists every node after its parents, so its reverse lists every node before its parents. A depth-first search that appends a node after visiting its parents produces one.

```python
    def backward(self):
        order, seen = [], set()
        def visit(v):
            if id(v) not in seen:
                seen.add(id(v))
                for p in v.parents:
                    visit(p)
                order.append(v)
        visit(self)
        self.grad = 1.0
        for v in reversed(order):
            v._backward()
```

The seed is $\partial L/\partial L = 1$. As a check, take the neuron $o = \tanh(w_1 x_1 + w_2 x_2 + b)$ with $x_1 = 1$, $x_2 = -1$, $w_1 = 0.5$, $w_2 = 0.25$, $b = 0.1$. The pre-activation is 0.35, so $o = \tanh 0.35 \approx 0.3364$ and $\partial o/\partial z = 1 - o^2 \approx 0.8869$. The gradients are then $\partial o/\partial w_1 = 0.8869 \cdot x_1 = 0.8869$, $\partial o/\partial w_2 = 0.8869 \cdot x_2 = -0.8869$, $\partial o/\partial x_1 = 0.8869 \cdot w_1 = 0.4434$, $\partial o/\partial x_2 = 0.2217$ and $\partial o/\partial b = 0.8869$. The engine reproduces exactly these numbers.

### Notes on practice

Gradients accumulate, so before a second backward pass on a fresh forward computation you must reset them to zero (frameworks provide `zero_grad`); building new `Value`s each time, as here, resets them automatically. The recursion in `visit` fails on graphs deeper than Python's recursion limit, so a production engine uses an explicit stack. PyTorch's `Tensor` does the same thing with tensors instead of scalars: each operation records a `grad_fn`, and `loss.backward()` walks the graph in reverse topological order.

The universal test for any new operation is the gradient check from Week 3: compare each `grad` with a central finite difference of the forward computation. A derivative formula that is wrong in one operation shows up as a disagreement in exactly the parameters that depend on it.

title: Backward pass by hand on a shared node
problem: With $a = 2$ and $b = -3$, compute $c = a b + a$ and its gradients $\partial c/\partial a$ and $\partial c/\partial b$ the way the engine would: forward pass, then nodes in reverse topological order.
step: Forward: $p = ab = -6$ and $c = p + a = -4$. The nodes in topological order are $a$, $b$, $p$, $c$.
step: Seed $c.\text{grad} = 1$. Node $c$ is a sum, so $p.\text{grad} \mathrel{+}= 1$ and $a.\text{grad} \mathrel{+}= 1$.
step: Node $p$ is a product: $a.\text{grad} \mathrel{+}= b \cdot p.\text{grad} = -3$, making $a.\text{grad} = 1 - 3 = -2$, and $b.\text{grad} \mathrel{+}= a \cdot p.\text{grad} = 2$.
step: Check with algebra: $c = a(b + 1)$, so $\partial c/\partial a = b + 1 = -2$ and $\partial c/\partial b = a = 2$.
answer: $\partial c/\partial a = -2$ and $\partial c/\partial b = 2$.

@example
title: Adding exp to the engine
problem: Give the local backward rule for $\exp$ in the engine and use it to differentiate $y = e^{x}\cdot x$ at $x = 1$.
step: For $\text{out} = e^{s}$ the local derivative is $e^{s} = \text{out.data}$, so the rule is `self.grad += out.data * out.grad`.

step: Backward: seed $y.\text{grad} = 1$. Product: $u.\text{grad} = x \cdot 1 = 1$ and $x.\text{grad} \mathrel{+}= u \cdot 1 = 2.7183$.

@mistakes
- Visiting nodes in the wrong order (for example, from the inputs toward the output, or a depth-first search that lists a node before its parents) so that a node's `_backward` runs before all its contributions have arrived; reverse topological order prevents this.
- Calling `backward` a second time without resetting the gradients, so the new gradients are added to the old ones.
- Using the output's local derivative formula with the wrong value: the local derivative of $\tanh$ is $1 - t^2$ with $t$ the output, and for a product it uses the *other* operand's `data`.
- Thinking backpropagation is an approximation or a symbolic algebra system: it computes exact derivatives (up to floating-point rounding) numerically.

model:
```python
def topo_order(root):
    """Iterative depth-first topological order: parents first, root last."""
    order, seen = [], {id(root)}
    stack = [(root, iter(root.parents))]
    while stack:
        node, it = stack[-1]
        for p in it:
            if id(p) not in seen:
                seen.add(id(p))
                stack.append((p, iter(p.parents)))
                break
        else:
            order.append(node)
            stack.pop()
    return order
```
hint: Keep a stack of (node, iterator over its parents); advance the top iterator, push an unseen parent, and append a node to the result only when its iterator is exhausted.
solution: This is the same depth-first search as the recursive one, with the call stack replaced by an explicit stack so that deep graphs cannot overflow it. A node is appended only after all of its parents have been appended, and the `seen` set (by `id`) lists shared nodes once. The 3000-node chain would exceed CPython's default recursion limit with a recursive version.

```python
import math

class Value:
    def __init__(self, data, parents=()):
        self.data = data
        self.grad = 0.0
        self.parents = parents
        self._backward = lambda: None

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other))
        def _backward():
            self.grad += out.grad
            other.grad += out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other))
        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward
        return out

    def backward(self):
        order, seen = [], set()
        def visit(v):
            if id(v) not in seen:
                seen.add(id(v))
                for p in v.parents:
                    visit(p)
                order.append(v)
        visit(self)
        self.grad = 1.0
        for v in reversed(order):
            v._backward()

    def __neg__(self):
        return self * -1.0

    def __sub__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        return self + (-other)

    def __pow__(self, k):
        out = Value(self.data ** k, (self,))
        def _backward():
            self.grad += k * self.data ** (k - 1) * out.grad
        out._backward = _backward
        return out

    def exp(self):
        out = Value(math.exp(self.data), (self,))
        def _backward():
            self.grad += out.data * out.grad
        out._backward = _backward
        return out
```
hint: For each new operation, create the output `Value` with `self` as parent and write `_backward` as (local derivative) times `out.grad`, added to `self.grad`. For subtraction, build it from addition and negation.
solution: The local derivatives are $-1$ for negation, $k x^{k-1}$ for the power and $e^x = $ `out.data` for the exponential; subtraction composes `+` and negation so it needs no new rule. The sigmoid test builds $\sigma(x) = (1 + e^{-x})^{-1}$ out of the new operations and checks the known derivative $\sigma(1 - \sigma)$, which is how composite functions get their gradients for free.
