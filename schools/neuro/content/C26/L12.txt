@article
You fit a model to a participant and get $\hat\beta = 4.5$. How much should you trust that number? One way to find out is to ask a question the data cannot answer but a simulation can: **if the true parameter were exactly $4.5$, and we had this experiment, what would our fitting procedure typically return?** If the answer is "anything from 2 to 9," the estimate says little. A **parameter-recovery study** answers the question directly.

### The recipe

1. Choose true parameter values, spanning the range you expect.
2. For each, simulate data from the model with the same design as the experiment (same trials, same stimuli), using random numbers.
3. Fit the model to each simulated data set with the same method (here, the grid search of week 3).
4. Compare recovered estimates with the true values: **bias** (mean of estimate minus truth), **root-mean-square error** (RMSE, $\sqrt{\text{mean}(\text{estimate}-\text{truth})^2}$), and the correlation between truth and estimate.

For several parameters, also check the correlation between the estimates of different parameters across simulated data sets: a strong correlation means the parameters **trade off** and are hard to separate with this design.

Simulating needs random numbers. A reproducible way to simulate a softmax chooser is to supply uniform numbers $u_t \in [0, 1)$ and choose option 1 on trial $t$ when $u_t < p_t(1)$, which is the same as drawing from the model. Here is a study with 40 trials of value differences $\pm 0.2, \pm 0.4, \pm 0.8$ and ten simulated data sets for each true $\beta$:

```python
import math
import random

def simulate_choices(deltas, beta, us):
    return [1 if u < 1 / (1 + math.exp(-beta * d)) else 0
            for d, u in zip(deltas, us)]

def log_lik(choices, deltas, beta):
    total = 0.0
    for c, d in zip(choices, deltas):
        p1 = 1 / (1 + math.exp(-beta * d))
        total += math.log(p1 if c == 1 else 1 - p1)
    return total

deltas = ([-0.8, -0.4, -0.2, 0.2, 0.4, 0.8] * 7)[:40]
grid = [0.5 * i for i in range(1, 25)]
rng = random.Random(1)
for true_beta in (0.5, 1, 2, 4, 8):
    est = []
    for _ in range(10):
        us = [rng.random() for _ in deltas]
        ch = simulate_choices(deltas, true_beta, us)
        est.append(max(grid, key=lambda b: log_lik(ch, deltas, b)))
    m = sum(est) / len(est)
    sd = (sum((e - m) ** 2 for e in est) / (len(est) - 1)) ** 0.5
    print(true_beta, round(m, 2), round(sd, 2))
```

It prints the mean estimate and the standard deviation across the ten data sets:

| true $\beta$ | mean estimate | SD |
|---|---|---|
| 0.5 | 0.75 | 0.49 |
| 1 | 1.00 | 0.67 |
| 2 | 2.65 | 1.45 |
| 4 | 3.95 | 1.42 |
| 8 | 8.65 | 2.06 |

Two lessons appear. First, **precision**: with 40 trials the standard deviation is comparable to the parameter itself for $\beta \ge 2$, so a single estimate of $4.5$ really could mean a true value of 2 or 8. Second, **bias from the edge of the grid**: for $\beta = 0.5$ many estimates sit at the lowest grid value, $0.5$, so they cannot fall below the truth and the mean is biased upward. Both would improve with more trials or a better design (more extreme value differences make choices more informative about $\beta$).

### Model recovery

**Model recovery** asks whether the comparison procedure can tell the candidate models apart. Simulate data from each model (with parameters in the plausible range), fit all models to each simulated data set, and record which one wins by AIC or BIC. Collect the counts in a **confusion matrix** with generating models in rows and winning models in columns. A matrix with large diagonal entries says that, with this design, the comparison usually recovers the truth. If a data set from model A is often won by model B, then a win for B in real data is weak evidence. Note a limit: model recovery works only among models you thought of, so it cannot rule out a model outside the set.

### Good practice

- State the models and the comparison criterion **before** looking at the data where possible, and report all models tried.
- Report the number of trials, the grid or optimizer settings, and that the best value is not at the edge of the grid.
- Fit by maximum likelihood, compare with AIC or BIC, and also check absolute fit, such as whether the winner reproduces the learning curve or the RT distributions.
- Run parameter and model recovery with the real design; if recovery is poor, simplify the model or collect more informative data.
- Use held-out data or cross-validation when possible, and share code and data.

None of this settles what the model means. A well-recovered parameter is a reliable description within the model; it does not make the model true, and the debate in the first lesson about what models show (Marr's levels, mimicry, the limits of comparison) remains.

@example
title: Summarizing a recovery study
problem: Three simulated participants had true $\beta$ values of $1, 2, 4$, and the fit recovered $1.2, 1.8, 5.0$. Compute the bias and the RMSE.
step: Errors (estimate minus truth): $0.2$, $-0.2$, $1.0$.
step: Bias: $(0.2 - 0.2 + 1.0)/3 = 0.333$.
step: RMSE: the squares are $0.04, 0.04, 1.00$, which sum to $1.08$; $\sqrt{1.08/3} = \sqrt{0.36} = 0.6$.
step: The correlation between truth and estimate is $0.983$, high, even though the bias is positive: correlation measures ordering, not accuracy of scale.
answer: Bias $0.333$ and RMSE $0.6$.

@mistakes
- Judging recovery by correlation alone: estimates can correlate perfectly with the truth and still be biased or on the wrong scale.
- Simulating with a different design than the experiment: recovery depends on the number and the kind of trials.
- Ignoring the grid edges: many estimates at the lowest or highest grid value signal that the grid, the design or the model is a problem.
- Taking a model-recovery success as proof that the best-fitting model describes real behavior: it only shows the models were distinguishable in the simulation.

model:
```python
import math


def recovery_summary(true_vals, est_vals):
    """Bias, RMSE and Pearson correlation of recovered parameters."""
    n = len(true_vals)
    errors = [e - t for t, e in zip(true_vals, est_vals)]
    bias = sum(errors) / n
    rmse = math.sqrt(sum(x * x for x in errors) / n)
    mt = sum(true_vals) / n
    me = sum(est_vals) / n
    st = sum((t - mt) ** 2 for t in true_vals)
    se = sum((e - me) ** 2 for e in est_vals)
    if st == 0 or se == 0:
        return bias, rmse, None
    cov = sum((t - mt) * (e - me) for t, e in zip(true_vals, est_vals))
    return bias, rmse, cov / math.sqrt(st * se)
```
hint: Compute the errors first for the bias and RMSE; compute the two sums of squared deviations before dividing for the correlation, checking for zero.
solution: Doubling every value gives a correlation of exactly 1 but a bias of 2.0: correlation ignores scale, which is why bias and RMSE are reported as well. A constant estimate has no variance, so the correlation is undefined and the function returns `None`.

model:
```python
import math


def recover_beta(deltas, us_list, true_betas, grid):
    """Simulate from each true beta with supplied uniforms, then refit by grid."""
    def log_lik(choices, beta):
        total = 0.0
        for c, d in zip(choices, deltas):
            p1 = 1 / (1 + math.exp(-beta * d))
            total += math.log(p1 if c == 1 else 1 - p1)
        return total

    estimates = []
    for beta, us in zip(true_betas, us_list):
        choices = [1 if u < 1 / (1 + math.exp(-beta * d)) else 0
                   for d, u in zip(deltas, us)]
        estimates.append(max(grid, key=lambda b: log_lik(choices, b)))
    return estimates
```
hint: Loop over the true values with their own uniform lists; simulate the choices, then pick the grid value with the highest log-likelihood.
solution: The true value 3.0 is recovered exactly, the true value 1.0 is recovered as 1.5, and the true value 6.0 is recovered as 2.5, a large error: with only 12 trials one unlucky set of uniform numbers (two choices against the value difference) pulls the estimate far down. Single-run recovery on short data is noisy, which is why recovery studies repeat many simulated data sets.

model:
```python
def confusion_matrix(pairs, models):
    """Counts of winning model (columns) by generating model (rows)."""
    index = {name: i for i, name in enumerate(models)}
    matrix = [[0] * len(models) for _ in models]
    for generating, winning in pairs:
        matrix[index[generating]][index[winning]] += 1
    return matrix
```
hint: Map each model name to its position, create a square matrix of zeros, and add 1 at row (generating) and column (winning) for each pair.
solution: Rows are what generated the data and columns are what the comparison chose, so a good design has large diagonal counts. Building the matrix with a list comprehension (not by repeating one list) keeps the rows independent, which matters when counts are incremented in place.
