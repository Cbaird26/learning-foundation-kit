@article
A participant faces two slot machines, and we know how good each is (say the expected payoffs $Q_0 = 0.3$ and $Q_1 = 0.7$). Does she always choose the better one? Almost never: people pick the better option more often, but not always, and the more different the options are, the more consistent they become. A model of choice must say not "she chooses option 1" but "she chooses option 1 with probability $p$". A model that predicts probabilities can be scored against the choices actually made.

### The softmax rule

For two options with values $Q_0$ and $Q_1$, the **softmax** (logistic) **choice rule** with **inverse temperature** $\beta \ge 0$ gives

$$p(\text{choose } 1) = \frac{e^{\beta Q_1}}{e^{\beta Q_0} + e^{\beta Q_1}} = \frac{1}{1 + e^{-\beta (Q_1 - Q_0)}} .$$

The inverse temperature $\beta$ measures how strongly value differences drive choice. With $\beta = 0$, choices are random ($p = 0.5$). As $\beta \to \infty$, the rule always picks the larger value. With $K$ options, $p(\text{choose } k) = e^{\beta Q_k} / \sum_j e^{\beta Q_j}$. Only differences in value matter, so adding a constant to all values changes nothing.

### The likelihood of a sequence of choices

Suppose trial $t$ has values $(Q_{0,t}, Q_{1,t})$ and the person chose $c_t \in \{0, 1\}$. If trials are independent given the model, the **likelihood** of the data under parameter $\beta$ is the product of the probabilities the model gave to what happened:

$$L(\beta) = \prod_t p_t(c_t), \qquad \log L(\beta) = \sum_t \log p_t(c_t),$$

where $p_t(1) = 1/(1 + e^{-\beta(Q_{1,t} - Q_{0,t})})$ and $p_t(0) = 1 - p_t(1)$. We work with the **log-likelihood** (natural log, in nats) because a product of many small numbers underflows and a sum does not. The log-likelihood is never positive; a model that predicted every choice with certainty would score $0$, and a model that guesses 50:50 scores $\log 0.5 = -0.693$ per trial.

Note what the likelihood is. It is the probability the model gives to the observed data **as a function of the parameter**. It is not the probability that the parameter is correct; turning it into one needs a prior (week 9).

### In code

Five trials with value pairs $(Q_0, Q_1)$ = (0.2, 0.8), (0.7, 0.3), (0.5, 0.5), (0.4, 0.6), (0.9, 0.2), and choices $1, 0, 1, 1, 0$:

```python
import math

def p_choose_1(q0, q1, beta):
    return 1.0 / (1.0 + math.exp(-beta * (q1 - q0)))

def log_lik(choices, q_pairs, beta):
    total = 0.0
    for c, (q0, q1) in zip(choices, q_pairs):
        p1 = p_choose_1(q0, q1, beta)
        total += math.log(p1 if c == 1 else 1.0 - p1)
    return total

pairs = [(0.2, 0.8), (0.7, 0.3), (0.5, 0.5), (0.4, 0.6), (0.9, 0.2)]
choices = [1, 0, 1, 1, 0]
for beta in (0, 1, 3, 6):
    print(beta, round(log_lik(choices, pairs, beta), 3))
```

This prints $-3.466$, $-2.645$, $-1.662$ and $-1.085$. With $\beta = 0$ the five-trial total is $5\log 0.5$. The score improves as $\beta$ grows because all four trials with unequal values went to the higher-valued option. The third trial has equal values, so it costs $\log 0.5$ whatever $\beta$ is; no parameter can improve it, so the best possible score on these data (as $\beta \to \infty$) is $\log 0.5 = -0.693$. Five trials are far too few to estimate $\beta$ well, which is why real experiments use hundreds.

### Extensions

A **lapse** rate $\epsilon$ mixes in random responding, $p(1) = \epsilon/2 + (1-\epsilon)\,\sigma(\beta\Delta)$, which keeps a single accidental error from driving the log-likelihood to $-\infty$. A **bias** or choice-history term adds a constant to the logit $\beta \Delta$. Each extension is a new model with new parameters, and whether it is worth having is a question for model comparison.

@example
title: Likelihood of two choices
problem: A softmax chooser has $\beta = 2$. On a trial with values $Q_0 = 0.3$ and $Q_1 = 0.7$ she chooses option 1. On another trial with the same values she chooses option 0. Find the log-likelihood of each choice.
step: The value difference is $Q_1 - Q_0 = 0.4$, so $\beta\Delta = 0.8$.
step: $p(1) = 1/(1 + e^{-0.8}) = 1/(1 + 0.4493) = 0.6900$, and $p(0) = 1 - 0.6900 = 0.3100$.
step: Choice 1: $\log 0.6900 = -0.371$. Choice 0: $\log 0.3100 = -1.171$.
step: For the pair of trials, add the logs: $-0.371 + (-1.171) = -1.542$, the log-likelihood of that sequence.
answer: $-0.371$ for the choice of option 1 and $-1.171$ for the choice of option 0; $-1.542$ in total.

@mistakes
- Multiplying probabilities for many trials instead of adding logs: the product underflows to zero.
- Using the probability of the choice the model favored instead of the probability of the choice that was made: each trial needs $p_t(c_t)$.
- Reading the likelihood as the probability that the parameter is true: it is the probability of the data given the parameter.
- Forgetting that $\beta$ only scales the value difference: equal values give $p = 0.5$ at every $\beta$.

model:
```python
import math


def softmax_probs(values, beta):
    """Softmax choice probabilities, shifted by the maximum for stability."""
    scaled = [beta * v for v in values]
    top = max(scaled)
    exps = [math.exp(s - top) for s in scaled]
    total = 0.0
    for e in exps:
        total += e
    return [e / total for e in exps]
```
hint: Multiply every value by `beta`, subtract the maximum of those products, exponentiate, and divide by the total.
solution: Subtracting the same constant from every exponent leaves the ratios unchanged, because the constant cancels between numerator and denominator, but it keeps the largest exponent at $e^0 = 1$ so nothing overflows. With `beta = 0` every exponent is $0$ and the probabilities are equal.

model:
```python
import math


def log_lik_lapse(choices, deltas, beta, eps):
    """Log-likelihood of binary choices under softmax with a lapse rate."""
    total = 0.0
    for c, d in zip(choices, deltas):
        p1 = eps / 2 + (1 - eps) / (1 + math.exp(-beta * d))
        total += math.log(p1 if c == 1 else 1 - p1)
    return total
```
hint: Compute `p1` with the lapse formula, then take the log of `p1` if the choice was 1 and of `1 - p1` otherwise.
solution: The lapse term mixes in a coin flip on a fraction $\epsilon$ of trials, so no choice can have probability below $\epsilon/2$; with $\Delta = 10$ and $\beta = 5$ the sigmoid is about $1$ and $p(1) \approx 0.9$. The second test shows that setting `eps = 0` recovers the plain softmax likelihood.

model:
```python
import math


def log_lik_perseverate(choices, deltas, beta, kappa):
    """Log-likelihood with a term favoring repetition of the last choice."""
    total = 0.0
    prev = 0
    for c, d in zip(choices, deltas):
        z = beta * d + kappa * prev
        p1 = 1.0 / (1.0 + math.exp(-z))
        total += math.log(p1 if c == 1 else 1.0 - p1)
        prev = 1 if c == 1 else -1
    return total
```
hint: Keep the previous choice coded as $+1$ or $-1$ (and $0$ before the first trial), add $\kappa$ times it to the logit, and update it after each trial.
solution: The previous choice is data, not a model prediction, so it is read from `choices` after each trial. A positive `kappa` makes repeating more likely; with `kappa = 0` the model reduces to the plain softmax.
