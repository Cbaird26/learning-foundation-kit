@article
A colleague sends you her spike times and asks for the tuning curve. Six months later a reviewer asks how the bins were chosen, and nobody, including you, can say which version of the script produced Figure 3. Analysis that cannot be rerun is analysis that cannot be checked. This lesson turns the pieces of the course into a **pipeline** that anyone can rerun and trust.

### Stages and parameters

A good pipeline has four stages, each a function with explicit inputs and outputs.

1. **Load** raw data from a file into a simple structure (a list of trials, each a dictionary).
2. **Validate**: check what must be true (spike times sorted, within the trial window, units consistent) and report problems instead of silently continuing.
3. **Analyze**: compute counts, rates, tuning curves, decoders, using parameters (window, bin width, number of iterations) read from **one dictionary** and never buried inside functions.
4. **Report**: return numbers with their uncertainty, the parameters used and a fingerprint of the data.

Functions should take their inputs as arguments and return results; they should not change global variables or their arguments. Name units in variable names (`t_stop_s`, `bin_ms`). A small function with a docstring and a few asserts is a test you can run after every change; the exercises in this course are exactly such tests.

### Loading and validating

Spike data are often stored as text, with one trial per line. Suppose the file has a header `trial,stimulus,spike_times` and lines like `3,90,0.05 0.15 0.25 0.95`, where the spike times (seconds) are separated by spaces and may be empty. A loader splits each line on commas, converts the fields and returns a dictionary per trial. Validation then checks each trial: the spike times should equal their sorted version and every time should satisfy $0 \le t < t_{\max}$.

```python
def run_analysis(trials, params):
    """Mean rate (Hz) and Fano factor of counts in [t_start, t_stop)."""
    t0, t1 = params["t_start"], params["t_stop"]
    counts = [sum(1 for t in tr["spikes"] if t0 <= t < t1) for tr in trials]
    n = len(counts)
    mean = sum(counts) / n
    var = sum((c - mean) ** 2 for c in counts) / (n - 1) if n > 1 else None
    return {
        "n_trials": n,
        "rate_hz": mean / (t1 - t0),
        "fano": None if var is None or mean == 0 else var / mean,
        "params": dict(params),
    }
```

For three trials with spike counts $3, 2, 4$ in $[0, 1)$, the function returns a mean rate of $3$ Hz and a Fano factor of $1/3$. The `dict(params)` copy stores the settings with the result.

### Randomness

Simulations and resampling use random numbers. A reproducible analysis either takes the random numbers as an argument (as we did for Poisson spikes) or creates a `random.Random(seed)` generator with a **recorded seed**. Tests of random functions should check properties (right length, values in range, same output from the same seed), not particular values, because different Python versions and implementations can produce different numbers from the same seed.

### Uncertainty by the bootstrap

Every result should carry an uncertainty. The **bootstrap** estimates it from the data: **resample trials** with replacement (draw $n$ trial indices from $n$ trials), recompute the statistic, repeat $B$ times, and read an interval from the spread. Here the resampling index lists are supplied, so the result is a deterministic function. For each index list the statistic is the mean rate of the chosen trials, $\sum_{i}\text{count}_i / (n\,T)$. Sort the $B$ rates $r_{(0)} \le \dots \le r_{(B-1)}$. For a confidence level `level`, let $k = \lfloor B(1 - \text{level})/2 + 10^{-9} \rfloor$ (the tiny term guards against floating-point error). The **percentile interval** is $[r_{(k)},\ r_{(B-1-k)}]$. Bootstrapping over trials respects the trial as the unit of replication; resampling bins or spikes within a trial would understate the uncertainty because they are not independent.

### What a report records

State each result with its uncertainty, the units, the number of trials and neurons, the parameters, the seed or random numbers, the data fingerprint (for example the number of spikes and a checksum), and the version of the code. State the limits: what the analysis does and does not show. For a population recording the same discipline applies: load the matrix, check it, compute the covariance, run PCA with a stated number of iterations and report the fraction of variance in the top component, together with the number of samples, since a dimensionality estimate from 20 time bins is not the same as one from 2000.

@example
title: A bootstrap interval by hand
problem: Spike counts $(4, 6, 8)$ from three trials over a window of $T = 1$ s give resampling index lists $[0,0,1]$, $[2,2,2]$, $[1,2,0]$, $[0,1,1]$, $[2,1,2]$. Compute the $60\%$ percentile interval for the mean rate.
step: Each resample's mean rate is the mean of the chosen counts divided by $T = 1$: $[0,0,1] \to (4+4+6)/3 = 4.67$; $[2,2,2] \to 8$; $[1,2,0] \to (6+8+4)/3 = 6$; $[0,1,1] \to (4+6+6)/3 = 5.33$; $[2,1,2] \to (8+6+8)/3 = 7.33$ Hz.
step: Sort them: $4.67, 5.33, 6, 7.33, 8$, so $B = 5$.
step: The index is $k = \lfloor 5(1 - 0.6)/2 + 10^{-9} \rfloor = \lfloor 1.000000001 \rfloor = 1$, so the interval runs from $r_{(1)}$ to $r_{(B - 1 - k)} = r_{(3)}$.
step: That gives $[5.33, 7.33]$ Hz. With only five resamples this is a rough interval; real analyses use thousands.
answer: $[5.33, 7.33]$ Hz.

@mistakes
- Hiding parameters inside functions (a bin width typed in three places), so that a change in one place silently makes the results inconsistent.
- Changing the input data in place (sorting or filtering a trial list that the caller still needs), which makes results depend on the order of calls.
- Testing random code against specific random values rather than properties, or not recording the seed.
- Bootstrapping spikes or bins instead of trials, which understates uncertainty when spikes within a trial are correlated.

```python
def parse_trials(text):
    """Parse the trial text format into a list of dictionaries."""
    trials = []
    for line in text.splitlines()[1:]:
        if not line.strip():
            continue
        parts = line.split(",")
        trials.append({
            "trial": int(parts[0].strip()),
            "stimulus": int(parts[1].strip()),
            "spikes": [float(x) for x in parts[2].split()],
        })
    return trials
```
hint: Skip the first line, split every other line on commas, convert the first two fields to integers, and split the third on whitespace.
solution: `str.split()` with no argument splits on any run of spaces and returns an empty list for an empty or all-space field, which handles trials with no spikes, and `int` accepts spaces around the digits. Skipping blank lines keeps a trailing newline from causing an error.

```python
def validate_trials(trials, t_max):
    """Report unsorted or out-of-range spike times, without changing data."""
    problems = []
    for tr in trials:
        spikes = tr["spikes"]
        if spikes != sorted(spikes):
            problems.append((tr["trial"], "unsorted"))
        if any(t < 0 or t >= t_max for t in spikes):
            problems.append((tr["trial"], "out_of_range"))
    return problems
```
hint: Compare each spike list with `sorted(spikes)` (which makes a copy), and test every time against the half-open range from 0 to `t_max`.
solution: `sorted` returns a new list, so the trials are not changed (calling `spikes.sort()` would modify the caller's data). A spike exactly at `t_max` is out of range because the analysis windows are half-open, and trial 4 has both problems, listed in the stated order.

```python
def bootstrap_rate_ci(counts, T, index_lists, level):
    """Percentile interval of resampled mean rates (Hz)."""
    rates = sorted(sum(counts[i] for i in idx) / (len(idx) * T) for idx in index_lists)
    b = len(rates)
    k = int(b * (1 - level) / 2 + 1e-9)
    return rates[k], rates[b - 1 - k]
```
hint: Compute one rate per index list, sort the list of rates, and read the entries at positions $k$ and $B - 1 - k$.
solution: The ten rates sorted are $4, 6, 10, 10, 10, 10, 12, 12, 14, 16$. With level 0.8, $k = 1$ gives $(6, 14)$; with 0.6, $k = 2$ gives $(10, 12)$; with level 1, $k = 0$ gives the full range $(4, 16)$.

```python
import math


def population_summary(text, iters):
    """Fraction of variance in PC1 for a recording given as comma-separated rows."""
    X = [[float(x) for x in line.split(",")] for line in text.splitlines() if line.strip()]
    n, d = len(X), len(X[0])
    mean = [sum(row[j] for row in X) / n for j in range(d)]
    C = [[sum((row[i] - mean[i]) * (row[j] - mean[j]) for row in X) / (n - 1)
          for j in range(d)] for i in range(d)]
    trace = sum(C[i][i] for i in range(d))
    result = {"n_bins": n, "n_neurons": d, "pc1_fraction": 0.0}
    if trace == 0:
        return result
    v = [float(j + 1) for j in range(d)]
    for _ in range(iters):
        w = [sum(C[i][j] * v[j] for j in range(d)) for i in range(d)]
        norm = math.sqrt(sum(x * x for x in w))
        v = [x / norm for x in w]
    lam = sum(v[i] * C[i][j] * v[j] for i in range(d) for j in range(d))
    result["pc1_fraction"] = lam / trace
    return result
```
hint: Parse the rows into numbers, center the columns, build the covariance with divisor $n - 1$, run power iteration, and divide the Rayleigh quotient by the trace.
solution: A constant recording has zero variance, so the trace is 0 and the fraction is defined as 0.0 before any division. In the three-neuron test the neurons do not move together, so PC1 explains only about $52\%$ of the variance (the blank line is skipped, leaving five bins); the same helper functions would give the result for a real recording with hundreds of neurons, with a larger `iters` when the top eigenvalues are close.
