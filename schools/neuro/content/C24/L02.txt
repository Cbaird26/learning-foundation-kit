@article
A neuron fires a different number of spikes on every repetition of the same stimulus, and a single raster row is too sparse to show how its firing changes in time. Average over trials, and the pattern appears. The **peristimulus time histogram** (PSTH) is the oldest and still the most common way to do this: align all trials to the stimulus, count the spikes in time bins, and divide by what you counted over.

### Conventions

In this lesson spike times are in **milliseconds** (ms), measured from the start of the analysis window. Choose a start $t_s$, a stop $t_e$ and a **bin width** $w$ (ms) that divides $t_e - t_s$. Bin $k$ (counting from 0) is the half-open interval $[t_s + k w,\ t_s + (k+1) w)$. A spike exactly on an internal edge belongs to the bin that starts there, and a spike exactly at $t_e$ (or later, or before $t_s$) is ignored. The bin index of a spike is therefore $\lfloor (t - t_s)/w \rfloor$; with integer milliseconds, integer division `(t - t_s) // w` computes it exactly.

With $N$ trials and total count $c_k$ in bin $k$, the PSTH is

$$r_k = \frac{c_k}{N \, w/1000} \quad \text{(Hz)},$$

the mean rate in the bin, since $w/1000$ is the bin width in seconds. Take three trials in $[0, 400)$ ms with $w = 100$ ms: trial 1 at $30, 80, 120, 150, 310$; trial 2 at $50, 110, 130, 340, 360$; trial 3 at $90, 100, 140, 180, 330$. The spike at 100 ms starts bin 1. The counts are $4, 7, 0, 4$, so $r = (13.3,\ 23.3,\ 0,\ 13.3)$ Hz.

```python
def psth(trials, t_start, t_stop, bin_ms):
    """PSTH in Hz; spike times in ms, half-open bins."""
    n_bins = (t_stop - t_start) // bin_ms
    counts = [0] * n_bins
    for spikes in trials:
        for t in spikes:
            if t_start <= t < t_stop:
                counts[(t - t_start) // bin_ms] += 1
    return [c / (len(trials) * bin_ms / 1000) for c in counts]
```

### Bin width and the bias-variance trade-off

The bin width is a choice, not a fact about the neuron. Narrow bins give fine timing but few spikes per bin, so $r_k$ is noisy. Wide bins give stable estimates but blur real changes. If counts in a bin are roughly Poisson, the relative standard error of $r_k$ is about $1/\sqrt{c_k}$.

### Smoothing with a kernel

Instead of one rigid bin choice, **smooth** the PSTH by replacing each value with a weighted average of its neighbors. A **kernel** $g_j$ for offsets $j = -m, \dots, m$ (in bins) is **normalized** if $\sum_j g_j = 1$. The smoothed value is

$$\tilde r_k = \sum_{j=-m}^{m} g_j \, r_{k+j},$$

with values outside the list treated as 0 (**zero padding**), so values near the ends are pulled down. Two common kernels: the **boxcar** of odd width $2m+1$ with $g_j = 1/(2m+1)$, and the **Gaussian** with standard deviation $\sigma$ bins, $g_j \propto e^{-j^2/(2\sigma^2)}$ for $|j| \le m$, divided by the sum of these weights. For $\sigma = 1$ and $m = 2$ the weights are $0.054, 0.244, 0.403, 0.244, 0.054$. Normalization keeps the area under the PSTH (apart from the edges) the same, so a smoothed peak is lower and wider but contains the same spikes. A larger $\sigma$ reduces noise but biases the estimated rate toward the neighbors, so a brief response looks weaker and longer than it was.

```python
import math


def gaussian_kernel(sigma, half):
    """Weights for offsets -half..half, normalized to sum to 1."""
    w = [math.exp(-k * k / (2 * sigma * sigma)) for k in range(-half, half + 1)]
    total = sum(w)
    return [x / total for x in w]


def smooth(x, kernel):
    """Zero-padded convolution with an odd-length kernel."""
    half = len(kernel) // 2
    n = len(x)
    out = []
    for i in range(n):
        acc = 0.0
        for j, g in enumerate(kernel):
            k = i + j - half
            if 0 <= k < n:
                acc += g * x[k]
        out.append(acc)
    return out
```

Smoothing the single spike-like input `[0, 0, 9, 0, 0]` with the kernel above gives about `[0.49, 2.20, 3.62, 2.20, 0.49]`; the total, 9, is kept except for the weight that fell off the ends.

### Uncertainty across trials

Each trial has its own rate $c_{jk}/(w/1000)$ in bin $k$. The **standard error of the mean** (SEM) is the sample standard deviation across trials (divisor $N - 1$) divided by $\sqrt N$. A PSTH without error bars cannot tell a real peak from a fluke of a few trials. NumPy computes the counts in one line with `numpy.histogram` over concatenated spikes; the loop above is the same operation, except that `numpy.histogram` also counts a spike exactly at the last edge in the last bin.

### Latency

The **response latency** is often defined as the start of the first bin whose rate reaches a criterion, for instance the baseline mean plus a few standard deviations. It depends on the bin width, so report both.

@example
title: A PSTH and one smoothed bin
problem: Four trials have spikes (ms) at $[15, 42, 47]$, $[44, 48, 90]$, $[10, 45, 46, 49]$ and $[88]$ in $[0, 100)$ with 20 ms bins. Compute the whole PSTH, then the boxcar-smoothed value (width 3, zero padded) of the last bin.
step: Count the spikes per bin over all trials. Bin $[0, 20)$ has $15$ and $10$; bin $[20, 40)$ is empty; bin $[40, 60)$ has $42, 47, 44, 48, 45, 46, 49$; bin $[60, 80)$ is empty; bin $[80, 100)$ has $90$ and $88$. The counts are $2, 0, 7, 0, 2$.
step: Convert to rates: the observation time per bin is $4 \times 0.020 = 0.08$ s, so $r = (25,\ 0,\ 87.5,\ 0,\ 25)$ Hz.
step: Boxcar of width 3 on the last bin uses its left neighbor (0), the bin itself (25) and one zero for the missing right neighbor: $(0 + 25 + 0)/3 = 8.33$ Hz.
step: Note the edge effect: the unsmoothed value 25 fell to 8.33 partly because of zero padding. A reader should know that smoothed values at the ends of the window are underestimates.
answer: The PSTH is $(25, 0, 87.5, 0, 25)$ Hz and the smoothed last bin is $8.33$ Hz.

@mistakes
- Dividing counts by the number of trials but not by the bin width (or using the width in ms), which gives spikes per bin rather than hertz.
- Using a kernel that does not sum to 1, so the smoothed PSTH has the wrong overall rate.
- Reading a smoothed PSTH's latency and width as properties of the neuron when they partly come from the kernel.
- Letting a spike exactly at the stop time create an extra bin or be counted twice.

model:
```python
import math


def psth_sem(trials, t_start, t_stop, bin_ms):
    """Mean rate (Hz) and its standard error across trials, per bin."""
    n_bins = (t_stop - t_start) // bin_ms
    n = len(trials)
    per_trial = []
    for spikes in trials:
        counts = [0] * n_bins
        for t in spikes:
            if t_start <= t < t_stop:
                counts[(t - t_start) // bin_ms] += 1
        per_trial.append([c / (bin_ms / 1000) for c in counts])
    rates, sems = [], []
    for k in range(n_bins):
        vals = [row[k] for row in per_trial]
        mean = sum(vals) / n
        rates.append(mean)
        if n > 1:
            var = sum((v - mean) ** 2 for v in vals) / (n - 1)
            sems.append(math.sqrt(var / n))
        else:
            sems.append(0.0)
    return rates, sems
```
hint: First build a per-trial rate for each bin; then, for each bin, take the mean and the sample standard deviation across trials.
solution: The mean across trials of per-trial rates equals the pooled PSTH, and the SEM uses the divisor $N - 1$. The third test has one trial, where a sample variance is undefined, so the function returns 0.0; the fourth shows that spikes at or after the stop time are dropped.

model:
```python
def smooth_boxcar(x, width):
    """Moving average of odd width with zero padding at the ends."""
    half = width // 2
    n = len(x)
    out = []
    for i in range(n):
        total = 0.0
        for k in range(i - half, i + half + 1):
            if 0 <= k < n:
                total += x[k]
        out.append(total / width)
    return out
```
hint: For output position $i$, add the values from $i - \text{half}$ to $i + \text{half}$ that exist, and always divide by `width`.
solution: Dividing by the full width, not by the number of values that exist, is what zero padding means, so the ends are pulled down (the fifth-sample test gives 3 and 4 at the edges, not 5). A width of 1 returns the input.

```python
def response_latency(rates, t_start, bin_ms, criterion):
    """Start (ms) of the first bin with rate >= criterion, or None."""
    for k, r in enumerate(rates):
        if r >= criterion:
            return t_start + k * bin_ms
    return None
```
hint: Scan the bins in order and stop at the first one that reaches the criterion; the comparison includes equality.
solution: A criterion equal to a bin's rate counts (the first test), so the comparison is `>=`. The bin's start time is the start of the window plus its index times the width; the result depends on the bin width.
