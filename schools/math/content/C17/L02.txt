@article
Last week, $(1 - \cos x)/x^2$ failed near $x = 0$ and a rewritten formula succeeded. So was the problem hard, or the first formula bad? The answer matters: a hard problem defeats every algorithm, while a bad algorithm can be replaced. Numerical analysis separates the two ideas.

### Conditioning: how sensitive is the problem?

Let $f$ be a function and suppose the input $x$ is replaced by a nearby $\tilde x$. The **relative condition number** measures the worst ratio of relative output change to relative input change.

**Theorem 1.** Let $f$ be differentiable at $x$, with $x \ne 0$ and $f(x) \ne 0$. Then
$$\lim_{\tilde x \to x} \frac{|f(\tilde x) - f(x)|/|f(x)|}{|\tilde x - x|/|x|} = \kappa_f(x) := \left| \frac{x f'(x)}{f(x)} \right|.$$

*Proof.* For $\tilde x \ne x$ the quotient equals $\left|\dfrac{f(\tilde x) - f(x)}{\tilde x - x}\right| \dfrac{|x|}{|f(x)|}$. As $\tilde x \to x$ the first factor tends to $|f'(x)|$ by the definition of the derivative. $\blacksquare$

A problem with $\kappa_f(x)$ near $1$ is **well conditioned**; one with $\kappa_f(x) \gg 1$ is **ill conditioned**. Examples: $f(x) = \sqrt x$ has $\kappa = 1/2$ everywhere; $f(x) = e^x$ has $\kappa = |x|$; $f(x) = x - c$ has $\kappa = |x|/|x - c|$, which blows up as $x \to c$. The last one is the reason for Theorem 2 of Week 1: subtracting nearby numbers is an ill-conditioned problem, and no algorithm can repair it. Cancellation is harmless only when the nearby numbers are exact data.

### Stability: how good is the algorithm?

An algorithm computes $\tilde f(x)$ instead of $f(x)$. It is **backward stable** if $\tilde f(x) = f(\tilde x)$ for some $\tilde x$ with $|\tilde x - x|/|x| \le C u$ where $C$ is a modest constant: the computed answer is the exact answer to a slightly perturbed question. The floating-point subtraction is backward stable: $\mathrm{fl}(x - y) = (x - y)(1 + \delta) = x(1+\delta) - y(1+\delta)$ is the exact difference of inputs perturbed by relative amount $|\delta| \le u$.

**Theorem 2 (backward stability and forward error).** Suppose $f$ is differentiable at $x$ with $x \ne 0$, $f(x) \ne 0$, and $\tilde f(x) = f(\tilde x)$ with $|\tilde x - x|/|x| \le Cu$. Then
$$\frac{|\tilde f(x) - f(x)|}{|f(x)|} \le \bigl(\kappa_f(x) + \rho\bigr)\, Cu, \qquad \rho \to 0 \text{ as } u \to 0.$$

*Proof.* By Theorem 1 the ratio of relative changes tends to $\kappa_f(x)$ as $\tilde x \to x$, and $\tilde x \to x$ when $u \to 0$. So for small $u$ the ratio is at most $\kappa_f(x) + \rho$ with $\rho \to 0$. Multiply by $|\tilde x - x|/|x| \le Cu$. $\blacksquare$

In words: **forward error $\lesssim$ condition number $\times$ backward error**. A backward stable algorithm is as accurate as the problem permits; an ill-conditioned problem still gives inaccurate answers. For $f(x) = 1 - \cos x$ at small $x$ we get $\kappa \approx 2$, a well-conditioned problem, so the naive formula's failure was an unstable algorithm, fixed by the rewrite.

### An unstable recurrence

Let $I_n = \int_0^1 x^n e^{x-1}\,dx$. Integration by parts gives $I_n = 1 - n I_{n-1}$ for $n \ge 1$, with $I_0 = 1 - 1/e$. Since $0 < e^{x-1} \le 1$ on $[0,1]$, we have $0 < I_n \le \int_0^1 x^n dx = 1/(n+1)$. The forward recurrence multiplies an error $e_{n-1}$ by $-n$:
$$e_n = -n\, e_{n-1}, \qquad |e_n| = n!\,|e_0|.$$
An initial rounding error near $10^{-16}$ becomes about $20! \cdot 10^{-16} \approx 240$ at $n = 20$. Run in double precision, the recurrence gives a negative number of size about $30$ for $I_{20}$, impossible for a positive integral below $1/21$. Solve the recurrence backward: $I_{n-1} = (1 - I_n)/n$. Now $e_{n-1} = -e_n/n$, so $|e_{n-1}| \le |e_n|/n$ shrinks at every step, and even the crude start $I_N = 0$ (true error at most $1/(N+1)$) gives an excellent value after enough steps:

```python
import math


def forward(n):
    x = 1 - 1 / math.e
    for k in range(1, n + 1):
        x = 1 - k * x
    return x


def backward(n, N=40):
    x = 0.0                       # crude guess for I_N
    for k in range(N, n, -1):
        x = (1 - x) / k
    return x


print(forward(20) < 0)                      # True: impossible
print(abs(backward(0) - (1 - 1 / math.e)) < 1e-12)   # True
```

The problem of computing $I_n$ is well conditioned; the forward algorithm is unstable and the backward one is stable. As always, the computations are evidence; the error recurrences are the proof.

@example
title: A well-conditioned problem with a bad formula
problem: Compute the relative condition number of $f(x) = 1 - \cos x$ at $x = 10^{-3}$.
step: Differentiate: $f'(x) = \sin x$, so $\kappa_f(x) = \left|\dfrac{x \sin x}{1 - \cos x}\right|$.
step: Use the identities $1 - \cos x = 2\sin^2(x/2)$ and $\sin x = 2\sin(x/2)\cos(x/2)$: $\kappa_f(x) = \dfrac{2x \sin(x/2)\cos(x/2)}{2 \sin^2(x/2)} = \dfrac{x \cos(x/2)}{\sin(x/2)}$.
step: For small $x$, $\sin(x/2) \approx x/2$ and $\cos(x/2) \approx 1$, so $\kappa_f(x) \approx 2$. At $x = 10^{-3}$ the exact value is $x\cos(x/2)/\sin(x/2) \approx 1.9999998$.
step: The problem is well conditioned, so an accurate algorithm exists (use $2\sin^2(x/2)$), and the failure of the direct subtraction is a stability failure of that algorithm.
answer: $\kappa_f(10^{-3}) \approx 2$.

@example
title: An ill-conditioned subtraction
problem: Find the relative condition number of $f(x) = x - 1$ at $x = 1.0001$ and say what it means for input data with relative error $10^{-12}$.
step: Here $f'(x) = 1$, so $\kappa_f(x) = |x|/|x - 1|$.
step: At $x = 1.0001$: $\kappa_f = 1.0001/0.0001 = 10001$.
step: By Theorem 1, a relative input error of $10^{-12}$ can become a relative output error of about $10001 \cdot 10^{-12} \approx 10^{-8}$, so about four digits are lost to the problem itself, whatever algorithm is used.
answer: $\kappa_f = 10001$; a $10^{-12}$ input error can become about $10^{-8}$.

@mistakes
- Calling an algorithm unstable because its answer is inaccurate: if the problem is ill conditioned, even a backward stable algorithm gives an inaccurate answer.
- Calling a problem ill conditioned because one formula for it fails: first compute $\kappa_f$; $1 - \cos x$ is well conditioned near $0$.
- Using the absolute condition number $|f'(x)|$ where relative errors are meant: the relative one is $|x f'(x)/f(x)|$.
- Trusting the output of a recurrence because it looks smooth: the forward recurrence for $I_n$ gives plausible values for the first dozen steps before the error takes over.

```python
def cond_estimate(f, x, h=1e-6):
    """Estimate |x f'(x) / f(x)| with a central difference."""
    derivative = (f(x + h) - f(x - h)) / (2 * h)
    return abs(x * derivative / f(x))
```
hint: Compute the central difference first, then form $|x \cdot f'(x)/f(x)|$ and take the absolute value of the whole quotient.
solution: Theorem 1 says the condition number is $|x f'(x)/f(x)|$; replace $f'(x)$ by the central difference, whose error is $O(h^2)$ plus rounding of order $u/h$. Taking the absolute value at the end handles negative $x$ and negative $f(x)$.

model:
```python
def backward_J_tol(n, tol):
    """Run the stable downward recurrence from an automatically chosen start."""
    N = n + 1
    while 1 / (5 * (N + 1)) / 5 ** (N - n) > tol:
        N += 1
    x = 0.0
    for k in range(N, n, -1):
        x = (1 / k - x) / 5
    return x, N
```
hint: Increase `N` from `n + 1` until the bound `1 / (5 * (N + 1)) / 5 ** (N - n)` is at most `tol`, then run the downward loop.
solution: Each downward step divides the error by $5$, so after $N - n$ steps the initial error bound $1/(5(N+1))$ has shrunk by $5^{N-n}$. The loop picks the smallest such $N$ (the condition is checked with `>`, so a bound equal to `tol` is accepted). The forward recurrence $J_n = 1/n - 5J_{n-1}$ would multiply errors by $5$ per step instead, so a tolerance cannot be reached by running upward.

The formula "mean of squares minus square of the mean" suffers cancellation for data with a large mean and a small spread. Write `variance(data)` for a nonempty list of floats that returns the population variance using two passes (first the mean, then the mean of squared deviations), with explicit loops. For example, `variance([1.0, 2.0, 3.0])` is about `0.6667`.
starter:
```python
def variance(data):
    m = len(data)
    mean_sq = 0.0
    total = 0.0
    for d in data:
        total += d
        mean_sq += d * d
    return mean_sq / m - (total / m) ** 2
```

model:
```python
def variance(data):
    """Population variance by the two-pass formula."""
    m = len(data)
    mean = 0.0
    for d in data:
        mean += d
    mean /= m
    total = 0.0
    for d in data:
        total += (d - mean) ** 2
    return total / m
```
hint: Subtract the mean before squaring: deviations are small numbers, so nothing large cancels.
solution: In the one-pass formula both terms are near $10^{18}$ and their difference is near $1$, so the rounding errors of the large terms become the answer. In the two-pass version the deviations $d_i - \bar d$ are computed exactly or nearly so (nearby numbers subtract exactly), and the squares are small and positive.
