@article
Two jugs hold $14$ and $21$ liters. By filling, emptying and pouring from one to the other, can you ever measure exactly $1$ liter? With jugs of $8$ and $15$ liters you can: fill the $8$ and pour it into the $15$, fill the $8$ again and pour until the $15$ is full, and one liter is left in the $8$. Why does one pair work and the other not? Every amount you can measure is an integer combination $14x + 21y$ or $8x + 15y$, and the question becomes: which integers are combinations of two given integers?

### Divisibility and the division algorithm

For integers $a$ and $b$ we write $a \mid b$ if $b = ak$ for some integer $k$. If $a \mid b$ and $a \mid c$, then $a \mid bx + cy$ for all integers $x, y$ (write $b = ak$, $c = al$ and factor out $a$).

**Theorem 1 (division algorithm).** Let $a, b$ be integers with $b > 0$. There are unique integers $q, r$ with $a = qb + r$ and $0 \le r < b$.

*Proof.* Existence: the set $T = \{a - kb : k \in \mathbb{Z},\ a - kb \ge 0\}$ is nonempty (take $k = -|a|$, so $a - kb = a + |a|b \ge 0$). By well-ordering it has a least element $r = a - qb$. If $r \ge b$, then $r - b = a - (q+1)b \in T$ is smaller than $r$, a contradiction, so $0 \le r < b$. Uniqueness: if $qb + r = q'b + r'$ with both remainders in $[0, b)$, then $b(q - q') = r' - r$ has absolute value less than $b$, so it is $0$; hence $q = q'$ and $r = r'$. $\blacksquare$

### The greatest common divisor

For integers $a, b$ not both zero, $\gcd(a, b)$ is the largest integer dividing both.

**Lemma 2.** If $a, b, q$ are integers, then $\gcd(a, b) = \gcd(b, a - qb)$ (when $(a,b) \ne (0,0)$ and $(b, a - qb) \ne (0,0)$, which holds if $b \neq 0$).

*Proof.* Any common divisor of $a$ and $b$ divides $a - qb$, so it is a common divisor of $b$ and $a - qb$. Conversely, any common divisor of $b$ and $a - qb$ divides $(a - qb) + qb = a$. The two pairs have the same set of common divisors, hence the same largest one. $\blacksquare$

### The Euclidean algorithm

Euclid's *Elements* (about 300 BCE) describes the following repeated division. To find $\gcd(a, b)$ with $a \ge b > 0$, divide, replace the pair $(a, b)$ by $(b, a \bmod b)$, and stop when the second entry is $0$:

```python
def gcd(a, b):
    """Greatest common divisor of integers a, b >= 0, not both 0."""
    while b != 0:
        a, b = b, a % b
    return a


print(gcd(1071, 462))
```

This prints `21`: $1071 = 2\cdot 462 + 147$, $462 = 3 \cdot 147 + 21$, $147 = 7 \cdot 21$.

*Correctness.* The loop terminates because the second entry is a nonnegative integer that decreases strictly (by Theorem 1, $a \bmod b < b$). By Lemma 2 with $q = \lfloor a/b \rfloor$ every pass keeps $\gcd(a, b)$ unchanged. When $b = 0$ we have $\gcd(a, 0) = a$. So the returned value is the gcd of the original pair. $\blacksquare$

*Cost.* Lamé's theorem (stated here without proof) says the number of divisions is at most five times the number of decimal digits of the smaller number; consecutive Fibonacci numbers are the worst case.

### Bézout's identity

**Theorem 3 (Bézout).** Let $a, b$ be integers, not both zero, and $g = \gcd(a, b)$. Then there are integers $x, y$ with $ax + by = g$. Moreover $g$ is the smallest positive integer of the form $ax + by$.

*Proof.* Let $S = \{ax + by : x, y \in \mathbb{Z}\}$. It contains a positive element ($a^2 + b^2 > 0$), so it has a least positive element $d = ax_0 + by_0$. Divide: $a = qd + r$ with $0 \le r < d$. Then $r = a - q(ax_0 + by_0) \in S$, and $r < d$, so $r$ is not positive, hence $r = 0$ and $d \mid a$. The same argument gives $d \mid b$. So $d$ is a common divisor and $d \le g$. Conversely $g \mid a$ and $g \mid b$ give $g \mid ax_0 + by_0 = d$, so $g \le d$. Hence $d = g$. $\blacksquare$

**Corollary 4.** The equation $ax + by = c$ has an integer solution if and only if $\gcd(a, b) \mid c$.

For the jugs: $\gcd(14, 21) = 7$ and $7 \nmid 1$, so $1$ liter is impossible; $\gcd(8, 15) = 1$, and $8 \cdot 2 - 15 = 1$.

### The extended Euclidean algorithm

Bézout's proof is not constructive. Running the Euclidean algorithm while tracking coefficients is:

```python
def ext_gcd(a, b):
    """Return (g, x, y) with g = gcd(a, b) = a*x + b*y, for a, b >= 0."""
    x0, y0, x1, y1 = 1, 0, 0, 1   # a = a0*x0 + b0*y0, b = a0*x1 + b0*y1
    while b != 0:
        q = a // b
        a, b = b, a - q * b
        x0, x1 = x1, x0 - q * x1
        y0, y1 = y1, y0 - q * y1
    return a, x0, y0


print(ext_gcd(1071, 462))
```

It prints `(21, -3, 7)`, and indeed $1071 \cdot (-3) + 462 \cdot 7 = 21$.

**Theorem 5.** For integers $a_0, b_0 \ge 0$ not both zero, `ext_gcd` returns $(g, x, y)$ with $g = \gcd(a_0, b_0) = a_0 x + b_0 y$.

*Proof.* We show the **loop invariant**: at the top of every pass, $a = a_0 x_0 + b_0 y_0$ and $b = a_0 x_1 + b_0 y_1$. Before the first pass, $a = a_0 = a_0\cdot 1 + b_0 \cdot 0$ and $b = b_0 = a_0 \cdot 0 + b_0 \cdot 1$. Suppose the invariant holds at the top of a pass. The new first entry is the old $b$, matching the new $(x_0, y_0) = (x_1, y_1)$. The new second entry is $a - qb = a_0(x_0 - qx_1) + b_0(y_0 - qy_1)$, matching the new $(x_1, y_1)$. So the invariant persists. The pair $(a, b)$ evolves exactly as in `gcd`, so the loop ends with $a = \gcd(a_0, b_0)$, and the invariant gives $a = a_0 x_0 + b_0 y_0$. $\blacksquare$

A computer run on many pairs is evidence; the invariant is the proof.

@example
title: A Euclidean algorithm trace
problem: Compute $\gcd(2024, 748)$ and say how many divisions the algorithm performs.
step: Divide $2024$ by $748$: $2024 = 2 \cdot 748 + 528$. Replace the pair by $(748, 528)$.
step: Divide again: $748 = 1 \cdot 528 + 220$, then $528 = 2 \cdot 220 + 88$, then $220 = 2 \cdot 88 + 44$.
step: Divide $88$ by $44$: $88 = 2 \cdot 44 + 0$. The remainder is $0$, so the algorithm stops.
step: By Lemma 2 each pass keeps the gcd, so $\gcd(2024, 748)$ equals the last nonzero remainder, $44$. There were $5$ divisions.
answer: $\gcd(2024, 748) = 44$, found in $5$ divisions.

@example
title: Writing the gcd as a combination
problem: Find integers $x, y$ with $391x + 299y = \gcd(391, 299)$.
step: Run the algorithm and keep the quotients: $391 = 1 \cdot 299 + 92$, $299 = 3 \cdot 92 + 23$, $92 = 4 \cdot 23 + 0$. So $\gcd = 23$.
step: Solve the second-to-last equation for the gcd: $23 = 299 - 3 \cdot 92$.
step: Replace $92$ using the first equation, $92 = 391 - 299$: $23 = 299 - 3(391 - 299)$.
step: Collect terms: $23 = 4 \cdot 299 - 3 \cdot 391$, so $x = -3$ and $y = 4$.
step: Check: $391 \cdot (-3) + 299 \cdot 4 = -1173 + 1196 = 23$.
answer: $x = -3$, $y = 4$ (one of infinitely many solutions).

@mistakes
- Stopping at the last remainder instead of the last nonzero remainder: the gcd is the divisor at the step whose remainder is $0$.
- Thinking the Bézout coefficients are unique. If $ax + by = g$, then $a(x + tb/g) + b(y - ta/g) = g$ for every integer $t$.
- Reading Corollary 4 as "$ax + by = c$ is solvable whenever $\gcd(a,b) \le c$". It needs $\gcd(a, b) \mid c$: $6x + 9y = 4$ has no integer solution although $3 < 4$.
- Treating a test on many pairs as the proof of correctness. The loop invariant is what proves the algorithm.

```python
def solve_linear(a, b, c):
    """Smallest nonnegative x (and matching y) with a*x + b*y = c."""
    x0, y0, x1, y1 = 1, 0, 0, 1
    r0, r1 = a, b
    while r1 != 0:
        q = r0 // r1
        r0, r1 = r1, r0 - q * r1
        x0, x1 = x1, x0 - q * x1
        y0, y1 = y1, y0 - q * y1
    g = r0
    if c % g != 0:
        return None
    step = b // g
    x = (x0 * (c // g)) % step
    return x, (c - a * x) // b
```
hint: Corollary 4 tells you when a solution exists; scale the Bézout coefficients by $c / g$.
hint: All solutions have the form $x = x_1 + t\,b/g$, so reduce $x$ modulo $b/g$ and recover $y$ from the equation.
solution: Compute $g$ and Bézout coefficients with $ax_0 + by_0 = g$. If $g \nmid c$ there is no solution (Corollary 4). Otherwise $x = x_0 c / g$ is a solution, and adding multiples of $b/g$ gives all others, so reducing modulo $b/g$ gives the unique one in the range. Then $y = (c - ax)/b$ is an integer because $ax + by = c$ has a solution with that $x$.

prompt: Which of these statements hold for all positive integers $a, b, c$?

model:
```python
def binary_gcd(a, b):
    """Binary gcd: only subtraction, parity tests and halving."""
    if a == 0:
        return b
    if b == 0:
        return a
    shift = 0
    while a % 2 == 0 and b % 2 == 0:
        a //= 2
        b //= 2
        shift += 1
    while a % 2 == 0:
        a //= 2
    while b != 0:
        while b % 2 == 0:
            b //= 2
        if a > b:
            a, b = b, a
        b -= a
    return a * 2 ** shift
```
hint: First pull out the common factors of $2$ and count them; then remove factors of $2$ from the one that is even and loop on the odd pair.
solution: After removing common twos, $a$ is odd, and a factor $2$ in $b$ cannot be shared with $a$, so it can be dropped without changing the gcd. For two odd numbers $\gcd(a, b) = \gcd(a, b - a)$ by Lemma 2, and $b - a$ is even, so each pass shrinks $a + b$; the loop ends when $b = 0$ and $a$ is the odd part of the gcd. Multiplying by the saved power of $2$ restores it.
