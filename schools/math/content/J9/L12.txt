@article
A beginner often opens the editor and starts typing. A better habit is to **plan first**. Ten minutes of planning saves an hour of debugging. Here is a plan you can use for any program, shown on this week's task: *analyze a list of test scores*.

### 1. Say what the program does

Write one or two sentences, and name the **inputs** and **outputs**. For example: "The program takes a list of scores. It reports the lowest score, the highest score, the average, and how many students passed (a score of 60 or more)."

### 2. Work an example by hand

Pick a small input, such as `[50, 90, 70]`, and work out the answer yourself: lowest `50`, highest `90`, average `70.0`, passing `2`. This is also your first test. If you cannot work out the answer by hand, you do not yet understand the problem.

### 3. Split it into functions

Each job becomes a function with a clear name, parameters and return value:

- `count_passing(scores, mark)` returns how many scores are at least `mark`.
- `average(scores)` returns the mean, or `0` for an empty list.
- `summary(scores)` uses the others and returns a text report.

Small functions are easy to test alone, and you can reuse them. A good function does **one thing** and returns its answer instead of printing it.

### 4. Write the plan as pseudocode

**Pseudocode** is a plan in plain words, close to code but not code:

```text
count_passing(scores, mark):
    set count to 0
    for each score in scores:
        if score >= mark: add 1 to count
    return count
```

### 5. Build and test one piece at a time

Write the first function and test it with its hand-worked example **before** you write the second. When something fails, you know the bug is in the code you just wrote.

```python
def count_passing(scores, mark):
    count = 0
    for s in scores:
        if s >= mark:
            count += 1
    return count

print(count_passing([50, 90, 70], 60))   # 2
```

### 6. Test the edge cases

Try the unusual inputs: an empty list, a list with one item, equal values, and values exactly at a boundary such as a score of exactly `60`. Many bugs hide there.

### 7. Keep input and output at the edges

Put the reading of input and the printing in a small part of the program, such as a `main` function, and keep the calculation in functions that take values and return values. Then the calculation functions are easy to test with `assert`, as you do on this site.

@example
title: Planning a counting program
problem: Plan a program that reads a list of temperatures and says how many days were freezing (below 0).
step: Say it in words. Input: a list of numbers. Output: a count of the numbers below `0`.
step: Work an example by hand: `[3, -2, 0, -7]` has two freezing days, `-2` and `-7`. Zero is not below zero.
step: Choose the function: `count_freezing(temps)` returns a count, and the plan is a counter that starts at `0` and adds `1` for each `t < 0`.
step: Write it and test the hand example and the edge cases:

```python
def count_freezing(temps):
    count = 0
    for t in temps:
        if t < 0:
            count += 1
    return count

print(count_freezing([3, -2, 0, -7]))   # 2
print(count_freezing([]))               # 0
```

@example
title: Combining small functions
problem: Use `average` and `count_passing` to report on a class: print the average and the number of students who passed.
step: Suppose `average(scores)` and `count_passing(scores, mark)` already work and are tested.
step: Write a function that only combines them and returns text:

```python
def report(scores):
    avg = average(scores)
    passed = count_passing(scores, 60)
    return f"average {avg:.1f}, passed {passed}"
```
step: For `[50, 90, 70]` the average is `70.0` and two students passed, so the report is `average 70.0, passed 2`.

@mistakes
- Starting to type code before you know what the answer should be for a small example.
- Writing one very long program with no functions, which is hard to test and hard to fix.
- Writing the whole program before running any of it, so that errors pile up.
- Testing only typical inputs and skipping the empty list, the single item and the boundary values.

def count_passing(scores, mark):

@practice code
prompt: Write `curve(scores, bonus)` that returns a **new list** in which every score has `bonus` added, but no score is above `100`. The original list must not change. For example `curve([70, 95], 10)` returns `[80, 100]`.
starter:
```python
def curve(scores, bonus):
    pass
```
tests:
```python
data = [70, 95]
assert curve(data, 10) == [80, 100]
assert data == [70, 95]
assert curve([], 5) == []
assert curve([100, 99], 0) == [100, 99]
assert curve([90, 50], 20) == [100, 70]
```
model:
```python
def curve(scores, bonus):
    result = []
    for s in scores:
        new_score = s + bonus
        if new_score > 100:
            new_score = 100
        result.append(new_score)
    return result
```
hint: Build a new list with `append`, one score at a time.
hint: After adding the bonus, replace any value above 100 with 100.
solution: For each score, compute `s + bonus`, cap it at `100`, and append it to a new list. Because the function builds a new list instead of changing `scores`, the caller's list stays as it was.

@practice code
prompt: Write `summary(scores)` for a non-empty list of numbers. It returns the text `low=L high=H avg=A`, where `L` is the lowest score, `H` is the highest and `A` is the average shown with one decimal place. For `[50, 90, 70]` it returns `low=50 high=90 avg=70.0`.
starter:
```python
def summary(scores):
    pass
```
tests:
```python
assert summary([50, 90, 70]) == "low=50 high=90 avg=70.0"
assert summary([80]) == "low=80 high=80 avg=80.0"
assert summary([60, 61]) == "low=60 high=61 avg=60.5"
assert summary([-5, 5, 0]) == "low=-5 high=5 avg=0.0"
```
model:
```python
def summary(scores):
    low = min(scores)
    high = max(scores)
    avg = sum(scores) / len(scores)
    return f"low={low} high={high} avg={avg:.1f}"
```
hint: The built-ins `min`, `max`, `sum` and `len` give you all the numbers you need.
hint: Format the average inside the f-string with `:.1f`. Return the text; do not print it.
solution: Compute the three values with `min`, `max` and `sum(scores) / len(scores)`, and build the text with an f-string. The format `:.1f` makes the average show one decimal place, such as `70.0`.

@quiz code
prompt: Write `percent_passing(scores, mark)` that returns the percentage of scores that are at least `mark`, as a number (`100 * passing / total`). For an empty list return `0`.
starter:
```python
def percent_passing(scores, mark):
    pass
```
tests:
```python
assert percent_passing([50, 60, 70, 80], 60) == 75
assert percent_passing([], 60) == 0
assert percent_passing([10, 20], 50) == 0
assert percent_passing([90], 50) == 100
assert percent_passing([59, 60], 60) == 50
```
model:
```python
def percent_passing(scores, mark):
    if len(scores) == 0:
        return 0
    passing = 0
    for s in scores:
        if s >= mark:
            passing += 1
    return 100 * passing / len(scores)
```
hint: Handle the empty list first, to avoid dividing by zero.
hint: Count the passing scores with a loop, then divide by the number of scores.
solution: Return `0` at once for an empty list, since dividing by `len(scores)` would be a `ZeroDivisionError`. Otherwise count the scores that are at least `mark` and return `100 * passing / len(scores)`.
