@article
Every programmer gets errors all the time. They are not a sign of failure: an error message is Python telling you exactly where it got confused. Learning to read it is the fastest way to fix your program.

### Anatomy of a traceback

```python
numbers = [10, 20, 30]
print(numbers[3])
```

Running this stops with a message like:

```text
Traceback (most recent call last):
  File "main.py", line 2, in <module>
    print(numbers[3])
IndexError: list index out of range
```

Read it **from the bottom**. The last line gives the **error type** (`IndexError`) and a short explanation. The lines above it show the line number and the code that failed. The list has indexes 0, 1 and 2, so index 3 is out of range.

### Common errors

| Error | Usual cause |
|---|---|
| `SyntaxError` | Broken grammar: a missing colon, bracket or quote. Python cannot even start the program. |
| `IndentationError` | Lines indented inconsistently, or a block with no indented body. |
| `NameError` | A name that does not exist: a typo, or a variable used before it was assigned. |
| `TypeError` | An operation on the wrong type, such as `"Age: " + 12`. |
| `ValueError` | The right type but an unacceptable value, such as `int("six")`. |
| `IndexError` | An index outside a string or list. |
| `ZeroDivisionError` | Dividing by zero, for example `5 / 0`. |

A `SyntaxError` is reported at the place where Python noticed the problem, which is sometimes a line later than the real mistake, so look at the line before it too.

### Logic errors

The hardest bugs give **no error message at all**. The program runs, but the answer is wrong. These are called **logic errors**:

```python
def average_of_two(a, b):
    return a + b / 2    # wrong: divides only b
```

To find a logic bug:

1. **Test with small inputs** whose answers you know: `average_of_two(4, 6)` should be `5`, but the function gives `7.0`.
2. **Print the middle**: add temporary `print` lines to show the values of variables while the program runs.
3. **Trace by hand**: write down each variable after each line and compare it with the program's output.
4. **Change one thing at a time**, then run again.

Fix it with parentheses: `return (a + b) / 2`.

### Testing your functions

A test is a call together with the answer you expect. For `average_of_two`, `assert average_of_two(4, 6) == 5` stops with an `AssertionError` if the function gives anything else. Write a few tests, including edge cases such as `0`, a negative number and a boundary value, **before** you decide that a function works. This is how you check your three small functions for this week's deliverable.

@example
title: Reading a traceback
problem: A program stops with this message. What went wrong, and how do you fix it?

```text
Traceback (most recent call last):
  File "main.py", line 3, in <module>
    print("Total: " + total)
TypeError: can only concatenate str (not "int") to str
```
step: Read the last line: a `TypeError` means an operation was used with the wrong type.
step: The message says that a string and an `int` were joined with `+`. Line 3 shows `"Total: " + total`, so `total` must be a number.
step: Fix it by converting the number to text, or by using an f-string:

```python
print("Total: " + str(total))
print(f"Total: {total}")
```
step: Either line prints `Total: ` followed by the value of `total`.

@example
title: Finding a logic bug
problem: This function should return the sum of 1 through `n`, but `sum_to(3)` gives `3`. Find the bug.

```python
def sum_to(n):
    total = 0
    for i in range(1, n):
        total += i
    return total
```
step: Trace `sum_to(3)`: `range(1, 3)` gives `1` and `2`, so `total` becomes `3`.
step: The loop should also add `3`, but `range` stops before its stop value.
step: Change the loop to `for i in range(1, n + 1):`.
step: Now `sum_to(3)` adds `1`, `2` and `3` and returns `6`. Test `n = 1` too: the result is `1`, which is correct.

@mistakes
- Reading the traceback from the top. Start with the last line, which names the error.
- Changing several things at once, so you cannot tell which change fixed the bug.
- Testing only one easy input. A function can be right for `5` and wrong for `0`.
- Ignoring the line number in the message, or forgetting that the real mistake may be on the line before it.

@practice code
prompt: The function below should return the average of two numbers, but it has a logic bug. Fix it so that `average_of_two(4, 6)` returns `5`.
starter:
```python
def average_of_two(a, b):
    return a + b / 2
```
tests:
```python
assert average_of_two(4, 6) == 5
assert average_of_two(0, 10) == 5
assert average_of_two(-2, 2) == 0
assert average_of_two(3, 4) == 3.5
```
model:
```python
def average_of_two(a, b):
    return (a + b) / 2
```
hint: Which part of the expression is being divided by 2?
solution: Division happens before addition, so `a + b / 2` divides only `b`. Parentheses make the addition happen first: `(a + b) / 2`.

@practice code
prompt: The function `sum_to(n)` should return `1 + 2 + ... + n`, with `0` when `n` is `0`. It has an off-by-one bug. Fix it.
starter:
```python
def sum_to(n):
    total = 0
    for i in range(1, n):
        total += i
    return total
```
tests:
```python
assert sum_to(4) == 10
assert sum_to(1) == 1
assert sum_to(0) == 0
assert sum_to(10) == 55
```
model:
```python
def sum_to(n):
    total = 0
    for i in range(1, n + 1):
        total += i
    return total
```
hint: Which number does `range(1, n)` leave out?
solution: `range(1, n)` stops before `n`, so `n` is never added. Use `range(1, n + 1)`. For `n = 0` the range is empty and the answer is still `0`.

@practice code
prompt: Write `safe_divide(a, b)` that returns `a / b`, but returns `None` when `b` is `0` instead of causing an error. Use an `if`, not `try`. Test it with a zero divisor, a negative number and a zero dividend.
starter:
```python
def safe_divide(a, b):
    pass
```
tests:
```python
assert safe_divide(10, 4) == 2.5
assert safe_divide(-9, 3) == -3
assert safe_divide(0, 5) == 0
assert safe_divide(5, 0) is None
assert safe_divide(0, 0) is None
```
model:
```python
def safe_divide(a, b):
    if b == 0:
        return None
    return a / b
```
hint: Check for the dangerous case before you divide.
solution: If `b == 0` return `None` right away. Otherwise the function continues to `return a / b`. Because `return` ends the function, the division never runs when `b` is zero.

@quiz code
prompt: This function should return `True` for ages 18 and over and `False` for younger people, but it gives back `None` for young ages. Fix it.
starter:
```python
def is_adult(age):
    if age >= 18:
        return True
```
tests:
```python
assert is_adult(30) is True
assert is_adult(18) is True
assert is_adult(17) is False
assert is_adult(0) is False
```
model:
```python
def is_adult(age):
    if age >= 18:
        return True
    return False
```
hint: What does a function return when it ends without reaching a `return`?
solution: When the condition is false the function ends without a `return`, so Python gives back `None`. Adding `return False` as the last line covers that path. Even shorter: `return age >= 18`.
