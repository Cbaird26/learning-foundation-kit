@article
A pipe network carries water from a reservoir to a town; each pipe has a maximum rate. How much water can arrive per second? Adding up pipe capacities at the reservoir overestimates the answer if some pipe farther along is a bottleneck. The theory of network flows finds the exact answer and a short proof that it cannot be beaten.

### Flows and cuts

A **flow network** is a directed graph on vertices $0, \dots, n-1$ with a nonnegative integer **capacity** $c(u,v)$ on each edge, a **source** $s$ and a **sink** $t \ne s$. In code, `edges` is a list of triples `(u, v, c)`. A **flow** assigns $f(u,v)$ to each edge with $0 \le f(u,v) \le c(u,v)$ (the **capacity constraint**) and, at every vertex other than $s$ and $t$, flow in equals flow out (**conservation**). Its **value** $|f|$ is the net flow out of $s$.

A **cut** is a partition $(S, T)$ of the vertices with $s \in S$ and $t \in T$; its **capacity** $c(S,T)$ is the sum of $c(u,v)$ over edges from $S$ to $T$.

**Weak duality.** For every flow $f$ and every cut $(S, T)$, $|f| \le c(S,T)$.

*Proof.* Sum the net outflow $\sum_{e \text{ leaving } v}f(e) - \sum_{e \text{ entering } v}f(e)$ over all $v \in S$. By conservation only $s$ contributes, giving $|f|$. On the other hand, every edge with both ends in $S$ appears once positively and once negatively and cancels, so the sum equals $f(S,T) - f(T,S)$, the flow on edges from $S$ to $T$ minus the flow on edges from $T$ to $S$. Thus $|f| = f(S,T) - f(T,S) \le f(S,T) \le c(S,T)$. $\blacksquare$

```python
def check_flow(n, edges, flow, s, t):
    """Value of the flow (a list aligned with edges) if feasible, else None."""
    balance = [0] * n
    for (u, v, c), f in zip(edges, flow):
        if f < 0 or f > c:
            return None
        balance[u] -= f
        balance[v] += f
    if any(balance[v] != 0 for v in range(n) if v not in (s, t)):
        return None
    return -balance[s]


def cut_capacity(edges, side):
    """Capacity of the cut whose source side is the set `side`."""
    return sum(c for u, v, c in edges if u in side and v not in side)


edges = [(0, 1, 3), (0, 2, 2), (1, 2, 1), (1, 3, 2), (2, 3, 3)]
print(check_flow(4, edges, [3, 2, 1, 2, 3], 0, 3), cut_capacity(edges, {0}))
```
This prints `5 5`: the flow is feasible with value $5$, and the cut $\{0\}$ has capacity $5$, so by weak duality the flow is maximum.

### The residual network and the theorem

Given a flow $f$, the **residual network** has, for each edge $(u,v)$, a forward residual capacity $c(u,v) - f(u,v)$ and a backward residual capacity $f(u,v)$ on $(v,u)$ (which lets us cancel flow). An **augmenting path** is a path from $s$ to $t$ in the residual network using only edges with positive residual capacity.

**Theorem (max-flow min-cut; Ford and Fulkerson, 1956).** For a flow $f$ in a flow network with nonnegative capacities, the following are equivalent: (1) $f$ is a maximum flow; (2) the residual network has no augmenting path; (3) $|f| = c(S,T)$ for some cut $(S,T)$. In particular, the maximum flow value equals the minimum cut capacity.

*Proof.* (1) $\Rightarrow$ (2): if there were an augmenting path, pushing its bottleneck residual capacity (positive) along it would give a flow of larger value. (2) $\Rightarrow$ (3): let $S$ be the set of vertices reachable from $s$ by positive residual edges; $t \notin S$ by (2). Every edge $(u,v)$ from $S$ to $T$ has zero forward residual capacity (else $v$ would be reachable), so $f(u,v) = c(u,v)$, and every edge from $T$ to $S$ has zero backward residual capacity, so $f = 0$ on it. Hence $|f| = f(S,T) - f(T,S) = c(S,T)$. (3) $\Rightarrow$ (1): by weak duality every flow has value at most $c(S,T) = |f|$. $\blacksquare$

**Integrality.** If all capacities are integers, augmenting along bottleneck paths changes the flow by integers, so every flow in the process is integer-valued, and each augmentation raises $|f|$ by at least $1$. Since $|f|$ is bounded by the capacity of any cut, the process stops after finitely many augmentations, with a flow satisfying (2), hence maximum. So an integer-valued maximum flow exists. This is the algorithm of **Ford and Fulkerson**; choosing at each step a *shortest* augmenting path (found by breadth-first search) is the **Edmonds–Karp** algorithm, which is known to need only $O(VE)$ augmentations, hence $O(VE^2)$ time, where $V$ and $E$ are the numbers of vertices and edges (stated here without proof), so it runs in polynomial time even when capacities are huge. With arbitrary augmenting paths and irrational capacities the process can fail to terminate, which is why the hypotheses on capacities matter.

### Applications

*Edge-disjoint paths.* Give each undirected edge capacity $1$ in both directions; the maximum flow from $s$ to $t$ equals the maximum number of pairwise edge-disjoint $s$–$t$ paths, by integrality (this is Menger's theorem for edges) and the minimum cut is the fewest edges whose removal separates $s$ from $t$.

*Bipartite matching.* Add a source joined to each left vertex and a sink joined from each right vertex, all with capacity $1$, and give the original edges capacity $1$. An integer flow of value $k$ is a matching with $k$ edges, so the maximum flow is the maximum matching, and König's theorem is a special case of max-flow min-cut.

@example
title: The Edmonds–Karp algorithm on a small network
problem: A network has vertices $0, \dots, 4$, source $0$, sink $4$, and edges $(0,1,5)$, $(0,2,4)$, $(1,3,3)$, $(2,3,2)$, $(2,4,3)$, $(3,4,4)$. Find a maximum flow value and a minimum cut.
step: Shortest augmenting path: $0 \to 2 \to 4$ with bottleneck $\min(4, 3) = 3$. Push $3$. Residual capacities: $(0,2)$ is now $1$, $(2,4)$ is $0$.
step: Next shortest paths have three edges. Take $0 \to 1 \to 3 \to 4$ with bottleneck $\min(5, 3, 4) = 3$. Push $3$; the total is $6$. Now $(1,3)$ is saturated and $(3,4)$ has residual $1$.
step: Take $0 \to 2 \to 3 \to 4$ with bottleneck $\min(1, 2, 1) = 1$. Push $1$; the total is $7$.
step: Search again: from $0$, the edge $(0,1)$ has residual $2$, so $1$ is reachable; $(0,2)$ is saturated. From $1$, the edge $(1,3)$ is saturated, and the only other residual edge goes back to $0$. So $S = \{0, 1\}$ and $t \notin S$: no augmenting path.
step: The cut $(\{0,1\}, \{2,3,4\})$ has capacity $c(0,2) + c(1,3) = 4 + 3 = 7$, equal to the flow value $7$, so the flow is maximum and the cut is minimum.
answer: Maximum flow $7$, minimum cut with source side $\{0, 1\}$.

@mistakes
- Adding the capacities of edges leaving the source and calling it the maximum flow: that is one cut, and it is only an upper bound.
- Forgetting the backward residual edges: an augmenting path may have to cancel flow, and without backward edges a greedy method can stop at a flow that is not maximum.
- Taking the minimum cut to be unique: a network may have several minimum cuts of equal capacity; the set of vertices reachable from $s$ in the residual network gives the one with the smallest source side.
- Counting a cut's capacity with edges from $T$ to $S$ as well: only edges from $S$ to $T$ count.

```python
def max_flow(n, edges, s, t):
    """Edmonds-Karp maximum flow value."""
    residual = [[0] * n for _ in range(n)]
    for u, v, c in edges:
        residual[u][v] += c
    total = 0
    while True:
        parent = [-1] * n
        parent[s] = s
        queue = [s]
        head = 0
        while head < len(queue):
            u = queue[head]
            head += 1
            for v in range(n):
                if parent[v] == -1 and residual[u][v] > 0:
                    parent[v] = u
                    queue.append(v)
        if parent[t] == -1:
            return total
        bottleneck = None
        v = t
        while v != s:
            u = parent[v]
            if bottleneck is None or residual[u][v] < bottleneck:
                bottleneck = residual[u][v]
            v = u
        v = t
        while v != s:
            u = parent[v]
            residual[u][v] -= bottleneck
            residual[v][u] += bottleneck
            v = u
        total += bottleneck
```

def min_cut(n, edges, s, t):
    """Maximum flow value and the source side of a minimum cut."""
    residual = [[0] * n for _ in range(n)]
    for u, v, c in edges:
        residual[u][v] += c
    total = 0
    while True:
        parent = [-1] * n
        parent[s] = s
        queue = [s]
        head = 0
        while head < len(queue):
            u = queue[head]
            head += 1
            for v in range(n):
                if parent[v] == -1 and residual[u][v] > 0:
                    parent[v] = u
                    queue.append(v)
        if parent[t] == -1:
            return total, [v for v in range(n) if parent[v] != -1]
        path = []
        v = t
        while v != s:
            path.append((parent[v], v))
            v = parent[v]
        bottleneck = min(residual[u][v] for u, v in path)
        for u, v in path:
            residual[u][v] -= bottleneck
            residual[v][u] += bottleneck
        total += bottleneck

def edge_disjoint_paths(n, edges, s, t):
    """Maximum number of edge-disjoint s-t paths (unit-capacity flow)."""
    residual = [[0] * n for _ in range(n)]
    for u, v in edges:
        residual[u][v] += 1
        residual[v][u] += 1
    flow = 0
    while True:
        parent = [-1] * n
        parent[s] = s
        queue = [s]
        head = 0
        while head < len(queue):
            u = queue[head]
            head += 1
            for v in range(n):
                if parent[v] == -1 and residual[u][v] > 0:
                    parent[v] = u
                    queue.append(v)
        if parent[t] == -1:
            return flow
        v = t
        while v != s:
            u = parent[v]
            residual[u][v] -= 1
            residual[v][u] += 1
            v = u
        flow += 1

Counting vertex-disjoint paths needs vertex splitting instead; using only one direction for each edge gives wrong answers on undirected graphs.
