@article
Finite automata have only finite memory and a stack gives only last-in, first-out access. A **Turing machine (TM)** has an unbounded tape that it can read, write and move along in both directions. It is the standard mathematical model of a general-purpose computer.

### Definition

A (deterministic, single-tape) Turing machine is a 7-tuple $M = (Q, \Sigma, \Gamma, \delta, q_0, q_{\text{accept}}, q_{\text{reject}})$:

- $Q$ is a finite set of states;
- $\Sigma$ is the input alphabet, which does not contain the **blank symbol** $\sqcup$;
- $\Gamma$ is the tape alphabet, with $\sqcup \in \Gamma$ and $\Sigma \subseteq \Gamma$;
- $\delta : Q' \times \Gamma \to Q \times \Gamma \times \{L, R\}$, where $Q' = Q \setminus \{q_{\text{accept}}, q_{\text{reject}}\}$;
- $q_0$ is the start state, and $q_{\text{accept}} \ne q_{\text{reject}}$ are the halting states.

The tape is infinite to the right. At the start it holds the input, followed by blanks, and the head is on the leftmost cell. In each step the machine reads the symbol under the head, then writes a symbol, moves one cell left or right (a move left from the leftmost cell leaves the head where it is), and enters a new state. A rule $\delta(q, a) = (r, b, D)$ means "in state $q$ reading $a$: write $b$, move in direction $D$, go to state $r$."

### Computation, acceptance and halting

A **configuration** records the tape contents, head position and state, written $u\,q\,v$: the tape holds $uv$ (then blanks), the machine is in state $q$ and the head is on the first symbol of $v$. The machine halts when it enters $q_{\text{accept}}$ or $q_{\text{reject}}$. For an input $w$ exactly one of three things happens: $M$ **accepts**, **rejects**, or **loops** (runs forever).

The language $L(M)$ is the set of strings that $M$ accepts. A language is **Turing-recognizable** if some TM has it as $L(M)$. A TM that halts on every input is a **decider**, and a language is **decidable** if some decider recognizes it. Every decidable language is recognizable; the converse fails, as we will prove. For a recognizer, a string outside the language may make the machine loop.

In the simulators below we also let a missing transition mean "reject", which is a convenient shorthand for sending the machine to $q_{\text{reject}}$.

### Computing functions and the cost of a computation

A TM can also compute: whatever is left on the tape when it accepts is its output. The **running time** on input $w$ is the number of steps before halting. A TM is the standard setting for defining time and space complexity.

### Simulating a TM

A simulator needs a tape that grows to the right, a head index and a transition dictionary. In Python:

```python
def step(delta, state, tape, head):
    state, write, move = delta[(state, tape[head])]
    tape[head] = write
    head += 1 if move == "R" else 0 if head == 0 else -1
    if head == len(tape):
        tape.append("_")
    return state, head
```

Here `"_"` stands for the blank. Everything the machine does is local: one cell read, one cell written, one cell moved.

@example
title: A TM that decides {0^n 1^n}
problem: Describe a TM deciding $\{0^n1^n : n \ge 0\}$ and trace it on $0011$.
step: Idea: repeatedly cross off the leftmost $0$ (write $X$), then cross off the leftmost remaining $1$ (write $Y$), and go back for the next $0$. Accept when no $0$ remains and no unmatched $1$ remains.
step: Rules, with blank written `_`. State $q_0$: on $0$ write $X$, move right, go to $q_1$; on $Y$ move right to $q_3$; on blank accept. State $q_1$: skip $0$s and $Y$s moving right; on $1$ write $Y$, move left, go to $q_2$. State $q_2$: skip $0$s and $Y$s moving left; on $X$ move right and go to $q_0$. State $q_3$: skip $Y$s moving right; on blank accept. Any other symbol rejects.
step: Trace on $0011$: $q_0$ marks the first $0$ giving $X011$, $q_1$ moves right to the first $1$ and marks it: $X0Y1$, and $q_2$ moves left to the $X$, returning to $q_0$ on the cell after it.
step: Now $q_0$ marks the second $0$: $XXY1$. $q_1$ moves right over $Y$ to the last $1$ and marks it: $XXYY$. $q_2$ moves left to the nearest $X$ and $q_0$ steps right onto $Y$.
step: In $q_0$ on $Y$ the machine goes to $q_3$, which skips the remaining $Y$ and reaches a blank, where it accepts. So $0011$ is accepted.
step: On $001$ the machine marks both $0$s but runs out of $1$s: in $q_1$ it reaches a blank with no transition and rejects. On $011$ it ends in $q_3$ facing an unmatched $1$ and rejects. On $10$ it rejects immediately because $q_0$ has no rule for $1$.
answer: The machine accepts exactly $\{0^n1^n\}$, and halts on every input, so the language is decidable.

@example
title: A TM that computes a function
problem: Design a TM that adds one to a number written in unary (a string of $1$s) and trace it on $11$.
step: Idea: scan right over the $1$s to the first blank, write one more $1$ there, and accept.
step: Rules: $\delta(q_0, 1) = (q_0, 1, R)$ and $\delta(q_0, \sqcup) = (q_{\text{accept}}, 1, R)$.
step: Trace on $11$: the head is on the first $1$ in $q_0$, moves right to the second $1$, moves right to a blank, writes $1$ and accepts.
step: At acceptance the tape holds $111$, so the output is three ones. On the empty input the head sees a blank at once and writes a single $1$, so zero maps to one.
answer: The tape holds $111$ at halt.

@mistakes
- Thinking a TM that does not accept must reject. It may also loop forever, which is neither.
- Forgetting that "decidable" requires a machine that halts on all inputs, including strings outside the language.
- Writing a transition function that is not total on non-halting states (or, in a simulator, forgetting the convention for a missing transition).
- Moving the head off the left end of the tape, which the standard model forbids by keeping the head in place.

```python
def run_tm(delta, start, w, max_steps):
    tape = list(w) if w else ["_"]
    state = start
    head = 0
    for _ in range(max_steps):
        if state == "qa":
            return "accept"
        if state == "qr":
            return "reject"
        key = (state, tape[head])
        if key not in delta:
            return "reject"
        state, write, move = delta[key]
        tape[head] = write
        if move == "R":
            head += 1
            if head == len(tape):
                tape.append("_")
        elif head > 0:
            head -= 1
    if state == "qa":
        return "accept"
    if state == "qr":
        return "reject"
    return "running"
```
hint: Keep the tape as a list, a head index and the current state; each loop pass is one transition.
hint: Check for the halting states at the top of each pass and again after the loop. Extend the tape with `"_"` when the head moves past the end.
solution: Loop at most `max_steps` times. At the top of the loop return if the state is `qa` or `qr`; look up the rule (rejecting if missing), write the symbol and move the head, growing the tape on the right and refusing to go left of cell 0. After the loop, check the halting states once more, since the last transition may have entered one, and otherwise report `"running"`.

model:
```python
def tm_steps(delta, start, w, max_steps):
    tape = list(w) if w else ["_"]
    state = start
    head = 0
    steps = 0
    while True:
        if state in ("qa", "qr"):
            return steps
        key = (state, tape[head])
        if key not in delta:
            return steps
        if steps == max_steps:
            return None
        state, write, move = delta[key]
        tape[head] = write
        steps += 1
        if move == "R":
            head += 1
            if head == len(tape):
                tape.append("_")
        elif head > 0:
            head -= 1
```
hint: Count each transition you take; a halt does not count as a step.
hint: Stop and return the count when the state is `qa` or `qr` or no rule applies, and return `None` if the next transition would be number `max_steps + 1`.
solution: The loop checks for halting before each transition and counts only transitions actually taken. For input `"0110"` the machine takes four steps flipping symbols and a fifth step moving into `qa` on the blank, so the result is `5`. On `"012"` it takes two steps, then finds no rule for `2` and halts.

@quiz mc
prompt: A Turing machine $M$ is run on a string $w$ and, after a very long time, has neither accepted nor rejected. What can you conclude?
choice*: Nothing yet: $M$ may still accept, may still reject, or may never halt.
choice: $M$ will reject $w$, since it did not accept in a reasonable time.
choice: $M$ is a decider.
choice: $w$ is not in $L(M)$.
hint: A computation that has not halted yet is simply unfinished.
solution: Until the machine halts you cannot tell which outcome will happen, and this is the root of the difference between recognizing and deciding. $M$ may yet accept (so $w$ may be in $L(M)$), and whether it is a decider depends on all inputs, not this one.
