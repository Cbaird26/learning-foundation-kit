@article
Theory of computation asks a blunt question: *which problems can a machine solve, and with how much memory, time or other resources?* To ask it precisely we first need to say what a "problem" is. We use the simplest possible form: a yes/no question about a string.

### Alphabets, strings and languages

An **alphabet** $\Sigma$ is a finite, non-empty set of symbols, such as $\{0,1\}$ or $\{a,b\}$. A **string** over $\Sigma$ is a finite sequence of symbols from $\Sigma$. The **length** $|w|$ is the number of symbols, and the **empty string** $\varepsilon$ has length $0$. Writing $uv$ means the **concatenation** of $u$ and $v$, so $\varepsilon w = w\varepsilon = w$. The set of all strings over $\Sigma$ is $\Sigma^*$, and the set of strings of length exactly $n$ is $\Sigma^n$; over $\{0,1\}$ there are $2^n$ of them.

A **language** is any subset $L \subseteq \Sigma^*$. A language is a decision problem: "is this string in $L$?" The language of binary strings that end in $01$ is infinite, but a very small machine can decide it.

### Deterministic finite automata

A **deterministic finite automaton (DFA)** is a 5-tuple $M = (Q, \Sigma, \delta, q_0, F)$:

- $Q$ is a finite set of **states**;
- $\Sigma$ is the input alphabet;
- $\delta : Q \times \Sigma \to Q$ is the **transition function**, defined for every state and every symbol;
- $q_0 \in Q$ is the **start state**;
- $F \subseteq Q$ is the set of **accepting states**.

The machine reads the input left to right, one symbol at a time, moving $q \to \delta(q, a)$. It **accepts** $w$ if it ends in a state of $F$. The **language recognized** by $M$ is $L(M) = \{w : M \text{ accepts } w\}$. A language is **regular** if some DFA recognizes it.

Because $\delta$ is total and single-valued, a DFA has exactly one computation on each input. It uses a fixed amount of memory, namely its current state.

### Designing a DFA

The method is to decide **what the machine must remember** about the prefix read so far, and make one state per distinct thing to remember. For "ends in $01$" we need to know whether the last symbols read are: nothing useful, a $0$, or $01$. That is three states.

The same machine in code is a table and a loop:

```python
delta = {
    ("s", "0"): "z", ("s", "1"): "s",
    ("z", "0"): "z", ("z", "1"): "t",
    ("t", "0"): "z", ("t", "1"): "s",
}
state = "s"
for ch in "1101":
    state = delta[(state, ch)]
print(state == "t")  # True: 1101 ends in 01
```

State `s` means "no progress", `z` means "the last symbol was 0", and `t` means "the last two symbols were 01" (the accepting state).

### Closure under complement

If $M$ decides $L$, swapping accepting and non-accepting states gives a DFA for the complement $\overline{L} = \Sigma^* \setminus L$. This works because every input has exactly one computation that always finishes. (It fails for machines with several computations, as we will see next week.) Running two DFAs in parallel, with states that are pairs, gives the **product construction** for union and intersection.

@example
title: Tracing a DFA
problem: A DFA over $\{0,1\}$ has states $s, z, t$, start state $s$, accepting set $\{t\}$ and transitions $\delta(s,0)=z$, $\delta(s,1)=s$, $\delta(z,0)=z$, $\delta(z,1)=t$, $\delta(t,0)=z$, $\delta(t,1)=s$. Does it accept $1101$? Does it accept $0110$?
step: Start in $s$ and read $1$: $\delta(s,1)=s$.
step: Read the second $1$: $\delta(s,1)=s$. Read $0$: $\delta(s,0)=z$.
step: Read the final $1$: $\delta(z,1)=t$. The input is used up and $t \in F$, so $1101$ is accepted.
step: For $0110$: $s \to z$ (read $0$), $z \to t$ (read $1$), $t \to s$ (read $1$), $s \to z$ (read $0$). The final state is $z \notin F$, so $0110$ is rejected.
answer: $1101$ is accepted and $0110$ is rejected. The machine accepts exactly the strings that end in $01$.

@example
title: Designing a DFA: binary numbers divisible by 3
problem: Design a DFA over $\{0,1\}$ that accepts the binary representations (most significant bit first, leading zeros allowed, $\varepsilon$ counts as value $0$) of the multiples of $3$.
step: What must be remembered about the prefix read so far? Only its value modulo $3$. That gives three states $r_0, r_1, r_2$, where $r_k$ means "the prefix has value $\equiv k \pmod 3$".
step: Appending a bit $b$ to a number with value $v$ gives the value $2v + b$. So $\delta(r_k, b) = r_{(2k + b) \bmod 3}$.
step: Compute the table: $\delta(r_0,0)=r_0$, $\delta(r_0,1)=r_1$, $\delta(r_1,0)=r_2$, $\delta(r_1,1)=r_0$, $\delta(r_2,0)=r_1$, $\delta(r_2,1)=r_2$.
step: The start state is $r_0$ (the empty prefix has value $0$) and the only accepting state is $r_0$.
step: Test on $110$ (which is $6$): $r_0 \to r_1 \to r_0 \to r_0$, accepted. Test on $101$ (which is $5$): $r_0 \to r_1 \to r_2 \to r_2$, rejected.
answer: Three states, $\delta(r_k,b)=r_{(2k+b) \bmod 3}$, start and accepting state $r_0$.

@mistakes
- Leaving some state-symbol pair out of $\delta$. A DFA's transition function is total; if a "trap" is needed, add an explicit dead state that loops on every symbol.
- Making accepting states depend on the last symbol only, instead of on what the whole prefix means. Decide first what each state remembers.
- Confusing a string with a language: $\{01\}$ is a language with one string, $01$ is a string, and $\varepsilon$ is a string while $\emptyset$ is a language with no strings.
- Forgetting that the empty string is processed too: it is accepted exactly when the start state is accepting.

model:
```python
def reachable_count(delta, start, alphabet):
    seen = {start}
    todo = [start]
    while todo:
        state = todo.pop()
        for ch in alphabet:
            nxt = delta[(state, ch)]
            if nxt not in seen:
                seen.add(nxt)
                todo.append(nxt)
    return len(seen)
```
hint: This is a graph search: states are nodes and each symbol gives an edge.
hint: Keep a set of states already seen and a list of states whose outgoing transitions you have not yet followed.
solution: Do a depth-first or breadth-first search from `start`, following `delta[(state, ch)]` for every symbol, and return the size of the set of states found. Each state is processed once, so the work is proportional to the number of states times the alphabet size.

model:
```python
from itertools import product


def accepted_strings(delta, start, accepting, alphabet, n):
    result = []
    for symbols in product(alphabet, repeat=n):
        state = start
        for ch in symbols:
            state = delta[(state, ch)]
        if state in accepting:
            result.append("".join(symbols))
    return result
```
hint: `itertools.product(alphabet, repeat=n)` produces every string of length `n` in the right order.
hint: Run the DFA on each candidate string and keep the ones that end in an accepting state.
solution: Enumerate all $|\Sigma|^n$ strings with `product(alphabet, repeat=n)`, which yields them in lexicographic order for the given symbol order, simulate the DFA on each, and collect those that end in `accepting`. For `n = 0`, `product` yields one empty tuple, which gives `""`.
