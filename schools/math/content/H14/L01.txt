@article
A **function** is a named recipe: you write the steps once, then *call* the recipe whenever you need it. Functions are the main tool for keeping a growing program understandable, because each one can be read, tested and fixed on its own.

### Defining and calling

```python
def area(width, height):
    return width * height

print(area(3, 4))
```

`width` and `height` are **parameters**: names the function uses for its inputs. The values you pass in the call (`3` and `4`) are **arguments**. When `area(3, 4)` runs, Python binds `width = 3` and `height = 4`, runs the body, and the `return` statement sends a value back to the caller. The call `area(3, 4)` then *is* the value `12`.

### `return` is not `print`

`print` shows text on the screen for a human. `return` hands a value back to the program so other code can use it.

```python
def show_double(x):
    print(x * 2)

def double(x):
    return x * 2

y = double(5) + 1    # y is 11
z = show_double(5)   # prints 10, and z is None
```

A function that reaches its end without executing `return` gives back the special value `None`. Forgetting `return` (or using `print` instead) is the most common beginner bug with functions: the answer appears on screen but the rest of the program receives `None`.

A `return` also ends the function immediately, so code after it in the same branch never runs.

### Local variables

Variables created inside a function, including its parameters, are **local**: they exist only during the call. Assigning to a parameter changes only the function's own copy of the name, not the variable you passed in (for a number or string, which cannot be changed in place).

### Default arguments

A parameter can have a default, used when the caller leaves the argument out. Parameters with defaults go after those without, and a caller can pass an argument by name:

```python
def greet(name, punctuation="!"):
    return "Hello, " + name + punctuation

print(greet("Sam"))                  # Hello, Sam!
print(greet("Sam", punctuation="?")) # Hello, Sam?
```

### Decomposition

**Decomposition** means splitting a big task into small functions, each with one clear job and a good name. Suppose you must report the average of the passing scores in a list. Instead of one tangled loop, write `is_passing(score)` first, then a function that uses it. Small functions are easier to test, can be reused, and let you read the main function almost like English. A good test of a function's size: you can describe what it does in one sentence without using the word "and" more than once.

Write a one-line **docstring** (a string right after the `def` line) when the purpose is not obvious: `"""Return the area of a rectangle."""`.

@example
title: Tracing nested function calls
problem: What does this program print?

```python
def area(w, h):
    return w * h

def room_cost(w, h, price):
    return area(w, h) * price

print(room_cost(3, 4, 5))
```
step: Python reads the two `def` statements and remembers them. Nothing runs yet.
step: `print(room_cost(3, 4, 5))` first evaluates the call: `w = 3`, `h = 4`, `price = 5`.
step: The body needs `area(w, h)`, so Python calls `area(3, 4)`. That call returns `3 * 4 = 12`.
step: Back in `room_cost`, the expression is `12 * 5 = 60`, and that value is returned.
step: `print` receives `60` and displays it.
answer: `60`

@example
title: Decomposing a task into helpers
problem: Write `average_passing(scores)` that returns the average of the scores that are at least 50, or `0` if no score passes.
step: Name the small decision first: a helper `is_passing(score)` that returns `True` when `score >= 50`.
step: The main function needs a total and a count of passing scores, so use two accumulators that start at `0`.
step: Loop over the scores, and for each passing one add it to the total and add 1 to the count.
step: Handle the case with no passing scores before dividing, because division by zero is an error. The finished code:

```python
def is_passing(score):
    return score >= 50

def average_passing(scores):
    total = 0
    count = 0
    for s in scores:
        if is_passing(s):
            total += s
            count += 1
    if count == 0:
        return 0
    return total / count
```
step: Check: for `[40, 60, 80]` only 60 and 80 pass, so the result is `140 / 2 = 70.0`.

@mistakes
- Using `print` where `return` is needed, so the caller receives `None`.
- Putting `return` inside a loop body by accident, so the function stops after the first pass.
- Expecting a function to change the caller's variable when it assigns to its parameter.
- Putting a parameter with a default before one without a default, which is a syntax error.

@practice code
prompt: Write two functions. `is_vowel(ch)` returns `True` if the one-character string `ch` is a vowel (`a`, `e`, `i`, `o` or `u`, in either upper or lower case) and `False` otherwise. `count_vowels(text)` returns how many vowels the string `text` contains, and should call `is_vowel`.
starter:
```python
def is_vowel(ch):
    pass


def count_vowels(text):
    pass
```
tests:
```python
assert is_vowel("a") is True
assert is_vowel("E") is True
assert is_vowel("b") is False
assert is_vowel("y") is False
assert count_vowels("Banana") == 3
assert count_vowels("rhythm") == 0
assert count_vowels("") == 0
assert count_vowels("AEIOU aeiou") == 10
```
model:
```python
def is_vowel(ch):
    return ch.lower() in "aeiou"


def count_vowels(text):
    count = 0
    for ch in text:
        if is_vowel(ch):
            count += 1
    return count
```
hint: `ch.lower()` lets you compare upper and lower case letters with one rule.
hint: In `count_vowels`, keep a count that starts at `0` and add 1 whenever `is_vowel(ch)` is true.
solution: `is_vowel` lowercases the character and checks whether it appears in `"aeiou"`. `count_vowels` is an accumulator loop that asks the helper about each character, so the vowel rule lives in one place. The letter `y` is not counted, and spaces are not vowels.

```python
def total_price(price, quantity=1, tax_rate=0.0):
```

```python
def total_price(price, quantity=1, tax_rate=0.0):

```

@quiz code
prompt: Write `clamp(value, low, high)` that returns `value` if it lies between `low` and `high` (inclusive), returns `low` if `value` is smaller than `low`, and returns `high` if `value` is larger than `high`. You may assume `low <= high`.
starter:
```python
def clamp(value, low, high):
    pass
```
tests:
```python
assert clamp(5, 0, 10) == 5
assert clamp(-3, 0, 10) == 0
assert clamp(15, 0, 10) == 10
assert clamp(0, 0, 10) == 0
assert clamp(10, 0, 10) == 10
assert clamp(2.5, 1, 2) == 2
```
model:
```python
def clamp(value, low, high):
    if value < low:
        return low
    if value > high:
        return high
    return value
```
hint: There are three cases: too small, too large, and in range.
hint: Check the two extreme cases with `if` and `return`; the in-range value is what is left.
solution: Return `low` when `value < low`, return `high` when `value > high`, and otherwise return `value` itself. Because each `return` ends the function, no `else` is needed.

@quiz text
prompt: What does this program print? Type the output exactly.

```python
def bump(n):
    n = n + 1
    return n

n = 5
bump(n)
print(n)
```
answer: 5
check: run("def bump(n):\n    n = n + 1\n    return n\n\nn = 5\nbump(n)\nprint(n)\n")
hint: The function's `n` is a separate local name from the `n` outside it, and the returned value is thrown away.
solution: Inside `bump`, `n` becomes `6`, and that value is returned, but the call's result is not stored anywhere. The outer `n` is never reassigned, so `print(n)` shows `5`.
