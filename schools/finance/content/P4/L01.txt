Welcome to the desk. Over the next fourteen weeks you will do what an equity analyst does: understand an industry, read a company's filings, build a model that forecasts its three financial statements, value it, and defend a view. This first week is about the job itself and the habits that separate a useful model from a pretty spreadsheet.

### Two seats, one craft

A **sell-side analyst** works at a broker-dealer or investment bank. The output is a published research note with a rating, a **price target** (the analyst's estimate of the stock's value in 12 months) and earnings estimates, distributed to many institutional clients. A **buy-side analyst** works at an asset manager, pension fund or hedge fund. The output is private: a recommendation to a portfolio manager, who decides whether and how much to buy. Sell-side work is judged by accuracy and usefulness to clients; buy-side work is judged by what it adds to portfolio returns. The craft is the same, and you will use the same models in both seats.

### The research process

Good analysts follow a repeatable process, because a process is what you can audit when you are wrong.

1. **Idea generation**: a screen, a news event, a conversation, a change in a company's fortunes.
2. **Industry analysis** (week 2): how the industry makes money and how competition works.
3. **Company analysis** (week 3): the business, management, accounting quality, risks.
4. **Forecasting** (weeks 4-8): revenue drivers, costs, schedules, debt, the integrated statements.
5. **Valuation** (weeks 9-10): DCF, multiples, scenarios, a price target.
6. **Communication** (weeks 11-12): the research note and the pitch.
7. **Monitoring**: update the model when new results arrive, and test the thesis against what actually happens.

### From price target to numbers

The first two numbers any note reports are simple. **Expected upside** is the percentage change from the current price $P_0$ to the target $P_T$:

$$\text{Upside} = \frac{P_T}{P_0} - 1.$$

**Expected total return** adds the dividends $D$ received over the horizon, because a shareholder earns both:

$$\text{Total return} = \frac{P_T + D}{P_0} - 1.$$

Ratings (Buy, Hold, Sell, or Overweight, Neutral, Underweight) are usually tied to the expected total return, but each firm sets its own bands. The rating is a label; the reasoning behind it is the product.

### A model is a program

In this course the model is Python code, and three habits make it trustworthy.

- **Separate inputs from calculations.** Every assumption (growth rate, tax rate, margin) lives in one place, such as a dictionary, never buried inside a formula.
- **Write small functions** that each do one calculation, so you can test each one on numbers you can check by hand.
- **Test as you go.** An `assert` that a balance sheet balances, or that a function returns the figure you computed by hand, catches errors before they reach a client.

```python
assumptions = {"price": 40.0, "target": 46.0, "dividend": 1.20}

def upside(price, target):
    """Expected price change as a decimal."""
    return target / price - 1

print(f"{upside(assumptions['price'], assumptions['target']):.1%}")
```

All numbers in this course are for fictional companies. Real filings live on SEC EDGAR, and you will use them in the project. Nothing here is a recommendation to buy or sell any security.

@example
title: Upside and total return
problem: Harbor Lantern Co trades at \$40.00. Your 12-month price target is \$46.00, and you expect \$1.20 per share of dividends over the year. Find the upside and the expected total return.
step: Upside uses only prices: $46.00/40.00 - 1 = 1.15 - 1 = 15.0\%$.
step: Total return adds the dividend to the ending value: $(46.00 + 1.20)/40.00 - 1 = 47.20/40.00 - 1 = 18.0\%$.
step: The dividend adds 3.0 percentage points ($1.20/40.00$). Under a rule such as "Buy if expected total return is at least 15%", both measures give the same label here, but a dividend can move a stock across a band.
answer: Upside 15.0%; expected total return 18.0%.

@example
title: Coding the calculation
problem: Write `upside(price, target)` and use it on a stock priced at \$80 with a target of \$68.
step: The result is a ratio of two prices minus 1, so return `target / price - 1`.
step: Code:

```python
def upside(price, target):
    return target / price - 1
```
step: Evaluate: $68/80 = 0.85$, so `upside(80, 68)` is about `-0.15`. A negative upside means the target is below the current price.
step: Floats are not exact, so when you test the function compare with a tolerance: `abs(upside(80, 68) + 0.15) < 1e-9`.

@mistakes
- Quoting the target as the return: a \$46 target is not a 46% upside; divide by the current price and subtract 1.
- Leaving dividends out of the expected return for a high-yielding stock.
- Hard-coding assumptions inside formulas, so nobody (including you) can find and change them later.
- Treating the rating as the product: a Buy with no reasoning that can be checked is worthless to the reader.

model:
```python
def screen(companies, max_pe, min_growth):
    """Tickers passing a valuation and growth screen, sorted."""
    passed = []
    for company in companies:
        if company["pe"] <= max_pe and company["growth"] >= min_growth:
            passed.append(company["ticker"])
    return sorted(passed)
```
hint: Loop over the dictionaries and keep the ticker when both conditions hold.
hint: Use `<=` and `>=` so the limits are inclusive, and return `sorted(...)` at the end.
solution: Test both conditions for each company, collect the tickers that pass, and sort them. The inclusive comparisons matter: the company with a P/E of exactly 15.0 and growth of exactly 0.08 must pass.

ideas = {
    "PQR": (20.0, 25.0),
    "STU": (50.0, 55.0),
    "VWX": (10.0, 13.0),
    "YZA": (30.0, 34.0),

model:
```python
def rank_by_upside(ideas):
    """Tickers sorted by expected upside, highest first."""
    def upside(ticker):
        price, target = ideas[ticker]
        return target / price - 1
    return sorted(ideas, key=upside, reverse=True)
```
hint: Sort the tickers using a key function that computes each one's upside.
hint: Pass `reverse=True` so the largest upside comes first.
solution: Define a helper that unpacks `(price, target)` and returns `target / price - 1`, then sort the dictionary's keys with that helper as the key and `reverse=True`. Sorting by target alone would put the most expensive stock first.
