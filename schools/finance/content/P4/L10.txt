@article
A valuation gives you a number today. A **price target** is a number a year from now, and it carries a promise: the analyst's best estimate of where the stock should trade at the end of the horizon if the thesis plays out. The honest way to present it is with a range and with the assumptions it is most sensitive to.

### Two ways to a target

**Target multiple method.** Forecast a metric for the end of the horizon and apply a multiple:

$$P_T = \text{Target P/E} \times \text{EPS}_{\text{next 12 months at } T}.$$

The target multiple comes from peers, from the company's own history and from growth. Because markets price forward earnings, the target in 12 months uses EPS for the 12 months after that date.

**DCF roll-forward.** A DCF gives value today, $V_0$. If the stock earns its cost of equity $k_e$ and pays a dividend $D$ during the year, the value in 12 months is

$$P_T = V_0 (1 + k_e) - D.$$

Either way, show the arithmetic and state the horizon.

### Scenarios

Three **scenarios** (bear, base, bull) express uncertainty with a story and a set of assumptions in each: for example, the bear case has revenue growth two points lower and a margin that does not expand. Assign **probabilities** that sum to 1 and compute the **probability-weighted (expected) value**:

$$E[P_T] = \sum_i p_i P_i.$$

Probabilities are judgments, so say so, and avoid making the base case look like certainty. A useful summary is the **risk-reward**: the upside to the bull case against the downside to the bear case.

### Sensitivity analysis

A **sensitivity table** recomputes the value over a grid of two key inputs, usually WACC down the rows and terminal growth across the columns. Read it for two things: how wide the range is, and where the result is fragile. In a Gordon model the terminal value depends on $1/(\text{WACC} - g)$, so the table is most sensitive where the spread between WACC and $g$ is smallest. Never show a table that includes cells with $g \ge \text{WACC}$.

In code, write the valuation as a function of its inputs and loop over the grid:

```python
def value(wacc, g):
    return 50 * (1 + g) / (wacc - g)

waccs = [0.08, 0.09]
growths = [0.02, 0.03]
table = [[value(w, g) for g in growths] for w in waccs]
for w, row in zip(waccs, table):
    print(f"{w:.0%}", [round(v, 1) for v in row])
```

This prints `8% [850.0, 1030.0]` and `9% [728.6, 858.3]`. The block deliverable for weeks 9 and 10 is a price target with a sensitivity table: state the target, the method, the scenarios with probabilities, and the table with the base case marked.

### Judging the target

A target is credible if you can explain it in a sentence ("15 times \$3.20 of forward EPS"), if it survives the sensitivity range, and if the scenarios are not all drawn from the same assumption. Update the target when the model changes, not when the stock price moves.

@example
title: A target from a multiple
problem: Coldwater Logistics trades at \$42.00. You forecast earnings per share of \$3.20 for the 12 months after your target date, and a target P/E of 15. Find the price target and upside.
step: $P_T = 15 \times 3.20 = \$48.00$.
step: Upside $= 48.00/42.00 - 1 = 14.3\%$.
step: State the multiple's source: for instance, the peer median is 14 and you add one turn for faster growth. The justification matters as much as the number.
answer: A target of \$48.00, upside of 14.3%.

@example
title: A probability-weighted target
problem: Coldwater's bear, base and bull values are \$32, \$48 and \$64, with probabilities 30%, 50% and 20%. Find the expected value and compare it with the \$42 price.
step: Check the probabilities: $0.30 + 0.50 + 0.20 = 1$.
step: $E = 0.30 \times 32 + 0.50 \times 48 + 0.20 \times 64 = 9.6 + 24.0 + 12.8 = \$46.40$.
step: Expected upside $= 46.40/42 - 1 = 10.5\%$. The base case is \$48, but the bear case is skewed more than the bull case in probability, so the expected value is lower.
step: Risk-reward: bull upside is $64/42 - 1 = 52\%$ and bear downside is $32/42 - 1 = -24\%$.
answer: Expected value \$46.40, an expected upside of 10.5%.

@mistakes
- Applying a target multiple to this year's earnings when the horizon requires the earnings of the following 12 months.
- Using probabilities that do not sum to 1, or dressing a single-scenario guess as a probability-weighted value.
- Presenting a sensitivity table over a narrow range of inputs that makes the answer look more certain than it is.
- Moving the price target because the stock price moved, not because the fundamentals or assumptions changed.

model:
```python
def expected_value(probs, values):
    """Probability-weighted value of scenarios."""
    if len(probs) != len(values):
        raise ValueError("probs and values must have the same length")
    if abs(sum(probs) - 1) > 1e-9:
        raise ValueError("probabilities must sum to 1")
    return sum(p * v for p, v in zip(probs, values))
```
hint: Validate the inputs first.
hint: The weighted value is the sum of each probability times its scenario value.
solution: Check the lengths and that the probabilities sum to 1 (with a tolerance because of floats), then sum `p * v` pairwise. For [0.5, 0.4] the total is 0.9, which is an error rather than an expected value.

def sensitivity_table(value_fn, waccs, growths):

model:
```python
def roll_forward_target(value_today, cost_of_equity, dividend):
    """12-month target from today's value, the cost of equity and dividends."""
    return value_today * (1 + cost_of_equity) - dividend
```
hint: Grow today's value by one year at the cost of equity.
hint: The dividend paid during the year leaves the stock, so it is subtracted from the ending price.
solution: Value at the end of the year is `value_today * (1 + cost_of_equity)` including the dividend; since the shareholder gets the dividend in cash, the stock's price is that amount minus the dividend. Subtracting the dividend is the step that is easy to forget.
