Statistics earns its place when it changes a decision. This lesson brings the course together around three questions a business analyst faces: *What do we expect to happen? How much data do we need? Can we trust a pattern we found?*

### Expected value and risk

When outcomes are uncertain, compare options by their **expected value** $E(X) = \sum x\,P(x)$ and their **risk**, the standard deviation $\sigma$ of the outcome. A project that pays \$400,000 with probability 0.25 and loses \$80,000 with probability 0.75 has $E = 0.25(400{,}000) + 0.75(-80{,}000) = \$40{,}000$. It is worth doing on average, yet it loses money three times out of four, so whether to take it depends on how much loss the firm can bear, not on the expected value alone. Statistics supplies the numbers; the decision also needs the firm's tolerance for risk.

### Planning an experiment: sample size

To compare two conversion rates $p_1$ and $p_2$ in an A/B test with significance level $\alpha$ (two-sided) and power $1-\beta$, each group needs about

$$n = \frac{(z_{\alpha/2} + z_{\beta})^2\,\left[p_1(1-p_1) + p_2(1-p_2)\right]}{(p_1 - p_2)^2}.$$

For $\alpha = 0.05$ and 80% power, $z_{\alpha/2} = 1.96$ and $z_{\beta} = 0.84$. The required $n$ grows fast as the difference to detect shrinks: halving it quadruples the sample. Decide the smallest difference that matters to the business, and the sample size, **before** the experiment.

### Multiple testing and data snooping

Each test at $\alpha = 0.05$ has a 5% false-positive chance when the null is true. Run $m$ independent tests, all with true nulls, and the probability of at least one false positive is $1 - (1-\alpha)^m$. With 20 tests that is 64%. This is the **multiple comparisons problem**. It is behind **data snooping** (searching many variables, periods or trading rules until something looks significant) and **backtest overfitting**: the best of hundreds of tested strategies often owes its record to luck. The **Bonferroni correction** controls the chance of any false positive by testing each hypothesis at $\alpha/m$; it is simple and conservative. Other remedies are to state hypotheses in advance, to hold out data (fit on one period, test on another), and to report how many things were tried.

### Other traps

- **Survivorship bias**: studying only funds or firms that still exist overstates average performance, because the failures have dropped out of the data.
- **Look-ahead bias**: using information in a test that was not available at the time of the decision.
- **Statistical versus practical significance**: with enough data a trivial difference gets a tiny p-value. Compare the *size* of an effect with its costs: a strategy that beats a benchmark by 0.02% a year is worthless if trading costs are 0.5%.
- **Correlation is not causation**: confounders, reverse causation and coincidence all create correlations. Randomized experiments (A/B tests) are the strongest tool for causal claims in business.
- **Base rates**: as in Bayes' rule, a rare event stays rare after a mildly informative signal.

### Communicating results

Report the estimate, an interval and the sample size; state the assumptions and what you checked (residuals, outliers, stability across periods); and say what the data cannot show. For public data, look up FRED (Federal Reserve Bank of St. Louis) for economic series and SEC EDGAR for company filings; statistics here is education, not investment advice.

### In Python

```python
import random

rng = random.Random(7)
n_tests, false_hits = 20, 0
for _ in range(n_tests):
    # a "strategy" with no skill: 50 coin-flip months
    wins = sum(rng.random() < 0.5 for _ in range(50))
    if wins >= 32:                  # chance of 32+ wins is about 3.3%
        false_hits += 1
print(false_hits)    # varies with the seed; each test has a 3.3% chance
```

@example
title: How many false discoveries?
problem: An analyst tests 20 trading signals, each at the 5% level. Suppose none of them has any real predictive power and the tests are independent. What is the probability that at least one signal looks significant, how many false positives are expected, and what Bonferroni threshold should each test use?
step: Each test has a 0.95 chance of correctly showing nothing, so all 20 do with probability $0.95^{20} = 0.3585$.
step: The probability of at least one false positive is $1 - 0.3585 = 0.6415$, or about 64%.
step: The expected number of false positives is $20 \times 0.05 = 1$.
step: The Bonferroni threshold is $\alpha/m = 0.05/20 = 0.0025$. A signal should only count as significant if its p-value is at most 0.0025, which keeps the chance of any false positive at or below 5%.
answer: 64.15%; 1 expected false positive; per-test threshold 0.0025.

@example
title: Sizing an A/B test
problem: A bank's current webpage converts 10% of visitors into applications. A redesign is worth launching if it raises the rate to 12%. How many visitors per page version are needed for a two-sided 5% test with 80% power? Use $z_{\alpha/2} = 1.96$ and $z_{\beta} = 0.84$.
step: The variance terms are $p_1(1-p_1) = 0.10(0.90) = 0.09$ and $p_2(1-p_2) = 0.12(0.88) = 0.1056$, which sum to $0.1956$.
step: The squared difference is $(0.12 - 0.10)^2 = 0.0004$.
step: $n = (1.96 + 0.84)^2(0.1956)/0.0004 = 7.84 \times 489 = 3833.8$.
step: Round up: about 3,834 visitors per version, 7,668 in all. If the bank cares only about a 3-point lift (10% to 13%), the requirement drops by roughly half.
answer: About 3,834 per version.

@mistakes
- Reporting the single best result among many tests or strategies without disclosing how many were tried.
- Treating a very small p-value as proof that an effect is large or valuable.
- Choosing the sample size (or stopping the experiment) after peeking at the p-value.
- Using an average that excludes failed funds or firms and treating it as the typical outcome.

@quiz code
prompt: Write `bonferroni(p_values, alpha)` that returns a list of booleans, one for each p-value, that is `True` when the p-value is at most `alpha / m` where `m` is the number of p-values. An empty list returns an empty list. For example, `bonferroni([0.001, 0.02, 0.04, 0.30], 0.05)` returns `[True, False, False, False]`.
starter:
```python
def bonferroni(p_values, alpha):
    pass
```
tests:
```python
assert bonferroni([0.001, 0.02, 0.04, 0.30], 0.05) == [True, False, False, False]
assert bonferroni([0.01, 0.01], 0.05) == [True, True]
assert bonferroni([0.03], 0.05) == [True]
assert bonferroni([], 0.05) == []
assert bonferroni([0.02, 0.02, 0.02, 0.02, 0.02], 0.05) == [False] * 5
```
model:
```python
def bonferroni(p_values, alpha):
    """Which hypotheses are rejected at Bonferroni-adjusted level alpha/m."""
    m = len(p_values)
    if m == 0:
        return []
    threshold = alpha / m
    return [p <= threshold for p in p_values]
```
hint: The threshold is `alpha` divided by the number of p-values.
hint: Handle the empty list before dividing, then build the list with a comprehension.
solution: With $m$ tests, each p-value is compared with $\alpha/m$. In the last test case, five tests give a threshold of 0.01, so p-values of 0.02 are not rejected even though each is below 0.05, which shows how the correction protects against false discoveries.
