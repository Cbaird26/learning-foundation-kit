@article
**Sorting** puts items in order. Sorted data is easier for people to read, is needed for binary search, and makes problems such as finding duplicates or the median much simpler. In real programs you almost always call Python's built-in sort, but writing simple sorts yourself teaches you how algorithms work and how to count their cost.

### Selection sort

Idea: find the smallest item and swap it into position 0, then find the smallest of the rest and swap it into position 1, and so on.

```python
def selection_sort(xs):
    xs = list(xs)                      # work on a copy
    for i in range(len(xs)):
        smallest = i
        for j in range(i + 1, len(xs)):
            if xs[j] < xs[smallest]:
                smallest = j
        xs[i], xs[smallest] = xs[smallest], xs[i]
    return xs
```

After pass `i`, the items at positions `0..i` are the smallest ones, in their final places. The line `xs[i], xs[smallest] = xs[smallest], xs[i]` swaps two items without a temporary variable. The comparison `xs[j] < xs[smallest]` runs $(n-1) + (n-2) + \dots + 1 = n(n-1)/2$ times, whatever the order of the data.

### Insertion sort

Idea: keep the front part of the list sorted, and insert each next item into the right place in it, like sorting playing cards in your hand.

```python
def insertion_sort(xs):
    xs = list(xs)
    for i in range(1, len(xs)):
        item = xs[i]
        j = i - 1
        while j >= 0 and xs[j] > item:
            xs[j + 1] = xs[j]          # shift a larger item right
            j -= 1
        xs[j + 1] = item
    return xs
```

For an already sorted list the `while` loop never runs, so insertion sort is fast on nearly sorted data; for a reversed list it shifts everything. Both sorts take about $n^2/2$ steps in their bad cases, so they are fine for small lists but slow for large ones.

### Python's sorting tools

```python
nums = [5, 2, 9]
ordered = sorted(nums)            # new list [2, 5, 9]; nums unchanged
nums.sort()                       # sorts in place and returns None
sorted(nums, reverse=True)        # [9, 5, 2]
```

`sorted` works on any sequence and returns a new list. `list.sort` changes the list and returns `None`, so never write `xs = xs.sort()`. Python's sort (called Timsort) takes at most about $n \log_2 n$ steps (worst case), much better than $n^2$ for big lists.

### Keys and stability

The `key` argument is a function applied to each item; items are ordered by the key values:

```python
words = ["pear", "fig", "apple", "kiwi"]
print(sorted(words, key=len))   # ['fig', 'pear', 'kiwi', 'apple']
```

Python's sort is **stable**: items with equal keys keep their original relative order (`pear` stays before `kiwi`). To sort by several criteria, make the key a tuple, since tuples compare element by element. A key function can be written with `def`, or with a short `lambda`, as in `key=lambda r: (r[1], r[0])`. To sort descending by a number, use its negative as the key: `-r[1]`.

@mistakes
- Writing `xs = xs.sort()`, which makes `xs` equal to `None`.
- Forgetting that selection sort on `xs` itself changes the caller's list unless you copy it first with `list(xs)`.
- In insertion sort, forgetting the check `j >= 0` before `xs[j]`, so the loop runs off the front of the list.
- Expecting `sorted(words)` to ignore capital letters: all capitals sort before lowercase letters unless you use `key=str.lower`.

@quiz num
prompt: Selection sort, as written in this lesson, sorts a list of 10 items. How many times is the comparison `xs[j] < xs[smallest]` evaluated in total, whatever the order of the items? Give the number.
answer: 45
check: comb(10, 2)
hint: The inner loop makes 9 comparisons on the first pass, 8 on the second, and so on.
solution: The passes make $9 + 8 + 7 + \dots + 1 = 10 \cdot 9 / 2 = 45$ comparisons. The count does not depend on the order of the data, because the inner loop always scans the whole unsorted part.
