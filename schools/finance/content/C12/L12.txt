@article
Machine learning (ML) methods such as penalized regression, trees and neural networks promise to find patterns in large data sets. In finance they are used for return prediction, credit scoring, fraud detection and reading text. The same flexibility makes them dangerous in finance: returns have a very low signal-to-noise ratio, so a flexible model finds patterns in the noise that vanish the day after you trade on them.

### Overfitting and the bias-variance trade-off

A model with many parameters can fit the sample almost perfectly. **In-sample** $R^2$ never falls as regressors are added, even useless ones. What matters is **out-of-sample** performance: forecasts on data the model has not seen. The expected squared forecast error splits into

$$E\big[(y - \hat f(x))^2\big] = \underbrace{\text{Bias}^2}_{\text{too simple}} + \underbrace{\text{Variance}}_{\text{too flexible}} + \sigma^2_{\varepsilon},$$

where $\sigma_\varepsilon^2$ is irreducible noise. A rigid model has high bias and low variance; a flexible one has the reverse. The goal is the level of complexity that minimizes the *sum*, found by evaluating on held-out data.

### Honest evaluation with time-ordered data

Split the sample into a **training** set (to fit parameters), a **validation** set (to choose tuning parameters such as the penalty) and a **test** set (touched once, at the end, to report performance). For time series and panels the split must respect time: train on the past, test on the future. Randomly shuffling observations before splitting lets the model learn from the future, a **look-ahead bias** (data leakage), and makes results look better than they could have been in real time. **Walk-forward** (rolling-origin) evaluation repeats this: fit on a window ending at time $t$, forecast the next block, move forward, and combine all the out-of-sample forecasts. Other sources of look-ahead bias are standardizing with full-sample means, using restated accounting data that was not available at the time, and survivorship bias (using only firms that still exist).

The **out-of-sample $R^2$** compares the model's forecasts with a benchmark forecast, usually the historical mean $\bar y$ from the training data:

$$R^2_{OOS} = 1 - \frac{\sum_{t \in \text{test}}(y_t - \hat y_t)^2}{\sum_{t \in \text{test}}(y_t - \bar y)^2}.$$

It can be negative (the model is worse than the mean), and in return prediction even small positive values can be economically meaningful because returns are so noisy.

### Shrinkage: ridge and lasso

**Regularization** limits complexity by penalizing large coefficients. **Ridge** regression minimizes $SSR + \lambda\sum_j\beta_j^2$, giving $\hat\beta = (X'X + \lambda I)^{-1}X'y$ (with standardized regressors and an unpenalized intercept). For a single regressor with no intercept, $\hat\beta_{ridge} = \sum x_i y_i/(\sum x_i^2 + \lambda)$: it shrinks the OLS estimate toward zero, trading a little bias for less variance, and it handles collinear regressors gracefully (week 4). **Lasso** penalizes $\sum_j|\beta_j|$ instead and sets some coefficients exactly to zero, performing variable selection. The penalty $\lambda$ is chosen by validation, often **cross-validation**: split the training data into folds, fit on all but one, evaluate on the one, and average (for time series use forward-chaining folds, not random ones).

### Data snooping and multiple testing

Test many predictors, strategies or specifications, and some will look significant by luck. If each of $m$ independent tests has false-positive probability $\alpha$ under the null, the probability of at least one false positive is

$$1 - (1-\alpha)^m,$$

which is $64\%$ for $m = 20$ and $\alpha = 5\%$. The **Bonferroni correction** tests each hypothesis at level $\alpha/m$ so the chance of any false positive is at most $\alpha$ (it is conservative, and valid without independence). Reported results must account for *all* the specifications tried, including those not written up (**p-hacking** or the file drawer problem). A backtest that picks the best of many strategies overstates what to expect from it. Disciplined practice: pre-specify the hypothesis, count the trials, keep a final test set, and prefer economic reasoning, simple models and results that survive transaction costs and out-of-sample periods.

### Prediction is not causation

A well-fitting ML model predicts; it does not show *why*. Predictive relationships can break when market conditions change (non-stationarity) or when many investors act on them. This course's tools (inference, robust standard errors, diagnostics) remain necessary for judging whether an ML result is more than noise.

@example
title: How many false positives to expect?
problem: A researcher screens 40 candidate predictors of next-month returns, each tested at the 5% level, when in truth none has any predictive power (and the tests are independent). What is the chance that at least one appears significant, and what Bonferroni threshold should each test use?
step: The chance of no false positive in one test is $0.95$, so for 40 independent tests it is $0.95^{40} = 0.1285$.
step: The probability of at least one false positive is $1 - 0.1285 = 0.8715$, about 87%. The expected number of false positives is $40 \times 0.05 = 2$.
step: With the Bonferroni correction, each test uses $0.05/40 = 0.00125$. A predictor must have a p-value below 0.00125 to count as significant at the family-wise 5% level.
step: Lesson: a "significant" predictor found among many candidates deserves much less trust than one chosen in advance.
answer: About 87%; use a per-test threshold of $0.00125$.

@example
title: Out-of-sample R-squared
problem: A model forecasts monthly returns. On a test set of four months, the actual returns are $2\%, -1\%, 3\%, -2\%$, the model's forecasts are $1\%, 0\%, 1\%, 0\%$, and the mean return in the training data was $0.5\%$. Compute $R^2_{OOS}$.
step: Model errors: $(1, -1, 2, -2)$ percentage points, so $\sum(y - \hat y)^2 = 1 + 1 + 4 + 4 = 10$.
step: Benchmark errors, $y - 0.5$: $(1.5, -1.5, 2.5, -2.5)$, so $\sum(y - \bar y)^2 = 2.25 + 2.25 + 6.25 + 6.25 = 17$.
step: $R^2_{OOS} = 1 - 10/17 = 0.4118$.
step: The model beats the historical-mean forecast on this test set. With four months this says almost nothing; real evaluations use hundreds of out-of-sample forecasts.
answer: $R^2_{OOS} = 0.4118$.

@mistakes
- Judging a model by its in-sample fit, or by a test set that was also used to choose the specification.
- Splitting time-series data at random, which lets future information leak into the training set.
- Ignoring the number of strategies, predictors or specifications tried when reporting a significant result.
- Treating a forecast model as an explanation of cause and effect, or assuming a pattern that held in the past will persist.

model:
```python
def walk_forward_splits(n, train_size, test_size):
    """Rolling-window train/test index splits that never look ahead."""
    splits = []
    start = 0
    while start + train_size + test_size <= n:
        train = list(range(start, start + train_size))
        test = list(range(start + train_size, start + train_size + test_size))
        splits.append((train, test))
        start += test_size
    return splits
```
hint: Keep a `start` position; the training block is `start .. start + train_size - 1` and the test block follows immediately.
hint: Loop while `start + train_size + test_size <= n`, and move `start` forward by `test_size` after each split.
solution: Each split uses a fixed-length window of the past for training and the next `test_size` observations for testing, then rolls forward by the size of the test block, so every observation after the first window is tested exactly once and no test index ever precedes a training index. The loop condition drops a final test block that would run past the end of the data.

model:
```python
def oos_r2(y_test, y_pred, y_benchmark):
    """Out-of-sample R-squared against a fixed benchmark forecast."""
    ssr = sum((y - p) ** 2 for y, p in zip(y_test, y_pred))
    sst = sum((y - y_benchmark) ** 2 for y in y_test)
    return 1 - ssr / sst
```
hint: The numerator is the model's squared forecast errors; the denominator is the benchmark's squared forecast errors.
hint: The benchmark is a fixed number: do not recompute the mean of `y_test`.
solution: Compare the model's sum of squared errors with that of the benchmark forecast on the same test observations. Using the test-sample mean in the denominator would flatter the model, because the mean of the test set is not known at forecast time. The last test shows that a model can be worse than the benchmark, giving a negative value.
