@article
A single DCF or NPV uses one number for each uncertain input. **Monte Carlo simulation** replaces each uncertain input with a probability distribution, draws many random sets of inputs, computes the result for each, and studies the resulting distribution. Instead of "NPV = 198", you learn "NPV averages 198, with about an 8% chance of being negative".

### The simulation loop
1. Choose a distribution for each uncertain input (normal for symmetric errors, uniform for "anywhere between", triangular for a most-likely value with a range, lognormal for a positive and skewed quantity).
2. Draw a value for each input.
3. Compute the output (here, NPV).
4. Repeat $n$ times and collect the outputs in a list.

Python's `random.Random(seed)` creates a generator. A **seed** makes the sequence reproducible: the same seed gives the same draws, so a result can be re-run and audited. A function that takes the generator as an argument stays testable:

```python
import random

def simulate_values(draw, n, seed):
    rng = random.Random(seed)
    return [draw(rng) for _ in range(n)]
```

Here `draw(rng)` produces one outcome, for example `rng.gauss(300, 80)` (mean 300, standard deviation 80) or `rng.uniform(1, 2)`.

### Example: a project with uncertain cash flows
A project costs \$1,000 and returns a cash flow at the end of each of 5 years, each independently normal with mean 300 and standard deviation 80, discounted at 8%. The exact answer is available, because NPV is a linear combination of independent normals:

- mean NPV $= -1000 + 300 \times 3.9927 = 197.8$, where $3.9927$ is the 5-year annuity factor at 8%;
- standard deviation $= 80\sqrt{\sum_{t=1}^{5} 1.08^{-2t}} = 143.7$;
- probability of a negative NPV $= \Phi(-197.8/143.7) = \Phi(-1.377) = 8.4\%$.

A simulation of this project should reproduce those numbers, which makes it a test of your code. When the exact answer is not available (taxes, caps, options), the simulation is the answer.

### Summarizing the results
- **Mean:** `statistics.mean(values)`.
- **Percentiles:** sort the values and interpolate. For $p$ between 0 and 100 the position is $(n - 1)p/100$; if it falls between two sorted values, interpolate linearly. For the sorted list 10, 20, 30, 40 the 25th percentile has position $0.75$, so it is $10 + 0.75 \times 10 = 17.5$.
- **Probability of loss:** the fraction of values below zero.

### Simulation error
A simulated mean is itself random. Its **standard error** is

$$SE = \frac{s}{\sqrt{n}},$$

where $s$ is the sample standard deviation of the outcomes. With $s = 120$ and $n = 10{,}000$ draws, $SE = 1.2$. To halve the error you need **four times** as many draws. About 95% of the time the true mean lies within $1.96\,SE$ of the simulated mean. Report the number of draws and the standard error with the result.

### Cautions
- Garbage in, garbage out: the distributions are assumptions, and fat tails or correlations that you leave out make the result look safer than it is. Drawing one shock and applying it to every year, versus an independent draw each year, gives very different spreads.
- Never test a simulation against specific random numbers. Test properties: the number of results, the range, and a mean within a few standard errors of the exact answer.
- The same seed gives the same results only for the same code and the same Python; do not depend on particular values.

### On your own computer
NumPy generates and sums arrays of draws at once, so a hundred thousand draws take a fraction of a second:

```python
# on your own computer: NumPy
import numpy as np

rng = np.random.default_rng(42)
flows = rng.normal(300, 80, size=(100_000, 5))
factors = 1.08 ** -np.arange(1, 6)
npv = -1000 + flows @ factors
print(npv.mean(), npv.std(ddof=1), (npv < 0).mean())
```

The browser version uses plain loops, so keep the number of draws to a few thousand.

@example
title: How many draws do I need?
problem: A simulation of NPV with 10,000 draws has a sample standard deviation of 120. Find the standard error of the mean, and the number of draws needed to cut it to 0.6.
step: $SE = 120/\sqrt{10000} = 1.2$.
step: Halving the error needs four times the draws: from 1.2 to 0.6 means $n \times 4 = 40{,}000$.
step: Check: $120/\sqrt{40000} = 120/200 = 0.6$.
answer: The standard error is 1.2; 40,000 draws give 0.6.

@mistakes
- Using the same random draw for every year of a project (perfect correlation) when the cash flows are independent, which overstates the spread.
- Reporting a simulated mean without its number of draws or standard error, so the reader cannot judge its precision.
- Testing a simulation against exact random values instead of against properties and the exact answer where one exists.
- Letting a distribution produce impossible values (negative sales or prices) without capping or choosing a better distribution.

model:
```python
def percentile(values, p):
    """Linear-interpolation percentile, p from 0 to 100."""
    if not values or not 0 <= p <= 100:
        raise ValueError("need values and 0 <= p <= 100")
    ordered = sorted(values)
    position = (len(ordered) - 1) * p / 100
    low = int(position)
    if low + 1 >= len(ordered):
        return ordered[-1]
    fraction = position - low
    return ordered[low] + fraction * (ordered[low + 1] - ordered[low])
```
hint: `sorted(values)` makes a sorted copy without changing the input.
hint: The position is `(n - 1) * p / 100`; its integer part is the lower index and its fractional part is the weight on the next value. At `p = 100` there is no next value.
solution: Sort a copy, compute the fractional position, and interpolate between the two surrounding values. At 100 the position is the last index, so return the last value directly. The 90th percentile of 20, 40, 60, 80, 100 has position 3.6, so it is $80 + 0.6 \times 20 = 92$.

model:
```python
import math
import statistics

def standard_error(values):
    """Standard error of the sample mean."""
    n = len(values)
    if n < 2:
        raise ValueError("need at least two values")
    return statistics.stdev(values) / math.sqrt(n)
```
hint: The standard error is the sample standard deviation divided by the square root of the number of values.
hint: Check `len(values) < 2` first and raise `ValueError`.
solution: Compute `statistics.stdev(values)` (divisor $n - 1$) and divide by `math.sqrt(n)`. For `[1, 3]` the standard deviation is $\sqrt{2}$ and $n = 2$, so the standard error is 1.

model:
```python
import random

def simulate_project_npv(n, seed):
    """Simulated NPVs of a project with four uncertain cash flows."""
    rng = random.Random(seed)
    results = []
    for _ in range(n):
        npv = -900.0
        for year in range(1, 5):
            npv += rng.gauss(280, 60) / 1.07 ** year
        results.append(npv)
    return results
```
hint: Create one generator, then repeat the whole project `n` times.
hint: Start each NPV at `-900.0`; for each year draw a new cash flow with `rng.gauss(280, 60)` and add its present value.
solution: For each simulated project draw an independent cash flow for each of the four years, discount each by `1.07 ** year`, and add them to the outlay. The exact mean NPV is 48.4 and the exact standard deviation is 101.9, which the tests check with generous margins; one shock reused for all years would give a standard deviation of about 203 and fail.
