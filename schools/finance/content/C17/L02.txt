@article
The time-value-of-money (TVM) functions are the core of any finance library. All of them follow from one idea: a cash flow $CF_t$ received at time $t$ (in periods) is worth $CF_t/(1+r)^t$ today when the discount rate is $r$ per period.

### Net present value
$$NPV = \sum_{t=0}^{N} \frac{CF_t}{(1+r)^t}$$

Our convention: `flows[0]` is at time 0 (today, undiscounted), `flows[1]` is one period later, and so on.

```python
def npv(rate, flows):
    """Net present value; flows[0] occurs at time 0."""
    return sum(cf / (1 + rate) ** t for t, cf in enumerate(flows))
```

`enumerate(flows)` supplies the time index $t$ along with each flow. **A spreadsheet's `NPV(rate, values)` discounts its first value by one full period**, so it equals this function's answer divided by $(1+r)$ when you pass the whole list. Always say which convention a function uses.

### Internal rate of return
The IRR is the rate $r$ that makes $NPV(r) = 0$. There is no closed form for more than two or three flows, so we search. **Bisection** keeps an interval $[lo, hi]$ in which the NPV changes sign, looks at the midpoint and keeps the half that still contains the sign change. After 200 halvings the interval is far smaller than floating-point precision.

```python
def irr(flows):
    """Rate at which NPV is zero, searched between -99% and 1000%."""
    lo, hi = -0.99, 10.0
    f_lo = npv(lo, flows)
    if f_lo * npv(hi, flows) > 0:
        raise ValueError("no sign change: no IRR in the search range")
    for _ in range(200):
        mid = (lo + hi) / 2
        f_mid = npv(mid, flows)
        if f_lo * f_mid <= 0:
            hi = mid
        else:
            lo, f_lo = mid, f_mid
    return (lo + hi) / 2
```

If every flow has the same sign there is no IRR, and flows that change sign more than once can have several. The function below raises an error when the NPV has the same sign at both ends of its search range, which catches the first case; with several sign changes it returns just one of the IRRs, so look at the pattern of cash flows before you rely on it.

### Annuities
A level payment $PMT$ at the end of each of $n$ periods has present value

$$PV = PMT \times \frac{1 - (1+r)^{-n}}{r}.$$

An **annuity due** pays at the *start* of each period, so every payment is one period closer and the value is multiplied by $(1+r)$. At $r = 0$ the formula divides by zero, but the value is simply $PMT \times n$; a robust function handles that case separately.

```python
def pv_annuity(pmt, rate, nper, when=0):
    """PV of level payments; when=0 end of period, when=1 start."""
    if rate == 0:
        return pmt * nper
    factor = (1 - (1 + rate) ** -nper) / rate
    return pmt * factor * (1 + rate) ** when
```

### Loan payments
The level end-of-period payment that repays a loan of $PV$ over $n$ periods solves the annuity formula for $PMT$:

$$PMT = \frac{PV \cdot r}{1 - (1+r)^{-n}}.$$

For a monthly loan, $r$ is the annual rate divided by 12 and $n$ is the number of months. Using the annual rate as the monthly rate is the classic error.

@example
title: NPV of a project, then in code
problem: A project costs \$1,000 today and returns \$300, \$400 and \$500 at the end of years 1, 2 and 3. The discount rate is 10% per year. Find the NPV and say what `npv(0.10, [-1000, 300, 400, 500])` returns.
step: Discount each flow: $300/1.10 = 272.73$, $400/1.10^2 = 330.58$, $500/1.10^3 = 375.66$.
step: The present value of the inflows is $272.73 + 330.58 + 375.66 = 978.96$.
step: Subtract the outlay at time 0: $978.96 - 1000 = -21.04$.
step: The function does the same sum, with `t = 0, 1, 2, 3`, so it returns about `-21.04`. A negative NPV means the project earns less than 10%.
answer: The NPV is about -\$21.04.

@example
title: An annuity and an annuity due
problem: Find the present value of \$100 received at the end of each year for 10 years at 5%, and then if the payments come at the start of each year.
step: The factor is $\dfrac{1 - 1.05^{-10}}{0.05} = 7.7217$.
step: Ordinary annuity: $100 \times 7.7217 = 772.17$, so `pv_annuity(100, 0.05, 10)` is about `772.17`.
step: Annuity due: every payment arrives a year sooner, so multiply by $1.05$: $772.17 \times 1.05 = 810.78$, which is `pv_annuity(100, 0.05, 10, when=1)`.
answer: \$772.17 for the ordinary annuity and \$810.78 for the annuity due.

@mistakes
- Passing a spreadsheet-style list (first flow at time 1) to a time-0 `npv`, or the reverse, and getting an answer off by a factor of $1 + r$.
- Using the annual rate as the monthly rate (or the monthly rate with annual periods) in a payment formula.
- Dividing by `rate` when `rate == 0`, which crashes; handle the zero-rate case separately.
- Reporting an IRR when the flows never change sign, or when they change sign several times and several rates solve the equation.
