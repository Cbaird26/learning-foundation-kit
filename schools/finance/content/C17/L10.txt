@article
A single DCF value looks precise and is not: it depends on a dozen uncertain inputs. **Sensitivity analysis** shows how the answer moves when inputs change. Because your model is a function, you get it almost for free: call the function many times with different inputs.

### One-way and two-way tables
A **one-way** sensitivity changes one input and holds the others fixed. A **two-way** table (a grid) changes two, such as WACC down the rows and terminal growth across the columns. For FCFF of 100, 110 and 120, the enterprise value in millions of dollars is:

| WACC \ g | 2% | 3% | 4% |
|---|---|---|---|
| 9% | 1,627.2 | 1,867.7 | 2,204.4 |
| 10% | 1,421.5 | 1,598.6 | 1,834.7 |
| 11% | 1,261.5 | 1,396.8 | 1,570.7 |

Value falls as WACC rises and rises as growth rises; the effect of growth is larger when WACC is low because the denominator $WACC - g$ is smaller. The code is one nested list comprehension:

```python
def sensitivity_grid(func, row_values, col_values):
    return [[func(r, c) for c in col_values] for r in row_values]
```

`func(r, c)` is any two-argument model, for example `lambda w, g: enterprise_value(flows, w, g)`.

### Scenarios
A **scenario** is a named, coherent set of assumptions: a *base* case, a *bull* case with faster growth and higher margins, a *bear* case with slower growth. Unlike a sensitivity, a scenario changes **several inputs together**, because in reality they move together (a recession cuts growth and margins at once). Store scenarios in a dictionary and run the model once for each:

```python
scenarios = {
    "base": {"growth": 0.05, "margin": 0.20},
    "bull": {"growth": 0.10, "margin": 0.25},
}
results = {name: model(**params) for name, params in scenarios.items()}
```

`model(**params)` unpacks a dictionary into keyword arguments. Probability-weighting the scenario values gives an expected value, but the probabilities are judgments and should be stated.

### Tornado analysis
A **tornado** table ranks inputs by how much they move the output. For each input, move it down and up by the same percent (say 10%) with the others at their base values, and record the **swing**, the absolute difference between the high-case and low-case outputs. Sorting by swing, largest first, shows where a better estimate is worth the most effort. Drawn as horizontal bars from the largest to the smallest, the chart looks like a tornado.

### Breakeven
A **breakeven** value is the input at which the output equals a threshold: the growth rate at which a project's NPV is zero, or the price at which a deal stops creating value. Write the output minus the threshold as $f(x)$ and find its root. Bisection works when $f(lo)$ and $f(hi)$ have opposite signs: halve the interval, keep the half where the sign changes, and repeat. Check the signs first and raise an error if there is no sign change.

### Showing it
In the browser the table is just a list of lists. On your own computer, a chart shows it better:

```python
# on your own computer: pandas and matplotlib
import pandas as pd
import matplotlib.pyplot as plt

table = pd.DataFrame(grid, index=waccs, columns=growths)
plt.imshow(table, aspect="auto")
plt.colorbar(label="enterprise value")
plt.show()
```

Whatever the medium, label units, show the base case, and keep the ranges realistic: a sensitivity over impossible values is noise.

title: Reading and building a grid
problem: What are `grid[1][2]`, the number of rows and the number of columns in this program?

```python
rows = [1, 2]
cols = [10, 20, 30]
grid = [[r * c for c in cols] for r in rows]
```
step: The outer comprehension loops over `rows`, so there is one inner list per row value: 2 rows.
step: Each inner list loops over `cols`, so it has 3 entries.
step: Row 0 (r = 1) is `[10, 20, 30]`; row 1 (r = 2) is `[20, 40, 60]`.
step: `grid[1][2]` is row index 1, column index 2: `60`.
answer: `grid[1][2]` is 60; the grid has 2 rows and 3 columns.

@example
title: A tornado ranking by hand
problem: A value model is $V = 3a + b$ with base values $a = 10$ and $b = 20$. Vary each input by 10% and rank the inputs by swing.
step: For $a$: low $= 9$, high $= 11$, with $b = 20$ fixed: $V_{low} = 47$, $V_{high} = 53$, swing $= 6$.
step: For $b$: low $= 18$, high $= 22$, with $a = 10$ fixed: $V_{low} = 48$, $V_{high} = 52$, swing $= 4$.
step: Rank by swing: $a$ (6) first, then $b$ (4).
step: Input $a$ matters more here because its coefficient (3) is larger, even though $b$ has the larger base value.
answer: The ranking is $a$ with a swing of 6, then $b$ with a swing of 4.

@mistakes
- Passing the row and column values to the model in the wrong order, so the table is transposed without any error message.
- Calling a scenario analysis a sensitivity analysis (or the reverse); scenarios move several inputs together, sensitivities move one or two at a time.
- Judging importance by the size of the input rather than by the size of its effect on the output.
- Running bisection when the function has the same sign at both ends, which finds nothing.

model:
```python
def breakeven(f, lo, hi):
    """Root of f in [lo, hi] by bisection."""
    f_lo = f(lo)
    if f_lo * f(hi) > 0:
        raise ValueError("f does not change sign on [lo, hi]")
    for _ in range(200):
        mid = (lo + hi) / 2
        f_mid = f(mid)
        if f_lo * f_mid <= 0:
            hi = mid
        else:
            lo, f_lo = mid, f_mid
    return (lo + hi) / 2
```
hint: First check that the function has opposite signs (or zero) at the two ends.
hint: If `f(lo)` and `f(mid)` have opposite signs (product at most zero) the root is in the lower half, so move `hi`; otherwise move `lo`.
solution: Verify a sign change, then repeatedly halve the interval, keeping the half where the sign changes. After 200 halvings the interval is smaller than floating-point precision. A function that is always positive, such as $x^2 + 1$, has no root and raises `ValueError`.

model:
```python
def tornado(model, base, pct):
    """Inputs ranked by the swing in model output for +/- pct."""
    swings = []
    for name, value in base.items():
        low = dict(base, **{name: value * (1 - pct)})
        high = dict(base, **{name: value * (1 + pct)})
        swings.append((name, abs(model(**high) - model(**low))))
    return sorted(swings, key=lambda item: item[1], reverse=True)
```
hint: For each input, build two copies of the base dictionary with only that input changed.
hint: `dict(base, **{name: new_value})` copies `base` and replaces one entry; sort the tuples with `key=lambda item: item[1]` and `reverse=True`.
solution: For each input create a low and a high version of the base dictionary, call the model on each with `**`, and record the absolute difference. Sorting by that swing, largest first, puts the most influential input at the top.
