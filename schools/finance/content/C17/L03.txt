@article
A **loan schedule** is a table with one row per payment. It is the most common model in consumer and corporate finance, and writing it in code makes the logic visible.

### The schedule logic
Take a loan of $P$ at an annual rate $i$ with monthly payments over $y$ years. The monthly rate is $r = i/12$ and the number of payments is $n = 12y$. The level payment is

$$PMT = \frac{P\,r}{1 - (1+r)^{-n}}.$$

Each month, starting from the balance $B_{k-1}$:

1. interest $= B_{k-1} \times r$
2. principal repaid $= PMT - \text{interest}$
3. new balance $B_k = B_{k-1} - \text{principal repaid}$

Interest falls and principal rises each month, while the payment stays the same. After $n$ payments the balance is zero, apart from floating-point dust of order $10^{-8}$ that you check with a tolerance, never with `==`.

```python
def amortization_schedule(principal, annual_rate, years):
    r, n = annual_rate / 12, years * 12
    pmt = principal / n if r == 0 else principal * r / (1 - (1 + r) ** -n)
    balance, rows = principal, []
    for k in range(1, n + 1):
        interest = balance * r
        repaid = pmt - interest
        balance -= repaid
        rows.append((k, pmt, interest, repaid, balance))
    return rows
```

A 360-row schedule in floats is instant; carry full precision and round only when you display.

### Remaining balance without a table
After $k$ payments the balance is the present value of the payments still to come, or equivalently the loan grown at $r$ minus the payments grown at $r$:

$$B_k = P(1+r)^k - PMT\,\frac{(1+r)^k - 1}{r}.$$

This closed form is a powerful cross-check on the schedule: two independent methods must agree.

### Dates
Python's `datetime.date` supports subtraction, which returns a `timedelta` whose `.days` is the actual number of days. Adding months is not built in, because months have different lengths. January 31 plus one month has no February 31, so we clamp to the last day of the month using `calendar.monthrange(year, month)[1]`.

```python
import calendar
from datetime import date

def add_months(d, n):
    year, month0 = divmod(d.year * 12 + d.month - 1 + n, 12)
    last = calendar.monthrange(year, month0 + 1)[1]
    return date(year, month0 + 1, min(d.day, last))
```

Always compute payment $k$ from the **first** payment date (`add_months(first, k)`), not from the previous date: if you step from a clamped February 28 you will never return to the 31st.

### Day counts
Interest between two dates depends on a **day-count convention**. *Actual/365* uses the real number of days over 365; *actual/360* uses real days over 360; *30/360 (bond basis, US)* treats every month as 30 days. The 30/360 rule: if the first day is 31, set it to 30; if the second day is 31 and the (adjusted) first day is 30 or more, set it to 30; then days $= 360\Delta Y + 30\Delta M + \Delta D$. The convention is part of the contract, so a model must state which it uses.

@example
title: The first two rows of a schedule by hand
problem: A \$12,000 loan at 6% per year is repaid in 12 monthly payments. Find the payment and the first two schedule rows.
step: The monthly rate is $r = 0.06/12 = 0.005$, and $PMT = \dfrac{12000 \times 0.005}{1 - 1.005^{-12}} = 1032.80$.
step: Month 1: interest $12000 \times 0.005 = 60.00$; principal $1032.80 - 60.00 = 972.80$; balance $12000 - 972.80 = 11027.20$.
step: Month 2: interest $11027.20 \times 0.005 = 55.14$; principal $1032.80 - 55.14 = 977.66$; balance $11027.20 - 977.66 = 10049.54$.
step: Interest fell by \$4.86 and principal rose by the same amount, so the payment is unchanged.
answer: Payment \$1,032.80; month 1 balance \$11,027.20; month 2 balance \$10,049.54.

@example
title: Month-end payment dates
problem: A loan's first payment is on January 31, 2026, with monthly payments. Give the dates of payments 1 to 3, and explain why stepping from the previous date is wrong.
step: Payment 1 is the first date, `add_months(first, 0)`: January 31, 2026.
step: Payment 2 is `add_months(first, 1)`. February 2026 has 28 days, so the day is clamped to 28: February 28, 2026.
step: Payment 3 is `add_months(first, 2)`: March has 31 days, so the date is March 31, 2026.
step: Stepping from the previous date would add a month to February 28 and give March 28, and every later date would stay on the 28th. Counting from the first date keeps the 31st whenever the month has one.
answer: January 31, February 28 and March 31, 2026.

@mistakes
- Using the annual rate as the monthly rate, or `years` as the number of payments, so the schedule has the wrong length.
- Testing that the final balance `== 0`; floating-point arithmetic leaves a tiny remainder, so use a tolerance.
- Stepping dates one month at a time from the previous (clamped) date, which drifts off the 31st.
- Mixing day-count conventions: a model that uses actual days for accrual and 30/360 for the rate schedule is inconsistent.

```python
def days_30_360(d1, d2):
    """Days between two dates, US 30/360 (bond basis)."""
    day1 = 30 if d1.day == 31 else d1.day
    day2 = d2.day
    if day2 == 31 and day1 >= 30:
        day2 = 30
    return 360 * (d2.year - d1.year) + 30 * (d2.month - d1.month) + (day2 - day1)
```
hint: Adjust the first day first, because the rule for the second day depends on the adjusted first day.
hint: A second day of 31 is changed only when the adjusted first day is 30 or more; January 15 to January 31 keeps the 31.
solution: Set `day1` to 30 if it is 31, then set `day2` to 30 only if it is 31 and `day1 >= 30`. For January 15 to January 31, `day2` stays 31 and the answer is 16, but January 30 to January 31 gives 0.

```python
def amortization_schedule(principal, annual_rate, years):
    """Monthly schedule of (period, payment, interest, repaid, balance)."""
    r, n = annual_rate / 12, years * 12
    if r == 0:
        pmt = principal / n
    else:
        pmt = principal * r / (1 - (1 + r) ** -n)
    balance, rows = principal, []
    for k in range(1, n + 1):
        interest = balance * r
        repaid = pmt - interest
        balance -= repaid
        rows.append((k, pmt, interest, repaid, balance))
    return rows
```
hint: First compute the level payment and the number of months $n = 12 \times \text{years}$.
hint: In a loop over `range(1, n + 1)`: interest is `balance * r`, principal repaid is `pmt - interest`, and the balance falls by the principal repaid.
solution: Compute the payment once, then loop over the months: interest on the opening balance, principal repaid as the rest of the payment, and a new balance. Append a tuple each month. The zero-rate case avoids dividing by zero and gives equal principal payments with no interest.

model:
```python
def remaining_balance(principal, annual_rate, years, k):
    """Balance after k level monthly payments, closed form."""
    r, n = annual_rate / 12, years * 12
    if r == 0:
        return principal * (1 - k / n)
    pmt = principal * r / (1 - (1 + r) ** -n)
    growth = (1 + r) ** k
    return principal * growth - pmt * (growth - 1) / r
```
hint: The balance is the loan grown for `k` months minus the payments grown for `k` months.
hint: With $g = (1+r)^k$, the balance is $P g - PMT\,(g - 1)/r$; handle $r = 0$ separately.
solution: Compute the level payment, then use $B_k = P(1+r)^k - PMT\,((1+r)^k - 1)/r$. With a zero rate every payment is `principal / n`, so the balance after `k` payments is `principal * (1 - k / n)`.
