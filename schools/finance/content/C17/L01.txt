@article
A financial model is a pile of small calculations: grow a balance, discount a cash flow, compute a payment. If each calculation is a **function** with a clear name and a test, you can trust the pieces and combine them. Every later week of this course builds on that habit, so this week reviews the Python you need and sets the conventions we use all course.

### Functions with units
A function takes inputs, returns one result and does nothing else. For compound growth the formula is

$$FV = PV\,(1 + r)^n$$

where $PV$ is the starting amount, $r$ the rate per period and $n$ the number of periods.

```python
def future_value(pv, rate, years):
    """Value after `years` of annual compounding.

    `rate` is a decimal per year (0.05 means 5%).
    """
    return pv * (1 + rate) ** years
```

The docstring states the unit. The most common modeling bug is a rate typed as `5` when the function expects `0.05`, so **rates are decimals, and the docstring says so.** Likewise, say whether a function *returns* a value (usual) or *prints* it (only for reports), and what it does for impossible input: raise `ValueError` rather than return nonsense.

### Tests as assertions
An `assert` statement stops the program with an error if its condition is false:

```python
import math
assert math.isclose(future_value(1000, 0.05, 2), 1102.5, rel_tol=1e-9)
assert future_value(500, 0.08, 0) == 500
```

Good tests cover the main case, the edges (zero periods, zero rate, an empty list) and one case a typical mistake would get wrong.

### Floats are approximations
Python floats are binary fractions, so `0.1 + 0.2` is `0.30000000000000004`, and `0.1 + 0.2 == 0.3` is `False`. Compare money and rates computed with floats using `math.isclose(a, b, rel_tol=1e-9)` or `abs(a - b) < 1e-6`. Reserve `==` for integers and for values that are exact.

### Decimal for exact cents
When a ledger must match to the cent, use `decimal.Decimal`, built from a **string** (`Decimal("2.675")`), never from a float (`Decimal(2.675)` carries the float's binary error). Round half up with `quantize`:

```python
from decimal import Decimal, ROUND_HALF_UP
cents = Decimal("2.675").quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
print(cents)  # 2.68
```

Built-in `round(2.675, 2)` gives `2.67`, because the float is slightly below 2.675 and Python rounds the stored value. Keep `Decimal` loops short; for long schedules use floats and round only when displaying.

### Printing money
`f"{1234.5:,.2f}"` prints `1,234.50`: a thousands separator, two decimals. Format only at the end; carry full precision through the calculation.

### Conventions for this course
- Rates are decimals per period; say per year or per month.
- Cash flows at the end of each period unless stated; time 0 is today.
- Functions return values; tests use `assert`.

@example
title: Why floats need a tolerance
problem: What does this program print?

```python
x = 0.1 + 0.2
print(x == 0.3)
print(abs(x - 0.3) < 1e-9)
print(f"{x:.2f}")
```
step: `0.1` and `0.2` are stored as the nearest binary fractions, so `x` is `0.30000000000000004`, not exactly `0.3`.
step: The first `print` tests exact equality. The stored values differ in the 17th digit, so it prints `False`.
step: The second compares the *difference* with a tiny tolerance. The difference is about `5.6e-17`, below `1e-9`, so it prints `True`.
step: The third formats `x` to two decimals, which hides the error and prints `0.30`.
answer: `False`, then `True`, then `0.30`, one per line.

@example
title: Writing and testing a small function
problem: Write `after_tax_return(pretax_return, tax_rate)` that returns the return left after tax, both as decimals, and test it.
step: The after-tax return is the pretax return times the share kept: $r_{\text{after}} = r(1 - t)$.
step: Write the function with a docstring that states the units:

```python
def after_tax_return(pretax_return, tax_rate):
    """Return after tax; both arguments are decimals (0.25 = 25%)."""
    return pretax_return * (1 - tax_rate)
```
step: Test the main case by hand: $0.08 \times (1 - 0.25) = 0.06$.
step: Add an edge case (no tax keeps the whole return) and use a tolerance:

```python
import math
assert math.isclose(after_tax_return(0.08, 0.25), 0.06, rel_tol=1e-9)
assert after_tax_return(0.08, 0) == 0.08
```
answer: `after_tax_return(0.08, 0.25)` is `0.06`, a 6% after-tax return.

@mistakes
- Passing a percent (`5`) to a function that expects a decimal (`0.05`), which makes every answer 100 times too large.
- Comparing floats with `==` in a test, so a correct function fails because of a 17th-digit difference.
- Building a `Decimal` from a float (`Decimal(2.675)`) instead of a string, which keeps the float's error.
- Printing a result inside a function that should return it, so other code cannot use the number.

```python
from decimal import Decimal, ROUND_HALF_UP

```

```python
from decimal import Decimal
assert to_cents("7.835") == Decimal("7.84")
assert to_cents("0.125") == Decimal("0.13")
assert to_cents("7.834") == Decimal("7.83")
```

```python
from decimal import Decimal, ROUND_HALF_UP

def to_cents(amount):
    """Round a string amount half up to the cent."""
    return Decimal(amount).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
```

@quiz code
prompt: Write `cagr(begin, end, years)` that returns the compound annual growth rate as a decimal: $(\text{end}/\text{begin})^{1/\text{years}} - 1$. Raise `ValueError` if `begin` or `years` is not positive.
starter:
```python
def cagr(begin, end, years):
    pass
```
tests:
```python
import math
assert math.isclose(cagr(100, 121, 2), 0.10, rel_tol=1e-9)
assert math.isclose(cagr(50, 80, 3), 0.1696070952851465, rel_tol=1e-9)
assert math.isclose(cagr(200, 100, 1), -0.5, rel_tol=1e-9)
assert abs(cagr(1000, 1000, 5)) < 1e-12
assert raises(ValueError, cagr, 0, 10, 2)
assert raises(ValueError, cagr, 100, 150, 0)
```
model:
```python
def cagr(begin, end, years):
    """Compound annual growth rate as a decimal."""
    if begin <= 0 or years <= 0:
        raise ValueError("begin and years must be positive")
    return (end / begin) ** (1 / years) - 1
```
hint: Divide end by begin, raise to the power $1/\text{years}$, then subtract 1.
hint: Validate the inputs first with `if begin <= 0 or years <= 0:`.
solution: Growth over the whole period is `end / begin`; taking the `1 / years` power gives the per-year growth factor, and subtracting 1 gives the rate. Invalid inputs raise `ValueError` before any division.
