@article
Real data is untidy. A price file may have blank cells, the text `NA`, numbers written `1,030.25`, the same date twice, dates out of order, or a day with a price a hundred times too large. A model built on such data gives confident, wrong answers, so **clean first and check always**.

### Parsing messy values
Convert text step by step: remove spaces with `.strip()`, remove thousands separators with `.replace(",", "")`, test for missing markers, then call `float`.

```python
def to_number(text):
    text = text.strip().replace(",", "")
    if text.upper() in ("", "NA"):
        return None
    return float(text)
```

`None` is Python's value for "no value". Returning it, rather than `0`, keeps a missing price from looking like a price of zero.

### Duplicates and order
Two rows for one date usually mean a repeated download or a correction. Decide a rule and write it down (keep the first, keep the last) and apply it the same way every time. To keep the first row for each date, record the dates you have seen in a `set`. ISO dates (`2026-01-05`) sort correctly as text, so `sorted` restores order.

### Missing values: drop or fill
You can **drop** rows with missing prices or **fill** them. A common fill for prices is the **forward fill**: repeat the last known value. It is reasonable for a stock that did not trade, and misleading for long gaps, because it creates returns of exactly zero. Never fill a price with `0`: the next return would be infinite or $-100\%$. Leading missing values have nothing to repeat and stay missing.

### Gaps
A series that should be daily may skip days. Weekends and holidays are normal gaps; a two-week hole is not. Using `(later - earlier).days` on `datetime.date` objects, list the consecutive pairs separated by more than a chosen number of days (4 days covers a long weekend), and look at them.

### Outliers
A **z-score** measures distance from the mean in standard deviations: $z_i = (x_i - \bar{x})/s$. Flag values with $|z_i| > k$ for a threshold such as $k = 3$. Two cautions:

- **A flag is a question, not an answer.** A large return may be real (an earnings surprise, a crash); only investigation can tell a data error from an event. Report flagged values; do not delete them silently.
- **Small samples cannot show large z-scores.** With $n$ values the largest possible $|z|$ is $(n-1)/\sqrt{n}$. For $n = 10$ that is 2.85, so a threshold of 3 can never flag anything. The outlier also inflates the mean and standard deviation that are used to judge it.

### Validation checks
Before using a price series, check that: prices are positive; dates are unique and increasing; the number of rows is what you expect; the largest and smallest returns are plausible; and the count of rows dropped or filled is recorded. Write these checks as functions that return a list of problems, so they can be run on every new file.

@example
title: Tracing a cleaning loop
problem: What does this program print?

```python
raw = ["1,234.50", " 98.2", "NA"]
values = []
for s in raw:
    s = s.strip().replace(",", "")
    if s.upper() == "NA":
        continue
    values.append(float(s))

```
step: For `"1,234.50"`: `strip` changes nothing, `replace` gives `"1234.50"`, which is not `NA`, so `1234.5` is appended.
step: For `" 98.2"`: `strip` gives `"98.2"`, so `98.2` is appended.
step: For `"NA"`: the uppercase text is `"NA"`, so `continue` skips the rest of the loop body and nothing is appended.
step: The `print` runs once after the loop.
answer: `[1234.5, 98.2]`

@example
title: Why a z-score threshold of 3 can miss an outlier
problem: Nine daily price changes of 1 and one of 10 are in a list of ten values. Compute the z-score of the 10 and decide whether a threshold of 3 flags it.
step: The mean is $(9 \times 1 + 10)/10 = 1.9$.
step: The squared deviations are $9 \times 0.81 = 7.29$ and $8.1^2 = 65.61$, which sum to $72.9$. The sample variance is $72.9/9 = 8.1$, so $s = 2.846$.
step: The z-score of 10 is $(10 - 1.9)/2.846 = 2.846$.
step: This is below 3, so a threshold of 3 does not flag the obvious outlier, and with $n = 10$ no value can ever reach 3. A threshold of 2 flags it.
answer: $z = 2.85$: a threshold of 3 misses it, a threshold of 2 catches it.

@mistakes
- Filling missing prices with `0`, which creates a $-100\%$ return followed by an enormous rebound.
- Deleting outliers automatically, which removes real crashes and flatters risk measures.
- Sorting dates stored in a non-ISO format as text (`"12/31/2025"` sorts before `"2/1/2025"`).
- Using `if not value:` to test for missing, which also treats a legitimate `0` as missing; test `value is None` instead.

```python
def clean_prices(rows):
    """Drop missing prices, parse numbers, dedupe dates, sort by date."""
    seen = set()
    cleaned = []
    for date_text, price_text in rows:
        text = price_text.strip().replace(",", "")
        if text.upper() in ("", "NA"):
            continue
        if date_text in seen:
            continue
        seen.add(date_text)
        cleaned.append((date_text, float(text)))
    return sorted(cleaned)
```

```python
def find_gaps(dates, max_days):
    """Consecutive date pairs more than max_days apart."""
    gaps = []
    for earlier, later in zip(dates, dates[1:]):
        if (later - earlier).days > max_days:
            gaps.append((earlier, later))
    return gaps
```
hint: Pair each date with the next one using `zip(dates, dates[1:])`.
hint: Subtracting two dates gives a `timedelta`; its `.days` is the number of days. Compare with `>`, not `>=`.
solution: Loop over consecutive pairs and keep those whose difference in days exceeds `max_days`. A gap of exactly `max_days` (the 11-day gap with `max_days=11`) is not reported, which is why the comparison is strict.

```python
import statistics

def flag_outliers(values, k):
    """Indexes of values more than k sample standard deviations from the mean."""
    if len(values) < 2:
        return []
    mean = statistics.mean(values)
    s = statistics.stdev(values)
    if s == 0:
        return []
    return [i for i, v in enumerate(values) if abs(v - mean) > k * s]
```

def forward_fill(values):
    """Replace None with the last earlier non-None value."""
    filled = []
    last = None
    for v in values:
        if v is None:

        filled.append(v)
